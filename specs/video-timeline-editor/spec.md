# Feature Specification: 章节视频剪辑与时间线导出

**Workspace**: `video-timeline-editor`  
**Created**: 2026-05-06  
**Status**: Ready for planning  
**Input**: 用户描述: "/specify 帮我实现一下视频编辑功能"

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开章节剪辑并生成可用的时间线草稿 (Priority: P1)

作为 **正在制作某一章节的编导或制片**，我希望 **从该章节进入剪辑视图后，系统自动按镜头顺序拉取各镜头已生成的成片片段，形成一条可预览的时间线草稿**，以便 **省去手动逐个导入素材的步骤（剪映式「一键草稿」体验）**。

**Why this priority**: 若没有可用的初始时间线，剪辑页会持续「空壳」，与用户已完成分镜生成的现实脱节；这是需求落地的第一道门槛。

**Acceptance Scenarios**:

1. **Given** 当前章节下至少有一个镜头已经具备可用的生成视频素材  
   **When** 用户从约定的章节剪辑入口打开剪辑视图  
   **Then** 时间线上出现与该章节镜头顺序一致的片段占位，且每个占位能区分「已有成片」与「尚未生成」两类状态（后者不得静默伪装为正常成片）。

2. **Given** 当前章节下没有任何镜头具备可用的生成视频素材  
   **When** 用户打开剪辑视图  
   **Then** 系统给出明确说明（例如提示先到分镜工作室完成生成），时间线可为空或仅展示引导，**不得**仅展示笼统的技术错误。

3. **Given** 用户已打开剪辑视图且时间线草稿已展示  
   **When** 用户在剪辑视图内触发预览（若本期提供预览能力）  
   **Then** 用户能够按时间顺序感知整条草稿的播放意图（连续播放或等价体验）；若本期明确不提供预览，则须在界面文案中诚实说明「本期仅支持编排与导出」，避免误导。

**Edge Cases**:

- **边界条件**：部分镜头有成片、部分没有——仅呈现有成片的片段顺序，缺失镜头在列表或侧栏中有明确标识，导出规则见 User Story 3。
- **边界条件**：镜头顺序与章节内索引不一致或用户期望调整——见 User Story 2。
- **错误场景**：素材在库中已被删除或不可访问——对应片段应标记异常并提示重新生成或替换来源（不要求本期实现「替换来源」交互时可仅阻断导出并提示）。
- **并发场景**：用户在剪辑页打开的同时，后台完成了新的镜头成片——刷新或重新进入后草稿应反映最新可用素材（具体刷新策略由实现阶段决定，本期验收以「再次进入可见更新」为准）。

### User Story 2 - 调整片段顺序并保存时间线 (Priority: P1)

作为 **编导**，我希望 **在时间线上拖拽或等价操作调整各镜头成片的先后顺序，并能保存当前编排**，以便 **控制成片叙事节奏而不必在外部工具里重做素材整理**。

**Why this priority**: 「剪映式」核心交互之一是时间线可控；仅自动生成草稿不可保存则无法形成可靠工作流。

**Acceptance Scenarios**:

1. **Given** 用户已具备一条非空的时间线草稿  
   **When** 用户将某一成片片段移动到新位置并确认保存  
   **Then** 再次进入同一章节的剪辑视图时，片段顺序与用户上次保存一致。

2. **Given** 用户调整了顺序但未保存（若提供显式保存）或离开页面前有未保存变更（若提供脏检测）  
   **When** 用户尝试离开或刷新  
   **Then** 系统应提示用户处理未保存变更（丢弃 / 保存 / 取消），或采用自动保存策略并在界面说明；**不得**无声丢失用户编排而不告知。

**Edge Cases**:

- **边界条件**：仅一条成片——仍允许保存（顺序平凡）。
- **错误场景**：保存失败（网络或服务不可用）——明确失败提示，保留本地未提交状态或允许重试（验收以「用户可知失败原因并可重试」为准）。
- **并发场景**：两名用户同时编辑同一章节时间线——本期可采用「后者覆盖」或「只读锁定」之一；须在 Resolved Decisions 中选定行为并在界面有最小提示（避免静默互相覆盖）。

### User Story 3 - 导出章节成片并得到文件库结果 (Priority: P1)

作为 **编导**，我希望 **在确认时间线编排后发起「导出章节成片」**，以便 **得到一条合并后的单一视频文件并出现在素材库中，便于下载或后续分发**。

**Why this priority**: 这是「剪辑」闭环的商业终点；仅有编排无导出仍无法替代外部工具。

**Acceptance Scenarios**:

1. **Given** 用户已保存一条至少包含一个有效成片片段的时间线  
   **When** 用户发起导出章节成片  
   **Then** 系统创建一项用户可感知的处理过程（进行中状态），完成后在素材库（或等价入口）中出现一条新的视频成品，并与该章节产生可追溯关联（例如用途标签或详情说明）。

2. **Given** 导出任务进行中  
   **When** 用户在任务中心等通用入口查看该任务  
   **Then** 仅展示通用任务信息（状态、进度、成功/失败），**不**承担完整时间线调试上下文（与产品既有任务中心边界一致）。

3. **Given** 时间线中存在标记为缺失或异常的片段  
   **When** 用户尝试导出  
   **Then** 系统阻止导出并提示用户修复编排（移除异常片段或补全素材）；不得产出静默跳过片段却未告知用户的成片。

**Edge Cases**:

- **边界条件**：成片时长总和过长——应有合理超时或队列提示（具体阈值由实现阶段定义），失败时信息可读。
- **错误场景**：导出处理失败（编码不兼容、存储失败等）——任务失败态明确，用户可重试或联系管理员的信息层级区分。
- **并发场景**：用户对同一时间线重复点击导出——不得在无明确产品语义的情况下并行产生多套冲突成品；应采用排队、幂等或禁用按钮等策略之一并在 Resolved Decisions 中固定。

### User Story 4 - 单片段入点/出点微调（裁剪） (Priority: P2)

作为 **编导**，我希望 **对某一镜头成片在时间线上设置入点/出点（trim），以去掉不需要的头尾画面**，以便 **控制单镜时长与衔接节奏**。

**Why this priority**: 剪映常见能力，但实现复杂度高于纯排序拼接；放在 P2 可在 P1 闭环后再增强。

**Acceptance Scenarios**:

1. **Given** 时间线上存在某一成片片段  
   **When** 用户为该片段设置有效的入点/出点并保存  
   **Then** 预览（若已提供）与导出结果应反映裁剪后的有效时长；保存后重新进入剪辑视图仍保留裁剪意图。

**Edge Cases**:

- **边界条件**：入点晚于出点或时长为零——校验失败并提示。
- **边界条件**：裁剪后时长极短——允许与否由产品阈值在实现阶段定义，须在界面或错误提示中说明。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供 **与章节绑定的剪辑视图**，使用户能查看并编辑该章节的时间线草稿；入口位置与导航文案须与「章节制作」主流程一致，避免与「分镜工作室—生成」职责混淆（剪辑不负责发起模型生成参数调试）。
- **FR-002**: 系统必须能够 **按章节内镜头顺序** 识别各镜头的「可供剪辑的成片素材」来源；若某镜头暂无素材，须在剪辑视图内 **显式标示**，且不得阻塞用户查看其它已有片段（除导出校验外）。
- **FR-003**: 用户必须能够对时间线上的 **有效成片片段** 进行 **顺序编排**（拖拽或等价无障碍交互），并 **持久化** 编排结果以便跨会话恢复。
- **FR-004**: 用户必须能够发起 **章节成片导出**，导出输入为当前已保存的时间线与各片段有效可用性；导出结果必须 **落入素材库（或系统统一的成品文件列表）**，并与章节存在可追溯的业务关联（面向用户可理解为「本章导出成片」）。
- **FR-005**: 导出过程必须 **异步或可中断等待**，用户能看到 **进行中 / 成功 / 失败** 结论；失败时提供 **原因归类级** 说明（无需暴露底层技术栈）。
- **FR-006**: **任务中心** 仅展示导出任务的 **通用任务信息**，时间线细节留在剪辑视图（与现有产品边界一致）。
- **FR-007** *(P2)*: 系统应支持对单个成片片段配置 **入点/出点**，并在导出中生效（与 User Story 4 对齐）。

### Non-Functional Requirements *(if applicable)*

- **NFR-001**: 剪辑视图加载与保存编排的交互应具备 **合理超时**，避免长时间无反馈。
- **NFR-002**: 权限与租户/项目隔离须与现有工作室能力一致；用户仅能访问其有权限的章节与素材。
- **NFR-003**: 成片导出应具备 **防误触与可理解的任务状态**，避免同一章节在短时间内产生多套无法区分的成品而又无列表可查。

### Key Entities *(if applicable)*

- **章节（Chapter）**: 剪辑归属的业务容器；用户按章节进入剪辑。
- **镜头（Shot）**: 生成成片的来源；剪辑时间线上的逻辑单元之一。
- **时间线草稿（Chapter Timeline Draft）**: 绑定章节的一条或多条持久化编排状态，包含片段顺序及（P2）裁剪信息。
- **时间线片段（Timeline Segment）**: 指向某一成片文件或镜头成片引用，带有轨道/顺序及可选裁剪元数据。
- **章节导出成片（Chapter Master Export）**: 导出任务产生的成品视频文件记录及其与章节的关联。

## Out of Scope *(if applicable)*

- 多轨道专业剪辑（多视频轨复杂合成、关键帧动画、高级调色、贴纸模板商城级能力）。
- 在剪辑视图内直接发起 **新的 AI 视频生成任务** 或调试生成参数（仍由分镜工作室承担；剪辑侧至多提供「跳转去生成」类入口）。
- 自动对白字幕轴生成与对齐（可作为后续独立规格）。
- 跨章节一键合并为「电影级」单文件（除非后续单独立项）。
- 实时多人协作编辑同一时间线（本期至多采用简单并发策略，见 User Story 2 Edge Cases）。

## Resolved Decisions *(来自前置产品规划对齐)*

以下结论用于消除范围歧义；若与干系人后续评审冲突，以评审更新为准：

- **归属粒度**：时间线与导出成品默认绑定 **章节**；不要求本期支持「项目级跨章节一条时间线」。
- **入口策略**：剪辑能力与现有「视频编辑」意图合并为 **章节剪辑** 主路径，避免多处半截页面并存。
- **MVP 裁剪**：**User Story 1–3** 为第一期必须交付；**User Story 4（trim）** 为第二期增强。
- **并发编辑**：同一章节时间线若发生冲突写入，本期优先采用 **「以后保存为准并提示覆盖风险」或「仅允许单编辑者」** 其一（实现阶段在计划中二选一并落地文案）。
