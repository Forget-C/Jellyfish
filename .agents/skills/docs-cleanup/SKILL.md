# 文档审计与清理

使保留文档准确表达适用版本、当前行为、有效决策与真实待办。以证据决定取舍，不设删文件数量、保留篇数或节省体积目标。

## 授权与范围

先从用户请求和已有确认确定工作模式、目录范围及保留约束。Jellyfish 文档归属与内容要求统一读取[文档规范](../../../docs/development/standards/documentation.md)；复核既有清理授权或调整技能配置入口时，再读取[项目边界](references/project-boundaries.md)。日常新增与更新使用 [docs-maintain](../docs-maintain/SKILL.md)。

- **审计／方案**：“检查、整理建议、列名单、先别修改”只允许读取与汇报。未经请求，不新建报告文件、不改元数据、不移动或删除文件。
- **执行**：“按已确认方案清理、合并、删除”等授权允许处理其范围内的具体条目及必要文档引用。沿用已确认名单和策略，不重复索要许可。
- 普通“整理文档”若未明确允许删除，先完成可核实的清单，针对实际删除项确认；skill 被加载本身不构成删除授权。
- 使用用户指定的工作树、位置与提交方式；创建工作树、提交、推送、部署不是本 skill 的自动步骤。保留既有未提交修改，不把他人的修改混入清理。

范围仅包含文档正文、目录导航和经核实归属于文档的附件。代码、测试用例／快照、迁移、配置、数据库与真实业务文件不因文档删除而一并清理；被应用或测试消费的“示例文件”也属于这条边界。可以读取这些内容验证事实与引用。需要修改授权范围外的文件才能安全完成某项删除时，保留该项并说明依赖；其他独立项继续。

## 形成删除证据

1. 清点源文件，区分正文、索引、附件、生成产物和依赖缓存。相同标题、文件名或文本相似度仅用于发现候选；不扫描构建目录后把复制页面当重复源文件。
2. 对候选读取相关正文，查替代关系、当前调用入口、类型／接口、测试和适用决策。代码可证明工作区实现，不能证明已部署、生产验收或产品效果。发现代码与规范冲突时定位差异；不能为了让文档“符合代码”把尚未修复的缺陷改写为预期行为。
3. 先确定读者和用途，再逐文件／章节区分：当前事实、仍支持的旧契约、历史过程、已确认未实施决策、未排期提案、独有约束和验证限制。混合文档按章节或段落拆分后选择目标位置，不能整篇套用 frontmatter 状态。用户操作、开发规范、已确认设计和当前架构分别归属；已确认但未实现的设计标明状态，不能冒充当前行为。
4. 给出可审阅的处置表：`源文件 → 处置 → 事实依据 → 独有内容去向 → 引用／附件依赖 → 删除前条件`。简单条目可合组，但成员及前提须明确；审计模式在此交付。

“完成”“过早”“无引用”“已有新版”“Git 可恢复”都不是单独成立的删除理由。日期仅作检索线索；用户明确给出日期界限时，用它限定候选，再检查独有有效内容和受保护记录。对已完整替代的内容也不因年代较近而强制保留。

## 处置判定

| 内容状况 | 处置与边界 |
| --- | --- |
| 当前实现或仍支持版本的唯一说明 | 保留并修正适用范围；旧入口仍受支持时，不因新入口存在就删除契约 |
| 同语义、同适用范围的重复正文 | 选定权威来源，合并差异后删重复文件；不同读者用途的操作指南、架构与参考不因主题相同强行合并 |
| 被完整替代且没有独有有效内容 | 可进入删除清单，注明替代证据；纯旧过程可无替代页，直接移除导航 |
| 旧正文含有效约束、决策理由、迁移／回退边界或验证局限 | 先迁移到合适文档，核对含义和引用后再删旧文；不能只加一个链接就视为已迁移 |
| 仍有明确剩余事项 | 对照实现核实，默认保留待办与依赖；用户已明确决定删除的提案、进度和任务清单按确认范围删除，先提取仍有效的约束与能力限制。保留的未实现增强标为提案，不自动承诺实施；已淘汰架构上的待办可进入删除清单 |
| 已完成且仍是当前一代关键依据 | 保留必要决策与验收边界，压缩过程；不要求保留整条演进链，被完整替代后重新评估 |
| ADR、发布说明、迁移／回退说明或必须保留的审计记录 | 默认保留其历史用途和适用版本；公开发布说明只修本次失效引用，不把历史改写成今天的行为。删除或改写须有该类内容的明确授权或适用保留规则 |
| 占位页、空壳或只剩重复摘要 | 有明确用途时补成可用索引，否则移除；有入链时同时处理导航与引用 |
| 证据矛盾、部署未知、用途不明 | 保留或明确标“待核实”，列出具体缺失证据；不将未知改成已完成／已废弃 |

**某项删除可执行的条件**：范围已授权；用途已失效、有效内容已完整承接，或用户明确放弃该提案／过程记录／任务清单且其中仍有效的约束已有承接；保留要求已满足；保留引用及依赖已有可执行的处理方式；当前文件状态仍与核查时一致。未满足的条目不进入批量删除集合。

## 链接、路径与附件

涉及移动、改名、删除正文或附件时，读取 [链接与附件核查](references/links-and-assets.md)，按实际站点路由和引用闭包操作。

网址策略由本次任务决定：复用已有明确选择。没有兼容要求证据时，不把“曾经允许改网址”当作跨项目许可；公开入口的兼容性未知且影响删除时，先保留地址，或针对候选确认。用户明确无需兼容时可改路径、删除旧入口，并更新所有可控制的保留引用，无需额外创建跳转页。

## 实施与验收

- 写入前核对工作树与候选最新状态；遇到并发修改重新评估受影响项，避免用旧清单覆盖新内容。
- 先承接独有有效信息，核对新位置的适用范围与表述，再更新引用、删除正文，最后清理经核实失去用途的附件。保留可检查 diff；局部修改不顺手统一全站排版或文件末尾换行。
- 按读者和知识职责承接内容，用户指南与开发设计不因主题相同强行合并。迁移时按任务范围补足已有操作的前提、步骤、结果和限制，不自动扩展为全产品手册或承诺新功能。
- 历史过程与提案的取舍按当前授权判断；有效知识有明确承接，不自动为删除项新建计划或归档。
- 涉及 AGENTS、技能索引或项目配置时，先核实消费它们的技能和读取入口，保留必要配置及最小导航，并同步迁移引用。路径修复不等于重跑初始化、升级技能或改写第三方工作流的授权。
- 修复“承接某旧计划”“验证记录保留”“见下文”等语义引用，不仅替换网址。标题、链接文字、锚点与实际目标内容必须一致；已删证据不能继续声称可查看。
- 验收以范围为准：变更清单与授权逐项对照、有效信息去向核对、源链接及构建产物的页面／资源／锚点检查、站点完整构建；展示或导航变化时预览代表页面。纯文档工作不为形式完整而运行无关应用测试，额外项目检查按适用规则执行。
- 检查失败时定位是变更引入还是基准已有。修复本次引入的问题；对依赖失效、既有警告或无法运行的检查说明限制，不能用“构建成功”代替语义和引用验收。

完成报告列出实际保留／合并／迁移／删除范围、网址策略、验证结果及仍保留待核实的条目。明确是否提交或发布，不把本地完成说成已经上线。任务未授权的部署、重写 Git 历史或远端永久删除不在完成动作中。
