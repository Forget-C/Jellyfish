# Jellyfish 文档边界

在本项目判断文档归属、处理进度／提案或调整技能配置入口时使用。这里区分长期归属与一次清理的授权；先应用用户当前指令及项目现行约定。

## 长期内容归属

项目入口见 [AGENTS.md](../../../../AGENTS.md)，开发规则以[开发规范](../../../../docs/development/standards/development.md)为准。下表用于选择内容去向，不要求创建空目录或补齐所有功能文档。

| 位置 | 内容与边界 |
| --- | --- |
| `site` | 面向普通产品用户的官网、产品说明、操作指南、常规安装部署／配置升级、用户参考和发布说明。自行部署者也是产品用户；开发入口仅保留环境准备、启动、基本检查与进一步阅读 |
| `docs/development/standards` | 开发与协作规范，包含真实适用范围和必要例外，不附按组件登记的实施进度 |
| `docs/development/design` | 已确认设计；尚未实现的部分明确状态，不表述为当前能力 |
| `docs/development/architecture` | 当前生效的模块、数据、状态和协作边界 |
| `docs/development/adr` | 重要决策的背景、取舍与后果，保留编号和历史语义 |
| `docs/development/guides` | 详细开发、调试、维护、历史数据修复及迁移演练步骤 |
| `docs/development/reference` | 接口、字段、协议、配置及专业输出契约等技术查询资料 |
| `docs/agents` | 技能需要的项目级任务系统、分诊标签和领域文档配置；根目录 AGENTS 保留条件明确的简短入口 |

混合文档按章节拆分。常规产品升级说明可留在官网，代码级调试与特定历史数据修复进入开发指南。规范例外说明当前适用范围；未来接入任务是否保留按任务授权判断，不把例外重新写成待办队列。

## 技能与任务记录

任务系统、标签和领域布局分别读取现有的 [issue-tracker](../../../../docs/agents/issue-tracker.md)、[triage-labels](../../../../docs/agents/triage-labels.md) 和 [domain](../../../../docs/agents/domain.md) 配置；不在本技能复制其操作协议。

`.scratch` 由现有 mattpocock 技能工作流使用。文档清理不自动向其中迁入站点历史进度，不为它增加项目自定义台账、生命周期规则或 AGENTS 声明。保留 AGENTS 中指向上述必要配置的入口，与保留历史进度是两件事。已有任务记录保持原状，除非当前任务明确授权修改。

## docs-audience-separation 清理的授权边界

以下只解释已确认的[清理规格](../../../../.scratch/docs-audience-separation/spec.md)，用于复核该范围；不构成今后新增内容的自动删除许可：

- 当时纳入范围的站点历史进度、开发流水账、阶段完成清单及过时执行／验收过程直接删除，不新建归档，也不迁入 `.scratch`。
- 当时纳入范围的未排期增强提案删除，不转写为设计待决事项；已确认设计保留并标明实施状态。
- 当时纳入范围的按组件登记的工程迁移清单删除；标准的真实覆盖范围、必要例外和有效约束保留。
- 数据保护、备份、迁移／回退边界、仍受支持的旧契约及当前能力限制仍须承接。删除提案不表示能力已经实现，删除进度不表示工作已经完成。
- 当时受影响的网址无需兼容旧路径；保留引用同步更新。新清理任务仍按其授权确定网址策略。

以后新增的提案、任务或记录不能仅凭上述历史决定删除；先确定当前任务范围与适用保留规则，再按通用删除证据判定。
