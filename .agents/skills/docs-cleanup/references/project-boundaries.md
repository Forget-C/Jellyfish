# Jellyfish 清理边界

长期目录职责与内容要求以[文档规范](../../../../docs/development/standards/documentation.md)为准。本页仅补充技能配置依赖和既有清理授权的适用范围。

## 配置依赖

涉及 AGENTS 或 `docs/agents/` 时，核查现有消费技能，保留必要项目配置及条件明确的简短导航。文档迁移只修复受影响的引用，不授权重跑初始化、升级技能或改变第三方工作流。

## docs-audience-separation 清理的授权边界

以下记录该轮已确认的清理取舍，仅用于复核当时范围；不是今后新增内容的自动删除许可：

- 当时纳入范围的站点历史进度、开发流水账、阶段完成清单及过时执行／验收过程直接删除，不新建归档。
- 当时纳入范围的未排期增强提案删除，不转写为设计待决事项；已确认设计保留并标明实施状态。
- 当时纳入范围的按组件登记的工程迁移清单删除；标准的真实覆盖范围、必要例外和有效约束保留。
- 数据保护、备份、迁移／回退边界、仍受支持的旧契约及当前能力限制仍须承接。删除提案不表示能力已经实现，删除进度不表示工作已经完成。
- 当时受影响的网址无需兼容旧路径；保留引用同步更新。新清理任务仍按其授权确定网址策略。

以后新增的内容不能仅凭上述历史决定删除；先确定当前任务范围与适用保留规则，再按通用删除证据判定。
