# 链接与附件核查

在移动、重命名或删除任何正文／附件前使用。本文件补充引用与资源边界，不授权新的删除范围。

## 引用不是文件名搜索

建立源文件身份与实际路由的映射，优先使用站点生成器的链接解析能力。核对：

- Markdown 链接、图片、引用式链接、HTML 的 `href`／`src`／`srcset`、模板与短代码。
- 导航配置、frontmatter 中的 slug／url／aliases、数据文件、CSS 资源及 JSON manifest。
- 保留的 HTML 报告、对比页面、下载清单及包内引用。
- 仓库内文档范围外的使用方：测试、代码、构建配置等只读核查；有使用方的文件不能按“文档孤儿”删除。

按源文件目录或构建后的路由解析相对地址，不混用两者；识别 index／目录页、扩展名、URL 编码、查询串与 fragment。相同 basename、字符串子串匹配或一次 `rg` 无结果只能提供线索。动态拼接、目录扫描、约定路径或无法解析的引用属于未核实边，保留涉及资源并报告具体原因。

外部链接不为本地清理顺带重写。若已知外部消费者引用当前公开地址且用户尚未决定兼容策略，先保留入口或只阻塞该地址变更。不能声称本地搜索证明没有外部入链。

## 移动与合并正文

维护明确的 `旧路径／路由／锚点 → 新位置或删除` 清单：

- 合并目标必须真正承接被引用的语义。旧验收报告删除后，不把名为“验收证据”的链接泛化指向无证据的架构首页。
- 保留必要章节时更新深链接；删除章节时删除失效论断或指向准确承接处，而非盲目去掉所有锚点。
- 先规范信息归属，再选择名称。当前行为和历史接口并存时，在标题及正文说明适用范围；历史契约页不能夹入正在使用的新界面规范。
- 用户要求不兼容旧网址时，清除受影响的旧 aliases／重定向与导航项；只处理本次涉及的路径，不顺带删除全站其他重定向。
- 发布说明的事件、版本状态、日期和结论保持原样；只修改本次被删除目标的引用或必要的引用说明，不用新文档冒充原始历史证据。

## 附件可删除的判据

附件须同时满足：

1. 属于已授权清理的文档或其证据包，而非共享业务资源。
2. 在保留正文、导航、模板、代码、测试和仍保留报告的传递引用中不再可达。
3. 不承担独立保留用途，例如当前版本唯一验收证据、产品展示、下载内容或明确保留的发布附件。
4. 核查没有留下会影响该附件判定的未解析引用。

计算引用可达性时以**保留的使用方**为起点，沿 HTML、CSS、JSON 等资源继续遍历。已删除报告内部的互相引用不构成保留理由；孤立资源循环也不能自证有用途。一个仍使用的报告依赖的 manifest 和图片必须一起保留，即使 Markdown 没直接引用图片。

精确列出待删除文件，再删除空目录。资源包部分仍被使用时，仅删除已核实的独占项；有疑点则保留该项，不以目录年龄或“一整包更方便”为依据。符号链接检查引用及真实目标归属，不能跟随链接越过授权根目录删除内容。

构建目录、缓存和生成快照不是正文重复项：只有明确纳入产物清理且确认可重建时才处理，不能顺带清理用户导出或非版本控制文件。无 Git 记录的新文件尤其需要核实来源和归属。

## 验证闭环

- 源检查：被删文件的保留引用已经迁移或移除，必要独有内容确实可定位，作用范围没有扩大或缩小。
- 构建检查：使用干净的临时输出目录或安全的清理选项，避免旧 HTML／资源残留掩盖缺失；清理选项仅作用于本次可重建输出目录。
- 产物检查：页面目标、资源目标、fragment 锚点分别核实。HTML 构建通常不会因为普通坏链接失败。
- 差异检查：正式发布正文、代码、数据与无关文件未被格式化或删除；额外修改均能解释与清理的直接关系。

构建不可用时可完成独立的源检查，但必须说明未验证的路由／资源范围。无法证明附件用途已消失时，保留附件，不把验证失败解释为删除依据。
