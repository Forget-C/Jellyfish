# 生成画布的组件与协议边界

2026-10-23 已确认的设计，尚未实现。沿用 [独立生成画布的行为基线](0001-independent-generation-canvas.md)，将卡片类型契约、编辑状态及运行状态分别归属，以支持共享输入组件、稳定引用及后台执行。模块职责、数据结构分工、保存修订、预检提交、请求幂等和诊断定位协议已确认。文本流式返回、增量持久化、断点恢复、未完成文本保留，以及统一推送运行状态、阶段、文本与结果的事件流协议均已确认。

## 类型定义与展示

后端的 `CardDefinition` 使用轻量基类，由具体卡片类型扩展稳定类型标识、类型版本、输入输出端口、配置结构、校验与编译规则。模型能力独立描述所选模型支持的输入模态、参考用途、数量与组合限制，以及参数范围；卡片类型不随每个供应商模型复制一份。

前端通过 `rendererRegistry` 将类型映射到明确的内容展示、编辑组件和参数栏。前端依据后端契约提供连线提示及参数选项，后端负责最终校验。视频模型卡具有统一契约，选择不同模型后，其可用参考用途和参数范围随实际接入能力变化。

## 前端职责

以下名称表示设计中的职责，不表示现有组件已完成抽取：

```text
GenerationCanvasPage
├─ useCanvasEditor          编辑、保存、连线、运行命令
├─ CanvasToolbar
├─ CanvasSurface            视口、拖动、框选、连线手势
│  └─ CardShell             标题、状态、端口、菜单
│     ├─ ContentRenderer    文本、图片、视频、音频
│     └─ ModelRenderer
│        ├─ ResultSetView
│        └─ GenerationComposer
│           ├─ ReferenceEditor   正文、引用、系统指令
│           └─ ParameterBar     模型选择、类型参数、运行按钮
├─ ReferencePicker
└─ ResultViewer
```

卡片及输入组件接收数据，通过回调报告编辑。保存、能力读取和任务同步集中在画布级模块；光标、菜单开合等临时状态留在组件内部。参数栏由各类型提供明确组件并复用共同控件。删除提示词中的引用只改变实际使用关系，已有候选连线仍保留，不能把编辑器内容与候选连接混成同一份状态。

现有 `Canvas` 基础组件可复用视口、卡壳和拖动等能力；现有 `GraphCanvas` 尚无完整的端口身份及连线编辑接口。`ExperimentComposer` 可参考其受控输入和底部参数布局，现有文本编辑器尚不提供画布需要的引用与指令编辑。接入时应复用这些明确能力并新增缺失部分。

## 后端职责

| 模块 | 职责 |
| --- | --- |
| 画布业务模块 | 文档保存、引用解析、模型能力校验、运行范围计算、节点依赖调度及结果归属。 |
| 现有任务模块 | 沿用单个生成任务的提交、状态、取消、执行及产物归档，保持既有调度、状态机、取消与恢复行为，不增加任务可恢复保证。 |
| 供应商 Adapter | 将标准生成输入转换为供应商请求，并转换返回结果。 |

具体卡片类型提供校验、输入消费和编译规则；整个图由画布运行模块统一调度。前端提交运行意图，后端决定实际执行与复用的节点，并遵守单卡、运行到目标和严格框选的行为基线。API 层负责收参、鉴权及响应组织，业务逻辑留在 service 层。

画布事件的断线重放及状态读取用于恢复显示，不承诺中断任务能继续执行；不以统一事件流为由新增任务恢复体系。运行中的任务使用已确定的输入和执行配置，画布内容及模型配置修改不应改写其执行依据，也不增加监听模型或供应商配置变更的独立机制。

已有文本、图片和视频生成 DTO 作为编译后的执行输入。画布需新增自己的任务目标和结果交付路径；当前文本任务的结果交付绑定实验室会话，媒体交付也依赖现有业务目标，不能仅替换界面。既有提交器冻结了部分输入与模型身份，但文本执行仍读取当前模型参数，媒体查询仍读取当前供应商配置。允许在输入与执行适配层局部调整配置读取，使用固定的有效参数与供应商路由，以满足执行依据冻结要求；不改造任务调度、状态机、取消或恢复机制，也不新增配置变更监听。

跨层生成契约放在 `app/core/contracts`，任务模块保留任务封装与编排，供应商适配仅依赖通用 contracts。普通 HTTP 接口通过 OpenAPI 同步生成前端 client。

## 输入文档协议

编辑内容保存为轻量的 `PromptDocument`，保留普通文本、稳定引用及系统指令，不以最终提示词字符串代替用户的编辑内容，也不保存某个编辑器库的内部数据格式。

| 内容类型 | 保存的信息 |
| --- | --- |
| 普通文本 | 用户原文。 |
| 引用 | 来源卡身份及稳定输出标识。 |
| 系统指令 | 指令标识、主体名等参数及输出引用。 |

来源卡维护自身稳定输出标识，关联输出端口和结果位置，新增输出由来源卡触发。协议以不可变的来源卡 ID、输出端口标识和来源内结果位置组成输出身份，在所属画布内唯一；“卡片N-图片N”可用于说明来源，不以可变卡片名称或界面排列序号作为身份。来源重新生成时仍按对应输出位置解析当前结果，固定某次产物继续使用结果集及产物身份。

接收端按自身同模态输入顺序显示“图片1”“图片2”等输入代号，同一来源输出在不同接收端可以有不同简称。选择窗插入与完整手动输入均将当前接收端代号解析为来源稳定输出标识，保存引用身份，不仅保存显示字符串。未完成输入可原样保存，执行前提供诊断。后端校验文档、来源输出引用及连线关系，再编译提示词及媒体参数。引用文本展开后作为数据处理，不再次触发引用或系统指令。

同一来源输出在同一接收端只有一个代号，不因重复引用或不同用途绑定增加候选项；不同来源身份即使对应相同文件也不合并。完全相同的来源端口与目标端口不重复建线。通用图片输入按来源输出身份去重，同一文件来自不同来源且均被引用时按两项提交；模型禁止重复素材时返回诊断，不静默按文件身份合并。

手动输入期间仅检索、定位候选；选择候选、Enter 或 Tab 确认、明确分隔符或编辑框失焦时才解析完整代号，不将 @图片10的前缀 @图片1提前绑定。中文输入法组合期间不转换，未匹配内容保留并诊断。选择及手动输入均不得为尚未实际提供内容的未来位置建立引用；预先连线不等于提前引用。

接收端输入顺序变化时，已形成的结构化引用按其原有输出身份显示对应代号，不能按旧编号重新绑定另一份内容；新输入的代号按当前顺序解析。普通文字不因代号展示变化而自动改写。

来源当前结果减少时，仍被实际引用的缺失输出保留接收端占位及来源身份，参与输入代号编号并阻止依赖它的执行；未被引用的消失项可移除。清理最后一个引用后可移除占位并重新编号，已有结构化引用仅更新显示代号；来源再次提供同一输出位置时恢复解析，不建立新引用。

缺失输入预检不能因所选范围包含上游、或上游声明将生成该位置而放行。先独立补齐来源，再提交依赖它的运行；仍有内容但依据已变的已绑定输出，可以继续按运行到目标的规则执行上游，并使用该次流程的新结果。

同一画布内复制提示词中的结构化引用时保留来源身份，在目标接收卡中显示对应的本地代号。目标卡尚未连接该来源时，明确标记来源未连接，由用户连接或重新选择，不自动创建连线，也不按同名代号绑定另一份内容。结构化剪贴内容携带来源画布身份；来自另一画布时显示“来源属于其他画布”，要求重新选择本画布来源，不建立跨画布动态引用、不自动复制来源卡，也不绑定目标画布中同名的输入代号。来自外部的纯文本不携带来源身份，按目标卡当前代号执行与手动输入相同的解析。这一规则仅约束输入编辑器的复制粘贴，不增加卡片或子图复制功能。

来源输出信息随结果更新，接收端依据来源信息及自己的输入顺序展示候选项和代号，已有引用保持来源身份，不通过结果到达改写引用目标。连线断开或来源卡删除前须校验下游实际引用；存在引用时拒绝操作并返回原因及引用位置，不能自动删掉用户的引用来完成操作。

编译器维护接收端输入代号、来源稳定输出身份与实际提交媒体位置或用途之间的对应关系。通用参考图片按接收卡输入顺序选出实际使用的子集，关键帧等有序用途保留指令顺序，再按模型适配能力编译引用表达及媒体参数。最终输入预览展示实际文本和媒体对应关系，编辑文档保留原结构化引用；不以局部显示代号直接代表供应商请求中的数组位置，也不猜测普通正文中的同名字样。

## 文档、运行与结果

| 协议对象 | 归属内容 |
| --- | --- |
| `CanvasDocument` | 卡片、连接、分组、模型配置、输出引用及提示词文档。 |
| `CanvasRun` | 本次运行范围、固定执行依据、各节点状态及关联任务。 |
| `ResultSet` | 一次节点执行的完整有序产物及来源信息。 |

卡片当前输出指向哪个结果集另行维护。后台任务进度及结果到达不改写当前编辑内容，不推进内容保存修订。位置、尺寸和视角继续采用独立的本地布局保存机制。保存状态仅表达当前画布内容是否已保存，不引入独立草稿对象或发布流程。

运行开始时，复用的已有输入固定到具体结果。已建立且对应内容存在的引用若来自本次要执行的上游，则固定到该上游节点与来源输出位置，待它完成后形成下游任务的具体输入快照；不因禁止提前引用而改为消费旧结果，也不能读取其他运行或后续编辑产生的内容。尚无实际内容的未来位置不能先建立引用，已有引用缺失时也不能以本次将生成作为放行依据。

## 保存修订

首版以完整 `CanvasDocument` 保存，提交 `request_id`、`expected_revision` 和 `document`。服务端仅在当前内容修订匹配时写入并返回新修订；版本不符返回 HTTP 409 和业务错误码 `REVISION_CONFLICT`，前端保留本地编辑并进入冲突处理。`schema_version` 表示文档格式版本，`revision` 表示内容修订，两者分别演进。

保存期间继续编辑时，回包只推进已保存基线，不覆盖请求发出后的编辑；这些后续编辑仍待保存。运行进度、结果及本地布局变化不推进文档修订。

前端按当前编辑内容检查断线及删除所需的引用清理，允许清理引用、断线或删卡后一次保存。服务端以完整文档的最终引用关系及 `expected_revision` 校验，不要求清理动作已经单独保存，也不要求操作日志证明点击顺序。

## 预检与提交

运行采用“保存当前编辑快照 → 服务端预检 → 携带 `preview_token` 提交 → 返回 `run_id`”的顺序。保存失败时不以旧内容代替当前编辑启动运行；预检或提交失败时，已经保存的编辑内容仍保留。

预检返回将执行的节点、复用的结果、阻塞问题，以及已能确定的提示词、媒体和参数。已建立且对应内容存在的引用，其上游若在本轮执行，新内容明确标为待本轮上游完成后解析；这不允许引用未曾提供内容的未来位置，也不放行当前缺失的引用。上游完成后，在调用下游模型前按固定依据完成解析与校验。

`preview_token` 绑定文档修订、运行范围、实际使用的输入结果及有效模型配置。提交时服务端重新校验这些依据，并检查执行节点是否被其他运行占用。依据变化返回 `PREVIEW_STALE`，范围冲突返回 `RUN_SCOPE_BUSY`；前端更新预检后再提交。预检不启动生成、不预占执行节点，提交成功后才持久化运行快照。

尚未提交运行时，任何需要保存的内容编辑立即使已有预检失效，不等待自动保存推进服务端修订。保存并重新预检后才能提交，迟到的旧预检回包也不能恢复提交资格。独立保存的布局及视角变化不使预检失效；已经提交的运行继续使用固定依据，不受后续编辑影响。

## 请求幂等与回执

保存及运行提交均持久化请求身份、请求内容摘要和原始回执。相同 `request_id` 和相同内容返回原保存回执或原 `run_id`；同一 ID 携带不同内容返回 HTTP 409 和业务错误码 `IDEMPOTENCY_CONFLICT`。每次独立的执行意图使用新的请求身份，提交接受后创建新运行。

响应丢失时，前端保留原请求身份及内容，通过回执查询或原请求重放核实；暂未查到回执不表示可以换新 ID 重复提交。回执去重与业务写入在同一事务中完成，已成功请求的重放返回原回执，不因后来的内容修订变化被当作新请求拒绝。

这保证应用侧同一请求不重复创建运行。供应商提交结果不明时，仍须按适配器能力查询或去重，不能直接更换请求身份重复生成。

## 统一执行与运行状态

前后端只提供统一的执行和取消命令，不设置首次运行、重新运行或重试的业务状态、专用接口或模式字段。单卡、运行到目标及框选仅表示执行范围。每次执行均使用当前保存并预检通过的配置，形成独立的 `CanvasRun`，不将历史运行的终态重置为运行中；同一请求的传输重放仍按幂等规则返回原运行。

用户通过卡片显示的状态、执行依据和结果决定是否执行或取消。实际执行状态由后端维护并通过统一运行事件流同步，前端不根据是否存在历史结果推断本次状态。用户主动执行仍须满足输入、模型能力、预检依据及运行范围占用校验；已有输出与本次执行状态分别展示，失败或取消按行为基线保留旧结果。

节点使用统一状态：

| 状态 | 含义 |
| --- | --- |
| `waiting` | 等待本次运行中的上游，尚未提交生成任务。 |
| `queued` | 生成任务已提交，等待执行。 |
| `running` | 正在执行，生成、归档等细节由阶段字段表达。 |
| `succeeded` | 完整产物已经归档并交付。 |
| `failed` | 本节点执行失败，或提交任务前未通过自身校验。 |
| `cancelled` | 本节点被明确取消。 |
| `blocked` | 必要上游失败、取消或画布流程已确认中断，本节点未执行；保留具体原因。 |

`blocked` 是本次节点执行的终态，与仍可等待上游完成的 `waiting` 分开。复用已有有效结果单独标记，不计为本次新执行成功的节点。

画布流程确认中断后，尚未创建任务的节点结束等待，不自动重新提交。已创建任务仍服从现有任务状态，浏览器断线不构成流程中断。节点在提交任务前校验失败时，以自身失败结束并阻止必要下游；不存在活动任务和仍可执行的节点后，画布运行结束并释放范围占用。这是画布编排的退出规则，不增加现有任务的恢复保证。

画布不再将整次运行归类为成功、部分成功或失败，用户通过各卡片状态和结果判断执行情况。运行层只保留执行范围、关联任务及生命周期所需信息；节点状态仍用于展示和判断依赖是否可以执行，不要求现有任务体系改变成功、失败等状态定义。

## 取消范围

取消单个节点只停止该节点，并使依赖它且尚未执行的后续节点以 `blocked` 结束；独立分支继续，已经完成的上游产物保留。例如 A → B → C 与 X → Y 并行时，取消 B 后 C 被阻塞，X、Y 继续。

取消整次运行时停止调度未启动节点，并请求取消正在执行的任务，保留已经完成的产物。前端在请求已接收但尚未获得终态时显示“取消中”，不自行宣布节点或运行已取消。

取消沿用现有任务机制，保留已经持久保存的成果；取消发出后的迟到结果按现有任务机制处理，不额外保证供应商立即停止，也不新增补抓结果或取消竞争裁决机制。运行未结束前仍遵守原有执行范围占用约束，不因前端点击取消立即放开重叠执行。

## 诊断定位

统一诊断使用稳定问题码 `code`、展示等级 `severity`、说明 `message`、定位 `target` 及阻断动作 `blocks`。定位包含相关卡片、连线、端口、输出引用或提示词片段的稳定 ID，以及必要字段路径；阻断动作明确区分保存与运行，不仅依靠严重等级推断。

诊断绑定被校验的文档修订或请求快照。前端可直接定位对应卡片及引用，旧快照产生的诊断不继续贴到已修改的正文上。

空内容、缺模型、未完成指令及能力不匹配等允许保留的编辑状态可以保存，并按需阻止运行。文档结构损坏、自环或循环等违反图结构约束的问题阻止保存。预检请求正常完成但发现问题时，正常返回诊断及 `can_run=false`；请求本身失败时沿用统一 HTTP 错误外层格式，在类型化 `data` 中补充业务错误码与诊断，前端不反解析文案。

模型切换后保留的不兼容候选若未被正文、系统指令或专用输入配置使用，只提示当前不支持，不阻止运行；实际使用的不兼容输入、提交数量超限及无效生成参数才阻断相应执行。新建不兼容连接仍拒绝，保留现场不等于允许自动删除引用或静默转换输入。

## 文本流式返回

文本模型卡须支持在生成过程中逐段接收并显示新增正文，而非等到全部生成完成后才展示。增量片段可以包含多个字符，不要求以单个字或 token 为显示单位。

该能力仍须遵守刷新或离开页面不取消后台运行、成功后才更新正式结果集，以及下游按明确运行范围使用结果的行为基线。卡片可以展示生成中的正文，但正式输出仍在完整成功交付后按既定规则更新。

累计正文和有序增量持久化保存，支持断点补齐。刷新或短暂断网后先恢复累计文本及游标，再补充后续片段，并按序号避免重复追加。旧游标无法继续使用时，重新读取累计文本，不重新生成。增量可以按小片段合并后持久化、推送，无须逐字写入数据库；恢复的是显示和订阅，不创建新的模型请求。

生成失败或取消时，已经返回的文本保留在本次运行历史中，明确标记为“未完成”，允许复制或显式保存为文本内容卡。未完成文本不替换原正式结果集，也不自动供下游使用；显式保存后成为独立内容卡，并保留来自未完成运行的来源信息。

## 统一运行事件流

生成画布通过统一的服务端事件流（SSE）接收运行状态、阶段、文本增量及结果，作为这些运行信息在前端的唯一实时数据来源，替代状态和结果轮询。文本增量属于事件类型；生成中、归档中属于运行阶段，接收文本增量时节点仍可处于运行状态。

| 事件 | 返回内容 |
| --- | --- |
| `snapshot` | 初次连接或恢复时的运行状态、累计文本、已有结果及游标。 |
| `node.updated` | 节点状态、当前阶段及可用的进度信息。 |
| `text.delta` | 指定节点、指定输出位置新增的正文。 |
| `node.finished` | 节点终态、已保存成果清单、最终文本或文件引用，以及错误信息。 |
| `run.finished` | 本次运行结束的生命周期通知，不计算整次运行的成功等级；各卡片状态及结果由节点事件表达。 |

事件统一携带协议版本、画布身份、适用的运行及节点身份和恢复游标。一个打开的画布共用一条连接，承载多个运行；单个运行结束不关闭整条连接。统一流负责运行观察，保存、预检、启动及取消继续通过 HTTP 命令接口完成。图片和视频通过结果中的文件引用按需加载，不把媒体二进制内容放进事件流。

节点状态更新、结果登记和对应事件写入在同一数据库事务中完成，提交后才推送。成功事件表示对应结果已经完成归档与交付；终态事件携带该节点已保存的成果清单，且明确当前输出是否更新，前端无需另行轮询结果接口。

失败或取消节点的快照与终态事件也列出已经持久保存的成果，并明确其未完成来源及不属于正式结果集的身份。产物清单非空不表示任务成功；用户可预览或显式保存为内容卡，未完成成果不自动成为当前输出或下游输入。

快照与其游标构成一致的切点，随后发送该游标之后的已提交事件。断线补发允许重复，前端按游标去重；游标过期时发送新的完整快照。断流时前端保留最后确认的内容并显示连接恢复状态，不把运行改为失败、不自动取消，也不重新发起生成。

现有 API 与 Worker 共享数据库，首版可由后端追读持久化事件并推送，不必先引入消息中间件；后端内部的日志读取不要求前端发起周期查询。SSE 负责传输，事件持久化、重放及业务去重由应用协议实现。

客户端在统一传输层支持流式响应、恢复及事件归并，继续使用生成的接口与类型。任务中心保持现有独立状态通道，画布事件协议只负责当前画布，不要求任务中心迁移或改为消费画布事件流。两者可以复用底层传输、事件解析等通用组件，各自保持业务数据与订阅边界。
