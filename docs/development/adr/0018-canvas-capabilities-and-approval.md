# 画布能力协议与独立审批

画布助手现有的编辑预演同时处理模型工具参数与画布业务规则。后端重构将以一组进程内 Python `typing.Protocol` 描述两个画布完整的后端业务能力。普通后端调用方可直接使用这些协议，画布实现负责校验各画布支持的操作。

审批组件接收申请，校验决定方的权限，记录其对特定版本和改动组的决定。业务执行方消费有效决定，复核当前业务状态并返回执行回执。例如用户批准修改时长后又手动编辑了原值，审批记录保留批准事实，画布可返回字段冲突。直接编辑入口沿用自身授权策略。

实施分四阶段。先定义并验收完整画布协议，再抽出并验收独立审批组件，随后封装 Agent 所需的画布和审批工具，最后迁移 Deep Agents。运行时按角色授予工具权限。画布和审批实现可独立于 Agent 框架验证；适配层承担模型参数、工具结果与领域契约之间的转换。

审批版本与分组语义沿用[双画布助手的专业技能与批量修改提案](0016-canvas-assistant-skills-and-change-proposals.md)。会话恢复与事件展示沿用[实验室与画布助手共用交互会话协议](0017-interaction-session-protocol.md)。

## 能力分组与提交入口

画布协议按四组职责提供：画布生命周期与能力查询、编辑预演与提交、生成输入解析与编译、生成运行与结果查询。调用方可独立组合各组能力。两种画布按当前资源、卡片目录及模型能力校验可执行的操作。

编辑器直接编辑与助手提案共用操作的来源身份、绑定、重复判定和冲突规则。前者沿用直接保存入口，后者通过审批后应用。迁移按业务操作逐项进行，保留前端整份文档保存的现有契约。

## 通用审批请求

审批组件记录请求身份、幂等键、可信上下文中的申请方身份和资源作用域。业务方提供待审对象的类型、标识、不可变版本、可审批的分组标识，以及可按版本重读的展示快照引用。快照由业务方维护，保存用户看到的差异、影响范围、操作数量和必要的预览材料。

决定绑定到所见版本和选中组，记录决定方、动作与时间。被替代的版本不能接受新的有效批准。业务执行方回报实际执行结果，便于分别核对批准内容与最终效果。

## 工具装配与批准后的恢复

Agent 工具按创作任务封装，可以组合多个画布协议操作。首批覆盖画布读取、批量修改预演、生成输入检查，以及发起和查询审批。预演和送审是独立动作；纯文本模型与原生工具调用模型使用同一套领域操作。

人工和自动审批共用决定入口，由可信调用上下文提供决定方身份。按钮和明确指向审批卡的文字确认绑定到用户所见的版本与选中组。自动审批由服务校验授权和代码规则，结合独立审批 Agent 的复核签发决定。

批准记录成功后，业务执行方接续获批组，并发布执行结果供会话显示。创作问题可由 Deep Agents 保存检查点并恢复。画布审批和执行由业务组件衔接，创作图结束后仍可完成审批和恢复。中断恢复按同一决定和分组核对结果，只继续未完成的获批动作；其他待审组仍待审。如果执行所依据的来源已经变化，保留原决定，记录冲突并展示新差异。

## 升级策略与首个迁移切片

每批能力切换后只运行新协议。对于已经切换的能力，不保留旧提案执行分支、旧工具名适配器或旧检查点恢复分支。升级时可以直接移除与新协议冲突的数据。前述按决定和回执恢复的保证适用于新协议自身的中断与重试。

清理按冲突记录定位。未完成的旧提案、工具检查点及对应待处理状态可以清除；升级前打开的旧审批卡再次提交时，返回提案已失效并提示重新发起。部分审批的提案保留已生效组产生的卡片、连线和绑定，清除其余冲突的待审状态。

对于已受理或提交结果未确定的生成操作，保留任务、请求标识及可查回执。任务系统继续跟踪原任务，切换流程禁止重复提交。可直接读取的画布内容、素材、生成结果和普通对话正文原样保留。

首个迁移切片贯穿视频正文引用与角色主体图采用。先从普通后端调用方验证画布协议能预演、应用并编译出一份完整描述和正确角色图片；再验证画布工具返回相同的预演结果；随后验证部分审批与中断恢复只执行获批镜头；最后从自由画布和分镜画布的 Deep Agents 对话入口验收。可比较只读预演，每次写入与生成提交只走一个执行入口。
