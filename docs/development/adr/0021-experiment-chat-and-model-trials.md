# 实验室多模态聊天与单模态试模

用户既需要直接验证指定模型的表现，也需要在连续对话中组合多个模型完成创作。新建实验室会话时，默认的多模态入口用于聊天，现有文本、图片、视频入口用于对应模态的直接试模。实现见[生成实验室架构](../architecture/generation-labs.md)。

[既有会话协议](0017-interaction-session-protocol.md)要求实验室每轮独立输入，这项约定继续适用于单模态试模。多模态聊天可跨轮引用已有产物，例如用上一轮生成的图作为视频首帧。主聊天模型需要解读素材内容时，按当前供应商配置的[模型有效能力](../../../GLOSSARY.md)判断。把文件引用交给生成工具时，由执行模型校验其能否接受该用途的参考素材。

两种入口均预选相应模态的全局默认模型。多模态聊天默认展示主模型选择器，图片和视频执行模型可在折叠的模态配置中分别更换。选定某个模态直接试模时，页面展示该模态的模型选择器。会话中的选择沿用到后续调用；缺少媒体模型时，在需要该工具时选择。主模型只支持普通对话时仍可聊天，调用生成工具需要支持工具调用与结果回传的主模型。

实验室聊天使用通用系统提示词，由用户与 Agent 决定创作方法和生成数量。用户可用自然语言，也可用 `/imagegen`、`/videogen` 选定生成动作，继续填写要求、附加素材后发送。工具进度和产物在原轮次展示。有后续步骤依赖产物时，待文件归档后继续；用户只要求提交时，收到提交回执即可结束回复。停止回复结束本轮后续动作，已提交任务的取消由任务卡提供，以任务回执为准。

首期工具覆盖图片和视频生成。统一产物可表达音频，独立旁白和音乐生成留待接入相应供应商操作。画布助手继续按[画布授权与审批约定](0018-canvas-capabilities-and-approval.md)处理画布操作。

## 聊天与试模的调用边界

画布助手和实验室多模态聊天共用 Deep Agents 运行时，各自提供上下文、工具、技能、默认提示词和业务授权规则。主聊天模型通过 LangChain 适配器使用已登记模型的[供应商能力](0020-model-provider-protocol.md)。单模态试模直接调用选定模型，以便用户用指定输入和参数检验该模型的实际表现。

三个入口共用会话客户端、事件 API 和 SSE 订阅，以相同方式发送一轮、读取历史、按游标恢复进度和停止。事件分别表达文本回复、工具调用、任务受理、产物交付和失败。工具卡标出实际执行模型，展开后可查看本次参数、引用素材和任务回执。画布审批和助手追问使用对应的交互卡。支持原生流式的主模型按增量交付文本，仅支持完整回复的主模型在正文就绪时一次交付；两者都可及时显示运行期间发生的工具和任务事件。

## 活动轮次的发送规则

画布助手和实验室多模态聊天按会话限制发送。本轮正在回复、执行工具或等待生成结果时，页面禁用普通发送，服务端拒绝该会话的新消息，同时关闭「补充到本轮」和「下一轮处理」。其他会话可独立使用。断线后重试原请求沿用原轮次，避免重复调用模型或生成工具。

运行期间可以停止回复。助手暂停提问或请求审批时，用户通过对应的问题卡或审批卡操作，决定关联到原轮次。本轮结束即恢复发送。例如，用户要求只提交一个视频任务，拿到提交回执并结束本轮后即可发送下一条消息，原任务卡继续显示视频的生成进度。
