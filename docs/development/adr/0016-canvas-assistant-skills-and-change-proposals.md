# 双画布助手的专业技能与批量修改提案

沿用[双画布共用 Deep Agents 助手](0015-canvas-assistant-harness.md)的决定。同一个助手按任务组合五项专业技能：剧本拆解与画布规划、镜头与场面调度、图片生成指导、视频生成指导和成片审看。新增的规划技能负责把剧本拆成叙事节拍与镜头，识别可复用的卡片、待建卡片和所需连接。两种画布各自的卡片目录决定这些专业建议可以落到哪些元素上。

助手需要三类只读信息：当前画布的摘要和相关卡片详情、画布支持的卡片与操作、指定素材或运行结果的实际观察依据。读取能力既可供工具调用，也可由应用将结果提供给文本模型。技能加载与示例读取复用现有机制。

内容与结构修改采用统一的批量提案工具 `propose_canvas_changes`。一份提案可以新建或修改卡片、建立或解除关系、删除卡片，并引用同一提案中的新卡。服务复用现有领域校验，按依赖关系组织可独立生效的改动组。这样一组共享设定与多个镜头可以在创建前一起预览。实现需要为批内引用解析稳定目标，并在应用时核对依赖及最新字段值。

## 审批卡与业务事件

助手在提出建议的对话内展示审批卡，用户可展开改动、核对依赖、选择改动组、要求修订或拒绝。页面分别展示决定与执行结果：服务接受决定后显示已批准或已拒绝，收到对应执行方的回执后才显示已写入、已排好或已提交生成。组间可以分别出现已应用、待审批或冲突，冲突组展示原值、当前值和建议值。自动审批标明决定来源。重新打开面板从服务端快照恢复。

服务记录提案创建（`proposal.created`）、审批决定（`approval.decided`）、旧版本被替代（`proposal.superseded`），以及执行成功、受阻或失败（`execution.succeeded`、`execution.blocked`、`execution.failed`）。事件关联画布、提案及版本、涉及的改动组、事件身份、顺序和时间。决定记录决定标识、动作及来源，执行结果关联决定和领域回执。保存成功与写入回执在同一事务记录。每次主动审批产生一个决定标识，绑定提案版本、所选组和动作。服务端逐组保存结果，包括全部冲突、部分成功和拒绝。结果未知时先按原标识查询；重发同一决定返回已记录的结果，即便字段随后恢复原值。用户核对最新差异后可以单独对冲突组作出新决定。框架的暂停与恢复由运行层处理，前端按业务事件呈现状态。

## 画布上的提案范围与对话引用

自由画布和分镜画布用独立于编辑选区的异色外阴影提示本次提案直接影响的卡片。阴影绘制在卡面外，沿用现有卡片布局；组级状态、字段差异和执行回执在对话审批卡中展示。只读参考列入本轮依据。新增卡在创建成功后出现；删除前可提示目标，删除后在对话保留卡名和回执。连接变动提示相应连线和端点。

画布和对话之间采用显式操作。用户复制一张卡、多张卡或编组，粘贴到助手输入框即可作为本轮引用，发送前仍可编辑消息。画布选区、对话焦点各自独立。审批卡中的定位由用户主动触发。

画布用青绿色外阴影高亮用户当前查看的提案版本，可与选中框和筛选描边同时显示。关闭助手、选择其他卡片或继续输入时保留高亮。查看另一份提案时切换范围，其他版本迟到的回执只更新各自的审批卡。用户可在原审批卡点击「隐藏高亮」，刷新同一画布后恢复上次查看的版本及其显示选择。折叠成员定位到可见的编组外框。已删除卡片保留名称和回执，关闭定位入口。已写入的改动随后被撤销时，在原审批卡标明「曾写入，后已撤销」。

单卡或临时多选粘贴为逐张可移除的引用。正式编组粘贴为一个可展开的引用，显示组名、成员数量及成员卡片。粘贴与 `@` 共用显式引用。复制 A、B 后即使改选 C，「这两张」仍指 A、B。只有用户明确指向当前选区或没有指定对象时，才用选区解释指代。发送前若编组新增成员，用户可沿用原成员或更新为当前成员；原成员已删除时点明失效项，待用户调整后再执行涉及它的动作。发送时固定来源画布及用户看到的成员身份，普通文本按本次剪贴板内容粘贴。跨画布对象在有读取权限时可作为参考，对源卡的修改须回到源画布提出并审批。

## 行动与授权边界

助手可以在用户已授权的资源内自行调查、组合专业技能和调整计划。选区用于理解指代，用户点名的目标和交付范围优先。只读分析及预览可以连续进行。持久的内容、关系和布局改动依据人工决定或已授予的自动审批权限执行。跨会话或跨项目的资源须由用户明确引用和授权。

一次批准绑定到已展示的提案版本、改动组和动作数量。助手可以依序完成其中的依赖步骤，并用原请求标识核对回执、恢复执行。目标、字段依据、影响范围或生成数量发生实质变化时，受影响部分需重新审批。用户拒绝某组后，后续规划遵守该决定，直至用户重新提出。允许审看和报告用户已授权的生成结果；追加生成版本需取得相应授权。

文字确认和审批按钮共用同一决定入口，提交操作当时用户看到的提案版本与勾选组，在原审批卡展示决定和各组回执。提案指向明确且仅剩一组待确认时，回复「确认」批准该组。多组待审时，「确认」作用于已勾选组；均未勾选则提示选组。「全部确认」和「批准全部 N 组」只处理明确指向的提案内全部待审组。若所见版本已被修订，先展示新版本供用户核对；多份提案指代不清时，提示用户选择。「确认，不过把时长改成 5 秒」属于修订请求，先展示更新后的差异。卡片阴影只表示提案范围，授权范围取自本次决定。

## 先给方案与逐项修订

用户输入「先给方案」或 `/plan` 时，助手可读取剧本和画布、审看素材、比较镜头安排，再交付可讨论的步骤、预计时长及涉及的卡片。此阶段限于分析和拟订方案。点击「按此方案继续」进入具体提案准备，持久写入与生成仍按各自的审批规则执行。简单字段修改可以直接提出差异。

对话中的单项差异提供「针对这项修改」。反馈绑定原提案版本、改动组和具体字段。例如在镜头 03 的「时长 8 秒 → 5 秒」旁输入「改为 6 秒」，助手据此重新展示受影响的差异，其他已决定的独立组保留原决定。修订入口放在对话内，卡面沿用提案外阴影。

## 草稿首次写入与跨步骤恢复

未保存的自由画布允许一次批准相互依赖的新卡和连线。例如「建两张卡并连接」构成一个改动组。首次保存将创建画布、写入获批组、归档对话和记录回执放在同一事务。组内连线校验失败时回滚该次写入，保留本地草稿和提案；保存成功但回执丢失时按原请求恢复同一张画布。其他未勾选的独立组在原对话继续待审。

一次批准可覆盖明确列出的字段写入、布局和生成动作。画布服务、持有编辑权的浏览器和生成 Worker 分别记录各自动作的进度与回执，各动作只等待实际依赖。例如「改提示词、整理卡片、生成一版」中，提示词已保存且排版只影响阅读时，生成可按获批输入提交。关页后，对话可同时显示「提示词已写入」「排版等待打开画布」「视频已提交」。重开后编辑器接续排版，Worker 按原请求标识查询生成任务。生成依赖的输入发生实质变化时暂停受影响步骤，展示新差异并取得相应批准。

## 自动审批的独立复核

自动审批依次经过代码准入、独立审批 Agent 的语义复核和服务端决定。代码校验当前授权、卡片与字段、数量、版本及依赖。审批 Agent 通过独立调用读取用户原话、授权和拒绝记录、锁定目标、差异及实际影响，只返回逐组结论、授权依据和疑点。其模型可以与创作助手使用同一型号，也可单独配置。审批 Agent 只读，用户已作出的人工决定直接交给业务服务校验。

在自动模式下，明确点名的编辑、建卡、连接和布局可进入复核。删除、解除采用关系和生成还需核对用户明确指定的动作与目标，生成同时核对数量。按独立生效的组作决定，依赖组作为整体。语义存疑、复核超时或输出无效时交由用户处理；无法满足业务校验的改动展示受阻原因。

审核绑定到提案版本、改动组及差异，保留规则版本、审批模型和简短依据。签发前复查授权、版本和人工决定，迟到结论不得覆盖用户拒绝或已撤销的自动审批权限。界面根据服务签发的决定展示批准状态，根据执行回执展示实际结果。

## 创作子 Agent 的委派

主助手在同一交互轮次内决定何时委派。简单修改由主助手直接选用专业 Skill；适合独立分析、并行处理或需要其他模型能力的工作可委派。首版提供两个角色：

- **分镜设计**按指定场次或节拍交付镜头方案、引用依据、候选修改及依赖。
- **素材与连续性审看**按指定素材或运行版本核对镜头衔接、动作、道具和声画表现，交付观察范围、镜头或时点、问题和建议。

委派时指定目标、交付格式、可读取的对象与版本。角色可组合专业 Skill，在授权范围内分析和读取材料。主助手负责核对结果、解决冲突并形成最终提案。画布写入、布局和生成仍经业务服务执行，独立审批 Agent 由审批服务对固定版本的最终提案发起复核。

支持原生工具调用的主模型可使用 Deep Agents 的 `task` 委派；普通文本模型可提交结构化委派请求。两条路径共用子任务输入与结果契约，服务端校验已注册角色、对象范围、允许的工具与预算。各角色可选用适合任务的模型。媒体审看结果注明素材身份、实际读取的时段和音轨情况，只有静帧时将结论限定在该帧。

首版支持一层委派，独立任务可并行，有依赖的任务按顺序执行。服务控制并发和整轮预算。子任务以稳定标识关联主轮次，恢复时复用已完成结果。用户可在原对话展开查看进度、范围、模型或 Skill、结果及失败原因。停止主轮次后停止派发，迟到结果不得加入已停止轮次的提案。某项审看失败时可标明缺失并交付已完成的分镜；若生成以该项审看通过为前提，则保持等待，直至条件满足或用户调整任务。

本记录描述已确认的目标设计。现有实现按字段编辑、结构变更和移除分别提供工具。
