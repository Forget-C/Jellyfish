# 实验室与画布助手共用交互会话协议

文本、图片、视频实验室与画布助手共用打开或恢复会话、发送一轮、读取快照、接收事件四项协议操作。审批决定、停止，以及画布助手的运行中补充、排队与问题回复，按接入能力提供。会话协议统一前端能观察到的受理、进度与结果；输入校验、运行方式和回执由对应业务服务负责。

实验室沿用既有会话和历史。文本保持逐轮流式输出，图片和视频沿用后台任务，一次点击生成即授权该次提交。请求身份关联受理的轮次及适用的任务标识。重试查询原请求，用户从历史回填后主动发送则建立新请求。每轮模型输入独立；历史供查看与回填，使用以前的素材或结果时以本轮明确提供的输入为依据。

共享协议使同一套前端交互能够承接流式回复、持久任务与画布提案。接入时需要保留各自的恢复语义，例如文本断流后的终态可能暂时无法核实，图片和视频的进度可从持久任务恢复。当前实现见[生成实验室架构](../architecture/generation-labs.md)，画布的目标设计见[双画布助手的专业技能与批量修改提案](0016-canvas-assistant-skills-and-change-proposals.md)。

## 会话与本轮上下文

- **对象边界。** 会话用 `session_id` 关联接入类型、业务归属和会话偏好。同一实验模态可有多段会话。每次提交用 `request_id` 识别重试，受理后用 `turn_id` 关联回复、提案与运行结果。页面快照用于恢复历史、待审项和回执，本轮上下文记录模型实际采用的依据。运行时检查点由服务端管理，用于恢复中断的执行。
- **组装责任。** 客户端提交用户输入、当前选区、编辑器可见草稿和显式引用。服务端核对对象归属、版本、模型能力和执行回执，按接入类型组装上下文。画布助手可以依据用户正在编辑的草稿提出建议，写入时仍核对目标字段的最新值。
- **身份与版本。** 发送时固定引用。网络超时重试沿用原请求和受理时的输入，回填后发送或要求再来一版开启新轮次。修订提案显式关联旧提案及版本，并核对目标当前值。批准提案经决定入口绑定提案版本和改动组。
- **历史策略。** 画布助手按当前任务选用本会话的相关对话与显式引用的提案，通过当前画布事实和回执判断执行结果。实验室每轮独立输入。跨会话使用素材或历史结果须显式引用，并固定文件和用途。
- **预算与可核对性。** 优先保留当前指令、点名对象及版本、待修订提案和对应差异。较早对话可压缩，大画布可按索引分批读取。无法完成指定范围时说明实际覆盖部分。界面简要显示本轮依据，展开可查看对象版本及媒体实际读取范围。后端保留可追溯的引用、必要草稿值和已使用的 Skill 版本，素材复用已有文件身份。

## 对话界面与依赖升级

两种画布先接入 Ant Design X 2.x 的消息列表、输入框和可折叠进度，三类实验室随后按模态复用。工作台主题继续控制面板、浮层与控件。前端先从当前 Ant Design 5.x 升至最新 5.x 并处理弃用项，再将 Ant Design、图标库升至 6.x，保留 React 18.2。基础库升级和助手组件改造分别验收，以便在工作台主题、下拉框或浮层出现回归时定位原因。

界面组件消费既有会话快照、业务事件与执行回执。画布审批卡在原回复内逐组更新决定与执行结果，写入成功且目标仍存在时提供定位入口，目标已删除时保留历史回执。实验室展示本模态的参数、素材、历史及结果。画布输入框通过 `@` 引用卡片或素材，通过 `/` 点名专业技能。回车发送，Shift+Enter 换行，中文输入法选词时回车交给输入法。

执行中先显示一行可核实的进度，展开后可查看子任务、使用的素材、实际审看范围及失败原因。用户向上阅读时保留位置，并提供返回最新进展的入口。待审批与冲突直接显示在对应回复中。服务支持停止当前操作时显示停止入口；已提交后台的图片和视频生成提供任务入口。

## 画布助手运行中的输入与结果

助手工作期间输入框保持可用，普通发送默认「补充到本轮」。发送菜单提供「下一轮处理」，排队消息列在输入框上方，开始处理前可编辑或移除。补充指令归入正在进行的轮次，排队消息在当前轮次结束后开始新轮次。例如用户说「只改镜头 03，先别生成」，助手按实际受理状态反馈：尚未提交时停止后续生成，已受理时显示「该版已提交」和任务入口。受理结果未知时先核对原请求回执。指令改变待审提案范围时，原版本停止接受批准。明确针对审批卡的「确认」仍走[画布审批决定入口](0016-canvas-assistant-skills-and-change-proposals.md#行动与授权边界)。

只有答案会实质改变交付物时，助手才暂停并在原对话显示创作问题。问题卡提供可选答案与自由输入，普通追问也可直接用文字回答。回答关联到具体问题，重开面板后仍可接续。选择「采用这个方向」使助手按该偏好继续创作，同时保留待审生成项；「批准生成 1 版」才提交该项审批决定。

有实际动作的轮次在原回复末尾给出结果摘要，依据各项回执和当前待办，写清已完成、待用户处理和仍在后台运行的事项。冲突和任务分别提供对应入口。后台进展更新同一条摘要。例如「镜头 03 的提示词已写入；镜头 04 的时长有冲突；视频已提交 1 版，正在生成」。纯咨询直接给出专业答复。
