# 自由画布与分镜画布共用 Deep Agents 助手

自由画布和分镜画布采用同一套 Deep Agents 运行时，每张画布拥有独立对话。一次请求可以从审看片段开始，经过专业建议和用户审批，继续到生成和结果点评。一个助手负责跟踪这次请求的目标、已获授权的动作和进度。实现见[生成画布架构](../architecture/generation-canvas.md#独立入口与共同画布交互)。

## 运行时与专业技能

项目已有 LangChain 和 LangGraph，直接使用 `create_agent` 也能调用工具、暂停和恢复，但需要自行接入技能发现、按需加载和长对话上下文管理。选择升级依赖并采用 Deep Agents，是为了让影视团队能独立维护专业方法，并让跨多个步骤的任务沿用同一段对话。代价是共享依赖升级，以及默认工具带来的提示词开销。首版只开放读取产品技能、观察素材和操作当前画布所需的工具。

镜头与场面调度、图片生成指导、视频生成指导和成片审看随产品以只读 `SKILL.md` 发布。助手可按创作任务组合技能，用户也可点名专业角度。回复记录实际使用的技能及版本，使创作者能追溯建议的依据。助手模型使用当前供应商配置的有效能力，可独立于卡片生成模型切换。

## 写入、生成与恢复

Skill 提供创作方法，画布服务掌握写入与生成权限。两种画布沿用同一套编辑与保存规则，并按真实画布类型校验操作。相同的运镜建议可以写入自由画布的视频提示词，也可以修改分镜画布中的运镜卡。审批绑定到具体目标、可独立生效的改动组及形成建议时的字段值。应用时核对最新内容，使手工编辑、共享卡片和助手修改可以安全共存。[两种画布的归属与卡片范围](0010-independent-canvas-ownership.md)

框架检查点记录助手应从哪一步继续。用户批准了哪些修改、授权生成几版以及任务是否已提交，由业务审批记录和画布回执确定。恢复已获授权的生成时，先用原请求标识核对已有运行，避免重复提交。布局沿用浏览器编辑器执行与回执；生成和审看由后端跟进。

集成分支通过了双画布 Chromium 验收和隔离 MySQL／Worker 恢复验收。真实供应商的工具往返与媒体判断仍需使用已配置的测试模型验收。[供应商复测步骤](../../../front/tests/README.md)
