# 通过 MCP 暴露统一画布协议

Jellyfish 是单用户系统，外部客户端需要像编辑器一样直接操作自由画布和场次分镜画布。首版决定在现有后端通过 Streamable HTTP 提供 `/mcp`，以可独立调用的画布业务操作为单位发布具名工具。工具直接调用[统一画布协议](0018-canvas-capabilities-and-approval.md)，完整覆盖生命周期与能力查询、编辑、生成输入、运行与结果，以及自由画布草稿、画布检查、场次分镜提取与采用等专属操作。助手和审批能力属于各自的调用流程，均在此次 MCP 接口范围之外。

## 接入会话

用户在 Jellyfish 中开启连接，取得服务地址和临时凭据。客户端在凭据有效期间可以断线重连。用户关闭连接或凭据到期时，服务端终止该凭据的访问权，已经受理的任务继续运行。有效会话均可使用完整画布能力，沿用单用户模型，无需维护用户、角色或项目授权。

## 跨请求调用

- 列表和创建工具返回统一的 `canvas_ref`。自由画布引用携带画布标识，分镜画布引用还携带项目标识。协议按实际归属核对类型与范围。按场次列出或创建画布时显式传入章节与场次。
- 分组编辑预演返回差异和服务端可验证的 `preview_ref`。客户端凭该引用、选中的组及 `request_id` 提交。协议复核来源并提供幂等回执。直接保存继续沿用已有修订校验。
- 布局预演使用宿主提供的坐标。应用前由协议根据最新坐标计算投影，再由持有布局的宿主应用结果。

实施验收以现有协议的业务操作逐项核对 MCP 工具覆盖，并从外部客户端验证双画布操作、分组提交冲突、重试取回原回执，以及会话失效后已受理任务继续运行。
