# 场次工作台与自由生成共享画布基础

2026-11-17：[ADR 0010](0010-independent-canvas-ownership.md) 保留共同画布基础，替代从自由生成入口打开场次画布的决定，并按归属限制卡片能力；设计与检查六类仅在分镜画布开放。新方案已在独立工作树实施、尚未部署，下文保留原决策背景。

2026-11-09：整体方案、一场次多画布边界及引用定位的受限基础扩展已确认。共同画布已成为新场次工作台的默认入口，旧版审片、剪辑和交付仍使用原有记录。实现边界见[场次工作台架构](../architecture/directing-foundation.md)。

生成画布定位为用户自主布置的自由生成空间；场次工作台定位为通过 Agent 完成原文分析、设计提取与卡片组织，以降低人工成本。工作台保留章节、场次提取和分镜提取的产品步骤，内部允许细化为多次处理；其分镜后产物须由共同画布完整表达、编辑并继续生成。

目标是让两者共享卡片类型、数据契约、关系校验、编辑保存及生成执行逻辑。Agent 建立的卡片与用户建立的同类卡片具有相同语义；工作台产物不能依赖一份只有工作台能读取的隐藏设计正文。选择共同基础，而非仅共享样式或长期维护两份设计内容的双向转换，是为了使自动生成和人工编辑可以连续使用同一份内容与规则。

共同基础从现有生成画布能力中提取，并按必要业务语义补齐。独立生成画布继续不依赖章节或场次；不要求普通自由生成先建立工作台流程。

实施采用新工作台页面壳层直接复用共同画布，旧实现原位暂留回退，验收后切换默认入口。没有选择在旧四视图内逐个替换组件，是因为其宿主仍绑定旧场次版本、生产单元与指令状态，继续沿用会保留已决定移除的数据层次。两个新入口共享实际画布工作区，不复制整页分别维护；新路径不创建隐藏旧版本或双写。旧下游入口保留及最终清理边界见目标设计。

落地遵循现有生成画布行为保持不变的约束。工作台专属需求优先在工作台编排中完成；非必要基础缺口不推动生成画布变更。确需扩展共同基础时，先列出当前行为、缺口、最小改动及对既有画布的影响，逐项取得用户确认。整体方案获确认不代表所有基础能力改动均已获准。

一个场次可以关联多张画布，每张画布直接承载一套独立场次方案，即用户所说的一个版本；画布内部不再提供方案版本，工作台不另外维护一套场次版本实体。此决定替代此前“一个场次版本关联一份画布”的双层方案，复用画布自身的自动保存、冲突保护、撤销与恢复。每次运行的固定依据继续按现有画布契约保留，不作为可切换的创作方案。

镜头通过视图或分组组织，同一画布中的共享卡片保持同一身份；从生成画布入口打开仍编辑原文档，不另建副本。分组负责浏览，设计适用范围由明确关系表达。各画布采用的默认对象参考独立管理，首版只复用新建画布，不增加整图复制，以限制共同基础的新增范围。

共同基础保留现有单模型卡执行边界；Agent 自动组织内容不构成媒体执行授权，不增加多镜头批量生成或上下游自动执行。工作台专属流程负责原文分析、对象预配、提取及重新提取差异，共同基础负责这些产物进入画布后的编辑、诊断与执行。

该选择的代价是必须补齐现有生成画布无法无损表达的来源、人工编辑和适用范围语义，以及对象默认参考的继承关系；仅能保存文字不满足统一要求。目标交互与已确认边界集中维护在[场次工作台与共同画布设计](../design/shared-canvas-workbench.md)，不在本记录重复规则。

第一轮覆盖分析、设计、共同卡片编辑、图片／视频生成与结果管理；审片、剪辑和交付保留既有入口。旧流程依赖场次版本，新画布产物本轮不接入这些流程，也不增加对应身份适配；不能因保留入口就声称新流程已接通。用户明确本次忽略存量数据，不做迁移或增加旧数据兼容逻辑；已有数据仅作为表达能力验证样本。选择直接面向新契约，是为了避免将本轮重构扩展为旧模型的长期兼容工程，其代价是不承诺旧场次在新共同画布中继续使用。

当前实现仍见[生成画布架构](../architecture/generation-canvas.md)和[场次工作台架构](../architecture/directing-foundation.md)。本记录不解除[独立生成画布的行为基线](0001-independent-generation-canvas.md)或[协议边界](0002-generation-canvas-protocol-boundaries.md)中的单卡执行、引用及固定运行依据约束；新增基础能力按上述要求单独确认。领域术语见[术语表](../../../GLOSSARY.md)。
