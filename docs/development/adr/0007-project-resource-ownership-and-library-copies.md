# 项目专属资源与独立入库副本

2026-11-14：用户纠正详情容器：只有新建使用右侧抽屉，已有对象详情恢复页面正文模式。两者继续复用设定、参考、图片、生成设置及离开保护；下述“同一抽屉”交互在详情场景对应同一页面正文。

2026-11-13：用户已最终确认完整共识，涵盖业务与领域方案、UI/UX 的 UX1–UX15（UX7 拆为 UX7a、UX7b）及展示基线，无待确认项。本轮调整已实施，对象公开 API、抽屉与工作台主流程已验证，当前机制同步于下述架构文档。本决策调整 [ADR 0006](0006-project-character-and-shared-assets.md) 中只有角色直接归属项目的范围、角色参考机制及默认选图规则。当前代码机制见[资产图片管理架构](../architecture/asset-image-management.md)，领域术语见[术语表](../../../GLOSSARY.md)。

项目资源中新建的演员、角色、场所、道具和服装直接归属该项目，不自动进入资产库。资产库中新建的对象为共享资产。项目资源因此同时包含项目专属对象和已关联的共享资产，保留手动关联入口，不能将列表所在页面当作对象归属。

项目专属对象通过明确的“进入资产库”操作生成独立共享副本，原项目对象保留，互不随对方修改。普通副本可独立编辑；角色入库生成演员资产，标注为“从角色转化”，允许结构化外观字段为空，入库后不能编辑，只能被引用。角色转化演员的资料、图片及主图以入库时为准，原项目角色身份及既有引用继续保留。选择独立副本而非把原对象转为共享对象，是为了让跨项目复用不改变已有项目对象的编辑边界；本决策不引入自动或持续同步。

角色入库前须有有效主图，缺图时先生成或采用主图；普通可编辑资产不受此无图限制。入库前预览名称和图片，名称默认沿用角色名，可单独调整本次副本名称；同名时要求改名，不覆盖或合并已有资产，原角色名称不变。角色转化演员允许删除，但存在当前项目关联或直接参考时阻止删除，须先解除使用关系；已生成结果和独立图片副本不构成此类直接引用，也不受删除影响。

从资产库关联到项目的对象继续保持共享身份。项目中保留可编辑共享资产的编辑入口，在新的浏览器标签页打开其资产页进行编辑，修改的仍是同一共享对象；项目内不直接编辑共享档案，也不自动派生副本。共享资产只能选择资产库及上传图片作为参考；只有项目专属对象可以额外选择当前项目资源。这样允许明确维护共享资产，同时避免共享资产对某个项目专属对象形成可变依赖；“从角色转化”的演员仍遵循只读规则。

使用库图作为生成参考不复制，直接作为项目对象主图则复制，项目入库也复制。复制采用独立图片记录和文件，隔离来源换图、删除及文件信息修改；生成后的目标图片也独立于源参考图。“互不影响”适用于独立目标与来源，不把同一共享来源在两个入口的显示误认为独立对象。

参考主体可选且单选，允许明确选用同一主体的多张图片；演员与角色可互为参考主体，仍受来源归属范围限制。其他类别使用同类主体；角色另可选择一项服装及多项道具。参考采用明确图片及其用途，生成文字以当前对象设定为准，不递归继承来源对象的组合，也不动态拼接来源对象的文字设定。选择这一规则是为了让统一参考表达真实输入，避免来源修改悄悄改变当前对象的生成依据。冲突清理限于旧关联、配置和失效引用，保留对象身份、现有图片与历史生成记录；不迁入旧组合文字，不保留旧行为兼容分支。实施时应列出实际清理项，本文不代表已执行数据删除，也不授权清空项目或资产库。

项目专属对象明确保存库中主体、服装或道具参考时，同时建立相应项目关联。仅用于生成的临时参考则在生成任务成功受理后，关联实际使用的库中对象，不回写对象长期参考配置。浏览、临时选择、应用生成设置、预览和取消都不建立关联；更换参考或已受理任务后续生成失败不撤销已建立的项目关联，重试不重复关联。上传图片作为文件参考，不自动成为资产对象。

工作台提取卡片只代表自动发现的对象。以提取数据操作对象时使用共同的新建流程，新建成功才形成项目对象并纳入项目资源，未新建不纳入。仍允许明确使用已有项目对象，只建立本场关系，不复制或用提取信息覆盖已有对象；同名不自动合并。已完成创建或复用的卡片再次打开对象详情。未创建卡片的上传及参考选择收拢到新建流程，取消不产生项目对象或已准备图片，提取文字继续保留。该决定替代 ADR 0006 中选择演员即建立角色并自动选图的工作台入口约定。

新建与详情复用对象设定、参考和图片区。新建在菜单右侧的正文范围内使用右侧抽屉与微透明遮罩，保留菜单可操作；关闭、Escape、遮罩关闭和菜单跳转经过同一未保存保护。打开抽屉只产生本地草稿，明确创建后才持久化；“创建并生成”先保存对象再受理任务，失败保留对象以便重试，任务受理后关闭抽屉不取消执行。

每个对象只有一张主图，用于默认展示及被引用时的默认选图，不等同于生图参考；视角文件夹不另设默认图。主图可以选自任意视角，首张成功生成图默认成为主图；已有主图时，后续生成只添加图片，不自动替换主图。可编辑对象允许手动更换主图，角色转化演员保持入库时的主图。明确不生成时允许选择参考主体图片作为主图，使用库图时按独立副本采用。已经明确选定的场次或画布图片不随对象主图更换。

图片按视角文件夹组织，每组可保存多张图片；默认正面、侧面（左侧）、俯视，并补充背面生成选项。生成可任选一个或多个角度，未选角度时默认正面；每个所选角度本次分别生成一张独立图片，部分成功保留结果，失败角度单独重试。旧图保持真实角度，不重新标记或混入其他视角。

入库复制已保存资料与各视角文件夹中已纳入对象的全部图片，保留主图选择；主图不代表其他成员均未采用。不复制参考关系链、生成任务或未纳入对象的候选；成功后提供查看库中资产的入口，不提供持续覆盖同步，失败重试不重复创建。角色入库使用前述只读转化类型，不要求补齐普通演员的结构化字段，也不自动从角色剧情或原参考演员推断这些字段。

历史共享对象保持当前归属，项目专属规则作用于后续新建。现有数据不能可靠区分共享对象的原始创建入口，不根据项目关联数量推定私有归属。

“入库复制”与“项目关联”因此具有不同后果：前者建立独立对象，后者保留共享身份；已有场次与画布明确选定的图片继续保留具体文件，不因共享设定或来源图片更新而自动更换。

## UI/UX 补充

本节由 `ui-ux-pro-max` 的界面评估进入 `grill-with-docs` 澄清。用户已逐项同意下表 UX1–UX15（UX7 拆为 UX7a、UX7b），并最终确认包含展示基线的整体汇总；此前未回答的基础交互 Q1–Q8 由 UX1–UX6 取代。对话中的交互示意不是业务实现，其未被这些决策涵盖的细节也不自动获批。下文记录已确认的目标交互与展示约定。

### 直接沿用的已确认边界

- 新建使用菜单右侧正文范围内的右侧抽屉与微透明遮罩，不覆盖菜单；菜单保持可操作，未保存离开使用统一保护。
- 新建与详情复用内容；对象必须明确创建才持久化。“创建并生成”先保存对象，再提交任务；失败保留对象，已受理任务可在关闭后继续。
- 项目中的可编辑共享资产通过新浏览器标签页打开资产页；角色转化演员只读，引用和删除限制沿用前文。
- 参考配置明确保存才持久化并补齐项目关联；临时参考仅在生成任务受理后建立实际使用来源的项目关联，不回写长期参考配置。候选浏览、临时选择和预览不建立关联。对象主图、生成参考及复制的语义沿用前文。
- 单对象单主图、任意选生成角度、未指定时默认正面、每角度分别产图及失败独立重试均已确认。

### 已确认的展示基线

现有雾蓝外观、导航、字体、间距、Ant Design 控件和键盘焦点规范继续使用，参见[管理页面前端规范](../standards/management-ui.md)与[项目内部页前端规范](../standards/project-internal-ui.md)。以下展示约定已随整体方案确认，不改变前述业务边界：

- 卡片及详情标题附近显示项目专属、共享资产或“从角色转化 · 只读”，项目专属卡片保留可见的入库按钮。共享编辑入口标注新标签页；只读详情显示可阅读内容，隐藏空外观字段和不允许的编辑、生成、换主图操作，删除收进更多菜单并解释阻止原因。
- 文件夹切换仅用于浏览；“本次生成”使用另一组角度复选框，初始勾选正面。全部取消时明确说明默认生成正面，按钮显示实际将生成的角度或数量；每角度进度与重试在图片区展示。
- 对象、图片和任务的加载失败分别在所属区域反馈，保留可用内容与输入；不因失败清空整份表单，也不以成功提示代替真实受理状态。
