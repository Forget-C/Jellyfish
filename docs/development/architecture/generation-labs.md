# 生成实验室架构

实验室统一使用 `/lab`，会话通过 `session` 参数定位。旧 `/text-lab`、`/image-lab`、`/video-lab` 地址已退役；会话历史和输入回填统一在此入口提供。

## 会话、输入与历史

`/lab` 由 `ExperimentLabPage` 处理会话读取、布局与路由。会话读取覆盖多模态聊天、文本、图片和视频试模，侧栏混合展示四类历史并按更新时间倒序排列，以类型图标标识；「＋新建」菜单默认进入多模态聊天，也可选择文本、图片或视频试模，点击历史会话自动进入对应模态。某个类型读取失败时保留已加载的会话并提供重试。当前会话所在类型刷新失败时继续保留该会话及输入。URL 的 `session` 指向会话，`mode` 指向未持久化草稿。恢复顺序为显式选择、最近更新会话、多模态聊天草稿。首次有效提交才创建会话；删除当前会话后打开剩余最新会话或多模态聊天草稿。

文本、图片、视频模态各自负责输入能力、提交和结果展示。三种模态复用 Composer、模型与模板选择器和历史滚动边界。模型列表与右侧添加菜单统一管理互斥浮层，模板选择通过添加菜单进入；参考摘要与配置抽屉复用同一份已应用素材，摘要不另存一份选择状态。变量表单按模板声明生成，抽屉中的临时配置应用后才更新输入。模型和模板在首次打开选择器时加载，和会话、资料库的加载状态分开。交互与可达性要求见[实验室前端规范](../standards/experiment-lab-ui.md)。

实验室记录当前会话的已接收输入，用于区分保留配置与未发送的编辑。切换会话或实验类型时，离开确认覆盖已应用输入及打开面板内的临时编辑。确认切换后重新建立输入上下文，首提从草稿写回会话 ID 时沿用当前上下文。浏览器刷新或关闭仅能使用原生离开提示。

`experiment_sessions` 和 `experiment_messages` 共用存储，按 `lab_type` 区分。历史按会话内单调 `sequence` 排序，服务端提供分页、重命名、删除与清空。历史响应携带共用的会话标识、游标与支持操作，画布和实验室共用工作台的 Ant Design X 消息渲染。删除和清空锁定会话并拒绝活动任务。会话当前为全局数据。单模态试模每轮只提交本次输入，多模态聊天可引用先前轮次归档的产物。文本增量在发送到页面前记录到原请求，重开历史可读尚未核实终态的部分回复；使用同一请求身份重连时回放原游标。实验室任务的目标为 `experiment_session`，项目、资产及场次生产另有各自入口。

标准生成入口写入实验消息，客户端通过会话历史读取已有消息。直接追加和修改普通消息的公开接口已退役。

## 多模态聊天

聊天和画布助手共用 Deep Agents 执行循环。聊天默认展示主模型，折叠区选择图片和视频执行模型，各项可沿用全局默认值。自然语言或 `/imagegen`、`/videogen` 均通过生成工具执行。引用图片作为首帧时校验视频模型的输入能力，要求分析画面时校验主模型的理解能力。

会话 API 公开受理、文本更新、工具、后台任务及产物事件，客户端按游标恢复。回复、执行工具和等待产物期间同一会话只处理当前轮次，其他会话仍可发送。工具回执、文件身份及已作出的模型决定与轮次关联，Worker 可接管中断的生成。停止回复结束后续动作，取消已受理任务使用任务卡并以实际回执为准。

## 聊天会话契约

画布助手、未保存画布、多模态聊天、文本试模和媒体试模均通过页面的 `chatClient` 发送消息和订阅事件。服务端根据会话 ID 查找实验室类型或画布所属项目；首次在未保存的画布中发送助手消息时，页面先用原画布 ID 保存当前内容，再通过正式画布会话提交消息。发送和订阅均无需提供场景、项目或轮次 ID 作为路由参数。

轮次受理后，发送方法立即以 HTTP 202 返回统一的 `ChatTurnReceipt`。其中 `session_id` 和 `turn_id` 标识已受理的轮次；将 `cursor` 作为 `events(session_id, cursor)` 的起点可以回读该轮。订阅覆盖整个会话，需要只跟踪本轮的组件可按 `turn_id` 筛选。受理后的文本、工具调用、问题、任务、产物和终态通过事件交付。

每个 SSE 数据帧都是同一个 `ChatEvent` 联合类型。`category` 决定 `payload` 的结构，`type` 表示具体事件。例如，`message.updated` 携带文本与追加或替换模式；轮次事件可携带已持久化的消息；任务与产物事件携带媒体任务回执。`detail` 可附带画布状态、队列项或实验室问题，页面包装负责将它们投影为业务组件。断线后以最后处理的事件游标续读。

## 文本流

文本试模通过 `POST /api/v1/studio/chat/sessions/{session_id}/turns` 提交模型、提示词和幂等键。服务器持久化用户消息后返回轮次标识和起始游标。页面订阅同一会话的 `GET /events`，回放 `turn.accepted`、`message.updated` 和一个终态事件。文本更新载荷中的 `mode` 指定追加片段或替换完整前缀。成功写入助手消息后才发布 `turn.completed`。连接中断可从最近游标重新订阅；同一请求身份不会再次调用模型，服务重启后仍可回放已保存的结果和增量。

停止使用该会话的 `POST /turns/{task_id}/stop`。此文本运行由进程内执行器驱动，事件单独持久化，页面断线后可以重新订阅。隐藏运行不进入任务中心。

站内离开确认在连接仍打开时请求停止。取消接口确认请求已受理，流事件确定运行终态。停止请求失败会保留会话，已经到达的完成事件继续以完成结果展示。当前文本流运行时，侧栏禁用删除该会话。收到 `turn.accepted` 后断流且未收到终态时，保留部分回复并提示状态暂不可用。带请求身份的运行在失败或取消时将可用部分随原运行保存。历史按运行标识核对终态，暂无法关联时保持未知。

## 图片与视频任务

- 图片选择器提供首帧、尾帧、关键帧、角色、演员、道具、场景正面与其他视角、服装等图片模板。参考项按选入顺序传递资料库 `file_id`、`media_kind` 和 `ordinal`。
- 视频使用 `video_prompt` 类提示词模板和画幅。界面从 `GET /api/v1/llm/video-generation-options` 获取所选模型的画幅和媒体能力。具名帧槽为 `frames.first`、`frames.last`、`frames.keys`，当前界面各槽选择一张图。命名 `subjects` 独立表达主体的有序图片或视频，主体名在同次提交唯一。界面依据当前模型明确返回的能力校验画幅、数量、类型及帧与主体组合，缺失字段交由现有服务端校验。切换模型保留配置，仅采纳与当前选择对应的能力响应。供应商映射及能力配置见[供应商注册与扩展](../guides/llm-provider-registration.md)。
- 固定模态试模使用 `POST /api/v1/studio/chat/sessions/{session_id}/turns`。会话绑定的模态约束生成 operation 和媒体结构。服务端校验资料库引用、文件类型和模型能力；实际供应商媒体表示由 Worker 执行时解析。
- 用户消息、带任务标识的任务消息及任务记录在同一数据库事务内写入，由持久任务表驱动 Worker。用户消息保存可回填的公开输入，任务消息通过任务标识读取状态、错误和文件结果。图片与视频按会话和原请求标识恢复回执；相同输入重试会复用原任务，使用同一标识提交不同输入时拒绝。Worker 从 `Task.input_snapshot` 和持久输入关系取得受理时固定的执行配置。任务状态与恢复见[任务执行架构](task-execution.md)。
- `task.accepted` 事件携带任务标识和两条已持久化消息。前端按消息 ID 去重、按 `sequence` 排序，并按游标订阅任务和产物事件。历史状态、错误和文件结果由任务事实派生，历史确认终态后优先使用该状态，终态继续显示在原任务消息位置。成功媒体按统一文件流程归档，供历史预览。

参考配置使用临时选择。上传成功即写入资料库，应用配置才将文件加入本轮输入，取消选择后已上传文件依然可供资料库读取。图片、视频收到任务回执后可以离开会话，任务由持久任务表继续驱动。创建回执不明确时，前端以已有会话历史核对，只有能与真实任务标识关联的消息才能确认该任务已接收。

## 历史查看与回填

三种实验的用户消息统一保存提示词与受理时采用的模型标识，图片和视频同时保存已提交的媒体引用与生成参数。回填将提示词恢复为自由输入，清除模板和变量。图片恢复模型和有序参考图，视频恢复模型、画幅、帧和主体参考。视频模型的能力以回填时加载的当前配置为准。历史输入缺失时只显示消息正文，文件失效时显示不可用。回填改变编辑草稿，下一次提交建立新的消息和运行或任务。
