# 文档规范

本规范维护长期项目文档的目录职责、内容归属和验收要求。文档技能负责执行流程，共同引用本文件；各篇领域文档继续维护其自身事实与规则。

其他技能专属产物（如规格、票据、研究报告和交接文档）的格式、位置、确认与交付流程由原技能负责，不因产物也是 Markdown 就自动纳入本规范的归档或索引要求。需要提炼为长期项目文档时，再按本规范维护相应内容。文档技能作为辅助步骤时，保留主流程要求的验证、审查与提交步骤，不以文档检查代替它们。

## 归属原则

- 先确定读者、用途和内容状态，再选择位置。混合文档按章节或段落拆分，不整篇照搬。
- 同一事实或规则选择一个权威来源；其他入口保留必要摘要与链接。面向用户的操作指南与面向开发者的架构说明不因主题相同判为重复。
- 优先更新已有文档。新主题确有独立用途时再建文件，不为凑齐分类创建空页。
- 文档位置不代表删除许可。重复、过时或归属错误的内容按清理流程核查，有效约束先承接，历史用途与引用依赖分别判断。

## 官网与产品文档

官网主要服务普通产品用户，自行部署者也属于产品用户。技术细节是否保留，取决于它是否帮助用户操作或作出决定。

| 位置（从仓库根目录解析） | 文件职责与内容边界 |
| --- | --- |
| `site/content/product/` | 产品定位、功能、工作流、截图与已确认的对外方向；区分当前能力与未来方向，不将提案表述为承诺 |
| `site/content/docs/getting-started/` | 安装、部署、初次运行与简短开发入门；开发入口只覆盖环境准备、启动、基本检查和进一步阅读 |
| `site/content/docs/guide/` | 围绕用户目标说明操作入口、步骤、结果、限制与失败处理；模块、事务和执行器机制进入开发文档 |
| `site/content/docs/community/` | 社区与贡献入口；详细开发协作步骤链接到仓库开发指南 |
| `site/content/blog/` | 版本发布说明；保持版本、日期和历史语义，具体格式见[发布说明规范](development.md#release-note-规范) |
| `site/content/**/_index.md` | 首页或栏目简介、导航；保持简短，避免复制正文 |

常规产品配置、升级说明可以留在官网；代码级调试、特定历史数据修复和开发迁移演练进入开发指南。教程可以解释必要的业务概念，不按是否含技术术语机械分流。

## 开发知识

| 位置 | 回答的问题 | 必要内容与边界 |
| --- | --- | --- |
| `docs/development/standards/` | 应当遵守什么？ | 规则、适用范围、必要例外及验收方式；不附按组件登记的实施进度 |
| `docs/development/design/` | 已确认要做成什么？ | 功能模型、交互、目标约束与范围；尚未实现的部分明确状态，不冒充当前能力 |
| `docs/development/design/research/` | 哪些证据支持设计？ | 仍支撑有效设计或决策的调研事实、来源、适用版本与局限；推断和已确认结论分开，不堆积浏览流水 |
| `docs/development/architecture/` | 系统现在如何运作？ | 当前模块职责、数据流、状态及协作边界；仍受支持的旧契约写明适用范围 |
| `docs/development/adr/` | 为什么作出这个重要选择？ | 背景、备选方案、真实取舍、后果与决策状态；保留编号和历史语义，不把一般实现记录写成 ADR |
| `docs/development/guides/` | 开发者或维护者如何操作？ | 环境、接入、调试、维护、迁移与数据修复步骤；保留数据保护、验证与回退边界，移除无长期用途的终端流水 |
| `docs/development/reference/` | 某个定义或参数是什么？ | 接口、字段、配置、协议和输入输出契约；按查询用途组织，与代码或生成定义保持一致 |
| `docs/development/README.md` | 从哪里开始查阅？ | 分类入口与必要阅读顺序，不复制各篇正文 |

设计可以已经确认但尚未实施；架构记录当前事实；ADR 解释重要决策。三者相互链接，不能因一份设计获批就更新架构声称已经实现。新研究是否形成长期文档由其实际用途决定，不自动把未确认建议归入设计。

## 仓库入口与 Agent 文档

| 位置 | 文件职责与内容边界 |
| --- | --- |
| `README.md`、`docs/README.<语言>.md` | 仓库对外简介、主要能力与快速入口；多语言版本维持相同事实口径，详细步骤链接到权威来源 |
| `AGENTS.md` | 必要项目指令与条件明确的阅读入口；技术细则由对应规范和领域文档维护 |
| `GLOSSARY.md` | 领域概念及关系，不承载实现细节、需求规格或操作步骤；布局见[领域配置](../../agents/domain.md) |
| `docs/agents/` | 技能依赖的项目配置；保持必要入口可发现，路径调整不授权重写技能工作流 |
| `.agents/skills/<name>/SKILL.md` | 技能触发条件、核心工作流程、授权边界、验收及按需读取参考资料的条件 |
| `.agents/skills/<name>/references/` | 条件性规则和专题资料；由技能提供明确阅读入口，不复制项目规范 |
| `.agents/skills/<name>/agents/openai.yaml` | 技能展示信息与调用策略 |
| `.agents/skills/<name>/scripts/` | 确有复用价值的自动化工具；新增或修改后验证实际行为 |
| `.agents/skills/<name>/assets/` | 用于生成成果的模板和素材 |

领域术语和决策由现有领域建模流程维护；Agent 指令与技能编写使用相应专门技能。普通文档维护不自动修改术语、批准设计或创建 ADR。

## 资源与就近说明

| 位置 | 文件职责与内容边界 |
| --- | --- |
| `site/static/` | 官网图片、截图、分享图与下载资源；按实际使用方维护 |
| `site/data/` | 模板消费的结构化内容，如首页文案块；不存放长篇文档或开发日志 |
| `site/layouts/`、`site/hugo.yaml` | 站点模板与配置，属于实现；修改后验证受影响的渲染、导航、路由和资源路径 |
| `site/README.md` | 站点环境、预览、构建、主题依赖与发布机制 |
| `docs/img/` | 仓库介绍使用的图片；不能因与官网资源相似而直接删除 |
| 模块目录的 `README.md` | 本模块运行、测试及维护入口；跨模块规范与架构链接到开发文档 |
| 测试目录的 `README.md` | 环境、执行命令、测试范围与限制；不持续积累历次通过数量或临时报告路径 |
| 资源旁的 `README.md` | 该资源的格式、使用与维护约定；被应用或测试消费的文件属于运行或测试资源，不按文档孤儿处理 |

代码、测试、配置和生成产物不是文档整理的自动修改范围。附件删除需核对保留使用方的传递引用，不能只搜 Markdown 文件名。

## 内容与引用

- 标题表达主题或操作目标；新文档文件名沿用现有小写连字符风格，ADR 使用顺序编号。避免用日期、阶段号替代长期主题名称；发布说明等有版本身份的文件沿用其约定。
- 用户指南说明前提、入口、步骤、可观察结果、限制和失败处理。开发操作还需写清执行目录及环境；数据迁移说明包含保护、验证和回退条件。
- 区分当前事实、已确认未实现设计、提案、被替代方案和仍支持的旧契约。删除提案不表示能力已经实现，删除进度不表示工作已经完成。
- 代码和测试只能证明相应实现与验证范围，不能据此声称已经部署或生产验收；生成成功、人工审查与采用分别表达。发现代码与规范冲突时先定位，不把缺陷改写为预期行为。
- Markdown 使用适合源文件位置的相对链接；站点正文按实际路由链接。面向官网读者的仓库资料使用可访问的仓库地址，避免将仓库文件路径当站点页面。
- 标题、链接文字、目标正文和锚点应一致。移动或删除章节后同步受影响引用；不能用宽泛首页替代原有证据。
- 站点页面按现有栏目维护 `title`，按用途设置 `description`、`weight` 等 frontmatter；发布说明的专用字段按发布规范。网址变更遵循当前任务的兼容要求，不从历史清理推导永久许可。

## 同步与验收

本规范范围内的日常新增和更新使用 [docs-maintain](../../../.agents/skills/docs-maintain/SKILL.md)；重复、过时或归属错误文档的审计、迁移和授权删除使用 [docs-cleanup](../../../.agents/skills/docs-cleanup/SKILL.md)。检查与方案不自动授权实施；是否保存成果按用户授权或已明确选用工作流的交付要求判断，遵守当前明确的只读限制。

只更新本次受影响的资料与必要入口。新增的长期项目文档应能从相应索引找到；已有正文与新内容相互引用而不是复制整篇。发布说明保持历史口径；历史过程是否保留按当前授权与有效信息核查，不设按年龄自动删除规则。

| 变更 | 验证要求 |
| --- | --- |
| 仓库文档、规范或索引 | 核对内容依据、信息归属、状态和相对链接；检查差异范围 |
| 技能或 Agent 指令 | 检查触发条件、授权边界、参考资料可发现性与专门技能要求的验证 |
| 站点内容、导航或资源 | 按[站点维护说明](../../../site/README.md)构建到干净输出目录，检查页面、资源和锚点；展示或导航变化预览代表页面，涉及路径时覆盖实际部署前缀 |
| 文档迁移或删除 | 额外核对有效信息承接、保留入链、网址策略和附件依赖 |

构建成功不代替语义与链接检查。按[开发规范](development.md#标准完成状态)执行受影响检查，不为纯文档改动运行无关应用测试；不能执行的验证明确说明范围和原因。
