# 身份参考存量整理（旧版）

以下步骤仅适用于仍提供旧场次版本接口的部署。该接口和读取时的自动整理均已随旧四画布退役，新基线的存储边界见[退役决策](../adr/0014-retire-scene-version-api.md#从空库初始化的新基线)。

正常打开当前场次的版本列表或单个版本时，服务端会先在事务内整理此次访问范围中已保存的不合规身份参考，再返回整理后的内容和同一 revision 的全部画布图。发生整理时 revision 增加一次；重复打开或合规内容不增加 revision。此流程不需要用户调用维护接口，也不扫描其他场次或整个数据库。非当前场次仅供历史阅读，不触发整理。

旧版维护者可使用独立 CAS 入口核对指定版本；该接口不接受待整理的新内容，也不是正常使用的前提：

1. 读取 `GET /api/v1/studio/projects/{project_id}/directing/sequences/{sequence_id}/versions/{version_id}`，保存响应以便核对，并记录当前 `revision`；正常打开时的自动整理已在返回前完成。
2. 调用 `POST` 到上述版本地址后加 `/identity-references/cleanup`，请求仅含新的 `request_id` 和所读的 `expected_revision`。
3. 回读版本并比较参考、顺序和真实缺项。发生清理时 revision 增加一次；没有变化时不增加。原请求重放与重复整理均不继续丢失内容。409 表示基线已变化，需重新读取并核对，不能覆盖最新编辑。

请求示例：

```json
{"request_id":"identity-cleanup-run-001","expected_revision":3}
```

整理只作用于身份用途且位于主体输入的参考，按原始模型组先分类。合规单对象单组单来源的多图全部保留；原本多组或多来源的对象按原 ordinal 只保留首份文件与访问条件有效的参考；空／多对象组整组移除。未设置组标识的每份引用原本各自占一个模型主体，不能在读取时先合并。没有有效幸存者时留下真实缺项，不补默认图片。

合规组即使缺文件、能力未知或超过模型限制也不因本次整理被删除；这些问题继续由预检说明。来源资产消失但固定文件合法的既有参考可保留。首尾帧、构图、空间、连续性和其他输入位置不参与本规则。

DirectingStore 在同一数据库事务内更新指定版本和其不再使用的文件保护记录，使用 revision CAS；失败整体回滚。其他单元合规内容、非当前场次、固定版本、指令依据／检查快照、任务输入、Take 及各自的文件保护均不被重写。实际输入变更后，现有指令依据和检查按原规则重新核对。正常访问入口仅整理已保存基线；内部快照读取和普通新提交不触发整理。普通新提交始终拒绝非法身份组，不会调用整理逻辑裁剪请求。

验证使用独立测试数据库及受控模型边界，不以真实项目试运行。版本与保存语义见[场次版本架构](../architecture/scene-versions.md)。
