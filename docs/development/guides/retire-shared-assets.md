# 旧共享关联退出

正常项目导入始终创建独立副本；选择生成参考不导入、不关联资产。旧共享关联写入口已经关闭，取消共享关联接口移除。已有部署必须在使用新版项目资源界面前完成本维护，不能用隐藏旧数据替代转换。

## 预检与审批

从仓库根目录维护 `.scratch/<work>/` 中的审批报告，逐项列出旧关联的类别、项目、来源资产、link ID、成员图片 ID/文件 ID，并按历史表列出明确主键。格式见本次工作的 `cleanup-review.md`，不能将该文件的本地数据库身份直接套用到其他部署。

从 `backend` 目录运行：

```sh
uv run python -m app.scripts.shared_asset_preflight --approval APPROVAL.md --output PLAN.json
```

命令只读，MySQL 使用只读事务。它检查来源身份、名称冲突、活动任务，并展开历史 JSON 和外键依赖，列出当前正文中的历史来源及无法分类的引用。输出同时绑定审批原文哈希；`ready_to_apply: false` 表示该只读报告本身不授予执行许可。

新增历史身份和当前采用影响须明确确认。当前分镜采用索引若依赖待删任务，不能伪造任务 ID 或静默丢弃正文；经确认可解除采用索引，保留卡片和连线。强类型来源无法安全清空时命令拒绝执行。同名冲突须先明确副本名称，在审批来源项写入 `copy_name` 后重新生成并核对计划；同项目同来源的各章节项须使用一致名称。命令不能自动合并或覆盖。

## 执行维护

停止并确认本部署的 API、Worker 及其他写入进程退出，确认活动任务已结束。维护窗口内不运行其他写数据库的管理脚本。先执行数据库结构迁移，再核对已批准计划；不能重新生成更大的计划后直接执行。

```sh
uv run python -m app.scripts.retire_shared_assets \
  --approval APPROVAL.md --plan PLAN.json --plan-sha256 APPROVED_SHA256 \
  --backup /private/tmp/private-retirement-backup.json --output RESULT.json \
  --detach-adoption --maintenance-window --worker-pid STOPPED_WORKER_PID
```

命令要求明确的维护窗口和采用解除选择；本地 MySQL 场景还检查 8000 端口无 API 监听、所列 Worker PID 已退出。所有本地/远端写入进程仍须由操作者实际隔离，参数不能代替运维隔离。`--database-url` 仅供隔离测试，实际维护默认使用应用配置，避免在命令行泄露数据库凭据。

执行会比对审批原文和计划哈希，重新预检精确主键集合及当前来源；任何范围变化、活动任务、未知依赖或冲突均拒绝。写入前以 0600、禁止覆盖的方式保存恢复备份，内容可能含私有任务快照，不应提交到 Git 或公开分享。

同一事务完成：按项目/类别/来源复制一次、保留全部设定及空图片槽位、为有效图片创建独立文件、映射全部批准章节及当前可编辑引用、同步当前文件保护、删除批准历史及其失效保护位置。物理文件与原库中对象不删除。画布保留单调递增事件游标，追加当前快照，避免清理事件后重放出已删成果。

事务失败时数据库回滚；对象存储写入不能随数据库回滚，重试使用稳定文件身份复用自己的复制对象，不应按前缀批量删除文件。已提交的同一计划重复执行返回已完成，不重新复制或覆盖副本后续编辑。

## 验收与恢复

恢复 API 和 Worker 后，核对：旧共享关联为零、项目副本资料和图片完整、图像文件身份独立且字节相同、当前方案/画布正文和连线保留、批准历史消失、其他项目记录及库中原件保留、当前媒体保护及事件快照可读。

命令不提供自动 downgrade。提交后若需回退，重新停止写入，根据私有备份及 RESULT 的身份映射按外键顺序恢复本次改变的记录和原引用，并使用匹配的代码；不要整表覆盖备份以免撤销其他项目后续操作。原文件仍保留，可用于恢复旧引用。部署库应另按自身备份策略保留数据库恢复点。
