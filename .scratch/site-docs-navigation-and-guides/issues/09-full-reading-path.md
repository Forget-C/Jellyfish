Status: ready-for-agent

**What to build:** 在整合后的官网验证新用户、独立试验者、旧书签访问者和开发者都能沿实际入口完成阅读。

## 验收标准

- [x] 从同一源码完整构建到空目录，记录根路径与 /Jellyfish/ 预览地址和源码状态。
- [x] 按教程从安装走到《雾海来信》的第一张候选图，沿独立工具、旧版书签和开发贡献入口抽查跨篇导航。
- [x] 复查所有受影响的公开网址、章节锚点和媒体；在桌面及手机记录实际落点、当前目录、截图可读性和原图访问情况。
- [x] 核对脚本错误、横向溢出及读者可见的状态；记录实际走查结果，修复并复验影响验收的问题。


## 验收记录

- 在集成基线 `f787f764` 上合入本票的正文修正，用 Hugo 0.159.2 从同一份源码分别完整构建根路径 `http://127.0.0.1:1490/` 与前缀 `http://127.0.0.1:1491/Jellyfish/`。两份产物各生成 72 页及 8 个别名。构建报告一项主题访问 `.Site.Data` 的弃用提醒。
- Chrome 桌面 1440px、手机 375px 依次从准备环境、启动服务、配置模型进入创建项目、划分场次、选参考图与分镜候选画面。新增模型验证结束处的项目入口。另从产品页、独立工具和贡献入口进入深层文章，核对四组菜单、当前页、面包屑、相邻文章与 13 种旧书签落点。
- 检查首页、产品及文档共 29 个 HTML 地址。每种部署下的 81 个本地资源或页面地址、75 组页面锚点均能解析。逐图检查 31 处教学截图的解码、显示宽度与原图链接，补齐对象参考和资产图片文章中五处缺少的原图入口。首页另验 320px，小屏菜单及轮播可用。上述浏览器走查未发现页面脚本报错或横向溢出。
- 安装补验使用独立 Compose 空库启动 MySQL、RustFS、迁移、种子、API、Worker 和前端，从产品页面新建《雾海来信》及第一章，保存「海边站台」「堤岸晨光」并刷新历史。制作补验沿用票据 04 在另一套隔离数据中新建的同一示例项目。通过真实工作台核对第一场原文，以零个对象参考提交分镜，待就绪后采用并进入画布。新增图片模型卡，填写灯下开信的正文，预检后确认执行，打开 836 × 470 的完整候选画面。仅模型输出采用本地演示响应与媒体。
