# 03: 整场剪辑总览与时间线片段联动

**What to build:** 用户进入剪辑画布后，默认浏览当前整场片段顺序、待拍占位和源 Take 关系，选择片段即可定位原时间线与播放器，继续使用既有片段编辑和保存。该票引入剪辑 graph 的完整读取、保存和前端消费路径，复用 02 的外部证据刷新保护。

Blocked by: 02 — 指令建议、检查与任务摘要实时更新

Status: ready-for-agent

- [ ] 后端提供强类型剪辑 graph，默认视图按时间组织当前片段、待拍占位及源 Take，并明确真实取材关系、源区间、时间位置、摘要和定位；前端不从当前业务数组重拼这一业务图。
- [ ] 读取与保存响应正式纳入剪辑图，四图、版本内容及元数据保持相同版本与 revision；共同校验覆盖新增对象、边、视图及来源，前端保存响应核验同时扩展。
- [ ] 素材身份保留 take_kind 与 take_id，采用身份使用独立 clip ID。同一 Take 多次采用分别显示和编辑各自区间、位置及片段适配，不合并为一个采用节点。
- [ ] 待拍占位的预期内容和预计时长与真实媒体区间分开；时间线空白不伪造为 Take、占位或覆盖缺口。此票不虚构接缝结论，真实接缝及审查迁移由 05 完成。
- [ ] 空时间线展示明确空态，保留现有素材浏览与添加片段入口，不自动选择或采用候选；独立素材视图的完整 graph 接入由 04 完成。
- [ ] 选择片段定位其真实源素材和原时间线编辑目标，并保留整场时间线；选择不自动播放、采用、修改区间或移动片段。播放器、时间线、片段适配、紧排及导出等原能力保持可用。
- [ ] 复用已有图容器、浏览与布局能力；读取来源和媒体证据使用基于已鉴权快照的底层查询，不通过完整版本读取形成递归，不解码媒体或触发生成任务。
- [ ] 保存图与当前时间线输入分开：新片段未保存时仍可在原编辑器操作；本地删除片段在旧图中显示目标不可用；保存响应不覆盖新编辑。
- [ ] 源 Take 或文件可用性变化通过 02 的刷新机制更新，不依赖 revision 改变。刷新与失败保持当前片段身份、未保存表单、视口和播放状态，不以其他素材替代。
- [ ] 通过版本 HTTP 和时间线浏览器回归验证四图快照、重复采用、源区间、占位、空白、空态、定位、编辑保存及媒体读取失败，覆盖桌面、窄屏、键盘和长时间线操作。
- [ ] 同步 OpenAPI 与 generated client，运行受影响测试、前端类型检查、后端 Pylint；新增共同契约运行 directing 测试集并回归已有三类 graph。

验收承接：A01、A02、A08（默认总览及空态）、A09（采用身份）、A11（占位／空白）、A14（片段定位）、A16（源素材证据）、A17、A18、A19、A20、A21（源素材）、A23、A24（剪辑基础）。
