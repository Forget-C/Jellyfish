# 02: 指令建议、检查与任务摘要实时更新

**What to build:** 用户在当前单元图中看见相关建议、依据与检查摘要，进入真实记录完成查看、应用、确认或原请求核实。任务完成后无需修改或保存正文即可看到更新，完整历史仍按需打开。该票同时落实后续剪辑可复用的 graph 证据刷新与当前输入保护。

Blocked by: 01 — 指令依据、参考与正文编辑接入共享图

Status: ready-for-agent

- [ ] 后端为当前单元投影绑定依据、当前相关建议／检查、待处理原请求及失效原因，提供真实记录身份与定位；主图不铺开全部历史任务，不隐藏需要核实或查看的记录入口。
- [ ] 任务和依据证据读取复用底层查询与比较，在固定场次内容上下文中完成，不回读完整版本造成递归，不以读取为由提交任务或创建确认记录。
- [ ] 当前正文来源、依据一致性、检查适用性、检查确认和任务状态分别表达；旧 graph 摘要不能将已编辑正文判为已经核验，普通保存不能解除依据已变。
- [ ] 保留建议固定输入与正文对照、预览、明确应用、来源绑定及一次撤销；查看不应用，迟到的应用或确认响应不能绑定到已经变化的正文。
- [ ] 检查提交、明确确认、视频预检、生成及按原依据重试仍走原流程。主操作依据真实业务状态和当前内容比较决定，graph 不构成执行授权。
- [ ] 待核实、运行中、成功、失败和取消均能定位原记录；未知结果只核实原授权请求，刷新和切换不会重复提交。历史查看保留原版本、输入与来源，不改写当前编辑。
- [ ] 复用现有轮询、操作完成通知和读取入口，使任务或外部证据在 revision 不变时也能更新 graph；不为刷新制造内容保存或额外内容 revision。
- [ ] 证据刷新核对版本与已保存内容基线，并拒绝迟到结果覆盖更新的读取。未保存输入、当前对象、焦点、视口和工作区状态保留；服务端内容基线变化沿已有冲突／恢复机制处理。
- [ ] 读取失败保留身份、当前输入和重试入口，旧摘要明确标示状态；不显示为无任务、空依据或可执行成功。刷新保护供后续剪辑 graph 使用，不引入通用任务引擎或第二套保存链。
- [ ] 通过现有指令建议、依据、检查和任务 HTTP／浏览器回归验证应用与撤销、依据失效、主操作、未知请求、同 revision 更新及乱序响应；验证切换画布后迟到结果不改写新现场。
- [ ] 同步本切片接口与 generated client，完成受影响业务测试、前端类型检查、后端 Pylint及相关窄屏／键盘检查；共同契约变更按规格扩大验证范围。
