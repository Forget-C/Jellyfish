# 指令与剪辑画布迁移共享 graph 协议

Status: ready-for-agent

日期：2026-10-21

本规格根据已确认的迁移范围、浏览方式、实施顺序与测试边界整理。沿用已有共识，不新增访谈或待确认事项。状态表示需求可进入实现，不表示功能已经落地或验收通过。本次仅发布规格，不执行实现、不另外创建站点计划文档。

## Problem Statement

导演画布和单元画布已经由后端生成完整业务 graph，前端负责展示、导航和编辑，四个画布也已经共用场次版本保存机制。指令画布与剪辑画布尚未接入共同 graph 协议，用户在不同阶段面对的浏览、来源定位和关系表达仍不一致。

当前指令画布围绕明确选择的生产单元，在前端组织单元依据、当前指令、参考输入及两条关系。正文、建议、依据确认、检查和拍摄已有完整业务入口，但展示摘要与关系仍依赖前端业务数组。迁移若混入旧版结构化指令模型，或把正文拆成没有可靠来源的要求节点，会改变当前自由文本指令的表达方式和工作流程。

当前剪辑画布把同场次素材、当前素材、方案判断、时间线放在四个工作区容器中，尚未表达 Take、采用片段、实际覆盖与真实接缝之间的对象关系。用户需要在素材、时间线和审片记录之间反复定位，才能理解某个片段来自哪里、覆盖了什么，以及哪些衔接需要复核。仅把四个容器名称移到后端，不能解决业务对象与关系缺少共同来源的问题。

两类画布还同时存在已保存内容、未保存编辑数据和独立变化的外部证据。任务完成、新 Take 登记、审片记录或文件可用性变化不一定推进场次版本 revision；图中的旧摘要不能冒充当前编辑的检查结果，刷新与保存响应也不能覆盖用户继续输入的内容。

## Solution

将当前场次工作台中的指令与剪辑画布接入既有共享 graph 协议。后端提供完整的业务节点、关系、成员、摘要、问题、视图与精确定位，前端复用共同图形能力，继续承担几何、视口、浏览状态和现有业务编辑。

指令画布默认直达当前明确选择的生产单元，展示单元依据、当前正文、明确参考及当前相关建议和检查摘要。保持单元切换与任务回跳，不新增全场指令总览，不将正文拆为逐句或逐要求节点。主正文编辑器继续可用，建议应用、依据确认、检查和拍摄沿用原有流程。

剪辑画布默认展示当前整场剪辑，按时间顺序组织真实媒体片段、待拍占位和实际存在的接缝，并关联源 Take、实际覆盖与相关审片依据。同场素材库保留独立浏览入口，播放器、时间线和审片表单继续承担预览与操作。主图呈现当前相关摘要，完整历史按需查看并保留原始版本、输入和来源。

图始终是已保存场次内容的展示投影，不另存一份业务数据。四个画布继续使用同一保存队列、周期、撤销、冲突与恢复机制。任务和证据变化可以刷新相关图摘要，但不能覆盖当前输入、自动应用结果或授权生成、采用、审片和导出。

## User Stories

1. 作为场次创作者，我希望四个画布使用一致的业务身份和定位方式，以便在设计、生产、指令与剪辑之间连续工作。
2. 作为指令编辑者，我希望进入指令画布时直达当前明确选择的生产单元，以便继续已有工作而不先浏览全场指令。
3. 作为指令编辑者，我希望能够明确切换生产单元，以便每次编辑都作用于正确对象。
4. 作为从单元画布进入的用户，我希望保留原单元身份与关联镜头上下文，以便不会误打开另一个单元的指令。
5. 作为从任务记录进入的用户，我希望定位原版本、单元与指定记录，以便回查真实执行依据。
6. 作为用户，我希望目标已删除或不可访问时得到明确提示，以便系统不会选择同名对象或剩余的第一个对象代替。
7. 作为指令编辑者，我希望查看本单元实际消费的执行项、约束、背景和未解决项，以便理解本次拍摄范围。
8. 作为指令编辑者，我希望依据内容能够精确回到原设计字段，以便核查来源而不靠文字匹配猜测。
9. 作为指令编辑者，我希望参考输入保留绑定身份、用途、输入角色与顺序，以便知道模型实际收到什么。
10. 作为指令编辑者，我希望正文中的素材提及不会自动变成参考绑定，以便输入关系始终来自明确选择。
11. 作为指令编辑者，我希望继续在主编辑器中阅读和修改完整正文，以便处理长指令时无需逐卡输入。
12. 作为指令编辑者，我希望正文保持自由文本，以便迁移不会引入额外的逐句或逐要求维护工作。
13. 作为指令编辑者，我希望当前正文、正文来源、依据状态和检查状态分别可辨，以便知道下一步应修改、确认还是检查。
14. 作为用户，我希望查看 AI 建议及其固定输入后再明确应用，以便预览不会改写当前正文。
15. 作为用户，我希望应用建议后仍可按原方式撤销，以便保留对当前内容的控制。
16. 作为用户，我希望依据确认、正文保存和检查确认分别执行，以便一次操作不会代替另一种业务判断。
17. 作为用户，我希望依据已变时看到真实原因，并沿原流程更新正文和重新检查，以便普通保存不会错误解除失效状态。
18. 作为用户，我希望看到待核实、运行中、成功、失败和取消的原任务状态，以便正确核实或查看已有请求。
19. 作为用户，我希望任务完成后相关摘要能够更新而不要求修改正文，以便无需制造一次内容保存才能看见结果。
20. 作为用户，我希望当前内容生成与按原依据重试仍明确区分，以便新编辑不会替换历史执行输入。
21. 作为剪辑者，我希望默认看到整场剪辑的片段顺序与真实接缝，以便判断当前成片组织。
22. 作为剪辑者，我希望空时间线显示真实空态并保留素材浏览与编辑入口，以便可以开始选片而不被自动放入候选素材。
23. 作为剪辑者，我希望通过独立素材浏览入口查看全部同场候选，以便未采用素材不会从工作流程中消失。
24. 作为剪辑者，我希望选择片段后能定位其源 Take 和真实源区间，以便准确核查取材。
25. 作为剪辑者，我希望同一 Take 的多个采用片段保持独立身份，以便分别调整区间、位置和片段适配。
26. 作为剪辑者，我希望跨版本素材保留真实生成来源，以便当前方案的判断不会改写历史生产依据。
27. 作为剪辑者，我希望素材审查、可用区间、实际覆盖和剪辑采用分别表达，以便不会把其中一个结论误认为其他步骤已完成。
28. 作为剪辑者，我希望看到人工登记的实际覆盖及其当前目标，以便计划覆盖不会被误报为真实素材已经覆盖。
29. 作为剪辑者，我希望待拍占位与真实媒体、时间线空白明显区分，以便预期内容不会被误认为已有成片素材。
30. 作为剪辑者，我希望只在直接相接的真实媒体片段之间看到真实接缝，以便占位和空白不会产生虚假审查关系。
31. 作为剪辑者，我希望替换素材、调整源区间或构图后看到有关接缝待复核，以便旧结论不会继续被当作当前有效证据。
32. 作为剪辑者，我希望整体平移未改变实际衔接的片段时保留适用结论，以便无关位置变化不会造成虚假失效。
33. 作为剪辑者，我希望图中选择对象只进行定位，以便不会自动播放、采用或移动片段。
34. 作为剪辑者，我希望继续使用原播放器、时间线和审片表单，以便迁移后仍能完成已有操作。
35. 作为审片者，我希望查看当前相关素材审查、接缝审查与整场验收摘要及失效原因，以便快速找到需要处理的问题。
36. 作为审片者，我希望画面、覆盖与声音状态分别表达，以便导出或画面通过不会自动代表声音完成。
37. 作为审片者，我希望按需查看完整历史记录及当时的固定依据，以便追溯过去结论而不拥挤当前主图。
38. 作为用户，我希望原素材不可用或证据读取失败时保留对象身份与重试入口，以便不会被静默替换成其他素材。
39. 作为需要局部返工的用户，我希望从受影响片段、接缝或落幅精确回到后段单元，以便沿原流程换绑参考并重审指令。
40. 作为用户，我希望返回和前进时恢复有效浏览位置，以便跨对象查看不会反复丢失上下文。
41. 作为用户，我希望关系树、图入口和任务回跳指向同一个真实对象，以便不同入口不会产生不同解释。
42. 作为用户，我希望图尚未同步时能识别它对应已保存内容，以便不会把旧摘要当作当前输入已通过检查。
43. 作为用户，我希望新增但尚未保存的对象仍能在原编辑入口继续操作，以便保存失败不会使输入失去访问入口。
44. 作为用户，我希望已在当前编辑中删除的对象不能从旧图误编辑到别处，以便过期卡片不会造成错写。
45. 作为用户，我希望保存过程中继续输入且新输入始终保留，以便迟到响应不会撤回我的修改。
46. 作为用户，我希望任务、新素材和审片证据在 revision 不变时也能刷新，以便看到当前可用的信息。
47. 作为用户，我希望后台刷新保留编辑内容、选择、焦点和播放状态，以便外部变化不会打断工作。
48. 作为用户，我希望手动保存与周期自动保存继续共用一个队列，以便两类画布不会增加并发覆盖风险。
49. 作为用户，我希望失败、未知结果和 revision 冲突继续保留输入并按原规则处理，以便迁移不会削弱数据保护。
50. 作为用户，我希望关闭页面后仍能恢复未保存编辑数据和必要请求状态，以便中断不会造成输入丢失或重复执行。
51. 作为用户，我希望图读取或结构校验失败时看到明确错误和恢复入口，以便界面不会伪装成空图或已保存成功。
52. 作为键盘和窄屏用户，我希望能够选择对象、阅读完整内容、定位问题并返回有效焦点，以便新图不妨碍实际工作。
53. 作为前端维护者，我希望直接消费后端的业务成员、关系、摘要和问题，以便不再维护两套业务图推断。
54. 作为后端维护者，我希望四类 graph 共用快照、引用校验与证据读取规则，以便新增画布不会产生递归读取或不一致响应。
55. 作为维护者，我希望通过现有版本接口和真实工作台行为验证迁移，以便测试能够证明功能闭环，而不是锁定内部函数结构。

## Implementation Decisions

### 1. 范围与既有领域边界

- 迁移对象是当前可编辑场次工作台的指令画布和剪辑画布；导演与单元画布作为共享协议与组件的已有实现。本轮保留现有业务能力，允许为统一浏览、定位和编辑调整界面。
- 场次版本是一套持续编辑的完整创作方案。保存延续同一场次版本并推进 revision，未保存编辑数据不是独立业务版本，graph 也不是新的可保存实体。
- 生产单元按其真实所属场次版本与单元身份定位；历史生产计划、指令、生成记录与素材保留原始来源，不改用当前最新内容重新解释。
- 保持六岗职责、实际执行范围和现有执行限制。多覆盖项单元仍可保存与浏览，图的完整呈现不扩大当前指令或视频执行能力。
- 依据一致、检查确认、模型准备、任务成功、素材审查、实际覆盖、剪辑采用、整场验收及导出分别表达，不合并为一个图级“就绪”状态。

### 2. 共同 graph 契约与版本响应

- 扩展共同 graph 契约及场次版本读模型，提供明确类型的指令图和剪辑图，继续返回已有导演图、单元图及仍有消费者的关系读模型。新增字段同步 OpenAPI 和前端 generated client。
- 读取与保存响应包含完整的业务展示投影；版本内容、元数据和四类 graph 的场次版本身份、revision 必须一致。内容快照先固定，再加载投影证据，不从后续被刷新的实例重新拼响应元数据。
- 后端决定业务节点、边、成员、视图、分组、摘要、计数、问题和来源定位；前端决定坐标、卡片尺寸、视口、缩放、浏览历史和几何排布。
- 每类图使用明确的业务节点类型与载荷，复用对象、来源、目标、视图、问题及构建校验能力，不引入任意 JSON 表单或另一套图框架。
- 每个显示节点使用不透明地址并保留真实业务身份；前端不解析地址前缀、中文标题或数组位置推断业务对象。历史无稳定身份项继续受 revision 边界限制，读取不补写身份。
- 各图保持唯一根视图、合法父级与锚点；复用节点表达多视图成员，不复制业务内容。指令图的视图协议不要求增加面向用户的全场指令总览。
- 所有业务边必须有真实来源。缺失引用或不可访问证据明确形成问题或缺失目标，不静默删边；非法重复、悬空端点、无效编辑目标、循环视图及跨快照引用由共同校验拒绝。
- 外部或历史来源显式保留身份和只读边界；编辑目标只能指向当前允许修改的业务内容。graph 结构合法不构成执行授权。

### 3. 后端投影与证据读取

- 指令和剪辑分别由 service 层领域投影器生成，复用共同构建器与读取上下文。API 负责收参、鉴权入口和响应，不在路由中组图。
- 场次内容继续通过 DirectingStore 读写，保留类型、项目归属、版本、引用与文件保护校验，不绕过存储边界直接更新业务数据。
- 在已鉴权、固定内容的上下文中批量读取需要的任务、依据、素材和审片证据；复用已有底层查询与比较逻辑。不得在 graph 构建中直接调用会再次读取完整版本的高层业务服务，以免形成递归。
- 单元实际消费范围沿用既有范围解析，指令依据比较和审查适用性沿用原规则，不根据图可见节点或连线重新推导业务状态。
- 合法但准备未完成的场次内容必须可读、可展示。缺少模型、参考或其他执行条件形成明确诊断，不能把完整执行预检作为读取整张图的前置条件。
- 图读取不提交任务、不读取或解码媒体字节、不应用建议、不确认检查、不采用素材，也不自动写入审片或落幅记录。
- 主图仅承载当前相关摘要及必要身份、定位和关系，完整历史通过原记录阅读入口按需获取。证据查询避免逐节点重复读取，版本列表读取也不能因此无界展开全部历史正文。

### 4. 指令图与编辑工作区

- 默认直达当前明确选择的生产单元。保留单元选择、从单元画布进入、任务回跳与目标不可用状态；明确导航目标优先于上次浏览记忆，不从第一个 coverage 推断替代对象。
- 图主体表达本单元依据、当前正文与明确参考，关系来源分别是实际消费的设计范围、正文绑定和参考绑定。参考仍保留独立绑定身份、用途、输入角色与顺序。
- 当前相关建议和检查通过摘要与原记录入口关联到该单元，保留绑定、待处理和失效原因。主图不铺开全部历史任务，不因只显示当前摘要而隐藏需要核实或查看的原请求入口。
- 完整正文保留在主编辑器中，继续编辑当前未保存内容；依据、参考和固定记录沿用相应只读详情或来源定位。编辑器不因摘要卡刷新、展开或视图调整而被重建并丢失输入。
- 自由文本不逐句或逐要求拆成节点，不迁入旧版不可变 Prompt、Plan、Design 链及其前端推断器。正文提及不产生参考绑定，也不通过自然语言猜测业务边。
- 建议预览、明确应用、依据确认、检查提交、检查确认和拍摄继续使用原业务入口及请求恢复。应用建议仍更新当前编辑内容并可撤销，普通保存不自动应用、确认或重新检查。
- 主操作仍按真实任务与当前内容比较结果决定可执行动作。graph 摘要仅解释已保存基线，不能代替当前正文校验、依据核对和执行预检。

### 5. 剪辑图与真实对象关系

- 默认根视图是当前整场剪辑，按时间顺序展示真实媒体片段、待拍占位和真实接缝；时间顺序不表示前端可重新推断业务邻接。播放器、时间线和审片表单保留为专属工作区。
- 同场素材库具有独立浏览入口，继续包含全部有权限查看的同场候选；默认总览聚焦当前剪辑不等于隐藏未采用素材。空时间线保持明确空态，不自动选择或采用候选。
- Take 身份保留素材类别与素材 ID，生成来源保持固定。当前版本的素材判断独立于共享 Take；其他版本的审查和采用不被改写。
- 每个采用片段具有独立身份，保持源素材、真实源区间、时间位置及片段适配。相同 Take 多次采用时，取材关系分别指向各片段，不按素材身份合并采用节点。
- 待拍占位保留预期内容和预计时长；时间线空白是没有片段内容的区间，不伪造为 Take、占位或覆盖缺口。图不改变现有时间线编辑、紧排、预览和导出规则。
- 实际覆盖只来自人工登记的真实素材及源区间，指向明确的当前单元及覆盖项。预计计划、生成成功、素材可用区间、审查通过和剪辑采用均不能自动生成“已覆盖”结论。
- 真实接缝只连接直接相接的两个真实媒体片段；空白、占位和非直接相接片段不形成该关系。适用性沿用既有规则：源素材、源区间或构图变化可能使相关结论待复核，整体平移且实际衔接不变不应错误失效。
- 当前相关素材审查、接缝审查、整场验收、落幅及受影响后段提供摘要与精确定位；历史按需进入原记录，保留原输入、版本、片段和素材身份。
- 图选择只定位业务对象，不自动播放、采用、修改区间、移动片段或执行审片。片段回跳保留整场时间线，素材回跳不误选某次采用。
- 局部返工沿用现有闭环：定位受影响后段，明确准备或换绑参考，再重新核对指令。提帧、素材复核、接缝审查、整场验收与导出仍是独立明确操作，不作为周期保存的副作用。

### 6. 共用前端能力与导航

- 两类画布复用已有图容器、浏览历史、布局状态、聚合预览能力（实际需要时）和工作台主题；业务载荷、渲染器、专属工作区与命令保持各自明确职责，不机械抽象为通用表单。
- 业务摘要和关系由服务端 graph 提供；专属编辑器继续按稳定身份读取并修改当前内容。时间线对当前输入的可视化、字段校验和编辑交互不等同于另建一套前端业务 graph。
- 场次关系树中涉及指令、素材与片段的导航复用相同后端身份和定位；不保留一套与新图相矛盾的关系推断或摘要。未保存新增对象通过现有当前编辑入口保持可达，不伪造临时业务节点。
- 明确回跳目标优先于记忆；目标失效时保留错误，不按同名、标题、数组位置或剩余对象替换。返回、前进和跨画布浏览保留有效上下文，不隐式保存或执行任务。
- 视口与布局缓存按用户、项目、场次、版本及视图隔离，稳定节点不因保存推进 revision 就丢失手动位置。旧容器位置不能按标题或索引猜测为新业务对象的位置；可可靠映射的状态才迁移。
- 长正文、播放器、时间线和内联审片仍按业务工作区布局，不强塞进紧凑摘要卡。详情、菜单、键盘焦点及窄屏行为沿用工作台设计规范。

### 7. 已保存基线、当前输入与外部证据

- 工作台继续区分已确认服务端基线和当前编辑内容。graph 对应已保存内容；未保存修改存在时明确提示图待同步，不能把旧摘要或旧检查结论呈现为当前输入已经核验。
- 新增未保存对象可以通过原编辑入口继续操作；保存失败不使其不可编辑。本地已删除的对象不能从旧图编辑到其他对象，必须显示当前目标不可用。
- 任务状态、新 Take、审片记录、落幅和文件可用性可以在场次 revision 不变时变化。复用现有轮询、手动刷新和操作完成通知，在需要时重读相关图证据；不能仅凭 revision 相同忽略新结果。
- 外部证据刷新不改变场次内容 revision，不借刷新隐式保存当前输入。graph 的内容快照身份与外部证据新旧分别处理，图摘要不是实时执行授权。
- 刷新响应核对所属场次版本和内容基线，并防止迟到结果覆盖更新的读取结果。后台刷新保持当前输入、选择、焦点、视口与播放状态；发现服务端内容基线已变化时沿现有冲突或恢复机制处理，不自动用旧内容覆盖服务端。
- 图读取失败保留当前编辑和必要对象身份，显示明确错误与恢复入口；仍显示旧图时标明其状态，不伪装成当前证据。不得回退到前端重新拼业务图来掩盖服务端失败。

### 8. 保存与恢复

- 四个画布继续共用已有版本保存机制：默认每 5 秒检查未保存修改，手动保存与周期保存进入同一个串行队列。不增加 graph 保存接口、草稿实体、自动提交链或独立发布阶段。
- 每次保存固定请求身份、预期 revision 和发送内容。响应验证原有保存契约并扩展到四类 graph，只推进确认基线，不覆盖请求期间产生的新输入。
- 暂时性失败、内容校验失败、未知结果与 revision 冲突按原规则区分。未知结果先核实或原样重放原请求，不把更新输入混入旧请求，不重复发起业务动作。
- 若内容已提交但图构建、响应传输或响应校验失败，不能直接宣称保存成功或丢弃本地输入，仍通过原保存证据进行结果核验和恢复。
- 保留本地未保存编辑数据、撤销、刷新恢复、跨版本离开保护和编辑所有权规则。图缓存与布局缓存不能替代内容恢复数据。
- 不改变独立业务操作的保存前置条件、幂等身份或原请求核实。建议应用、确认、生成、提帧、审片和导出不因浏览或普通保存自动触发。

### 9. 实施顺序与交付边界

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1. 共同契约与证据 | 扩展两类 graph、版本读模型、共同校验和基于固定快照的证据读取 | 四图与内容一致；无递归读取；合法未完成内容可展示；接口与客户端同步 |
| 2. 指令迁移 | 单元直达、依据与参考、正文工作区、当前记录摘要及原业务入口 | 编辑、切换、来源定位、建议应用、检查、拍摄及未知请求恢复可用 |
| 3. 剪辑迁移 | 整场总览、素材浏览、真实取材／覆盖／接缝关系和现有工作区联动 | 重复采用、跨版本素材、占位、空白、替换、审片与返工回跳正确 |
| 4. 刷新与导航 | 接通外部证据刷新、共同身份导航和基线保护 | 同 revision 更新可见；迟到响应不覆盖输入；目标失效不替换对象 |
| 5. 联合验收与文档 | 清理本次替换后不再使用的组图代码，执行回归并同步生效文档 | 验收矩阵通过；类型、静态检查及界面检查完成；记录未完成项或限制 |

顺序为先共同契约、再指令、后剪辑；刷新与导航在对应画布接入时同步实现，在第四阶段联合核验。两类投影和消费者配套交付，不以旧前端组图作为正式降级路径。只清理本次替换产生的无用代码，不顺手删除未被本轮使用的旧工作台实现。

## Testing Decisions

### 已确认的测试边界

- 复用上一轮已经确认的版本读取／保存快照、相关业务回归、真实浏览器交互及共同图契约验证，不新增需要用户重新确认的测试接口。
- 以完整场次工作台的可观察用户行为为主要验收边界；在已有版本 HTTP 边界验证浏览器难以可靠观察的快照、幂等、权限与并发语义。两者均复用现有入口，不为投影器、卡片或每个 hook 单独增加一层测试接口。
- 好的测试验证用户能完成操作、业务身份正确、数据不被覆盖、错误能恢复以及接口承诺成立；不依赖内部函数调用顺序、中文节点地址、固定 JSX 层级或像素坐标。共同构建器已有的非法结构测试继续复用，只补新增类型和缺失边界。
- 测试范围包括共同 graph 契约与版本读写、指令依据／建议／检查、素材判断与时间线、接缝／整场审查／落幅依赖，以及前端两类画布、相关关系导航和共有保存恢复。既有业务规则以回归验证为主，不借迁移重写行为。

### 现有测试先例

- 共同 graph 与版本读写已有结构闭合、外部来源、并发加载快照一致性、revision 冲突和请求幂等用例；新增两图进入同一组契约断言。
- 指令已有依据比较与确认、建议预览与明确应用、局部修订、检查及去向核对、主操作与准备入口、未知任务请求恢复等测试；当前场次的用例作为验收依据，旧结构化指令图测试不能代替本次验证。
- 剪辑已有同场和旧计划素材库、跨版本独立判断、实际覆盖、时间线替换与播放、接缝与整场审查、落幅依赖、来源导航和复制后审查适用性测试。
- 工作台已有周期保存、保存期间继续编辑、失败重试、关闭恢复、跨画布导航和 graph 载荷与编辑分离的浏览器测试；迁移扩展这些场景，而不是重新建立一套保存测试框架。

### 验收矩阵

| 编号 | 场景 | 可观察结果 |
| --- | --- | --- |
| A01 | 读取或保存版本 | 内容、响应元数据、四类 graph 及本地目标属于同一版本与 revision；历史来源保持原身份 |
| A02 | 非法图结构和缺失引用 | 重复、悬空、循环、跨快照本地目标被拒绝；业务缺失提供明确问题，不静默删边 |
| A03 | 模型、参考或执行准备未完成 | 合法内容仍可读取和展示；图诊断准确，不误报可生成或要求先执行任务 |
| A04 | 指令默认入口及明确回跳 | 默认当前单元，单元切换与任务精确目标正确；不存在全场指令总览前置步骤 |
| A05 | 指令依据与参考 | 实际消费范围、阶段、来源、参考绑定身份及顺序正确，不从正文猜关系 |
| A06 | 长正文、建议应用与撤销 | 完整编辑器可操作；预览不写入；明确应用保留来源且可撤销；刷新不丢输入 |
| A07 | 依据、检查与生成状态 | 普通保存不解除依据已变，不自动确认检查；原请求核实、当前内容生成和原依据重试保持区分 |
| A08 | 默认剪辑总览、空态及素材浏览 | 片段按时间组织；空时间线不自动采用；未采用同场素材可从独立入口访问 |
| A09 | 同一 Take 多次采用及跨版本取材 | 各 clip 独立编辑，取材区间正确；原生成来源、其他采用和其他版本判断不变 |
| A10 | 实际覆盖、可用区间和采用 | 三者独立表达，覆盖定位到准确当前目标；计划范围和生成成功不产生实际覆盖 |
| A11 | 占位、空白和真实媒体 | 身份、预计时长与真实区间分开；占位和空白不形成真实接缝 |
| A12 | 接缝替换、区间／构图改变与整体平移 | 仅相关结论按原规则失效；实际衔接未变的整体平移不错误失效 |
| A13 | 当前摘要与完整历史 | 当前待处理、绑定及失效原因可见；完整历史按需打开且保持固定输入和来源 |
| A14 | 图、关系树与任务定位 | 相同对象定位一致；不按首项或同名替换；选择不播放、不采用、不保存、不执行任务 |
| A15 | 局部返工和独立审片操作 | 精确定位受影响后段，换绑与重审沿原流程；无自动补拍、提帧、审片或采用副作用 |
| A16 | revision 不变但任务完成、新 Take 或审片证据变化 | 刷新展示新摘要和有效状态，无需编辑再保存；不会覆盖当前内容 |
| A17 | 新增／删除对象尚未保存 | 新对象仍可从当前编辑入口操作；旧图中的已删除目标不可错写其他对象；图待同步明确 |
| A18 | 保存或刷新在途时继续编辑、切换对象 | 新输入、选择和有效焦点保留；迟到响应不撤回输入、不切回旧对象或覆盖较新证据 |
| A19 | 保存成功但 graph 响应失败或不满足契约 | 保留输入和原请求证据，通过核实／重放确认结果，不重复业务动作或虚报保存成功 |
| A20 | 暂时失败、校验失败、未知结果、冲突和关闭恢复 | 各走已有恢复路径；相同非法内容不无意义重发，旧本地内容不覆盖新服务端版本 |
| A21 | 媒体或外部证据读取失败 | 保留身份与输入并提供重试；不以空态、替代素材或旧成功结论掩盖失败 |
| A22 | 返回、前进、四画布切换和来源查看 | 浏览与编辑上下文有效恢复；历史只读查看不改写当前方案；新明确目标优先 |
| A23 | 桌面、窄屏、键盘与长内容 | 能选中节点、阅读全文、定位问题、编辑和关闭详情；焦点可恢复；输入框操作不触发画布快捷键 |
| A24 | 共用基础设施与原流程回归 | 导演、单元、共有保存恢复及原指令／剪辑主流程仍可用；前端无被替换业务图的另一套推断 |

### 验证完成标准

- 后端版本 HTTP 与共享契约测试覆盖四图，运行 directing 测试集；若实现影响超出该模块，再扩展相关范围。
- 前端运行受影响的当前场次浏览器回归，覆盖指令、剪辑、导航、周期保存与恢复，并补齐矩阵中未覆盖的行为。实际业务交互不能由静态截图替代。
- 对外 schema 变化后，先确认本地 8000 端口加载当前工作区后端，再从项目根运行 `pnpm --dir front run openapi:update`，同步生成客户端。
- 前端代码变更后运行 `pnpm --dir front run typecheck`；Python 应用代码变更后在 backend 目录运行 `uv run pylint app`。桌面与窄屏及键盘验收遵循现有工作台设计规范。
- 相同代码和环境下已通过的检查复用结果；仅相关修改、失败或新疑点出现时重跑。实现验收记录必须区分通过、失败和未执行项，不将本次规格整理描述为实现测试已通过。

## Out of Scope

- 新增指令生成、编译、素材采用、时间线、导出或自动补拍能力；扩大多覆盖项执行支持；重做六岗或现有业务流程。
- 全场所有单元指令总览、逐句／逐要求指令节点、通过模型或自然语言猜测连线、迁入旧结构化指令模型。
- 默认把全部历史任务、审片和落幅记录画入主图，或复制历史正文成为另一份可编辑内容。
- 仅将剪辑四个工作区容器名称搬到后端并宣称完成业务对象图迁移。
- 把播放器、主正文编辑器、时间线或完整审片操作替换成紧凑摘要卡；增加普通编辑的另一套提交事务。
- 独立 graph 存储、graph 保存端点、每次按键的 graph 投影接口、第二套草稿或发布机制、通用动态表单引擎。
- 改变确认、任务提交、重试、提帧、审片和导出的授权及保存前置条件；因刷新、浏览或周期保存自动执行这些操作。
- 自动采用候选、自动改写历史来源、用预计覆盖替代实际覆盖、把导出成功当作整场验收或声音完成。
- 清理与本次替换无关的旧工作台、旧图文件或其他既有死代码；修改固化 release note。
