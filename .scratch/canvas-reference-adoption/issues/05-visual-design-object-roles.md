# 05: 简化五类画面设计的通用对象关系

Status: ready-for-agent
Blocked by: 01

**What to build:** 机位、光影、构图、运镜和焦点设计用具体字段表达一般对象关联，同时保留关注、焦点、所属镜头、验收标准及画面定位，避免同一来源承担多用途时被错误解除。

## 范围与约束

- 处理 `direction.camera`、`direction.lighting`、`direction.composition`、`direction.movement`、`direction.focus` 的 `effect_object`。
- 依赖 01 的用途定向清理和历史保护。保留其余端点的真实用途，不因多个用途共用来源而合并角色。
- 规格依据：Implementation Decisions 1–4、6–9；User Stories 1–8、12–13、26、29、33–38、42–47。

## Acceptance criteria

- [ ] 五类卡片的通用作用对象从目录、连接、保存、输出与编辑界面退役；具体设计字段仍可使用纯文本和完整来源引用。
- [ ] 运镜与焦点的关注对象、焦点卡的焦点对象保持独立；正文引用同一来源不自动建立任一角色。
- [ ] 所属镜头、关联验收要求及其现有范围保持；不向其他卡片新增验收关系。
- [ ] 运镜阶段身份、构图的运镜画面定位及其失效／冲突校验保持；不将专用状态定位退化为任意来源字段采用。
- [ ] 同源旧作用对象、关注对象、焦点对象或字段引用并存时，只清除通用用途，其他绑定、必要连接、身份和顺序完整保留。
- [ ] 清理后仍有有效用途时来源线保留；仅剩合法字段来源时成为纯候选；无合法用途时清除。不存在重复线、废弃端点或自动补引用。
- [ ] 旧通用用途独有依赖退出，其他用途引用同一来源时保留并去重；图片、视频及多项输出不扩大采用范围。
- [ ] 显式媒体引用继续检查目标模型能力和视频用途，不支持时明确诊断；未引用候选和本地示例不自动进入模型。
- [ ] 字段、预设、元信息、画面状态和无关失效数据不被清理改写；保存重开、撤销／重做规范化防止废弃用途复活。
- [ ] 五类冲突旧快照适用请求前拒绝与重新提交规则；已发起请求及历史结果不改写，无冲突运行正常。
- [ ] 前后端契约、生成客户端、受影响行为说明同步；其他七类不迁移卡片及画面风格行为不被误改。

## 验证方式

- 扩展画面设计公开接口测试，按五类卡片验证清理、完整编译、媒体能力、所属镜头及验收关系；覆盖焦点同源多角色与构图定位对照。
- 真实浏览器验证各编辑器入口、字段引用、角色选择、单条来源线、画面定位、保存重开、只读、窄屏和撤销／重做。
- 将五类类型加入冲突快照回归；运行前端 typecheck、相关前后端测试及应用 Pylint。公共契约变化同步 OpenAPI 与生成客户端。
