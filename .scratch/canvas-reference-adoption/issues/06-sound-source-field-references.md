# 06: 声音安排改用字段表达声源

Status: ready-for-agent
Completion: completed
Blocked by: 01

**What to build:** 声音安排直接在声源说明、环境声或动作声等字段表达与引用来源，不再重复选择“声源对象”；对白的明确说话对象和本地音频参考继续工作。

## 范围与约束

- 只处理 `direction.sound` 中显示为“声源对象”的 `effect_object`，不修改对白卡的 `speaker`。
- 依赖 01 的清理、合法候选保留、快照准入和撤销恢复行为，不依赖其他卡组迁移。
- 不新增音频字段引用或音频生成，不改变制作安排和本地参考用途。
- 规格依据：Implementation Decisions 1、3、6–9；User Stories 1–8、25、30、33–38、42–47。

## Acceptance criteria

- [x] 声音安排移除声源对象控件、输入用途及可生效绑定；声源说明、环境声、动作声、音乐约束保留。
- [x] 例如“钥匙落地的金属碰撞声”可以纯文本表达，也可在动作声字段引用完整钥匙来源；不要求再次选择声源对象。
- [x] 明确引用携带完整内容及既有允许的依赖；不自动采用同卡全部素材或历史输出，不扩充音频字段引用能力。
- [x] 同期生成意图、待后期、待确定等制作安排及本地音频参考、参考区间与说明保持；本地参考不因浏览或关联变成生成输入。
- [x] 对白的说话对象、类别／数量限制、稳定对白身份与版本及视觉生成主体校验不回退。
- [x] 旧声源对象绑定清理时保留正文、元信息、有效字段引用和其他合法用途；合法来源保留为纯候选，无合法用途则移除连接。
- [x] 不自动填入声源说明、转换成说话对象或改写纯文本；旧通用用途独有依赖退出，有效其他用途贡献的依赖保留。
- [x] 保存重开和旧撤销／重做快照不会恢复声源对象，正常编辑保持原子撤销；无关失效来源和旧媒体不顺带清理。
- [x] 声音安排冲突旧快照在发起模型请求前被拒绝；已发起请求、完成历史及无冲突运行保持原行为。
- [x] 契约、生成客户端和受影响说明同步，未扩大到对白或其他声音业务重设计。

## 验证方式

- 扩展声音公开接口回归，覆盖旧声源对象清理、字段引用编译、制作安排和本地音频参考不携带；以对白作为保留关系对照。
- 真实浏览器验证声音安排字段、制作安排、本地参考、对白说话对象、保存重开及撤销恢复。
- 验证声音安排的冲突快照识别；前端 typecheck、相关前后端测试和应用 Pylint；公共契约变化同步 OpenAPI 与生成客户端。
