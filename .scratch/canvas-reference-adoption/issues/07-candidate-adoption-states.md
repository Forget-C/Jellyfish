# 07: 统一候选的实际用途与状态展示

Status: ready-for-agent
Blocked by: None
Completion: integrated

**What to build:** 用户在候选区直接看清来源正在承担的全部用途，区分正文引用、明确业务角色、本地参考和未采用候选，不再遇到关系已经采用却仍显示纯候选，或展开后无说明空白的情况。

## 范围与约束

- 可基于现有有效关系及字段引用独立实施，不要求 01–06 先完成，也不在此票退役任何卡片用途。
- 读取当前真实字段引用、关系和目录表达状态，适应各卡组后续清理结果；不为展示创建第二份可编辑采用列表或额外持久采用状态。
- 规格依据：Implementation Decisions 5、9；User Stories 8、21、31–32、48。

## Acceptance criteria

- [x] 候选展示同时识别字段引用和已采用业务关系；明确角色采用不再被显示为纯候选。
- [x] 用具体用途说明来源，例如“已用作说话对象”“已引用于动作说明”；同源多用途分别可见，不仅显示一个笼统使用标志。
- [x] 暂不生效字段引用显示为保留但未生效，不计入本次实际生成采用；本地示例、浏览和预览不被显示为模型已采用。
- [x] 未采用候选、有效采用、失效引用及本地参考状态准确，计数与展示含义一致，不因同源多用途重复制造候选项。
- [x] 同一来源与接收端仍只展示一条来源线，线的用途信息与实际保留用途一致；不同输出项保持独立身份。
- [x] 无来源、加载中和读取失败分别提供明确反馈，不显示无说明的空白，不以失败伪装为零候选。
- [x] 解除一种用途或编辑字段引用后展示及时反映剩余用途；本票不改变现有解除规则、建立新绑定或自动采用唯一候选。
- [x] 只读画布可查看用途、来源与诊断，不能修改采用；预览、展开、收起和浏览选择不保存文档或增加撤销记录。
- [x] 保持验收只读展示区与素材候选分离及既有默认收起规则，不将它们合并成一个候选列表。
- [x] 键盘操作和窄屏布局可用，复用现有工作台组件；18 类清理完成后无需保留不存在的通用作用对象展示分支。

## 验证方式

- 使用真实后端浏览器场景覆盖字段采用、仅关系采用、同源多用途、本地示例、未生效引用、失效来源和无来源；核对保存文档没有被浏览操作改变。
- 在现有浏览器控制边界模拟或控制加载／请求失败，确认状态分别可见，不添加生产测试 API。
- 以对白说话对象、视觉关注／焦点关系及普通字段引用作为互补样例，确保独立于其他卡组退役即可验收。
- 运行前端 typecheck 和受影响组件／浏览器测试；仅当实际修改后端或公共契约时追加相应后端测试、应用 Pylint 和契约同步，不为纯展示改动无故扩大接口。
