# 03: 简化表演与活动卡的通用对象关系

Status: ready-for-agent
Blocked by: 01
Completion: integrated

**What to build:** 用户在情境、人物表演和镜内活动的具体字段引用相关对象，同时保留明确参与对象；删除通用作用对象不会使模型失去表演主体或其他业务关系。

## 范围与约束

- 处理 `direction.situation`、`direction.performance`、`direction.activity` 的 `effect_object`；不移除 `participant` 等专用关系。
- 依赖 01 的类型定向清理、来源线保留及快照／撤销保护能力。与 02、04–06 无业务阻塞关系，修改共享模块时协调集成。
- 规格依据：Implementation Decisions 1、3、6–9；User Stories 1–8、24、33–38、42–47。

## Acceptance criteria

- [x] 三类卡片移除通用作用对象的输入用途、绑定及界面入口，参与对象和原有业务字段仍可正常配置。
- [x] 处境、人物关系、目光、动作或任务等字段可纯文本表达或引用完整来源；例如主体甲看向乙时，甲保留参与对象，乙可在相关字段中引用。
- [x] 正文提及或引用甲不自动设置参与对象；现有主体类别／数量约束及视觉生成主体检查保持，不因移除通用关系放宽或错误失败。
- [x] 表演的所属节拍、接收事件、对白依据、验收关联，以及镜内活动的区域锚点和触发事件等保持原有用途和保护。
- [x] 同一 A 同时作为参与对象、旧作用对象和正文引用时，只清除旧作用对象；主体身份、正文引用和必要连接不变。
- [x] 只有旧通用用途的来源按合法性保留为纯候选或清除，不推断为主体、不插入正文，不新增重复线。
- [x] 完整引用和保留关系继续带入明确依赖；旧通用用途独有依赖退出，其他有效路径仍采用且不重复导入。
- [x] 正文、预设值、元信息及无关失效数据不被清理改写；旧编辑快照、保存重开和重做不能恢复废弃用途，正常操作保持原子撤销。
- [x] 三类卡片的冲突旧运行在请求前被阻止并提示重新提交；已发起请求、已完成历史及无冲突运行沿用 01 规则。
- [x] 类型目录、前后端校验、输出、生成客户端和受影响行为说明同步；不改变其他卡片主体规则。

## 验证方式

- 在现有表演和空间活动公开接口测试中逐类覆盖主体保留、主体缺失诊断、完整来源引用和新旧文档混合；真实编译图／视频输入验证主体规则，文本分析保持其现有规则。
- 真实浏览器验证同源三用途、移除通用用途后的可见关系、字段引用、保存重开、删除保护和撤销／重做。
- 扩展退役类型与冲突运行准入回归，复用 01 的历史执行边界。前端 typecheck、后端相关测试和应用 Pylint；涉及公共契约时同步 OpenAPI 与生成客户端。
- 检查主体、对白和事件的用户可观察结果，不仅检查新控件是否消失。
