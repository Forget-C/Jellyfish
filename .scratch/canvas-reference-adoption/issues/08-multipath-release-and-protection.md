# 08: 完善多路径采用、解除与删除保护

Status: ready-for-agent
Completion: completed
Blocked by: 01

**What to build:** 同一标准或完整来源经多条路径进入模型时只导入一次，用户解除某一路径不会误伤其他用途；失效、断线、删除及撤销都有可解释且一致的结果。

## 范围与约束

- 依赖 01 已完成的验收卡新引用语义与清理边界；不依赖 02–06 或 07，使用现有明确角色和字段引用即可独立验证。
- 复用正常编译使用的完整依赖闭包和稳定输出身份，不只测试较窄的验收补充路径，不另存最终依赖列表。
- 规格依据：Implementation Decisions 2–4、7–9；User Stories 7、12–13、17–23、37–42、47。

## Acceptance criteria

- [x] 同一 B 经多个已采用设计及 B → D 直接连接进入 D 时，完整标准仅导入一次，并可追溯实际采用路径。
- [x] 菱形依赖 A → B → D 与 A → C → D 中，同一明确来源输出只导入一次；未采用候选及未采用设计不参与闭包。
- [x] 去重依据稳定来源输出身份，不按名称、正文、文件内容或单一卡片 ID 去重；不同身份相同正文／文件不合并，文字与图片等不同输出不误删。
- [x] 同一媒体承担不同合法用途时用途保持，按现有素材契约处理；不扩大到全部来源输出或历史结果。
- [x] 用户正文多次主动引用相同来源时，原有表达位置和文字保持；依赖去重不改写正文。
- [x] 对 B → C → D 与 B → D，分别解除 B → C、解除 B → D、停止采用 C 时，只有相应贡献撤回；最后一条有效路径消失才移除 B。
- [x] B 不再引用 A 时，如果 D 仍直接或经其他有效关系采用 A，A 继续保留；撤销／重做重新根据现存路径计算，不依赖过期缓存。
- [x] 卡内解除单用途不删除其他用途；断开整条来源线检查全部用途，受保护的正文或业务关系存在时拒绝并给出具体位置。
- [x] 纯候选线可直接断开；现有可随断线解除的独立采用仍可解除，不为其增加不必要的引用保护。
- [x] 显式来源失效保留身份和引用并提供定位，允许保存草稿；只阻止实际采用且生效的必要依赖涉及的生成，不因未采用候选失效阻塞。
- [x] 暂不生效字段中的引用不进入生成，但保留删除保护；失效引用不自动删除或转成普通文字。
- [x] 删除 A 或 B 前检查所有保留消费者：正文显式引用受保护；B 仅有验收附着／独立采用时允许删除并展示受影响接收端，一次操作移除相关线和绑定。
- [x] 删除 B 不删除其曾引用的 A，不改变其他接收端对 A 的采用。批量删除只检查删除集合之外的引用，不要求先拆内部关系。
- [x] 断线、解除和删除按单次操作原子撤销／重做，卡片、线和绑定一致恢复；规范化不恢复 01 已废弃用途。
- [x] 方向、验收互引和 DAG 限制继续生效，标准不产生结果复核结论；来源缺失及媒体能力诊断与实际编译路径一致。
- [x] 公共语义、生成客户端和受影响行为说明同步；已有正确行为以回归固定，不为相同结果另建通用关系框架。

## 验证方式

- 扩展已有多设计加直接验收去重、菱形完整依赖、媒体能力和失效资产公开接口用例；逐步修改同一文档并编译，检查每次实际输入、来源映射和诊断。
- 用真实画布操作验证逐条解除、整线保护、单卡及批量删除、撤销／重做和保存重开；不要仅测试内部去重集合或绑定数组长度。
- 对必要异常输入覆盖缺失输出、暂不生效引用、相同文字不同身份、同源多输出及不同媒体用途。
- 前端 typecheck、后端相关测试与应用 Pylint；共享依赖／删除保护影响广，扩展对应画布回归。契约变化同步 OpenAPI 与生成客户端，复用未改变代码的已通过结果。
