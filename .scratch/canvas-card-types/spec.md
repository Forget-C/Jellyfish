## Problem Statement

自主探索的用户需要直接管理画布、组织内容并执行生成，不应被要求建立章节、镜头、节拍或先完成整套场次设计。场次工作台是后续能力复用方，本期不改变其章节及创作流程。

导演设计需要的结构化内容、关系和生成能力应当能在新的产品形式中使用，不以改造现有导演画布为前提。如果不同创作入口继续分别维护生成配置、输入解析、预检、状态和结果处理，用户会遇到同类操作行为不一致、来源难以追溯的问题。

此前卡片分类混合了“文本、图片、视频、音频”等输出形式，以及“对象、计划、模型”等业务职责或生成方式，用户难以判断人物、场所和镜头应该属于哪一类。

普通图片还不能清楚表达参考中的角色、场所、道具或服装。用户需要反复说明图片代表什么、在提示词中怎样指代；仅凭名称或连线自动采用，又可能混淆身份、用途或误用素材。

导演内容还包含结构化字段与稳定业务身份；如果仅按一段自由文本处理，就会丢失背景、设计、约束、适用范围和对象关系。用户还需要区分使用设计内容、引用对象身份和关联示例素材，避免误将全部关系当作生成输入，或将一段动作过程直接当作静态画面。

如果描述与资产选择在文本卡、参考卡中重复维护，或候选内容被当作接收卡自身字段，用户难以确定哪一处负责内容。连线即生效、沿关联跨级读取和允许回连的规则，还会使模型实际输入无法从直接连接与明确选择中看清。

独立完整页面及工作台布局已交付。本轮进一步解决添加目录浏览成本、多个常驻逻辑端点撑高卡片、状态信息挤占内容，以及阅读与拖动手势不够统一的问题。用户需要从分类图标直接找到卡片，在拖线时得到连续反馈，并在有歧义时选择连接用途；卡面主要展示输出内容，避免把内部字段与协议暴露成密集控件。

如果为复用旧模块而要求用户先建立完整场次版本，或把输入选择继续分散在提示词、关系字段和独立勾选状态中，自由编排仍会受旧流程限制。参考卡与导演卡逐级组织内容后，系统还需准确判断哪些变化影响本次生成，避免未采用候选或关联描述的修改使无关结果过期。

编辑字段、明确输出和采用粒度若混为一谈，人物表演就可能被拆成失去主体和情境的零散动作。前后端各自猜测输出结构或重复计算名称映射，也会造成预览与实际请求不一致；保存后迟迟不更新下游，或旧响应覆盖新编辑，会让用户无法判断当前生效的依据。

## Solution

优化以画布为管理单元的自主编排与生成能力，本期覆盖导演设计所需内容及独立使用方式，不改造场次工作台和现有导演画布的业务流程。前后端统一通用生成链路，形成可供后续工作台接入的能力；后续接入不作为本期交付前置条件。

项目中保留画布生成入口，点击后打开独立、完整的画布页面，完全遵循场次工作台的布局、样式与基本交互，包括顶部菜单栏及按钮、左侧悬浮面包屑与筛选、左侧添加卡片入口、卡片基本样式与交互、右侧悬浮编辑栏及底部辅助区域。不强制组件复用，只有符合当前功能规划和交互契约时才复用；验收以真实页面效果与行为为准。完整页面不再嵌在项目标签内容中。本轮明确的展示例外为左侧二级分类图标栏、四边各一连接点、输出优先卡面及单击编辑／长按拖动，按下文新规则替换原单一添加按钮、常驻左右多端点和标题直接拖动；其余工作台布局及交互继续遵循原规范。卡片内容、逻辑端点、候选选择和传输协议不因展示合并改变。

以画布文档承载创作内容，用卡片、候选连线、输入绑定和明确输出分别表达内容、可选来源、实际采用与对外提供的内容。导演对象可在画布内拥有稳定身份，不以创建旧场次版本为前置条件。前后端共用类型化协议与生成语义，预览与执行使用同一套输出及编译规则；先确定这些职责和接口，再决定复用或重设计现有模块。

后端输出处理行为与跨端数据契约分别定义：小型 Protocol 负责形成本卡输出，类型化数据模型负责结构校验与传输，前端通过生成类型和明确声明展示候选及采用操作。结构化字段不天然成为独立采用项；人物表演和其他导演工具默认整体采用，摄影设计按声明支持局部选择。导演卡已提供结构化阶段／状态时，图片生成端可指定画面目标，整卡采用的内容保持完整。

编辑在本卡即时反馈，有修改时约每秒合并保存；成功保存后由后端统一计算并刷新受影响输出，结果与对应修订匹配。不新增独立草稿对象或保存前跨卡输出预览流程，自动保存与输出刷新不触发模型生成。

### 本期与后续接入的边界

本期生成画布使用项目与画布身份创建、保存、预检和执行，不依赖章节。章节绑定、锁定、数量关系和章节驱动 AI 填充属于场次工作台后续评估范围，不新增章节创作模块，也不将这些事项留作本期实现的阻塞决策。已有项目归属、文件管理和场次业务保持现状；布局复用不引入场次四画布切换或场次版本管理。

产品入口分为基础内容、模型生成、导演工具箱；输出模态仍只使用文本、图片、视频、音频。产品分组组织用户要做的事，模态说明主要对外内容，子类型表达内容含义和字段结构，展示方式按内容选择。

人物／物件和场所使用基础内容中的文本卡维护名称与描述，不在文本卡选择资产。角色参考、场所参考、道具参考、服装参考四类图片卡只负责选择图片及名称，保存明确的默认对应；文本描述对参考卡无用，不读取、不预览、不复制。没有对应文本卡时可独立命名，也可通过直接名称关联从已有参考建立同一对象的另一份参考。角色参考可绑定人物及可选服装、道具，分别对应同一主图中的要素；服装参考只接受服装名称。完整描述由模型端通过直接文本输入独立采用。

图片参考可将其合法人物、服装、道具、场所身份提供给适配的导演关系端点，无需先建立描述卡。多人或多要素参考须明确选择具体对象；同一人物的不同角度参考复用身份，不成为多个参与对象。参考卡不会因此提供镜头、节拍等不存在的身份，也不把图片随对象关系传入导演工具。

空间锚点属于导演工具箱的表演与调度，仍以结构化文本表达。导演工具箱中的画面设计提供可视化预设与专用编辑；表演、叙事、声音、连续性与约束采用适合各自内容的结构化文本编辑。

完整目录按三组列清模态、子类型、卡片自身字段、输入绑定和派生展示。候选内容由直接连线计算；选中关系保存来源身份、用途与必要定位，不复制上游描述。目录记录产品目标，不表示全部类型、展示或生成路径已经实现；功能入口也不要求逐项建立独立卡片。

参考卡角度描述主图本身，默认正面、允许修改，不规定最终生成视角。同一对象可有多张不同角度参考，模型逐张明确采用；同画布不同独立对象在新建、改名、复制时保持名称唯一，同一身份的多份参考可复用名称。用户也可直接用模型正文或文本输入表达对应和创作要求，参考卡只减少重复声明，文字不自动增加图片输入。

输入输出与连线按生成输入、业务引用、素材关联三类关系整理；所有连线仅提供候选，接收端明确选择后才形成实际使用或绑定。三类候选连线组成统一的有向无环管道，每张卡只读取直接上游的明确输出；下游不得沿来源或对象关系跨级查询内容。导演工具仍通过文本依据参与模型生成，保留自身设计及必要对象标识，不为每种工具增加生成端点。

四类图片参考卡通过图片来源入口绑定明确选定的主图，主要输出仍是图片。接收模型明确实际采用后，系统自动建立参考名称、稳定身份与实际提交图片的映射，并在生成预览中可见；候选连线、绑定主图或预览选中不触发本次模型采用。端点目录说明语义与限制，不要求所有端点都以常驻连接圆点呈现。

## User Stories

1. 作为创作者，我希望从目录中看到四种输出模态，以便理解卡片主要提供什么内容。
2. 作为创作者，我希望产品分组、模态、子类型和生成方式分别表达，以便不会把模型生成或导演工具箱误当作第五种模态。
3. 作为导演，我希望目录保留工作单的全部字段及其用途，以便背景、设计和约束不会被混为一段正文。
4. 作为导演，我希望人物／物件、场所和镜头设计保留文本模态及明确子类型，以便产品分组变化后业务身份仍然清楚。
5. 作为创作者，我希望每类卡片说明对外输出，以便知道下游得到什么内容。
6. 作为创作者，我希望每类卡片说明图片／视频关联方式，以便区分附属素材与实际生成输入。
7. 作为创作者，我希望目录区分既有字段和建议补充字段，以便不把方案误当作当前能力。
8. 作为维护者，我希望业务目标及目录与实现验收分开记录，以便后续工作不会擅自采用尚未确定的验收边界。
9. 作为创作者，我希望输入端点说明允许的来源类型、子类型和数量，以便建立正确的连接。
10. 作为导演，我希望人物、节拍和镜头等业务引用保留对象身份，以便连接不会退化成复制一段文字。
11. 作为创作者，我希望素材关联与生成输入明确区分，以便附属图片、视频或音频不会自动参与生成。
12. 作为独立创作者，我希望直接从画布管理开始创作，以便无需创建章节或完成场次设计。
13. 作为独立创作者，我希望新建、命名、保存并重新打开画布，以便持续管理不同的创作探索。
14. 作为创作者，我希望自主添加、拖拽、编辑和组织卡片，以便按自己的思路编排内容与生成步骤。
15. 作为创作者，我希望明确配置接收端用途和实际使用的输入，以便理解本次生成依据。
16. 作为创作者，我希望生成结果可以预览、比较并明确用于后续创作，以便持续探索而不丢失已有成果。
17. 作为创作者，我希望手工创建、导入或明确另存的同类内容使用一致字段语义，以便继续编辑和生成。
18. 作为创作者，我希望明确修改内容及其关系，以便保留无关内容和仍有效的对象身份。
19. 作为导演，我希望在本期产品中编辑人物、场所、叙事、表演、摄影、声音和镜头等设计，以便完整表达拍摄意图。
20. 作为导演，我希望这些功能可以通过合适的卡片、详情编辑或关系操作提供，以便不依赖现有导演画布改造才能使用。
21. 作为导演，我希望结构化设计能作为生成依据，结果可在下游继续使用并保留来源，以便衔接后续生产而不建立反向传输环。
22. 作为创作者，我希望画布内同类生成使用一致配置、输入规则和诊断，以便不因卡片入口不同而误判能力。
23. 作为创作者，我希望生成时固定实际执行依据，以便当前编辑不会悄然改变正在执行的请求。
24. 作为创作者，我希望重新打开画布后看到真实运行状态和历史结果，以便继续工作而不重复发起生成。
25. 作为维护者，我希望前端的公共交互与后端的通用生成能力集中维护，以便修复能够同时作用于真实复用入口。
26. 作为场次工作台用户，我希望后续四个画布复用共同能力时仍保留各自业务职责，以便设计、生产、指令和剪辑的含义保持清楚。
27. 作为创作者，我希望从基础内容、模型生成和导演工具箱三个入口找到能力，以便按创作意图添加内容或工具。
28. 作为创作者，我希望人物／物件和场所留在基础内容中，并被导演工具引用，以便不会重复建立同一个对象。
29. 作为导演，我希望在表演与调度中建立空间锚点，以便为人物站位、走位和镜内活动提供稳定位置依据。
30. 作为导演，我希望锚点可以先用文字建立再补充图片标记，以便参考素材变化时已有身份和调度引用仍能保留。
31. 作为创作者，我希望通过效果预览选择并调整风格、构图、光影和运镜，以便更直观地表达画面要求。
32. 作为导演，我希望表演卡先显示人物与动作过程，再展开情境、细节和约束，以便能逐步完善表演而不面对整张复杂表单。

150. 作为创作者，我希望缩放、布局、撤销和小地图与工作台位置一致，以便快速找到常用画布操作。
151. 作为键盘或窄屏用户，我希望菜单、卡片、端点和详情均可访问，以便视觉调整不会限制原有编辑能力。
152. 作为维护者，我希望以同尺寸真实页面截图和交互验证判断对齐效果，以便不会把组件复用或功能测试通过误作视觉验收。
153. 作为维护者，我希望复用以满足当前功能规划为前提，以便无需为了既有组件引入场次专属流程或改变生成协议。

154. 作为创作者，我希望从左侧分类图标直接进入对应卡片列表，以便用两级选择找到需要的内容。
155. 作为创作者，我希望一级图标有可读名称和选中反馈，以便理解基础、参考、模型及不同导演工具入口。
156. 作为创作者，我希望二级面板可以搜索、点击创建及拖入创建，以便在长目录中快速操作。
157. 作为创作者，我希望每张卡片四边中间各有一个连接点，以便自由安排走线而不被内部字段撑高卡片。
158. 作为创作者，我希望悬浮连接点只查看最终输出摘要，以便快速了解可提供的内容。
159. 作为创作者，我希望拖线从按下开始持续跟随指针并吸附兼容目标，以便一直看到连接方向和目标。
160. 作为创作者，我希望唯一兼容方式直接建立候选、多种方式让我选择用途，以便减少操作但不猜测我的意图。
161. 作为创作者，我希望取消用途选择时不留下连接或绑定，以便试探操作不会改变创作依据。
162. 作为创作者，我希望图片参考的名称身份和主图仍能分别用于适配目标，以便简化端点外观不会丢失对象关系能力。
163. 作为创作者，我希望卡片中部优先呈现最终输出，顶部命名、底部显示状态，以便从画布直接阅读创作成果。
164. 作为创作者，我希望生成中的临时内容与已发布结果有明确区别，以便失败或过期时不会误认当前成果。
165. 作为创作者，我希望普通点击或长按拖动完成后松开都打开该卡右侧详情，拖动期间保留已有详情，以便编排与编辑可以连续进行。
166. 作为创作者，我希望键盘和触摸都能完成分类选择、候选连接及卡片移动，以便核心操作不依赖鼠标悬浮。

167. 作为创作者，我希望点击添加在可见空闲位置创建、拖入在释放位置创建，并打开新卡详情，以便立即开始编辑而不丢失画布视角。
168. 作为创作者，我希望尚无结果时也能按声明类型先布线，以便先编排流程、待输出可用后再明确采用。
169. 作为创作者，我希望重复连接定位已有关系、不同用途分别展示，以便避免重复关系并准确管理用途。
170. 作为创作者，我希望所选连接侧边随布局恢复，以便移动或重开画布不会改变我安排的走线。
171. 作为创作者，我希望通过“连接到…”选择目标并在拖线时看到接收用途，以便触摸与键盘也能清楚地建立候选。
172. 作为创作者，我希望过早移动取消长按、取消拖动不切换详情，以便操作不会引起意外位移或编辑目标变化。
173. 作为创作者，我希望左侧摄影入口新建独立设计、已有卡详情编辑自身设计，以便不同摄影方案不会被自动合并。

## Implementation Decisions

本节记录已确认的业务边界、页面布局、卡片协议、模块职责与接口约束、生成链路及复用原则。结构和模块名称表达职责，不规定最终代码文件、类名、物理表结构或 HTTP 路径；具体编码和迁移仍须后续设计。

### 画布创作与结果应用

- 本期围绕人工建卡、导入、字段编辑、明确关系和模型生成展开；章节提取、锁定及其批量填充／提案应用流程移出本期。
- 原文／创作依据卡保存用户输入或导入的内容及来源定位，不建立章节绑定，不改变外部原文。事实、提议、待确定内容及其来源保持区分。
- 模型可提供文本建议，用户通过明确复制、另存结果或字段编辑形成新的内容；不因生成成功自动覆盖卡片、建立绑定或发起后续生成。本期不新增批量 AI 画布变更提案系统。
- 复制／另存后的内容有独立身份及自身正文或文件，保留只读来源；它是明确内容应用，不是持续读取来源卡的隐藏输入。普通文本和媒体卡不为这一操作新增持续输入端点。

### 导演功能覆盖与产品形式

- 内容表达覆盖下方完整卡片目录中的导演设计内容，保留背景、设计、约束、待确定信息及其字段语义。
- 关系表达覆盖人物、事件、节拍、镜头、素材与适用范围。关系可以通过端点、关联区或其他明确操作表达，不要求每个字段都变成连线。
- 创作操作覆盖人工创建、导入、字段修改、关系调整和局部生成；结果经明确选择后进入下游参考或后续创作，并保留只读来源记录，不建立回到上游设计的传输环。
- 产品按基础内容、模型生成和导演工具箱分类，完整页面及工作台布局按下方已确认方案；卡片、详情和关系选择按本规格。卡片基本样式与基本交互完全遵循场次工作台，专用字段和业务端点按本规格；具体有限尺寸档位与专用编辑细节在该边界内确定。
- 本期不规划改造现有导演画布试点，也不迁移单元、指令和剪辑画布。四画布逐步复用是后续方向，各自的设计、生产组织、指令检查、素材审查与剪辑职责继续保留。
- 功能覆盖不等于本期重建生产单元、Take、实际覆盖和剪辑采用系统。计划、生成结果和实际采用仍分别表达，不因生成成功而自动采用。

### 共用生成链路与复用范围

共用主流程为：编辑卡片与明确选择 → 保存画布 → 解析已选直接输出 → 编译与预检 → 固定执行依据 → 提交生成 → 发布结果。结果后续通过明确选择或复制／另存进入新的创作步骤，不回写输入选择。

| 层面 | 共用能力目标 | 保留的业务职责 |
| --- | --- | --- |
| 前端 | 画布交互、卡片公共结构、端点、引用编辑、模型参数、媒体预览、运行状态与结果展示。 | 本期导演字段及设计信息编辑；场次工作台专属操作留在原业务。 |
| 后端 | 通用生成契约、输入解析与媒体处理、模型能力规则、固定执行依据、任务执行、状态、结果来源和公共诊断。 | 本期画布对象身份、直接关系及必要内容校验；章节和生产登记规则不在本期改造。 |

- 画布内同类生成操作实际使用共同能力；统一不能只体现为外观相同或同名接口，输入、能力、状态和结果语义应一致。
- 统一链路不等于将所有任务合成一种业务类型，也不扩大为章节或后续生产流程改造。
- 复用从本期真实共同需求中提取，不因少量外观相似建立万能卡片、任意字段字典或通用表单框架。
- 以本规格的画布行为为设计目标，先确定卡片、输入绑定、明确输出与编译接口，再决定现有模块如何承接。模块只有在契约与行为不冲突时才复用；冲突部分允许重新设计，不为保留旧实现增加双重数据源或旧语义限制。
- 当前编辑、执行依据、运行状态、当前输出、历史结果和文件分别表达。重新打开恢复真实状态与已有成果，不因恢复界面而重复生成。
- 下方确定画布数据职责、模块接口和页面组件复用边界；最终代码组织、物理存储、详细协议字段及全站其他入口迁移方案仍未确定。保留必要业务能力不等于原样保留现有类、类型或内部调用方式。

### 面向画布的数据职责与类型契约

画布文档是创作单元。卡片保存本卡内容，候选连线声明可选来源，输入绑定记录实际采用，明确输出说明本卡向下游提供什么；产品分组、模态和展示入口不能代替这些职责，也不直接决定是否创建生成任务。

| 结构 | 主要内容 | 契约与保存边界 |
| --- | --- | --- |
| 画布文档（CanvasDocument） | 身份、项目、名称、创作上下文、卡片、候选连线、分组、协议版本。 | 采用严格类型的文档；独立画布不要求章节或场次。编辑修订与协议版本分别管理。 |
| 卡片定义（CardDefinition） | 类型与版本、字段结构、产品分组、输出模态、输入输出声明、可采用粒度与范围、展示入口。 | 由系统定义，前端不能任意拼接类型和模态；端点语义不能只从名称推导，可采用范围使用稳定标识。 |
| 卡片（Card） | 卡片身份、类型与版本、本卡内容、输入绑定。 | 内容按子类型校验；结构化设计保留字段状态、背景／设计／约束用途、范围与来源，不退化成任意 JSON。 |
| 候选连线（CandidateEdge） | 来源卡与输出端点、接收卡与输入端点、生成输入／业务引用／素材关联用途。 | 只提供直接候选，全部边共同构成有向无环图；同模态不代表用途或对象资格匹配。 |
| 输入绑定（InputBinding） | 绑定身份、直接来源输出、选择范围、用途、顺序、分组及必要字段／媒体区间定位。 | 接收端实际采用的唯一权威记录；不复制来源正文或保存候选全集。 |
| 明确输出（DeclaredOutput） | 共同外壳包含稳定输出身份、所属端点、可用状态与必要来源；内容按明确类别提供强类型变体及适用模态。 | 内容卡及工具按契约形成输出，模型从已发布结果提供输出；对象引用是关系数据，不是第五种内容模态。输出与卡片编辑结构分开，不作为第二份可编辑内容维护。 |
| 运行快照（RunSnapshot） | 固定文档与选择、执行范围、实际输入、编译结果、模型和有效参数。 | 与当前编辑分离；本轮上游结果按固定依赖解析，下游提交前固定具体请求，不能读取后续编辑替换依据。 |
| 生成结果集（ResultSet） | 一次运行成功交付的有序输出、媒体文件和生成依据。 | 与当前输出指针、历史及未完成成果分别表达，保持来源和生成身份。 |
| 画布布局 | 卡片位置、尺寸、视口等。 | 与生成依据分开，拖拽不使结果过期或预检失效；跨设备持久化及存储方式另行确定。 |

- 目录入口不等于独立数据对象。同一摄影设计只由一张摄影内容卡保存，构图、机位、运镜、光影、焦点是该卡的编辑入口，不建立多张可编辑卡同步一个隐藏对象。在已有摄影卡中打开入口只编辑对应区域；独立方案通过明确新建或复制形成新卡，不因所属镜头相同自动合并。独立风格卡保持独立。
- 提示词中的结构化引用指向输入绑定，输入区选择和媒体用途也维护同一份绑定。引用内容被明确采用，不另设可能与正文或请求矛盾的独立勾选状态；引用插入、取消及用途修改须同步维护这份记录。
- 候选列表、来源预览、已选数量、显示代号与映射预览由直接连线、绑定和输出派生，不成为新的内容或采用依据。界面排序不能改变上游输出身份与结果集。
- 卡片间的输入必须对应直接候选边。直接上传或选择文件／资产时保存明确文件及来源身份，不虚构上游卡片，也不能借外部来源绕过实际存在的跨卡关系与无环规则。
- 外部来源仅在相应卡片和输入允许时使用；人物／物件、场所文本仍不提供资产选择。参考卡主图固定选中的具体图片，不能只保存资产“当前默认图”；来源再次生成或资产默认图变化不自动替换主图。
- 自身内容、输入绑定、输出、运行和布局分别有清晰职责，但不要求每个结构、目录入口或子类型独立建表。物理表、字段名及缓存方案后续再映射。

### 画布创作上下文与稳定身份

本期以画布作为默认创作上下文。结构化人物、场所、锚点、节拍、事件和镜头可在画布内建立有效对象身份，不以创建章节、完整场次工作单或已确认场次版本为前提。独立命名参考可按参考类别建立稳定对象身份；其对象引用与结构化文本的对象引用按相同类别规则接入名称关联或导演业务端点，不以图片模态排除参与资格。参考只能提供实际声明的人物、服装、道具、场所等对象，不获得镜头、节拍等其他身份。普通正文、文件名与模型输出中提到的对象不能自动获得业务身份。

| 身份 | 负责区分 | 使用规则 |
| --- | --- | --- |
| 卡片身份 | 画布中的可编辑、可连接内容单元。 | 不因显示标题、位置或预览变化而改变。 |
| 描述／设计对象身份 | 人物、物件、场所、锚点、节拍、事件、镜头及其他明确设计对象。 | 在创作上下文内校验类型和关系；参与哪个镜头、属于哪个节拍由明确绑定决定。 |
| 图片参考身份 | 某份命名视觉参考，与被命名对象身份分开。 | 可关联已有对象，或独立命名后提供稳定对象引用；接收端明确选择且类别适配时可成为画布内参与对象。同一对象多份参考保留各自参考身份、主图和角度，不因角度增加参与对象数量，不自动创建现有场次实体。 |
| 资产身份与文件身份 | 素材的资产来源及实际媒体。 | 分别保留；同图不等于同一对象，文件引用须通过项目归属、类型、可用性及使用关系校验。 |
| 外部场次对象身份 | 后续明确接入既有场次版本时的对象。 | 本期不新增场次对象导入或同步；未来接入继续按原业务校验版本，不因画布名称绑定自动创建该身份。 |

- 画布、章节与场次不合并为一个身份；本期只使用画布创作上下文，不新增章节绑定和锁定。
- 名称关联只建立名称与图片的默认对应；稳定身份用于同一对象在多份参考间的明确复用，不按同名合并，不传递描述正文，不推断镜头参与、道具持有或服装穿着指令。
- 同一画布内不同独立对象名称唯一，校验覆盖新建、改名和复制；跨画布允许重名。复制为新独立对象须使用不同名称，明确复用同一身份则不算创建重名对象。唯一性针对对象名称，不仅是卡片标题；多份参考可显示“张三·正面参考”“张三·侧面参考”，共享同一张三身份。尚无合法名称及身份的未完成卡片不提供有效对象引用输出。
- 从上游选中的名称与身份由该直接输出提供，接收参考不能就地改成另一对象；须先明确取消或替换名称绑定，才能独立命名。物件须通过结构化类别区分服装、道具，不从名称、正文或图片猜测类别。
- 对象引用统一提供稳定身份、名称及必要类别；来源可以是适配的结构化文本或命名图片参考。选择具体对象而不是整张参考卡；关系数量按对象身份计算，同一身份的多份参考不重复算作不同人物，绑定仍保留明确选择的直接来源，不自动改用其他同身份来源。
- 独立参考可直接参与表演等设计，无需新增“补充描述并转移身份”操作。需要补充文字时，可由普通文本直接参与模型生成；参考中的图片仍须单独直接采用。
- 镜头、节拍、适用范围、阶段和条件作为设计信息保存与展示。模型端不要求设置目标镜头／所属场次，不按这些信息自动筛选、补齐或扩大输入；用户明确选择本次内容，系统检查必要对象、明确结构化冲突及实际能力。范围校验不能成为跨级读取理由。
- 接入现有场次时保留既有来源、范围和版本语义；本期不把自由画布保存切换为场次版本保存，也不迁移现有导演画布。

### 画布模块职责与接口约束

本期按以下四项职责组织模块，优先保持接口集中；这不要求四个独立进程、服务或固定数量的代码文件。不新增章节创作模块，也不为未来接入预建额外存储或同步层。

| 模块 | 对外承担的职责 | 内部处理 |
| --- | --- | --- |
| 画布文档模块 | 创建、读取、保存和管理画布。 | 修订冲突、幂等、身份与名称唯一性、字段结构、候选图、绑定合法性、项目及文件引用。 |
| 卡片输出模块 | 提供直接候选、已选输入及卡片明确输出。 | 按拓扑组织逐卡计算，处理直接输入、对象映射、输出范围、可用性与相关变化。 |
| 生成编译模块 | 将模型配置和实际采用的明确输出编成请求及诊断。 | 采用范围、字段状态与用途、媒体用途、默认名称映射及参考角度、实际能力和可确定结构冲突；不推断全场／镜头适用关系，不校验纯文本语义或图片内容。 |
| 画布运行模块 | 预检、提交、观察、取消并保留结果。 | 实际依赖规划、依据冻结、任务占用、事件恢复、结果发布与有效性。 |

- 单张卡的输出处理接口只接收本卡内容、已选直接输入及本卡已发布结果（模型卡需要），不取得整张画布的任意内容读取能力。输出组织可以遍历依赖，逐卡处理仍限于一级，不允许通过来源或对象标识补读祖先正文。
- 模型编译接口只接收模型配置、实际采用的明确输出和能力信息；不能持有整张画布或按对象身份查询更多创作内容。模型请求中的名称映射必须来自直接输出中已经形成的对应信息。
- 候选展示由直接输出形成，不能以预览为由跨级展开正文。身份、文件归属等合法性校验与创作内容读取分别处理，校验不增加实际输入。
- 角色参考形成命名图片、导演工具形成设计文本属于数据组织，不创建模型任务；只有明确的生成操作进入生成任务系统，导演卡不成为隐式模型节点。
- 前后端预览与实际执行遵守同一输出和编译规则；前端可提供即时提示，后端负责最终校验。内部结构变化不授权前端新增另一套按名称猜测类型或用途的规则。
- API 层负责收参、归属核实和响应，业务编排由相应模块负责；跨层生成契约集中维护，前端通过 OpenAPI generated client 使用公开协议，任务与供应商模块不重复定义这些契约。

| 处理位置 | 接收到的直接输入 | 对外明确输出或请求 |
| --- | --- | --- |
| 角色参考卡 | 直接候选中明确选择的人物及可选服装、道具身份与名称，明确主图和本卡角度。 | 主图、参考身份、所选名称—主图默认绑定、参考角度及必要图内定位；不读取描述，不聚合上游媒体。 |
| 人物表演卡 | 本卡表演字段及明确选择的人物、节拍等直接关系。 | 本卡背景、设计、约束、范围与必要对象标识组成完整设计输出，不拆选目光或身体动作；不附带关联对象全文或示例媒体。 |
| 视频模型 | 已采用的角色参考输出、表演输出。 | 实际图片、名称映射和所选表演要求；完整张三描述只有直接连接并另行采用后才加入。 |

### 卡片输出行为与前后端协议

协议分为数据契约、后端行为接口和前端展示接口，职责如下；这些概念不要求新增独立服务或每类卡片一套继承层级。

| 层次 | 负责内容 | 明确边界 |
| --- | --- | --- |
| 跨端数据契约 | 使用既有 Pydantic 类型化数据模型定义卡片、端点、绑定、输出与诊断，经 OpenAPI 生成前端类型。 | 使用明确判别字段和强类型变体，不靠可选字段是否存在、类型名称字符串或任意 JSON 猜测输出含义。Protocol 本身不承担 JSON 校验或序列化。 |
| 后端输出处理接口 | 采用小型 Python Protocol，约束根据本卡内容、已采用直接输入及本卡已发布结果形成明确输出与诊断的行为。 | 卡片数据定义与行为处理器分开；共用字段可保留数据模型基类。候选查找、绑定解析、图及归属校验由外围模块承担，处理器不取得任意画布或数据库查询能力。 |
| 前端展示接口 | 按类型使用专用编辑组件，复用端点、候选、采用和诊断展示；消费生成类型、输出声明与后端派生结果。 | 前端负责即时编辑和基于统一声明的基础提示，不再维护完整的输出计算或名称映射编译逻辑，不将全部字段自动变成可采用项。 |

- 明确输出采用共同外壳与强类型数据变体。文本、媒体、命名图片和对象引用分别声明允许提供的内容；描述文本出口与对象引用出口即使属于同一卡，也不能互相补读字段。下游只消费所连出口的明确内容。
- 结构化文本输出保留字段语义、状态及背景／设计／约束用途，生成编译时再形成模型所需文本；不提前压平为丢失结构的一段正文，也不暴露本卡全部输入绑定或内部编辑字段。
- 各类型处理器按实际差异组织输出；角色参考组织名称与主图，导演工具组织本卡设计与必要对象，模型输出处理器提供已发布结果。输出计算不提交模型任务，生成编译和运行继续承担各自职责。
- 接收端按输出契约获得可采用范围与稳定标识，显示名称和列表序号不承担定位身份；动态条目重排后仍指向原条目。未声明的内部字段不可通过任意路径读取。范围粒度按下方采用规则决定，不统一开放逐字段勾选。
- 输出为派生数据，不成为第二份可编辑内容。编辑引起的下游更新以保存成功为时点，模型结果继续遵守既有结果发布规则；运行快照和历史不随新输出改写。

### 输出选择、执行依赖与结果有效性

| 判断事项 | 依据 | 限制 |
| --- | --- | --- |
| 连线能否成立 | 声明的输出类型、端点语义、模态、来源资格和整张候选图。 | 可在尚无实际输出时先建立候选边；未采用边也检查无环，同模态不等于用途兼容，模型能力未确定时不猜测用途。实际采用仍要求有效明确输出。 |
| 输入是否采用 | 接收端的明确输入绑定。 | 新增候选不生效，断线或失效不能静默换用其他来源。 |
| 是否需要执行上游 | 实际采用、当前结果有效性与明确执行范围。 | 候选边不直接产生任务，固定产物不因下游执行而要求重跑来源。 |
| 本卡输出是否变化 | 本卡契约实际提供的内容及必要映射。 | 不把未传递的描述、候选和关联示例变化一律当作输出变化。 |
| 已有结果是否仍适用 | 模型实际使用的输出、用途、编译依据、模型与有效参数。 | 画布任意编辑不等于所有结果过期；相关变化才影响对应依据。 |
| 历史是否变化 | 本次运行的固定依据与已保存结果。 | 历史不被按新编辑重新解释；结果适用性与真实运行终态分别表达。 |

| 输出选择方式 | 定位对象 | 更新规则 |
| --- | --- | --- |
| 当前输出引用 | 来源维护的稳定输出位置。 | 按明确执行范围解析其已发布内容；位置身份与暂时是否有内容分开，不提供未发布未来位置的引用。 |
| 固定产物引用 | 明确结果集中的具体产物，或明确选择的文件与来源。 | 参考卡主图、连续性等选定媒体保持固定；来源再次生成不自动替换，不等待其下一次运行。 |

- 本轮需要执行的上游，其已有合法输出引用可按既有预检规则在上游完成后解析；执行文档、绑定、范围与依赖已固定，下游提交前校验并固定具体输入。不新增对从未发布或当前缺失输出的引用能力。
- 结果有效性按实际使用的明确输出判断；预检凭据仍受文档修订及既有编辑失效规则约束，不能把“结果未过期”误当成旧预检仍可提交。布局变化与内容编辑分别管理。
- 未采用候选不改变模型的实际依据；参考名称映射按稳定对象身份组织，不按同名合并。一个图片输出映射多个对象不自动重复提交图片，不同用途和主体组织仍遵守真实模型能力。

| 变化示例 | 对仅采用相应输出的模型的影响 |
| --- | --- |
| 修改人物年龄，但模型只采用其命名图片参考。 | 年龄未进入图片参考的明确输出，不应仅因此使结果过期。 |
| 修改人物名称，直接参考输出的名称映射发生变化。 | 重新判断受影响模型的实际依据。 |
| 增加一个未采用的候选。 | 不改变已有结果的实际依据，也不自动选择它。 |
| 表演卡的示例视频变化，但模型只使用表演文本。 | 不将示例视频变化当作模型媒体输入变化；如实际文本要求未变，不因此使结果过期。 |

### 采用范围与字段状态

编辑结构、输出结构与采用粒度分别声明。结构化字段可以单独编辑，不表示接收端能够逐字段采用；输入绑定按对应出口声明的单位和范围保存实际选择，不保存采用当时内容的隐藏快照。

| 输出或用途 | 可采用粒度 | 规则 |
| --- | --- | --- |
| 人物表演的设计文本 | 一张表演卡的完整设计输出。 | 参与对象、人物目标、目光变化、身体动作等共同作为一次输出；不能只选择其中一项。连接多张表演卡时逐卡选择，可以采用其中一张或多张。 |
| 其他导演工具的设计文本 | 默认完整设计输出。 | 角色情境、站位与走位、空间锚点、叙事节拍、声音与约束等不机械开放逐字段选择；摄影设计按下行例外。 |
| 摄影设计文本 | 完整输出，或契约明确声明的区域、字段／状态、动态阶段。 | 可选择运镜、运镜的结束画面等独立范围，不能访问未声明字段；所选范围与动态条目使用稳定标识。独立风格卡仍按完整设计输出采用。 |
| 对象引用、模型生成结果与其他输出 | 按各自明确输出单位和已声明范围。 | 对象引用选择具体对象，模型多结果逐项选择；不因导演文本整卡采用而整批采用结果、主图或其他出口。媒体区间及用途继续遵守对应端点规则。 |

采用完整设计仍保留每个字段的状态与用途，背景用于解释、设计用于呈现、约束用于限制，不把全部字段都解释成必须可见的动作。人物表演不提供“单独采用目光后自动补齐其他字段”的机制，也不沿对象关系补读正文或图片。

| 采用范围或变化 | 当前生成依据的处理 | 边界 |
| --- | --- | --- |
| 整卡采用 | 跟随已选内容输出的当前字段范围，包含后来补充到该范围内的字段。 | 例如表演卡补充身体动作、参考卡新增明确名称绑定进入相应当前依据；不自动采用模型后来新增的结果项或本卡其他出口。 |
| 契约允许的局部采用 | 只跟随选定区域、字段／状态或动态条目的当前内容。 | 摄影只采用运镜时，后来补充的光影不进入；其他导演卡不因此获得局部采用能力。 |
| 字段仍存在但被清空或设为不适用 | 保留原选择范围，不生成该项要求，不改选其他字段。 | 仅本次所需对象、静态目标等必要信息缺失时阻断，不把合法空字段一律视为失效引用。 |
| 所引用的对象、输出或动态条目被删除，无法定位 | 按失效引用处理，明确取消或替换绑定。 | 不静默忽略必要输入、不退回旧值，也不自动改绑。 |
| 增加直接候选或修改所选范围之外的内容 | 不自动采用，不扩大现有范围。 | 范围内更新不等于自动运行；当前变化不改写运行快照或历史。 |

完整／局部采用仅控制已选输出内部范围，不扩大已采用的生成结果项集合。当前输入按所选范围计算，编辑保存成功后刷新相关输出；重生成按既有当前输出位置／固定产物规则解析，已受理运行与历史仍使用固定依据。

图片生成的画面目标与采用范围分别表达。导演卡已明确提供结构化阶段／状态时，图片生成端可选择本张图要呈现的目标状态，同时完整采用该卡设计；这一选择属于接收模型的本次生成配置，并定位到已采用输出中的明确状态，不删除设计中的其他字段，也不新增第二份采用记录。已有多阶段静态画面所需的目标状态校验仅针对这种明确结构；普通文本卡或动作字段中的自由描述不自动拆解成阶段，不因文字描述了过程而强制选择时刻，也不为此新增阶段字段。视频生成可使用完整过程，摄影契约已经声明的局部选择能力仍独立保留。

结构化字段的状态影响输出表达，不通过分析用户正文推断状态。图片／视频生成按下表保留含义；文本生成也可接收明确选中的状态信息辅助分析或完善设计。

| 字段状态 | 实际采用后的表达 | 运行边界 |
| --- | --- | --- |
| 未填写 | 不生成对应要求，不补写猜测内容。 | 可继续保存或使用其他有效内容；必要输入缺失才阻断。 |
| 不适用 | 不生成对应要求。 | 不等同于明确禁止某事。 |
| 明确没有 | 按字段含义表达否定，例如没有对白。 | 不与未填写混为一谈。 |
| 待确定 | 保留开放选择标记，可用于探索式生成，不编译为已确认硬要求。 | 必需对象、图片所选目标状态等仍须明确；生成结果不自动把设计改为已确定。 |
| 提议 | 保留建议性质，可作为已采用的创作提议参与探索。 | 不自动升级为事实或必须执行的约束。 |
| 事实 | 按所选内容保留事实标记及来源。 | 系统不通过正文或图片真实性校验替用户证明该事实；背景／设计／约束用途仍分别保留。 |

“提议特写”与“提议全景”作为开放探索输入保留，不自动升级成两条必须同时执行的要求；状态语义先于互斥要求判断。纯文本中的类似表述仍不做语义检测。

### 保存、预览与运行协议

保存允许未完成创作，运行要求本次实际采用的内容有效。空名称、缺主图、未填写设计等状态按卡片规则可保存为未完成内容，不建立独立草稿对象或草稿接口，也不把占位当作可用输出；非法类型、身份、端点或传输环仍阻止保存。

| 完整性层次 | 判断内容 | 本期边界 |
| --- | --- | --- |
| 保存合法 | 类型、身份、候选图与绑定结构合法。 | 允许未填完的设计；合法的空关系不等于错误绑定。 |
| 生成可用 | 本次实际选择的内容、必要作用对象、目标状态和模型用途明确。 | 运镜无需先建镜头、表演无需先建节拍；实际用到的对象或静态目标状态缺失时才定位补充，不把缺少全部导演关系当成统一阻断条件。 |
| 导演设计完整 | 镜头、节拍等关系及整套设计达到完整业务要求。 | 与生成可用分开；本期不建立整场完整性或自动适用性检查系统，也不把它作为生成前置条件。 |

本期只校验可明确表达的结构与数据，以下边界同样适用于编辑提示、编译预览和运行预检。

| 校验对象 | 处理 | 不扩大的边界 |
| --- | --- | --- |
| 对象类别、名称唯一性、直接关系、端点、数量、文件与模型能力 | 按明确契约校验；非法结构或实际必要输入缺失须定位处理。 | 不从自然语言、图片内容推断对象身份或实际采用。 |
| 同一明确目标／所选状态上必须同时满足的互斥单值配置 | 按字段状态判断后阻止相关生成，用户调整或取消其中一项后继续。 | 例如同一静态画面必须同时满足特写与全景。待确定／提议保留探索性质，不仅因取值不同就当作硬冲突；类型、数量和模型能力仍校验，不推断时序或整场适用范围。 |
| 用户手写纯文本 | 原样保留并按明确采用进入请求。 | 不做纠错、语义冲突检测或基于此类检测的警告，不猜测它覆盖了哪个绑定；显式结构化引用仍按绑定协议校验。 |
| 图片中的人物、角度、左右位置及是否符合描述 | 不做内容正确性或视觉一致性验证。 | 可校验文件、已填写的结构数据和引用合法性，不能据此宣称图片标注正确。 |
| 替换参考主图 | 保留明确名称绑定，在确认替换时提示核对角度与图内位置，可由用户修改标注。 | 不自动识别或纠正标注，不要求额外视觉审核或强制待复核状态。 |
| 合法空字段与失效引用 | 按“采用范围与字段状态”分别处理。 | 不因未填完全部导演设计而阻断无关有效分支。 |

| 阶段 | 对外能力 | 主要校验与效果 |
| --- | --- | --- |
| 编辑与保存 | 创建、读取、保存、删除画布及管理修订。 | 保存卡片、候选边和输入绑定的一致文档；校验结构、身份、来源归属与无环，不要求全画布创作完成。 |
| 编辑预览 | 本卡编辑即时反馈，保存成功后展示更新的直接候选、已选绑定对应内容、本卡输出及定位诊断。 | 不提交模型；跨卡派生预览使用对应已保存修订，预览不改变采用，旧响应不能覆盖新状态。 |
| 模型能力与编译预览 | 展示真实能力、实际文本、设计、媒体、名称映射和用途。 | 与执行使用同一输出及编译规则，不因工具预设扩大模型能力。 |
| 运行预检 | 核对运行范围、实际输入和模型条件，形成预检依据。 | 仅相关依赖和采用内容影响运行准备度；画布中无关未完成卡片不阻断独立有效分支。 |

| 观察与取消 | 恢复真实状态、事件、累计成果与取消进度。 | 沿用一致快照和事件恢复语义，重开页面不重跑任务，取消请求不等于任务已终止。 |
| 完成与继续创作 | 登记结果集、历史和当前输出，明确选择下游来源。 | 判断是否更新当前输出，不回写输入选择，不自动采用结果或覆盖固定产物。 |

- 卡片字段、候选连线和输入绑定可通过一次完整文档保存共同变更，不要求按每个子类型或每条关系分别建立写接口。
- 卡片与端点定义、非模型卡的输出预览需要统一协议表达；是否分别提供目录或预览 HTTP 接口，以及具体路径，后续按真实调用需求决定。
- 本期模型端按明确选择编译，不新增章节操作、AI 批量提案流程或场次目标上下文作为运行前置条件。
- 实现时同步受影响的公开契约、OpenAPI 和 generated client；具体接口路径、错误码扩展及兼容策略另行细化，不以沿用旧接口为由限制已确认语义。

### 自动保存与保存后输出刷新

沿用既有编辑、修订、幂等、恢复与冲突保护，将自动保存合并周期从当前约 5 秒调整为约 1 秒。这里是有修改时的自动保存周期，不是停止输入后等待 1 秒的去抖；持续输入期间也会保存，无修改不发送请求。

| 场景 | 保存与输出行为 | 保护规则 |
| --- | --- | --- |
| 本卡内容、选择或配置修改 | 本卡立即反馈，待保存修改约每秒合并提交一次。 | 自动保存请求按约 1 秒周期协调，不为每次按键单独提交；布局继续与生成依据分离。 |
| 没有修改 | 不发送保存请求。 | 不因定时检查制造无意义修订。 |
| 上次保存尚未完成 | 等待在途请求，只合并最新待保存内容，完成后按自动保存节奏处理。 | 同一画布保存串行，回执推进保存基线，不覆盖期间的新编辑，不积累逐次编辑请求队列。 |
| 保存成功 | 后端统一计算受影响的明确输出与诊断，前端更新相关候选和已采用内容的展示。 | 输出与已保存修订对应；旧回执或旧输出响应不能覆盖较新状态，前端不另行复算完整业务输出。 |
| 手动保存或点击生成 | 立即处理待保存修改，不等待下一个自动保存周期；已有请求仍串行协调。 | 生成必须先成功保存并完成预检，不能使用尚未保存的修改绕过既定冻结与提交规则。 |
| 保存失败、结果未明或冲突 | 保留本地编辑并提示，沿用幂等核实和冲突保护，不把未保存修改当作下游新输出。 | 同一无效内容不每秒重复报错；结果未明沿用原请求身份核实，修订冲突不静默覆盖。 |

下游可见延迟包含约 1 秒合并等待以及保存、输出计算和响应耗时，不承诺端到端严格 1 秒。保存与刷新只更新对应当前内容，不自动采用新增候选、不自动运行模型，也不改写运行快照或历史。已保存输出与本地编辑的状态须能区分，但不新增独立草稿实体、草稿发布流程或保存前跨卡预览接口。

| 表演与调度 | 人物＋路径 | 角色情境、人物表演、表演规则、空间锚点、站位与走位、镜内活动、环境活动与留白。 | 导演工具箱；不重复创建人物／场所描述卡。 |
| 叙事与镜头 | 场记板 | 叙事概览、叙事节拍、事件与刺激、镜头设计。 | 导演工具箱。 |
| 声音设计 | 声波 | 对白、声音安排。 | 导演工具箱；tooltip 明确为声音设计，区别于导入音频。 |
| 连续性与约束 | 盾牌＋勾选 | 空间规则、连续性设计、不可改事实、创作控制、生成指导、验收要求。 | 导演工具箱；不使用笼统的“其他”入口。 |

- 图标外观参考本轮竖向悬浮栏与右侧二级面板示意，颜色、边框、字体和按钮状态沿用工作台。一级栏靠左留边、与筛选及底部工具避让，二级面板在相邻右侧展开，不挤压画布；高度受可用视口约束，超长目录在面板内滚动。窄屏面板在视口内调整宽度和位置，关闭入口始终可达。
- 悬浮一级图标仅显示名称，点击才展开；点击另一分类直接切换，点击当前分类或 Escape 收起。内层输入／菜单优先消费 Escape；关闭恢复到对应一级入口。展开不改变画布视角，初始无展开面板。
- 二级项使用图标＋名称；搜索过滤当前分类，切换分类清空搜索避免新分类看似缺失。无匹配结果显示明确空态。点击创建和拖入创建均可用，拖入取消不建卡；只读时可浏览但创建禁用。
- 点击添加在当前可见画布的空闲位置创建，避开浮层并尽量避免卡片重叠；拖入添加在释放位置创建。两者均选中新卡、收起添加面板并打开右侧编辑栏，不自动平移、缩放、连接或采用。
- 左侧摄影入口每次创建独立方案，不按当前选中卡、同一镜头或已有摄影卡自动合并；修改已有卡的其他摄影字段从该卡详情进入，五个入口不是全画布唯一实例。
- 模型、基础卡、参考卡和导演分组的图标取统一风格，禁止只靠图标猜测含义；tooltip、可访问名称与面板标题一致。
- 素材库／上传若作为已有动作保留，放在分隔线下方，与卡片分类区分；本次不因此新增素材管理能力或上传入口。

### 浮层协作与连接操作状态

- 添加面板与连线用途菜单互斥；开始连接时收起添加面板。桌面可保留编辑栏，但不能遮挡正在选择的目标；窄屏进入添加或连接操作时暂时隐藏编辑栏，取消或连接结束后恢复原编辑会话。创建成功按新卡规则打开其详情，原卡会话仍保留。
- 卡片菜单提供“连接到…”，进入明确的连接操作状态并显示目标连接点；选择目标后按唯一／多种兼容方式确认候选。键盘可从连接点启动同样流程，触摸不必先打开详情或精确拖动小圆点。选择目标不触发普通卡片点击详情，退出后恢复普通点击规则。
- 临时隐藏和恢复不丢输入、不重置媒体上下文、不改变画布视角。Escape 优先处理内层控件及当前菜单／连接，再处理编辑栏；取消连接不创建边或采用。

### 四边连接点、悬浮输出与连线确认

一个卡片四边中间各一个连接点，共四个。它们是同一卡片的几何锚点，不是字段或逻辑端口；每条实际关系仍明确保存原有来源输出和目标输入用途。连接从 A 拖向 B 就表示 A 提供候选给 B，由箭头表达方向，选哪一边只改变走线，不改变语义。几何位置与业务采用分离，多条连接可共享一个几何点。

| 状态 | 可见内容与操作 | 数据结果 |
| --- | --- | --- |
| 默认 | 不显示字段级端点列表、类型标签和候选计数；已有连线的连接位置保留可辨小点。 | 不改变现有关系。 |
| 卡片悬浮、键盘聚焦或选中 | 显示四边连接点，小圆点配更大的有效命中区；触摸通过选中显示。 | 不创建关系或采用。 |
| 连接点悬浮／聚焦 | 显示主要最终输出摘要，如“文本”“图片 · 4 项”“视频”；离开连接点与提示区域后消失，键盘失焦同样收起。 | 不列人物目标、动作等内部字段，不因预览指定某个结果。 |
| 从连接点开始拖动 | 立即显示从起点到指针的临时连线并持续跟随，不等待卡片长按阈值；指示方向。 | 不提前保存边。 |
| 接近目标连接点 | 兼容目标高亮并吸附，提示切换为接收用途，如“可作为首帧／尾帧候选”；不可连接时说明原因，临时线仍可随指针移向其他目标。 | 平常悬浮显示输出，连接过程中目标显示接收用途；不因几何吸附建立采用。 |
| 松开：无兼容方式 | 不建立连接，提示不兼容或能力待核实；能力未核实不能猜默认用途。 | 原文档不变。 |
| 松开：唯一兼容方式 | 直接确定该来源输出／目标用途并固定连线。 | 只建立候选关系，不建立绑定、不采用、不运行。 |
| 松开：多种兼容方式 | 在松开时的指针位置附近弹出用途菜单，等待用户选择；临时线继续显示，菜单自动避开屏幕边界。 | 选择后才建立相应候选；不是按目标拥有的全部输入类别数量判断。 |
| 取消 | Escape、取消用途菜单、释放到空白或取消指针操作后撤销临时线与菜单。 | 不留下边、绑定、采用或布局变化。 |

- 兼容方式由来源声明的输出类型、目标用途、类别资格和实际模型能力共同决定；候选布线不要求当前已有结果，实际采用资格仍由有效输出决定。菜单列出兼容的“来源输出 → 接收用途”组合，用“作为首帧候选”“作为主体参考候选”“引用人物身份”等可理解文案；互不等价的组合不能被一个模糊模态名合并。选择时重新核实直接关系及无环规则，等待菜单期间目标被删除、能力或输出变化时不能保存失效选择。
- 尚未生成的模型卡、尚未选图的图片卡可按声明类型先布线，接收端显示“暂无可用输出”；内容保存或结果发布后才提供可采用项，不自动采用、不产生未来输出绑定、不触发运行。不从空内容推断对象身份，类型／类别与模型能力不足以确定用途时不猜测兼容。
- 相同来源卡、来源输出、目标卡和目标输入用途只保留一条候选关系；再次连接提示“该候选连接已存在”并高亮已有线，不新增、不改绑定或采用。不同用途允许分别建立关系，仍遵守无环及实际模型能力。
- 同一对卡的不同用途使用轻微错开的独立曲线，可分别选中；默认不堆叠文字，悬浮或选中显示具体用途与采用状态。删除按每条关系的实际采用保护处理，不合并为一条含义不明的线。
- 用户选择的起止侧边固定，移动卡片后不自动换边；侧边随现有布局状态保存，同一浏览器重开恢复，不新增跨设备同步。旧连线没有侧边时按卡片相对位置确定初始侧边；几何变化不改变业务关系或生成依据。
- 例如图片 → 视频模型可能有首帧、尾帧、关键帧和主体参考多种方式；文本 → 同一模型可能只有文本依据一种方式。多输入目标并不意味着每次都弹菜单。
- 主要模态摘要不取代完整协议。命名图片参考仍可提供主图及对象身份，结构化文本仍可提供正文及对象身份；适配目标需要区分时进入用途菜单。对象引用不新增第五种模态，也不从图片内容或正文推断身份。
- 四个连接点不表示所有卡片都有输入能力。普通基础内容卡仍没有持续输入；作为目标时按实际协议拒绝连接。合法建立候选后，关系保护、明确采用及删除规则继续按原规格执行。
- 多结果来源的预览项、第一项或全部结果都不能因拖线被自动采用；单结果、唯一用途也不例外。落点确认只确认候选连接，输入端实际选择仍独立进行。
- 悬浮输出提示与用途菜单不能泄漏祖先内容或未声明字段。键盘和触摸使用等价的可访问连接操作，唯一／多种方式、取消和明确采用规则相同；不要求精确鼠标悬浮才能完成任务。
- 固定连线跟随卡片移动和缩放，箭头与来源／目标一致；候选与发生明确采用的关系可区分，完整用途、候选和采用计数按需在悬浮或详情查看，默认不持续堆在卡面。

### 输出优先卡面与状态层级

卡面固定按“顶部名称＋弱化类型 → 中部主要输出 → 底部辅助状态”组织。使用工作台统一字号、间距、深灰卡面和边框；普通状态小字号、低强调但保持可读对比，失败、失效和需处理事项保留文字及语义提示，不能全部弱化为浅灰。名称与类型不替代内容，内部 ID、完整参数、字段状态清单和候选统计不常驻卡面。

| 卡片 | 中部主要输出 | 底部状态与阅读边界 |
| --- | --- | --- |
| 普通文本、原文依据、对象描述 | 正文、摘录或描述的可读摘要。 | 未填写、待保存或来源失效等必要信息；完整编辑进入详情。 |
| 图片与命名参考 | 图片预览；参考卡在图旁或图下显示已绑定名称及角度。 | 缺少主图、名称不完整、关联失效等；不展示候选描述正文。 |
| 视频／音频 | 可播放的媒体预览。 | 时长、加载或文件异常等；播放器操作不拖动整卡。 |
| 导演工具 | 对外设计文本的可读摘要，适用时配图示或已关联参考示例。 | 缺项／明确失效等；示例不冒充对外媒体输出，摘要不删减完整设计或改变整卡采用。 |
| 模型生成 | 最近已发布结果，多结果提供预览切换；无结果时显示“尚未生成”及简短输入概况。 | 模型信息、生成中／失败／依据已变更等简短状态。临时流式内容与正式输出明确区分；保留旧成果时标明其身份和状态，不将旧图冒充本次新结果。 |

保存前本卡编辑仍即时显示；“输出优先”不要求本卡等保存后才回显，也不增加独立草稿。下游仍只消费保存成功后的明确输出。多结果预览、播放和展开不改变输出集合、采用范围或模型运行。

### 单击编辑与长按拖动

卡面只展示内容，不提供字段内联编辑或正文拖选；字段编辑、文字选择与复制在右侧编辑栏完成，卡片菜单可提供复制正文。卡面非独立控件区域仍可点击打开详情或长按拖动。

| 手势阶段 | 卡片与详情行为 | 边界 |
| --- | --- | --- |
| 按下卡面 | 开始点击／长按判定，不打开或切换详情。 | 已打开详情保持原对象与会话。 |
| 短按并在容差内松开 | 打开当前卡片右侧详情。 | Enter／Space 提供等价打开操作；字段不在卡面编辑。 |
| 长按阈值前明显移动 | 取消本次长按及点击判定，不移动卡片、不打开新详情；本次手势不转为画布平移。 | 已打开详情保持不变，不能计时结束后突然开始拖动。 |
| 达到长按阈值 | 提供抬起或描边反馈，随后可随指针拖动。 | 鼠标初始约 200ms、触摸约 350ms，先在小范围内保持按住；触摸容差可更宽，真实操作验证后可微调，不增加用户配置。 |
| 拖动中 | 移动卡片，原详情保持不变。 | 若拖动的正是已打开卡，持续保留同一编辑会话；拖动与详情展示可以并行。 |
| 正常结束长按／拖动并松开 | 打开或切换到当前卡片详情；原本已打开该卡则保持同一会话。 | 不要求拖动后再点一次；详情开合不自动平移、缩放或整理画布。 |
| Escape／指针取消 | 取消拖动并恢复本次拖动前布局，不提交半完成拖动、不打开新详情。 | 已打开的原详情保留；取消后释放不再触发点击打开。 |

- 从端点按下立即进入连线，不等待长按；标题也遵循整卡长按规则。媒体播放、按钮和菜单使用自身事件，不触发整卡拖动或详情打开。
- 同一次指针手势不同时承担卡片拖动与连线；详情展示与拖动不互斥。只读状态沿用既有布局权限，不借手势绕过内容或关系编辑权限。保留键盘移动、框选和修饰键多选，这些操作不误触普通点击打开，焦点始终可见。
- 详情开合、对象切换、临时隐藏和展开保留各卡片已访问会话、预览结果及媒体播放位置；隐藏媒体暂停。长按拖动只改布局，不改内容、采用或生成依据。

### 分类定义

- **产品分组**：基础内容负责组织已有内容，模型生成负责可配置的生成操作，导演工具箱负责创作设计与指导。三组是产品入口，不增加新的输出模态。
- **模态**：卡片主要对外提供的内容形式，仅有文本、图片、视频、音频；不表示整条流程的最终成果。模型生成看主要输出，导演工具箱当前以结构化文本要求为主。
- **子类型**：内容的业务含义与字段结构。人物／物件、场所属于基础文本内容；角色参考、场所参考、道具参考、服装参考属于基础图片内容；空间锚点属于导演工具箱的表演与调度，仍是文本模态。
- **展示方式**：按内容选择预览、字段、步骤、对照或关系操作。图片与视频可以用于示例展示，不因展示媒体而改变工具卡模态。
- **来源与生成方式**：手动编辑、导入、原文选取、资产选择、模型结果及明确复制／另存分别记录。生成操作集中在模型生成组表达；模型提出的建议仍须通过明确编辑应用，不新增章节提取或批量 AI 填充流程。
- **保留内容的归属**：卡片自身字段维护本卡内容；输入绑定维护明确选中的直接来源、用途和关系；派生展示读取这些信息形成界面，不建立第二份上游描述。结构化文本继续保留字段状态、用途和适用范围，不能退化成正文与类型标签。
- **对外输出**：普通文本提供正文，业务文本提供带语义和来源的设计内容，媒体提供文件引用，模型提供独立生成结果；图片参考同时保留名称、类别与稳定参考身份，用于实际采用后的映射，不增加独立文本输出或第五种模态。单份内容与有序结果集分别表达。
- **媒体关联**：对象素材、说明、参考或来源证据。示例预览、素材关联、生成实际输入和最终采用分别表达，不因选择预设或显示预览而自动使用媒体。

所有基础内容、模型生成和导演工具遵守同一归属规则。下表说明需要维护的信息，不规定数据库布局或具体接口。

| 层次 | 负责内容 | 保留边界 | 示例 |
| --- | --- | --- | --- |

- 图片尺寸、媒体时长等由文件信息展示；本卡预计时长、生成时长参数和实际媒体时长保持不同含义。

### 完整卡片类型表

### 来源、输出与媒体关联

- 基础文本可手工建立、导入或明确复制／另存生成结果；原文／创作依据保留只读来源定位。人物／物件、场所文本不提供资产选择，参考卡只绑定名称与图片；模型文本建议通过明确字段编辑应用，不新增章节提取或批量填充流程。
- 普通文本输出正文；业务文本输出本卡描述或设计及必要对象身份、名称、范围和来源。人物表演等混合字段按背景、设计、约束组织，不沿输入关系加载其他卡的完整内容。
- 基础图片、视频、音频各提供一份媒体；模型输出保留结果身份，多结果按明确顺序及选择使用。视频保留自带音轨，声音安排文本不会自动成为音频。
- 人物、物件和场所的视觉素材通过对应图片参考卡组织；需要多份参考时分别明确选择，不把文本卡变为资产素材板。参考素材可来自本地上传、项目或资产库、明确选定的生成结果。
- 锚点、表演、构图、运镜等工具可明确关联参考，并定位具体字段；连续性区分前态／后态素材，不可改事实保留证据用途，验收要求区分合格示例／反例。工具可显示直接关联媒体，但其文本输出不携带这些文件。
- 镜头设计的分镜、预演和效果参考不代表实际覆盖；对白及声音安排可关联音频、表演或口型参考，不自动改写对白版本或替换视频音轨。模型需要关联媒体时，须从媒体输出建立直接连接并采用，不能穿透工具读取。
- 首帧、尾帧、关键帧和主体参考仍是接收端用途，不新增对应基础图片子类型。

### 图片参考卡的内容与身份

四类参考卡提供可复用的默认名称—图片对应。它们通过名称关联消费直接对象引用中的身份、名称与必要类别，不读取、预览或复制描述正文。来源可以是文本对象或命名图片参考；同一对象引用也可供适配的导演关系选择，仅连线不建立绑定。

| 图片参考子类型 | 可绑定名称类别 | 默认绑定表达与限制 |
| --- | --- | --- |
| 角色参考 | 人物，以及可选服装、道具。 | 有效人物名称可来自绑定或本卡独立命名；服装与道具不必填写，只说明同一主图中的可选构成要素；可明确多人或图内位置，不聚合上游参考图片，不自动新增穿着／持有动作指令。 |
| 场所参考 | 场所。 | 名称对应本卡环境主图；不输出场所正文，不保证布局、尺度或空间规则准确。 |
| 道具参考 | 道具。 | 名称对应本卡道具主图；不推断持有者或使用动作。 |
| 服装参考 | 服装。 | 只绑定服装名称；不把人物名称或示例模特当作服装对象，不自动新增穿着要求。 |

- 每张卡明确选择一张主图，来源为上传、项目／资产素材或明确选定的产物，固定文件及来源。主图不随来源再次生成或资产默认图变化而替换。
- 对象引用只包含本卡已明确绑定的对象，或本卡合法独立命名的对象身份、名称与类别，未选候选不进入输出。它可供名称关联或类型适配的导演关系选择，不携带主图；服装／道具类别由结构化数据明确，不分析自由描述或图片判断。
- 未绑定本类别主对象时可按参考类别独立命名，并保留可供其他参考或类别适配的导演关系使用的稳定对象身份；角色参考独立命名人物时仍可绑定可选服装／道具。参考身份、被命名对象身份、标题、资产和文件身份分别表达；独立名称遵守同画布唯一规则，复用同一身份的多个参考不算重名对象。
- 角度描述本卡主图本身，默认正面、允许修改。它随命名图片输出说明“这张参考是什么角度”，不规定最终画面的拍摄角度；最终视角由明确采用的摄影设计或模型正文表达。
- 一张主图可明确对应多个名称，必要时填写图内位置；位置只说明名称指向主图中的哪一处，不是描述正文。绑定不证明图中真的存在这些对象，也不保证模型视觉一致性。
- 模型可同时采用同一对象的多张参考，每张均须明确采用。相同身份的多图不天然冲突；需要主体分组时由用户明确组织，单值端点、数量和组合限制仍按模型能力校验。
- 替换主图保留明确名称绑定，确认替换时提示核对角度、图内位置等标注，用户可修改。只校验可明确的结构、数据与文件，不自动识别、纠正或强制视觉审核，不新增强制待复核状态。
- 名称或主图缺失可保存为未完成内容，但没有有效命名图片输出；已有合法对象身份与名称可通过对象引用独立提供候选，不等同于图片已经可用。未命名且未绑定对象的参考卡不提供有效对象引用，不另设草稿实体。
- 本期不新增单卡多主图、自动识别、裁切或自动汇聚角度组；多份参考与模型支持的显式主体分组不受此限制。

“添加另一角度参考”通过明确的直接名称关联复用身份，并独立选择新卡主图和角度；操作须明确包含选择含义，不因普通拖线就采用。例：独立命名的正面参考 A 提供张三名称，侧面参考 B 明确选择 A 的名称出口，模型分别采用 A、B。B 不读取 A 的祖先，不转发 A 的图片或未选候选；新建 B 不自动增加模型采用。来源失效、改名或删除沿用直接绑定、唯一性和失效处理规则。

### 文本与图片在模型端独立采用

参考卡中的“名称绑定”与模型中的“文本采用”独立。文本描述对参考卡无用；模型只采用参考卡时，自动使用其已确认的默认映射，完整描述不进入请求。

| 阶段 | 候选 | 用户明确操作后的效果 |
| --- | --- | --- |
| 张三文本卡连接参考卡 | 张三的稳定身份和名称。 | 仅连接不建立绑定；参考卡不展示年龄、外貌等正文。 |
| 在参考卡选择张三及主图 | 名称与图片分别可选。 | 建立张三—图片的默认绑定，形成参考卡自己的明确输出。 |
| 参考卡连接模型卡 | 该参考卡的命名图片输出。 | 仅连接不提交图片，也不生成本次映射提示词。 |
| 模型明确采用参考卡 | 已确认名称—图片绑定随该输出提供。 | 采用图片并自动生成名称映射，不要求再次勾选参考卡已确认的默认绑定。 |
| 文本卡直接连接模型卡 | 完整文本描述。 | 另行明确采用后，才加入本次创作描述。 |

以文本 A“张三，30 岁，神情疲惫”和已绑定张三名称及主图的参考 R 为例：

| 模型端实际采用 | 本次输入 |
| --- | --- |
| 只采用 A | 张三的所选文本描述。 |
| 只采用 R | 图片及“张三对应这张图片”的默认映射；不包含“30 岁、神情疲惫”。 |
| 同时采用 A 和 R | 所选文本描述、图片及默认映射；按稳定身份对应，不按同名猜测。 |
| 都只有连线，没有采用 | 均不进入请求。 |

需要完整描述时，必须有文本卡到模型的直接连接和明确采用。组合快捷操作也须明确包含这两步，不通过参考卡读取正文。所有卡片都遵守“直接候选 → 接收端明确选择 → 本卡明确输出”的流程；参考卡可输出已选名称供下一张参考建立自己的绑定，导演卡输出自己的设计，均不能把所有上游绑定或媒体整体转发。

### 实际采用后的名称映射

参考卡保存默认对应，模型在实际采用后自动编译本次映射，不另设第二次采用映射的步骤。参考卡不是表达创作要求的必经步骤；用户可直接在模型正文或已采用文本中表达名称对应、穿着、持有等要求，实际媒体仍须明确采用。

| 情形 | 映射行为 | 边界 |

| 编译与预览 | 映射进入编译后的提示词及模型支持的输入表达，实际图片、角度与用途可核对。 | 不反复追加到用户编辑正文；图片代号属于当前接收模型。 |
| 修改主图、角度、已绑定名称或采用范围 | 当前映射按直接输出及有效选择更新，取消采用后不再提交。 | 不自动运行；历史保留固定依据，未采用候选变化不改变实际映射。 |
| 同一对象多参考或一图多名称 | 保留对象身份与每份参考身份，分别说明已采用主图和角度。 | 不同独立对象禁止同画布重名，不按名字合并；多名称不自动重复提交同一输出，多图仍受用途、分组及数量限制。 |
| 角色、服装、道具等同时采用 | 按明确类别组织默认名称—图片对应。 | 角色卡的服装／道具名称只说明同一主图要素；额外衣物、道具图片须由模型直接采用，不自动新增穿着或持有动作。 |
| 模型不支持用途或组合 | 保留编辑内容并定位问题，阻止不受支持的生成。 | 不强制转换用途，名称映射不保证视觉一致性。 |

用户手写纯文本原样保留，不做纠错、语义冲突检测或基于此类检测的警告；即使文字与默认映射存在语义矛盾，也不自动改写正文、覆盖结构化绑定或推断增加图片输入。默认映射继续按实际绑定编译，正文按用户输入参与请求，不承诺自动识别或解决二者的自然语言矛盾。显式插入的结构化输入引用仍受直接关系、实际采用和类型校验约束。

参考图不因连接视频生成就成为首帧；用户选定首帧、尾帧、关键帧或主体用途后按用途处理，名称映射不额外增加主体输入。四类参考不是四种同名模型参数。仅接收文本的模型不能借名称映射采用图片，完整描述须从文本依据独立提供。

### 共同保留信息与关联规则

- **身份与来源**：卡片和业务对象的稳定身份、所属项目与画布创作上下文、来源对象与版本；实际接入既有场次时另保留场次及版本身份。卡片身份、图片参考身份、资产身份和文件身份分别保留。名称映射不能取代这些身份或按同名合并对象。
- **字段状态与范围**：按“采用范围与字段状态”保留空值、否定、事实及开放设计的区别；采用按输出声明的粒度跟随所选范围；导演默认整卡、摄影可按明确范围局部采用。制作阶段、条件及适用范围仍为设计信息，不自动判断整场／镜头适用性，不按位置、分组或连线数量推断。
- **生成记录**：模型、提示词和有效参数归本卡配置；结构化引用与用途属于输入绑定。当前编辑、运行状态、当前输出和历史结果分别保留，候选列表不是另一份生成配置。
- **媒体来源**：本地上传后关联项目文件；资产库和已有素材保留明确引用；生成结果经明确选择后关联，不自动成为已采用素材。
- **关联用途**：对象素材、说明、参考、来源证据以及正向示例／反例明确区分。必要时定位到具体字段或视频区间。
- **身份稳定**：人物或场所文本可以没有图片；下游参考卡可选择其身份与名称并绑定媒体，同一图片可对应多个明确名称。反向使用摘要只读，替换媒体不改变对象身份，不因共享文件合并对象。
- **采用边界**：人物设定图、摄影结束画面示例或连续性前后态图片，不自动绑定为首帧、尾帧或主体参考；实际使用由接收端明确决定。
- **关系边界**：三类传输连线都只提供候选且统一无环，不能通过业务引用、素材关联、选择器或隐藏绑定建立等价回路。只读来源记录、被使用记录不作为反向输入，不用于跨级取数。
- **现有职责**：人物描述与角色情境分别保留；场所、空间规则与空间锚点分别保留，空间锚点的产品入口在表演与调度；镜头设计与实际生成视频分别保留。验收要求及其示例不代表验收通过。

### 直接上游传输与统一无环

候选展示只能查看直接上游的明确输出；用于本卡处理、实际绑定或生成的内容还须在接收端明确选中。下游只消费当前卡声明的输出，不能沿对象引用、素材关联、来源记录或名称映射继续查询祖先内容。输入绑定和展示方式不构成豁免。

允许多级生产，每次读取只有一级。例如“图片生成 → 角色参考 → 视频生成”中，角色参考明确选择具体图片并形成自己的命名图片输出；视频生成直接消费它。禁止把全部上游内容包装为通用集合继续透传。

| 当前卡片 | 明确输出的范围 | 不随输出继续传递 |
| --- | --- | --- |
| 普通文本／媒体 | 本卡明确提供的正文或媒体及必要来源标识。 | 来源卡的其他内容和输入集合。 |
| 命名图片参考 | 图片出口提供本卡主图、参考类别与身份、已选名称／身份、角度及位置说明；对象引用出口只提供合法名称、身份与类别。 | 关联文本全文、未通过图片来源明确选为本卡主图的上游图片、其他候选及上游输入集合。 |
| 人物表演等导演工具 | 本卡背景、设计、约束、范围及必要的作用对象名称／身份，默认作为完整设计输出采用。 | 所引用人物的完整描述、图片及其他关联设计。 |
| 空间锚点 | 本卡锚点说明、空间关系及必要标识。 | 所属场所完整描述和关联素材。 |
| 模型生成 | 已发布的生成结果及必要结果／来源标识。 | 本次模型全部输入和祖先卡片内容；生成结果本身可以表达基于实际输入新形成的内容。 |

- 必要身份与名称用于明确指代，不授权继续读取对象正文。参考卡通过名称关联输入，只消费直接文本对象引用或参考卡对象引用出口中的身份、名称与必要类别，仅名称关联不读取描述或来源图片；另行明确选择图片来源时只读取该图片出口，其他接收端也只预览所连出口声明的内容。
- 所有生成输入、业务引用、素材关联的候选连线共同构成有向无环图；尚未实际采用的连接也必须无环。按关系类型排除某些边、把连线藏在关联区或改称素材绑定都不能绕过检查。
- “人物描述 → 图片生成 → 同一人物描述”的回连不允许。可将生成结果和人物描述分别直接连接到新的下游参考卡，再明确选择；来源和反向使用信息以只读记录显示。
- 来源、历史与“被哪些卡使用”可以追溯，但不是传输连线，也不使原卡反过来读取生成结果。依赖调度可按整张有向图排序，这不授权任何卡跨级取内容。
- “流式管道”只表达内容按方向逐级处理，不自动意味着连线、输入改变或上游完成后立即运行模型。执行时机、当前输出与固定产物规则仍分别管理；不新增未发布未来结果的引用能力。

### 输入输出端点与三类连线

卡片按基础内容、模型生成、导演工具箱提供不同内容；连线分为生成输入、业务引用、素材关联。三类连线全部只提供直接候选，并共同接受无环检查；接收端明确选择才建立实际关系。卡片分组、输出模态与用途分别判断，不能仅凭同一模态认定用途相同。

导演工具通过模型的文本依据端点参与生成，保留字段结构、背景／设计／约束用途、作用对象、适用范围和来源。文本依据的来源区可以分为“内容材料”和“导演设计”展示；这是同一输入下的来源组织，不为运镜、光影、表演等各增加一个生成端点。

端点名称表达产品语义，不增加第五种模态，也不要求每个逻辑端点都显示为独立、常驻的圆点。关系出口可以通过选择器、拖拽或关联区表达；具体交互细节后续确定。

### 参考卡名称关联端点表

名称关联属于业务引用，只消费直接文本对象引用或参考卡对象引用出口中的稳定身份、名称与类别。来源卡为图片模态时，该出口仍只传名称，不传图片；描述正文对参考卡无用，不作为候选预览，也不通过自由文本指令建立绑定。

| 来源模态 | 端点 | 允许来源子类型 | 接收卡 | 数量与绑定规则 |
| --- | --- | --- | --- | --- |
| 文本／图片（关系出口） | 名称关联 | 文本人物／物件、场所的对象引用；四类图片参考明确提供的对象引用。 | 角色参考接受人物及可选服装、道具；场所参考接受场所；道具参考接受道具；服装参考只接受服装。 | 连接后名称进入候选，可明确选择一个或多个类别适配的名称，与本卡唯一主图建立对应。不选择则不绑定，不读取正文或名称来源图片；模型采用本卡后自动使用已确认映射。 |

没有适用文本对象时可独立命名，或直接选择已有参考提供的对象身份。添加另一角度参考须建立直接名称关系并明确采用；只复用对象身份，主图和角度属于新卡。不同独立对象同画布名称唯一，同一身份多参考可复用名称；标题不替代对象名。该端点只建立本卡名称—图片绑定；同一对象引用也可供适配的导演关系直接选择，但不自动创建现有场次实体，不推断穿着／持有关系，不增加模型端的第二次映射确认。

### 导演业务引用端点表

这些连线只提供对象候选，接收端明确选择后才建立业务关联；单独连接不绑定、不触发生成。来源模态说明卡片提供的主要内容，业务资格由对象引用的稳定身份、实际类别及接收字段规则决定。结构化文本与命名图片参考均可提供适配的对象；普通正文、通用图片或仅图中的人脸不能替代明确对象身份。模型不沿关系读取正文或图片，只消费直接工具输出中的本卡设计与必要标识。

端点沿用导演字段语义并补齐画布卡片实际需要的关系，关系只在明确选择后成立。数量是实际绑定上限或选定关系的约束，不等于创建卡片时必须填满。镜头、节拍等按需关联；生成只校验本次明确采用内容所需的对象与状态，不执行完整工作单检查。参考中的对象按类别接入同一关系，不新增“图片参与对象”端点；它不能提供自身未声明的镜头、节拍、事件等身份。

| 来源模态 | 端点 | 允许对象类别与来源 | 接收卡 | 数量与绑定规则 |
| --- | --- | --- | --- | --- |
| 文本／图片 | 参与对象 | 人物／物件文本，或命名图片参考明确声明的人物、服装、道具对象。 | 镜头设计、站位与走位、角色情境、人物表演、镜内活动、连续性设计 | 镜头设计可绑定多个；调度、情境、表演、活动主体至多 1 个，连续性可选单个。按实际对象身份计数，多人图明确选具体对象，同一对象多角度不增加人数；必要主体须明确。 |
| 文本／图片 | 说话对象 | 人物／物件文本，或命名图片参考提供且符合本字段类别的人物／物件。 | 对白 | 选择时绑定 1 个明确对象；实际生成需要说话身份时须明确，不以图中人脸或显示名称代替身份，不携带来源图片。 |
| 文本 | 覆盖节拍 | 叙事节拍 | 镜头设计 | 可绑定多个；未完成设计可暂未分配，不能据此认定镜头覆盖完整。 |
| 文本 | 所属节拍 | 叙事节拍 | 人物表演 | 可选至多 1 个节拍；无节拍也可独立使用明确表演，不表示所有覆盖该节拍的镜头都执行本条表演。 |
| 文本 | 关联事件 | 事件与刺激 | 叙事节拍、镜头设计、连续性设计 | 节拍和镜头可关联多个；连续性为可选单个。保留事件关系，不自动推导适用镜头。 |
| 文本 | 变化事件 | 事件与刺激 | 站位与走位 | 可选单个；表示站位与走位变化所依据的事件。 |
| 文本 | 接收事件 | 事件与刺激 | 人物表演 | 可关联多个；表示人物接收到的刺激或变化，不与变化事件、触发事件混成同一种用途。 |
| 文本 | 触发事件 | 事件与刺激 | 镜内活动 | 可选单个；表示启动该活动或反应的事件。 |
| 文本 | 位置锚点 | 空间锚点 | 站位与走位 | 可关联多个；绑定明确锚点，不从位置描述中猜测同名对象。 |
| 文本 | 区域锚点 | 空间锚点 | 镜内活动 | 可选单个；表示活动所在区域的空间依据。 |
| 文本 | 调度依据 | 站位与走位 | 镜头设计 | 可关联多个；保持对应人物、位置及状态记录的身份。 |
| 文本 | 所属镜头 | 镜头设计 | 镜头摄影设计的相关工具入口 | 可选至多 1 个镜头；摄影工具可不建镜头独立使用，关联只记录设计信息，不触发模型端的范围推断。 |

“镜头摄影设计的相关工具入口”指承载同一镜头摄影对象的构图、机位、运镜、光影、焦点成像等入口，共享原有关系；不据此要求独立风格卡绑定镜头。空间锚点移入表演与调度后，位置锚点和区域锚点端点继续引用原有稳定身份。

- 以上绑定须指向明确业务上下文内的有效对象；本期默认使用画布创作上下文，使用既有场次模型时继续限定在对应场次版本内。不通过名称、文件相同或文本相似推断身份，子类型匹配不能替代业务字段校验。画布内有效对象不自动转成旧场次实体，不因此要求本期改造现有导演画布。
- 空间锚点、不可改事实、角色情境等文本子类型不需要机械增加同名的通用生成入口。作为生成依据时进入文本依据端点；只有对应卡片字段声明对象引用时，才使用相应业务引用端点。
- 项目角色、道具、场所的资产图片在相应图片参考卡选择，文本不重复选择资产。名称关联和导演业务引用共用对象引用来源：前者建立本卡名称—图片对应，后者建立明确设计关系；都不自动带入图片或创建既有场次实体，不新增“资产”模态。
- 原文选取、字段适用范围、全场规则、模型参数及制作阶段仍是各自配置，不把所有字段都转换成连线端点。
- 同一业务关系只保存一个规范方向，另一侧通过只读被使用记录展示。例如镜头明确采用验收要求后，验收卡的“被哪些镜头采用”不再创建镜头 → 验收要求输入；作用对象端点不能绕过该约束建立等价反向关系。其他关系也须遵守已声明方向与统一无环，不引入隐藏双向绑定。

| 视频 | 视频素材 | 需要动作、表演、运镜等媒体参考的导演工具。 | 从直接候选中明确选择具体视频、用途及有效媒体区间。 | 不随设计文本传递；模型须直接选择受支持视频输入，不新增动作迁移、编辑或续写能力。 |
| 音频 | 音频素材 | 需要音频参考的导演工具，如对白、声音安排。 | 从直接候选中明确选择音频，记录具体产物、来源、用途及必要媒体区间。 | 供直接接收卡播放参考，不跨级传递，不生成声音、替换音轨或新增音频模型输入。 |

“对象素材、参考、来源证据、正向示例、反例”等是关联用途，不为每种说明场景新建永久端点。前态、后态、摄影结束画面等通过对应字段定位；同为图片不自动解释为生成参数。工具箱内置演示同样遵守此边界：看过示例或选过预设，不等于提交演示文件。

### 连线与执行规则表

| 规则 | 行为 |
| --- | --- |

| 候选不成为自身字段 | 候选和来源预览由直接连线派生；输入绑定保存已选来源、用途与定位，不复制上游正文。 |
| 文本与图片独立采用 | 参考卡只绑定名称与图片，不读取描述；模型采用参考后自动编译映射，完整描述须由直接文本输入独立采用。 |
| 实际采用后建立名称映射 | 模型采用参考卡后自动编译该输出中已确认的默认名称—图片绑定，不再要求选择一次映射；未选候选及描述正文不进入请求。 |
| 三种用途统一无环 | 全部候选连线共同检查有向无环，不以未采用、业务引用或素材关联为例外。 |
| 只消费直接明确输出 | 本卡处理或生成只使用直接选中的上游输出；候选预览也限于直接来源，不改变选择。下游不穿透当前卡，来源／对象身份不授权跨级读取。 |
| 逐级处理而非整体透传 | 当前卡可根据直接输入形成自己的明确输出，但不把上游候选、正文、附件或输入集合整体包装转发。 |
| 不允许结果形成回连环 | 生成结果进入新的下游卡片；原设计的来源与被使用记录只读，不成为反向输入。 |
| 明确关系用途 | 区分生成输入、业务引用、素材关联；同一业务关系只保留规范方向，反向使用只读。选择器和隐藏绑定不能绕过直接关系及无环校验。 |
| 按实际采用组织执行 | 模型结果实际使用时形成必要执行依赖；可按有向图排序调度，任务参数仍只读直接输入。连接或输入变化不自动等于立即运行。 |
| 只消费明确选择 | 按输出契约允许的单位、范围及用途编译，保留设计标注；导演默认完整采用、摄影可局部选择，图片目标状态独立于采用范围。不根据镜头、整场、分组或关联自动筛选、补齐或扩大输入。 |
| 保留字段用途 | 背景、设计、约束及制作安排分别组织；空字段不生成要求，明确没有保留否定，待确定／提议保留开放状态，生成不自动确认设计。 |
| 关联内容需要直接采用 | 表演卡的关联人物正文、锚点详情或示例媒体需要进入模型时，分别建立直接连接并明确采用。 |
| 选择持续且局部有效 | 完整输出或契约允许的局部选择跟随所选范围，不扩选模型结果项；人物表演不能拆项。新增候选不自动采用，同一来源在不同接收端独立选择，保存后刷新不自动运行、不改历史。 |
| 失效选择不静默替换 | 纯候选边可直接删除，被采用时显式取消／替换绑定；失效引用须定位，不自动改绑。合法字段清空继续保留局部选择，不生成该项要求；必要信息缺失才阻断。 |
| 冲突不静默覆盖 | 先按字段状态判断，必须同时满足的同目标单值结构冲突才阻断；提议／待确定不因取值不同就成为硬冲突。纯文本与图片内容不做语义校验；类型、数量和能力仍须校验。 |
| 不做隐式转换 | 视频不自动取帧，音频不自动转写，图片不自动转成描述；需要相应能力与明确操作。 |
| 区分当前输出与选定产物 | 生成输入可明确引用当前输出；参考卡主图和连续性等已选具体产物不随来源下一次生成静默替换。 |
| 执行依据可核对 | 运行前可核对实际文本、设计、图片、名称映射及用途；受理后固定本次依据，当前编辑不改写正在执行的请求或历史。 |

本节允许依据声明类型预先建立候选边，但不改变首版尚未调整的未来输出引用策略，也不把候选连线解释成可以使用尚未发布的结果。无环管道不承诺新的自动执行、事件触发或媒体流处理能力。

例如，人物文本 A 直接连接人物表演 B，B 明确选择其为参与对象，再直接连接视频生成 C。C 采用 B 时，只获得 B 自身表演设计与输出中必要的人物标识。若需要 A 的年龄、外貌等描述，须增加 A 到 C 的直接连接并采用；B 的示例视频同样需要从视频输出直接连接 C、按已接入能力选择用途。C 的视频结果可明确另存为独立视频内容，或按已接入能力直接进入下游主体视频参考；不能直接进入仅接收图片的四类参考卡，也不自动取帧。任何传输类别都不能回连 A 或 B 形成环。

独立角色参考 R 也可直接连接人物表演 P 的参与对象端点。P 明确选择 R 输出中的张三身份后，只输出本卡表演设计及必要人物标识；模型 M 要使用 R 的图片，仍须建立 R → M 的直接生成输入并采用。正面、侧面参考共享张三身份，不能据此算作两个人；多人／多要素参考按字段类别选择具体对象，不需要先创建人物描述卡。

本轮输入目录共 28 类端点：7 类生成输入、17 类业务引用、4 类素材关联。业务引用包括名称关联，以及补齐所属空间、作用对象后的 16 类导演关系；数量是覆盖结果，不限制后续发现真实遗漏时修正目录。端点表达逻辑用途，不要求常驻显示为圆点，不改变真实模型能力。

### 删除候选与处理已采用绑定

- 纯候选边没有真实输入绑定，可直接删除；删除仅作为候选的来源也不要求处理不存在的采用。检查按实际被选输出及接收端进行，不因有连线就视为已采用。
- 来源或连线被明确采用时，先由用户取消或替换相关绑定再删除；组合操作可在一次文档保存中完成。多个接收端分别检查，不默默清除或改绑其他接收端的选择。
- 固定主图只保证不随来源新结果替换，不豁免直接关系。希望删除已采用来源并保留图片时，可明确另存为独立图片卡并改绑，再删除原来源；不自动建立替代来源。
- 上游故障或文件不可用导致的失效继续保留可定位诊断；失效内容不参与运行，不自动退回旧结果或选其他候选。运行与历史中的文件保护沿用对应生命周期。
