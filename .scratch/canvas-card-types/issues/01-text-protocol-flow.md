# 01: 新协议下的文本生成闭环

**What to build:** 用户创建通用文本或创作依据，连接文本模型、明确采用并生成；保存、重开、预览和执行使用同一套明确输出与输入绑定。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 通用文本与原文／创作依据可手工建立、导入、保存和重开，保留正文及只读来源定位，不依赖章节，也不新增持续输入端点。
- [x] 先在这条完整链路内完成必要公共重构：卡片数据、候选边、输入绑定、明确输出和运行记录分别维护；后端使用小型输出处理 Protocol，跨端使用强类型数据契约与生成类型。
- [x] 输出处理器只获得本卡内容、已采用的直接输入及本卡已发布结果；输出是派生数据，不得把全部输入透传，也不获得任意查询画布或祖先正文的能力。
- [x] 普通连线只提供候选；提示词中的结构化引用与输入区采用共享一份绑定。插入、取消、调整顺序和用途后，保存重开能恢复相同选择。
- [x] 来源预览只展示所连出口的明确内容；输出身份与接收端代号分开，改名、重排不改绑。纯文本原样保留，不进行语义纠错。
- [x] 候选图统一检查无环；已采用来源被删除或失效时定位取消／替换，纯候选删除不要求处理不存在的绑定；这些保护随本票交付。
- [x] 保存后后端可解析该修订的输出与实际输入，编译预览和正式生成使用相同规则；预检、受理、正文增量、结果发布及重开观察保持既有行为。
- [x] 仅已发布结果可成为有效候选，不预先引用未来结果；结果明确复制／另存后形成独立文本，历史与当前编辑分开。
- [x] 公共改造保留既有媒体及运行路径的可用行为，后续模态沿同一契约扩展，不建立长期双重采用状态或两套编译依据。

规格依据：[总体规格](../spec.md)。共同约束与验证边界见[任务索引](../README.md)；本票已按下方实际证据完成，未执行的 MySQL 竞争及真实供应商质量验证不计为通过。
