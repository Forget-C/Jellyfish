# 29: 四边连接点与用途确认闭环

**What to build:** 用户从任一边连接点拖出连续可见的连线，在目标确定兼容用途后建立候选，再明确采用进入生成；用户安排的连接侧边随布局恢复。

**Blocked by:** 28

**Status:** ready-for-agent

- [ ] 每卡上右下左中点各一个几何连接点，与逻辑输出／输入用途分离，任一边可发出或接收合法连接；不固定左入右出、不按字段数撑高卡片、不为无输入卡赋予输入能力。
- [ ] 默认隐藏逻辑标签与字段列表，已连接位置可辨；卡片悬浮／聚焦／选中显示连接点。平常连接点提示主要输出，拖线目标提示接收用途；身份输出仍可按协议使用，不新增第五模态。
- [ ] 按下端点立即显示跟随指针的临时线，移动、兼容高亮、吸附、离开、等待用途菜单都有连续反馈，方向由来源到目标明确表示；松开空白、Escape 或取消不残留边／绑定。
- [ ] 按实际来源输出与目标用途组合处理零／一／多种兼容方式：拒绝并解释、直接候选、落点附近菜单确认；菜单避开边界，选择时重新核实目标、用途、能力及无环。不能按目标全部输入数机械弹菜单或猜未知能力。
- [ ] 用户选择的起止侧边固定，移动／缩放不自动换边；随现有布局同浏览器保存、刷新和重开恢复。旧边无侧别按相对位置初始化，不引入跨设备同步或业务依据变化。
- [ ] 完整输出字段不因简化外观丢失，三类关系均只提供直接候选；唯一用途、单结果、第一项或当前预览均不自动采用，不跨级读取、不自动执行。现有可访问连接入口保持可用，新增连接模式由 32 承接。
- [ ] 通过真实页面和既有 HTTP 验证三类候选关系、零／一／多种方式、能力未知、自连／环路拒绝、菜单取消／失效，以及明确采用前后实际输入；受控请求验证文本与图片独立采用、名称映射和导演采用粒度。
- [ ] 提供默认／悬浮／拖线中／菜单／已采用视觉证据及侧边移动重开检查。本票以已有有效输出完成候选到生成闭环，空输出预布线由 30 承接，重复与多用途专门管理由 31 承接。
