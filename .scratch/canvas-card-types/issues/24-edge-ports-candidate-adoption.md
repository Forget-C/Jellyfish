# 24: 边缘端点、候选连接与明确采用

**What to build:** 用户沿卡片左右边缘辨认输入和输出，通过兼容提示连接直接候选，再在接收端明确采用；可见状态与实际模型输入一致，不把连线误认为采用。

**Blocked by:** 23

**Status:** ready-for-agent

- [ ] 输入在左、输出在右，以带短标签的连接点替代顶部整排按钮；悬停、键盘聚焦或详情可读完整用途、数量限制和不兼容原因，高端点数量的卡片不重叠、不截断必要操作。
- [ ] 连接中突出兼容端点；连线锚点跟随对应端点及卡片移动、尺寸和缩放，不统一连接到错误位置。视觉调整不更改逻辑端点、类型、用途、数量限制或创建混合端点。
- [ ] 鼠标端点拖动可建立候选连接，键盘和触摸可通过可访问的候选操作完成同一行为；连接、卡片激活、拖动和媒体操作互不误触，取消连接不产生关系。
- [ ] 端点或详情分别表达候选数量与已采用／绑定数量；纯候选和已发生明确选择的关系可辨且不只依赖颜色，多结果保持部分采用状态。
- [ ] 生成输入、业务引用、素材关联按原规则使用，普通连线不建立采用；实际采用前仍完成类别、数量、模型能力及统一无环检查，所有取数限直接上游，不跨级读取。
- [ ] 明确采用、取消采用及删除候选沿用原绑定保护；文本与图片独立采用，参考卡采用后自动名称映射，人物表演整卡采用、摄影声明范围采用和生成规则保持不变。
- [ ] 真实页面分别验证三类关系及纯候选→明确选择→取消／断开，包含不兼容与环路拒绝、多结果部分采用；通过现有 HTTP 预检及受控生成请求核对仅实际采用内容进入模型，没有自动执行。
- [ ] 提供桌面／窄屏端点、候选、已采用与连接中状态的视觉证据；维持工作台卡片基本样式，并标明端点是生成画布业务必需的展示差异。
