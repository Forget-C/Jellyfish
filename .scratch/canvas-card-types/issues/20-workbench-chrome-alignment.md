# 20: 完整画布布局与顶部菜单对齐

**What to build:** 用户进入铺满页面的生成画布，通过与场次工作台一致的顶部菜单管理画布、保存编辑、发起适用的生成操作并查看运行记录；原有保存、恢复和任务行为继续可用。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 画布铺满独立页面，顶部菜单与状态浮层不挤占画布空间；背景、留边、区域层级和按钮样式对齐场次工作台，移除独立画布外框及常驻连接状态行造成的布局差异。
- [ ] 顶部左侧提供返回项目、画布名称／管理菜单、保存状态、带可访问名称的保存图标及浏览前进／后退；右侧提供适用的生成操作、运行记录、任务与更多菜单。中央无对应业务时留白，不新增场次版本或四画布切换。
- [ ] 画布管理菜单支持新建、切换、改名和删除；选择后能编辑、保存、重开及返回项目，保留未保存内容、只读、所有权、冲突、删除及未知请求结果保护。
- [ ] 菜单按钮的尺寸、间距、圆角、边框、主次动作、选中、悬停、焦点、禁用与加载状态遵循工作台；普通选择不冒充提交动作，低频管理操作不常驻堆叠。
- [ ] 运行记录从顶部入口打开，保留历史实际输入、结果另存、取消及目标记录恢复；预检继续支持明确提交与诊断定位。操作容器正文可滚动、底部动作固定，打开不移动画布，关闭不终止任务。
- [ ] 必要的布局宿主或预重构在本票先完成并立即用于真实页面；不强制抽公共外壳，不挂载整套场次业务，不重新设计保存、预检或运行协议。
- [ ] 真实页面验证管理画布→编辑保存→重开、顶部预检／记录／任务入口及失败恢复；提供与场次工作台同视口同主题的顶部和整体区域对照，桌面 1440px 与窄屏 390px 无越界、不可达菜单或丢失操作。
- [ ] 后续票据负责的导航、筛选、添加、卡片、端点和底部区域保持现有能力可用；本票不以整页视觉全部通过代替这些尚未完成的局部对齐。

规格依据：[页面布局与卡片交互](../spec.md#与场次工作台一致的页面布局)、[视觉与交互验收](../spec.md#本次布局视觉与交互验收增补)。共同边界见[任务索引](../README.md#布局对齐增补2026)。
