# 55: 统一四类编辑外壳与工具栏避让

**What to build:** 基础文本、基础图片、文本模型和图片模型打开默认或展开编辑区时，呈现同一套 C 轻量外壳，并能在常驻工具栏之间完整阅读和操作。必要局部适配随此完整行为交付，不另建纯组件或测试框架票。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Completion:** integrated (awaiting final review)

- [x] 四类共同表面、边框、约17px圆角、字号与留白符合 C 视觉契约；一行模态图标、既有可读名称、必要弱状态，正常已保存不常驻；无大号类型标题、第二行保存状态和头部分割线，不新增名称存储字段。
- [x] 右侧展开／收起、关闭顺序和键盘焦点一致，桌面命中至少32px、触摸至少36px；默认与展开共享标题结构和同一输入会话，不重复叠加正文padding。
- [x] 按最终可见尺寸和扣除顶部、左侧常驻分类栏、底部工具后的可用矩形定位；靠左至少留出常驻栏实际右边界外约8–12px，标题、正文首字、图片、字数、来源移除与提交均不被工具遮挡。
- [x] 四类分别覆盖靠左、靠右、靠底和视口转窄的默认／展开；真实点击或键盘聚焦必要控件，保留整页上下文，不能只用未越屏的坐标断言证明避让。
- [x] 仅主动打开必要最小平移，不重排节点，不因输入、保存、关闭或正常拖动新增平移；主动二级菜单／Modal及展开模式的背景暂停、焦点恢复和Escape遵守既有规则。
- [x] 在1440×960、390×844、3830×1688实际查看四类共同外壳与避让图片，记录逐区域差异；本票证明共同外壳，不提前宣称后续F01–F12完整通过。验证编辑、自动保存、展开收起和HTTP重开，保持原有会话与业务协议。

## 规格与验证约定

依据[最新规格](../spec.md)的“四类卡片的 C 视觉契约”和“四类视觉契约的逐类图片验收”，以及[任务索引](../README.md)的55–60依赖图。共同标题、外观、工具栏避让和原有业务规则均适用；实现票独立交付自身行为及图片证据，60只收口组合问题。原型是设计目标，复审正式页是差异证据，不能互换。

验证沿用真实页面＋公开HTTP，供应商和外部存储使用已确认受控替身。按改动影响运行前端typecheck、适用工作台和受影响浏览器检查；仅后端实际变化时运行相关测试／Pylint，仅对外契约实际变化时同步OpenAPI及generated client。不为本轮视觉增补机械新增接口、测试框架或复制原型示例数据。
