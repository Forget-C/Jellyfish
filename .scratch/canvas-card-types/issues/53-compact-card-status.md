# 53: 卡底紧凑状态栏

**What to build:** 用户在卡片底部单行读到低强调的运行状态、实际采用来源数及必要规格或字数，候选、旧成果和当前运行不会因压缩显示而混淆。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 基础内容与模型卡按各自适用信息紧凑单行排列：运行状态、实际采用来源数、结果规格或文本字数；普通文字小字号低强调，失败／失效／只读有可读文字及语义提示，不以多行状态表撑高卡片。
- [ ] 采用来源数从现有真实绑定／采用语义派生，新增候选连线不增加计数，明确采用／取消后同步变化；不新增按媒体拆项的计数协议，不读取跨级内容。
- [ ] 运行、失败、来源失效、只读、无结果及保留旧成果均明确表达；临时流式内容、旧成果与本次正式结果身份保持，不能把有旧图等同本次成功。
- [ ] 完整原因及诊断按需可访问；长错误／长规格不撑成多行，不靠不可读字体或隐藏关键阻断原因保持紧凑；各卡面主要输出和基本交互保持。
- [ ] 按 C06 通过真实页面与 HTTP 观察未采用候选→采用→取消的计数，以及受控模型运行／失败／旧成果状态；保存重开与数据输出不因展示修改而改变。
- [ ] 实际查看桌面、390px及不同状态的卡底局部图，核对排列、对比、间距、图标及主要输出占比；状态来自真实业务，不引入原型固定值。

规格依据：[最新实现规格](../spec.md)中的 C「焦点编辑」专节及 C01–C08 验收；既有候选／采用、卡片字段、单模型提交、保存和输出协议继续适用。共同范围与依赖见[任务索引](../README.md)。
