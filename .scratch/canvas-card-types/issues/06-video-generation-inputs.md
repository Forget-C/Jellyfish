# 06: 视频生成的用途与实际采用

**What to build:** 用户把直接文本、图片或视频候选用于受支持的视频输入用途，明确选择后完成预检、拍摄和结果查看。

**Blocked by:** [04 基础媒体导入与明确输出](04-media-content-outputs.md)

**Status:** ready-for-agent

- [ ] 文本依据、首帧、尾帧、关键帧、主体图片参考和主体视频参考按真实能力提供；普通拖线不选择用途或自动采用。
- [ ] 首尾帧单值、关键帧顺序、主体分组及各层数量限制按能力校验；当前不支持的主体参考与首尾／关键帧混用返回定位诊断。
- [ ] 实际引用与用途统一保存在输入绑定，显示代号随接收端排序变化但来源身份稳定；同一媒体涉及多个主体时不自动任选归组。
- [ ] 编译预览和正式请求使用同一份实际有序输入、参数及用途，受理后固定依据；仅候选连接不引发上游执行。
- [ ] 视频结果保留真实文件及原音轨，区分当前输出、历史、未完成成果和固定产物；可明确另存或用于受支持的下游主体视频参考。
- [ ] 不把视频自动取帧后送入图片参考，不新增音频模型输入、通用视频编辑／续写或动作迁移。
- [ ] 该路径的失效绑定、取消、恢复、运行状态及文件保护可观察且与新协议一致；不依赖先完成图片生成票据。

规格依据：[总体规格](../spec.md)。共同约束与验证边界见[任务索引](../README.md)；本票未开始实现，勾选项不代表已通过验收。
