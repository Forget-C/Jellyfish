# 30: 无输出预先布线与后续采用

**What to build:** 用户可以在模型尚未生成、图片尚未选定时先编排候选管道，待明确输出可用后再选择采用，保持布线与执行分离。

**Blocked by:** 29

**Status:** ready-for-agent

**Completion:** integrated

- [x] 根据声明输出类型、目标用途、类别资格和已知模型能力允许无实际结果时先连候选；尚未生成模型和未选图图片均覆盖，三类候选统一检查无环。
- [x] 接收端明确显示暂无可用输出，不伪造可采用产物、未来输出引用、对象身份或默认绑定；类型／类别与能力不足以确定用途时不给猜测用途。
- [x] 填充内容保存成功或模型结果发布后刷新直接候选，须由用户明确选择；唯一项、首项、当前预览或全部结果不被自动采用。
- [x] 纯候选未采用时不进入生成依据、不自动提交任务；实际采用仍按已有有效输出、当前输出／固定产物规则及直接一级传输处理，不扩充未来结果执行能力。
- [x] 保存重开仍保留候选布线及空输出状态；仅有候选可直接删除，形成实际采用后的断线／替换沿用原保护，不默默替换来源。
- [x] 真实页面完成先布线→保存重开→填充／发布→候选出现→明确采用→受控生成旅程；HTTP 核对边、绑定、输出、预检和实际请求，包含能力未知、缺失身份、环路及取消的负例。
- [x] 记录空输出提示、输出到达但未采用和采用后的桌面／窄屏证据，不以供应商替身结果宣称真实生成质量。
