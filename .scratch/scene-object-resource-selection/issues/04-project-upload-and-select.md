# 04: 直接上传创建项目对象

**What to build:** 创作者从对象卡片的创建或重新创建入口拖入图片，直接创建本项目角色、场景或道具并选用，随后通过同一资源详情完善资料与生成图片，不需要在资产库建立中间对象。

**Blocked by:** 02 — 三行对象卡片与项目资源选用。

**Status:** ready-for-agent

- [ ] 创建方式同时提供“上传图片”和已有“填写设定并生成”，选择方式本身不创建资源；新上传入口限定对象参考，不同步扩展项目资源列表入口。
- [ ] 上传使用标准 Dragger，支持拖动与选择图片、受控列表、进度、失败重试、移除及预览；无有效图片或仍有未完成／失败上传时不能错误提交。
- [ ] 上传可设置视角与主图，沿用既有默认图规则；非法文件、无效文件身份、权限与类别错误经服务端校验，不只依赖前端限制。
- [ ] 直接创建当前项目对应资源：人物为项目角色，场所与道具同类；不先创建库中对象、不建立共享关联、不扩展其他项目或类型范围。
- [ ] 角色与其他资源的详情沿用各自既有编辑及图片权限，不将演员结构化字段强加给角色，也不从提取文字暗中填充未经确认的外观事实。
- [ ] 创建成功选用新资源，故事对象名称、描述、出处不变，点击名称可进入实际资源详情管理图片和生成。
- [ ] 重新创建保留旧资源与图片，新名称冲突时要求调整；不得把上传解释为覆盖旧资源或直接替换画布固定图片。
- [ ] 创建请求重复提交或结果待核实时保持同一身份；资源已创建而选用失败时可重试选用，不重复创建资源或库中中间对象。
- [ ] 取消、上传中关闭及未保存草稿遵守已有离开保护；失败保留可恢复输入，成功返回恢复对象列表现场，提交期间阻止同卡冲突操作。
- [ ] 清空或重新选用后原资源的已受理生成仍可完成，迟到结果不能恢复旧选用；资源图片更新可供下一次动态生产读取，不改已受理任务输入。
- [ ] 公开 API＋真实任务流程覆盖三类项目上传、归属、文件与名称校验、重复请求和部分成功恢复；浏览器覆盖 Dragger、视角／主图、错误重试、详情往返、只读和窄屏。
- [ ] 完成适用接口生成、类型检查、后端检查、回归与文档同步；不依赖资产库选用票据，也不新增不必要的公共上传架构。
