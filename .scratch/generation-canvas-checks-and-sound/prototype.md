## 要解决的界面问题

检查项目、证据、生成安排与声音设计怎样组织，才能既保留画布上下文，又让每次检查范围和结果可理解？

| 方案 | 结构 | 原型观察 |
| --- | --- | --- |
| A | 设计 → 生成 → 检查关系，右侧就地详情 | 最接近现有画布，但完整项目与报告需要切换 |
| B | 左侧目标摘要，中间检查清单，右侧证据 | 适合逐项核对，牺牲一部分画布空间 |
| C | 生成前、生成与报告三分区 | 状态关系直观，横向空间占用较大，窄屏纵向排列 |

以上是原型分析，不是用户已确认的赢家。没有把布局决定写入生产实现。

## 可操作范围

- 全部 9 类生成前项目、6 类生成后项目、6 组只读技术诊断。
- 项目开关、独立检查模型、整卡／单项重查、历史报告、相关输入变化提示。
- 补充说明后重新检查原报告，原依据不可读取时禁止复核，不自动改判。
- 自动生成后检查默认关闭，提交时固定配置，完整结果集逐产物报告；取消、超时、未完整交付和断开检查关系演示。
- 对白的语言／发音与声画关系、声音安排的主次层次，以及模型支持／不支持／未接入／未知提示。
- 完整相关状态可在演示控制中展开，也输出到浏览器控制台。

## 验证结果

- 样式修订复用生成画布的卡壳、模型预览框、摄影摘要与曲线连线。桌面及窄屏重验三种方案，确认拖动更新连线、专用端口可进入检查，检查和声音表单可操作。

- `pnpm --dir front run typecheck` 通过；`git diff --check` 通过。
- Chrome 中已走通整卡检查、单项重查、复核、输入变化提示、提交后修改自动开关仍按冻结配置执行、两个产物分别生成报告。
- 方案切换保留状态并更新 URL；输入框方向键不会切换方案。
- 超时显示执行失败且保留其他项目；取消不新增完成报告并保留历史；未完整交付不触发自动检查。
- 1440 × 1000 桌面与 390 × 844 窄屏均检查；三方案无页面横向溢出。方案浮条已预留独立底部空间。
- 所验证浏览器流程无页面异常、无真实业务 API 请求。
- 未新增自动化测试套件；按原型技能只进行类型检查与直接浏览器操作验证。
