# 生成画布检查卡与声音设计实施规格

Status: ready-for-agent

日期：2026-11-07

范围：生成画布（导演工具箱卡片）。产品方案、首版检查目录及本文测试边界均已由用户确认。本文件是待实施规格，不表示功能已经实现，也不授权自动开始实现。

## Problem Statement

用户已经可以在生成画布中组织设计并提交模型生成，但缺少一个面向本次实际输入的统一检查入口：难以确认已采用要求是否传递到提交内容、要求之间是否冲突、明确时长是否匹配，以及模型能力是否能够承接声音设计。现有技术预检不能替代这些业务判断。

生成结果交付成功也不代表落实了设计。用户需要针对具体产物、依据原生成要求获得有证据和范围限制的检查结论，并能重查或补充线索复核。验收要求卡保存标准，本身不会产生审片结论。

声音设计还需要补充少量表达字段，并清楚区分创作要求、模型声明能力、当前接入能力及实际声音结果，避免把设计文字误认为已经执行的声音配置。

## Solution

新增一种通用检查卡，通过目标模型生成卡的专用接口取得生成检查依据。连接后自动列出适用项，用户用开关选择范围并手动检查；每次执行形成独立报告。检查只根据已采用设计、明确依赖和实际输入，不推测用户未表达的设计意图，不要求六岗齐全。

生成后检查提供手动入口及默认关闭的自动开关。自动配置在提交生成时固定，完整成功交付后对本次结果集逐个检查。用户根据报告自行决定后续动作；检查不控制生成许可，不改变生成成功状态，不自动采用、剪辑或重拍。现有默认技术预检和运行诊断继续内置执行。

保留对白卡、声音安排卡及人物表演卡的职责，仅增加已确认的可选声音设计字段。模型端声明原生声音输出、声音开关、音频参考输入能力，生成界面如实提示支持、未接入及未知情况。首版不扩展尚未接入的声音执行接口，也不审核实际音轨内容。

## Implementation Decisions

### 1. 职责与数据流

- 验收要求卡保存可复用的合格要求；检查卡保存目标关系、检查项选择和检查方式；检查报告记录一次执行的目标、依据、配置和结论。三者不合并为同一个状态。
- 每张检查卡只有一个模型生成目标。允许为不同目标创建检查卡，不引入跨模型设计集合或片段衔接检查。
- 模型生成卡增加生成前即可读取的专用检查输出。该接口输出观察依据，不是生成产物，也不要求先提交生成。
- 检查连线仅允许从模型生成卡的专用检查输出进入检查卡。设计卡、媒体卡不能直接作为检查卡输入，检查报告不能反向形成生成许可或输入循环。
- 模型生成卡是本次请求的汇合点，可能继续被其他卡采用；不把“整张图的最终节点”作为连接或执行前提。
- 检查执行与生成执行分开，复用现有任务运行和状态观察机制；不恢复整张画布自动执行或自动运行上游依赖。
- 无检查报告、不符合、无法判断、执行失败及报告不再适用，均不增加业务生成门槛。已有技术校验仍按现有契约决定请求是否合法。

### 2. 生成检查依据与版本

生成检查依据复用实际请求编译结果和实际采用关系，避免另建一套与生成请求不同的内容汇总。至少包括：

| 内容 | 必须保留的语义 |
| --- | --- |
| 目标身份 | 项目、画布、模型生成卡及本次目标版本 |
| 实际请求 | 实际提交文本、参数、模型选择及必要技术诊断 |
| 采用来源 | 实际采用设计、明确依赖、来源字段、要求状态和适用范围 |
| 媒体用途 | 实际采用的媒体、具体用途及稳定来源身份 |
| 能力依据 | 生成能力声明、当前接入情况及检查所需模态能力 |
| 历史目标 | 生成后检查对应的具体运行、完整结果集、具体产物和原生成依据 |

- 不根据未采用卡片、同名对象、视觉编组或同镜头邻居补全设计意图。
- 未填写和不适用不是要求；明确没有是可核对的否定要求；提议和待定不是已确定约束；背景用于理解，不能机械转换为执行项。
- 按检查项读取必要素材。引用和用途规则只读结构；内容判断必须读取对应真实媒体，不全量发送无关或未采用素材。
- 业务报告的适用版本与短期技术预检凭证分开。技术凭证到期或需刷新，不自动等同于业务结论失效；凭证仍按现有提交契约校验。
- 当前输出位置不能单独充当历史产物身份。报告必须固定真实历史产物与原生成依据，不随当前输出切换而改绑。

### 3. 检查项自动维护

- 使用稳定规则与采用来源派生适用项，连接时不调用模型。需要语义理解的判断留到用户触发执行。
- 首次连接时开启适用的生成前基础项；其他类别显示关闭或有依据的不适用。生成后列项不代表自动执行，自动开关默认关闭。
- 类别与具体子项保留稳定规则身份、来源定位和人工选择。来源变化更新相应派生项，避免重复生成同义项目，尊重人工修改和排除选择。
- 已有类别因内容变化新增的子项沿用类别开关；软件升级新增类别默认关闭。关闭项不参与本轮整卡或自动检查，也不清除历史报告。
- 来源不再属于实际采用范围时，不继续以该旧来源要求约束当前生成；原项目的历史记录仍可追溯。
- 适用性与可执行性分开。缺模型、缺媒体或无读取能力时，保留适用项并说明原因，不伪装为不适用或已通过。
- 必要信息提示必须指向实际已声明要求及缺少的判断依据。“没有机位卡”不能成为问题；“未提供结构化机位”也不能证明实际提示词未表达机位。

### 4. 首版固定目录

以下编号用于稳定追踪检查范围，不表示每个编号都需要单独调用模型。规则与模型可以共同完成一个项目，但必须保留各自证据和判断边界。

#### 默认技术预检与运行诊断

这些能力沿用现有保存、编译、提交和运行职责，不搬入可关闭业务检查，不对同义技术错误重复收费。检查卡可以只读展示诊断及定位。

| 编号 | 触发依据 | 内容与方式 | 结论边界 |
| --- | --- | --- | --- |
| T01 身份与引用 | 保存或使用来源、字段引用和依赖 | 程序校验项目／画布归属、稳定身份、连接资格、来源和输出可用性 | 存在不代表内容正确 |
| T02 素材类型与用途 | 实际采用媒体 | 程序校验文件、类型、首尾帧／关键帧／主体用途、数量与组合 | 接入合法不代表画面符合设计 |
| T03 必要主体和关系 | 已采用设计触发当前契约的明确主体要求 | 复用表演、走位、镜内活动及非明确无对白的对白等主体和关系诊断 | 不强迫未采用设计补关系，不另设可关闭的同义项 |
| T04 模型参数和指令 | 提交具体模型、参数和系统指令 | 程序核实模态、画幅、秒数范围、数量、分辨率、seed 和指令合法性 | 可接受 5 秒不代表内容适合 5 秒 |
| T05 静帧目标和结构化构图 | 图片采用多状态设计，或同目标状态存在可比较景别约束 | 复用目标有效性和已有结构化冲突诊断 | 不混淆不同阶段、提议与背景 |
| T06 运行与交付 | 生成／检查提交或产物返回 | 复用运行状态、响应和文件诊断 | 交付成功不代表创作合格，不宣称已有完整媒体扫描 |

#### 生成前业务检查

| 编号 | 触发依据 | 检查内容与方式 | 结论边界 |
| --- | --- | --- | --- |
| P01 已采用要求落实 | 至少一项有效已采用设计或验收要求 | 程序整理来源；模型对照实际文本与素材用途，核对含义、否定、条件和阶段 | 不要求逐字复制；纳入来源不等于落实含义，更不保证产物遵从 |
| P02 同范围要求一致性 | 已采用设计及补充指令中存在对象、时刻、条件可对应的要求 | 规则定位范围，模型引用冲突双方并解释同时适用关系 | 不重复 T05；范围不明只提示；不同阶段及待定方案不直接判矛盾 |
| P03 对象与参考素材语义一致性 | 描述关联实际参考，或文字对实际参考作具体说明 | 读取身份和用途映射；视觉模型观察相关媒体并比较可见内容 | 文件名不是内容；不猜身份；不同角度不自动构成错误；不可见为无法判断 |
| P04 行动与调度时序 | 有效表演、活动、节拍、事件或走位含动作、触发、延迟、出入画等 | 模型核对触发、反应、行动顺序和对象；明确结构值由规则比较 | 不补动机、事件或必填字段；自然度只作建议 |
| P05 连续性状态自洽 | 前态、变化、后态或保持约束可定位对象和范围 | 模型对照动作／事件与状态；明确结构值由规则比较 | 前后不同不等于冲突；缺变化依据提示不足；不检查跨产物接缝 |
| P06 明确时长要求匹配 | 视频秒数明确且有对应范围的预计或明确时长要求 | 区分估计、最低、固定和分段；规则比较可靠数值，模型解释文字出处及范围 | 预计 12 秒对生成 5 秒只是差异／风险；仅同范围硬要求可判矛盾；不累加并行动作或整场时长 |
| P07 动作与对白节奏风险 | 明确视频秒数及动作过程、运镜阶段或对白 | 模型评估动作、停顿、反应、运镜与台词的拥挤风险并给出理由 | 经验语速不是硬上限；不听音、不判实际发音或口型；无内容不凭空估算 |
| P08 声音要求与已声明能力匹配 | 有效对白、声音安排或明确声音策略 | 规则对照能力与接入状态，模型辅助文字需求分类并定位来源 | 仅提示匹配情况；不新增声音接口、不核验音轨；非法实际输入仍由 T02／T04 处理 |
| P09 检查依据可核对性 | 已采用设计或验收要求需要据此判断落实 | 程序整理对象和范围，模型说明何种判断缺何种已知依据 | 不检查卡片齐全度，不要求字段填满，不擅自制定标准 |

P01 判断含义传递，P02 判断同范围矛盾，P09 判断依据是否足以核对。同一问题关联多项时共用证据，不包装成多个独立缺陷。

#### 生成后业务检查

| 编号 | 触发依据 | 检查内容与方式 | 结论边界 |
| --- | --- | --- | --- |
| R01 明确内容与结果落实 | 具体产物及原依据中的必呈现内容、可见结果、不可改事实或可观察验收要求 | 读取真实文本或媒体，对照要求并提供结果片段／画面证据 | 不扩张用户意图；叙事效果只作建议；局部未见不等于全片缺失；音轨未核验 |
| R02 对象与外观落实 | 图片／视频及原依据的明确特征或视觉参考 | 视觉模型观察产物与必要参考，定位人物、服装、道具、场所差异 | 不猜不可见部分，不把未限定姿态或角度判为身份错，不比较候选间连续性 |
| R03 静态摄影与风格落实 | 图片／视频画面及构图、机位、光影、焦点、风格要求 | 视觉模型读取画面，可信元信息辅助明确媒体属性判断 | 图片只核对目标状态；抽帧只覆盖观察时刻；不虚构物理焦距、光圈 |
| R04 行动、表演与镜内活动落实 | 视频及明确动作、反应、出入画、背景任务、留白、结束状态 | 连续视频观察并提供实际区间证据 | 离散帧不证明完整过程；自然度、情绪效果只作建议；不核验声音或声画同步 |
| R05 运镜过程与落幅落实 | 视频及固定／移动机位、阶段、起幅／落幅要求 | 连续观察方向、触发、阶段和结束；真实帧可辅助单时刻判断 | 起终点不证明路径、速度；语义阶段不是时间码；不扩展跨片段衔接 |
| R06 片段内连续性落实 | 单个视频及明确状态、变化事件或保持要求 | 连续观察并关联前态、变化、后态证据 | 合理遮挡不是消失；抽帧不证明全程保持；不检查跨模型接缝或整场剪辑 |

文本产物仅执行可通过文字判断的 R01。媒体类型匹配只是前提；不能用产物描述代替观察图片或视频。

### 5. 执行方式与报告

- 检查卡独立选择并记住检查模型，不自动继承被检查的生成模型。按实际项目核实文字、图片、视频过程读取能力，不静默切换模型。
- 规则项目无需模型。模型项目缺少能力或证据时逐项表达，其他可执行项继续。
- 主按钮首次为“检查”，完成一次检查后为“重新检查”。重新检查真正执行本轮所选项目并生成新报告，不能以旧结论替代执行。
- 每项提供“检查／重新检查”入口，明确只执行当前项。整卡开关决定批量／自动选择；单项显式操作的范围必须清楚，不伪装为整卡执行。
- 每次执行固定目标、依据和配置；完成后报告不可原地改写。执行中的进度、已完成部分及最终报告应可区分。
- 执行状态与业务结论分开：待执行、执行中、完成、失败、取消描述执行；符合、明确不符合、风险建议、无法判断等描述有据可查的判断。未执行、关闭、失败不计为通过或不符合；不适用须说明原因。
- 每项记录规则与要求出处、目标版本、来源字段／请求片段／产物位置、观察事实、结论、边界和必要建议。媒体记录真实观察模态、时间点或区间，不虚构时间码。
- 多个产物和检查项分别保留结果。摘要说明实际范围，不能以一项成功代表整批通过，也不输出无范围限制的六岗齐全或整段完全合格。
- 超时、服务不可用、响应无法解析是执行失败。首版不自动重新发起完整模型检查，用户可重试失败部分，保留已完成结果。任务状态轮询不属于重查。

### 6. 自动生成后检查及成本

- 生成后检查默认不执行；自动开关默认关闭，手动检查必须选定具体产物。
- 提交生成时固定自动开关、所选项目和检查模型；后续改动只影响之后提交的自动检查。普通手动检查采用当次选定配置，复核采用原报告上下文。
- 自动检查只针对本次完整成功交付的结果集，逐个检查所有产物，不只检查当前预览，也不静默缩减数量。未完整交付的失败或取消运行不自动触发；保留结果可手动检查。
- 开启自动开关不追溯历史。后续关闭开关或修改项目不取消已经固定的本次任务；用户使用明确取消动作停止该次检查。
- 执行前显示产物数量、检查方式及预计调用情况；自动检查在发起生成前显示计划检查数量。估算与实际执行区分，有可靠价格依据才给费用估算。
- 同一媒体和观察范围可共用分析或合并模型调用，仍保留逐项证据与结论；不按六部门机械调用六次，不以省成本为由缩小选定覆盖范围。
- 静态要求可依据实际帧；过程要求须有足够连续证据。证据不足显示无法判断，不将抽样通过扩展为全程通过。
- 检查失败、不符合或无法判断不修改已成功生成的状态，不自动采用、删除、修改或重拍。

### 7. 结果适用性、历史与取消

- 生成前相关内容变化后，仅受影响结论不再代表当前输入。来源内容、采用关系、有效参数或相关能力变化须可识别；无关布局变化不使业务结论失效。
- 历史报告始终保留原目标、依据和检查配置。固定产物及原生成依据不变时，历史报告继续针对该版本成立，但不能代表当前新设计已通过。
- 当前所选范围、当前配置与旧报告不同，应清楚展示差异；关闭项目不删除旧结果，也不将旧结果统计成本轮执行。
- 断开、换目标、删除检查卡，取消尚未开始的相关检查并请求取消正在执行的检查；不取消生成。已完成报告保留原归属，不移到新目标。
- 供应商已受理的调用可能无法立即停止，按真实状态展示取消请求与终态，不能伪装远程调用已结束。
- 复用现有任务幂等与结果发布约束，重复状态观察或同一完成通知不得反复触发同一自动检查；显式重新检查则必须是新的执行。

### 8. 单次复核

- 不新增纯备注，也不提供人工直接覆盖自动结论。
- 单项结果提供“补充说明后重新检查”。说明可包含证据位置或待核实内容，属于线索，不自动成为事实或通过依据。
- 复核使用原目标、原要求、原依据、原结论及本次说明，实际重新判断，产生关联的新报告并保留原报告。涉及媒体时仍须实际观察媒体。
- 规则硬条件不能由补充文字绕过。要改变真实关系或设计，应编辑相应内容，再用普通重新检查验证新输入。
- 长期改变检查范围通过编辑检查项，长期改变合格标准通过设计或验收要求卡；不将这些改变藏在复核说明中。
- 说明仅进入本次复核，不自动带入未来检查，不自动学习或形成跨运行记忆。
- 原依据不可读取时提示无法复核，不静默换成当前内容。普通重新检查面向当前生成前输入或选定具体产物，和原报告复核分开。

### 9. 声音设计与模型能力

| 卡片 | 保留职责 | 本次变化 |
| --- | --- | --- |
| 对白卡 | 说话对象和对白正文 | 增加可选语言／发音要求、声画关系说明 |
| 声音安排卡 | 声源、环境声、动作声、音乐约束 | 增加可选声音层次／主次关系 |
| 人物表演卡 | 语气、气息、情绪、表达节奏、身体反应 | 不向对白卡重复迁移这些字段 |

- 新字段沿现有设计状态、适用条件、保存、采用和编译流程传递；未填写不新增必需要求。
- 声音出现时机优先复用适用条件，具体起止与变化在相关声音字段表达，不新增精确混音时间线。
- 设计卡表达希望发生的内容；实际生成配置由生成卡承担；模型端声明原生声音输出、声音开关、音频参考输入能力。
- 能力声明与当前适配器接入分别表达。明确不支持、已支持但未接入、声明未提供或尚未核实均应准确提示，不把未知强行转成支持或不支持。
- 首版只完善设计字段、能力声明与提示。仅已有真实执行途径可以开放配置，不新增尚未接入供应商的声音参数或音频输入执行接口。
- 设计中的不支持要求属于提示；真正非法的实际参数或素材输入由默认技术预检处理，不能通过关闭 P08 绕过。
- 不恢复声音安排卡退役的整卡 production 字段，不新增统一“同步生成／后期制作／待定”枚举，不按对白、环境声、动作声、音乐分别建立制作路由。
- 本地可试听不代表模型支持音频参考；提示词写对白不代表模型能保证准确对白；返回音轨不代表声音要求落实；后期制作意图不代表能强制输出静音。
- 首版只核对声音设计文字落实和能力匹配。实际对白逐字、发音、听感、主次效果和声画同步均标为未核验。

### 10. 实现与契约约束

- 复用现有画布文档、类型化连线、实际输入编译、生成能力声明、历史内容身份及任务执行边界。只扩展本功能需要的数据和行为，不建立通用审批引擎或独立工作流平台。
- 对外契约需要覆盖检查卡保存、检查依据读取、整卡／单项执行、进度与报告查询、取消、原报告复核，以及自动检查关联配置。具体端点和存储布局按既有约定实现，不在规格中猜定。
- 保存与执行校验项目和画布归属、连接类型、目标存在性、来源合法性及版本。不依赖前端控件防止非法请求。
- API 层负责收参、鉴权和响应；服务层负责检查依据、项目派生、状态与任务编排；跨层能力和执行契约沿用现有公共契约归属。
- 公共接口变化同步 OpenAPI 与前端生成客户端，前端不另写一套手工服务封装。提示、状态及错误码须能支持定位到目标或检查项。
- 多模态检查是需要实际验证的执行能力。现有文字调用、视频生成或人工审片功能不能证明已经支持图片／连续视频理解；未接通时如实显示不可执行或无法判断，不返回虚构通过结果。

## Testing Decisions

用户已确认以下测试边界。优先复用现有最高层行为测试，不为内部函数、存储布局或提示词措辞建立镜像测试。

### 测试边界与现有先例

| 边界 | 覆盖模块 | 采用方式与先例 |
| --- | --- | --- |
| 画布公开接口 → 真实任务执行 → 报告查询 | 画布文档、检查依据、检查执行、自动检查、历史报告、取消 | 复用现有真实 HTTP、数据库、提交器和 Worker 测试方式；只在外部模型／存储依赖边界使用可控替身，不替换本功能服务层 |
| 浏览器完整操作 | 连线、开关、按钮、单项操作、复核、结果定位、失效与取消展示 | 复用现有画布浏览器服务与操作测试，检查用户看见的状态和公开请求结果 |
| 既有声音保存与编译流程 | 设计字段、采用输入、能力声明和提示 | 在上述公开接口和浏览器边界覆盖，不新建独立声音测试框架；复用声音设计和退役字段约束的已有回归先例 |

### 必须覆盖的外部行为

| 验收组 | 验收条件 |
| --- | --- |
| A01 连线与依据 | 生成前可以读取实际编译依据；拒绝非模型专用端口或多目标输入；观察边不修改生成内容，也不要求上游重新生成 |
| A02 范围与列项 | 只包含实际采用及明确依赖；覆盖空值、不适用、明确没有、提议、背景；连接不调用模型；未采用设计和编组不造成遗漏提示 |
| A03 选择维护 | 开关、人工修改和排除保留；原类别新子项沿用选择；新增软件类别默认关闭；来源移出采用范围后不继续约束当前目标 |
| A04 技术边界 | T01–T06 中已有诊断保持原职责；关闭全部业务检查仍不能提交非法参数、引用或素材；不对技术错误重复收费 |
| A05 生成前目录 | P01–P09 各有适用样例与关键反例；至少覆盖不同阶段非冲突、预计时长非硬限制、并行动作不简单累加、文件名不代表图像、没有机位卡不等于缺机位 |
| A06 执行范围 | 首次与重查按钮语义正确；整卡执行只取所选范围；显式重查产生新执行和新报告；单项执行不把其他历史结果冒充本轮结果 |
| A07 模型与失败 | 独立检查模型选择；规则项无需模型；缺能力不静默切换；超时、不可用、解析失败与业务不符合分离；部分成功保留且无自动完整重跑 |
| A08 报告与证据 | 规则、来源、目标版本、观察内容和结论边界可查；关闭、失败、未执行不计通过；同一缺陷关联多项不重复夸大；结果摘要说明覆盖范围 |
| A09 版本适用性 | 相关输入变化影响相应当前结论，无关布局不影响；旧产物及原依据报告仍属原版本；技术预检凭证刷新不自动废弃业务结论 |
| A10 复核 | 复核读取原目标、依据、要求和结论，并加入本次说明；说明不能绕过硬条件，不污染下一轮；原依据缺失不能替换当前内容继续判定 |
| A11 自动配置 | 默认关闭；提交时冻结；之后编辑不改本次；关闭开关不是取消；开启不追溯历史；普通手动检查可使用当前所选配置 |
| A12 结果集与幂等 | 完整成功结果逐产物检查，非只预览项；未完整交付不自动运行但保留结果可手查；重复完成通知不重复执行；一项失败不抹掉其他结果 |
| A13 取消与换目标 | 独立取消、断开、换目标、删卡停止相应检查而不取消生成；原报告不改归属；供应商尚未停止时不显示虚假终态 |
| A14 生成后目录 | R01–R06 各有适用性和证据范围验证；文字只做适用 R01；静态帧不能证明动作、运镜路径或全程连续性；遮挡不直接判消失 |
| A15 成本与结果隔离 | 显示数量、方法和调用提示，无可靠价格不编造费用；合并调用仍保留逐项结果；内容不符合不改变生成成功、不自动采用或重拍 |
| A16 声音设计 | 三个新增可选字段保存、重开和采用编译后含义保留；未填不成必填；人物表演职责不重复；退役 production 字段不恢复 |
| A17 声音能力 | 覆盖明确支持／不支持、声明未知、适配器未接入；无法执行不开放控件；关闭 P08 不绕过非法实际输入；实际音轨审核保持未核验 |
| A18 非法输入与归属 | 外部请求不能跨项目访问报告或媒体；拒绝非法连接、缺失目标、无效历史产物与不匹配版本；失败不覆盖原文档或历史报告 |

### 模型与真实媒体验收

- 自动化测试用可控模型替身检查实际发送的采用内容、媒体用途、调用数量、能力分支、结果解析及证据约束，不能用替身证明模型判断正确。
- 实际模型接入另用小规模已知要求与已知产物样例验证文字理解、图片观察、视频静态观察及连续过程观察。记录所用模型、实际输入方式、可观察范围、证据和失败条件。
- 连续视频检查必须验证实际连续媒体读取途径，不能以文本请求成功或几张抽帧替代验收。未通过的能力明确列为不可用／未验证，不能宣称已完成对应实际审片能力。
- 样例质量判断允许模型不确定性；测试不要求固定自然语言措辞或保证所有艺术判断正确，但必须遵守证据边界，不把无法判断报为通过。
- 实际音轨内容不进入本轮验收，不为证明未纳入范围的功能增加听音、转写或同步检查。

## Out of Scope

- 未采用设计遗漏推断、预期设计范围、强制六岗齐全、固定设计卡必填清单。

- 纯人工备注、人工覆盖自动结论、复核意见跨运行记忆或自动学习。
- 新增供应商声音参数或音频输入执行接口、独立配音生成、混音、音轨替换、口型同步生产和精确声音时间线。
