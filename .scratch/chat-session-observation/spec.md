# 五类会话统一观察与旧路由退役

Status: ready-for-agent

Completion: resolved

Integration branch: codex-unified-chat-integration

Validated revision: 80f8aa67

## Problem Statement

画布助手、实验室多模态聊天和三种试模已经使用统一会话入口。文本试模仍在发送新请求时才开启事件订阅。用户重开正在运行的会话能看见已保存的内容，但后续文本与终态不会自动到达。站内离开还可能主动停止文本运行，影响稍后恢复。

图片和视频在提交结果未知时仍调用旧的媒体任务受理查询。实验室旧消息读取也返回名为 cursor 的值，其中使用消息序号的文本响应无法可靠接续 SSE。用户和调用方需要一条从历史恢复、接收新事件到核实原回执的统一流程。

## Solution

五类页面打开交互会话时，从一致的快照恢复历史和当前状态，再通过一条会话 SSE 持续接收事件。文本试模离开时只解除订阅，重新打开后可以观看原轮次继续输出。媒体试模通过统一会话内的只读查询核实原请求。完成调用方迁移后退役旧 HTTP 路由，统一入口继续回放已存的旧数据。

## User Stories

1. 作为打开已有会话的用户，我希望看到已保存的消息和当前待办，以便从离开的位置继续工作。
2. 作为运行文本试模的用户，我希望切换会话后原轮次继续执行，以便稍后回来查看结果。
3. 作为重开文本试模的用户，我希望无需再发送消息就能收到原轮次的增量和终态。
4. 作为需要中断文本运行的用户，我希望点击停止时才取消该轮，以便区分暂时离开和结束执行。
5. 作为收到部分正文的用户，我希望在断线和重连期间保留已显示内容，以便判断已有进度。
6. 作为翻阅历史的用户，我希望较早消息加载时仍能收到新事件，以便同时浏览历史和观察当前输出。
7. 作为快速切换会话的用户，我希望迟到的快照和事件只影响其所属会话，以便当前页面保持正确。
8. 作为画布用户，我希望重开后仍能看到原轮次的提案、审批和待答问题，以便继续处理。
9. 作为多模态聊天用户，我希望使用同一条会话流接收回复、追问和生成任务，以便跟踪它们各自的进度。
10. 作为未收到图片提交回执的用户，我希望核实原请求是否受理，以便避免重复生成。
11. 作为未收到视频提交回执的用户，我希望取回同一任务的原回执，以便接续原来的事件流。
12. 作为查询受理结果的用户，我希望查询本身只读取已受理事实，以便核实操作不会新建任务。
13. 作为网络重传的调用方，我希望仍可取回原发送或原续答的回执和游标，以便安全处理超时。
14. 作为部署维护者，我希望知道旧入口的替代路径和生效条件，以便在退役前调整现有调用。
15. 作为升级后的用户，我希望以统一入口读取既有文本、画布和媒体记录，以便继续使用过去的会话。

## Implementation Decisions

### 五类会话观察

- 保留按 kind 和 session_id 绑定的公共 send、answer、events 与 snapshot。每个打开的会话视图使用共享观察流程，先加载快照，再从快照的公共事件游标建立一条 SSE。发送和续答的后续结果经同一订阅读取。切换会话时释放前一个视图的订阅和读取，按会话隔离迟到响应。
- 共享客户端处理连接、重连、去重和已应用游标。断线后从最后成功应用的游标续读，必要时读取快照核实。采用较新的快照时以该快照的会话游标为准。历史分页位置与 SSE 进度独立。回执的游标始终指向该次命令原来的回放起点，旧回执到达时不重置正在使用的订阅位置。
- 服务层提供共享快照入口并按会话类型复用已有读取器，由它负责历史、当前状态与事件游标的一致性。统一快照与画布停止返回的快照遵循相同规则。HTTP 路由负责校验和组织响应。画布审批、多模态追问、试模输入和媒体任务状态继续由场景解释。
- 文本试模重开活动会话时，恢复已有部分回复，并把后续增量和终态归入原轮次。切换会话或离开页面只解除订阅。明确点击停止时才请求取消本轮，终态未核实时保留已知内容及状态。重开时从服务端快照和事件恢复已受理的轮次，未受理的请求不自动补发。

### 媒体只读回执

- 在统一会话入口下，图片、视频通过原请求身份查询已提交的受理记录。查询返回与原发送一致的 session_id、turn_id 和 cursor。任务状态、进度与产物继续从快照及 SSE 获取。
- 已受理请求在任务仍运行或已经结束时返回同一份回执。未知身份得到明确的未查到结果。查询只读取对应会话的受理事实，全程使用原身份，既不产生新的轮次，也不提交任务。切换会话后迟到的查询结果归原会话。
- 统一媒体发送要求幂等键。普通发送和问题卡续答沿用既有回执合同与身份核对规则，同身份原内容重传返回原回执及游标。

### 迁移顺序

1. **接入统一观察。** 使共享快照与订阅衔接可独立验收，再让五类视图采用同一观察流程。以文本试模运行中离开及重开作为主要验收，保持其他四类的历史和进度呈现。
2. **迁移媒体只读查询。** 在统一会话入口提供原回执查询，切换图片和视频的正式调用方。验证结果未知时能取回原受理，查询不会新增生成任务。这一步可与会话观察迁移并行。
3. **完成迁移后退役。** 先核对正式调用方、生成客户端和接口文档。确认统一快照、订阅和媒体查询都已接管后，按下表移除旧 HTTP 入口。同步 OpenAPI、生成客户端、开发架构和公开接口变更说明。保留公开回归来证明旧入口已退役。

下表路径以 /api/v1/studio 为共同前缀。

| 退役入口 | 替代能力 |
| --- | --- |
| 仅按会话 ID 的 `/chat/sessions/{session_id}/turns`、`/events` 和 `/turns/{turn_id}/answer` | 带 kind 和 session_id 的统一发送、事件及续答。图片和视频使用带幂等键的发送。 |
| `GET /chat/sessions/{canvas\|lab\|text\|media}/{id}` 和 `GET /generation-canvases/{id}/assistant` | 统一会话快照。 |
| `GET /experiment-sessions/{id}/messages` | 统一会话快照的历史读取与适用的分页。 |
| `GET /experiment-sessions/{id}/interaction/requests/{request_id}` | 统一会话下的媒体只读原回执查询。 |
| `POST /chat/sessions/canvas/{id}/turns/{turn_id}/stop` 和 `POST /generation-canvases/{id}/assistant/turns/{turn_id}/stop` | 返回权威快照的画布停止操作。 |

旧数据仍由统一入口读取及回放，包括旧文本运行的已知终态、画布历史续答、旧媒体受理载荷。历史清空、模型配置、画布审批及媒体任务取消继续按各自的业务契约提供。

## Testing Decisions

沿用已确认的两类验收入口。通过公开 HTTP 与 SSE 验证服务端可观察的事实，通过真实页面与统一客户端验证用户可观察的恢复和交互。使用可控模型或任务执行器安排回执、快照、事件和结果的到达顺序，复用现有统一会话契约、旧路径退役、提交恢复及浏览器回归。

| 验收场景 | 可观察结果 |
| --- | --- |
| 五类会话分别打开 | 读取与该会话匹配的公共快照。快照返回与 SSE 建连之间提交的事件能补读，之后投递新事件。发送或续答沿用已打开的订阅。 |
| 文本运行中切换、关闭及重开 | 离开动作没有发送停止请求。重开读取已存部分回复，从快照游标收到原轮次的后续文本及终态，全程没有新发送。明确停止时，看到同一轮的确认结果。 |
| 快照读取与业务提交并发 | 快照中的历史和游标对应同一可观察位置，客户端从该位置接续后得到完整结果。测试让消息序号与事件游标不同，以捕获序号混用。 |
| 订阅断线、切换会话和向上翻页 | 断线后补读未应用事件，重复事件只展示一次。旧快照、旧回执、旧会话响应和历史分页不会回退或覆盖当前订阅位置。 |
| 图片、视频回执丢失 | 通过统一入口按原请求身份核实，逐字段比对原回执及游标。分别查询运行中和已结束的任务，并核对查不到请求时也没有新增任务。 |
| 普通发送与问题卡续答重传 | 返回该操作原有回执和游标，任务或模型执行次数不增加，事件与原轮次保持关联。 |
| 旧入口退役与历史恢复 | 所列旧方法和路径不再执行原操作，公开契约移除相应声明。统一入口仍可回放既有文本终态、画布续答和媒体受理记录。 |

## Out of Scope

模型供应商与执行器重构、跨浏览器共享订阅、后台任务取消和画布审批策略变更、旧历史数据重写。

## Further Notes

本规格是已完成的五类会话轮次生命周期规格的独立后续项，具体决策承接 ADR 0017 的“会话观察与旧路由退役”。旧路由退役须从部署方能看见的公开接口变更说明提供替代操作。
