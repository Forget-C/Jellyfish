# 视觉验收与工程检查改进

Status: ready-for-agent

日期：2026-10-30

本规格承接本轮 retro 的1–4项：视觉基线与签收、lint／CI检查链、提交标题检查、浏览器采集与失败诊断。用户已确认验收接缝为公开CLI、临时Git仓库／worktree和真实页面；供应商与外部存储沿用受控替身。本次仅发布独立规格，未拆分票据、未开始实现或执行新验收。现有生成画布业务规则、01–60票据及完成记录和既有环境检查交付保持原样。

## Problem Statement

开发者需要知道一次运行究竟证明了什么。当前生成画布用例已经能完成真实页面与HTTP旅程、产出截图，但原型目标清单是可选输入；行为通过、截图产出和视觉已核对容易被同一个PASS概括。完整原型矩阵主要留在临时证据目录，新检出与CI不能仅凭仓库内的少量参考图恢复全部比较上下文。

本轮曾反复重采邻卡遮挡、筛选遮挡和原生焦点滚动后的图片；基础图片展开空白、竖图裁切与首次重开锁高也需要实际查看原图和命中几何才能识别。先前功能通过不能自动证明新视觉契约通过，单纯增加等待时间也无法区分采集准备错误与真实布局缺陷。

仓库已有lint基线检查、浏览器运行器、预检和CI。当前两条未被基线接纳的hooks依赖告警使本地lint门禁失败；前端浏览器任务依赖该检查任务，按工作流配置会被阻断。本轮没有推送，不能把这个配置判断写成远程CI已运行的结果。

提交标题规则已经明确，本地hook和CI也已存在，但本地未启用仓库hook，且两处都豁免默认Merge／Revert标题，本地还豁免整个合并状态。一次默认合并标题因此未在生成时阻断，后来需要另获明确授权、备份并改写相关后续哈希。重复写规范不能代替现有检查的实际生效。

## Solution

在现有工具和测试接缝上完成四项增补，以生成画布四类C卡片作为视觉验收试点，保持业务内容、输入采用、生成链路和旧交付记录不变。

| 范围 | 本轮结果 | 对既有能力的复用 |
| --- | --- | --- |
| 视觉基线与签收 | 目标可从干净检出定位；行为、证据和视觉审阅分别报告，缺目标或未审阅不能宣称视觉通过。 | 已确认C原型、最新明确视觉契约、四类F01–F12矩阵、现有运行器与CI证据归档。 |
| lint与CI | 修复两处依赖问题，既有基线门禁及其下游检查可以正常执行，仍阻断新增问题。 | 原始lint、基线检查／收缩、纯逻辑测试、typecheck、现有前端工作流。 |
| 提交检查 | 本地hook与CI调用同一标题规则，普通、合并和回滚提交一致检查；安装状态可见。 | 现有Git hook、提交规范与提交范围检查工作流，不引入新规则引擎。 |
| 浏览器采集与诊断 | 共享可视位置准备、无原生滚动焦点、真实命中、原尺寸采集和失败几何，保留原业务断言。 | 既有浏览器helper、隔离HTTP／Worker夹具、日志、端口与进程清理机制。 |

## User Stories

1. 作为开发者，我希望行为通过与视觉通过分别显示，以便知道已有结果实际覆盖的范围。
2. 作为开发者，我希望仅运行业务旅程时明确显示视觉未审阅，以便不把普通PASS当作设计签收。
3. 作为评审者，我希望视觉检查缺少目标清单时明确失败，以便发现遗漏的比较依据。
4. 作为评审者，我希望从干净检出定位已确认目标和版本，以便复核不依赖某台机器的临时目录。
5. 作为评审者，我希望目标记录卡类、状态、视口和缩放，以便只比较匹配的画面。
6. 作为评审者，我希望完整卡面与仅主体的边界明确，以便不把外部标题计入方式误判为密度差异。
7. 作为评审者，我希望目标确实缺少手机卡面时注明原因，以便仍按规格检查正式卡面而不伪造目标。
8. 作为评审者，我希望已确认的文字覆盖和原型局限可追溯，以便不复制原型自身的响应式缺陷。
9. 作为维护者，我希望待验正式图片不会自动成为基线，以便失败不会被自动更新目标掩盖。
10. 作为维护者，我希望基线更新记录新版本、来源和理由，以便旧验收仍可追溯。
11. 作为评审者，我希望每组同时有目标、正式整页和原尺寸局部，以便查看真实层级和遮挡。
12. 作为评审者，我希望缺文件、坏图片、重复状态或错视口被检查发现，以便证据清单可信。
13. 作为评审者，我希望逐区域记录通过、差异或未验证，以便必须项遗漏不会被汇总成视觉通过。
14. 作为维护者，我希望图像或基线变化使原签收失效，以便复用结果时有明确边界。
15. 作为开发者，我希望真实模型参数和测试素材差异有解释，以便不会为追求截图一致硬编码产品数据。
16. 作为CI使用者，我希望目标、实际图、对照索引和日志一并归档，以便失败可以在另一环境复核。
17. 作为开发者，我希望修复现有hooks依赖告警，以便lint检查重新通过且相关行为不退化。
18. 作为用户，我希望诊断定位使用当前目标片段，以便依赖修正不会产生过期定位或重复抢焦点。
19. 作为用户，我希望直接候选刷新仍拒绝旧响应覆盖新范围，以便依赖修正不会造成无限查询或状态回退。
20. 作为维护者，我希望基线仍拒绝新增问题，以便存量债务不会继续扩大。
21. 作为维护者，我希望只显式收缩已解决的基线条目，以便检查修复不被新增豁免抵消。
22. 作为CI使用者，我希望lint、纯逻辑、类型与浏览器检查保留原依赖关系，以便上游失败不会被绕过。
23. 作为开发者，我希望环境失败与产品断言失败可区分，以便禁止监听或缺浏览器不会被解释为业务缺陷。
24. 作为维护者，我希望本地验证与远程CI执行分别说明，以便本地检查不冒充远程结果。
25. 作为提交者，我希望合法标题在本地和CI一致通过，以便正常提交不会被不同规则误拒绝。
26. 作为提交者，我希望默认Merge标题也接受格式检查，以便首次错误就被发现。
27. 作为提交者，我希望默认Revert标题也接受相同规则，以便回滚类型使用现有允许格式。
28. 作为提交者，我希望合并中及解决冲突后仍检查首行，以便合并状态不是自动豁免。
29. 作为维护者，我希望空标题、非法类型和缺少摘要返回明确原因，以便及时修正提交消息。
30. 作为维护者，我希望CI检查约定范围内的所有待检提交，包括合并提交，以便本地绕过不会成为最终放行。
31. 作为维护者，我希望无效提交范围失败、空范围明确显示没有待检提交，以便错误输入不会伪装为检查成功。
32. 作为开发者，我希望能检查并显式安装仓库级hook，以便知道规则是否真正生效。
33. 作为开发者，我希望已有自定义hook配置得到保留和提示，以便安装不会静默覆盖其他工作流。
34. 作为worktree使用者，我希望从实际检出正确解析hook和共享Git目录，以便子代理提交与主区使用同一规则。
35. 作为维护者，我希望在临时仓库验证提交检查，以便不为测试改写真实项目历史。
36. 作为测试维护者，我希望复用焦点和可视位置准备，以便跨视口切换后不会直接激活已出屏卡片。
37. 作为测试维护者，我希望按实际工具栏边界准备普通采图位置，以便手机筛选换行不会盖住标题。
38. 作为评审者，我希望靠边回归保留原场景位置，以便helper不会把待测遮挡问题移走。
39. 作为测试维护者，我希望截图不触发隐式页面滚动，以便局部图与已记录的整页上下文一致。
40. 作为评审者，我希望必要控件具有真实命中或键盘访问证据，以便未越屏不被等同于可操作。
41. 作为测试维护者，我希望初始可达与用户明确滚动后的可达分别验证，以便滚动不会掩盖默认操作被裁去。
42. 作为诊断者，我希望失败立即保留面板、正文、工具栏与命中元素的几何，以便区分锁高、遮挡和采集错误。
43. 作为诊断者，我希望截图失败仍保留原始错误，以便辅助诊断不会覆盖真正的失败原因。
44. 作为测试维护者，我希望首次重开、未知元信息和异步图片加载有真实回归，以便240px锁高一类问题不会靠延长等待掩盖。
45. 作为测试维护者，我希望竖图、长文、空态、只读和展开收起仍通过原公开交互，以便helper调整不削弱业务覆盖。
46. 作为用户，我希望采图和查看证据不会采用候选或执行模型，以便验收基础设施不改变创作结果。
47. 作为维护者，我希望01–60及旧环境检查的完成记录保持原样，以便本轮增补不会重写历史通过结论。
48. 作为维护者，我希望本轮范围与验收可独立拆票，以便工程检查改进不混入新的卡片产品设计。

## Implementation Decisions

### 1. 分开行为、证据与视觉结论

- 复用现有统一浏览器公开入口和结果归档，在输出中分别表达行为断言结果、证据完整性结果和视觉审阅结果；不以单个PASS隐含三者都完成。
- 普通行为运行可以不携带原型目标，此时明确为“行为通过／视觉未审阅”，不能声明完成视觉验收。
- 视觉证据核验必须取得有效目标清单。缺清单、无效版本、缺必须文件、重复组合、错视口或不可读图片均失败，并定位具体组合及原因。成功只表示“证据可审阅”。
- 形成“视觉已通过”结论还需逐项审阅记录；必须项存在差异、未验证或缺审阅时不能通过视觉签收。自动证据检查与人工视觉判断分别负责，不以文件计数、CSS数值或通过时长替代阅图。
- CI继续执行行为检查并归档证据，显式提供视觉证据核验所需目标；视觉待审阅作为独立状态保留。任何汇总或发布报告宣称视觉通过时，必须校验相应签收结果，不能把待审阅转换为通过。不为本轮新增面向所有PR的人工审批平台。

### 2. 基线和证据可定位、可配对

| 对象 | 最少保留的信息 | 规则 |
| --- | --- | --- |
| 目标基线 | 版本、已确认来源、适用卡类／状态、视口、画布缩放、必要素材与模型能力状态、目标图片身份。 | 清单和必要原图从仓库干净检出可读取；不能依赖某台机器的绝对临时路径。现有已确认C直接复用，不重新设计产品。 |
| 目标边界和偏差 | 主体／含标题等裁图边界、目标缺项及原因、最新文字契约明确覆盖的原型局限。 | 明确无目标不等于正式版免验。手机原型隐藏卡面可作为有理由的缺项，但正式卡面仍须按契约检查。缺项不得默认补成当前正式图。 |
| 实际产物 | 运行身份、源码及夹具版本、环境、视口／状态、整页及卡面／编辑区原尺寸图、图像身份和行为结果。 | 同一组默认／展开保持相同内容、文件和采用状态；无输入、无输出及未选模型不能互相替代。运行产物本身不是设计目标。 |
| 视觉审阅 | 审阅身份及时间、目标和实际图的内容身份、逐区域结果、差异说明及允许差异的依据。 | 目标或实际图变化使原签收不再适用；相同图片和相同契约的复用须明确注明来源，不宣称重新执行。 |

- 当前试点矩阵为四类C卡片F01–F12，在1440×960、390×844、3830×1688各一组，共36组。默认、展开、空态以及目标明确缺项的检查语义沿用已确认契约。
- 保留可读取的原图与逐项索引；比较图可以辅助检查，不能代替原图。模型名、真实参数、结构化引用、图片内容或比例的合理差异必须有具体说明，不能解释掉标题、分割线、双动作、单位或遮挡遗漏。
- 基线更新是明确选择并审查的动作，保留新旧版本及理由，不在失败时自动接受新图。既有负向复审图和失败采图只作问题证据，不升级为目标。
- 必要目标清单与原图在仓库中受版本管理；大量运行截图继续使用已有CI artifact／证据归档和索引，不新建外部存储服务。完整证据索引应能定位目标及实际文件，归档失败或缺文件不得声称证据齐全。

### 3. 修复两处lint阻塞，保留原检查链

- 仅处理本次已定位的诊断片段定位与候选读取effect依赖问题，以及为通过检查所必要的局部调整。按实际读取值或稳定派生身份建立依赖，保留最新目标定位、修订匹配与旧响应拒绝。
- 不能用关闭规则、增加新的eslint豁免、扩大存量基线或移除行为断言获得通过。允许显式收缩确已解决的基线条目，记录依据；基线维护仍拒绝接纳新增问题。
- 原始lint保留存量诊断能力；完成标准是既有lint基线门禁通过，而非宣称全仓原始lint零告警。
- 复用现有前端CI的lint、纯逻辑、typecheck与浏览器依赖。保持严格失败传播，不移除依赖关系来掩盖上游失败。用工作流配置核查和实际本地命令证明接入，远程结果仅在确实执行后报告。

### 4. 提交规则单一来源，本地和CI一致

- 复用既有提交规范的允许类型、分隔空格及非空摘要规则。hook和CI调用同一可独立验证的校验实现，规则调整只有一个维护来源，不再维护两份正则或两组例外。
- 保持Git标准的消息文件输入和既有CI提交范围输入。合并、冲突解决后提交和回滚提交都检查实际首行，默认Merge／Revert前缀和合并状态不再豁免。
- 范围检查覆盖约定范围内全部待检提交，包括多父提交；无效引用／范围明确失败，合法空范围明确报告没有待检提交。失败保留提交身份、标题和不满足的要求，不能仅给笼统退出码。
- 提供仓库级显式安装和只读检查入口。只读检查发现未启用、文件缺失或不可执行时明确失败并提示修复方式；不在依赖安装、业务启动或普通预检中静默改配置。
- 安装仅作用当前仓库及其关联worktree的预期Git配置，正确解析实际Git目录与共用目录；从不同工作目录调用的结果一致。不改全局Git配置，不静默覆盖已有自定义hooksPath；冲突时保留配置并明确要求显式选择。
- 实现验收在临时Git仓库／worktree验证安装与提交行为。真实开发仓库的安装单列为显式操作，按届时授权处理；CI直接使用同一校验器，不依赖runner已经装好本地hook。
- 不重写现有历史，不改01–60记录，不修改用户Git身份或签名策略。现有工作流触发范围沿用原约定；不另建一套提交检查平台。

### 5. 小范围共享浏览器准备和诊断

| 能力 | 本轮要求 | 防止误判的边界 |
| --- | --- | --- |
| 普通采集准备 | 从真实工具栏／筛选矩形计算可读位置；通过公开焦点与键盘移动使目标及标题可见，必要时移开相交邻卡，记录最终视口及缩放。 | 不硬编码手机标题安全高度，不通过隐藏邻卡、改样式或私有状态注入制造合格画面。 |
| 靠边场景 | 明确区分采图摆位与待验位置，保留左／右／底边和窄屏原始场景，再执行产品允许的打开、最小平移或限位。 | 不能在遮挡断言前先把卡片移到安全区，以helper修好被测问题。 |
| 焦点与截图 | 复用无原生页面滚动的焦点准备，再发出真实键盘动作；稳定后按实际区域采集原尺寸图，整页与局部保持同一上下文。 | 不全局替换浏览器焦点／滚动API；不能让截图操作改变被证明的位置。 |
| 稳定与命中 | 等待明确的内容加载与布局条件，在有界等待内核对必需控件中心命中或真实键盘访问；保存初始状态。 | 未越屏、CSS可见、扩大超时或一直重试到绿，均不能替代真实可达。 |
| 滚动 | 将初始可达和用户明确滚动后的可达分别验证、记录动作；长文和长错误按原产品规则内部滚动。 | 不在初始可达检查前自动scrollIntoView掩盖被裁去的按钮。 |
| 失败诊断 | 尽力保留整页、原尺寸局部、视口／缩放、面板／正文／工具栏矩形、clientHeight／scrollHeight、滚动位置、命中元素和焦点／inert状态。 | 辅助截图或几何收集失败不能覆盖原始断言／运行错误，必须记录诊断缺失原因。 |

- 优先扩展已有浏览器helper和运行器输出，在四类视觉与共同外壳用例中复用；只收敛本轮确有相同语义的准备和诊断，不机械重写全仓浏览器测试或建立通用编排框架。
- 图片未知元信息后首次重开、异步加载、竖图完整显示、同内容展开收起、只读选择、素材采用和当前单模型提交保留已有业务断言，新增必要失败场景仍走公开页面／HTTP。
- 运行器既有端口冲突保护、日志、超时／中断清理和外部进程保护保持，沿用原公开命令回归验证。截图、采集和签收不触发模型执行、候选采用或生产数据修改。

## Testing Decisions

### 已确认的接缝

2026-10-30用户明确确认：公开CLI检查退出码与结果；临时Git仓库／worktree验证hook和合并提交；真实页面验证实际布局、截图和失败诊断；供应商与外部存储使用受控替身。视觉签收必须实际查看原图，产图本身不能判定通过。现有公开HTTP作为页面状态与业务不变性的核对入口复用，不新增内部测试入口。

测试观察外部行为和产物，不直接调用私有测量函数、不依赖内部调用次数或复制实现公式断言自身。预期来自现有提交规范、已确认视觉契约及可人工核对的可见结果。

| 验证对象 | 公开验证方式及必选案例 | 能证明与不能证明的范围 |
| --- | --- | --- |
| 视觉状态与清单 | 从CLI运行无目标的行为模式，确认视觉未审阅；运行视觉证据核验，覆盖有效清单、缺目标、缺图、重复组合、错视口／状态和损坏图片。 | 证明结果分类和证据完整性，不证明画面已经被人看过。 |
| 基线与签收 | 从干净检出读取目标；核对36组配对、声明缺项、主体／标题边界及逐区域结果；变更目标／实际图片后旧签收不再适用。 | 证明签收绑定正确证据；人工查看原图才能判断设计差异。 |
| lint与effect行为 | 运行原始lint、既有基线检查及受影响真实页面；覆盖最新诊断片段定位、候选修订刷新及旧响应拒绝。复用基线CLI案例验证新增诊断失败、显式收缩有效且收缩不能新增豁免。 | 证明门禁可用和两处局部修正不退化，不宣称整个存量代码无诊断。 |
| 本地hook与CI同规则 | 临时仓库从真实提交入口验证合法／非法普通标题、默认Merge／Revert、合并中及解决冲突后标题；以同一消息和范围调用CI使用的校验入口，比较结果。 | 证明规则与适配一致；不改写真实仓库历史，不宣称实际GitHub runner已经执行。 |
| hook安装与worktree | 临时仓库覆盖未启用、正确安装、重复安装、文件缺失／不可执行、已有自定义路径、非仓库调用及关联worktree；从不同cwd调用并核对配置。 | 证明显式配置、可见失败和作用域；不静默安装到用户实际仓库或全局。 |
| 浏览器准备 | 真实页面覆盖跨视口后卡片出屏、手机筛选换行、邻卡相交，以及普通采集与左／右／底边场景的不同准备；确认原图和上下文一致。 | 证明helper没有原生滚动或掩盖待测场景，不证明全部设备和浏览器。 |
| 命中与失败诊断 | 真实验证控件被工具栏／容器遮挡时失败；对未知元信息首次重开与受限高度保留原回归。故意失败时检查原错误、截图和关键几何；页面关闭或截图异常时原错误仍可见。 | 证明能发现遮挡、定位失败并保留根因，不以大超时或偶发一次绿替代回归。 |
| 业务和CI接入 | 复用受影响四类真实页面＋HTTP及受控Worker旅程；统一入口核对候选／采用、当前单模型、保存重开。检查现有清单登记、前端工作流依赖及artifact内容。 | 证明本地入口和配置接入；远程CI结果只在真实执行后报告。 |

### 先例、检查范围与完成标准

- 复用现有公开命令回归：串行／跨cwd、占用端口、失败保留日志、超时进程树清理、中断，以及lint拒绝新增和仅收缩基线。已有能力保持，不再重建同类运行器。
- 页面先例包括四类统一F01–F12、基础文本／图片、模型素材与运行、共同外壳及失败重开回归；工具调整优先接入这些用例，保留原断言。
- 以CLI可读输出、退出码、结果文件、实际Git行为、真实页面动作及原图为验收证据；自动检查机械部分，评审承担原型一致性与合理差异判断。
- 按实际影响完成前端typecheck、单元／命令回归、受影响浏览器用例与既有lint门禁。仅修改测试夹具时做相应语法／运行验证；应用后端、公开契约没有变化则不机械新增Pylint、OpenAPI再生或全量后端测试。
- 目标是新增规则无旁路、原检查可通过、原业务断言保留、失败可定位、证据可复现。源数据或规则未变时明确复用通过证据；相关产品／测试／环境变化时重跑适用范围，用户明确复审仍保留独立检查。
- 本文仅发布规格，未执行上述新验收，不预填通过结果。
