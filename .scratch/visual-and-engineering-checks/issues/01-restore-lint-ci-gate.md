# 01: 恢复 lint 门禁与既有 CI 检查链

**What to build:** 开发者运行既有检查时，两处已定位的hooks依赖问题得到正确修复，lint基线门禁恢复通过；诊断定位和直接候选读取保持正确，CI仍按原严格依赖继续检查。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 处理诊断片段定位与候选读取的两处effect依赖，依赖当前实际读取值或稳定派生身份；新定位目标生效，旧请求不能覆盖新范围，不引入无限查询或重复抢焦点。
- [ ] 通过真实页面／公开HTTP验证同卡不同片段的最新定位、候选修订刷新及旧响应拒绝；复用已确认受控供应商与存储，不新增业务能力。
- [ ] 既有lint基线检查通过；保留原始lint输出，不关闭规则、不增加豁免或扩大存量基线。不把原始lint仍有已知存量诊断说成失败已清零。
- [ ] 必要时只显式收缩已解决的基线条目并记录原因；复用公开CLI回归证明新增诊断非零失败，收缩操作也不能接纳新问题。
- [ ] 现有前端CI的lint、纯逻辑、typecheck和浏览器依赖保持，不能通过绕过上游门禁放行；核对工作流配置与本地实际命令，未执行远程CI时如实说明。
- [ ] 完成受影响页面和命令回归、前端typecheck及必要单元检查，保留实际命令结果和未完成项；不清理无关存量代码。

**规格覆盖：** User Stories 17、18、19、20、21、22、23、24。

## 依据与边界

依据[独立规格](../spec.md)与[本轮索引](../README.md)。本轮已确认公开CLI、临时Git仓库／worktree和真实页面验收接缝；供应商与外部存储沿用受控替身，业务HTTP复用既有入口。测试观察退出码、结果、实际Git行为、真实页面及原图，不依赖私有函数或复制实现公式。

按实际改动运行必要检查，只有应用后端或公开契约变化才增加对应同步与验证。保留既有生成画布业务、旧01–60及前期环境检查完成记录；不新建平行运行器或为少量相似代码机械抽象。
