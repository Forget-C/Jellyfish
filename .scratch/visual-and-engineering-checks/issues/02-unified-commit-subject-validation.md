# 02: 统一本地与 CI 提交标题校验

**What to build:** 提交者通过本地Git hook或既有CI入口得到同一标题校验结果；普通、合并、解决冲突后及回滚提交都执行现有规则，错误在首次提交或提交范围检查时明确阻断。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 以现有提交规范为唯一规则依据，hook和CI调用同一可验证校验实现；不继续维护两份正则、两套类型枚举或不同例外。
- [ ] 保留Git消息文件输入及既有CI提交范围入口；合法类型、分隔空格、非空摘要和合法中文内容正常通过，空标题、非法类型及缺摘要明确失败。
- [ ] 默认Merge／Revert标题不再豁免，合并中存在MERGE_HEAD或解决冲突后也不跳过首行检查；不依靠实施者手工检查标题替代确定性门禁。
- [ ] 范围内每个待检提交均被检查，包括多父提交；错误引用或范围非零失败，合法空范围明确报告没有待检提交，不冒充已经检查过提交。
- [ ] 在临时真实Git仓库验证合法／非法普通提交、合并、冲突解决后提交及回滚；同一消息／范围通过本地和CI使用的公开入口得到一致结论。
- [ ] 既有CI提交检查实际适配到同一规则，失败保留提交身份、标题与规则原因；不等待07才接入本票必要的CI适配，不另建检查平台。
- [ ] 不修改真实项目历史、Git身份或签名策略。临时夹具内的hook配置只服务本票校验；面向开发者的持久安装与自检由03交付。

**规格覆盖：** User Stories 25、26、27、28、29、30、31。

## 依据与边界

依据[独立规格](../spec.md)与[本轮索引](../README.md)。本轮已确认公开CLI、临时Git仓库／worktree和真实页面验收接缝；供应商与外部存储沿用受控替身，业务HTTP复用既有入口。测试观察退出码、结果、实际Git行为、真实页面及原图，不依赖私有函数或复制实现公式。

按实际改动运行必要检查，只有应用后端或公开契约变化才增加对应同步与验证。保留既有生成画布业务、旧01–60及前期环境检查完成记录；不新建平行运行器或为少量相似代码机械抽象。
