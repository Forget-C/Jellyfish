# 03: 提供仓库 hook 安装与自检入口

**What to build:** 开发者可以显式检查、安装并再次核实当前仓库的提交hook；从关联worktree和不同工作目录调用时行为一致，已有自定义配置得到保护。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 只读检查识别未启用、文件缺失、不可执行和配置不匹配，明确非零失败并给出修复入口；不能因仓库里存在hook文件就报告已经生效。
- [ ] 显式安装在正确的仓库作用域生效并可重复执行；正确解析实际Git目录和共用目录，主检出与关联worktree使用预期hook。
- [ ] 已有自定义hooksPath发生冲突时保留原配置并要求显式选择；不静默覆盖，不写全局配置，不改变用户Git身份或签名策略。
- [ ] 在临时真实仓库／worktree从不同cwd验证未启用、安装成功、重复安装、文件缺失／不可执行、自定义路径冲突和非仓库调用。
- [ ] 安装后通过真实Git提交确认02规则生效，包含合法提交通过和默认非法合并标题被拒绝，不能只检查配置字符串。
- [ ] 依赖安装、业务启动及普通预检不悄悄安装hook；CI直接使用02校验器，不依赖runner本地hook安装状态。
- [ ] 提供清晰的安装／只读检查操作说明；实际开发仓库安装作为单独显式操作按届时授权执行，本票验收不修改真实仓库配置或历史。

**规格覆盖：** User Stories 32、33、34、35。

## 依据与边界

依据[独立规格](../spec.md)与[本轮索引](../README.md)。本轮已确认公开CLI、临时Git仓库／worktree和真实页面验收接缝；供应商与外部存储沿用受控替身，业务HTTP复用既有入口。测试观察退出码、结果、实际Git行为、真实页面及原图，不依赖私有函数或复制实现公式。

按实际改动运行必要检查，只有应用后端或公开契约变化才增加对应同步与验证。保留既有生成画布业务、旧01–60及前期环境检查完成记录；不新建平行运行器或为少量相似代码机械抽象。
