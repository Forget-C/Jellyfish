# 官网产品文档与开发知识分层：实现规格

Status: ready-for-agent

日期：2026-11-08

依据：本次会话已确认的文档定位、拆分与删除边界，以及核对 mattpocock setup 文档后修订并确认的技能配置保留方案。本规格承接第一轮站点清理的结果。发布规格不表示整理已经实施，也不授权发布官网。

## Problem Statement

普通产品用户在官网中同时遇到操作说明、接口契约、架构设计、工程计划和历史验收记录，难以判断哪些内容与自己的使用任务有关。部分可用于产品教程的内容埋在技术文档中，直接移动整篇文件不能解决读者和内容混杂的问题。

开发者需要按规范、设计、架构、决策、实践指南和技术参考找到权威资料。现有站点计划还混有长期有效的约束、已完成进度、未排期提案和工程迁移清单，既容易重复维护，也可能在清理时误删有效知识。

项目使用的工程技能依赖项目级任务系统、分诊标签及领域文档配置。配置目前随站点文档发布；将这些入口当作重复进度管理删除，会使技能重新要求配置，或按默认位置建立另一套领域文档。

## Solution

按读者和知识职责拆分现有材料。官网承担产品介绍和产品文档职责，保留简短的开发入门；长期开发知识在仓库内独立维护；技能集成配置沿用上游约定并退出官网。

以章节和段落为拆分单位，将已有用户操作内容改写为可执行的教程，将有效技术知识归入对应开发文档。历史进度、未排期提案和重复的工程迁移清单按已确认边界删除。当前限制、已确认设计、仍受支持的历史契约及维护约束继续有明确归属。

沿用现有技能任务系统，不迁入站点历史进度，不建立新的实施日志、计划归档或项目自定义任务制度。导航、规则入口、网址和资源引用随内容归属同步更新。

## User Stories

1. 作为产品访客，我希望从官网了解产品定位、能力、截图和主要工作流，以便判断产品是否适合我的创作需求。
2. 作为自行部署产品的用户，我希望找到应用安装、配置和启动说明，以便在自己的环境中开始使用。
3. 作为产品用户，我希望教程说明操作前提、入口、步骤和可观察结果，以便完成任务而无需理解内部实现。
4. 作为创作者，我希望从已有材料整理的指南中理解章节、场次、生产单元、Take、剪辑和导出的关系，以便按当前产品流程工作。
5. 作为资产使用者，我希望知道如何生成图片、选择参考和采用候选，以便明确区分生成结果与实际采用。
6. 作为生成画布使用者，我希望知道如何准备输入、发起执行、查看结果和处理失败，以便理解当前实际支持的操作范围。
7. 作为任务发起者，我希望理解任务状态、取消和重新提交的效果，以便作出正确操作而无需阅读 Worker 实现。
8. 作为产品用户，我希望用户可见的参数、能力限制和常见问题使用产品语言说明，以便排查问题。
9. 作为升级用户，我希望历史发布说明继续保留对应版本的事实和升级信息，以便判断变化与兼容边界。
10. 作为关注产品方向的用户，我希望路线图仅表达已确认的对外方向，以便不会把内部设想误认为实施承诺。
11. 作为首次贡献者，我希望官网提供简短的开发环境启动和基本检查入口，以便快速进入开发并找到详细资料。
12. 作为开发者，我希望开发知识有独立且可发现的入口，以便无需穿过产品教程寻找工程资料。
13. 作为开发者，我希望规范说明必须遵守的约束与适用范围，以便正确实施和审查修改。
14. 作为开发者，我希望设计文档说明已确认的功能模型、交互和约束，以便理解目标行为。
15. 作为开发者，我希望架构文档描述当前真实实现，以便不会把未来设计或旧方案当作现行事实。
16. 作为维护者，我希望重要决策保留背景、取舍和后果，以便后续演进时理解选择原因。
17. 作为接入能力的开发者，我希望找到开发、调试和扩展指南，以便复用现有分层及接入方式。
18. 作为维护者，我希望迁移与数据维护指南保留前置条件、执行范围、验证和回退限制，以便安全地判断操作适用性。
19. 作为接口使用者，我希望通过稳定参考资料查询字段、协议、配置和领域契约，以便使用当前权威定义。
20. 作为历史数据维护者，我希望仍受支持的历史契约与当前主流程清楚区分，以便维护旧记录而不会恢复已退役流程。
21. 作为文档维护者，我希望同一主题按读者与职责拆分并交叉引用，以便每项规则有唯一权威来源。
22. 作为文档维护者，我希望旧记录中的有效约束先被提炼，以便清理历史进度时不丢失当前仍必要的知识。
23. 作为项目维护者，我希望已结束的开发流水账和阶段完成清单退出文档体系，以便减少重复维护。
24. 作为项目维护者，我希望未排期增强提案被删除，以便开发设计仅保留已经确认的范围。
25. 作为规范维护者，我希望具体组件迁移清单被移除而真实覆盖范围继续可见，以便既不维护第二套进度，也不宣称标准已经全面落实。
26. 作为任务技能使用者，我希望项目保留可发现的任务系统配置，以便技能继续使用已经选择的本地任务方式。
27. 作为分诊技能使用者，我希望现有标签映射继续可用，以便技能无需重新猜测项目词汇。
28. 作为领域建模技能使用者，我希望术语表和决策记录的位置明确，以便领域文档始终写到同一个位置。
29. 作为代码审查者，我希望审查来源索引指向迁移后的规则和需求入口，以便审查仍使用完整的项目依据。
30. 作为项目维护者，我希望既有技能工作流和任务记录保持稳定，以便文档整理不演变为任务系统改造。
31. 作为文档读者，我希望站点导航、网址、仓库链接和锚点对应实际内容，以便能够到达所需资料。
32. 作为资料维护者，我希望共享图片和有效附件继续可用，以便文档拆分不会破坏仍在使用的证据或展示资源。
33. 作为交付验收者，我希望看到内容归属、引用、资源和页面构建的验证结果，以便判断整理是否完成。
34. 作为项目负责人，我希望本轮只拆分并必要重写已有内容，以便整理工作不会扩展成全产品手册或业务功能开发。

## Implementation Decisions

### 1. 以内容为单位盘点与拆分

逐篇识别产品说明、用户操作、规范、已确认设计、当前架构、决策依据、实践步骤、参考定义及历史过程。混合文档按章节或段落拆分；相同语义的当前知识合并到一个权威来源，通过链接连接不同读者的解释。

对每篇受影响文档核对保留、拆分、合并或删除的去向，以及独有信息、链接和附件依赖。工作清单用于实施核对，不成为新的长期进度台账。原来的整篇保留与迁移数量方案已失效，文档数量不是完成指标。

### 2. 官网以普通产品用户为主要读者

保留产品介绍、截图、工作流、应用安装部署、使用指南、用户参考、常见问题和发布说明。自行部署者属于产品用户；常规配置和升级说明可以留在官网，代码级调试、特定历史数据修复和开发迁移演练进入开发指南。

从现有材料提炼用户教程，围绕用户目标说明入口、操作、结果和限制。将内部字段、模块路径、事务及执行器机制移交开发文档。生成画布与场次工作台沿用现有领域术语并保持对象边界，生成成功、素材审查和人工采用分别表达。

开发入口仅提供环境准备、启动、基本检查和进一步阅读的简要路径；详细开发步骤和规范由仓库文档维护。产品路线图只保留已确认的对外方向。

### 3. 开发知识按六个维度维护

| 维度 | 内容边界 |
| --- | --- |
| 规范 | 开发、协作与审查应遵守的规则、适用范围和必要例外 |
| 设计 | 已确认的功能模型、交互组织及目标约束；明确与当前实现的关系 |
| 架构 | 当前真实生效的模块、数据、状态及协作边界 |
| 决策记录 | 重要选择的背景、备选、取舍与后果；保留原编号及历史语义 |
| 开发与维护指南 | 环境、接入、调试、维护、迁移等可复用操作说明 |
| 技术参考 | 接口、配置、字段、协议和专业输出契约等查询资料 |

按实际内容建立必要文档，不为凑齐分类创建空页。已确认设计可以尚未实施，但必须明确状态，不能写进当前架构；被替代的设计与仍受支持的历史契约分别判断。调研保留仍支撑有效设计或决策的事实、来源和适用版本，未确认建议按提案删除边界处理。

### 4. 删除历史过程与未确认提案

删除站点中的历史进度、开发流水账、阶段完成清单、过时的执行与验收过程；不为它们建立归档，不转入既有任务系统。

删除未排期增强提案，仅保留已确认设计。实验室后续事项中的完整历史回填、提交幂等、游标分页和用户归属等未排期设想，不转成开发设计的待决事项。现有能力限制仍按当前事实维护，不能因为删除提案而宣称能力已补齐。

删除按具体组件登记的工程迁移清单，只在规范中保留真实覆盖范围及必要例外。例外描述说明标准实际适用于哪里，不重新形成待办队列。

### 5. 保留有效约束，避免以进度名义误删知识

已实施计划中的长期设计只提炼仍适用部分，不能整篇照抄为当前架构。检查目录属于已接受的业务设计，应保留其范围、证据要求和能力边界，剥离实现进度。

历史记录中的数据保护、备份、停止旧写入、演练后显式应用、降级限制、历史记录身份和回退约束，仍有效时进入相应开发文档。系统种子待办中的用户模板保护等有效约束与未确认重构设想分开处理。

模型输入被传递不等于供应商逐项实现，生成结果仍需人工验收；不同数据库和验证环境的证据适用范围应保持准确。历史日期、通过数量和临时产物位置不作为保留整个过程记录的理由。

### 6. 保留上游技能需要的项目配置

保留任务系统、分诊标签和领域文档三份配置，沿用 setup 提供的项目配置机制。项目指令入口只保留必要的简短导航；本地任务选择、默认标签映射和领域文档布局继续可发现，既有 Wayfinding 所需操作约定继续有效。

领域文档继续采用单上下文术语表，决策目录指向新的开发文档位置。项目定制的 Grilling 讨论与实施边界、UI/UX 技能使用边界继续保留。

本轮不重跑 setup、不修改第三方技能的通用工作流、不新增任务执行状态、结项或清理制度。仅修复本次迁移影响的项目配置和本地定制技能引用；代码审查来源索引继续承担技术规则导航职责。

### 7. 规范与入口保持单一权威来源

技术规则按新分类归位，项目指令文件保留必要约束与条件明确的阅读入口。同步修订原先与新归属冲突的维护来源声明，避免一处要求独立规范、另一处又要求所有规则只维护在入口文件。

贡献、开发和审查说明指向同一份权威规则。普通用户的操作解释与开发者的技术契约可以面向不同读者展开，但不得各自维护矛盾的行为定义。

### 8. 导航与网址随内容归属调整

产品文档、简短开发入口、仓库开发文档和技能配置分别具有清楚的入口。原计划栏目及已迁出内容退出官网导航，文档标题、链接文案和实际目标含义保持一致。

网址体现最终目录与内容，不保留旧路径兼容页或重定向。仓库内文档采用可解析的文件引用；官网引用仓库资料时使用对应仓库页面，并确保正式发布时目标内容已进入相关分支。

同步受影响的现行文档、项目入口、技能索引、维护说明及测试文档中的引用。既有任务记录保持历史内容，本次不为整理旧链接而改写它们；检查结果需区分现行入口和历史记录。

### 9. 发布记录与附件按用途处理

历史发布说明保留原版本口径，仅修复确受迁移影响的引用。产品截图、标识和其他仍被使用的资源继续保留。

附件随实际内容归属处理。删除前检查保留文档、模板、样式、数据及附件之间的直接和传递引用；只有确认专属于被删除内容、无其他保留用途的资源才可删除。存在未解引用或共享关系时保留，不以简单文本搜索无命中推定可删。

### 10. 核对当前事实并控制变更范围

将保留或改写的当前行为与相关代码、配置及必要的本地界面证据对照。发现实现与旧文档不符时先定位，再按真实当前行为修订；涉及尚未确认的产品取舍时记录问题，不借文档整理改动业务。

新索引和简短过渡说明服务于阅读与维护；不创建重复知识库。站点模板或配置仅在导航和内容呈现所需范围内调整。

## Testing Decisions

验收沿用用户已确认的文档阅读链路：从官网或仓库入口找到正确内容，阅读的行为与现状一致，引用和资源可达，发布产物能够正确呈现。本次不引入新的业务测试边界。

| 验证范围 | 可观察的完成条件 |
| --- | --- |
| 内容去向与独有信息 | 每篇受影响文档的处理可追溯；有效知识有权威归属；被删除部分符合历史过程、未排期提案或工程清单边界 |
| 用户阅读路径 | 产品入口能到达现有内容整理的使用指南；操作前提、步骤、结果和限制清楚；详细工程资料退出用户导航 |
| 开发知识分类 | 六类内容边界清楚；已确认设计、当前架构、历史契约和决策语义准确；无重复维护的现行规则 |
| 技能配置可发现性 | 三个简短入口能到达迁移后的项目配置；本地任务选择、标签映射、单上下文术语表和 ADR 位置明确；审查索引无失效入口 |
| 引用与资源 | 现行正文、导航、模板及仓库入口中的文件、路由、锚点和资源引用可解析；共享及传递引用的资源保留；旧路径不靠兼容页掩盖 |
| 站点发布产物 | 使用现有 Hugo 构建链路，在隔离输出目录完成构建；检查生成页面中的链接和资源；通过本地预览核对主要入口与重写页面 |
| 删除边界 | 既有任务记录未改动；历史发布语义保留；无业务实现、数据库迁移、测试资源或用户数据的顺带清理 |
| 交付说明 | 汇报实际拆分、迁移和删除范围、通过的检查、已知限制及未完成项；本地成功不表述为远程发布成功 |

优先复用现有站点构建命令、发布工作流中的构建方式，以及第一轮清理已使用的源引用与渲染产物链接检查方法。已有临时检查工具可以作为参考，应核实其路径和假设适用于新目录；本规格不要求建立新的校验框架。

静态检查验证文件、路由、锚点和资源是否可达；语义审查验证目标内容是否真正支持链接文字和原有约束，两者不能互相替代。保留与删除使用同一组规则核对，重点检查混合文档、共享附件和技能配置入口。

对既有任务记录只做只读核对，区分记录时的历史路径和现行入口；发现相关限制如实报告，不借验收自动扩大任务记录修改范围。纯文档、导航和静态资源变化使用直接检查，不要求无关的业务测试；如实际修改可执行逻辑，按其影响补做适用检查。

## Out of Scope

- 编写覆盖所有产品功能的全新用户手册，或为现有材料之外的主题批量补文档。
- 新增业务能力、修复无关业务问题、改变接口或数据库契约。
- 实施被删除的增强提案或工程迁移待办。
- 将站点历史进度迁入任务系统，建立新的计划归档、开发日志或任务台账。
- 修改既有任务记录、增加项目自定义任务生命周期字段或改变技能的任务协议。
- 重跑 setup、升级整套第三方技能、重写其通用工作流。
- 改写历史发布事实、恢复已退役流程，或提供旧网址兼容层。
- 删除业务代码、测试夹具、数据库迁移、用户数据和归属不明的附件。
- 未经后续实施授权修改站点或开发文档；发布本规格不包含任务拆分、业务实施或官网部署。
