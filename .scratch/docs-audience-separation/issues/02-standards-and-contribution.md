# 02: 整理开发规范与贡献文档

**What to build:** 让贡献者和审查者从统一入口找到通用编码规范、工作台设计标准、提交约定和协作说明；让官网只保留简短贡献入口。明确规范的真实覆盖范围，并将当前前端布局与应遵守的设计标准分开维护。

**Blocked by:** 01 — 建立开发文档与技能配置入口

**Status:** ready-for-agent

需求依据：[实现规格](../spec.md)，重点覆盖用户故事 11、13、21、25、29；所有删除与验证边界沿用母规格。

- [ ] 通用编码、接口同步、验证与提交规范归入开发规范，贡献操作归入开发指南；保持已有规则的实际约束，不借迁移增加新的工程制度。
- [ ] 工作台动作、文本、主题、组件复用和验收标准迁出官网，适用范围与必要例外明确；当前前端布局事实进入架构资料。
- [ ] 删除按具体组件登记的设计标准迁移清单，只保留当前标准的真实覆盖范围；不将未完成项改写为全面达标，也不在新文档中重新建立待办队列。
- [ ] 项目指令文件保留必要约束与条件明确的规范入口，修订与独立规范归属冲突的维护来源声明；每项规则有单一权威来源。
- [ ] 官网保留简短贡献说明并能到达完整协作规范；开发者能通过开发文档入口找到当前规范、布局和贡献指南。
- [ ] 审查来源索引、贡献说明及其他受影响的现行引用同步更新，原站点详细规范退出发布内容；场次领域规则由后续主题票据继续按对应范围处理。
- [ ] 对照已有代码、配置和适用验证入口核对标准及例外，保留可复用的验证规则，删除历史通过数量和过程记录。
- [ ] 完成本票内容去向核对、现行链接与资源检查、站点构建及相关入口预览；既有任务记录与业务实现保持不变。
