# 09: 完成官网导航与全站联合验收

**What to build:** 将已经整理的各主题组织成一致的官网产品阅读路径和仓库开发入口，完成产品页、文档首页、简短开发入口及全站引用资源的最终收敛。交付能够构建、预览和审查的完整文档结构及验证结果。

**Blocked by:** 02 — 整理开发规范与贡献文档；03 — 分离产品安装与开发入门；04 — 拆分任务运行、模型配置与数据库维护文档；05 — 拆分资产与生成实验室文档；07 — 整理场次设计、拍摄、剪辑与交付文档；08 — 整理生成画布与检查功能文档

**Status:** ready-for-agent

需求依据：[实现规格](../spec.md)，重点覆盖用户故事 1、9–12、21–25、30–34，并联合验证全部用户故事。

- [ ] 官网产品介绍、工作流、截图、用户指南、安装部署和简短开发入口形成清楚的阅读路径；普通用户不再经由站点栏目进入详细工程知识或历史计划。
- [ ] 产品路线图只保留已确认的对外方向，原任务计划栏目及退出官网的技术栏目完成收敛；标题、链接文字、网址和实际内容含义一致。
- [ ] 仓库开发文档六类归属及技能配置入口均可发现，规则与当前事实无重复权威来源；现行项目介绍、维护说明、审查与测试文档中的相关入口完整。
- [ ] 对照实施前盘点核对所有原正文、首页或目录索引及必要的站点维护资料，确认保留、拆分、合并和删除去向完整；不以文档数量代替独有信息检查。
- [ ] 历史进度、未排期提案和工程迁移清单未被搬成新计划、归档、待决清单或任务记录；有效约束和真实适用例外没有随它们丢失。
- [ ] 六份历史发布说明保持原版本语义，仅修复确受迁移影响的引用；产品截图、标识、多语言项目介绍及其他共享资料没有被顺带清理。
- [ ] 全面核对保留文档、模板、样式、数据和附件的直接与传递引用。仅删除已经确认无保留用途的专属资源；共享或归属不明资源继续保留。
- [ ] 验证现行文件、路由、锚点和渲染资源可达，并检查链接文字与目标内容的语义；旧网址不靠兼容页或重定向维持，历史任务引用与现行入口分开报告。
- [ ] 使用现有 Hugo 链路在隔离输出目录完成构建，并从本地预览检查主要入口及重写页面；引用仓库新文档时核对目标存在及正式发布的分支前提，不声称本地文件已公开发布。
- [ ] 核对本次变更范围：既有任务记录保持不变，无业务实现、数据库迁移、测试资源或用户数据的顺带修改；未重跑 setup 或改造第三方技能工作流。
- [ ] 汇报最终拆分、迁移与删除范围、有效信息保留情况、已通过的检查、既有问题及未完成项；相同状态下已经通过的结果复用，相关变化或新疑点出现时才重跑检查。
- [ ] 票据完成以本地文档交付和联合验收为准，官网部署仍需后续相应授权。
