# 01: 建立开发文档与技能配置入口

**What to build:** 让开发者和工程技能通过清楚的项目入口找到开发文档、任务系统配置、标签映射、领域文档及审查依据。将三份技能配置、现有 ADR 和审查来源索引迁出官网，建立后续主题整理共用的开发文档入口，保持既有技能工作流可用。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

需求依据：[实现规格](../spec.md)，重点覆盖用户故事 12、16、26–30；所有删除与验证边界沿用母规格。

- [ ] 任务系统、分诊标签和领域文档配置进入已确认的技能配置区域；本地任务选择、默认标签映射和 Wayfinding 所需操作约定继续可发现。
- [ ] 项目指令文件保留三个简短配置入口，保留现有 Grilling 和 UI/UX 使用边界；本票不增加项目自定义进度、执行状态、结项或清理制度。
- [ ] 现有四份 ADR 迁入已确认的开发文档决策区域，编号、决策背景和历史语义保持准确；术语表维持单上下文，新位置通过领域文档配置明确提供。
- [ ] 审查来源索引迁入开发文档，相关本地定制技能引用同步修复；索引继续指向当前实际存在的规范和需求配置，不提前引用尚未迁入的目标。
- [ ] 开发文档入口能够到达本票交付的真实内容；后续主题沿用母规格的六类归属，不为分类数量创建空白正文。
- [ ] 三份配置、ADR 和审查索引的旧站点正文退出发布内容；本票影响的现行入链、交叉引用、锚点及导航同步更新，不建立旧网址兼容页。
- [ ] 未运行 setup、未升级整套技能、未改写第三方通用工作流；既有任务记录保持不变。
- [ ] 从项目指令和审查技能入口逐一验证配置及技术来源可达；检查迁移内容完整性、相关资源和站点构建，报告历史任务引用与现行入口的区别。
