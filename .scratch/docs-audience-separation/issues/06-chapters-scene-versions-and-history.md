# 06: 整理章节、场次版本与历史维护文档

**What to build:** 让产品用户理解章节划分、场次版本、保存和历史恢复，让开发者与维护者找到对应的已确认设计、当前架构和旧历史接入约束。先整理这些基础边界，为后续场次设计到交付的文档提供稳定依据。

**Blocked by:** 01 — 建立开发文档与技能配置入口

**Status:** ready-for-agent

需求依据：[实现规格](../spec.md)，重点覆盖用户故事 3、4、14、15、18、20–23、31；所有删除与验证边界沿用母规格。

- [x] 用户指南明确章节原文、场次划分、场次版本与历史方案的操作关系，说明编辑、保存、查看和恢复的当前入口与结果。
- [x] 当前可编辑版本、并发修订、历史身份和固定记录的适用边界核对准确，不将旧确认或派生流程套用到普通保存。
- [x] 从章节历史编辑与场次画布计划、相关核心架构中提炼本主题仍有效的已确认设计和现行事实；删除对应阶段进度、历史完成与验收流水账。
- [x] 章节历史接入和身份参考整理等维护操作迁入开发指南，保留备份、停止旧写入、演练后显式应用、作用范围及回退限制。
- [x] 仍受支持的历史记录与已退役流程清楚区分，已有生产成果和历史身份保护约束继续可查。
- [x] 与场次设计、生产及交付共用的混合正文按主题分段处理；尚未归位的有效片段继续可达并由 07 接续，不能因本票完成就提前整篇删除。
- [x] 更新本主题影响的项目规则、开发索引、用户指南和现行链接，页面网址反映当前内容；不会为了保留旧网址生成空兼容页。
- [x] 核对当前实现与文档语义，验证章节至版本和历史维护两条阅读路径、受影响锚点资源及站点构建；既有任务记录与实际业务数据保持不变。
