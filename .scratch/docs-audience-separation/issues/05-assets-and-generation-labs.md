# 05: 拆分资产与生成实验室文档

**What to build:** 让产品用户按现有能力理解资产图片生成、参考选择、候选采用及文本、图片、视频实验室的使用；让开发者在独立资料中理解相应架构、契约和维护操作。删除未排期实验室提案，同时保留当前能力限制。

**Blocked by:** 01 — 建立开发文档与技能配置入口

**Status:** ready-for-agent

需求依据：[实现规格](../spec.md)，重点覆盖用户故事 3、5、8、15、17–19、22、24、32、34；所有删除与验证边界沿用母规格。

- [x] 从现有资产图片材料整理用户操作，说明生成、参考、预览、AI 建议和候选采用的入口、步骤及结果，不混入保存结构或组件实现。
- [x] 三类生成实验室的已有输入、执行、结果和历史使用内容按实际能力整理，必要重写限于现有材料所覆盖的主题。
- [x] 资产图片、生成准备及实验室的当前架构、输入输出契约与业务职责迁入开发资料，面向用户和开发者的解释保持一致。
- [x] 资产结构化切换等维护内容进入开发指南，保留适用环境、数据损失边界、系统与用户内容保护，以及回退限制。
- [x] 删除实验室后续事项中的完整历史回填、提交幂等、游标分页和用户归属等未排期设想；已实现事实及仍存在的能力限制归入对应现行文档。
- [x] 保留输入传递不等于供应商完整实现、结果须人工验收等有效边界；删除历史小样日期、调用次数和过程表现记录。
- [x] 产品截图、示例图片及共享资源继续可用；附件删除须核实直接和传递引用，不能仅因原文迁出官网而删除。
- [x] 修复本主题的现行引用、导航和资源关系，核对用户任务与技术查阅路径，完成局部预览和站点构建；不调用真实供应商来验证文案。
