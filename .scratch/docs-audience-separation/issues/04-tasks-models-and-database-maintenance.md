# 04: 拆分任务运行、模型配置与数据库维护文档

**What to build:** 让产品用户理解任务查看、取消、重新提交及结果含义，让维护者在开发文档中查询任务执行、模型解析和数据库维护机制。拆分混合内容，保留有效的数据保护与回退约束，清除系统种子待办中的未确认设想和过程记录。

**Blocked by:** 01 — 建立开发文档与技能配置入口

**Status:** ready-for-agent

需求依据：[实现规格](../spec.md)，重点覆盖用户故事 7、8、15、18、19、22、24；所有删除与验证边界沿用母规格。

- [x] 用户任务指南围绕界面入口、状态含义、取消效果、重新提交和结果查看组织，内部接口及 Worker 排查说明迁入开发资料。
- [x] 任务状态、固定执行输入、后台执行与恢复、供应商状态查询及结果交付等现行机制进入架构资料，并与实际实现核对。
- [x] 用户可见的模型配置及限制用产品语言表达；默认模型解析和技术配置规则进入开发文档，保持对已受理任务与新任务的区别准确。
- [x] 数据库迁移、系统种子、启动依赖和可复用维护步骤按架构与指南分开维护；备份、模板保护、实际执行范围和回退限制保留。
- [x] 系统种子待办中的未确认重构设想、环境执行进度及历史验证流水账删除；必要的部署前检查作为操作前提维护，不声称真实目标环境已经完成升级。
- [x] 任务取消、恢复和重新提交的说明与当前行为一致；不同数据库或验证环境的证据适用范围不被扩大。
- [x] 修复本主题影响的现行链接、锚点、导航和审查引用；开发启动步骤与共用入门说明保持一致，其他主题迁移前后的目标均能准确解析。
- [x] 验证用户任务阅读路径和维护者查阅路径、内容去向、资源引用及站点构建；不实际迁移数据库、改变供应商配置或执行生成任务。
