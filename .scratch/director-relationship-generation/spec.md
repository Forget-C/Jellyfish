# 导演画布权威关联与视频生成意图规格

本规格记录已确认的关联关系、展示、保存及生成边界。场次指 Sequence；场所指 Scene 资产；文中的单镜、多镜均指一份场次版本内的镜头。配套实施票据按用户可验收的行为拆分，状态为 ready-for-agent。

## Problem Statement

用户在导演画布看到的连线和“未关联设计”目前主要由前端按已有字段引用及固定对象类型组装。固定类型的整场卡片还会被统一标成“全场适用”，混淆六岗工作单中的场次背景、规则和执行内容。画布归位不能稳定说明数据是否真实关联、是否全场适用，更不能说明一个生产单元这次实际要拍什么。AI 提取后即使存在合法的未使用设计，用户也难以区分它与已有引用但尚未归镜头的设计。

当前单元指令输入会保留整场的镜内活动、连续性等背景；单元已选节拍和事件也未完整约束送给指令 AI 的设计范围。检查按六岗覆盖项返回结论，没有逐条证明全场规则和已选动作进入最终指令。视频模型实际接收的是指令正文、单元明确绑定的参考与参数，而不是画布连线。由此，关系图可能看似正确，生成意图却无法追溯到真实请求。

保存期间，前端可继续发生编辑。若把保存响应的内容重新写回当前暂存，或把旧暂存与新的服务器 revision 配对，可能丢失编辑或覆盖外部更新。用户需要明确的保存状态、失败后保留输入、关闭页面后的恢复和并发冲突保护。

## Solution

场次版本保存真实的设计引用和明确适用性，六岗工作单的正式归属不因关联范围改变。后端从同一保存修订构造权威关系图，给出对象、直接引用、可解释的间接路径、适用范围、内容用途及未关联原因；前端负责布局、筛选与交互，不自行决定业务归位。场次背景作为非执行性上下文单独说明，不因缺少逐镜引用而成为未关联设计或全场规则；混合工作单按字段或条目区分用途，仍只有一张可编辑原卡。全场规则仅指全场实际生效的约束或不变事实；镜头关联决定设计可用于哪些镜头，单元出现项的明确选择才决定本次执行内容。

初次加载或明确恢复时初始化前端可编辑暂存。其后保存冻结本次提交快照，服务器响应只核实请求身份、修订和该快照，并更新已确认基线及关系图，不覆盖仍在编辑的暂存。自动保存、手动保存、冲突处理和本地恢复遵循同一 revision 规则。

后端将单元出现项已选动作、适用的全场及局部约束、实际消费的解释背景和真实绑定参考分开组成固定指令依据，并记录背景纳入原因。每条适用于视频阶段的约束及每项已选可拍内容都须有可追踪的最终去向；遗漏或未解决的冲突阻止生成，逐项去向门禁补充而不替代六岗检查。历史指令、检查、视频任务与 Take 保留当时真实输入。系统表达和校验拍摄意图，不宣称视频模型必然实现它；实际覆盖仍由素材审查判断。

## User Stories

1. As a 导演, I want 画布连线对应可追溯的保存数据, so that 我能判断关联是否真实存在。
2. As a 导演, I want 查看关联的拥有对象、字段和直接或间接路径, so that 我能找到应修改的真实引用。
3. As a 导演, I want 同一设计对象在全场只有一个可编辑身份, so that 跨镜共享不会产生多份互相矛盾的副本。
4. As a 导演, I want 全场规则与跨镜共享对象分开显示, so that 我不会把“多镜使用”误认为“所有镜头必须遵守”。
5. As a 导演, I want 只有全场生效的约束或不变事实被标为全场规则, so that 规则的含义不随当前镜头数量改变。
6. As a 导演, I want 将规则明确限定到一个或多个镜头, so that 有局部例外的内容不会伪装成全场规则。
7. As a 导演, I want 在同镜不同拍摄内容需要不同规则时精确到单元出现项, so that 局部拍摄意图不会互相覆盖。
8. As a 导演, I want 条件式全场规则只在条件成立时约束画面, so that “角色出现时服装一致”不会强制每次都让角色出镜。
9. As a 导演, I want 有引用但无法确定镜头的独立设计项显示为待归镜头, so that 它不会被误说成完全未关联。
10. As a 导演, I want 没有真实引用也没有明确适用性的独立设计项显示为未关联, so that 我可以自主决定后续是否使用。
11. As a 导演, I want 查看未关联设计的完整原对象并手动建立关系, so that AI 提取出的备用想法不会被迫进入生成。
12. As a 导演, I want AI 提取时明确给出可验证的引用和适用范围, so that 应用后的版本有稳定的数据关系。
13. As a 导演, I want AI 的非法引用或冲突适用性在应用前被拒绝, so that 错误关系不会写进版本。
14. As a 导演, I want 编辑字段时保留我尚未保存的内容, so that 自动保存和关系图刷新不会打断输入。
15. As a 导演, I want 看到未保存、保存中、保存成功和保存失败, so that 我知道当前修改是否已经入库。
16. As a 导演, I want 保存失败后继续修改并手动或自动重试, so that 网络或校验错误不会清空工作。
17. As a 导演, I want 关闭页面后恢复与原版本和修订绑定的未保存编辑, so that 意外离开不会丢失创作内容。
18. As a 导演, I want 外部修订发生变化时比较差异并自行处理, so that 较旧的本地暂存不会覆盖较新的服务器数据。
19. As a 导演, I want 未保存期间清楚看到关系图属于上次已保存修订, so that 我不会把尚未入库的编辑误认为权威关系。
20. As a 制片或导演, I want 在同一镜头建立多个生产单元并分别选执行项, so that 人物动作与环境补镜可以分开拍摄。
21. As a 制片或导演, I want 每个单元出现项明确选择节拍、事件、镜内活动、表演行动和可见连续性变化, so that 镜头关联不被误用为本次执行清单。
22. As a 制片或导演, I want 用动作范围描述所选项目的具体表现, so that 结构化身份和创作细节能够共同表达意图。
23. As a 制片或导演, I want 单元区分已选动作、适用约束和有明确消费依据的背景, so that 同镜头其他动作不会混入本次拍摄。
24. As a 制片或导演, I want 全场视频规则进入每个适用单元的固定依据, so that 每次拍摄遵守同一全场约束。
25. As a 制片或导演, I want 声音或后期规则保留其全场身份但只进入相应制作阶段, so that 视频模型不会被要求提前完成后期工作。
26. As a 制片或导演, I want 区分执行内容、约束和引用背景, so that 背景中的人物或动作不会被自动追加为本次拍摄要求。
27. As a 制片或导演, I want 查看每项已选动作及全场、局部视频约束在指令或实际参考中的去向, so that 我能核对视频模型到底收到了什么。
28. As a 制片或导演, I want 关键动作在指令正文中表达, so that 仅绑定一张身份参考图不会被误认为已经描述了动作。
29. As a 制片或导演, I want 适用约束或已选动作缺少执行去向时停止生成, so that 数据里的要求不会被静默遗漏。
30. As a 制片或导演, I want 全场规则与局部要求冲突时得到定位和处理入口, so that 系统不会擅自决定哪项优先。
31. As a 制片或导演, I want 相关设计变化后保留原指令并重新核对受影响单元, so that 人工正文不丢失且旧检查不再误放行。
32. As a 制片或导演, I want 未被当前单元消费的设计编辑不使其检查失效, so that 我不必重复检查未受影响的拍摄。
33. As a 制片或导演, I want 参考素材仅在单元明确绑定后进入视频请求, so that 设计资产关联不会暗中改变模型输入。
34. As a 剪辑与验收人员, I want 历史生成记录保留当时的规则、指令和参考, so that 新设计不会改写旧素材的真实依据。
35. As a 剪辑与验收人员, I want 将视频实际呈现与计划执行项分开判断, so that “模型已接收要求”不会被误当成“素材已覆盖要求”。
36. As a 导演, I want 场次背景标明无需逐镜关联且不自动执行, so that 我不会把背景误当成未关联设计或全场规则。
37. As a 导演, I want 同一工作单内的背景与约束逐项标明用途, so that 混合内容仍只保留一张可编辑原卡。
38. As a 制片或导演, I want 背景进入单元时看到消费原因, so that 我能判断它的变化影响哪些单元。
39. As a 制片或导演, I want 相关范围未知或背景中误写了执行约束时得到具体定位, so that 未判定的要求不会被静默放行。

## Implementation Decisions

- 沿用场次版本这一可编辑方案身份。保存递增 revision，不因 AI 提取或自动保存增加用户可选择的草稿层；AI 结果仍为建议，明确应用后写入同一版本内容。
- 六岗及对白与声音工作单保留原有正式归属、完整设计字段和六岗逐出现项检查；内容用途、镜头适用性、单元执行选择与岗位归属分别表达，不新建岗位副本或审批状态。
- 设计数据保留强类型局部身份、真实字段引用和明确的适用性。全场规则、指定镜头、待归镜头与未关联是业务语义，不由前端对象类型、名称、画布位置、引用次数或当前镜头数量推断。
- 场次背景是有岗位归属的非执行性叙事、人物或环境上下文，不要求逐镜引用。它是后端权威图给出的内容用途与展示分类，不增加可任意切换的关联状态；画布标明“场次背景 · 无需逐镜关联 · 不自动执行”，不计入未关联或待归镜头。独立的节拍、镜内活动、对白、摄影及连续性变化等不能仅因缺少镜头关系改标背景。工作单可同时含背景和规则，仍保留一张可编辑原卡，按字段或独立条目标注用途，不把整卡统一判为其中一种。
- “全场规则”只适用于全场真实生效的约束或不变事实。即使一项普通设计恰好关联当前所有镜头，它仍是明确多镜关联；新增镜头不会因此自动受它约束。规则可带全场一致的条件，条件不隐含强制对象出镜。
- 场次设计的全场规则如有镜头或单元局部例外，不维持全场身份，而明确列出实际适用的镜头；确需区分同镜单元时精确到单元出现项。不设置“全场规则优先”或“局部规则自动覆盖”的隐式优先级。项目风格规则已有的条件与例外仍按其场次、模型范围求实际适用性，不因存在例外说明而自动取消项目范围。
- 规则记录其作用阶段。视频相关规则进入适用单元的指令依据；声音与后期规则保留在设计中，按其阶段处理。现有制作能力未覆盖的阶段不伪装为视频模型已执行。
- 对象直接引用与设计适用性分别存储。因果引用、共用参与对象、空间锚点或资产绑定不能单独证明某项设计适用于镜头；关联多个镜头也不能单独证明它是全场规则。
- 除场次背景外，完全没有真实引用且没有明确适用性的独立设计项显示为未关联；有真实引用但无法确定镜头且未标全场规则的独立设计项显示为待归镜头。明确适用一个镜头为镜头专属，多个镜头为跨镜共享。
- 可单独定位、关联、选择或追踪去向的设计行使用稳定身份，包括当前仅依赖数组位置的镜内活动和表演行动。逐项校验去向的规则、局部约束与已选动作也有稳定定位：语义上只有一项要求的字段可用稳定字段路径，列表中的独立要求须各有 ID，不以数组位置或文本内容作身份；纯说明背景无需逐句编号。删除或改绑引用必须经场次版本的类型、项目、版本和文件校验。
- AI 提取可产生有效关联，也可产生用户尚未决定使用的未关联内容。用户可手动修改相同关系；不增加“提取到”“决定使用”两套状态或数据来源身份。AI 按字段语义输出背景、规则与动作，不用任意背景标签掩盖缺失关联。非法引用、互相矛盾的结构化范围按已确定的有界纠错一次处理，仍不合格则整次建议失败。
- 后端从同一已保存修订产出权威关系图。图包含稳定对象身份、类别、适用性、字段或条目的内容用途、直接边、间接路径、拥有引用的对象与字段、未关联或待归镜头原因，以及场次背景无需逐镜引用的说明。图是设计内容的服务端读模型，不是第二份可编辑真值；展示分类不伪造镜头边。
- 图与场次版本读取及保存确认快照绑定同一版本身份和 revision。前端可做布局、聚合、过滤、高亮与导航，但不能自行决定业务归位或补造引用。检查详情必须可看到全部直接引用，即使某视图压缩或隐藏了边。
- 第一阶段不提供未保存草稿的关系投影接口。用户编辑暂存期间，关系图明确标示其上次已保存 revision 和关系更新中；可继续编辑字段，暂缓图上关系操作，保存确认后展示新图。
- 初次加载可用服务器内容初始化暂存；有本地恢复数据时先核对其版本身份、基础 revision 和原请求状态。后续普通读取或保存响应不能静默覆盖当前暂存，也不能把旧暂存重新配对到新的服务器 revision。
- 保存冻结快照 S、预期 revision 与 request_id。自动保存约在停止编辑一秒后触发，连续编辑至多约五秒触发一次；手动保存沿同一事务路径，一次只发一个保存请求。
- 保存确认核对版本身份、request_id、预期的新 revision 与本次提交快照的业务等价性；只推进已确认基线和权威关系图，不用响应正文替换可编辑暂存。请求在途又有编辑时仍为未保存，继续提交下一快照；仅当前暂存已被确认时显示保存成功。
- 请求结果不明时按同一 request_id 核实或重试；可确定的校验错误保留输入，用户修改后再试；revision 冲突停止自动保存并提供本地与服务器差异，绝不自动重基或覆盖。关闭恢复沿用这些规则。
- 内容等价判断保持业务区别，包括镜头参与对象范围的 null（待核对）与空数组（明确无对象），不能为减少保存次数而合并语义。
- 单元出现项是执行选择的粒度，保留镜头、节拍、事件和动作范围，增加镜内活动、表演行动与可见连续性变化的明确选择。选择对象的稳定身份与适用范围由服务端校验；镜头关联只确定候选，不自动选入单元。
- 后端为指令建议、依据确认、六岗检查及视频预检使用同一份单元范围投影，分开记录已选执行动作、适用全场及局部约束、实际消费的解释背景。摄影、空间、连续性前后态及岗位禁止项即使不是已选动作，只要明确适用于该单元，仍按其作用阶段进入约束依据；未选动作、待归镜头项和未关联项不会因同镜或共用对象自动成为执行要求。六岗逐出现项审查继续保留。
- 场次背景仅在后端有明确消费依据时进入单元解释背景，并记录纳入的字段或条目及原因：场次级核心背景可供全部单元使用，人物情境等依据明确相关范围纳入；展示为背景本身不代表每单元都消费。背景不自动变为动作或约束。参与对象等范围未知且影响背景或约束纳入时，允许保存和浏览，但相关单元在范围补明前不能通过检查或提交视频；不把 null 当作全部或空名单。
- 每条适用于视频阶段的全场或局部约束、每项已选设计中需要拍出的动作或可见结果均记录可追踪去向，不要求叙事目标、潜台词或其他解释背景逐字进入指令。动作必须由执行正文表达；身份、空间等可由正文或实际绑定的参考表达。没有去向、引用了未绑定素材、或仍有未解决冲突时不允许检查通过和视频提交。逐项去向校验补充而不替代六岗检查，两者均满足才可生成。
- 结构化冲突由数据校验拒绝。自然语言语义冲突由指令检查指出并交由用户处理，不让系统自动选择全场或局部优先。背景字段中误写命令式约束不靠文案自动升级；普通保存保留原文，检查识别后定位字段，用户明确移入规则条目或改成纯背景说明，未解决则不能通过检查和视频门禁。AI 检查和人工核对不能保证发现所有隐含要求，也不能保证模型实际遵从。
- 全场视频规则变化影响所有相关单元；镜头或单元范围的动作、局部约束及背景仅影响固定输入实际消费它们的单元。依据已变时保留原正文和历史检查，要求重新确认并检查；无关单元不失效。
- 历史指令任务、确认回执、检查和视频执行保存原输入及投影语义版本；新的投影算法不得追溯改写历史快照或用当前规则重新解释旧建议。旧场次数据不做自动迁移。
- 项目资产关联、场次设计关系、单元实际参考绑定和 Take 实际覆盖保持独立。生成成功只登记候选，不能推定镜头或规则已被满足。
- 对外契约变化同步后端接口、OpenAPI 和前端生成客户端；当前事实与未来方案分开维护，落地后更新相应架构和领域术语文档。

## Testing Decisions

- 以用户可观察的业务结果为断言：保存后回读的关系、固定指令输入、实际视频请求、错误状态和历史快照。避免只测试前端分组函数、DTO 字段存在或 mock 出来的成功提示。
- 主要复用场次版本的真实 HTTP 与数据库事务入口，贯穿创建、保存、读取、AI 建议应用、单元选择、指令依据与检查、视频预检／提交。这是数据权威性和生成去向的主要验收缝；现有场次版本、设计建议、指令、检查与视频接口测试提供先例。
- 在该缝覆盖有效单镜／多镜／全场规则／场次背景／待归镜头／未关联、混合工作单的字段用途、缺失与跨版本引用、条件式规则与项目风格例外、阶段归属、同镜两个单元选不同动作、适用局部约束、背景按原因进入但不执行、未知参与范围、实际绑定参考、冲突和遗漏阻断，以及未消费内容不使单元失效。
- 复用工作台的真实浏览器流程作为第二条用户交互验收缝，验证画布的“场次背景 · 无需逐镜关联”与混合卡片逐项用途、未关联计数及真实引用来源、背景消费原因和受影响范围提示、图修订提示、在途编辑、自动与手动保存、失败保留、关闭恢复、409 比较、延迟响应不覆盖新输入和可访问的状态提示。现有场次工作台、设计引用、单元覆盖、指令依据、指令检查及视频浏览器场景提供先例。
- 以固定输入断言历史任务在新投影规则上线后仍可读取、比较和按原依据重试；旧 Take 的真实输入不被当前设计变化重写。模型质量不使用伪造检查通过来代替验收。
- 对语义等价、并发与异常输入补有针对性的回归：null 与空名单、背景相关范围未知、同一卡背景与规则并存、独立规则重排后身份稳定、命令式约束误入背景、同一 request_id 重放、未知保存结果、在途新编辑、修订冲突、非法规则范围及删除被引用设计行。

## Out of Scope

- 旧场次数据的自动迁移、批量补关系或根据名称推断历史对象身份。
- 为 AI 提取结果增加候选／采用两套数据状态，或把一次保存创建成新的用户版本。
- 从设计资产关联自动选择参考文件，或从画布连线直接生成视频请求。
- 对尚未保存的前端暂存提供即时服务端关系图，或让前端保留另一套权威业务归位逻辑。
- 以任意开关将独立设计项标为背景、靠自然语言自动升级规则，或为场次背景补造镜头引用。
- 新建声音生成、混音或后期流水线；本规格只要求规则的作用阶段明确且不误投给视频模型。
- 保证视频模型遵从每条指令，或把生成成功当成 Take 已通过素材审查、已覆盖计划或已进入剪辑。
- 跨设备实时协同编辑；revision 冲突保护和本地恢复仍在本规格内。

## Further Notes

- 当前实现的全场区按固定对象类型归位，卡片统一显示“全场适用”；单元指令输入仍保留整场镜内活动与连续性，六岗检查也未逐条建立要求到最终请求的映射。这些是本规格要修正的现状，不应在架构文档中提前写成已落地能力。
- 项目术语表按本轮确认的“场次背景”“全场规则”“镜头适用设计”“待归镜头设计”和“未关联设计”说明用途与关系边界；既有界面中称为“全场共享”的背景及汇总卡不得因此被默认为全场规则。
- 实施按项目既有边界进行：后端业务编排走 service，场次写入走统一存储，前端接口走生成客户端；具体模块和路径由实现时的代码现状决定。
