# 02: 在统一会话中处理画布提案、审批与停止

**What to build:** 自由画布与分镜画布的用户在原回复中查看建议、回答问题、审批或停止，两个页面对正在执行的轮次采用相同的发送规则。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 助手按实际画布、选区、可见草稿和适用 Skill 提出建议。决定仍绑定展示过的提案版本与改动组，冲突或成功以画布业务回执呈现。已有画布操作继续遵循其授权范围。
- [ ] 追问和审批通过对应卡片继续原轮次。工具卡显示实际执行模型及可公开的参数、引用和回执。刷新后可恢复待答问题、待审项及已作出的决定。
- [ ] 回复、执行工具和等待产物期间，页面禁用普通发送，关闭运行中补充与排队。两客户端并发发送不同请求只有一个受理，服务端对其他入口执行同一限制；原请求可以幂等重试，其他会话仍可发送。
- [ ] 停止回复会结束本轮后续动作并恢复发送。已受理的后台生成仍关联原任务，任务卡继续显示实际进度并按能力提供取消。
- [ ] 通过两个画布的会话 API 验证授权、刷新恢复和并发受理，通过浏览器验证发送状态、问题卡及审批卡操作。

对应[规格用户故事](../spec.md#user-stories) 14、15、16、17、18、20。
