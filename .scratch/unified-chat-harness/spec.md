# 画布助手与实验室的统一聊天协议

Status: ready-for-agent

Completion: resolved

## Problem Statement

用户可以在画布助手里与模型连续讨论创作，也可以在实验室分别测试文本、图片和视频模型。现有实验室按模态提交输入。要完成「先画一张雨夜街景，再拿这张图做一个 5 秒推进镜头」，用户需要在不同会话之间传递素材，两个页面展示模型回复、任务进度和结果的方式也不同。

用户同时需要保留直接试模的能力。当目的是比较两款视频模型时，能否将指定参数和参考图直接交给所选模型，决定了比较是否有意义。

## Solution

画布助手与实验室多模态聊天共用一套 Agent Harness。主聊天模型通过供应商协议调用模型能力，结合当前场景提供的工具、Skill、提示词和上下文完成一轮对话。实验室默认新建多模态聊天，选文本、图片或视频则直接进入对应的单模态试模。三个入口共用会话客户端、公开事件类型和 SSE 订阅。

在雨夜街景的例子中，用户可以看到使用了哪款图片模型，打开生成的图，再看到视频工具将同一份图片用作首帧。任务受理后立即显示进度，文件归档后在原回复展示产物。用户刷新页面可以继续查看这一轮，下一轮也可以引用刚才的视频。

## User Stories

1. 作为实验室用户，我希望新建时默认进入多模态聊天，以便直接用自然语言开始创作。
2. 作为模型测试者，我希望选择文本、图片或视频进入单模态试模，以便让指定模型直接处理我本轮填写的参数和素材。
3. 作为已有实验会话的用户，我希望仍能打开历史、查看结果和回填输入，以便继续先前的试模工作。
4. 作为聊天用户，我希望默认只看到主模型，并能展开配置分别选择图片和视频模型，以便只调整这次创作需要的模型。
5. 作为实验室用户，我希望各模型选择器预选对应的全局默认模型，改选后在本会话沿用，以便比较不同执行模型时保留其他选择。
6. 作为聊天用户，我希望先用通用助手讨论创意，再按对话需要生成一版或多版，以便自己决定创作方法。
7. 作为熟悉工具的用户，我希望从斜杠指令中选择 `/imagegen` 或 `/videogen`，再补写要求、附加参考素材，以便明确这次要执行的动作。
8. 作为创作者，我希望主聊天模型能在一轮中先出图，再把已生成的图片用作视频首帧，以便连续完成有先后依赖的生成。
9. 作为继续创作的用户，我希望下一轮说「把刚才的视频改成横屏」时能引用具体产物，指代不清时可以选择，以便保留原版并得到新版。
10. 作为使用纯文本主模型的用户，我希望可以把已选图片交给支持首帧的视频模型，以便直接复用素材。
11. 作为要求分析素材的用户，我希望在主模型无法理解图片或视频时得到具体说明，并能在原会话切换到合适模型，以便得到有素材依据的回答。
12. 作为使用工具能力有限模型的用户，我希望仍可进行普通文本对话，在需要生成时保留输入和附件并选择支持工具往返的主模型，以便继续当前工作。
13. 作为聊天用户，我希望原生流式模型逐段显示回复，其他模型在正文就绪时整段显示，以便两类模型都能用于对话。
14. 作为画布或实验室用户，我希望看到工具使用的实际模型、任务进度、产物和失败原因，并可展开查看参数、引用素材和回执，以便核对执行结果。
15. 作为画布用户，我希望助手继续基于当前画布、选区和草稿提出修改，并通过已有的版本与分组审批机制执行，以便控制实际生效的操作。
16. 作为有多个聊天会话的用户，我希望忙碌会话暂时关闭发送、补充与排队，其他会话仍可使用，以便清楚地知道每条消息属于哪一轮。
17. 作为被助手追问或请求审批的用户，我希望能在原问题卡或审批卡作出决定，以便原轮次继续工作。
18. 作为改变主意的用户，我希望能停止本轮的后续动作，并能在任务卡单独取消支持取消的生成任务，以便分开控制对话和后台生成。
19. 作为只想提交任务的用户，我希望助手拿到提交回执后便结束本轮，任务卡继续更新，以便立即开始下一轮聊天。
20. 作为重新打开页面的用户，我希望看到原有回复、待办和产物，断流重连或重试后每一步生成仍只提交一次，以便恢复工作。

## Implementation Decisions

### 三层职责

| 边界 | 职责 |
| --- | --- |
| 供应商协议与模型管理 | 使用所选登记模型和供应商配置的有效能力，校验输入、参数与交付方式。主聊天模型通过现有 LangChain 适配器接入，图片和视频调用复用既有生成服务与 Worker。 |
| Agent Harness | 从画布助手已有的 Deep Agents 运行逻辑提取共用部分，负责组装本轮上下文、执行模型与工具循环、在有依赖时等待工具结果、恢复并继续原轮次。画布提供选区、草稿、专业技能、提案和审批规则。实验室提供通用提示词、会话素材及生成工具，生成数量由用户与 Agent 决定，执行参数遵循模型有效能力。 |
| 会话 API 与前端客户端 | 统一打开或恢复会话、提交一轮、读取快照、按游标订阅事件、停止，以及适用的问题回复与审批操作。会话类型决定执行方式。单模态试模直接将本轮输入交给所选模型；两个聊天场景进入共用的 Harness。 |

### 模型选择与素材

- 新建时预选多模态聊天。其主模型默认可见，图片和视频的选择器收在高级或模态配置中。单模态试模直接展示该模态的选择器。每项从对应全局默认模型开始，用户的改选在本会话沿用；缺少媒体模型时，在用到该工具时提示选择。
- 单模态试模沿用逐轮独立输入和历史回填。已有文本、图片和视频会话按原模态恢复。多模态聊天可跨轮引用本会话的产物，引用落实到具体文件。用户说「刚才那个」且存在多个合理对象时，由用户指明。
- 按动作校验模型能力。传递首帧文件只要求视频工具接受该引用。解读图片、评估视频运镜需要主模型在当前供应商配置下具备相应的理解能力。能力不足时说明具体原因，保留会话、输入和附件供用户改选。
- 普通聊天可使用只支持文本的模型。工具循环要求主模型支持工具调用和结果回传。文本流式能力独立判断，只支持完整正文的主模型也可在具备工具能力时完成连续生成。
- 采用 Ant Design X 的输入建议呈现快捷指令。选中指令表示用户已选定生成动作，用户可继续编辑和附加素材后再发送。输入充分时执行对应工具，关键信息有歧义时可追问。自然语言和快捷指令共用工具执行与事件展示。

### 轮次、工具与事件

- 会话用 `session_id` 定位，提交用 `request_id` 识别重试，受理后用 `turn_id` 关联本轮交互。同一轮中的各次工具调用各有 `tool_call_id`，媒体任务另有 `task_id`，文件归档后以稳定的 `file_id` 引用。这样同一轮的多次生成、各自的结果和后续依赖均可追溯。
- 公开事件共用有类型的载荷，表达轮次受理与终态、文本增量或完整回复、工具调用与结果、后台任务受理与进度、产物及失败，以及场景适用的追问和审批。三个入口对同一种事实使用相同类型。单模态直接提交产生真实的任务或文本事件。页面按会话游标恢复事件，以同一份快照恢复历史和待处理事项。
- 工具卡展示实际执行模型，可展开查看本次公开参数、引用素材和任务回执。供应商流分片与框架内部步骤由服务端映射为用户可见的产品事件。工具失败关联对应调用，同一轮先前成功的产物仍可查看。
- 媒体工具通过生成服务提交，Worker 负责使用冻结的执行输入、查询任务和归档产物。任务受理即可展示任务卡。后续步骤依赖产物时，文件归档后才将结果交回主模型；例如视频请求中的首帧应指向同轮图片工具的实际产物。只要求提交时可凭回执结束本轮，原任务卡继续更新。
- 对已受理的请求、工具和媒体任务沿用原身份恢复。断流重连或 Worker 重启后核对原回执，受理状态未知时先核实，避免重复生成。SSE 断开只结束当前订阅。
- 画布助手和实验室多模态聊天在回复、执行工具或等待产物时，前端关闭普通发送，服务端拒绝同一会话的新消息，包括运行中补充和排入下一轮。对原请求的幂等重试仍有效。其他会话可以发送；暂停提问和审批时，通过对应卡片处理原轮次。
- 停止回复结束本轮后续动作，已受理的生成继续由原任务跟踪。任务卡按供应商能力提供取消，终态依据实际回执。本轮结束即开放普通发送。

## Testing Decisions

主要从公开会话 API、SSE 和恢复快照验收。使用可控供应商响应，保留实际工具循环和生成服务边界，通过收到的请求、公开事件、归档文件与任务回执验证行为。浏览器只补充页面上才能观察的交互。已有画布断线审批恢复、Worker 重启、实验室媒体提交与历史恢复用例，以及实验室输入框和提交恢复的浏览器用例可作为先例。

| 验收场景 | 可核对的结果 |
| --- | --- |
| 同轮从图到视频 | 输入「先出一张雨夜街景，再用它做 5 秒推进镜头」。每步生成只提交一次，分别使用选定模型。核对视频供应商实际收到的首帧对应图片步骤归档的文件，时长为 5 秒。任务受理、产物就绪、工具结果和最终回复能在同一轮关联。 |
| 三个入口的契约 | 通过同一客户端操作画布聊天、实验室聊天及文本、图片、视频试模。相同事实产生同类事件。直接试模的供应商收到用户指定的模型、本轮输入及参数。已有实验历史可打开与回填，画布提案仍按原授权执行。 |
| 流式、整段回复和失败 | 原生流式模型逐段交付正文；非流式主模型一次交付正文，也能在具备工具能力时执行媒体工具。视频工具失败时失败归属正确，之前成功的图片仍可查看。 |
| 素材引用与能力 | 文本主模型把同一图片传给支持首帧的视频工具时可成功；要求其分析图片或视频时提示相应能力不足。切换主模型后可在原会话继续。无工具能力的主模型可普通对话。跨轮引用有多个候选时先澄清。 |
| 断流、重试与恢复 | 在生成受理后断开，按游标重连、重发原请求，并覆盖 Worker 重启。历史与实时结果能对应原轮次，已受理的任务只有一份，依赖步骤收到正确文件。重复投递事件不会在页面多出一张产物卡。 |
| 忙碌会话与用户决定 | 从两个客户端向同一聊天会话并发提交不同请求，只有一个新轮次获受理。运行中补充和排队也不能创建工作，其他会话仍可发送。通过追问卡或审批卡的决定关联原轮次，本轮结束后可再发送。 |
| 停止与仅提交 | 停止回复后不再发起后续工具，已提交任务仍可追踪；单独取消任务时显示真实回执。只提交视频的轮次在取得回执后结束，此时可开始下一轮，原任务卡随进度更新。 |
| 浏览器交互 | 检查默认入口、三类试模、全局默认选模、折叠配置与会话改选。验证斜杠指令可编辑和附图，缺少能力时保留输入。两个聊天页面都正确禁用和恢复发送，并显示实际模型、工具结果和可用产物。 |

## Out of Scope

独立旁白、配乐等音频生成工具和相应供应商接入留待后续。统一产物契约可表达音频。画布的修改授权、版本审批和结果采用继续由画布业务服务负责。供应商协议、任务调度和文件归档沿用现有职责，本次规格聚焦交互会话及其接入。

## Further Notes

实验室的逐轮独立输入约定适用于单模态试模。画布原有的运行中补充和排队条款，由活动轮次的发送规则取代。相关设计依据见[统一聊天与直接试模决策](../../docs/development/adr/0021-experiment-chat-and-model-trials.md)、[交互会话协议](../../docs/development/adr/0017-interaction-session-protocol.md)、[画布能力与审批](../../docs/development/adr/0018-canvas-capabilities-and-approval.md)和[模型供应商协议](../../docs/development/adr/0020-model-provider-protocol.md)。
