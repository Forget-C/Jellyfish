# 双画布后端能力协议、独立审批与 Deep Agents 工具接入

Status: ready-for-agent

## Problem Statement

同一次视频卡编辑可以由用户在画布里完成，也可以由助手提议。目前编辑预演同时处理模型参数和画布业务规则。后端调用方难以独立复用这些规则，维护者也难以证明手动编辑与助手写入会得到相同的生成输入。用户批准某个镜头后，还需要知道它是否真正写入，以及重试是否会再建一张卡或再次提交生成。

## Solution

让自由画布和分镜画布通过进程内 Python 类型协议提供完整的后端业务能力。助手按创作任务使用其中一部分能力，先预演，再将可独立生效的改动组送审。独立审批组件记录谁对哪个版本的哪些组作了什么决定；画布负责执行并提供回执。用户能在原对话中分别核对所见差异、自己的决定和最终效果。手动编辑继续使用现有保存入口。

## User Stories

1. 作为后端调用方，我希望直接查询当前画布和它支持的操作，以便根据画布自身的约束调用功能。
2. 作为后端调用方，我希望能独立完成预演、提交、生成输入编译及运行查询，以便在没有助手会话时也能完成业务。
3. 作为自由画布用户，我希望手动编辑和助手预演都遵守自由画布的卡片目录，以免建议新增设计卡。
4. 作为分镜画布用户，我希望助手按分镜画布现有规则创建和修改设计卡，以便继续在同一画布制作分镜。
5. 作为剪辑者，我希望视频卡既能直写完整描述，也能引用文本内容卡，以便只维护一份正文。
6. 作为创作者，我希望被视频卡采用的角色主体图进入实际生成输入，以便提交前核对引用的是哪张图片。
7. 作为创作者，我希望继续修改同一镜头时复用原卡、连线和绑定，以便补说明或重复执行后仍保留原有结构。
8. 作为助手用户，我希望先查看候选改动、依据和差异，再决定是否送审，以便在构思阶段自由迭代。
9. 作为文本模型用户，我希望获得与原生工具调用模型一致的预演及错误反馈，以便使用相同的创作流程。
10. 作为审批人，我希望按钮和明确指向审批卡的文字确认都绑定到我看到的版本与所选组，以免误批后来的修改。
11. 作为审批人，我希望只批准第一个镜头，将第二个留待审核，以便分批推进制作。
12. 作为授权自动审批的用户，我希望每组改动按我的授权和实际影响独立复核，以便追溯自动决定。
13. 作为手动编辑画布的用户，我希望保存整份草稿时继续沿用当前入口，并与助手共享引用和冲突规则，以便切换编辑方式。
14. 作为审批人，我希望能分别看到已批准、已写入、执行失败和字段冲突，以便判断是否需要调整或重试。
15. 作为在审批后又手动改过字段的用户，我希望查看原值、当前值与建议值，以便依据最新差异再作决定。
16. 作为中途关闭页面的用户，我希望重开后找回原决定与执行结果，以免再次批准已经生效的操作。
17. 作为业务接入方，我希望独立发起审批、核验决定和消费有效决定，以便复用审批组件并保留自己的执行规则。
18. 作为升级中的用户，我希望旧审批卡明确提示失效，而已写入的画布、素材及可追踪的生成任务继续可用，以免重复劳动或重复生成。

## Implementation Decisions

1. **完整画布协议。** 用可独立组合的 `typing.Protocol` 覆盖四组现有后端业务能力：画布生命周期、读取与能力查询；编辑预演、提交与回执；生成输入解析与编译；生成运行与结果查询。各组使用领域输入、结果和错误。按两种画布已有的公开业务操作逐项核对覆盖范围，分别记录适用的画布和对应协议，避免以首批助手工具代替完整能力清单。
2. **业务规则归画布。** 画布实现根据资源作用域、卡片目录和模型能力验证操作。直接编辑保留整份文档保存契约；助手持久改动走获批执行入口。两条路径共享来源身份、引用绑定、重复判定和冲突规则。每次写入或生成提交只有一个执行入口。允许只读比较预演结果。
3. **面向创作任务的工具。** 首批封装画布读取、批量修改预演、生成输入检查、发起审批和查询审批。预演可组合多个领域操作，产出目标、字段差异、依赖及可独立生效的组；用户只请求方案时，停在预演。原生工具调用与纯文本适配都使用同一组领域操作，参数转换和面向模型的反馈由适配层承担。创作技能提供专业方法，运行时按角色分配工具。
4. **审批契约。** 请求记录请求身份、幂等键、可信上下文中的申请方和资源作用域，并关联业务对象类型、标识、不可变版本、可审批组及展示快照引用。业务方维护可按版本重读的快照，包含差异、影响、操作数量及必要预览。审批组件验证决定方权限，记录决定标识、动作、来源、时间、版本和所选组。被替代版本上的新批准失效。申请方、决定方和执行业务方可以分别接入，权限由服务端授予。
5. **人工与自动审批。** 人工按钮、明确指向所见审批卡的文字确认和自动审批共用决定服务。文字无法唯一确定版本或组时保留待审。自动流程先核对用户授权及代码规则，再由独立审批 Agent 按组复核，服务依据两者签发决定。删除卡片、解除已采用引用、发起模型卡运行沿用现有明确指令要求。创作助手只能调用其角色获授的工具。
6. **获批执行与恢复。** 决定持久化后由业务执行方接续获批组，无需模型再次调用写入工具。应用前复核来源、依赖和当前字段。保存画布与记录写入回执在同一事务完成；外部生成以原请求标识查询已受理或结果未知的提交。恢复时按原决定和组核对回执，只继续未完成的获批动作。已拒绝组和待审组保留各自状态。冲突保留原决定和实际值，重新确认最新差异产生新决定。
7. **接入顺序。** 先验收完整画布协议，再验收独立审批组件，随后按角色封装画布与审批工具，最后切换 Deep Agents。首个贯穿切片采用视频正文引用与角色主体图，其他现有能力按同一契约逐项迁移。会话继续使用既有的提案、决定和执行事件，展示端以领域回执确认写入或生成提交。
8. **升级。** 已切换的能力只运行新协议，移除相应旧提案执行分支、旧工具名适配器和旧检查点恢复分支。按记录清理发生冲突的未完成旧提案、工具检查点及待处理状态。旧页面提交失效提案时提示重新发起。部分审批保留已生效组产生的卡片、连线和绑定；保留可读的画布内容、普通对话正文、素材、生成结果，以及已受理或结果未知的生成任务、请求标识与可查回执。

## Testing Decisions

验收使用以下三个公开入口，断言用户可见状态、实际持久化效果、编译后的输入和生成提交次数。沿用现有生成画布描述引用、引用素材保存与编译集成、助手审批及会话恢复用例的测试方式。模型和生成执行使用可控替身，保留真实领域校验与持久化边界。

| 验收入口 | 操作 | 通过条件 |
| --- | --- | --- |
| 普通后端调用方 | 在两种画布上直接查询能力，预演并应用两个镜头，分别使用视频卡直写和文本卡引用，采用指定角色主体图，再编译生成输入。以相同起始状态经助手工具重做预演，并覆盖原状重放和来源值变化。 | 每个镜头编译后的完整描述只出现一次，实际图片文件与所选主体图一致。重复应用不增加卡片、连线或绑定。工具和直接调用在差异、无变更、冲突三种情况下给出一致结果。手动整份保存后重新读取仍符合这些规则。 |
| 两种画布的助手入口 | 使用可控原生工具模型与纯文本模型，从只要方案、送审一路走到决定。对两个可独立镜头只选第一个，通过按钮和指向审批卡的文字分别验证；再覆盖旧版本确认、自动授权范围内外和独立复核未通过的情形。 | 预演可修改且无写入；送审展示实际版本与分组差异。只写入获批镜头，另一镜头仍待审。自由画布拒绝新增设计卡，分镜画布按现有规则处理设计卡。失效或指代不明的确认不生效。自动决定有来源可查，越权或未通过复核的动作不执行。 |
| 持久化、重启与升级入口 | 分别在批准后执行前，以及效果产生后、调用方收到回执前中断并恢复。重放同一决定，模拟生成已受理但本地结果未知。用含旧待审、部分已生效、原任务标识及普通历史的升级样本检查清理结果。 | 重启后可不依赖下一次模型回复接续；原决定能查到各组执行回执，重复或并发消费最多产生一次效果。审批后字段变化时保留批准事实并显示最新差异。旧卡再次提交明确失效，已生效内容和可读历史保留；两类生成状态均按原标识跟踪，新增提交次数为零。 |

## Out of Scope

本次保留现有编辑器保存接口、助手界面、会话事件语义和两种画布各自的卡片规则。跨进程服务化、替换 Deep Agents、扩展其他业务的审批页面，以及整理历史重复卡片，均在本次范围之外。

## Further Notes

架构依据为 ADR 0018《画布能力协议与独立审批》。审批版本、分组和执行回执沿用 ADR 0016，会话恢复与事件展示沿用 ADR 0017。首个切片用于尽早验证从普通业务调用到用户实际生成输入的整条路径；整项重构以四组协议覆盖现有后端能力并完成相应入口切换为验收终点。
