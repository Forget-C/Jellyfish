# 03: 首尾帧独立配置并进入视频生成

**What to build:** 用户通过独立首帧、尾帧卡选择、替换和查看本次图片输入；绑定可以独立保存、取消及撤销，真实图片按首尾位置进入视频生成请求。

**Blocked by:** None

**Status:** ready-for-agent

**Spec:** [AI 指令起草与参考媒体视频生成链路](../spec.md)，实施决策 5、6、8、10；验收 A05、A06 的帧输入部分，A07、A09、A15 的首帧及首尾帧路径，以及有关的 A16、A17、A20。

## Acceptance criteria

- [ ] 单元画布首帧和尾帧分别展示独立卡片，显示缩略图、起始／结束标识、来源和可用状态；未选择时显示添加入口。
- [ ] 通过已有图片或上传选择素材，明确应用后建立绑定并自动展示至单元的输入关系；不通过拖线创建或断线删除。
- [ ] 卡片与编辑目标由后端业务图投影提供，保存后和当前编辑预览的关系一致；前端不另算一套业务拓扑。
- [ ] 从首帧或尾帧卡打开选择器时固定对应输入位置，更新只影响目标绑定；模型不支持时解释原因，不自动切换为主体参考。
- [ ] 同一图片能分别用于首帧和尾帧，两处绑定独立；替换或移除一处不会修改另一处，文件去重不吞掉另一个位置。
- [ ] 明确应用形成一次可撤销编辑，取消保留原绑定；弹窗期间发生相关变化时，旧选择不能覆盖新编辑。
- [ ] 来源、对应对象和输入位置分别表达；继续遵守文件归属、权限、类型及模型能力限制，不自动选用默认候选。
- [ ] 提示词加首帧、提示词加首尾帧两条路径，从保存到固定任务和供应商实际请求均保留真实图片内容及正确位置；运行期间编辑不替换原任务输入。
- [ ] 不支持的组合、重复位置、不可访问或跨项目文件明确拒绝，不静默丢图、改角色或降级为其他模式。
- [ ] 完成受影响的图契约、浏览器、场次 HTTP 和媒体传递测试，以及类型检查、后端检查、接口客户端和文档同步。

## Validation

- 通过真实浏览器分别添加、取消、替换、撤销首尾帧，读取保存内容核对独立绑定和空态连线。
- 使用可区分的图片以及同一图片复用两种夹具，经真实任务执行与媒体读取，在供应商请求边界核对内容及首尾顺序。
- 本票负责普通首尾帧链路；前段实际落幅及关联依赖的完整生命周期由依赖本票的 05 负责。真实生成验收归入 08。
