# 05: 实际落幅承接与依赖状态一致

**What to build:** 用户将已采用片段所选区间的实际落幅作为当前单元首帧，在一次操作中建立或替换承接来源；移除或换图后，前段依赖保持真实、可保存且有明确的待绑定状态。

**Blocked by:** 03 — 首尾帧独立配置并进入视频生成

**Status:** ready-for-agent

**Spec:** [AI 指令起草与参考媒体视频生成链路](../spec.md)，实施决策 6、7、10；验收 A10、A11、A12、A13，以及有关的 A06、A09、A16、A20。

## Acceptance criteria

- [ ] 继续仅从已保存、已采用真实片段的所选媒体区间提取最后可解码画面，保留源 Take、片段、区间、取帧时间和文件依据。
- [ ] 用户在单元画布明确应用承接时，同步建立首帧、素材来源及依赖；首帧已占用时不得自动退为主体参考。
- [ ] 已有首帧时展示原图和拟用图片，明确替换才更新；取消保留原图片与依赖关系，整次应用可以按已有编辑机制撤销。
- [ ] 本期场次工作台的新承接操作每单元只选一个前段；从 A 改为 B 时明确替换，并同时更新首帧和依赖，不留下两个生效承接。
- [ ] 约束限于场次工作台及对应服务边界；读取及无关编辑不自动删减既有多前段，重新配置时要求明确选择保留的来源。
- [ ] 历史来源同样展示原身份和已有占用，不绕过冲突追加承接；不扩大修改共用依赖契约或旧生产入口，不重写固定历史。
- [ ] 卡片标明承接片段，可定位原片段及取帧依据；源片段、采用区间或相关依据变化按现有规则失效或待复核，不自动换图。
- [ ] 移除承接图片时，清除依赖中的实际落幅及参考绑定，保留声明并回到待绑定；允许保存合法未齐备配置，生成继续受原硬门槛阻塞。
- [ ] 将承接首帧换成无关图片前说明依赖影响；应用后新图只是普通首帧，原依赖清除落幅与参考绑定并待绑定，不继续显示承接有效。
- [ ] 明确“移除前段依赖”才删除目标声明；普通解绑不删除原媒体、取帧记录或其他独立配置。
- [ ] 非法或伪造来源、文件不符、失效落幅和版本冲突不得形成部分保存；只影响相关单元，不错误阻断其他独立单元。
- [ ] 完成浏览器和场次 HTTP 状态转换、事务及异常输入验证，以及受影响类型检查、后端检查、契约与文档同步。

## Validation

- 复用末帧提取、前段依赖及保存事务用例，验证选取、替换、取消、撤销、移除图片、换普通首帧、重新绑定和明确取消依赖的可观察状态。
- 用已有多前段及历史来源夹具核对无关保存不会清理数据；使用伪造或不匹配证据验证请求失败后原内容仍完整。
- 复用 03 的首帧传递路径，确认承接所得图片确实以首帧角色进入固定任务输入；不新增中间关键帧、任意位置取帧或新首帧提取能力。
