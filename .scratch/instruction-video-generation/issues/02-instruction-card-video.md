# 02: 当前指令卡完成检查与视频生成

**What to build:** 用户在当前指令卡核对执行上下文，完成依据核对、检查、明确确认和视频提交；纯提示词输入能够经过固定任务、供应商请求及输出保存形成候选。

**Blocked by:** None

**Status:** ready-for-agent

**Spec:** [AI 指令起草与参考媒体视频生成链路](../spec.md)，实施决策 4、8、10；验收 A04、A15 的纯提示词路径，以及有关的 A16、A17、A19、A20。

## Acceptance criteria

- [ ] 当前指令卡集中提供修改指令、发起检查、查看并确认结果、生成视频和任务状态入口，明确作用于当前单元。
- [ ] 卡片展示指令摘要、模型、时长、画幅、参考数量和检查状态；详细报告在检查工作区阅读，缺项能定位到原单元配置。
- [ ] 准备缺项、依据已变、检查待查看或确认、任务执行中和提交待核实分别表达，动作按现有状态显示及禁用。
- [ ] 现有准备、指令依据确认、六岗审稿及视频执行硬门槛保留；指令或相关输入失配后，旧检查不能授权新生成。
- [ ] 从已有当前指令即可完成本票流程，不以 01 的新 AI 起草入口作为实现前置。
- [ ] 纯提示词路径从场次保存内容、视频准备、固定任务输入到实际供应商请求，指令、模型及生成参数一致，不凭当前最新单元覆盖已提交输入。
- [ ] 受控供应商响应经过真实结果保存与候选登记流程；输出保存未完成前不报告可用候选，不自动加入时间线。
- [ ] 单次、保存并生成、批量、预检、取消、原请求核实及原依据重试保持原有规则；检查通过不自动提交视频。
- [ ] 键盘、只读、窄屏及任务期间继续编辑保持可用；当前单元的阻塞不错误限制其他独立单元。
- [ ] 完成相应浏览器、场次 HTTP 和供应商请求验证，以及受影响的类型检查、后端检查和契约、文档同步。

## Validation

- 复用当前指令检查、视频提交和任务恢复先例，通过真实界面及场次接口验证检查、确认、提交的先后条件。
- 在外部供应商传输边界使用受控响应，核对实际发出的纯提示词请求；输出使用有效媒体夹具并核对候选记录。
- 候选库的主动刷新及查看定位由 07 负责，真实供应商生成验收由 08 汇总完成。
