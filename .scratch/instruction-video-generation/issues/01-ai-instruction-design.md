# 01: AI 设计起草、预览与应用指令

**What to build:** 用户从单元画布进入同一单元的指令画布，通过顶部“AI 设计”完成整体或选段起草、预览差异、明确应用和后续修改，已有内容及未保存工作受到保护。

**Blocked by:** None

**Status:** ready-for-agent

**Spec:** [AI 指令起草与参考媒体视频生成链路](../spec.md)，实施决策 1–3、10；验收 A01、A02、A03，以及本流程涉及的 A19、A20。

## Acceptance criteria

- [ ] 单元画布直接起草指令的快捷入口改为“进入指令画布”；保留明确选中的同一单元及当前编辑内容，导航不提交任务、不创建对象。
- [ ] 准备未齐也能进入查看，实际起草继续执行原有硬门槛；单元画布自身的 AI 设计继续负责组织生产单元。
- [ ] 指令画布顶部固定“AI 设计”，工作区明确当前单元、整体或选段范围及可选要求；要求留空时仍可使用已准备的资料起草。
- [ ] 打开工作区不提交任务，点击“生成指令”才提交；现有设计、执行范围、风格、参数及参考绑定信息按原规则进入固定输入。
- [ ] 建议和差异先预览，明确应用后才成为当前指令；重新起草在应用前保留原指令，应用后返回画布并可继续修改。
- [ ] 整体和选段修订保留正确范围；生成期间指令、相关依据或版本变化时，旧建议不能覆盖新内容。
- [ ] 使用“修改指令”等明确文案，章节原文继续由项目工作台维护；不新增视频模型专属提示词策略或图片、视频理解能力。
- [ ] 保留应用撤销、任务恢复和原请求核实；用户已离开工作区时，任务完成只提示并提供返回入口，不抢占位置。
- [ ] 键盘、只读、窄屏、焦点恢复和弹窗开合符合工作台约定，未保存内容及画布视口不因浏览丢失。
- [ ] 完成对应浏览器及场次 HTTP 回归、受影响类型检查和必要的契约与文档同步。

## Validation

- 复用指令建议、局部修订和工作台导航用例，通过真实浏览器连接测试后端验证提交、预览、应用、取消和撤销。
- 核对保存后内容、实际请求次数及单元隔离，包含起草前准备不足、可选要求为空、任务期间继续编辑和离开页面的场景。
- 本票覆盖指令形成流程；当前指令卡的检查及视频动作由 02 负责。
