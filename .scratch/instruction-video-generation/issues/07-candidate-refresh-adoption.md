# 07: 生成候选及时刷新与明确采用

**What to build:** 视频输出成功保存后，用户能及时在编辑画布看到并明确定位新候选，核对固定生成依据并自主采用；后台完成、重复通知及当前输入变化不会改动既有剪辑。

**Blocked by:** None

**Status:** ready-for-agent

**Spec:** [AI 指令起草与参考媒体视频生成链路](../spec.md)，实施决策 9、10；验收 A17、A18、A19，以及有关的 A20。

## Acceptance criteria

- [ ] 输出媒体成功保存并完成候选登记后，刷新候选库及受影响编辑画布读模型；用户已经停留在编辑画布也能看到新候选，无需重新进入页面。
- [ ] 创建任务、获得供应商任务编号或仅报告完成不能提前显示为可用候选；文件保存未完成、失败或取消沿用原有真实状态。
- [ ] 提供明确“查看候选视频”入口并定位实际结果，后台完成不自动跳转、不抢占当前单元或工作位置。
- [ ] 生成成功只登记 Take；不自动插入时间线、替换已采用片段、登记实际覆盖或生成审片通过结论。
- [ ] 候选保留原场次、版本、单元、任务、指令和固定媒体输入；运行期间相关输入变化时，正确显示旧依据候选并可查看原依据。
- [ ] 刷新只更新有关读取数据，不覆盖当前未保存剪辑、参考配置或其他编辑内容。
- [ ] 重复完成通知、重复读取和恢复不重复登记候选，也不重复提交视频任务；原请求核实及原依据重试保持原行为。
- [ ] 新结果读取失败时显示可恢复错误并保留已知内容，不误报没有候选或以重新生成代替重试读取。
- [ ] 候选能播放有效媒体，并通过既有明确采用流程加入指定真实区间；采用前时间线保持原内容。
- [ ] 完成结果保存与登记、编辑画布浏览器、幂等及异常恢复测试，以及受影响检查、契约和文档同步。

## Validation

- 使用既有视频任务及有效媒体夹具触发保存完成，验证用户在编辑画布和其他画布两种位置下的刷新与明确回跳。
- 结合场次 HTTP、任务完成和真实浏览器流程，核对候选身份、固定输入、时间线及未保存编辑；覆盖重复通知和读取失败恢复。
- 本票可通过现有任务入口独立验证，不依赖新的 AI 起草、指令卡或参考选择入口。真实生成结果由 08 做整体验收。
