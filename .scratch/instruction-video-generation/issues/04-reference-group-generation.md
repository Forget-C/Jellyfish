# 04: 参考组按组编辑并进入视频生成

**What to build:** 用户按参考组准备本次素材，在一张卡中查看同组多图及对象、用途和来源，局部编辑目标组，并将同组图片作为同一主体完整传入视频模型。

**Blocked by:** None

**Status:** ready-for-agent

**Spec:** [AI 指令起草与参考媒体视频生成链路](../spec.md)，实施决策 5、6、8、10；验收 A05、A06 的参考组部分，A08、A09、A15 的主体参考路径，以及有关的 A16、A17、A20。

## Acceptance criteria

- [ ] 普通参考按组展示卡片，同组多图保留在同一卡中，展示对应人物／物件或用途、缩略图、数量、来源及可用状态。
- [ ] 未选参考时提供添加入口；候选或默认资产不自动产生实际绑定，明确应用后才显示该组到单元的输入关系。
- [ ] 后端图投影提供稳定的参考组身份及编辑目标，当前编辑预览和保存后的关系一致。
- [ ] 从组卡进入编辑只管理该组图片、参与对象及用途，应用不覆盖其他组、其他单元或首尾帧。
- [ ] 应用一次更新并可撤销；取消、关闭或相关内容并发变化不会丢失原组或留下半组替换。
- [ ] 继续遵守既有身份主体的一对象一组、单一来源和同组多图规则；其他用途沿用自身约束，不把身份主体规则扩大到所有参考。
- [ ] 用途、对应对象、来源和输入归属分别表达并可查看，不新增平行的对象关联配置或图片识别推断。
- [ ] 从场次保存到固定任务及供应商请求，主体身份、组内图片、顺序及类型一致；同组多图仍作为同一主体输入，不按图片数拆成多个主体。
- [ ] 运行期间修改参考组不影响已提交任务；文件不可访问、归属不符、组不合法或模型不支持时明确阻止执行，不静默裁剪或改变生成模式。
- [ ] 完成相应图契约、浏览器、场次 HTTP 和供应商请求验证，以及类型检查、后端检查、必要契约及文档同步。

## Validation

- 复用参考来源和身份主体分组先例，以真实浏览器操作多组、多图和更换来源，核对保存结果及非目标输入不变。
- 使用可区分媒体，经真实任务执行和媒体读取，在受控供应商请求中核对主体及图片归组；覆盖非法来源、对象和能力组合。
- 本票可沿用现有生成入口独立验证，不依赖 01、02 或 03 的界面完成。真实供应商验收由 08 汇总。
