# 08: 四种模式真实生成与整体验收

**What to build:** 在前置功能集成后，完成从 AI 起草、输入准备、检查确认、视频生成到候选查看及明确采用的整条用户流程；四种基础模式均有真实可播放结果和可追溯证据。

**Blocked by:** 01 — AI 设计起草、预览与应用指令；02 — 当前指令卡完成检查与视频生成；05 — 实际落幅承接与依赖状态一致；06 — 指令画布只读输入核对与回跳；07 — 生成候选及时刷新与明确采用

**Status:** ready-for-agent

**Spec:** [AI 指令起草与参考媒体视频生成链路](../spec.md)，完整规格，尤其是 A01–A20、四种模式真实生成验收及检查与完成要求。

## Acceptance criteria

- [ ] 确认 01–07 的交付及各自测试证据齐备；03、04 已由 05、06 的依赖链覆盖，不将前置功能的基本测试延后至本票才执行。
- [ ] 完成集成流程：同一单元进入指令画布 → AI 设计起草 → 预览 → 明确应用及必要修改 → 按现有门槛核对检查 → 当前指令卡生成 → 查看候选 → 明确采用。
- [ ] 纯提示词使用当前接入且支持该模式的真实模型完成生成，固定指令和参数可核对，输出已保存且可播放。
- [ ] 提示词加首帧使用真实首帧图片完成生成，核对绑定、真实媒体传递及首帧位置，输出已保存且可播放。
- [ ] 提示词加首尾帧完成真实生成，核对两个位置各自的图片及顺序，输出已保存且可播放。
- [ ] 提示词加主体参考图完成真实生成，核对主体身份、分组及同组多图传递，输出已保存且可播放。
- [ ] 每种模式记录供应商和模型、任务身份、非敏感固定输入依据、候选媒体及播放核查结果，证据中不包含凭证。
- [ ] 每种模式的候选均及时可见、来源可追溯，查看不会自动采用；通过既有明确采用流程确认真实区间能进入编辑。
- [ ] 验证跨功能组合：参考或首帧变化使旧依据按原规则失配，前段解除绑定仍阻塞生成，只读输入回跳正确，运行期间修改不会改写固定任务输入。
- [ ] 对照 A01–A20 核对已有证据；修复集成中发现的本规格范围内缺口并补充对应回归，只因相关改动或新问题重跑已通过检查。
- [ ] 完成影响范围内的类型、后端、浏览器、桌面及窄屏检查；对外契约与客户端、受影响架构事实、操作说明和现有计划进度保持一致。
- [ ] 如某模式真实调用不可用、失败或尚未执行，明确记录该模式及原因并保持此项未完成；受控替身、夹具视频或供应商任务编号不能代替真实生成证据。

## Validation

- 复用前置票据的自动化结果，并以真实模型结果验证四种模式；分别选择当前实际支持相应模式的模型，不要求同一模型覆盖所有模式。
- 保留一份逐模式验收记录和可访问结果，能由任务、固定输入追溯至候选及人工采用区间；区分自动化通过与真实调用通过。
- 验收集中在实际输入传递和可播放生成链路，素材是否覆盖计划及接缝是否合格仍遵循已有人工审片规则。
- 本票不扩大到模型专属提示词优化、图片理解、中间关键帧、任意模式混用、新供应商或旧生产体系重构。
