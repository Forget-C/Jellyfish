# AI 指令起草与参考媒体视频生成链路

Status: ready-for-agent

日期：2026-10-22

本规格汇总本轮已经确认的产品决策和代码核查结果。用户已确认测试边界：复用真实浏览器连接测试后端的工作台流程，以及场次 HTTP、临时数据库和任务执行流程；在外部供应商请求边界核对实际媒体内容和输入位置。四种输入模式的真实生成并可播放作为独立验收要求。规格发布表示可以进入任务拆分与实现，不表示应用代码已修改、测试已通过或真实生成已验收。

## Problem Statement

用户已经在场次设计和生产单元中准备了动作范围、人物、空间、摄影、连续性及生成参数，希望据此形成视频指令，尽量减少从空白开始手写和反复补充。项目已有 AI 指令起草、局部修订、建议预览与应用能力，但入口和操作分散，单元画布直接起草指令，指令画布的编辑、检查和生成职责不够集中。

参考媒体已有从单元配置进入视频任务及供应商请求的实现基础。当前参考卡和选择器仍将不同输入混在一起，首帧、尾帧和主体参考的输入位置、使用目的、对应对象及文件来源不够直观。按文件去重的选择交互还限制了同一图片独立用于首尾帧。用户需要能明确选择、查看和修改本次实际输入，并知道哪些图只是候选、哪些图确实会送入模型。

前段承接也存在需要调整的行为：首帧已被占用时，当前绑定可能退为主体参考；移除图片后可能留下悬空依赖。现有依赖列表可以包含多个前段，但新的“实际落幅作为首帧”流程只有一个首帧位置，需要明确选择和替换规则，同时保留已有记录。

视频生成后，用户需要在编辑画布及时看到候选及其真实来源，自己决定是否采用。任务成功、文件保存、候选登记和剪辑采用必须分别表达。只验证页面有图片或任务已创建，不能证明实际媒体已传到供应商并产出可播放视频。

## Solution

以现有 AI 起草能力作为形成指令的主流程：准备单元 → 进入指令画布 → 点击顶部“AI 设计” → 明确提交生成 → 预览建议和差异 → 用户应用 → 必要时修改指令 → 按现有规则核对依据、审稿及确认 → 从当前指令卡生成视频。

单元画布统一配置本次执行范围、模型、时长、画幅、首尾帧、参考组和前段依赖。首帧与尾帧各有独立卡片，普通参考按组展示；选入并应用后自动显示输入关系，不通过拖线创建绑定。指令画布用一张只读“本次输入”卡分区展示这些内容，修改时返回同一单元并定位原卡片。

本期场次工作台的新承接操作只选择一个前段，将已采用真实片段所选区间的实际落幅作为当前单元首帧。替换来源时明确更新首帧和依赖；移除承接图片或换成无关图片时，保留依赖声明并回到待绑定状态。已有多前段记录不自动删减。

补齐并验证实际媒体传递及生成完成后的候选刷新。成功保存的视频登记为候选，保留固定生成依据，用户明确进入查看并决定采用。现有 AI 起草、准备、指令依据、六岗审稿及生成硬门槛保持原状。

成功标准：

- 已有设计和单元信息可以通过 AI 设计工作区形成可预览、可应用、可修改的指令，不要求用户先手写完整指令；可选要求仍可留空。
- 页面职责、当前单元、操作作用范围、实际媒体输入和来源关系清晰，导航或浏览不会产生生成任务或应用建议。
- 首帧、尾帧及参考组可以独立配置；替换、取消、撤销、依赖解除绑定和历史数据处理均保持一致。
- 本次选定的指令、媒体、输入角色和主体组完整进入固定任务输入及供应商实际请求，不静默遗漏或改变语义。
- 纯提示词、提示词加首帧、提示词加首尾帧、提示词加主体参考图四种模式均完成真实生成，并有可播放、来源可追溯的候选视频。
- 候选完成后及时出现在编辑画布；不自动跳转、不自动加入时间线、不自动替换已采用片段。

## User Stories

1. 作为场次创作者，我希望继续在导演画布维护设计意图，以便设计信息有明确归属。
2. 作为场次创作者，我希望章节原文继续在项目工作台维护，以便修改指令不会改动故事正文。
3. 作为准备拍摄的用户，我希望在单元画布配置本次动作范围和生成参数，以便拍摄输入集中可查。
4. 作为准备拍摄的用户，我希望通过“进入指令画布”继续处理同一单元，以便不必重新寻找工作对象。
5. 作为准备拍摄的用户，我希望准备尚未齐备也可以进入指令画布查看，以便理解还需要补充什么。
6. 作为用户，我希望进入画布、打开弹窗或查看输入不会提交生成任务，以便浏览和执行明确分开。
7. 作为场次创作者，我希望单元画布的 AI 设计继续负责组织生产单元，以便已有能力不因指令入口调整而丢失。
8. 作为起草指令的用户，我希望指令画布顶部提供一致的“AI 设计”入口，以便沿用其他画布的操作习惯。
9. 作为起草指令的用户，我希望工作区明确显示当前单元、修改范围和可选要求，以便知道建议针对什么内容。
10. 作为起草指令的用户，我希望无需手写完整提示词也能基于已有资料起草，以便减少重复输入。
11. 作为起草指令的用户，我希望点击“生成指令”后才发起任务，以便先核对目标和输入。
12. 作为起草指令的用户，我希望先看到建议和差异，再决定是否应用，以便保留对当前指令的控制。
13. 作为起草指令的用户，我希望重新起草时保留当前指令，直到我明确应用新建议，以便尝试不会覆盖已有工作。
14. 作为修改指令的用户，我希望继续支持整体及选段修订，以便只调整需要改变的内容。
15. 作为修改指令的用户，我希望应用后仍能修改和撤销，以便对建议作必要调整。
16. 作为用户，我希望建议生成期间发生的指令或依据变化受到应用保护，以便旧建议不会覆盖新编辑。
17. 作为用户，我希望离开 AI 工作区后任务完成只提示结果，以便后台任务不抢占当前位置。
18. 作为准备生成的用户，我希望在当前指令卡找到修改、检查、确认和生成入口，以便下一步明确可达。
19. 作为准备生成的用户，我希望卡片同时显示模型、时长、画幅、参考数量和检查状态，以便核对执行上下文。
20. 作为准备生成的用户，我希望详细审稿报告在专属工作区查看，以便卡面保持清晰。
21. 作为准备生成的用户，我希望准备缺项能定位回单元具体配置，以便直接补齐问题。
22. 作为用户，我希望修改指令或相关输入后继续遵守原有核对和审稿规则，以便旧检查不会错误授权新输入。
23. 作为选择素材的用户，我希望首帧和尾帧分别显示独立卡片，以便清楚约束的是起始还是结束画面。
24. 作为选择素材的用户，我希望同组多张参考图放在同一卡内，以便理解它们共同描述的对象或用途。
25. 作为选择素材的用户，我希望未选素材时看到添加入口，以便空态不会被误认为已经绑定。
26. 作为选择素材的用户，我希望明确应用后才建立输入连线，以便连线反映真实选择。
27. 作为查看画布的用户，我希望连线说明输入归属、卡片说明对应对象和素材来源，以便不同关系不被混淆。
28. 作为选择素材的用户，我希望用途和输入位置分别表达，以便“连续性”不会被误当成“首帧”等位置。
29. 作为选择素材的用户，我希望能从已有图片或上传图片中选择首尾帧，以便复用已准备素材。
30. 作为选择素材的用户，我希望同一图片可以分别绑定首帧和尾帧，以便在模型支持时复用同一画面。
31. 作为选择素材的用户，我希望更换一处绑定不会改动另一处，以便两个输入位置保持独立。
32. 作为选择素材的用户，我希望从某张卡进入编辑时只修改该卡的内容，以便局部操作不会覆盖其他参考。
33. 作为选择素材的用户，我希望首尾帧选择器固定输入位置，参考组选择器只管理该组，以便不会误改其他用途。
34. 作为选择素材的用户，我希望应用一次更新且可以撤销，取消保留原绑定，以便修改具有明确边界。
35. 作为选择素材的用户，我希望模型不支持某种输入时说明原因，以便系统不会悄悄换成主体参考或丢图。
36. 作为选择素材的用户，我希望原有身份主体分组和来源规则继续有效，以便多图仍被正确传为同一主体。
37. 作为审阅指令的用户，我希望在只读输入卡同时看到首帧、尾帧和参考组，以便核对本次实际素材。
38. 作为审阅指令的用户，我希望查看大图和来源，并能回到同一单元的对应卡片修改，以便不用重复寻找。
39. 作为剪辑者，我希望从已保存、已采用的真实片段区间提取实际末帧，以便承接依据来自真实使用的画面。
40. 作为准备承接的用户，我希望选取实际落幅时同时建立首帧、来源和依赖，以便不会留下只有图片或只有关系的半完成绑定。
41. 作为准备承接的用户，我希望首帧已存在时先比较原图和拟用图片，再明确替换，以便不会被直接覆盖。
42. 作为准备承接的用户，我希望本期新承接操作只选择一个前段，以便它与唯一首帧位置一致。
43. 作为准备承接的用户，我希望选择其他前段时明确替换原来源，以便不会产生无法同时满足的多个首帧依赖。
44. 作为已有内容的用户，我希望多前段记录保留原状，重新配置时由我选择保留项，以便系统不会自动删减历史配置。
45. 作为准备承接的用户，我希望卡片标明承接片段并能定位取帧依据，以便核对首帧从何而来。
46. 作为准备承接的用户，我希望移除承接图片后依赖回到待绑定状态，以便图片移除不会默默取消连续性要求。
47. 作为准备承接的用户，我希望换成无关图片后该图只作为普通首帧，以便它不会冒充前段的实际落幅。
48. 作为准备承接的用户，我希望应用上述替换前看到依赖影响，以便可以选择重新绑定或明确移除依赖。
49. 作为准备拍摄的用户，我希望未齐备但合法的配置可以保存，而生成仍受硬门槛约束，以便准备过程可以逐步完成。
50. 作为素材使用者，我希望普通解绑不删除原媒体或取帧记录，以便其他引用和历史依据保持可用。
51. 作为生成视频的用户，我希望实际选定的媒体内容及其角色进入模型请求，以便页面选择真实影响生成。
52. 作为生成视频的用户，我希望任务固定提交时的指令和媒体输入，以便后续编辑不会改写正在运行的任务。
53. 作为生成视频的用户，我希望不支持的组合、缺失文件和失效依赖明确阻止执行，以便不会被自动降级成另一种生成方式。
54. 作为生成视频的用户，我希望四种基础模式各有真实可播放结果，以便确认生成链路完整可用。
55. 作为剪辑者，我希望媒体成功保存后候选库及时刷新，以便无需重新进入页面才能看到结果。
56. 作为剪辑者，我希望通过明确入口查看新候选，以便后台完成不打断当前操作。
57. 作为剪辑者，我希望视频成功只登记候选，由我决定是否采用，以便任务状态不会代替剪辑判断。
58. 作为剪辑者，我希望输入已经变化时看到旧依据候选标识及原生成信息，以便正确判断结果适用性。
59. 作为用户，我希望原请求核实、取消、批量处理和原依据重试继续可用，以便入口调整不破坏任务恢复能力。
60. 作为键盘或窄屏用户，我希望新增卡片、弹窗和返回定位遵守已有工作台交互，以便完成相同流程。

## Implementation Decisions

### 1. 范围与复用边界

- 本次涉及单元画布、指令画布、编辑画布候选刷新，以及场次参考、依赖和视频生成服务；导演画布和项目工作台保留现有职责，不借此重做设计编辑。
- 复用现有 AI 指令起草、局部修订、预览差异、应用保护、撤销、依据确认和六岗审稿能力；不另建一套提示词生成系统。
- 复用现有单元参考、文件、实际落幅、依赖、固定任务输入和 Take 契约。已有视频媒体传递链路作为基线，修复本期需要的缺口，不整体替换生成基础设施。
- 页面显示的“指令”是生产单元执行文本。统一使用“修改指令”等明确名称，不把章节原文编辑迁入指令画布。
- 仅修复本规格涉及的实现；不恢复已移除的旧镜头生成入口，不重构无关旧生产流程。

### 2. 画布职责与导航

| 所在位置 | 本期职责 |
| --- | --- |
| 项目工作台 | 章节原文、项目资产与项目风格 |
| 导演画布 | 动作、人物、空间、摄影、连续性等设计意图 |
| 单元画布 | 本次覆盖范围、模型、时长、画幅、首尾帧、参考组和前段依赖 |
| 指令画布 | AI 起草与应用、修改指令、输入核对、检查及视频生成 |
| 编辑画布 | 候选浏览、人工采用、实际片段和已采用区间末帧提取 |

- 单元画布原有直接起草指令的快捷操作替换为“进入指令画布”。导航携带同一个明确单元及当前编辑内容，不提交任务、不自动应用、不自动创建对象。
- 准备不齐不阻止进入查看；实际 AI 起草、检查和生成仍按原条件判断。缺项入口回到原单元具体配置。
- 单元画布自己的“AI 设计”继续负责生产单元组织。切换画布保留当前有效单元和未保存工作；没有有效选择时沿用既有明确选择与空态规则。

### 3. AI 指令设计与应用

- 指令画布顶部固定“AI 设计”，沿用工作台已有 AI 设计弹窗和工作区模式，明确目标单元、整体或选段范围及可选要求。
- 打开工作区只是浏览；用户点击“生成指令”才提交任务。用户要求可留空，起草使用已有设计、动作范围、适用约束、风格、单元参数及参考绑定信息。
- 指令 AI 继续使用已有文本与结构化资料，不新增图片或视频理解，也不根据未实际读取的画面编造视觉事实。实际图片传给视频模型的链路独立保留。
- 结果先展示建议和差异，用户明确应用后才成为当前指令；查看或任务成功不自动应用。应用后返回画布，可继续修改。
- 重新起草在应用前保留原指令；既有整体与选段修订、原文及依据匹配、版本冲突防护、恢复和撤销行为继续生效。
- 用户仍在原工作区时展示结果；已关闭或离开时只提示并提供明确返回入口，不抢占位置或覆盖新编辑。

### 4. 当前指令卡与执行门槛

- 当前指令卡是生成视频动作的触发载体，展示指令摘要、模型、时长、画幅、参考数量、检查状态和任务状态。
- 提供修改指令、发起检查、查看并确认检查结果、生成视频及查看任务入口；各动作按既有状态显示和禁用。详细报告继续在检查工作区查看。
- 准备缺项、依据已变、建议待应用、检查待查看或确认、任务进行中及提交待核实分别表达，不用一个始终可点的生成按钮替代状态判断。
- 保留 AI 起草、准备检查、指令依据确认、六岗审稿及视频执行的现有硬门槛。修改指令或有关输入造成失配时，按现有规则重新核对、检查与确认。
- 保留单次、保存并生成、批量、预检、取消、原请求核实及原依据重试的授权与恢复规则；检查通过不自动提交视频任务。

### 5. 参考卡片、对象与来源关系

- 单元画布的首帧参考和尾帧参考各为一张独立卡片；普通参考按组展示，同组多图留在一张卡中。
- 首尾帧卡展示缩略图、起始／结束画面标识、来源和可用状态；参考组卡展示对应人物／物件或用途、缩略图、数量和可用状态。
- 未选择时显示添加入口，不画已建立的输入关系。只有明确选入并应用的素材才成为本次输入；默认资产候选不自动成为参考。
- 卡片至单元的连线表达输入归属，并标明首帧、尾帧或用途；对应人物／物件和素材来源在卡内分别标注并可查看。三种关系不混用。
- 首尾帧是输入位置，身份、空间、构图、连续性等是使用目的；沿用各自字段语义，不新增模糊的通用分类替代它们。
- 连线自动展示和定位，本期不支持拖线创建或断线删除。业务关系仍由后端画布图投影提供，当前编辑沿用已有预览机制，不在前端另建拓扑事实。

### 6. 参考编辑与模型能力

- “选择首帧”“选择尾帧”“添加参考组”进入相应素材选择；首尾帧支持已有图片和上传图片。来源选择及实际文件的项目归属与可用性沿用原规则。
- 从某张卡进入编辑，只能更新该卡对应的输入。首尾帧选择器固定输入位置；参考组选择器只管理该组图片、参与对象及用途。
- 明确应用才一次更新目标内容，并形成可撤销的一次编辑；取消保留原绑定，弹窗期间发生的相关变化继续由已有冲突保护处理。
- 同一图片允许分别绑定首帧和尾帧，共享原文件但拥有独立绑定；更换或移除一个位置不影响另一个位置。不能以全单元文件去重误删另一位置。
- 继续遵守既有身份主体的一对象一组、单一来源及同组多图等规则，不把首尾帧或其他用途套入身份组限制，也不新增平行的对象关联配置。
- 按实际模型能力校验输入位置、数量及模式。卡片独立展示不表示允许主体参考与首尾帧混用；不支持时说明原因，不自动换角色、不静默丢图或降级。
- 指令画布提供一张只读“本次输入”聚合卡，按首帧、尾帧和参考组分区展示。首尾帧显示来源、承接对象及可用状态；参考组显示对象或用途、缩略图和数量。
- 点击图片查看大图；“修改”导航至同一单元并定位对应卡片。聚合卡连到当前指令卡，说明本次媒体输入，不提供直接换图或拖线编辑。

### 7. 实际落幅与前段承接

- 继续只从已保存、已采用的真实片段所选媒体区间提取最后可解码画面，保留片段、源 Take、媒体区间、取帧时间及文件依据。选择其作为某次生成输入仍由用户在单元画布明确完成。
- “承接前段落幅”固定使用当前单元首帧位置，在同一编辑与保存操作中建立首帧、素材来源和前段依赖。不能在首帧已占用时退为主体参考。
- 已有首帧时展示原图与拟用图片，明确替换后才更新；取消保留原图和原关系。卡片标明“承接片段”并能定位原片段与取帧依据。
- 本期场次工作台的新承接操作每单元只选择一个前段，与唯一首帧位置一致。选择另一个前段时明确替换原来源，并同步替换相关首帧与依赖关系，不形成两个生效的首帧承接。
- 约束位于场次工作台及对应服务边界，不给共用依赖列表增加影响旧生产入口的全局数量限制。已有多前段配置保留原记录，读取及无关编辑不自动删减；重新配置首帧承接时，必须明确选择保留的来源，不能随意取第一项或同时追加。
- 对涉及历史来源的配置同样展示真实来源和已有占用，不绕过冲突追加承接。固定生成记录及原取帧记录不随当前选择被重写。

| 用户动作 | 当前首帧 | 前段依赖 |
| --- | --- | --- |
| 选定前段实际落幅并应用 | 使用该实际落幅 | 同时建立或完成对应绑定 |
| 明确将承接来源 A 换为 B | 替换为 B 的实际落幅 | 同步替换为 B 的依赖关系 |
| 取消绑定或替换操作 | 保持原样 | 保持原样 |
| 移除正在用于承接的首帧图片 | 移除该输入绑定 | 清除依赖中的落幅及参考绑定，保留声明并回到待绑定 |
| 将承接首帧换成无关图片 | 新图作为普通首帧 | 清除原落幅及参考绑定，保留原声明并回到待绑定 |
| 明确移除不再需要的前段依赖 | 不把移除声明扩展为媒体删除 | 删除目标依赖声明，不影响其他独立配置 |

- 换成无关图片的选择器在应用前说明依赖影响；不能凭一张新图片继续表示原前段承接有效。
- 待绑定配置允许保存，但不能消除现有准备和执行阻塞。用户须重新绑定有效落幅，或明确移除不再需要的依赖；移除图片不等于取消依赖。
- 普通解绑只影响当前单元，不删除原媒体文件或取帧记录。源片段、采用区间或相关依据变化继续沿用现有失效和待复核规则，不自动重新取帧或替换输入。

### 8. 视频媒体传递与固定输入

- 核对完整链路：单元参考配置 → 场次保存内容 → 视频准备结果 → 固定任务输入 → 执行时读取真实媒体 → 供应商请求 → 结果下载与保存 → 候选登记。
- 传递指令、模型与参数，以及媒体文件身份、类型、用途、输入角色、顺序、主体分组和必要来源。任务保留生成当时的输入，执行不能临时用当前最新单元替换。
- 供应商实际请求必须携带对应的真实媒体内容或该适配器要求的可读取媒体表示，不能仅发送内部文件标识、缩略图说明或文件名。
- 同图首尾帧保持两个输入位置；主体同组多图保持同一主体。适配器按已有供应商协议组装字段，不把输入位置和主体分组混用。
- 保留模型能力、媒体类型、数量、访问权限、项目归属、文件可用性、依赖有效性和参数约束。无效时报告可定位的问题，不静默删减媒体或改变生成模式。
- 本期验证四种基础模式：纯提示词、提示词加首帧、提示词加首尾帧、提示词加主体参考图。分别使用当前接入中实际支持该模式的模型，不要求单个模型支持全部模式。
- 暂不增加视频模型专属的提示词策略。不同供应商的请求格式和媒体能力继续由现有适配及能力规则处理。
- 通用生成输入、输出和供应商契约沿用统一契约层；任务层负责执行编排，供应商集成不反向依赖任务类型。场次业务状态由服务层和既有存储入口处理，接口层负责收参与响应。

### 9. 视频完成与编辑画布

- 媒体成功保存并完成候选登记后，及时刷新候选库及受影响的编辑画布读模型；用户已停留在编辑画布时，也应通过现有刷新机制看到新增候选。
- 任务创建、供应商返回任务编号或仅报告完成均不能提前冒充可用候选。沿用现有结果保存、幂等登记及失败恢复机制，避免重复 Take。
- 提供明确的“查看候选视频”入口，定位真实结果。后台完成不自动切画布，不改变用户当前工作目标、时间线或未保存编辑。
- 候选保留真实场次、版本、单元、任务、指令和固定媒体输入。运行期间相关输入已变时，显示为旧依据候选，不将其伪装为满足当前要求。
- 生成成功只登记 Take；不自动加入时间线，不替换已采用片段，不自动产生实际覆盖或素材审查结论。实际区间、采用及接缝复核继续在编辑流程明确处理。
- 新结果读取失败应显示真实加载或错误状态并可重试，不能把读取失败误报为没有候选，也不因此重复生成。

### 10. 契约同步、保存和工作台一致性

- 参考、首尾帧和依赖的编辑继续通过场次服务及既有存储入口，遵守版本、类型、项目归属和文件引用校验；不绕过校验直接写入持久化内容。
- 在现有读模型和选择器上增加必要的卡片身份、编辑目标及定位信息，避免复制一套独立的前端参考或依赖状态。后端保持业务图关系的权威来源。
- 若对外参数、响应、图契约或接口语义变化，同步后端、OpenAPI 和前端 generated client。前端继续使用生成客户端；仅内部调整且未改变对外契约时不要求无意义再生成。
- 继续使用当前自动或手动保存、未保存内容恢复、撤销和冲突处理机制。卡片拆分不改变这些保存边界，也不能让一个目标的局部应用覆盖其他单元。
- 复用工作台现有按钮、动作区、弹窗、详情、主题及图组件。保留键盘访问、焦点恢复、内层 Escape 优先、只读状态、窄屏可用性和画布视口稳定性。
- 任务中心继续只承载通用状态、进度、取消及业务回跳；指令、来源、媒体输入及详细诊断留在场次业务页面。
- 实现落地后同步受影响的架构事实、操作说明及现有计划进度；规格发布本身不把目标方案写成已经生效的架构事实。

## Testing Decisions

### 已确认的测试边界

1. **前端交互：真实浏览器连接测试后端。** 使用现有 Playwright、真实工作台组件、场次接口及隔离测试数据，操作用户可见的按钮、弹窗和画布。断言实际显示、请求是否发生、保存后内容和业务回跳，不能只检查组件是否渲染。验证导航、AI 设计、预览应用、按卡参考管理、承接状态、候选刷新和不自动采用。
2. **后端业务：场次 HTTP、临时数据库及任务执行。** 从场次接口提交和读取内容，验证真实服务、存储和事务行为；覆盖指令依据、检查门槛、引用及依赖一致性、固定任务输入、候选登记和幂等。业务服务和状态流转不由一组总是成功的替身代替。
3. **外部请求观察：供应商传输边界。** 复用现有受控 HTTP 响应方式，在实际组装并发出的请求上核对提示词、媒体内容、首尾帧位置和主体分组。使用可区分的媒体夹具，沿真实任务执行及媒体读取路径验证，避免仅手工构造适配器输入就宣称整条链路已通过。外部模型响应使用受控替身，文件读取使用隔离的测试存储；不因此修改产品对外接口。

以上复用现有业务边界，不为测试引入新的生产抽象或测试专用业务接口。已有契约和少量纯逻辑测试仅用于补齐异常组合；不按每个内部函数分别写与实现结构绑定的测试。

### 现有测试先例

- 指令建议和局部修订浏览器用例已有真实测试后端、单元隔离、固定输入查看、手工编辑保护、原请求核实与撤销流程，可调整入口并扩展 AI 设计工作区覆盖。
- 参考来源浏览器用例已有上传、项目资产、身份主体分组、明确应用及保存读取；前段依赖和末帧用例已有真实采用区间与来源定位，可扩展按卡操作及待绑定状态。
- 视频生成浏览器用例已有指令依据核对、六岗检查、明确确认、保存并提交和提交结果不明恢复；素材库及剪辑图用例已有候选读取、固定依据和人工采用。
- 场次指令 HTTP 用例已有单元范围和应用冲突验证；前段依赖 HTTP 用例已有未绑定仅阻塞对应单元及伪造证据拒绝；视频 HTTP 用例已有固定输入、幂等提交及只登记候选。
- 任务执行、媒体保存及供应商适配用例已有受控 HTTP 传输、结果归一化、输出保存和请求载荷断言。需将这些先例用于验证本次完整传递，不把分段通过等同于端到端已验收。

### 自动化验收矩阵

| 编号 | 行为 | 可观察结果 |
| --- | --- | --- |
| A01 | 当前单元准备未齐，点击“进入指令画布” | 同一单元及当前编辑保留；允许查看；没有起草或视频请求；原硬门槛仍在 |
| A02 | 打开 AI 设计、明确生成、查看建议、应用 | 打开不提交；明确生成才提交；预览不覆盖；应用后更新当前指令并可修改 |
| A03 | 整体及选段修订，任务期间指令或依据发生变化 | 保留非目标内容，旧建议不能覆盖新编辑；取消与撤销符合原规则 |
| A04 | 当前指令卡执行核对、检查、确认和生成 | 入口作用于当前单元；缺项可定位；未满足门槛不提交；详细报告可达 |
| A05 | 首帧、尾帧、参考组的空态及应用 | 卡片和输入归属正确；候选不产生绑定；应用后才有实际关系 |
| A06 | 按卡编辑、取消、撤销及并发变化 | 仅目标输入改变；取消保留原绑定；撤销恢复整次编辑；旧弹窗不覆盖新内容 |
| A07 | 同图分别绑定首尾帧并只替换其中一处 | 两份独立绑定可保存；另一处不受影响；请求中两个位置保留 |
| A08 | 主体参考组多图及对象、用途、来源展示 | 分组和来源满足原契约；同组作为同一主体传递；不误套首尾帧规则 |
| A09 | 模型不支持角色、数量或主体与帧的组合 | 明确提示原因并保留可定位的问题；不自动改角色、不丢图、不错误放行生成 |
| A10 | 从已采用区间提取实际落幅并承接 | 来源及区间可追溯；首帧和依赖同时更新；不退为主体参考 |
| A11 | 已有首帧或已有承接来源时选择新前段 | 应用前能核对原图与新图；明确替换后只保留本次选定承接；取消原样保留 |
| A12 | 移除承接图片或换成无关图片 | 清除原落幅及参考绑定，声明待绑定且可保存；无关图片只是普通首帧；生成仍受阻塞 |
| A13 | 明确移除不需要的依赖及读取既有多前段配置 | 不删除媒体或取帧记录；既有多前段不被自动裁剪；重新配置由用户明确选择 |
| A14 | 指令画布只读输入卡查看及修改回跳 | 首尾帧与参考组信息齐全；大图可查看；回到同一单元正确卡片；无直接换图行为 |
| A15 | 四种模式经过单元保存、任务固定输入及供应商请求 | 提示词和参数一致；真实图片内容、首尾帧位置、顺序和主体组完整一致 |
| A16 | 文件不可访问、跨项目引用、伪造落幅或失效依赖 | 在既有边界明确拒绝；无半次保存或错误供应商请求；其他独立单元不受无关阻塞 |
| A17 | 任务运行期间修改当前输入，随后成功保存输出 | 原任务使用固定输入；候选保留原依据并正确显示适用状态；未保存完成前不伪报可用 |
| A18 | 用户已在编辑画布时视频完成 | 候选库及时刷新；可明确定位新视频；不自动跳转、插入或替换时间线 |
| A19 | 重复通知、结果读取失败、提交未知、取消及重试 | 不重复登记或生成；错误可恢复；原请求核实与原依据重试保持原语义 |
| A20 | 键盘、只读、窄屏和详情开合 | 操作可达、焦点可见且关闭恢复；无横向溢出；无无关视口跳动或编辑丢失 |

对新增或修改的输入校验补齐异常用例，覆盖本次影响到的有效及无效组合；不为未改变的供应商或旧流程扩展无关矩阵。涉及播放的自动化用例使用有效媒体夹具，不能用任意字节冒充可播放视频。

### 四种模式的真实生成验收

| 模式 | 实际输入 | 必须保留的验收证据 |
| --- | --- | --- |
| 纯提示词 | 当前指令与合法生成参数 | 实际任务、固定指令与参数、保存的视频和播放结果 |
| 提示词加首帧 | 当前指令及明确的首帧图片 | 以上证据及首帧绑定、真实媒体传递和输入位置 |
| 提示词加首尾帧 | 当前指令及明确的首帧、尾帧 | 以上证据及两个位置各自的媒体与顺序 |
| 提示词加主体参考图 | 当前指令及合法主体参考组 | 以上证据及主体身份、分组和同组多图传递 |

- 各模式选择当前已接入且支持该模式的真实模型运行。记录模式、供应商及模型、任务身份、非敏感固定输入依据、候选媒体及播放核查结果；不得在证据中记录凭证。
- 每种模式都核对实际输入传递、输出保存、候选可见和来源可追溯，并验证查看候选不会自动采用。按既有明确采用流程确认结果可以用于编辑。
- 不要求任意模型、任意参考组合都通过，也不将模型输出自动判为计划已覆盖或接缝已合格；这些继续依赖原有审片判断。
- 真实调用不可用、失败或尚未执行时，明确记录未完成模式及原因。自动化通过、已有测试夹具视频或仅有供应商任务编号不能替代真实生成成功证据。

### 检查与完成要求

- 实现过程中运行受影响的前后端用例及对应浏览器场景；共享契约、任务基础设施或影响范围扩大时，扩展相关回归。相同代码和环境已通过的检查复用结果。
- 前端代码、类型或构建配置变化后执行 `pnpm --dir front run typecheck`，工作台交互按现有设计规范完成对应组件及桌面、窄屏验收。
- 后端代码变化后运行相关测试；Python 应用代码变化后，在后端目录执行 `uv run pylint app`。不能执行的必要检查必须记录，不能用无关检查代替。
- 对外契约变化时，从已确认加载本工作区改动的本地后端生成 OpenAPI 和前端客户端，并核对受影响调用；不从旧服务生成契约。
- 完成标准包括自动化行为验证、四种模式的真实生成证据和受影响文档同步。规格阶段不执行这些实现验收，也不提前标记完成。

## Out of Scope

- 将 AI 起草、准备、指令依据确认、六岗审稿或视频执行硬门槛改成建议；放宽批量、预检或原依据重试条件。
- 在指令画布修改章节原文，或重新设计导演画布的设计编辑及单元画布的生产组织能力。
- 让 AI 建议自动应用，或让导航、打开弹窗、检查完成自动提交视频。
- 新增视频模型专属提示词策略，新增指令 AI 的图片或视频理解，自动识别人脸或推断素材对应对象。
- 指定中间时刻的关键帧、新增首帧提取、未采用候选或任意播放位置取帧，以及主体参考与首尾帧任意混用。
- 拖线创建引用、断线删除引用或新增通用图编辑系统。
- 全局收紧旧生产依赖契约、自动删减已有多前段配置，或迁移、改写历史固定生成输入。
- 自动采用候选、自动替换时间线片段、自动登记实际覆盖，或新增一套剪辑与审片规则。
- 新增供应商、全面重写生成基础设施、建立新测试框架或整理无关既有代码。
