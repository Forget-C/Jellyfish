# 02: 草案审查与失败恢复

**What to build:** 首次及重新提取在应用前审查单镜可执行性和跨镜连续性，用户能看到阶段、问题及失败原因，并可从失败的审查阶段重试而不丢失草案。

**Blocked by:** 01

**Status:** ready-for-agent

Resolution: completed

- [x] 展示生成草案、审查及结果阶段，覆盖首次和重新提取；审查过程中不改已有画布，不新建独立 Agent 服务或画布版本。
- [x] 程序负责结构、出处和引用等确定性校验，模型负责景别、调度和前后态语义审查；报告包含涉及镜头、冲突要求及建议。
- [x] 区分执行失败、设计冲突和依据不足；未完成审查不显示通过，结构无效或引用损坏不能绕过，依据不足保持警告而不逐项强制确认。
- [x] 覆盖入场与无位移、中近景与头手双脚同框、无交代换手或换位；正常景别切换与对象出画不作为必然冲突。
- [x] 服务超时或无效响应时保存草案及失败状态，用户从审查阶段重试，不重新生成整套分镜；刷新后仍可恢复该流程。
- [x] 审查绑定输入内容，结果不能用于静默覆盖后续编辑；本票尚未提供风险接受时，未解决冲突保留待处理，不冒充通过。
- [x] 浏览器和公开接口使用固定正常、冲突、超时及无效响应，验证真实任务状态、草案持久化和重试；测试结论不冒充真实模型识别率。

验证边界：复用现有真实浏览器与服务端公开接口；仅替换外部 LLM 和媒体供应商响应，保留真实保存、引用校验、输入编译和任务状态。使用隔离数据，不以真实付费生成作为自动测试前提。
