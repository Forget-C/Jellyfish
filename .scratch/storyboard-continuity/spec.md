# 分镜设计连续性审查与视觉承接

Status: ready-for-agent
Resolution: completed
日期：2026-11-10
实施状态：12 张票据已实施并验收，集成分支为 `codex-storyboard-continuity`，最终代码为 `26af67ce`。
决策依据：本轮 grilling Q1—Q22 全部确认；to-spec 写入前已单独确认具体测试入口、替换边界及新增验证重点。

## Problem Statement

用户在同一场次中生成多个分镜视频，发现车辆、人车距离、人物姿态和构图在镜头之间无法衔接。当前共享设计文本可以进入生成输入，但每个镜头仍独立生成；“保持上一镜状态”没有指向上一镜实际产出的画面。分镜设计还可能同时要求人物入场与无位移，或要求中近景却必须展示头部、持棍手与双脚。

用户需要系统首先保证分镜设计自身成立，再允许明确采用前镜画面帮助后镜生产。正常景别和机位切换不应被误判为不连续，用户也不应因前镜尚未生成而无法制作后镜。对象参考不足及参考图未表达本场状态确实影响画面，但本轮暂缓处理。

## Solution

在原有工作台和共同画布中分两个阶段交付，阶段一独立验收，不依赖阶段二完成。

阶段一让系统先确定场次共同状态，再为各镜头表达继承状态、允许变化和结束状态。分镜草案应用前自动经过单镜可执行性与跨镜连续性审查；必要时进行一次定向修正和复核，未解决的问题由用户处理。已有画布可主动检查，不在打开时自动改写。

阶段二让用户从后镜视频卡的“视觉承接”入口，选择本画布更早镜头的成功视频结果和具体帧，确认用途后作为固定图片素材采用。连续动作可以推荐尾帧作首帧，切换景别则不默认这么处理。上游新结果只提示，不替换已采用画面，不自动触发媒体生成。

所有场次设计落在共同画布可编辑、可引用的既有卡片中。工作台承担审查与承接编排，共同基础仅补齐通用视频选帧、图片素材保存和来源记录能力。

## User Stories

1. 作为创作者，我希望先确定同一场次的共同状态，以便多个镜头具有一致的空间和动作依据。
2. 作为创作者，我希望每个镜头明确继承状态、允许变化和结束状态，以便理解镜头如何接续。
3. 作为创作者，我希望摄影机展示内容的变化不被解释成人物新动作，以便不把切到人物误写成人物入场。
4. 作为创作者，我希望对象出画后其场内状态仍被继承，以便后续镜头不会丢失车辆等背景对象的约束。
5. 作为完整分镜模式用户，我希望必要补充标为设计提议，以便区分原文事实与系统创作。
6. 作为忠实提取模式用户，我希望未写明的信息保留待定，以便系统不暗中补全调度。
7. 作为创作者，我希望系统不擅自增加剧情动作，以便尊重原文意图。
8. 作为创作者，我希望分镜草案在落卡前自动审查，以便不用额外手动触发首次检查。
9. 作为创作者，我希望看到提取、审查、修正和复核阶段，以便了解任务进展。
10. 作为创作者，我希望系统发现同一镜头的景别、动作与构图冲突，以便避免不可同时满足的指令。
11. 作为创作者，我希望系统发现相邻镜头未交代的换手、换位和状态跳变，以便提前修正连续性。
12. 作为创作者，我希望正常切换景别或对象暂时出画不被误报，以便保留正常剪辑表达。
13. 作为创作者，我希望设计冲突与依据不足分别显示，以便判断必须处理的问题与可接受的风险。
14. 作为创作者，我希望系统仅定向修改自己补充的设计，以便原文和人工要求不被覆盖。
15. 作为创作者，我希望两项人工要求冲突时由我取舍，以便保留创作决定权。
16. 作为创作者，我希望自动修正有明确次数上限，以便避免无休止的生成与重试。
17. 作为遇到审查执行失败的创作者，我希望保留草案并从审查阶段重试，以便不丢失已完成工作。
18. 作为创作者，我希望未完成审查不会显示通过，以便准确理解当前状态。
19. 作为创作者，我希望看到冲突涉及的镜头、要求和修正建议，以便作出可理解的选择。
20. 作为创作者，我希望可逐项接受仍存在的语义冲突，以便在知情情况下保留设计。
21. 作为创作者，我希望已接受的风险仍有提醒且不被标为通过，以便避免误以为冲突已经解决。
22. 作为创作者，我希望未变化的同一冲突不反复要求确认，以便减少重复操作。
23. 作为创作者，我希望新冲突和已变内容不能沿用旧风险确认，以便确认始终对应实际设计。
24. 作为创作者，我希望结构无效或引用损坏不能靠接受风险绕过，以便生成依据仍然有效。
25. 作为已有画布用户，我希望主动检查当前已保存的设计，以便无需重新提取即可发现问题。
26. 作为已有画布用户，我希望打开画布不自动检查、重排或改写，以便继续原有工作。
27. 作为创作者，我希望修正建议通过差异确认应用并可撤销，以便控制改动范围。
28. 作为并发编辑的创作者，我希望旧审查结果不能覆盖新设计，以便保护后续修改。
29. 作为整理布局的创作者，我希望移动卡片或调整堆叠不使语义审查失效，以便自由组织画布。
30. 作为制作后镜的创作者，我希望从该视频卡进入视觉承接浮层，以便无需切换页面。
31. 作为创作者，我希望默认推荐前镜且能选择本画布更早的镜头，以便选择合适的承接依据。
32. 作为创作者，我希望选择具体成功视频结果并定位一帧，以便明确实际采用内容。
33. 作为创作者，我希望连续动作与切换景别使用不同推荐方式，以便避免不必要的尾帧续拍。
34. 作为创作者，我希望用途对应模型真实支持的参考能力，以便采用不是仅在界面显示。
35. 作为创作者，我希望参考组合不兼容时明确选择保留或切换，以便不静默丢失已有主体输入。
36. 作为创作者，我希望确认选帧前不创建素材卡，以便预览不会污染画布。
37. 作为创作者，我希望采用的帧成为可查看、移动和复用的普通图片素材卡，以便继续自由编辑。
38. 作为创作者，我希望引用展示视频来源和时间位置，以便追溯并定位依据。
39. 作为创作者，我希望重复确认不产生重复素材，以便避免重复操作污染画布。
40. 作为创作者，我希望采用失败不留下部分连接或停用结果，以便原配置仍可使用。
41. 作为创作者，我希望一次撤销恢复本次新增画布内容和输入调整，以便方便反悔。
42. 作为创作者，我希望移除承接后素材卡保留，以便继续使用已选画面。
43. 作为创作者，我希望恢复旧主体参考前核对当前模型和配置，以便不覆盖后来修改。
44. 作为创作者，我希望上游生成新结果仅提示更新，以便固定采用不会静默变化。
45. 作为创作者，我希望重新采用后保留已有视频并提示依据已变，以便自行决定是否重新生成。
46. 作为创作者，我希望可以跳过视觉承接直接生成，以便前镜未完成不阻塞制作。
47. 作为重新提取的创作者，我希望人工建立的承接默认保留，以便不丢失选帧工作。
48. 作为创作者，我希望镜头被删除或变化时明确提示承接影响，以便关系不被迁移到其他镜头。
49. 作为创作者，我希望来源视频或卡片不可用后仍能使用已保存帧，以便固定依据不因来源导航失效而丢失。
50. 作为创作者，我希望选帧图片本身缺失时收到真实输入诊断，以便不误以为参考仍有效。
51. 作为普通生成画布用户，我希望动态连线、单卡生成和保存保持现状，以便专项能力不改变自由生成方式。

## Implementation Decisions

### 阶段一：共同状态与分镜审查（Q1—Q6、Q8—Q9）

- 复用现有提取、任务、候选结果、差异核对及应用流程；不建立独立 Agent 服务、画布版本或隐藏设计正文。
- 共同状态涵盖人物与道具位置、朝向、持物手、动作状态及摄影机轴线一侧。各镜头的继承、变化和结束状态由既有空间、站位、表演及连续性设计卡表达。
- 完整分镜模式可补充必要的空间和摄影提议，忠实提取模式缺项待定；两者均不能以衔接为由擅增剧情。背景对象即使不承担本镜叙事重点，也须保留必要连续性约束及采用关系。
- 结构与引用等确定性校验继续由程序负责；景别、调度、前后态等语义问题由模型审查。复用现有纠错能力组织流程，不因多层重试形成无限修正。
- 首次提取与重新提取均执行草案生成、审查、必要修正、复核、结果展示流程，处理期间不改已有画布。语义审查最多一次自动定向修正，随后复核；未消解问题交给用户。
- 修正限于系统补充设计，优先最小受影响范围，并复核相邻依赖。原文事实、用户已确认或人工修改的要求不能被自动覆盖。无法兼容的人工要求由用户选择。
- 区分执行失败、设计冲突和依据不足。执行失败保留草案并支持从审查重试；未完成不显示通过。语义冲突展示涉及镜头、冲突要求、建议，可定向修正或逐项明确接受风险后应用；结构无效与引用损坏不能绕过。依据不足保持警告，不逐项强制确认。
- 接受风险不等于审查通过。相关内容未变时复用具体冲突确认但持续提醒；内容或前后镜状态改变后重新判断，新冲突不能继承旧确认。

### 已有画布与并发保护（Q18、Q20—Q21）

- 工作台提供“检查分镜连续性”，针对当前已保存内容产生问题与修正建议；不要求重新提取。建议通过差异核对后应用并支持撤销。
- 打开已有画布不自动审查、重排或改写。检查结果绑定受检内容及相关依赖，设计变化后标记依据已变。
- 应用前核对相关内容与依赖，审查期间被编辑则旧结果过期，不能覆盖新设计，须重新检查。移动卡片与调整堆叠等纯布局变化不使语义结果过期；实际保存继续遵守共同画布并发保护。

### 阶段二：视觉承接入口与用途（Q7、Q10—Q11）

- 入口位于工作台后镜视频卡操作菜单，以浮层完成选择，不增加页面或视图。默认推荐前镜，可选本画布更早镜头的具体成功视频结果，预览拖动定位、选帧、选择用途后确认采用。
- 连续动作且机位适宜时可推荐尾帧作首帧；切换景别或机位时不默认选尾帧、不默认首帧用途。参考只提供视觉依据，不强制相邻画面重合。
- “连续性参考”必须映射为当前模型真实支持的参考用途，不能新建不参与执行的虚假用途。不可用时明确提示。
- 当前 Vidu 适配不允许主体与帧参考混用。采用首帧产生冲突时列出受影响参考，用户可保留主体参考并取消本次采用，或明确切换首帧并停用不兼容主体输入。仅调整该模型采用关系，保留参考卡与素材。
- 无视觉承接可提示一致性风险后继续用户明确发起的生成，不以未采用前镜画面作为统一阻断条件。系统推荐不构成选定结果、选帧或媒体执行授权。

### 固定素材、原子采用与恢复（Q12、Q14—Q16、Q22）

- 选帧预览不创建卡片。确认后抽取并保存独立图片文件，建立普通图片素材卡，记录具体来源视频文件、结果身份和时间位置。抽帧不调用生成模型。
- 卡面只展示简短来源，复用引用浮窗展示索引与定位；不增加重型来源内容。素材卡可独立查看、移动和复用。
- 同一次确认重复提交不重复创建素材；用户主动选另一帧属于新的采用操作。
- 创建素材卡、接入目标和停用冲突输入作为一次完整画布操作。抽帧或保存失败保持目标原状，不留下半完成连接；成功支持一次撤销恢复原采用关系及本次新增画布内容。撤销不删除历史视频或其他卡已使用的素材文件。
- 已采用帧固定到具体视频结果与时间位置；上游新成功结果只提示“来源镜头有新结果”，支持预览新旧并重新选帧或保持旧采用。更新提示不阻止生成。
- 重新采用仅更新后镜输入，已有视频保留并提示依据已变；不自动生成、不连锁更新后续镜头。
- 可从承接入口移除关系，保留素材卡。恢复曾停用的主体参考前核对当前模型、输入及配置，显示拟恢复项和冲突，由用户确认，不盲目恢复旧配置。
- 来源视频或卡片不可用时，独立选帧图片仍可采用。引用浮窗注明来源不可用，不允许失效的定位或重新选帧操作。图片本身缺失时按共同画布现有缺失输入规则诊断。

### 重新提取保护与职责边界（Q13、Q17）

- 人工选帧承接属于人工编辑，重新提取默认保留。接收镜头移除或设计变化影响承接时，在差异核对中明确提示，不静默迁移到另一个镜头。
- 来源镜头移除但固定帧仍可用时采用保持有效，提示来源已移除，不自动替换或删除素材。
- 共同基础仅获准补齐通用视频选帧、图片素材保存及视频来源与时间位置记录。复用既有图片内容卡、参考输入、固定成果、来源浮窗、保存与撤销机制。
- 镜头顺序、承接推荐、跨镜审查与固定承接的上游新结果提醒由工作台负责。普通生成画布动态连线不改为固定承接，单卡生成与自动保存不变，不接入旧 Take 或场次版本。
- 所需审查状态、问题、依据身份、具体风险确认与承接记录随相应任务或工作台文档持久化；不建立另一套设计事实。接口须表达阶段失败、过期、结构错误与语义风险的差异，不能仅以成功/失败掩盖状态。
- 文件保留与删除保护优先复用现有能力。若实施发现额外共同基础扩展必需，先说明缺口、最小改动及影响并重新确认，不能以本规格整体获批为授权。

## Testing Decisions

### 测试入口与替换边界

- 使用最高可行入口，复用真实浏览器操作与服务端公开接口，检验用户可观察行为、保存后文档、真实任务输入与状态，不以私有函数调用次数或实现形状作为验收。
- 优先扩展既有工作台浏览器、分镜范围、重新提取、恢复、参考采用及历史成果公开接口测试。沿用隔离测试数据库与媒体存储，不用用户真实画布做破坏性实验。
- 只替换外部 LLM 和媒体供应商响应；保留真实存储、保存、引用校验、输入编译与任务状态。采用本地真实视频测试抽帧，核对所选时间对应的图像及保存后的可读取性，不用占位图冒充抽帧成功。
- 从公开接口补足异常、并发与幂等用例，尽量不新增内部测试入口。必要的选帧接口作为实际产品能力通过公开入口验证。

### 阶段一验收

- 本场雨夜车旁等待用例能够报告“入场与无位移”“中近景却要求头手双脚同框”，并验证允许的定向修正及结果展示；正常景别切换与对象出画不误作必须修正的冲突。
- 覆盖共同状态继承、背景对象约束、完整与忠实模式差异、事实及人工设计保护。定向修正后复核受影响镜头，不默改无关镜头。
- 覆盖审查服务失败保留草案并从该阶段重试、一次修正后仍有冲突、逐项接受风险、依据不足可继续，以及结构/引用错误不可绕过。
- 覆盖已有画布主动检查、打开不自动执行、建议差异确认及撤销；相关内容编辑使旧结果不可应用，布局修改不使语义结果失效。
- 覆盖具体风险确认的持久化、同内容不重复确认、变化后重新判断，以及未完成/接受风险/通过状态的区别。

### 阶段二验收

- 浏览器完成后镜入口、成功结果选择、时间定位、用途选择、确认采用、撤销和重新打开。校验具体帧文件、时间来源、目标绑定及生成任务实际输入一致。
- 覆盖无前镜成功结果仍可跳过承接生成、连续动作与景别切换的不同推荐、模型不支持用途时的说明，以及首帧/主体组合冲突的两条选择路径。
- 覆盖重复确认不重复创建、抽帧和保存失败不留下半完成关系、一次撤销恢复输入与新增画布内容、素材文件不被撤销误删。
- 覆盖移除承接保留素材，恢复旧参考前核对最新配置；上游新结果仅提醒，重新采用保留旧视频并提示依据变化，不创建自动媒体任务。
- 覆盖重新提取保留人工承接、镜头移除影响提示、不静默迁移，以及来源不可用但选帧图片仍有效、选帧图片自身缺失的不同处理。

### 回归与验证局限

- 对普通生成画布回归动态输出连接、单卡执行、自动保存、历史固定成果及原有参考能力，确认不增加场次前置条件或工作台专属规则。
- 固定响应验证审查编排、结果处理和保护规则，不能据此宣称真实 LLM 能发现所有语义冲突。真实模型审查质量与实际视频视觉连续性另作人工验收，记录结果与局限，不以真实付费生成作为自动测试前提。
- 阶段一可独立验收。阶段二验证真实采用输入，不承诺对象外观或生成画面绝对一致；暂缓的对象/场景参考问题不能被计为已解决。

## Out of Scope

- 补全面包车、雨衣、甩棍等对象参考，制作符合本场状态的角色/场所参考，自动生成场次基准图。
- 新页面、新画布视图、新场次版本、旧 Take 接入及独立 Agent 服务。
- 多镜头自动生成、上下游连锁执行、自动选定视频结果或自动替换承接依据。
- 将所有镜头统一设为尾帧续拍，强制相邻画面重合，保证生成结果绝对连续。
- 把工作台语义审查规则施加给普通自由生成画布，改变原有动态连线语义。
- 实施票据拆分、代码实现、数据库迁移实施、自动启动临时托管 worker 或未授权付费生成。本次 to-spec 只发布规格。

## Further Notes

本轮确认矩阵：Q1—Q3 确定分阶段范围、连续性标准和提取补充权限；Q4—Q7 确定审查位置、问题分类、修正权限和可跳过承接；Q8—Q13 确定失败处理、风险接受、采用入口、能力冲突、固定更新及基础边界；Q14—Q19 确定选帧素材、原子采用、移除恢复、重新提取、已有画布检查与验收；Q20—Q22 确定并发过期、风险确认范围及来源不可用处理。

原始诊断场次为雨夜胡同中张三站在白色面包车旁持棍等待。示例正确关系是同一人物持续等待，镜头从环境转到人车同框再转持棍细节，而非每镜重新入场、布置或换姿态。阶段一不得将该示例固化为只适用于此场景的规则。
