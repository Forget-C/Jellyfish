# 分镜画布视频优先布局与默认堆叠

Status: ready-for-agent
Resolution: completed
日期：2026-11-10
实施状态：8 张票据已在 `codex-storyboard-video-first` 完成，代码与回归见票据验收记录；实施基线为 `4e8b93a0`。
测试确认：本轮测试边界和新增验证重点已在写入规格前单独获得用户确认。

## Problem Statement

用户进入工作台生成的分镜画布，通常想先找到对应镜头的视频卡并生成。现有画布从原文与共享对象开始，镜头组依次向下排列。每组又混有镜头说明、设计和生产卡，用户需要浏览多张卡，再打开模型编辑器才能找到运行入口。只调整列数或收起整个镜头组都不能解决这个问题：前者仍让辅助卡争占首屏，后者会连同视频卡一起隐藏。

用户还需要随时核对原文、修改设计或补参考图。收纳设计不能丢失引用或改变实际采用，重新提取也不能悄悄解除人工堆叠或挪动人工布局。普通生成画布作为共同基座，继续服务于用户自主布置和逐卡生成。

## Solution

继续使用同一张工作台画布。新分镜应用后，以视频模型卡为画布主区，打开时先看到视频卡和「生成视频」入口。镜头说明和设计默认收纳在旁边的堆叠，素材、参考和原文保持可直接找到。需要核对设计时点开只读查看，需要修改时解除堆叠。

卡面入口复用现有模型配置、预检和用户确认执行。重新提取仍先核对差异；确实需要更新被保护的自动堆叠时，用户一次确认应用差异并解除对应堆叠，必要时可一次撤销。所有专项规则由分镜层提供。共同基座只开放两处获准的可选接入点，普通生成画布沿用现有入口和操作规则。

## User Stories

1. 作为刚生成分镜的创作者，我希望打开原有工作台画布就看到视频主区，以便马上开始当前镜头的生产。
2. 作为需要按剧情生产的创作者，我希望视频卡按镜头顺序横排并换行，以便快速扫到下一镜头。
3. 作为制作多片段镜头的创作者，我希望同一镜头的各段视频卡相邻并有可辨识的标题，以便运行正确片段。
4. 作为使用窄屏的创作者，我希望首次打开时至少一张视频卡和它的操作完整可见，以便直接开始生成。
5. 作为拥有较多镜头的创作者，我希望首屏保持卡片和按钮可读，以便不用为了查看全场而先放大才能操作。
6. 作为已经移动卡片和缩放过的创作者，我希望重开画布恢复原有布局和浏览位置，以便接续上次的工作。
7. 作为主动整理画布的创作者，我希望整理后视频居中、视口对准首排、独立设计按分镜来源收纳，以便一次完成新布局。
8. 作为误触整理的创作者，我希望一次撤销恢复原分组、位置和视口，以便继续使用自己的布局。
9. 作为拥有已有分镜画布的创作者，我希望打开时不迁移或重排，以便保留之前的组织结果。
10. 作为使用可识别的已有分镜画布的创作者，我希望视频卡也有卡面生成入口，以便旧项目可以减少一次展开编辑器的操作。
11. 作为已配置模型的创作者，我希望在视频卡面点击「生成视频」即可预检，以便不必先展开模型编辑器。
12. 作为首次使用新视频卡的创作者，我希望点击时可应用该卡的系统默认配置，以便在配置齐全时同次进入预检。
13. 作为默认值不可用或配置不足的创作者，我希望原有编辑器打开在这张卡上，以便补完配置后继续生成。
14. 作为媒体生成的发起人，我希望核对真实输入后再确认执行，以便明确授权当前视频卡的任务。
15. 作为正在等待视频任务的创作者，我希望卡面显示排队或运行状态并禁止重复提交，以便避免重复创建任务。
16. 作为遇到运行失败的创作者，我希望从原卡发起「重试生成」并再次预检，以便核对修正后的配置。
17. 作为拿到视频结果的创作者，我希望保留预览和既有结果卡展示，并可从原卡发起「再次生成」，以便继续对比产出。
18. 作为先生产后核对设计的创作者，我希望六部门设计、镜头描述、节拍与制作片段说明按镜头收成一叠，以便减少首屏的辅助卡数量。
19. 作为使用跨镜头设计的创作者，我希望共享设计只收纳一份，以便多个镜头继续引用同一张卡。
20. 作为核对镜头细节的创作者，我希望打开堆叠只读查看，以便看完就回到视频卡。
21. 作为需要修改设计的创作者，我希望解除堆叠后能在原组织区域编辑原卡，以便保留引用并避免遮挡视频主区。
22. 作为要检查生成依据的创作者，我希望堆叠里的已采用设计仍参与预检和生成，以便收纳不会改变生成输入。
23. 作为需要核对文本或对象的创作者，我希望固定原文和对象描述独立可见，以便直接查找依据。
24. 作为在画布补参考图的创作者，我希望素材卡和参考卡独立展示，镜头专用参考就在对应视频卡附近，以便迅速找到并编辑。
25. 作为参考尚未齐备的创作者，我希望空参考卡保留缺失提醒，由预检区分可继续和必须补齐，以便自行决定下一步。
26. 作为重新提取分镜的创作者，我希望在差异确认中看见本次实际会解除的自动堆叠，以便先了解布局影响。
27. 作为同意应用重新提取结果的创作者，我希望一次确认即可应用差异并解除受影响的自动堆叠，以便不必逐个拆解。
28. 作为需要反悔的创作者，我希望一次撤销恢复卡片、引用、堆叠和位置，以便回到应用前的方案。
29. 作为移动过自动堆叠的创作者，我希望它仍按自动堆叠处理，解除后在移动到的位置附近显示成员，以便保留我的摆放选择。
30. 作为亲手重组过堆叠的创作者，我希望重新提取指出受影响的人工堆叠并等我主动解除，以便我的分组不会被悄悄拆散。
31. 作为已经解除某个堆叠的创作者，我希望重提取时旧镜头新增的设计就近单独放置，以便不用再拆一次堆叠。
32. 作为重新提取出新镜头的创作者，我希望新镜头按默认布局接到视频区末尾，以便加入新内容时不挪动既有卡片。
33. 作为普通生成画布用户，我希望继续用原有模型编辑器、整理和堆叠功能，以便按自己的方式组织和生成。
34. 作为从普通入口打开同一份分镜文档的创作者，我希望读到原来的卡片、堆叠和引用，以便使用同一份内容继续编辑，同时保留普通入口的操作方式。

## Implementation Decisions

### 专项职责与两处基座接入点

- 分镜画布是工作台宿主使用同一份画布文档和工作区的方式。卡片类型、内容、连接、实际采用、引用、保存、运行和结果仍由共同画布提供。专项按钮和布局策略由工作台宿主按入口启用，不因文档含有分镜元数据或存在视频模型卡就在普通入口启用。
- **Q17：卡面操作接入点。** 共同基座可提供一个可选的卡面操作位置，并允许该操作复用已有模型配置、保存和单卡预检流程。分镜层决定操作文案、状态、适用卡片和出现条件。无传入操作时，普通卡面及从编辑器发起预检的原有交互保持现状。共享层不判断镜头、片段或分镜入口，不复制模型卡、编辑器或执行链路。
- **Q18：排布与视口接入点。** 共同基座可接受可选的排布与视口策略，继续使用现有布局、可见外框、视口记忆和整理撤销能力。分镜层提供视频主区、辅助卡位置、镜头排序及首排定位规则。无传入策略时，普通生成画布沿用原有规则。
- 自动堆叠的组装、归属和重提取策略属于分镜层。使用现有扁平的编组和堆叠契约，成员不能同时属于多个组织；镜头关联继续由现有分镜关系表达，不能依赖卡片在某个视觉编组内。自动堆叠归属不向通用分组增加分镜字段。共同卡片契约、保存和堆叠保护不因本功能放宽。
- 两项确认只覆盖上述可选接入点。发现第三处基础改动需求时，按共享基础 ADR 先说明现状、缺口、最小改动及对普通生成画布的影响，另行确认后再处理依赖工作。

### 布局与卡片组织

- 新画布首次应用分镜时建立初始组织和排布。视频模型卡按镜头顺序横排，放不下就向下换行；同一镜头多段视频相邻、独立运行，卡面保留镜头和片段标识。首屏优先让第一排视频可读，不为了显示所有卡片而过度缩小。窄屏首次进入优先完整显示第一张视频卡和按钮，只调整首次视口，不因窗口变化重排已有卡片。
- 每个镜头的六部门设计、镜头描述、节拍与制作片段说明使用现有堆叠；共享设计单独成叠，不按镜头复制。堆叠在视频主区周围就近展示，初始摆放为解除后显示成员预留空间。点开只读查看，使用现有解除操作编辑原卡；已有来源导航与诊断继续遵守堆叠只读规则。收纳不改写卡片身份、连接、实际采用或编译输入。
- 固定原文和对象描述独立展示。素材卡、共享参考和镜头专用参考均保持单卡，前两者放在主区一侧，镜头专用参考就近放置。空参考继续展示缺失提醒；可选缺项可在预检后继续，必要输入缺失由现有预检阻断。沿用原有绑定与提示，不新增素材或参考卡类型。
- 已有画布打开时不迁移、不重排、不补叠；可识别的已有分镜画布从工作台进入时提供卡面生成入口。再次打开尊重已保存的布局、平移与缩放。用户主动在分镜画布点击「整理布局」时，按视频居中的分镜策略排布，将尚未堆叠且有分镜来源的设计按镜头或共享范围收纳，保留人工堆叠，将视口对准首排；一次撤销恢复整理前的分组、布局与视口。

### 卡面生成

- 仅由用户点击发起当前视频模型卡的准备与预检。保留人工已有配置；尚未保存模型配置时，复用卡片自己的系统默认模型及参数机制。默认值齐全时，完成同一套能力匹配、配置与输入更新和保存后直接预检；缺可用默认模型或必填配置时，打开同一张卡的现有编辑器。打开画布或定位首排本身不应用默认配置或启动任务。
- 预检、确认执行、错误反馈、结果和输出采用沿用现有单卡契约。预检不提交媒体任务；只有用户确认执行才提交当前卡。卡面按状态显示「生成视频」、排队或运行状态、「重试生成」或「再次生成」。排队或运行时防止重复提交，重试和再次生成均需重新预检和确认。保留已有的结果预览和结果卡展开规则。

### 重新提取与撤销

- 在已确认的重新提取差异流程上扩展堆叠影响。根据实际应用内容判断是否触碰现有保护，例如修改或删除成员、改变其输入关系；未被应用的差异、单纯视口变化不应将堆叠列为受影响。保留人工修改是否覆盖、人工新增保留及孤儿提示等既有规则。
- 受影响的自动堆叠列在差异确认中。用户确认「应用并解除受影响的堆叠」后，解除对应堆叠和应用差异为一次操作，继续经过现有保存和校验。未经确认或应用失败不留下部分修改。一次撤销恢复提取前的卡片、引用、堆叠和位置。
- 移动自动堆叠不改变其归属；因重提取解除时，成员在该堆叠当前位置附近恢复展示。用户解除后自行重组的堆叠按人工堆叠处理。选定差异碰到受保护的人工堆叠时，指出具体堆叠，要求先手动解除再重新核对；不自动拆解或绕过保护。
- 未受影响的堆叠和已有卡片位置保留。已有镜头新增的设计在该镜头附近独立摆放，不塞进已有堆叠，也不重建用户已解除的堆叠。确属新增的镜头按默认规则建立视频卡和设计堆叠，接到视频区末尾，不挪动已有卡片。

## Testing Decisions

- **测试入口。** 主路径从真实浏览器贯通服务端公开 API，复用现有分镜和画布浏览器场景。只有界面无法观察或需要直接验证绕过界面的保护时，使用公开 API 补充。使用隔离数据库和测试媒体；仅在外部 LLM、图片及视频供应商边界提供受控响应。保存、引用和采用、编译、预检、任务状态、候选应用和撤销仍走真实逻辑。
- **断言边界与先例。** 断言可见卡片位置、操作状态、公开响应、已保存文档与实际提交输入，避免断言组件树、内部回调和具体坐标算法。复用已有的分镜打开、来源定位、视频生成与预检、生成画布布局和堆叠浏览器验证，以及分镜重提取撤销和堆叠保护的公开 API 用例。既有通过记录只证明基线。
- **首屏与组织。** 用多镜头、多片段、共享设计、独立素材和有图／空参考的分镜走真实创建及应用流程。验证宽屏首排、窄屏首卡和按钮可操作，卡片类别按规则展示。验证只读查看、解除堆叠后原卡和引用仍有效、视频卡不被遮挡，再次打开恢复视口，主动整理收纳旧画布的独立设计，一次撤销恢复分组、布局及视口。核对已有分镜打开不迁移或重排。
- **单卡生产。** 验证配置就绪、系统默认可用和缺配置等路径；覆盖空参考警告与必要输入阻断。预检前使用真实保存，堆叠中的已采用设计仍出现在实际输入；确认执行前无媒体提交，确认后只运行当前卡。覆盖排队／运行、失败后重试、成功预览及再次生成，确认结果卡沿用原规则。
- **重新提取。** 验证差异准确区分受影响与未受影响的自动堆叠，以及受保护的人工堆叠；覆盖移动过的自动堆叠、用户已解除或手动重组的堆叠、已有镜头新增设计和新增镜头。确认、取消与撤销均检查可见布局和持久化卡片、引用及堆叠。直接调用重新提取的公开应用接口，验证未先解除的人工堆叠仍受保护，未明确确认时不解除受影响的自动堆叠。
- **入口隔离和基座回归。** 分别打开普通自由画布、从普通入口打开同一份分镜文档，以及从工作台入口打开该分镜文档。验证文档身份和已保存内容一致，普通入口不显示专项卡面操作或使用专项整理策略，原编辑器、模型默认机制、预检、编组和堆叠保护仍有效。两处基座接入点不传入时保持原行为。
- 实施阶段按受影响范围运行相关浏览器、公开 API 和项目要求的静态检查。规格发布仅核对内容、章节、状态、引用和文件范围，不将文档核对视作产品验收，也不以真实付费生成作为自动测试前提。

## Out of Scope

- 为本方案另建视图或画布文档，增加分镜专用卡片类型，或建立第二套布局保存、引用、预检、执行系统。
- 普通生成画布新增视频按钮、默认堆叠或分镜排布；修改共同卡片的数据和行为契约、放宽堆叠校验，或扩大到未经确认的其他基座扩展。
- 存量画布迁移、自动重排或补叠，以及旧场次数据兼容工程。
- 批量生成、自动运行视频或上游模型、改变结果卡展开规则、重做设计卡与参考卡编辑或绑定能力。
- 改造分镜提取 Agent、调整六部门输出契约、改动工作台管理页或旧版交付链路。
- 本次规格发布后自动拆票、生成预拆票据、开始实施、提交或部署。
