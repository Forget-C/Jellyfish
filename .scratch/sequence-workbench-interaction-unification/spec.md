# 场次四画布公共组件与统一交互

Status: ready-for-agent
日期：2026-10-20

本规格汇总已确认的设计讨论与现有代码核查结果。验收边界已由用户确认：以现有真实场次工作台浏览器入口为主，通用控件状态与画布几何沿用现有测试入口。规格发布不表示功能已经实现。

## Problem Statement

创作者在导演、单元、指令、编辑四种画布中反复查看对象、编辑字段、阅读来源和执行生成或导出。当前这些操作混用对象卡、右侧附加信息、悬浮区域、Drawer 和独立 modal，同一类详情可能因入口不同而使用不同容器。用户需要重新判断点击后的行为、是否必须完成当前操作才能返回，以及关闭是否会影响编辑或任务。

已有公共主题、按钮、弹窗和画布机制可以复用，但容器边界与卡片交互仍不完整。仅统一颜色不能解决操作预期不一致；照搬导演画布也会压缩指令正文、视频预览和时间线等主要工作区。

本次需要明确可复用的公共组件及其职责，统一日常详情的展示方式，并逐项区分应迁入悬浮详情面板的内容和仍需要独立 modal 的操作。业务对象、保存方式、任务执行与跨画布业务关系保持现有含义。

## Solution

四画布共享工作台布局区域、视觉规则、适用的画布基础交互和三种卡片行为。各画布保留适合自身工作的中央布局，导演画布作为设计起点，也接受必要调整。

对象完整信息、普通字段编辑、关系、来源和只读业务记录统一进入单个悬浮详情面板。桌面上面板位于右上方，四周留边，不使用抽屉滑入或遮罩，不挤压和移动画布；提供常规与展开两档尺寸。窄屏使用同一内容的近全屏呈现，保留清晰关闭入口。

独立 modal 用于有明确选择、预览、提交边界的操作，以及必须先处理的冲突或一致性保护。内容长、信息重要、包含 AI 或存在后台任务，都不能单独成为使用 modal 的理由。同一对象的完整编辑只保留一种主容器。

成功标准：

- 四画布相同语义的卡片、控件、详情入口和关闭行为可以预测，业务主工作区仍适合各自任务。
- 普通详情与独立操作按本规格清单完成归类；没有同一完整编辑器在两类容器中重复维护的入口。
- 面板打开、关闭、切换和展开不改变画布视口、节点布局或业务保存状态。
- 当前场次版本的自动／手动保存、未保存输入、固定来源和后台任务生命周期不因迁移改变。
- 桌面与窄屏均可通过鼠标、触摸和键盘完成相应操作；公共样式不污染其他页面。
- 工作台任务中心及其历史弹窗不参与本次迁移。

## User Stories

以下采用“作为某类用户，我希望某项能力，以便获得相应收益”的用户故事格式。

1. 作为场次创作者，我希望四画布保留一致的场次身份、版本和保存状态区域，以便随时知道正在编辑哪份方案。
2. 作为场次创作者，我希望四画布切换与当前主要操作的位置稳定，以便切换工作阶段时仍能找到入口。
3. 作为场次创作者，我希望当前对象、范围和已有返回入口清晰可见，以便理解当前浏览位置。
4. 作为场次创作者，我希望各画布保留适合自身任务的中央布局，以便阅读长指令、观看媒体和调整时间线。
5. 作为场次创作者，我希望不同画布的同类控件具有一致的尺寸和状态，以便正确区分选中、加载、禁用与危险操作。
6. 作为场次创作者，我希望单击普通对象摘要卡即可选中并查看完整详情，以便无需猜测隐藏手势。
7. 作为场次创作者，我希望单击子图入口即可进入对应范围，以便明确区分进入子图与编辑对象。
8. 作为场次创作者，我希望引用卡清楚标明引用或只读身份并定位原对象，以便避免误把引用当作另一份内容。
9. 作为场次创作者，我希望卡片只呈现简洁摘要，以便在密集画布中识别对象与状态。
10. 作为场次创作者，我希望在详情区域阅读完整字段，以便卡片不因长正文出现内部滚动或不断增高。
11. 作为场次创作者，我希望可拖动卡片通过明确的标题拖动区域移动，以便查看详情和操作按钮时不误拖。
12. 作为场次创作者，我希望卡内按钮、菜单和整卡点击分别执行自己的动作，以便避免一次点击触发多个操作。
13. 作为触摸或键盘用户，我希望无需悬停或双击也能访问卡片菜单和主要动作，以便完成与鼠标用户相同的工作。
14. 作为场次创作者，我希望所有普通对象详情使用同一个悬浮面板，以便保持稳定的阅读和编辑位置。
15. 作为场次创作者，我希望桌面详情面板不遮罩或挤压画布，以便边看详情边浏览和选择其他对象。
16. 作为场次创作者，我希望打开、关闭或展开详情时画布视角不变，以便保持空间记忆。
17. 作为场次创作者，我希望点击另一个对象时替换当前面板内容，以便不会积累多个互相覆盖的详情窗口。
18. 作为场次创作者，我希望再次点击当前对象或点击画布空白时详情仍保留，以便连续查看时不误关。
19. 作为场次创作者，我希望使用关闭按钮或 Escape 退出详情，以便关闭行为明确可控。
20. 作为场次创作者，我希望长详情可以在同一面板内展开，以便获得更大的阅读空间。
21. 作为场次创作者，我希望改变面板尺寸时保留输入、焦点和滚动位置，以便继续当前工作。
22. 作为场次创作者，我希望对象详情、关系和附加信息共用同一位置并提供必要的局部返回，以便不用在多个侧边区域间寻找上下文。
23. 作为窄屏用户，我希望详情接近全屏且标题、保存状态和关闭入口持续可达，以便在有限空间中完成编辑。
24. 作为键盘用户，我希望嵌套菜单先处理 Escape，关闭容器后焦点返回有效入口，以便连续操作不丢失位置。
25. 作为场次创作者，我希望普通字段编辑沿用当前场次版本的自动或手动保存，以便无需理解新增的保存阶段。
26. 作为场次创作者，我希望切换或关闭面板保留现有未保存输入，以便布局操作不会丢失工作。
27. 作为场次创作者，我希望来源与生成记录仍显示发生时的固定依据，以便不会把当前编辑内容误认为历史事实。
28. 作为场次创作者，我希望只读关系总览、审片回放和导出记录也能在详情面板内查看，以便使用一致的阅读方式。
29. 作为场次创作者，我希望从卡片、菜单或问题入口打开同一对象时使用同一完整编辑器，以便获得一致的功能和保存行为。
30. 作为场次创作者，我希望具有明确确认边界的参考选择继续独立完成，以便确认前不改变已有绑定。
31. 作为场次创作者，我希望原文依据更新和时间线整理保留比较、预览与明确确认，以便确认操作结果后再修改方案。
32. 作为场次创作者，我希望保存冲突、离开未保存内容、编辑权交接和恢复处理保持必要保护，以便不会因统一外观而丢失数据。
33. 作为场次创作者，我希望结果未知的受保护操作仍先核实结果，以便不会因关闭界面重复提交或破坏一致性。
34. 作为场次创作者，我希望 AI 设计、批量拍摄和导出按准备提交与只读记录分开呈现，以便仅在需要完成一项操作时进入独立 modal。
35. 作为场次创作者，我希望支持后台运行的任务在关闭界面后继续执行，以便查看容器不决定任务是否存在。
36. 作为场次创作者，我希望操作 modal 打开时保留底层详情但暂停其交互，以便关闭后能回到原来的工作。
37. 作为场次创作者，我希望查看操作相关的只读材料时在当前 modal 内进入并返回，以便不叠加第二个大窗口且不丢失操作输入。
38. 作为场次创作者，我希望删除导出成果等危险动作继续明确确认，以便日常阅读不会误触不可轻易恢复的操作。
39. 作为场次创作者，我希望现有内联的指令检查、单次拍摄和审片操作保持直接可用，以便统一容器不会增加无意义步骤。
40. 作为工作台使用者，我希望任务中心及其历史查看保持现状，以便本次改造不扩展到已排除的通用任务管理。
41. 作为维护者，我希望共享组件负责稳定的展示与交互机制，以便四画布可以一致演进而不混合各自业务规则。
42. 作为维护者，我希望通过真实工作台入口验证保存、焦点、视口和任务行为，以便组件复用不会掩盖实际流程回归。

## Implementation Decisions

### 1. 范围、术语与既有能力

- 范围是场次导演、单元、指令、编辑四画布，以及本节列出的场次业务详情和操作容器。
- “面板”在本规格中专指承载对象详情、关系、附加信息和只读业务记录的悬浮详情面板。主指令编辑器、主播放器、时间线、菜单、工具栏、任务中心和独立 modal 不属于此概念。
- 当前打开的场次版本是编辑对象。自动或手动保存延续同一版本，不新增“草稿”“应用到当前版本”等日常字段编辑阶段或文案。
- 既有新建、另存为、AI 设计建议审阅与明确确认等业务动作保持原义；不借容器统一重写版本管理、建议确认、素材审查或剪辑采用。
- 采用现有领域词汇：场次与场所不同，镜头与生产单元不同，生成记录、导出记录与可编辑场次版本不同。只读历史必须保留固定依据。
- 不计划修改后端、数据 schema 或对外接口。现有保存、请求凭据、权限、来源和一致性校验保持原有职责。

### 2. 公共组件及接口职责

组件名称用于指明职责；优先演进现有实现，不要求按建议名称创建另一套组件。

| 公共部分 | 对外提供 | 由调用方保留 |
| --- | --- | --- |
| 工作台主题与基础控件 | 复用 WorkbenchTheme、WorkbenchButton、WorkbenchIconButton、WorkbenchDialogActions 等；统一视觉状态、图标尺寸和可访问属性 | 主动作是什么、何时可用、加载原因、提交处理 |
| 工作台布局区域 | 演进 WorkbenchChrome，提供顶部身份／保存／画布切换／主操作、左上当前位置、右侧详情和底部辅助工具的区域 | 各画布中央布局、业务对象和当前操作；不需要的区域直接省略 |
| 通用 CanvasSurface | 视口变换、缩放、平移、测量、节点定位、适用的拖动、事件隔离和通用绘制机制 | 导演对象类型、分组、镜头适用范围、业务关系计算和其他画布布局规则 |
| 对象摘要卡、子图入口卡、引用卡 | 稳定卡片外观、有限尺寸档位、选择与焦点、摘要区、拖动区、独立动作区及对应点击语义 | 标题、摘要字段、业务状态、进入范围或定位原对象的实际处理 |
| 悬浮详情容器 | 一个当前目标、标题、保存／只读状态区、正文、常规／展开尺寸、关闭与焦点恢复、必要的局部返回 | 对象内容、字段校验、保存策略、只读来源解析与业务操作 |
| 独立操作 modal | 复用 WorkbenchModal，统一滚动、标题、固定操作区、焦点管理和与底层面板的交互隔离 | 操作步骤、确认／取消含义、提交条件和结果未知时的关闭保护 |
| 可复用只读内容 | 在详情面板或操作内辅助阅读中呈现同一来源、固定依据、记录或媒体内容 | 数据身份、权限、业务定位和原有媒体行为 |
| 视口辅助控件 | 在已有实际用途处复用缩放、适应画布、导航、小地图和通用连线外观 | 哪些画布需要这些工具，以及连线代表的业务含义 |

当前四画布已经共用带有导演名称的画布表面实现。本次拆清通用机制与导演业务适配即可，不另建通用节点编辑平台、表单配置语言或插件注册系统。

公共容器接受业务内容和明确的操作回调，不拥有完整业务流程。只读展示与可编辑字段可以复用合适的内容组件，但只读材料不得通过隐藏开关重新变成第二个完整编辑入口。

### 3. 工作台布局与视觉

- 顶部稳定展示场次身份、场次版本、保存状态、四画布切换与当前画布主要操作；低频动作沿用适当菜单归属。
- 左上区域显示当前对象或范围、位置和现有返回入口；右侧用于单个悬浮详情；底部提供适用的辅助控件。无对应功能时不保留空工具条。
- 共享区域不推导跨画布对象映射，也不规定切换画布后应带入哪个业务对象。
- 中性黑灰容器、细边框、有限圆角与间距沿用当前工作台设计标准。普通动作和选中状态使用灰阶；蓝色用于链接与可见键盘焦点；错误、警告、成功与危险操作保留各自语义。
- 常规控件高 32px，显著入口可用 38px，窄屏固定操作区至少 36px；常规图标 16px，强调入口可为 20px；间距使用现有 4／8／12／16／24px 等级。
- loading、disabled、selected、hover 与 focus-visible 分别可辨。禁用原因、保存异常及只读限制不得只靠颜色表达。
- 主题覆盖本次涉及的 portal 内容，同时保持作用域；不得因共享 tokens 调整而改变全站浅色页面或任务中心既有行为。
- 正文清楚可读，长内容由容器正文滚动，必要操作持续可达；后台刷新保留已有内容和滚动位置。

### 4. 三种卡片的统一交互

| 类型 | 主点击行为 | 必要识别信息 |
| --- | --- | --- |
| 对象摘要卡 | 选中对象并打开或切换到其悬浮详情 | 对象身份、有限摘要、必要状态 |
| 子图入口卡 | 进入对应子图／范围 | 明确的进入提示、真实计数或布局预览等适用信息 |
| 引用卡 | 定位原对象，使用已有业务导航规则 | 引用／只读身份、来源或原对象标识 |

- 不依赖隐藏双击行为；整卡行为可通过键盘触发。
- 可拖动卡片仅在明确的标题拖动区域启动拖动。拖动、菜单、卡内按钮与整卡点击隔离，拖动结束不误打开详情。
- 菜单在 hover 或键盘 focus 时可见；触摸环境有持续可达的入口。
- 卡片按类型使用有限尺寸档位，每个摘要字段最多两行，不使用卡内滚动承载全文。
- 具体摘要字段由业务决定。字段缺失、只读、未保存及业务状态分别表达，不合并成含义模糊的统一状态。
- 长指令编辑、主媒体预览和时间线不强制使用紧凑摘要卡尺寸；既有实际媒体信息不能因卡片统一被隐藏。

### 5. 悬浮详情面板

| 项目 | 约定 |
| --- | --- |
| 桌面形态 | 右上方悬浮，四周留边，完整圆角与边框；无遮罩，不侧滑，不推挤画布 |
| 尺寸 | 常规与展开两档；展开朝工作区中央增加阅读空间；不提供自由拖动或任意缩放 |
| 实例 | 同一时刻一个详情目标；对象、关系与附加信息在同一容器内切换 |
| 选择 | 新对象替换当前目标；重复点击当前对象不关闭；点击空白不关闭 |
| 关闭 | 显式关闭按钮或 Escape；嵌套菜单、选择器等先消费 Escape |
| 画布 | 桌面仍可平移和选择；面板开合、切换与尺寸变化不触发视口移动、缩放或节点重排 |
| 状态保留 | 尺寸变化不重建编辑会话；保留输入、有效焦点和滚动；关闭与对象切换沿用既有输入保留策略 |
| 标题区 | 对象身份及适用的保存／只读状态、展开与关闭入口 |
| 保存 | 沿用当前自动／手动保存，不新增关闭即提交或通用确认／取消事务 |
| 窄屏 | 同一内容接近全屏但保留边距；标题、保存状态和关闭入口可达，正文滚动，焦点限定在当前覆盖区域 |

桌面详情不锁定画布焦点。窄屏的焦点约束是同一详情容器的响应式行为，不把普通编辑变成需要提交的独立操作。关闭后恢复有效的触发入口；入口已消失时使用现有合理焦点回退，不聚焦已卸载元素。

关系总览、只读审片回放等长内容可以使用展开尺寸，必要时在面板内返回此前视图。普通切换不得自动丢弃编辑；既有必须处理的未保存或所有权保护仍生效。

用户主动点击定位、返回、缩放或适应画布时，继续执行这些明确导航动作；“面板不改变视口”不禁止用户主动导航。

### 6. 独立 modal 的功能边界与叠层

- 普通字段、参数、依赖、来源、关系、问题和只读记录进入悬浮详情。
- 独立选择、比较、预览并明确确认的操作保留 modal；冲突处理、不可轻易恢复的动作确认和结果未知的一致性保护保留必要阻塞。
- 判断依据是操作完成边界与是否必须先处理。内容长度、AI 属性、复杂程度、存在确认按钮或后台任务本身都不构成充分理由。
- 同一对象的完整编辑器只能有一个规范容器；卡片、菜单和问题入口复用它。
- 操作 modal 可以覆盖已打开的详情，但底层详情保持挂载和输入，详情与画布暂时不可交互。关闭后回到有效触发入口。
- 不叠加第二个大型 modal。确有必要的短危险确认允许在当前操作上出现；关闭和 Escape 只作用于当前可处理的最上层，不穿透关闭底层。
- 任务状态不能由容器可见性决定。已有支持后台执行的任务可关闭后继续；已有结果未知或复制过程保护不因此变成可随意关闭。

**操作内只读辅助阅读例外（Q19）**：用户在一个操作 modal 中需要核对来源、固定依据、参考图等相关材料时，可以在该 modal 内切换到只读阅读并返回。操作选择与输入必须保留，复用相同只读内容模块；不再打开大型弹层，不激活底层详情，不提供完整原对象编辑。需要编辑原对象时使用唯一的悬浮详情入口，不另建操作内编辑副本。

### 7. 现有容器迁移清单

清单按当前可达的场次工作台功能归类，不依据组件名称是否带 Modal、Drawer 或 Panel 判断。

#### 迁入悬浮详情

| 现有功能／组件 | 目标呈现 | 必须保留的行为 |
| --- | --- | --- |
| 设计卡完整字段（SceneDesignPanel） | 对象详情；长内容可展开 | 字段直接变更与现有保存方式；无需通用确认底栏，仅保留明确关闭 |
| 人物／物件／场所与项目资产关联（SceneAssetLinks 的导演入口） | 对象详情中的关联内容 | 现有选择、解除和添加的直接变更语义；不改成先选后提交的事务 |
| 单元模型参数、前段依赖（SceneUnitCanvas） | 单元详情 | 现有直接 patch；“完成编辑”仅关闭的行为不得被误改成提交 |
| 导演定位、缺陷、关系来源等附加信息 | 与对象详情共用右侧容器 | 现有范围和定位规则，避免并列第二个详情区 |
| 对象关系详情（SceneRelationDetails） | 同一详情容器中的只读内容 | 依据、共享、场所、人物、引用等已有业务含义 |
| 全部关系总览（SceneWorkbenchOverview） | 展开详情，可局部返回 | 源／目标的实际定位规则不改 |
| “来源版本 · 只读”（Sources、SceneSourceRevision） | 只读详情 | 指定历史来源身份；不得替换成当前最新内容 |
| “生成指令的冻结依据”（PromptReader 的来源阅读入口） | 只读详情内的依据阅读 | 固定生成依据；不再通过 Drawer 打开另一套阅读区域 |
| “任务固定记录 · 只读”（场次业务入口） | 只读业务记录详情 | 已有链接参数、上下文解析与固定记录身份；不属于任务中心迁移 |
| 历史接缝／整场审片回放（SceneReviewPreview） | 展开只读详情 | 对应审片媒体与区间；主播放器工作区不因此迁入面板 |
| “整场导出记录”（SceneExportPanel 的记录部分） | 业务记录详情 | 状态、预览、下载及现有可用的重试／取消／删除；危险删除继续独立确认 |

设计卡创建中的必填关联选择与“建立工作单”是已有显式业务动作，继续保留；不能因为字段容器迁移就自动创建，也不因存在一个确认按钮机械拆成新 modal。

#### 保留独立 modal 或必要阻塞

| 功能／组件 | 保留理由 | 约束 |
| --- | --- | --- |
| 参考选择（ReferencePicker） | 本地选择后明确确认绑定，取消不修改原绑定 | 保留现有上传的实际副作用，不承诺取消会撤销已上传文件；单纯查看参考属于只读详情 |
| 原文依据比较与更新（SceneSourceBasis） | 对比、选择并明确更新依据 | 仅阅读原文依据使用详情，不复制完整更新流程 |
| 时间线整理预览（SceneTimelineEditor） | 预览后确认，并检查原内容未变 | 保留提交前一致性校验 |
| 保存冲突、未保存离开、编辑权交接、未保存编辑数据恢复 | 必须先作出决定或完成保护 | 继续使用已有保存与恢复语义，不创建另一套版本层级 |
| 复制场次版本过程及结果未知保护 | 避免状态未明时继续编辑或重复操作 | 保留原关闭限制和核实流程，不作为普通后台任务弹窗处理 |
| 删除导出成果 | 对不可轻易恢复的文件操作明确确认 | 保留原接口约束与权限校验，使用短危险确认 |

#### 按使用目的拆分的复合功能

| 功能 | 保留 modal 的部分 | 详情或非模态呈现的部分 |
| --- | --- | --- |
| AI 设计（SceneDesignSuggestions） | 准备、提交、比较建议和已有明确确认操作；操作过程中需要的进度可在原容器内显示 | 纯状态、历史或诊断阅读；不得因“AI”一概强制 modal |
| 批量拍摄（SceneVideoBatch） | 选择、预检、明确提交 | 已提交任务的状态和结果阅读 |
| 成片导出（SceneExportPanel） | 导出配置、检查、明确提交 | 导出记录、运行状态、结果视频和下载 |

拆分展示职责时不复制完整业务流程，不因关闭卸载而终止既有任务或丢失同一编辑会话中的输入，不承诺新增跨刷新持久化。已有未知提交结果核实和重复提交保护保持生效。

#### 保持内联或原有菜单形态

- 指令建议、指令检查、直接单次拍摄、素材审查、接缝审查和整场验收的现有内联主操作不因本次统一新增 modal。
- 版本管理与保存设置沿用现有工具栏菜单，不新增版本命名或保存设置弹窗。
- 主指令编辑器、媒体播放器与时间线继续作为各画布工作区；历史回放迁移不代表主编辑区一起迁移。
- 工作台任务中心与其任务历史不纳入本次，保留现有 Drawer／Modal。这是范围排除，不将其作为场次业务容器的新增范例。
- 未经当前场次入口实际使用的旧资产编辑弹窗、旧工作台历史等不因被搜索到或间接导出就纳入改造。

### 8. 生命周期与数据边界

- 展开、折叠、切换阅读内容、移动视口和调整展示布局均不触发业务保存、生成、采用或另存为。
- 用户实际编辑字段继续触发原有自动保存或手动待保存状态；保留失败、待核实、只读、权限与冲突提示。
- 当前场次内容、固定生成依据、生成任务状态、素材审查和剪辑采用分别表达，不因共用一个容器合并状态。
- 后台刷新保留已有内容、展开状态和滚动；异常在稳定区域显示，不清空正在阅读的数据。
- 历史来源和业务记录的解析、权限与链接回跳保持现有规则。本次不统一跨画布的业务对象映射或携带策略。
- 公共层仅收敛展示与交互机制；不要让通用 CanvasSurface、详情容器或 modal 掌握业务保存、生成编排与版本迁移。

## Testing Decisions

### 已确认的测试边界

以**真实场次工作台浏览器入口**作为主要测试边界，从用户操作验证结果。复用现有隔离后端、前端和浏览器测试设施；测试夹具控制数据与任务响应，避免为验证展示发起真实付费生成。

现有 Workbench UI 示例、四画布样式、场次版本工作台、画布导航、导演布局与设计完整性浏览器回归提供先例。公共控件状态通过已有示例入口补充；CanvasSurface 几何或持久化算法有实际改动时复用现有画布与导演布局测试。不新建一套测试框架，也不为每个容器增加仅供测试调用的业务接口。

好的测试断言用户看见与操作后的结果：打开哪类容器、数据是否保留、是否发生请求、视口是否变化、焦点是否有效。不要断言内部 hook 数量、组件层级、任意 CSS 类名或实现细节；对同一行为优先在已有最高层入口验证。

### 行为验收矩阵

| 场景 | 必须验证的可观察结果 |
| --- | --- |
| 四画布布局与控件 | 公共区域与同类状态一致；指令、媒体和时间线保留合适工作空间；空内容、密集节点和长文本可用 |
| 三类卡片 | 单击分别打开详情、进入范围或定位原对象；按钮／菜单不冒泡；拖动不误点击；触摸和键盘可达 |
| 卡片摘要 | 摘要截断有效、无卡内正文滚动；完整内容在详情可读；真实计数、引用身份与媒体信息正确 |
| 面板与视口 | 打开、关闭、切换、展开前后缩放、平移和节点位置不变；主动定位等导航仍正常 |
| 面板选择 | 新对象替换当前目标；重复选择和点击空白不关闭；同时只有一个详情容器 |
| 保存与输入 | 自动保存与手动保存分别覆盖；编辑后切换、关闭、重开及改变尺寸按现有规则保留输入；单纯浏览不增加业务保存 |
| 长内容与刷新 | 展开不产生第二份编辑器；焦点和滚动保留；后台刷新不清空内容；固定操作区持续可达 |
| 来源真实性 | 只读来源与生成／导出记录保持固定依据；当前版本后来修改不改变被阅读的历史事实 |
| 规范入口 | 同一对象从卡片、菜单、关系或问题入口进入同一完整编辑容器，不残留另一套 modal 编辑路径 |
| 现有显式确认 | 参考选择取消不改变绑定，确认沿用原行为；原文更新、时间线预览、建立工作单仍有各自既定边界 |
| 保存与一致性保护 | 保存冲突、未保存离开、编辑权交接、恢复和复制结果未知等原有阻塞不被面板关闭绕过 |
| modal 覆盖详情 | 底层输入保留且不可交互；关闭恢复有效焦点；没有第二个大型 modal 堆叠；短危险确认只作用于当前层 |
| 操作内辅助阅读 | 只读材料在当前 modal 内进入和返回；选择与输入不丢失；没有完整对象编辑副本或被激活的底层面板 |
| 复合功能与任务 | 准备提交和记录阅读使用正确容器；支持后台执行的任务关闭后继续；重开呈现原任务；结果未知保护仍生效 |
| 导出记录 | 状态、预览、下载及原有可用动作完整；删除仍明确确认；主播放器不因迁移失去工作区 |
| 桌面与窄屏 | 至少覆盖 1440px 与 390px，按既有回归补充 1280px；关键入口不重叠、不越界；窄屏聚焦与返回正确 |
| 键盘关闭 | 内层菜单先处理 Escape；一次关闭只影响当前层；关闭后的焦点有效且可见 |
| 范围与主题隔离 | 内联操作没有额外 modal；任务中心既有入口仍可用且无本次设计迁移；全站浅色实例不受公共样式影响 |

实现阶段必须运行前端类型检查及受影响的浏览器和算法回归。公共基础设施变更影响范围不明时扩大到完整相关测试集；使用相同隔离端口的浏览器套件顺序执行。截图用于核对真实内容下的布局与状态，不替代保存、焦点和任务行为断言。

本次仅发布规格，不运行应用构建或把既有测试通过记录当作新功能验收。发布时检查规格结构、状态、迁移完整性和已确认排除项。

## Out of Scope

- 工作台任务中心、任务历史及全站任务管理的容器迁移或交互重设计。
- 不同画布之间的业务对象映射、选择携带、导航语义及工作流程重构。
- 项目工作台、旧工作台或其他页面的整体样式统一。
- 新增“草稿”、通用“应用到当前版本”阶段、额外版本状态，或重写当前自动／手动保存模型。
- AI 建议内容、生成策略、模型能力、参考选择规则、业务权限、审片判断或剪辑采用语义的改变。
- 将四画布都改成导演图结构，或把指令编辑器、播放器与时间线收进紧凑卡片。
- 可自由拖拽／任意缩放的浮动窗口、多详情并排、可插拔节点平台、万能卡片或表单配置系统。
- 新后端接口、数据迁移、接口契约变更和新的跨刷新输入恢复能力。
- 仅因搜索结果包含 Modal／Drawer 就清理未被当前场次流程使用的旧代码。

## Further Notes

- 本规格承接前期四画布样式与控件统一成果。此前“复杂详情继续使用宽弹窗”的约定，以及导演正式卡通过 modal 编辑的实现描述，由本次按用途划分容器的决策替代；现有主题、控件和业务保护继续复用。
- 实现落地时同步更新工作台前端设计标准中受影响的组件职责、详情编辑例外、容器边界与验收说明。当前规格属于待实现方案，不提前把架构文档改写为已经落地。
- 不新增领域概念，也不为本次可逆的界面容器决策创建独立 ADR。若实施中发现确需改变已排除的业务契约，另行确认范围，不静默扩大本规格。
- 建议实现顺序为：公共布局与详情容器 → 已有普通详情迁移 → 复合操作的阅读与提交职责拆分 → 四画布接入与回归 → 同步当前设计指南。每一步以对应行为验收作为完成依据。
- 本规格可直接用于后续任务拆分；本次不生成实现票据、不修改应用代码、不提交版本控制。
