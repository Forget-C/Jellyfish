# 10: 分离导出操作与导出记录

Status: ready-for-agent
Blocked by: 06 — 统一确认操作、辅助阅读与阻塞保护

**What to build:** 创作者在独立 modal 中配置、检查并提交成片导出，在悬浮详情中查看导出记录、状态、视频与下载。既有重试、取消、删除确认和未知结果核实继续有效，导出成果与当前时间线各自保持原有身份。

规格依据：《场次四画布公共组件与统一交互》的导出复合功能拆分、记录迁移、短危险确认与一致性保护约定。

## Acceptance criteria

- [x] SceneExportPanel 的导出配置、检查和明确提交保留独立 modal，保存前提、可用条件、检查反馈与原业务提交含义不变。
- [x] “整场导出记录”、运行状态、结果预览和下载进入悬浮详情；当前与历史业务入口复用对应记录内容，不在 modal 中保留第二套完整记录页面。
- [x] 每条记录仍使用其固定剪辑依据与输出配置；当前场次、时间线或输出设置后续变化不改写历史记录或成果身份。
- [x] 普通查看、展开和下载入口不自动导出或保存；主播放器与时间线仍留在编辑工作区，不随历史预览迁入详情。
- [x] 保留各记录原本可用的重试、取消与删除，保持权限和状态条件。重试、核实原提交、按当前内容导出及重新下载仍分别表达。
- [x] 删除导出成果继续使用短危险确认，提交中和失败时保留原关闭与错误处理；取消确认不删除，实际删除不能由普通阅读误触。
- [x] 已有支持后台运行的导出不因关闭容器终止；原历史入口在提交中、结果未知或恢复异常时的必要关闭限制继续有效，不能因详情通常可关闭而丢失核实能力。
- [x] 固定请求凭据、核实流程与重复提交保护保持原状；导出完成不自动表示整场验收通过或素材已采用。
- [x] 操作所需只读材料在当前 modal 内查看并返回，复用 06 的规则；modal 覆盖时底层详情输入保留且不可交互，不叠加第二个大型窗口。
- [x] 轮询保持已有记录、视频、展开和滚动，错误使用稳定反馈区域；详情开合不改画布视口，焦点和 Escape 只处理当前有效层。
- [x] 在真实工作台用既有隔离数据覆盖配置→检查→提交→关闭→记录更新→预览／下载，以及重试、取消、删除确认和未知结果核实；验证历史依据不会随当前编辑变化。
- [x] 1440px／390px 下长记录、媒体及操作可达，前端 typecheck 与受影响导出／工作台浏览器回归通过，同步导出容器边界、保护和验收说明。

## Scope boundaries

不修改导出后端、文件删除权限、重试算法或接口契约；不增加新的持久化、自动采用或版本层级。无需等待 09 的编辑画布展示迁移即可接入现有导出入口。

任务中心及其历史保持原状；不清理未被本次场次流程使用的旧弹窗，不修改跨画布业务导航或全站主题。
