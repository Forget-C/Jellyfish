# 05: 按结果归属安全删除卡片与组合

**What to build:** 创作者删除关联结果、模型卡或一组卡片时，系统根据更新归属和最终保留的引用决定能否删除，给出明确原因，并保留已独立的内容；删除及其撤销不留下悬空引用或重新创建已删除路径。

Blocked by: 03 — 断开上游固定内容并迁移引用

Status: ready-for-agent
Completion: integrated

- [x] 单独删除仍关联的 R 被拒绝，说明“请先断开与生成卡的连线”等具体原因；不自动固定、不仅仅隐藏、不删除生成文件，也不添加固定菜单。
- [x] 断开上游形成独立内容后，沿用普通内容卡删除规则；仍被保留消费者引用时继续受保护，不能用已固定状态绕过保护。
- [x] 删除 A 时，若其关联结果仍被最终保留的消费者引用，则拒绝并提示先断开上游保留内容或解除引用；现有活动运行等删除保护仍生效。
- [x] 允许删除 A 后，一并移除属于它的关联结果展示和对应候选关系；已固定独立卡及其消费者保持不变，不自动把剩余关联结果转成独立卡。
- [x] 批量删除按最终保留的消费者检查，组内同时删除的引用不阻止整组删除。A 及其关联展示的选中集合须按实际归属处理，不能被 R 的单独删除禁令误拦截。
- [x] 删除成功后同步清理对应连接、输入顺序、分组和布局成员；拒绝时整个文档不变。后台迟到事件或重新打开显示不能重建已删除关系。
- [x] 删除与撤销使用现有编辑历史保持原子性，不回滚后台生成历史；恢复关联展示时仍按当前正式输出与真实连接范围解析。
- [x] 真实浏览器旅程验证拒绝原因、先断线再删、删除 A、保留独立内容和多卡批量删除；公开 HTTP 保存验证保留引用不能被绕过及失败无部分写入。
- [x] 使用已经固定的普通内容即可验收本票，不依赖复制票据完成。无需为删除逻辑新增运行机制、来源别名或通用事务框架。
- [x] 同票完成必要的契约与文档同步，运行受影响的图操作、服务端及浏览器回归和项目规定检查。
