# 05: 项目概览与章节的继续制作入口

**What to build:** 用户在项目概览和章节列表直接看出当前制作对象、状态与可执行动作，从正确章节继续编辑原文、划分场次或管理场次。

**Blocked by:** 04 — 项目内二级菜单与上下文导航。

**Status:** ready-for-agent
**Completion:** integrated

- [x] 项目概览采用最终 A 的桌面布局，将“当前制作”与生成画布预览并排，章节、状态、主要操作同组；窄屏按清晰顺序堆叠，不把操作推离对应章节。
- [x] 页面标题约 20px、区块标题约 16px，使用留白与轻底色区分内容，移除重复页眉引导。状态有明确文字与浅底色，不单靠颜色表达含义。
- [x] 章节列表让章节名称、已有状态与下一步动作相邻，保留原有章节操作、空态及失败反馈，不重新定义状态或制作完成率。
- [x] “编辑原文”“划分场次”“进入场次”遵循已有条件及行为，使用真实项目和章节定位。验证最终进入的业务页面与文案一致，不使用原型示例定位提示作为正式操作结果。
- [x] 生成画布预览复用现有数据与合适封面；没有现成字段或可靠汇总的展示标记为示例，并与真实信息区分。示例不产生业务操作，不进入虚构画布或章节。
- [x] 进入生成画布及场次画布后保留独立布局、主题、浮层和既有操作；返回项目后上下文仍正确。
- [x] 在正式页面使用代表性章节状态验证每种动作及对象定位，并检查空态、读取失败、示例、键盘焦点和宽窄屏布局；复用现有章节与画布入口验收，运行受影响的前端检查和类型检查。

范围：只调整概览与章节呈现和现有入口，不改变章节划分、场次版本、生产规则、接口或表结构。直接依赖项目二级导航，不依赖项目列表改版或外观选择完成。
