# 03: 项目列表的查找、管理与继续制作

**What to build:** 用户在项目列表快速找到项目、理解当前章节状态并继续制作，常用操作直接可见，详情与较少使用的管理操作按需打开。

**Blocked by:** 01 — 顶部导航与首页生成画布入口。

**Status:** ready-for-agent
**Completion:** integrated

- [x] 项目列表按可用桌面宽度展开，不保留固定速览栏；卡片响应可用宽度排列，使用最终 A 的紧凑标题、留白及轻底色。
- [x] 搜索、制作阶段筛选、新建直接可见，桌面尽量聚为一行；沿用现有状态筛选语义，不推导新的制作阶段。排序、方向、视图与批量管理进入次级入口。
- [x] 选中筛选和视图使用较轻的底色，工具栏的实心强调色突出新建项目。原有搜索、筛选、排序、视图与新建行为继续可用。
- [x] 批量模式显示选中数量、删除和退出，沿用现有删除确认及成功／失败反馈，不能因重新排布绕过确认。
- [x] 卡片突出题材、项目名、具体章节、状态和下一步动作；仅有合适预览时使用缩略图。更新时间只出现一次，百分比和资产计数降为次要信息，不重复显示“下一步”说明和同义按钮。
- [x] 项目名进入项目概览；“编辑原文”“划分场次”“进入场次”等动作按现有业务规则进入正确项目和章节。不把现有聚合值改称制作完成率。
- [x] 点击“详情”才打开待处理内容，移除悬停切换和常驻速览。内容帮助判断下一步，使用“查看章节列表”等准确说明去向的文案，避免重复整张项目卡。
- [x] 优先使用既有真实数据；缺少接口支持的待处理汇总明确标记为示例并与真实内容分区，不触发虚构跳转或业务操作。空态、真实请求失败及示例可区分。
- [x] 复用项目列表及路由验收，验证搜索、筛选、新建、排序、视图、批量删除确认、详情关闭与焦点恢复，以及实际项目／章节落点；检查宽屏、桌面断点和手机，运行受影响的前端检查和类型检查。

范围：只修改项目列表布局、呈现与入口，复用既有接口、状态和操作规则，不新增进度计算或后端汇总。可直接使用既有项目及章节页面，无需等待 04、05，也不等待外观选择票据 02。
