# Jellyfish 前端导航、首页与项目布局

Status: ready-for-agent

确认日期：2026-11-10

## Problem Statement

目前顶栏主要展示当前位置，左侧图标栏并列放置项目、模型、资产等不同层级的入口。用户进入项目后还需在横向页签里找到章节、资源或设置。管理与实验室已有各自的侧栏，增加全局导航时容易挤出第二条常驻侧栏。根地址直接跳到项目列表，缺少可回到画布、项目和实验室会话的综合首页。

项目卡的百分比、计数和重复说明挤占主要位置，用户难以快速找到下一步。悬停会切换项目速览，速览和卡片又提供去向不同的入口。桌面 A 原型评审还发现，34px 大标题和多行引导文案占用首屏，项目状态与动作在宽屏上容易被拉开，重复使用同样的白色容器也让内容层级难以区分。

## Solution

普通页面采用“顶部一级导航＋按上下文显示的左侧二级导航”。顶栏保留 Logo、任务与用户，首页和项目列表用完整宽度，进入具体项目后才显示项目菜单。管理与实验室各使用一条左栏。

首页服务于恢复创作。上方显示最近更新的生成画布，下方并排显示项目进展和最近实验室会话。项目页让项目名称、具体章节、状态和动作成为扫读主线，待处理详情按需打开。首页与项目的桌面视觉以用户选定的最终 A 原型为依据，采用紧凑页眉、浅色状态标签和不同的内容表面。

首版在普通页面提供雾蓝微渐变和雾蓝纯色。主题切换立即生效，在当前浏览器保存。此次范围是前端布局、导航呈现、样式与本地外观选择。现有接口可提供的数据优先复用，缺少字段或汇总的展示标注为示例数据。

## User Stories

1. 作为创作者，我希望从顶部直接进入首页、项目、管理和实验室，以便明确知道自己所在的领域。
2. 作为创作者，我希望点击 Logo 回到首页，以便快速回到工作概览。
3. 作为创作者，我希望在普通页面右上角打开任务中心，以便切换页面时继续查看任务。
4. 作为创作者，我希望通过右上角用户菜单进入个人设置，以便区分个人和项目偏好。
5. 作为创作者，我希望深层页面在内容区显示必要的面包屑，以便返回上一级。
6. 作为通过书签进入项目的创作者，我希望刷新、前进和后退时保持正确的页面和菜单选中项。
7. 作为手机用户，我希望四个一级菜单保持可见，以便直接切换领域。
8. 作为窄屏用户，我希望按需打开二级菜单，以便为内容留出空间。
9. 作为回到首页的创作者，我希望看到生成画布的名称、所属项目和封面，以便识别手头的工作。
10. 作为回到首页的创作者，我希望看到具体章节、当前状态和下一步动作，以便继续推进项目。
11. 作为回到首页的实验室用户，我希望看到会话类型、名称、摘要和更新时间，以便识别原对话。
12. 作为从首页继续工作的创作者，我希望真实入口打开相应的画布、章节或会话，以便恢复正确上下文。
13. 作为查看首页的创作者，我希望明确区分真实数据和示例数据，以便正确理解展示的状态。
14. 作为查看首页的创作者，我希望看到真实读取失败的提示，以便知道何时需要重试。
15. 作为项目管理者，我希望点击顶部“项目”始终回到项目列表，以便切换项目。
16. 作为项目管理者，我希望直接搜索、筛选和新建项目，以便完成常用操作。
17. 作为项目管理者，我希望按需使用排序、视图和批量管理，以便保持工具栏简洁。
18. 作为批量管理项目的用户，我希望看到已选数量、删除和退出入口，以便掌握批量操作的范围。
19. 作为创作者，我希望项目卡突出项目名、章节和动作，以便快速辨认并继续工作。
20. 作为创作者，我希望更新时间只显示一次，以便扫读项目卡。
21. 作为创作者，我希望点击项目名称进入项目概览，以便确认项目身份和进展。
22. 作为创作者，我希望点击明确的章节动作后进入对应位置，以便填写原文、划分场次或管理场次。
23. 作为创作者，我希望点开“详情”后才看到待处理事项，以便避免悬停切换或常驻侧栏占据空间。
24. 作为进入项目的创作者，我希望左侧菜单标明当前项目并提供返回列表入口，以便知道操作归属。
25. 作为进入项目的创作者，我希望按创作、项目资源和项目管理浏览入口，以便快速找到功能。
26. 作为查看项目概览的创作者，我希望“当前制作”里的章节、状态和主要操作相邻，以便知道按钮作用于哪一章。
27. 作为打开生成画布或场次画布的创作者，我希望继续在对应的独立工作区操作，以便保有原来的工作空间。
28. 作为管理者，我希望在同一左栏切换模型、资产库、提示词模板、文件和 Agent，以便在管理领域内移动。
29. 作为管理者，我希望回到管理时恢复上次的二级页面，以便继续处理同类对象。
30. 作为管理者，我希望在内容区切换类别并筛选，以便在一条左栏下完成管理。
31. 作为实验室用户，我希望左侧三个类型入口下只显示当前类型的会话，以便清楚当前上下文。
32. 作为实验室用户，我希望点击历史会话恢复该会话，以便继续原来的对话。
33. 作为实验室用户，我希望从类型入口使用已有的新会话输入界面，以便按现有方式开始实验。
34. 作为桌面用户，我希望标题和说明适度收紧，以便首屏显示更多有用内容。
35. 作为桌面用户，我希望章节状态可通过文字和轻底色辨认，以便在列表中快速区分待处理事项。
36. 作为键盘用户，我希望菜单、按钮和弹层有清楚的焦点和选中状态，以便完成同样的操作。
37. 作为使用不同显示偏好的用户，我希望在用户菜单或设置页切换雾蓝微渐变与雾蓝纯色，以便选择舒适的页面背景。
38. 作为切换外观的用户，我希望选择即时生效并在同一浏览器重开后恢复，以便不用重复设置。
39. 作为使用画布的创作者，我希望普通页面的外观偏好与独立画布的主题隔离，以便保持画布和浮层的视觉一致性。

## Implementation Decisions

### 导航与页面上下文

- 普通页面顶栏显示 Logo、首页／项目／管理／实验室、任务与用户。Logo 进入首页。移除旧的左侧一级图标栏。面包屑移到内容标题上方，仅在需要表达上下级关系的页面展示。
- 保留现有业务地址、项目页签定位参数、实验室模式和会话地址及既有兼容跳转。一级与二级选中态根据实际页面呈现。保留全局任务运行时在导航过程中的连续性。
- 首页与项目列表不设固定左栏。桌面项目、管理与实验室页面按当前领域展示二级导航。中等宽度改用按需展开的导航抽屉。手机顶部分两行，第一行是 Logo、任务、用户，第二行是四个一级文字入口。
- 生成画布与场次画布保留现有独立布局、导航、任务入口、主题、浮层和响应式行为。普通页面使用已有目标地址进入对应画布，外观配置限定在普通页面范围内。

### 首页、项目列表与项目内页

- 首页采用最终 A 的模块顺序。上方为最近更新的生成画布，下面为项目进展与最近实验室会话，桌面两区约为 2:1，窄屏按相同顺序纵向排列。桌面首张画布卡略宽，实验室会话使用轻量列表，项目动作紧贴章节与状态。场次画布由项目及章节入口访问。
- 有真实生成画布封面时复用。现有列表按项目读取完整画布文档，首版跨项目“最近更新”展示使用示例数据。没有现成字段或可靠汇总的制作进展也使用带标记的示例。实验室会话可复用现有列表字段。真实数据和示例明确分区，示例不产生真实业务操作，也不跳到虚构对象。真实读取失败保留失败反馈。
- 现有项目进度和聚合字段不能直接表示制作完成率。使用可用的章节、场次信息和已明确的具体动作，百分比和资产计数降为次要信息。保持项目状态及章节动作现有规则。
- 项目列表宽度随桌面窗口展开。搜索、筛选、新建直接可见，排序、视图和批量管理收进次级菜单。进入批量模式后显示选中数量、删除和退出，继续沿用已有删除确认。桌面将控件聚为一行，卡片按可用宽度排布。项目卡突出题材、项目名、章节、状态和动作，缩略图仅在有合适预览时使用，时间只显示一次。
- 项目名进入项目概览，明确的章节动作进入现有对应入口。待处理“详情”由点击打开，移除常驻速览及悬停切换。需要新增数据能力的待处理汇总使用有标识的示例。
- 项目左栏顶部显示当前项目名称和“返回项目列表”。创作依次为项目概览、画布生成、章节。项目资源依次为演员、角色、场景、道具、服装。项目管理为文件、项目设置。菜单分组默认展开，项目切换经项目列表。
- 桌面项目概览将“当前制作”与生成画布预览并排。章节、状态和主要操作同组。“编辑原文”“划分场次”“进入场次”使用现有业务页面验证，原型中的示例定位说明不作为正式落点。

### 管理与实验室

- 管理左栏依次为模型管理、资产库、提示词模板、文件管理和 Agent 管理。首次打开进入模型管理，后续恢复上次管理二级页，不自动打开具体记录编辑页。供应商、模型、运行设置及资产类别在内容区切换，分类与类型筛选放在工具栏或筛选面板内。
- 实验室在同一左栏放置文本、图片、视频三个类型入口，以及当前类型的会话列表和新建入口。长列表独立滚动，输入区保持可见。类型切换进入现有模式输入界面，历史会话使用原会话地址，现有首次有效提交后创建会话的行为继续适用。
- 这两项是已确认的正式页面要求。A 原型中的“管理”“实验室”仅预览顶栏位置。

### 视觉与外观

- 复用 React、Ant Design 和现有交互约定。普通页面用留白、对齐、标题和轻微底色变化区分区域。移除结构性分割线和普通展示卡描边。表单、错误、选中与键盘焦点保留可辨识边界，阴影用于浮层。
- A 的桌面调整以 1024px 为起点。顶栏约 56px，项目左栏约 216px，菜单行约 40px。桌面外边距采用最终原型的 20px，手机约 16px。页面标题约 20px，区块标题约 16px。收起重复页眉引导文案，章节状态使用可读文字和浅色底，项目与动作保持近距离。后续桌面精修不替换此前确认的窄屏方案。
- 雾蓝微渐变为默认，背景从 #F0F5FC 到 #F7F8FB。雾蓝纯色背景为 #F7F8FB。两者共用白色内容表面、#245FC5 强调色、#E4EDFB 菜单选中底色、#263244 正文和 #536174 辅助文字。静态渐变只用于普通页面背景，表单、卡片、列表、弹窗和按钮使用纯色。
- 用户菜单的“外观”提供两种预览、名称和当前选中标记。设置页用同一外观偏好取代失效的“深色模式”开关。选择立即应用，与个人资料保存独立。浏览器本地保存，刷新和重开时恢复。无有效记录使用默认值，存储不可用时保留当前页面切换能力。

## Testing Decisions

- 以已确认的真实页面浏览器验收为主，在正式前端路由中验证用户看到的结果。复用现有应用壳验收与键盘导航测试、实验室旧路由兼容测试以及画布导航和交互验收。通过实际点击、键盘、刷新、返回和选中状态验证可观察行为，避免依赖组件内部状态、类名或原型专用入口。
- 用同一浏览器验收边界覆盖首页、项目列表、项目概览与章节入口、管理、实验室、用户外观设置及两个画布入口。覆盖原有深层链接、浏览器前进后退、真实对象定位和任务在导航期间的连续性。
- 验证宽屏、桌面断点及手机布局的菜单可达性、浮层关闭与焦点恢复、溢出和遮挡。以最终 A 截图核对桌面紧凑标题、信息顺序和主要操作位置。
- 验证两种外观立即生效、两处选择同步、刷新恢复、无有效记录回退及存储不可用时的体验。切换后进入两类画布并检查画布和浮层。
- 验证真实数据、示例、空态和读取失败能被区分。示例无法触发虚构跳转。使用现有前端依赖和数据替身覆盖页面组合，正式实施完成后运行受影响的前端检查与类型检查。

## Out of Scope

- 数据库表结构、接口、跨项目轻量画布列表、项目生产进度汇总、完成率计算和制作状态规则改造。
- 实验室草稿隔离与持久化、按类型恢复上次访问会话、离开保护和失效链接恢复改造。
- 生成画布和场次画布内部布局、主题、操作或执行链路改造。
- 全站深色模式、跟随系统、跨设备同步、更多配色、动画渐变及首页模块自定义。
- 直接迁移原型路由、B／C 方案、切换条或内存模拟操作到正式产品。本轮产物为规格与原型记录。
