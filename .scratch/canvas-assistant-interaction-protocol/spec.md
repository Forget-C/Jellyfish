# Deep Agents 画布助手后续规格：创作对话、审批与执行恢复

Status: ready-for-agent

2026-11-23 · 基于已确认的 Q1–Q48。适用于自由画布、分镜画布及接入共用会话协议的文本、图片、视频实验室。

## Problem Statement

创作者对助手说「把镜头 03 的推近放慢，生成一版给我看」，需要知道助手选中了哪个镜头、会改哪个字段、什么时候开始生成。现有按钮审批能处理部分编辑，但对话框中的「确认」没有携带审批卡上的勾选组。还有一条已复现的路径：审批遇到字段冲突，后来字段恢复原值，同一请求重发却写入了画布。两种情况都使用户难以判断自己授权了什么。

一次创作还可能经历调整方向、回答问题、局部修订、浏览器关页和后台生成。仅凭聊天文字或转圈状态，用户无法判断哪些步骤已生效、哪些需要自己处理。实验室有相似的交互需求，但文本流和后台媒体任务各自有不同的停止与恢复方式。

## Solution

两种画布使用一个 Deep Agents 助手。用户可以直接提问，也可以复制镜头到对话、先讨论方案、在工作中补充指令，并逐项核对建议。专业方法由按需加载的 Skill 提供。画布服务按真实画布类型和用户对具体提案的授权执行操作。对话显示每组决定与执行回执，画布只用独立外阴影提示本次涉及的对象。

例如，用户复制镜头 03、04 后又选中 05，仍可要求「调整这两张」。用户仅批准 03 时，审批卡分别显示「03 已写入」「04 待审批」。若用户同时授权生成一版，视频提交后可从原回复查看任务。收起助手、恢复会话或重发原请求，都能核对同一份结果。

## User Stories

1. 作为自由画布创作者，我希望在提示词和允许的卡片上应用影视建议，以便直接改进画面，同时保持自由画布的卡片目录。
2. 作为分镜导演，我希望助手能创建、连接和修改已有规则允许的设计卡，以便把调度方案落到镜头。
3. 作为创作者，我希望普通文本模型也能读结构化的画布文字，以便使用当前模型讨论剧本、卡片和可见草稿。
4. 作为导演，我希望按需调用剧本规划、镜头调度、图片指导、视频指导和成片审看技能，以便让同一助手完成连贯的制作工作。
5. 作为导演，我希望先看镜头取舍和方案，再决定是否准备具体修改，以便先讨论叙事节奏。
6. 作为创作者，我希望粘贴单卡、多选或正式编组，并能核对引用，以便后续选卡不改变当前指令。
7. 作为创作者，我希望在编组变化或成员失效时看到具体对象，以便选择沿用、更新或调整本轮范围。
8. 作为素材审看人，我希望知道助手实际看过的帧、时段和音轨，以便判断建议适用于哪些素材。
9. 作为导演，我希望能查看分镜设计与素材审看子任务的进度、依据和失败原因，以便判断主助手交付是否完整。
10. 作为创作者，我希望运行中直接补充「只改 03，先别生成」，以便及时纠正尚未执行的步骤。
11. 作为创作者，我希望能将另一项工作排到下一轮，并在开始前编辑或移除，以便完成手头任务后再处理。
12. 作为导演，我希望用选项或自由文字回答创作问题，以便明确风格取向，同时保留待审批的生成请求。
13. 作为编辑，我希望在同一份提案里比较多组改动及其依赖，以便单独批准可独立生效的部分。
14. 作为编辑，我希望回复「确认」与点批准按钮作用于同一版本和同一组，以便直接在对话里执行决定。
15. 作为编辑，我希望在「时长 8 秒 → 5 秒」这一项上要求改为 6 秒，以便准确修订该字段并保留其他组的决定。
16. 作为画布负责人，我希望授权自动审批后仍能查明每组由谁批准、依据是什么，以便及时拒绝或收回授权。
17. 作为编辑，我希望冲突时保留手改，能在核对差异后单独决定是否再批准，以便网络重试不会替我做决定。
18. 作为自由画布创作者，我希望一次确认便能在新草稿上建两张卡并连接，以便整组保存并可撤销。
19. 作为分镜导演，我希望能看到改动共享来源会影响哪些镜头，以便只调整我点名的镜头。
20. 作为画布用户，我希望能用阴影识别提案目标，同时保留自己的选区、键盘焦点和卡片布局，以便对照建议继续编辑。
21. 作为画布用户，我希望查看旧提案时能识别已删除、已撤销或藏在折叠组里的目标，以便正确理解历史。
22. 作为创作者，我希望一轮结束后直接看到写入、冲突和生成状态，以便只处理真正需要我操作的事项。
23. 作为视频制作者，我希望关页后再次打开能接续待排版工作、找回已提交的视频，以便重连时只生成约定的版本数。
24. 作为文本实验室用户，我希望停止本轮输出，断流后仍能查看已收到的文字，以便根据可核实状态决定是否再次提交。
25. 作为图片或视频实验室用户，我希望直接提交、查看后台进度和回填历史配置，以便在原会话找到结果或主动生成新版。
26. 作为模型管理员，我希望查看具体型号和接入地址验证过的工具往返及媒体能力，以便选用能完成当前工作的模型。
27. 作为移动端或键盘用户，我希望输入、阅读历史和审批时维持焦点、滚动位置及工作台主题，以便在窄屏和中文输入法下顺畅操作。

## Implementation Decisions

### 助手、技能与画布能力

- 两种画布分别拥有会话，复用同一主助手。五项只读产品 Skill 为剧本拆解与画布规划、镜头与场面调度、图片生成指导、视频生成指导、成片审看。用户可通过 `/` 点名，主助手也可组合使用。保留实际使用的技能及版本。
- 助手读取当前画布摘要、相关卡片细节、可用操作目录和素材观察依据。在已授权范围内自主调查、规划和预览。工具型模型可原生调用；普通文本模型由应用提供文本事实并校验其结构化请求。文本阅读与工具往返分别判定。媒体观察受当前接入的实际输入能力约束，仅收到静帧时把结论限定到该帧。
- 模型管理沿用按供应商配置和型号记录的能力档案。分别表达文本、图片、连续视频、音频输入，文字输出、完整工具往返和已知的上下文上限；保留支持／不支持／未知、声明来源，以及与本次接入对应的验证结果。旧数据缺项按未知处理，变更接入地址后区分旧验证。能力元数据与发给供应商的生成参数分别管理。助手选型默认沿用全局文本模型，可按画布覆盖，独立于模型生成卡。
- 统一批量提案工具 `propose_canvas_changes` 表达修改字段、建卡、删除、建立或解除关系及同批新卡引用。编组、布局、素材采用和提交生成沿各自业务入口校验。自由画布允许基础、参考和模型生成卡；设计卡只在分镜画布按目录开放。服务端复核画布归属、目标、字段、合法连接及共享影响。局部镜头调整优先形成只影响所指镜头的方案。
- 主助手可向两个注册角色作一层委派：分镜设计、素材与连续性审看。委派指定任务、交付格式、材料身份和版本。原生委派与结构化委派使用相同的工具范围、并发及轮次预算。独立任务可并行，有依赖的依序执行。主助手核对候选结果，业务服务掌握写入与生成。子任务有稳定标识，恢复时复用已完成交付；停止后停止派发，迟到结果不进入提案。若审看失败，交付标明缺失，依赖该审看的步骤继续等待。

### 会话服务与引用

- 建立统一的服务接入契约，覆盖打开或恢复会话、发送一轮、读取快照和订阅有序事件。接入方声明支持的停止、审批、补充、排队和问题回复操作。具体 Agent、输入校验、持久化、任务执行和供应商调用由各业务接入方负责。事件和快照均能关联会话、轮次及相应动作，客户端可去重、补读和重建界面。
- 会话身份绑定业务归属与偏好。请求身份用于幂等受理；轮次身份关联回复、提案、子任务、审批及结果。补充指令和创作回答归入当前轮次，排队消息开始处理时进入新轮次。网络重试沿用原请求和原输入；历史回填后主动发送形成新请求。框架检查点供恢复执行，用户看到的事实取自业务记录。
- 会话快照能区分待回答的问题、可编辑的排队项、待决定的提案版本及各执行方回执。问题回复携带问题身份，补充指令指向活动轮次。已有会话、单组提案和历史结果仍可阅读；恢复旧记录只展示有依据的状态。快照和增量事件共用对象身份与顺序，重连后能核对遗漏或重复的更新。
- 两个画布统一使用一个输入入口，移除手动提问范围下拉。显式引用优先，其次采用提示词点名对象，当前选区解释其余指代。写入仍由提案审批决定。客户端提交用户输入、显式引用、选区、编辑器可见草稿和版本。服务端核对归属、实际能力及授权，按任务选用相关历史。在上下文受限时优先保留指令、目标版本、待修订差异和必要依据；大画布可按索引分批读。告知用户实际覆盖范围，详细依据可以展开。
- 粘贴与 `@` 共享对象引用。临时多选逐张可移除；编组为可展开的一项，显示组名、成员数和成员卡片。发送前可沿用旧成员或更新到当前成员，遇删除点明失效项。发送时固定来源画布和成员身份。明确对象优先，选区用于解释指代。普通文本按本次系统剪贴板粘贴；粘贴到助手引用现有对象，画布自身粘贴仍按其副本规则处理。跨画布只在有读取权限时引用，修改源卡需回到源画布审批。
- 实验室每轮模型输入独立，保留模态参数、素材、草稿、历史分页与回填。文本按轮流式传输，支持停止，断流或离开后保留部分输出并核对终态。图片和视频由后台任务承接，主动发送即授权该次提交，恢复查询原任务，结果归回原会话。三种实验室按自身能力复用协议和界面。

### 决定、事件与回执

- 审批单位是可独立生效的改动组。版本化提案列出目标、动作数量、形成建议时的字段值、拟议值、影响与依赖。组内改动一起应用，独立组逐组记录结果。写入前核对相关目标、最新字段与引用。冲突展示原值、当前值、建议值；一次应用进入现有撤销路径。
- 沿用 Deep Agents 的人机审批中断与检查点恢复机制，通过已记录的业务决定接续原执行。服务向客户端发布提案创建（`proposal.created`）、审批决定（`approval.decided`）、旧版本被替代（`proposal.superseded`）及执行成功、受阻或失败（`execution.succeeded`、`execution.blocked`、`execution.failed`）的事件，含事件身份、顺序、时间、目标版本和组。回复「确认」和按钮提交同一决定入口，仅一组明确待审可直接批准；多组按勾选，无勾选则提示。「全部确认」限于明确指向的一份提案。指代不清、版本失效先定位或核对。「确认，不过改为 5 秒」走修订。
- 每次主动审批具有独立决定标识，绑定来源、提案版本、动作及所选组。持久保存全部冲突、部分成功、拒绝和成功的逐组结果，保存成功与画布回执处于同一事务。重复提交同一决定返回原结果，字段随后恢复原值也不重新写入。用户看过新差异后可仅为受影响组作新决定。
- 自动审批按画布授权，默认人工。先由代码校验权限、字段、版本、数量及依赖，再由独立的只读审批 Agent 核对用户原话、范围、已有拒绝和真实影响，逐组给出依据与疑点。审批服务在签发前复查；语义不清、复核超时或输出无效转人工，业务校验失败显示受阻。删除、解除采用和生成需明确动作及目标，生成还核对数量。记录规则版本、审批模型、依据及来源。迟到结果不能推翻人工拒绝或已撤销权限；人工决定直接走业务校验。
- 未保存自由画布的首个获批组可含多张新卡及其连线。创建画布、应用整组、归档对话、记录回执在同一事务完成。失败保留本地草稿和待审项；成功但丢失回执时按原请求找回同一画布；未勾选组随原提案保留。
- 一次授权可列明编辑、布局与生成。画布服务、持编辑权的浏览器和 Worker 分别跟踪可恢复的动作及回执，只等待实际依赖。依赖提示词已保存即可依授权提交视频，纯展示排版可待编辑器重开后完成。生成前若输入实质变化则暂停该步并重新展示差异。结果未明先查原回执，追加一版需新授权。停止助手与取消已受理任务分别处理。

### 交互、审阅与依赖升级

- 升级分两步验收。先将现用 Ant Design 5 升至最新 5.x，处理弃用项；再升至与 Ant Design X 2.x 兼容的 Ant Design 6.x 与图标库 6.x，保留 React 18.2。完成全站依赖的工作台兼容性验证后接入 X 的消息列表、输入框、附件及可折叠进度等适用组件。业务审批卡、执行回执和服务协议继续由 Jellyfish 管理。
- 桌面用画布右侧图标打开约 420px 非模态面板，窄屏接近全宽。标题与输入区固定，消息区独立滚动，保留工作台配色和弹层归属。用户上翻时保持位置，提示返回最新进展。回车发送、Shift+Enter 换行，中文输入法选词回车由输入法处理。仅支持停止的活动提供停止入口。
- 工作期间输入框保持可用，默认补充到本轮，发送菜单可选择下一轮处理；等待消息可编辑或移除。补充改变范围后，旧提案版本停止接受批准。「先别生成」按受理事实回应；任务已提交则显示任务入口，结果未知先查回执。指向审批卡的确认仍按决定处理。
- `/plan` 或「先给方案」只进行读取、审看与规划。「按此方案继续」开始准备可审批提案。简单编辑可直接提出差异。需要用户选择且影响交付时，创作问题卡支持选项、自由回答、重开后继续；答复关联问题，不授权同时待审的动作。在单项差异上反馈绑定原版本、组及字段，重新展示受影响部分，保留其他独立组的决定。
- 原对话内的审批卡分别展示决定和执行回执。写入成功显示「已写入」，任务受理显示「已提交生成」，产物就绪后可查看结果。运行中用一行显示已核实的进度，展开看任务范围、模型、Skill、媒体读取情况和失败原因。有实际动作的轮次在末尾用同一批回执生成摘要，列出已完成、待处理和后台运行项，后续进展就地更新；纯咨询直接给专业答复。
- 用青绿色外阴影标出正在查看的一份提案版本直接影响的卡片，不改卡面布局，不占用编辑选区。只读参考留在依据中；新卡创建成功后出现；关系变动提示连线和端点。收起面板、继续输入或改选保留高亮，用户可隐藏，刷新恢复上次查看版本和选择。迟到回执只更新原审批卡。主动定位到画布可见区域，折叠成员定位到组框；已删除目标保留卡名与回执，关闭定位入口；撤销后原审批卡注明「曾写入，后已撤销」。

## Testing Decisions

复用以下三处外部边界。通过条件取自用户可见状态、实际画布内容、公开事件与回执、真实任务提交次数。自动化使用可控模型与已知素材；无需依赖模型恰好输出某句文案或框架内部节点的排列。

### 1. 双画布和三类实验室的真实页面

| 用户场景 | 可核对的结果 |
| --- | --- |
| 自由画布与分镜画布分别提出「改镜头 03、生成一版并审看」 | 自由画布只写允许的卡片和提示词。分镜可新建设计卡，镜头 03、04 共用来源时仅改预期范围。审批前相应提交数为零，批准后生成一版；审看依据关联该版实际媒体。 |
| 粘贴 A、B 后选 C；正式编组从 4 张增至 5 张，或原成员被删除 | 消息仍引用 A、B；可核对、沿用或更新成员。失效项被点明。复制一段普通文本后粘贴得到该文本。没有写权限的跨画布引用不会改写源卡。 |
| 从方案开始，回答问题、工作中补充和排队；对时长差异要求改为 6 秒 | 计划只读；选择创作方向后待审生成仍待审。待处理消息可编辑或移除；补充「先别生成」准确反映受理状态。字段反馈只修订关联项，旧版本失效。 |
| 多组勾选后回复「确认」，再试无勾选、全部确认、歧义、过期版本 | 文字与按钮产生一致的逐组结果。无勾选或指代不清时先澄清，旧版本不能批准；同时看最后一条摘要和实际卡片即可核对。 |
| 切换提案、关面板、刷新、定位折叠成员、删除或撤销卡片 | 读过的卡片不误亮，原选区保留。迟到回执不切换当前高亮；隐藏状态恢复；删除与撤销均在历史里有据可查。 |
| 文本停止或断流；图片和视频生成后离开、重开、回填并主动再发 | 文本保留已收到内容，未核实终态有提示。媒体恢复原任务及结果；回填后的主动提交开启新轮次，保留本模态参数与素材。 |
| 先回归依赖升级，再验收 X 组件 | 单独验证全局与工作台主题、下拉框和弹层挂载、桌面及窄屏；再验证助手固定输入、历史滚动、键盘焦点、中文选词回车和审批反馈。沿用双画布 Chromium 旅程与实验室真实页面及隔离 SSE 用例。 |

### 2. 公开会话接口、模型管理和供应商

- 以同一任务走原生工具和普通文本两条路径，检查显式引用、草稿以及用户可见的读取依据，分别覆盖未知能力、静帧、连续画面和音轨。两类模型均可处理画布文字，能用的工具和收到的媒体以实际接入为准。
- 用可控模型组合五项 Skill 中适用的方法，并分别验证简单任务直接交付、两个注册子 Agent 并行或按依赖执行、部分审看失败、停止后迟到结果。核对产出的提案、依据范围和版本，复原后已完成子任务只计一次。
- 开启自动审批，覆盖明确编辑、数量不明的生成、推断删除、复核失败、并发人工拒绝和撤回授权。通过公开快照与事件验证逐组来源及结果。提问、补充、排队和决定送入各自的交互操作；同屏回答偏好不产生生成授权。
- 沿用模型管理的能力验证入口，对真实供应商另做完整工具往返和媒体实测。使用已知样片比较单字段编辑与全场审看，记录型号、接入、实际收到的模态、目标命中、时段依据、调用数、耗时和 token 消耗。受控结果与实测结果分别报告。

### 3. 隔离 MySQL、Worker 与持编辑权的浏览器

| 中断或并发点 | 恢复后必须成立 |
| --- | --- |
| 手改目标导致全组冲突，随后字段恢复原值，重发原决定 | 返回同一冲突结果，画布修订和生成次数不增加。用户看过差异后另作新决定才可写入。混合组中已成功项只应用一次。 |
| 首次批准「建两卡并连线」；另测非法连线、成功后响应丢失 | 校验失败整组回滚并保留本地草稿；成功后重试仅有一张画布、两张目标卡、一条连接、一份决定记录，余组仍待审。 |
| 等待审批或创作回答时断线；签发期间人工拒绝、版本修订或停止主轮次 | 服务恢复同一待办和可核对的状态。迟到决定及子任务不会覆盖较新的用户操作；刷新不会自行批准或重跑已完成步骤。 |
| 提示词已写入、排版等待编辑器、生成已受理但回执传送中断；重启 Worker 并重开画布 | 三个动作分别恢复。浏览器只接续待执行布局，原授权只产生一版视频。执行依赖变化时受影响步骤等待新批准，原轮次摘要随回执更新。 |

沿用现有审批重放、字段冲突、草稿转正式画布、浏览器布局回执和 MySQL／Worker 重启用例，扩展至上述异常次序。上轮 SQLite 隔离复现的「先冲突、字段还原、同决定竟成功」是必须通过的回归，原按钮审批通过不能替代这条验证。

## Out of Scope

本期只提供两个注册创作子 Agent 和一层委派。自由画布沿用现有目录。跨画布引用仅供有权读取的参考使用。通用 Agent 市场、任意递归委派、跨画布批量写入及其他站点页面改版均不在本期交付范围。实验室沿用各自生成语义，画布的分组审批与排版只适用于画布。
