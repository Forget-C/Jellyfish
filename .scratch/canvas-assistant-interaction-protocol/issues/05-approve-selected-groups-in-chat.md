# 05: 回复「确认」写入勾选组

Status: ready-for-agent
Blocked by: 01, 02

**What to build:** 将对话确认与按钮接入同一个业务决定入口，在原审批卡核对用户所见版本、选中组和最终回执。

对应[后续实现规格中的用户故事](../spec.md#user-stories) 13、14、15、17。

## Acceptance criteria

- [ ] 分别通过回车发送与按钮验证单组确认、多组选中部分、无勾选提示及明确的全部确认；两种入口对同一目标给出相同的生效范围。
- [ ] 多份待审提案指代不清时先选择目标，过期版本须展示更新内容。「确认，不过改为 5 秒」先准备修订。上述情况下不写入原提案。
- [ ] 从暂停的 Deep Agents 执行接续对应决定；界面分别展示已批准、已写入或受阻。刷新或重复提交时保持原决定和回执，画布高亮不会扩大批准范围。

## 实施进度

提交 `5e4a2f5c` 已将对话确认和按钮写入接到同一审批入口，双画布浏览器用例覆盖单组、无勾选和勾选部分组。后端目前在提出提案后结束模型轮次，尚未接续暂停中的 Deep Agents 图。该项及审批状态事件仍待完成。

## Comments

### 实施与验证记录

在对话中回复「确认」走提案决定入口，保留所勾选组、版本及业务回执。原生 Deep Agents 从对应审批中断点接续。受控浏览器核对生效前后的已保存内容和待审组，后端覆盖陈旧版本和决定重放。
