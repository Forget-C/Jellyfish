# 04: 普通文本模型读取画布与素材依据

Status: ready-for-agent
Blocked by: None

**What to build:** 让普通文本模型和原生工具模型都能讨论当前文档与可见草稿，并让用户核对实际可用的读取依据。

对应[后续实现规格中的用户故事](../spec.md#user-stories) 3、8、26。

## Acceptance criteria

- [ ] 同一问答分别使用应用提供的画布文本及原生工具往返，核对卡片身份、未保存字段和真实目录；结构化请求须经服务端归属、权限和能力校验。
- [ ] 大画布按索引分批或受上下文预算限制时，保留点名对象、待修订差异及必要草稿，在对话中说明实际覆盖部分。跨会话素材有明确引用和读取权限。
- [ ] 分别演示不可读媒体、静帧、连续画面和音轨；展开依据得到实际时点、区间或未读取说明。仅有静帧时不声称审看了完整动态画面。
- [ ] 核对具体型号及接入的模态声明、文字输出、工具能力、上下文上限和实测来源。旧数据缺项为未知，切换地址可识别旧验证，画布助手模型可独立于生成卡切换。

## 实施进度

提交 `5e4a2f5c` 已实现普通文本模型只读能力。自由画布和分镜画布使用锁定选区、可见草稿和真实卡片目录，现有工具模型与媒体路径继续可用。20 个相关后端用例通过，1 项依赖隔离 MySQL 的用例跳过。大画布分批及逐次覆盖记录仍待实现。

## Comments

### 实施与验证记录

已实现普通文本的带预算画布上下文及原生读取工具。双入口浏览器覆盖同一目标和未保存草稿，后端覆盖权限、分页和媒体证据。独立助手模型切换不改变生成卡模型。实际供应商声明与输入接收情况见 22。
