# 07: 未知请求核验与关闭恢复

Status: ready-for-agent
Blocked by: 06

**What to build:** 保存结果未知或页面关闭后，用户重新进入工作台仍能找回输入，系统先核对最新服务端和原请求结果，再恢复保存或显式处理冲突。已经授权的保存并生成请求不会因重试产生新的生成意图。

**依据：** [实现规格](../spec.md)；[共同执行规则](../README.md)。前置：[06 周期保存与错误处理](06-periodic-save-and-error-handling.md)。

## Acceptance criteria

- [x] 本地恢复保留确认基线、当前编辑内容、既有撤销／恢复依据及必要的原在途请求信息；布局或 graph 缓存不能替代编辑恢复。
- [x] 结果未知时，原 `request_id`、`expected_revision` 与发送内容完整保留；先核验或原样重放，期间新输入不并入原请求。
- [x] 原请求成功后，确认基线先推进；若仍有更新输入，再以新 revision 和新请求保存，不误判新内容已保存。
- [x] 响应内容、revision 或 graph 不满足契约时，不清空输入或宣布成功；保留证据并通过既有读取／重试机制核验实际结果。
- [x] 重新进入先核对最新服务端。服务端未变时正确恢复；已推进时识别原请求结果或进入显式冲突，不直接用旧本地内容覆盖服务端。
- [x] 尊重后端仅保留最近保存请求幂等信息的限制；其他保存已推进时，旧请求不被当然认定成功，不增加任意历史请求账本。
- [x] 保护另一尚未处理的恢复记录，沿用既有存储边界；不新增无限多版本恢复缓存或额外草稿概念。
- [x] 浏览器存储不可用时准确提示恢复能力受限，当前可保留输入不被清空，不虚报已保存到服务端。
- [x] 已有保存并生成操作仅核验／重放原授权和原请求，不将重复核验视为新的生成、重试生成或新的业务动作。
- [x] 恢复后继续使用 06 的同一队列和错误分类，四个画布与其切换得到相同保护；只读历史不会因恢复进入可写状态。

## Validation

- API 模拟原请求已提交但响应丢失、未提交、再次请求已推进 revision、响应不符合契约等状态，验证真实持久化及请求身份。
- 浏览器关闭并重新打开，分别验证服务端未变、原请求已成功、其他写入已推进、本地还有更新输入及另一待恢复记录。
- 受控测试存储失败、重新进入冲突、恢复后周期／手动保存；不得只断言恢复提示存在。
- 使用已有保存并生成流程的受控测试替身验证核验／重放不新增业务意图，不调用真实生成服务产生素材。
- 承接 A13 的未知结果、A14 的恢复冲突、A15、A18 的响应／存储／只读保护、A19；新 graph 组合由 08 验证。执行相应前后端检查。

## Scope and handoff

在现有本地暂存、请求核验、幂等和冲突机制上补齐行为，不另建持久化系统或扩大生成授权。06 负责在线调度，本票负责未知结果及中断恢复的完整性，两者合并成同一工作台机制。
