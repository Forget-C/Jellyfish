## Acceptance criteria

- [x] 两类 graph 同时接入版本读取／保存；后端使用同一基础协议、图工具和完整性规则，前端使用共同容器、导航、聚合预览及布局状态，无第二套业务事实推断。
- [x] 新增单元后保存失败、关闭详情再进入、随后关闭页面恢复，当前输入始终可达；无强制提前保存、临时前端业务图或额外草稿工作区。
- [x] 提交 A 后输入 B，在图 A 到达、周期重试、画布切换和页面恢复的组合中，基线与当前输入正确分离，随后保存 B 使用正确 revision。
- [x] 当前删除或调整对象后旧图不会错绑目标；保存后的稳定节点位置、筛选及历史导航保持正确，临时目标不跨 revision 复用。
- [x] 外部模型／文件／落幅证据在场次 revision 不变时改变，界面如实表达未知或待复核，实际编译／预检／试拍重新校验输入。
- [x] 完成配置 → 参考 → 编译审稿 → 能力检查 → 试拍 → Take 回看旅程，任务业务回跳定位精确，生成成功不自动采用或声明实际覆盖完成。
- [x] 多覆盖项单元、固定历史、声音／后期、只读内容与执行限制在完整旅程中保持原语义；没有扩大跨镜头或批量生成能力。
- [x] 导演和单元迁移完整，清理本次替换后无用的前端拼图、导入及无效临时代码；不存在图失败时回退业务拼装。指令和剪辑 graph 保持本轮范围边界。
- [x] 实际页面、窄屏、键盘、聚合预览、来源详情和保存提示符合工作台规范；四个画布共同保存与恢复均有证据。
- [x] A01–A20 有完整验收归属与结果；复用相同代码／环境下通过的检查，为集成改动、缺失组合或新疑点补充验证，修复相关问题后回归受影响范围。
- [x] 对外接口、OpenAPI 和 generated client 一致；必要类型检查、后端测试／静态检查及所选实现流程额外检查完成，未通过项明确记录。
- [x] 按真实落地结果更新当前架构和计划状态，记录未完成项及限制；不得仅因票据已发布或前置已完成而提前声明全部验收通过。

## Validation

- 以真实前端和受控后端测试环境执行完整旅程及故障组合，使用可观察界面、实际持久化内容、revision 和请求身份作为证据；不产生真实外部付费生成。
- 共同图规则同时验证两个投影器；端到端响应核验与后端并发／幂等行为配套检查。
- 优先补齐 A12、A16、A17、A18、A19 的组合路径及 A20 全流程，其余 A01–A20 按前置证据和集成影响决定复用或回归。
- 汇总通过、失败、未运行项及原因；截图用于交互与布局证据，不代替保存、恢复、冲突或实际执行检查。

## Scope and handoff

本票承担集成修正和完整验收，不接收前置票据尚未完成的主体功能作为隐含待办。只清理本次替换引入的无效内容，不扩大到无关画布重构或历史数据迁移。全部必要工作完成后再按实现工作流结项。
