# 04: 单元配置卡与新增操作闭环

Status: ready-for-agent
Blocked by: 03

**What to build:** 用户从动作覆盖、生成配置和组织要求摘要卡进入对应详情编辑，新增或 AI 设计单元时明确目标镜头；修改经过既有保存机制回读成新的服务端图。新增后即使保存失败，也能重新打开该单元继续编辑。

**依据：** [实现规格](../spec.md)；[共同执行规则](../README.md)。前置：[03 单元 graph 浏览](03-unit-graph-browsing.md)。可与 05 并行，不等待周期调度改造即可验证本票行为。

## Acceptance criteria

- [ ] 动作覆盖逐项显示镜头、动作范围及显式执行选择，编辑目标包含准确单元与覆盖项身份；多个覆盖项不只展示或修改第一项。
- [ ] 生成配置详情提供模型、时长、生成画幅、种子及额外参数，沿用已有模型能力、字段校验和保存契约。
- [ ] 组织要求展示入幅、出幅、待准备参考要求，来源和理由进入详情；待参考要求不被显示为已绑定素材。
- [ ] 三类卡面由后端提供摘要和缺项；详情读取当前编辑内容，应用／取消沿用既有边界。修改后保存并重读，图与内容一致。
- [ ] 全部镜头视图下新增或 AI 设计先明确选择一个目标镜头；单镜头视图使用当前镜头。已有单元的来源／目标使用精确身份，不从自然语言、名称或数组位置猜测。
- [ ] 复用原 AI 建议审阅、应用／取消及保存行为，不扩大跨镜头或批量生成，不改写六岗设计、其他单元或固定历史。
- [ ] 新建或编辑后图仍表示服务端基线，界面明确待同步；未保存新单元可从既有编辑／选择入口重新进入，不强制提前保存、不补造前端临时 graph、不新增草稿工作区。
- [ ] 保存失败、关闭详情再打开及本地删除／修改旧图目标时，保留当前输入，不错绑其他对象；响应迟到也不覆盖更新内容。
- [ ] 当前多 coverage 执行限制与其他业务校验继续有效，能保存／浏览不被误当作能直接执行。

## Validation

- API 验证配置修改的保存回读、各覆盖项身份、非法输入和现有范围保护；改变对外载荷时同步 generated client。
- 浏览器完成三类详情的应用、取消、重新打开、手动保存和图更新；覆盖全部／单镜头新增与 AI 建议确认流程。
- 注入保存失败，验证新增单元关闭详情后仍可找回编辑；验证旧图目标本地失效和迟到响应。不依赖 06 才能证明现有编辑保护成立。
- 承接 A04、A05 的三类配置、A16；与新周期保存组合的场景由 08 验证。执行本票相关前后端检查。

## Scope and handoff

前段依赖卡、真实参考绑定和只读执行依据由 05 负责。本票只替换涉及的原设置编辑入口和无用拼接逻辑，不改变存储身份、AI 生产组织方法或视频执行能力。按单元内容 patch 更新，避免与 05 的其他配置互相覆盖。
