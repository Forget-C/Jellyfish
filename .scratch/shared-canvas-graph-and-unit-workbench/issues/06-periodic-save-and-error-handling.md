# 06: 四画布周期保存与错误处理

Status: ready-for-agent
Blocked by: None

**What to build:** 用户在四个画布持续编辑时，工作台每 5 秒检查并保存未保存内容；手动保存使用同一队列。普通失败持续可见并可重试，校验和冲突分别处理，任何迟到响应都不覆盖新输入。

**依据：** [实现规格](../spec.md)；[共同执行规则](../README.md)。本票可在现有画布和协议上验证，不依赖新 graph，可与 01 独立开展。

## Acceptance criteria

- [ ] 默认每 5 秒检查是否有待保存内容，不要求停止输入；无修改不请求，有在途请求不并发提交，不增加周期配置页面。
- [ ] 手动保存、周期保存和重试复用现有串行队列及本地编辑状态，连续点击不会生成并发保存。
- [ ] 一次发送固定版本、`expected_revision`、`request_id` 和发送内容；新输入保持在当前编辑内容中，不混进在途请求。
- [ ] 响应核对版本、预期 revision 推进、请求身份、发送内容及已有 graph 一致性；成功仅推进确认基线，不把之后的输入标为已保存。
- [ ] revision 8 提交 A 后继续输入 B，A／revision 9 返回时 B 仍存在且待保存；随后以新 revision 和新请求提交 B。
- [ ] 暂时性失败保留可见错误和全部输入，允许下周期或手动重试；复用原在途身份，不能因结果未知而创建携带新内容的替代请求。
- [ ] 校验失败定位问题并等待修改，不每周期重发相同非法内容；修改后可再保存。revision 冲突沿用显式处理，不盲目重试或自动覆盖服务端。
- [ ] 后端继续进行原有版本比较和请求幂等校验；按需要修正缺口并验证，不能另建保存协议或任意历史请求账本。
- [ ] 四画布及其切换都使用同一保存规则，切换不遗漏输入或创建第二个调度队列；图基线和当前输入继续分离。
- [ ] 当前恢复机制与未知请求保护不回退；07 可继续在此队列上核验重新进入后的恢复，不需要另起保存系统。

## Validation

- 受控浏览器时间／响应验证连续输入、无修改、周期边界、重复点击、慢请求及画布切换；同时观察持久化内容、请求身份和当前输入。
- HTTP 验证 revision 并发保护、原请求重试与校验错误；浏览器验证错误分类、提示保留、修改后恢复保存和显式冲突处理。
- 复用已有编辑期间保存响应测试，补齐真正按周期和失败后可再尝试的回归；不只断言计时器或私有调用次数。
- 承接 A11、A12、A13 的在线失败部分、A14、A17 的四画布共用保存部分；新图组合由 08 验证，关闭恢复和未知结果强化由 07 负责。完成必要前后端验证。

## Scope and handoff

修改现有调度和失败处理，不迁移 graph，不增加领域草稿或保存入口。保持对既有返回图的校验方式，与图迁移集成时校验响应中实际提供的两类图。向 07 提供稳定的串行队列和保留原请求的重试行为。
