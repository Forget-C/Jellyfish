# 06: 提交失败恢复与重复生成防护

Blocked by: 02, 04
Status: ready-for-agent

来源：[实验室统一规格](../spec.md)，分区五的提交、配置读取与恢复规则。主要用户故事：48–53、55。

**What to build:** 用户通过自由输入、已应用模板和参考素材提交实验，在校验或创建失败后保留完整工作，明确区分读取重试和再次生成；请求结果不明确时先核对已有记录，避免重复任务。

## Acceptance criteria

- [ ] 文本、图片、视频在校验失败、上传失败或任务创建失败时保留完整提示词、变量和已应用选择，错误可定位并可继续编辑，不提前清空草稿。
- [ ] 服务端确认接收前保留输入。接受状态依据现有文本流事件或异步任务返回的真实身份判断，不能把点击发送、开始请求或本地乐观占位视为已经接收。
- [ ] 请求进行中及当前生成锁定期间阻止重复提交，快速双击或重复快捷键不产生多个创建请求；状态恢复后主要操作仍可用。
- [ ] 提交结果不明确时先通过已有历史或任务信息核对。没有可靠任务身份或核对仍失败时显示未知，不自动重发、不编造身份，也不宣称未创建成功。
- [ ] 创建失败、任务执行失败和状态读取失败分别呈现。实际执行失败可回填修改后由用户明确提交；读取失败及重试不会触发创建。
- [ ] 配置读取中的模型、模板与素材各自区分加载、空数据和错误，刷新失败保留上次数据和当前输入；字段未知不当作零数量、未配置或成功。
- [ ] 已应用模板和视频／图片参考在失败恢复后仍与摘要一致，再次明确提交使用当前输入；取消的配置不被恢复逻辑重新带回。
- [ ] 在流式回复失败或请求延迟返回时恢复本轮必要上下文，不把旧请求结果写入不同会话，也不覆盖用户后来修改的新输入。
- [ ] 成功接收的提交与后续新编辑可以区分，保留显示的已提交配置不自动成为新草稿；系统自动选择默认模型、查看预览和取消面板不算有效用户修改，为离开保护提供可靠行为基础。
- [ ] 不因提交结果核对而改变现有任务持久化语义、引入后台重试生成、扩展接口或新增服务层。与结果展示票据保持一致的状态口径，但可通过现有历史独立验证本票。

## 验证要求

- 在真实页面与隔离 HTTP／SSE 边界覆盖三种模式的成功、校验失败、创建失败、流式错误、慢响应、请求结果不明确及重复提交；检查对外请求次数、真实身份与失败后可见输入。
- 分别用自由输入、模板变量、图片参考及视频主体／帧配置执行提交恢复，验证恢复后的再次提交携带正确内容。
- 模拟已接收但响应中断，通过既有历史／状态核对；再模拟核对失败，验证显示未知且无自动重复创建。检查读取重试、回填及媒体重载均不生成。
- 运行前端类型检查及受影响回归，测试数据隔离，不调用付费供应商或修改真实业务数据。
