# 05: 消息阅读、媒体预览与状态展示

Blocked by: 01
Status: ready-for-agent

来源：[实验室统一规格](../spec.md)，分区四及分区五的历史读取与任务状态展示。主要用户故事：36–47、51–53、61–63。

**What to build:** 用户在三个实验室中阅读清晰、宽度合理的消息和媒体结果，按需查看完整图片或视频，准确理解任务状态，并在历史更新和读取失败时保持阅读上下文。

## Acceptance criteria

- [ ] 消息按身份与状态、正文或媒体、轻量操作三层呈现。身份使用小图标与辅助文字，语义色保留给状态并配文字／图标，不反复使用抢眼身份标签。
- [ ] 短消息随内容收缩，长文本限制阅读宽度，建议约 80 个字符宽度及 1.6 行高；模型回复使用白色表面，不让短句占满宽色块。
- [ ] 单图最大宽约 480px，两张可双列，多张依结果区实际宽度排列；保留完整比例。竖图同时限制展示高度，尺寸是上限而非强制放大值。
- [ ] 视频常规预览宽约 360–480px，按容器收缩并保留比例；竖视频限制高度，播放指引常驻，历史列表不自动播放。
- [ ] 图片查看层支持同条结果内切换，视频查看层提供播放控制且关闭立即停止。查看层不超出视口，完整内容和关闭操作可达。
- [ ] 媒体加载中和失败均有稳定占位，失败允许重载，不出现破图或明显布局跳动；重载不发生成请求。
- [ ] 用户消息保留回填入口，沿用现有回填功能且不立即提交。缺失历史模型或素材配置时说明需要重新选择，不推测补齐。覆盖保护由模板配置票据落实，不作为本票独立验收的前置依赖。
- [ ] 区分排队、生成中、已完成、失败和已取消。系统等待文案随实际任务状态更新，终态不同时显示等待结果，原始用户提示词保留。
- [ ] 仅显示可靠进度，未知不模拟百分比。状态读取失败显示“状态暂不可用”，不变成任务失败或成功，轮询失败不反复弹通知。
- [ ] 历史首次加载、成功为空、首次失败与刷新失败有不同反馈；刷新失败保留已显示消息和当前输入，重试读取不创建任务。失败原因及恢复入口就近呈现。
- [ ] 用户正在阅读旧消息时新内容不强制拉到底部，提供回到最新入口；加载更早消息后阅读位置稳定。
- [ ] 预览具有可访问名称和键盘操作，Esc 只关闭最上层，关闭后恢复触发焦点。不增加下载、收藏、入库或独立重新生成按钮。

## 验证要求

- 使用真实页面、隔离历史及任务响应、本地可控媒体，覆盖短／长文本、单图／多图、横竖媒体、破图、任务状态流转及状态未知。断言可见文案与媒体行为，不依赖组件内部结构。
- 验证图片切换、视频关闭停止、媒体重载零生成请求、历史读取失败保留结果、滚动位置及键盘焦点。结合截图和几何检查媒体尺寸，不只检查截图。
- 在常规桌面、低高度和窄屏检查两种主题。运行前端类型检查和受影响浏览器回归，不调用付费生成。
