# 模型供应商协议与能力声明

Status: ready-for-agent

## Problem Statement

管理员可以通过自定义 Base URL 接入网关，但网关支持文本聊天，并不能据此判断它是否能处理工具调用、编辑参考图或生成特定时长的视频。现有模型声明和各供应商的能力表分别描述这些限制，部分判断还依赖画布。用户可能在模型页面选到某个参数组合，到提交时才发现业务入口无法执行。

维护者也面对同一问题：Worker 和供应商适配器都在处理部分媒体请求。修改某一处请求映射，无法保证画布、实验室及其他调用方都得到同样的结果。

## Solution

通过统一的供应商协议发现模型、按操作查询能力、校验请求并执行调用。管理员可以为同一接入方式创建多份供应商配置，在每份配置下手动录入模型和能力。模型管理页面同时展示声明值、来源及模型有效能力，业务入口据此展示和提交请求。LangChain Agent 通过专用适配器使用同一协议。

## User Stories

1. 作为管理员，我希望从远端或内置目录选择模型并查看目录来源，以便判断可发现的型号。
2. 作为管理员，我希望按模型 ID 手动添加目录外的型号，以便接入兼容网关。
3. 作为管理员，我希望同一模型 ID 在不同供应商配置下分别保存能力，以便反映各网关的实际差异。
4. 作为管理员，我希望修改 Base URL 后直接使用新地址并沿用模型绑定和声明，以便在已知变更后继续工作。
5. 作为管理员，我希望按操作填写输入输出模态、工具与流式支持，并将未知项留空，以便准确表达已知能力。
6. 作为管理员，我希望为不同生成模式和分辨率填写时长区间或离散值，以便保留供应商的真实组合限制。
7. 作为模型管理用户，我希望区分内置默认、管理员声明和适配器可用范围，以便知道某一选项为什么可用或不可用。
8. 作为模型管理用户，我希望自己决定何时发起真实能力验证，以便控制模型调用和费用。
9. 作为生成用户，我希望预检和实际提交指出相同的参数冲突，以便一次修正请求。
10. 作为画布或实验室用户，我希望普通文本响应和原生流式响应均可用，以便按场景一次取得结果或逐段阅读。
11. 作为 Agent 使用者，我希望工具调用及结果回传保留对应关系，以便模型在同一轮并行调用多个工具后继续回答。
12. 作为 Agent 使用者，我希望既有同步、异步和结构化输出流程保持可用，以便继续使用原有工作流。
13. 作为图片生成用户，我希望编辑参考图和批量生成后按原顺序取得所有图片，以便正确选择候选结果。
14. 作为视频生成用户，我希望已受理的任务在 Worker 重启后继续查询，以便取得原任务结果并避免重复生成。
15. 作为用户，我希望区分本地停止等待、取消请求已受理和远端已取消，以便判断生成是否真正终止。
16. 作为供应商接入维护者，我希望按操作复用已兼容的适配器，并为独有协议显式注册实现，以便修正一次即可覆盖所有业务使用者。

## Implementation Decisions

- **注册与配置。** 注册表将供应商接入方式解析到适配器，绑定当前或任务冻结的配置，注入共享 HTTP 客户端。兼容性按操作判定。未知供应商返回配置错误；目录外型号可按 ID 查询，未知能力保留未知或标明供应商默认值的来源。
- **能力契约。** `list_models` 返回模型及目录来源；`describe_model` 返回指定配置、模型及操作的能力；`validate` 对具体请求给出字段或组合诊断。模型能力声明支持“支持／不支持／未知”，未填写的数值表示未知。管理页面可补充、收窄或覆盖内置默认值，有效能力受适配器实际可编码和可解析的范围约束。普通文本保留既有兼容行为，需要工具等能力的自动流程按有效能力选模。
- **表单与校验。** 按所选适配器的操作展示字段。页面、预检与发送前校验使用同一组规则；一次操作的输入支持不自动延伸到其他操作。

| 操作 | 可声明字段 |
| --- | --- |
| 文本与多模态理解 | 输入和输出模态分别声明，非流式响应、原生流式响应、最大输入及输出 token 数。 |
| 工具与结构化输出 | 工具调用与结果回传、流式工具参数、并行工具调用、JSON 对象输出、JSON Schema 结构化输出。 |
| 图片生成与编辑 | 文生图、参考图生成、编辑；按模式声明尺寸、分辨率、宽高比、出图数、参考图数以及 seed、水印。 |
| 视频生成 | 文生、首帧、首尾帧、关键帧和主体参考；按模式和分辨率声明时长与宽高比，限制参考素材类型、数量及组合。分别描述音频参考输入、原生音轨输出和音轨开关。 |
| 交付与取消 | 按操作声明直接返回、远端任务、原生流式、远端取消，限于适配器支持的方式。 |

- **配置变更。** 同名型号分别归属于各自供应商配置。保存新的 Base URL 后，新调用使用新地址，保留原绑定和手动声明。该操作不检查历史数据、不触发提示、复核、探测或调用阻断。真实模型验证仅由用户主动发起。
- **调用。** `ModelProvider` 独立于业务及 LangChain。公共 I/O 采用异步接口，`invoke` 返回完整结果或已受理的远端任务引用；调用方决定是否等待。文本保留消息、工具调用、结束原因和可用的用量信息。媒体保留结果数量及顺序。`stream` 以异步迭代交付原生增量、结束和错误事件。按调用 ID 关联工具及结果，支持并行参数分块。不支持的操作在向供应商发送前返回明确诊断。
- **任务生命周期。** `poll` 对已有引用执行单次查询。`cancel` 按远端支持情况发起取消，分别表达不支持、已受理、已确认。关闭流或结束本地等待只影响本地消费。Worker 负责冻结配置、持久化引用、调度查询及归档；提交结果未知时保留不确定状态，查询失败时围绕同一引用处理。
- **业务及框架边界。** 工具执行、审批和结果采用由使用方负责。`LangChainChatModelAdapter` 在框架侧提供 `BaseChatModel`，转换消息、工具定义、工具结果及流分块。同步 Agent 的等待由调用侧承接；冻结参数、回调与流式语义随迁移保留。
- **迁移。** 核对并复用文本客户端、媒体输入、请求构造、状态及结果解析。逐个迁移操作后收敛重复 HTTP 路径，模型能力判断从画布移入供应商层。现有模型工厂仅供过渡；同步、异步、工具及结构化输出通过回归后移除旁路。

## Testing Decisions

通过以下三个已确认的公开入口验证行为。沿用已有模型管理、供应商适配、Worker 恢复及 Agent 测试的夹具，在供应商 HTTP 边界提供可控响应和事件。断言用户可见结果、真实发出的请求数量和内容、原任务可恢复性；测试不依赖适配器私有方法。

1. **模型管理页面与 API。** 验证目录发现、来源、手动录入、配置隔离、声明与有效能力的区别。设置同一模式在 720p 允许 5～15 秒（含端点），在 1080p 只允许 5 秒或 10 秒。验证两个端点、区间外值，以及 8 秒在前者通过、后者被预检和提交拒绝，拒绝时没有上游请求。保存新 Base URL 后，原绑定与声明可用，新调用到新地址，没有变更风险提示、自动探测或复核阻断。
2. **生成任务入口与 Worker。** 同步图片及参考图编辑覆盖 URL 和 Base64 返回，核对多结果顺序。异步视频只创建一次，Worker 重启后用原冻结配置及远端引用查询并归档。分别模拟提交后断线和查询暂时失败，核对没有重复创建。远端取消覆盖不支持、请求已受理、供应商确认三种结果；停止本地等待不得误报远端已取消。
3. **Agent 调用入口。** 通过 LangChain 适配器分别运行同步、异步及结构化输出流程。用交错的流分块模拟两个并行工具调用，验证参数各自拼接完整、结果按正确 ID 回传、模型完成下一轮回复。核对终止和错误能传回消费方。

## Out of Scope

本次不引入新的供应商品牌或页面可编程的自定义请求协议，不改变业务审批、工具执行权限或生成产物采用规则。端点变更历史审计、自动付费探测和公共协议的阻塞式 Python 方法均在范围之外。

## Further Notes

架构依据为 ADR 0020《模型供应商协议与能力声明》。术语沿用“供应商配置”“模型能力声明”“模型有效能力”和“模型能力验证”。规格状态表示可进入实现规划，功能状态仍为待实施。
