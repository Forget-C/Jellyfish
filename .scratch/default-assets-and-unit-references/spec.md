# 默认资产与单元参考解耦及卡片入口整理

Status: ready-for-agent

日期：2026-10-22

本规格汇总 2026-10-21 至 2026-10-22 的最终设计决策与代码核查结果。用户已确认以场次版本 HTTP 行为和真实画布浏览器流程作为两个主要测试边界，以已有契约测试补齐分组及清理的异常组合。生成测试使用受控替身，不调用付费模型。规格发布表示需求可进入任务拆分与实现，不表示功能、数据清理或验收已经执行。

## Problem Statement

导演画布的部分普通对象卡同时提供整卡点击和“编辑此卡”，两者打开相同编辑内容；多个动作有时纵向堆叠，占用卡片空间。导演的“编辑资产绑定”和单元的“编辑本单元参考”名称与容器不同，但界面没有充分解释两者的业务区别。单元参考卡还把只读查看和参考管理分成两个入口，增加了操作选择。

当前导演资产绑定既表达本场参与对象或场所与项目资产的对应关系，又成为单元选择资产图片的前置条件。选择器只列出设计已关联的资产，后端还要求参考来源与设计关联一致。用户希望导演提供可选的默认资产，单元能够为同一个场内参与对象独立选择素材，而无需先修改导演设计。

这种耦合也影响已有内容：修改或解除默认关联，可能使原本合法的单元参考无法保存；来源资产删除或移出项目，即使固定图片仍可访问，也可能阻断工作。除参考来源校验外，整个设计及 AI 设计出口的资产检查还会让无关参与对象的失效默认阻断保存、指令检查或生成。

另一方面，现有身份参考允许空对象、多对象或同一对象跨多个主体组。模型按实际参考组接收主体，并不会根据人物名称自动合并。要支持“同一对象使用单一来源，明确更换时整组替换且不影响其他对象”，必须收紧主体归属和分组，并处理既有可编辑数据，同时保留真实历史生成输入。

## Solution

导演中的资产绑定定位为当前场次版本的可选默认资产关联，操作称为“设置默认资产”，在右侧非模态详情面板调整。默认关联用于理解设计和带出候选，不代表任何生产单元已选用图片，也不是单元使用项目资产的前提。

单元按照覆盖镜头的明确参与对象及本场场所优先展示默认资产候选，允许手动选择其他可用项目资产、已有文件或上传素材。候选与已选参考分别展示，只有用户明确选入并应用的具体素材才成为单元输入。单元不另存一层尚未选图的默认资产配置，也不回写导演默认或其他单元。

人物与物件的身份主体参考采用一一对应的分组：一个单元内每个对象最多一组，每组恰好归属一个对象。每组使用同一个项目资产的多份素材，或由用户指定的一组人工素材，两种方式互斥。来源限制只作用于身份用途的主体输入，其他用途和输入位置沿用自身规则。更换来源是一项明确操作：准备新组，应用时完整替换目标组，取消则保留原组。

删除与整卡激活重复的“编辑此卡”；卡片动作优先横排并允许换行。单元参考卡直接进入“编辑参考素材”管理弹窗，移除重复编辑按钮；弹窗先展示已选内容，再按需添加或更换。查看、只读、键盘访问、焦点和画布视口保持可用。

既有可编辑单元中的不合规身份参考按确定规则自动清理；新提交的违规输入明确拒绝。合规单组的多图保留，多组或多来源仅保留按原顺序第一份有效参考，空对象或多对象归属的身份组移除。固定生成记录及 Take 输入保持原样。

成功标准：

- 无默认关联、默认已改变或存量默认已失效时，单元仍能独立准备并保存合法参考；有效实际输入不会被无关默认阻断。
- 默认候选、已选参考和固定生成记录分别表达，打开界面或切换候选不会自动采用素材。
- 每个身份主体组具有唯一对象、单一来源和明确身份；同组多图作为一个模型主体输入。
- 更换来源只改变目标身份组，取消、失败和并发变化不会造成半组替换或丢失其他输入。
- 存量清理符合最终规则、结果可重复，既不误删合规多图，也不改写固定历史。
- 卡片动作精简且可访问，桌面和窄屏均无按钮重叠或横向溢出。

## User Stories

1. 作为场次创作者，我希望直接激活普通设计卡片即可进入相同编辑内容，以便不必在重复入口之间选择。
2. 作为键盘用户，我希望通过 Enter 或 Space 激活卡片且焦点清晰，以便删除显式编辑按钮后仍可完成操作。
3. 作为只读用户，我希望仍能查看卡片及参考内容并理解不可编辑状态，以便编辑入口精简不会同时移除阅读能力。
4. 作为场次创作者，我希望同一卡片的多个动作优先横排、空间不足时换行，以便节约空间而不缩小点击区域或截断文字。
5. 作为场次创作者，我希望导演入口明确称为“设置默认资产”，以便知道它配置的是候选来源。
6. 作为准备拍摄的用户，我希望参考操作明确称为“编辑参考素材”，以便知道它决定本单元的真实输入。
7. 作为场次创作者，我希望普通默认关联在右侧详情修改、参考选择在独立弹窗应用，以便理解两种操作的保存边界。
8. 作为准备拍摄的用户，我希望激活参考卡后直接进入参考管理，以便不必先经过另一份只读详情。
9. 作为准备拍摄的用户，我希望参考管理先展示已选素材，再按需添加或更换，以便不必每次从选图流程开始。
10. 作为场次创作者，我希望查看和关闭这些界面不改变画布视口或丢失未保存输入，以便保持工作上下文。
11. 作为场次创作者，我希望参与对象不关联资产也能成立，以便先完成故事设计，再准备素材。
12. 作为准备拍摄的用户，我希望为既有参与对象直接选择其他可用项目资产，以便无需先修改导演默认关联。
13. 作为准备拍摄的用户，我希望单元优先带出覆盖镜头中明确参与对象及本场场所的默认资产，以便减少重复查找。
14. 作为准备拍摄的用户，我希望镜头参与范围未知时看到待补全提示，以便系统不会擅自把全场人物加入当前单元。
15. 作为准备拍摄的用户，我希望候选资产和具体图片不会自动变成已选参考，以便由我决定实际送入模型的素材。
16. 作为准备拍摄的用户，我希望候选数量和已选参考数量清楚区分，以便不会误判拍摄准备度。
17. 作为准备拍摄的用户，我希望只浏览或切换资产但没有选入素材时不产生新的持久化配置，以便单元状态由真实选择表达。
18. 作为场次创作者，我希望修改某个单元的参考不回写导演默认或其他单元，以便各次拍摄可独立准备。
19. 作为场次创作者，我希望修改或解除导演默认后已有单元参考保持原样，以便默认调整不会替换、清空或否定既有选择。
20. 作为场次创作者，我希望失效的存量默认只表现为不可用候选，以便它不会阻断本单元或其他单元的合法工作。
21. 作为场次创作者，我希望新增或改选默认时仍校验项目归属与可用性，以便无效默认不会被新写入。
22. 作为场次创作者，我希望局部 AI 设计不会被原样保留的无关失效默认卡住，也不能伪造新默认，以便默认规则在人工与 AI 流程中一致。
23. 作为场次创作者，我希望默认关联和单元已选素材分别表达，以便不会把设计关联列表误认为实际引用全貌。
24. 作为准备拍摄的用户，我希望每组身份主体参考明确归属一个人物或物件，以便系统知道该组表示谁。
25. 作为准备拍摄的用户，我希望同一对象在一个单元中只有一个身份主体组，以便多图不会意外被作为多个模型主体发送。
26. 作为准备拍摄的用户，我希望同一资产的多张合规图片保留在同组，以便提供同一对象的不同视角。
27. 作为准备拍摄的用户，我希望未建立项目资产时也能指定一组上传或已有素材，以便直接准备试拍。
28. 作为准备拍摄的用户，我希望同一身份组不能混用多个资产或资产与人工素材，以便来源约束清晰。
29. 作为准备拍摄的用户，我希望一个单元内的不同人物或物件各自使用自己的来源，以便单一来源限制不会错误扩展到整个单元。
30. 作为准备拍摄的用户，我希望首尾帧、场所、构图等参考按实际用途独立选择，以便人物身份规则不会限制其他输入位置。
31. 作为准备拍摄的用户，我希望多人整体画面可以用于构图，而身份参考必须明确目标对象，以便系统不会自动识别人或拆分主体。
32. 作为准备拍摄的用户，我希望通过明确的“更换来源”操作准备新的整组素材，以便区分浏览候选与替换已选输入。
33. 作为准备拍摄的用户，我希望应用新来源时一次替换目标身份组，以便不会留下新旧来源混合的半完成状态。
34. 作为准备拍摄的用户，我希望取消、上传失败或关闭选择器后原组保持不变，以便尝试其他素材不会损失已有准备。
35. 作为准备拍摄的用户，我希望更换甲的身份组不影响乙、其他单元或首尾帧等输入，以便局部操作保持局部影响。
36. 作为协作编辑者，我希望参考在弹窗打开期间发生变化时阻止旧内容覆盖，以便另一处已完成的编辑不被丢失。
37. 作为准备拍摄的用户，我希望模型能力未知、素材不兼容或数量超限时看到明确问题，以便在真实生成前完成处理。
38. 作为准备拍摄的用户，我希望实际参考变化继续使相关指令依据和检查需要重新核对，以便不会把旧确认用于新输入。
39. 作为准备拍摄的用户，我希望仅修改默认候选不使本来有效的当前指令与检查失效，以便无关偏好调整不打断拍摄。
40. 作为场次创作者，我希望资产改名或调整图库后已选参考仍使用原文件及来源记录，以便当前输入不会随资产维护悄然变化。
41. 作为场次创作者，我希望来源资产删除或移出项目后，只要已选文件仍可合法使用就能继续使用，以便来源目录生命周期不会抹掉已固定的参考。
42. 作为准备拍摄的用户，我希望实际文件缺失或不可访问时明确阻止生成，以便系统不会用其他默认图冒充原输入。
43. 作为维护者，我希望既有合规单组多图完整保留，以便数据整理只处理不合规情况。
44. 作为维护者，我希望同一对象既有多组或多来源时只保留原顺序第一份有效参考，以便整理结果明确且可重复。
45. 作为维护者，我希望未指定对象或同时指向多对象的身份组被直接移除，以便不会随机给图片分配人物身份。
46. 作为维护者，我希望历史清理只作用于当前可编辑单元的身份主体参考，以便其他用途、版本与固定生成记录保持真实。
47. 作为维护者，我希望清理后实际输入变化沿用既有指令和检查核对机制，以便旧确认不会被误认为适用于整理后的输入。
48. 作为维护者，我希望新提交的违规参考明确报错而不被静默裁剪，以便用户知道哪些新选择尚未生效。
49. 作为维护者，我希望真实项目权限、文件类型、文件归属和所选图片来源仍被验证，以便解除默认关联前提不会放松其他契约。
50. 作为维护者，我希望通过真实事务及画布流程验证这些行为，以便前后端都遵守相同边界。

## Implementation Decisions

### 1. 领域关系与适用范围

- 沿用“场次版本”“参与对象”“资产绑定”“生产单元”“生成记录”等现有领域术语。参与对象是场内人物或物件身份，不等同于项目资产；默认资产不决定该对象是否存在。
- 导演资产绑定在本流程中承担可选默认关联职责。实际参考由单元保存的具体文件、用途、输入位置、顺序、对象归属、主体组与来源记录决定。
- 单元可以为同一参与对象使用与导演默认不同的项目资产；选择来源不得把对象身份自动改成该资产原先关联的另一人物。
- 人物、物件和场所的默认都不构成单元实际输入的使用前提。身份主体的单一来源及一一分组限制只适用于人物／物件。
- 默认关联展示与单元实际引用展示分开；本规格不把当前场次的设计关联列表定义成整个项目的实际使用统计。

### 2. 卡片、命名与编辑容器

- 删除普通对象卡中与整卡激活打开相同编辑内容的“编辑此卡”。保留悬停反馈、可见焦点、Enter／Space 激活、触摸访问及明确的只读／不可用状态。
- 保留与整卡行为不同的独立业务动作。子图进入、引用定位、标题拖动和卡内按钮事件保持各自语义，不批量改成编辑或让一次操作触发两个入口。
- 卡片动作使用横向布局并允许自然换行，不以缩小点击尺寸、截断文案或强制单行节省空间。
- 导演资产操作统一使用“设置默认资产”，由对象上下文说明设置目标，在已有右侧非模态详情面板编辑；字段变更沿用工作台当前保存机制。
- 单元参考管理统一使用“编辑参考素材”。参考卡整卡激活直接进入该管理弹窗，删除通往同一内容的重复卡面编辑按钮。
- 管理弹窗先展示已选内容，需要时进入添加或更换；没有已选参考时展示真实空态和候选入口。只读场景保持可阅读，但不能应用修改。
- 入口、标题与动作使用一致的业务上下文。开合、切换与展开不得移动或缩放画布、重排卡片或丢失已有未保存输入。
- 复用工作台现有按钮、详情、弹窗、动作区和主题；保留门户主题、焦点恢复、内层 Escape 优先及窄屏行为。

### 3. 默认候选与真实选择

- 默认候选范围为当前单元全部覆盖镜头中的明确参与对象，以及本场场所；按对象身份去重，不把所有场内人物自动加入每个单元。
- 明确空的镜头参与名单表示无对象，不能从默认资产、背景文字或其他工作单补成有对象。范围未知时显示待补全提示，不推断参与者。
- 用户仍可手动选择其他可用项目资产，并沿用已有文件和上传入口；这不自动增加镜头参与名单或新建场内对象。
- 自动带出的是候选资产及可选素材，不是已选引用。打开页面、默认变化、切换候选或资产只有一张图片，都不能自动选图。
- 候选不计入已选数量，不表示模型已经获得输入，也不能据此消除真实参考缺项。
- 只切换资产、尚未选入并应用具体素材时，不新增持久化的单元资产选择字段。再次打开可回到默认候选；不新增一层单元默认配置。
- 已明确应用的选择只更新目标单元。修改或解除导演默认不替换、移除或自动修复既有单元参考；单元参考也不回写默认。

### 4. 默认、来源与可用性校验解耦

- 取消“单元来源必须属于当前设计关联资产集合”和“单元来源必须等于该参与对象默认资产”的保存与执行前提。
- 全面覆盖场次设计校验、参考来源校验、人工保存、指令准备／应用／依据核对、检查、单次及批量生成预检和 AI 设计结果校验，不能只修选择器或某一个保存入口。
- 已失效的存量默认保留其可识别状态并提示不可用，只影响候选；不能阻断有效实际输入，也不能让无关对象的默认阻断其他单元。
- 新增或改选默认仍须使用当前项目的可用资产。AI 原样保留无关存量失效默认不得使整份候选失败，但新增／变更默认仍须核实，不能写入伪造资产。
- 新选择的项目资产素材仍须验证真实资产、项目归属、媒体类型、文件访问及文件确实属于所声明的资产。解除默认前提不等于跳过整个设计或文件校验。
- 实际参考变化继续影响指令消费依据和检查有效性。仅默认偏好变化不得使本来有效的当前指令与检查失效，也不得恢复此前已失效或未确认的状态。

### 5. 身份主体的归属、分组与来源

- 限制精确作用于用途为 `identity`、有效输入角色为 `subject` 的参考。输入角色缺省时按现有契约的有效默认值判断；显式非法值仍是契约错误。
- 未选择身份参考的对象可以没有主体组；存在身份参考时，该对象在当前单元恰好对应一个组，每组恰好归属一个明确存在的参与对象。
- 一个单元可以有多个人物／物件主体，各自使用自己的来源。不可把单一来源限制扩大为整个单元只允许一个资产。
- 每个身份组采用以下互斥方式之一：同一个项目资产的素材，或用户明确指定的一组人工素材。人工组可包含上传和已有文件，不创建新资产或新的持久化配置层。
- 单一资产组允许模型能力支持的多份素材；同组内不能混入其他资产，也不能混入人工来源。来源身份按资产类型及稳定标识判断，选择时的名称属于来源快照，不单独构成新来源。
- 人工组中的素材由用户明确指定对象；系统不通过图片识别推断身份，不因人物同名或图片相似自动合组。
- 模型输入继续按明确主体组组装。同一合规组的多图发送为一个主体，不把每张图分成一个新人物。
- 多人整体画面可以作为构图等适当用途；作为身份参考时必须明确目标对象。不自动把一个多人身份组拆成多个对象。
- 首尾帧、场所、构图、连续性等其他用途或输入位置不套用本节的人物身份限制，继续遵守原有模型能力、用途和媒体约束。没有独立“风格”用途的现状不因讨论中的举例而改变。

### 6. 添加、更换与应用的事务边界

- 浏览或切换候选资产只改变选择上下文，不删除已选素材。向现有身份组添加素材必须符合该组的对象与来源规则。
- 更换来源使用明确动作，先在弹窗内准备新组，再由“应用到本单元”一次替换目标身份组；不能先删原组再等待用户选图。
- 取消、关闭、上传失败或未成功应用时保留原组。沿用既有上传上下文校验，忽略关闭后或上下文变化后的迟到结果。
- 只替换目标对象的身份主体参考。其他对象、其他单元和同对象的非身份参考保持原样；不能仅凭参与对象标识清空它的全部输入。
- 落幅依赖及其连续性参考不属于身份组替换范围。通用参考管理实际修改此类引用时，继续提示并执行原有明确重绑和一致性校验。
- 弹窗打开期间参考集合已被修改时，拒绝用旧基线覆盖；服务器仍执行现有并发修订保护。
- 应用更新工作台当前编辑内容，持久化继续走现有手动／自动保存。失败保留输入，不新增第二套保存或发布阶段。
- 模型能力未知、不兼容或超限时保留已有准备并显示问题，真实生成前执行统一校验；不能因候选新组失败而损失原组。

### 7. 资产与固定参考的生命周期

- 已保存参考固定具体文件和选择时来源。资产改名、图库替换或图库移除原图不会自动改写这些记录。
- 来源资产删除或移出项目后，既有已选文件仍存在且可合法访问时，允许保留并继续使用，显示来源资产不可用并保留来源快照。
- 失效来源不得用于新增选择，也不能利用已有来源快照伪造新的资产选择；“继续使用”限于可核实的既有引用。
- 具体文件缺失、不可访问或不满足执行要求时，保留可识别的引用及问题状态并阻止生成，不能静默改用默认图或其他文件。
- 历史来源快照不由当前资产最新名称、最新图库或当前默认重新解释。

### 8. 既有可编辑数据的自动清理

- 范围仅为既有当前可编辑单元的身份主体参考；固定生成任务、Take 输入、历史执行证据和不可编辑记录保持原样。
- 依据原始对象归属、有效输入角色、来源和实际模型主体组识别不合规情况。实际组键优先取明确主体组标识；没有分组标识时，按现有执行行为视为各引用独立成组。
- 同一明确组内、单对象、单来源的合规多图全部保留，不能因为图片数量大于一而裁剪。
- 同一对象原本存在多个主体组或多个来源时，按现有 `ordinal` 顺序仅保留第一份有效参考，不是保留第一个组的全部图片。同来源但未分组的多图，以及同来源但分属不同组的多图，均按原本多组处理。
- 空对象或同时归属多个对象的身份组直接移除，不随机挑选归属人物。
- 先识别原始情况再执行选择，不能先删部分内容、再把剩余内容重分类为合规多图而额外保留；不通过读取时自动合并组来改变已确认规则。
- 判断有效参考时继续核实对象、文件和访问条件；来源资产失效但固定文件仍可合法访问的参考按上一节保留，不能只因资产消失将其判为无效。
- 清理触发条件限于本节的归属、分组和来源不合规。单纯文件缺失沿用不可用提示与执行阻断，不扩大为另一种自动删引用；能力未读取、不兼容或数量超限也不能单独触发清理。
- 没有有效候选时保留真实缺项，不自动使用默认候选或其他组填补。清理不得扩展到非身份用途、首尾帧或其他单元的合规输入。
- 清理结果应确定且可重复，重复处理已经合规的结果不继续丢失内容。清理使实际输入变化时，沿用现有指令依据与检查重新核对机制。
- 历史清理和新提交校验明确分开：新提交违反单对象、单组、单来源规则时报错并保留原保存内容，不能借自动清理悄悄裁剪用户的新选择。
- 本规格授权后续实现受控的数据整理行为，不表示规格生成时已经运行清理；无需为了历史无效字段补造兼容身份或新领域对象。

### 9. 实现职责与同步

- 场次版本契约和业务存储负责规则、来源核实、并发与清理边界；API 层负责收参、鉴权及响应，不在展示层独占关键约束。
- 参考选择与画布负责候选、已选、来源更换和明确的交互状态；模型输入组装负责忠实消费已经明确的主体组，不按资产名称或人物名字猜测合并。
- 复用现有场次版本 HTTP、数据库事务、参考选择和工作台组件入口，优先局部修改；不为本功能建立泛化配置系统或新资产管理层。
- 对外保存和参考语义变化须依项目要求同步受影响的接口说明、OpenAPI 与前端 generated client，生成时确认服务加载当前工作区；不新增手写接口封装。
- 实现时同步已不准确的领域说明、工作台操作约定和相关架构事实，尤其是“资产来源必须匹配导演关联”及参考卡旧入口。规格中的目标不能提前写成已生效实现，也不修改已固化发布说明。

## Testing Decisions

测试边界已由用户确认。以外部可观察行为为主，不以组件内部状态、私有函数调用顺序或字段复制方式代替验收。

### 1. 两个主要测试边界

1. **场次版本 HTTP 与真实数据库事务。** 复用已有场次创建、版本保存、重新读取、指令准备／依据／检查和视频预检的集成测试方式，验证持久化结果、拒绝行为、输入冻结及跨单元隔离。模型与外部生成使用现有受控替身，覆盖输入消费而不调用付费服务。
2. **真实导演／单元画布浏览器流程。** 复用已有独立测试服务、数据库和真实工作台页面，验证用户从卡片到默认设置、参考管理、应用／取消及保存的完整路径。通用控件状态、键盘、窄屏和主题隔离继续使用已有工作台回归入口。

已有主体组契约、媒体输入组装和参考准备测试用于补齐精确异常组合；不为本次规格要求新增独立测试框架。契约测试补充 HTTP 和浏览器行为验证，不替代两条主边界。

### 2. 后端与数据清理验收矩阵

| 场景 | 必须验证的可观察结果 |
| --- | --- |
| 无默认关联，给既有参与对象选择可用项目资产图片 | 保存并重新读取成功；对象身份保持；导演默认不被写入 |
| 默认为 A，单元明确选择 B | 引用与生成输入使用 B；默认及其他单元不变 |
| 修改、解除或失效存量默认 | 有效既有引用仍可保存、核对和准备生成；无关单元不受阻 |
| 新增无效或越权默认／伪造 AI 默认 | 明确拒绝新选择；不覆盖原内容 |
| AI 设计原样保留无关失效默认 | 不因该默认单独拒绝整个候选；其他真实约束继续校验 |
| 同一对象、同一组、同一来源多图 | 全部保留并作为一个模型主体，顺序保持 |
| 新提交空对象、多对象、多组或混合来源的身份参考 | 明确拒绝；原保存内容保持；不静默清理 |
| 人工组及不同对象各自使用不同来源 | 合规保存；不错误应用整个单元单一来源限制 |
| 非身份参考、首尾帧与连续性引用 | 不被身份组规则或整组替换误删，原有用途限制仍有效 |
| 既有合规单组多图清理 | 所有合规图片保持 |
| 既有多组、多来源或缺省分组的多图清理 | 按原始分组与排序仅保留第一份有效参考，不合并为新组 |
| 既有空对象／多对象身份组清理 | 目标身份组移除；其他合法内容保持 |
| 缺省输入角色与显式非法角色 | 缺省按有效默认判断；非法值不能被当作缺省吞掉 |
| 来源改名、图库变化及名称快照不同 | 稳定资产身份不变；既有文件及各自来源快照保持 |
| 来源资产删除／移出项目但固定文件仍合法 | 既有引用继续可用；不能据此新增伪造来源 |
| 实际文件缺失、越权、类型不符或不属于声明资产 | 相应新选择或执行明确拒绝，不替换成默认图 |
| 清理前后固定任务及 Take 输入比较 | 固定历史完全保持，不用当前输入重解释旧记录 |
| 同一清理重复执行 | 已整理结果稳定，不继续删除 |
| 实际参考改变与仅默认改变对比 | 前者触发相关依据／检查核对，后者不使本来有效的状态失效 |
| 并发保存与基线过期 | 拒绝旧内容覆盖，其他单元和已有记录保持 |

清理测试应使用隔离数据库中的既有数据样本，不在验收时试清理真实用户数据。样本应同时包含合规多图、不合规组、其他用途、多个单元及固定历史，以验证作用范围。

### 3. 浏览器验收矩阵

| 场景 | 必须验证的用户结果 |
| --- | --- |
| 普通设计卡激活 | 鼠标、Enter、Space 均打开原编辑内容；重复“编辑此卡”消失 |
| 子图、引用、拖动、卡内独立动作 | 各自语义保留，不串触发、不误编辑 |
| 导演默认设置 | 命名准确，使用详情面板，保持既有保存和只读行为 |
| 单元参考卡激活 | 直接进入参考管理弹窗，无重复编辑按钮；已有参考优先可见 |
| 单元覆盖范围及未知名单 | 只带出明确范围候选；未知状态有提示且不擅自扩大对象名单 |
| 默认无关联、无图片、失效或有可用图片 | 正确显示候选／问题；均不自动增加实际参考 |
| 切换资产但未选图 | 关闭后没有新增引用或持久化单元默认 |
| 合规多图与来源限制 | 同资产多图、人工组可操作；混源不能作为正常新增方式应用 |
| 更换来源后应用 | 目标身份组一次替换，其他对象和其他用途不变 |
| 更换来源后取消、上传失败、关闭或迟到结果 | 原组保持，不出现部分替换 |
| 编辑期间输入变化 | 明确提示基线变化，不覆盖较新参考 |
| 能力未知或超限 | 问题可读，既有输入保留，真实生成受相应限制 |
| 桌面与 390px 窄屏 | 按钮横排优先且自然换行，文字和点击尺寸保留，无重叠与横向溢出 |
| 焦点、Escape、只读及门户主题 | 焦点与关闭恢复有效，内层优先，非工作台主题不被污染 |
| 开合、应用／取消与后台刷新 | 视口、布局、滚动及未保存输入符合现有工作台保护 |

### 4. 完成检查

- 根据实际修改范围运行相关契约、集成和浏览器测试；共享校验影响保存、指令与生成时覆盖这些共同调用路径，不能只验证参考选择器。
- 前端实现改动完成项目要求的类型检查和工作台组件、四画布样式及设计完整性回归。后端应用代码变化完成受影响测试及项目要求的 Pylint 检查；共享基础设施变化按范围扩展测试。
- 验证接口与 generated client 同步、受影响文档准确，报告未覆盖或无法执行的必要检查。
- 本次规格写入只检查决策覆盖、文档结构与差异，不冒充应用测试或数据清理已完成。

## Out of Scope

- 允许同一人物／物件的身份组混用多个项目资产，或混用资产与人工来源。讨论中一度考虑过混用，最终已明确否决。
- 自动选取默认资产的第一张图、全部图片，或因默认变化自动替换已选素材。
- 新增尚未选图时持久化的单元默认资产层，以及单元选择回写导演默认或其他单元。
- 新增项目级资产使用统计面板、新的资产类别、独立“风格”用途或通用表单配置系统。
- 新增同一文件跨多个输入位置／对象的复用能力；选择器现有文件去重边界沿用，历史重复记录不因本条自动删除。
- 自动识别人脸、按图片相似度合组、自动拆解多人图片或为缺失身份补造人物／物件。
- 改写固定生成任务、Take 输入或其他历史执行证据；恢复旧镜头槽位、双写或兼容别名。
- 将本次默认解耦扩大为历史无消费范围回执的迁移或自动恢复确认。既有重新核对流程保持，不能宣称本次修复了原有历史兼容缺口。
- 全站 UI 改造、任务中心改造、与本次行为无关的代码重构，以及新增或修改固化发布说明。
- 在生成规格时执行应用实现、真实业务数据清理、票据发布、提交或部署。

## Further Notes

- 最终选择以本规格为准：单一来源，而非混合来源；自动清理既有可编辑不合规数据，而非保留到用户手工整理；同一合规组内的多图仍完整保留。
- 自动清理的“保留一个”明确为按现有顺序保留第一份有效参考，不能扩大成保留第一组，也不能因为同一资产就把原有多个模型主体合并。
- 已确认的只读、事务、并发、文件访问及固定历史边界继续有效。仅改变候选默认不构成真实输入变更，实际素材替换或清理则需要按既有机制重新核对依据。
- 后续拆票应围绕可独立验收的完整用户行为及真实依赖组织，不按前端／后端简单横向切层。本次仅发布规格，尚未创建实现票据。
