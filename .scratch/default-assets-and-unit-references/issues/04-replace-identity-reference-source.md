# 04: 身份参考来源整组替换

Status: ready-for-agent
Blocked by: 03

**What to build:** 用户通过明确的“更换来源”准备某人物／物件的新身份参考组，点击“应用到本单元”后一次替换原组。浏览、取消、关闭、上传失败和并发变化均不会提前删除原组或损伤其他输入。

**依据：** [实现规格](../spec.md)。主要覆盖用户故事 32–38、50，并验证故事 18 的单元隔离。

**前置：** [03 身份主体单组单来源与存量清理](03-identity-groups-and-existing-data-cleanup.md)，间接依赖 01、02。整组替换依赖唯一的目标身份组、稳定来源规则和已明确的存量状态。

## Acceptance criteria

- [ ] 为已有身份组提供明确的“更换来源”操作。浏览或切换候选仅改变选择上下文，原组在新组成功应用前保持完整，不能先删除原组再让用户选材。
- [ ] 支持资产 A 换为资产 B、资产组换为人工组、人工组换为资产组及重新准备人工组。新组遵守单对象、单组、单来源与现有媒体规则，正常追加同来源素材继续走合法添加路径。
- [ ] “应用到本单元”一次提交目标新组，应用结果不能同时残留新旧来源或出现半组状态。选资产而未选入具体素材不构成完成替换，也不持久化一层单元默认。
- [ ] 取消、关闭、上传失败或应用失败时原组保持；沿用上传上下文保护，关闭后、切换上下文后的迟到结果不能回填旧弹窗或影响其他单元。
- [ ] 替换精确限定为目标对象的身份用途主体参考；其他对象、其他单元和同对象的首尾帧、构图等非目标输入保持原样，不按对象标识删除它的全部参考。
- [ ] 落幅依赖及其连续性参考不进入身份组替换范围。通过通用参考管理实际修改此类引用时，仍执行原有明确重绑提示与一致性校验。
- [ ] 弹窗打开后参考集合已变化时，拒绝用旧基线覆盖并给出明确提示；服务器现有修订／并发保护继续生效，失败不覆盖较新内容。
- [ ] 应用更新工作台当前编辑内容，保存继续走已有手动／自动保存流程；不新增第二套保存或发布阶段，保存失败保留用户输入与可见错误。
- [ ] 模型能力未知、不兼容或数量超限时保留准备内容并显示问题，真实生成前执行统一校验；新组准备或应用失败不能导致原组丢失，不能通过静默删图满足能力限制。
- [ ] 实际替换成功后，相关指令依据与检查按现有机制重新核对；浏览和取消不产生实际输入变化，不额外改写导演默认或恢复失效确认。
- [ ] 编辑过程保留当前单元、画布视口、布局、滚动及其他未保存输入；只读状态可查看但不能执行替换或应用。
- [ ] 用户界面、保存结果与生成输入均消费同一个替换结果；如外部契约改变，按项目要求同步接口说明、OpenAPI 与 generated client，并更新受影响的参考操作说明。

## Validation

- 通过真实单元画布验证资产到资产、资产到人工、人工到资产及人工组重新准备的完整操作：打开、浏览、选材、应用、保存、回读。核对目标整组、其他人物、其他用途及其他单元的前后差异。
- 在真实浏览器流程中覆盖取消、关闭、上传失败、关闭后迟到上传、切换上下文、应用失败；每次失败均断言旧组完整，其他未保存输入和视口不丢失。
- 模拟弹窗期间另一处修改及后台刷新，验证本地基线保护；通过实际 HTTP 并发保存与数据库事务验证服务端拒绝旧修订及失败后的原子性。
- 通过 HTTP 回读和受控模型输入确认整组来源、目标和顺序正确，没有新旧混源；检查实际替换与取消对指令依据／检查的不同影响。
- 覆盖能力未知、超限、不兼容和连续性引用边界，问题可见、输入保留、真实预检阻断有效；不调用付费模型。
- 完成相关契约／HTTP／浏览器测试、前端类型检查和相关工作台回归；涉及后端应用代码时完成 Pylint，按影响范围扩展测试并记录必要检查局限。

## Scope and handoff

本票复用现有参考管理、上传和工作台保存机制，交付可观察的选择与应用事务，不新建通用编辑事务框架。新组的规则与存量处理复用 03，不在替换流程中静默整理用户的新输入。

可在既有参考管理入口独立验收；[05](05-card-actions-and-reference-entry.md) 负责参考卡直达、入口命名及布局，不构成本票前置。两票同时修改管理界面时需集成验证，但共享编辑位置本身不增加阻塞关系。
