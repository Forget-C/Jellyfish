# 02: 来源资产失效后保留固定参考

Status: ready-for-agent
Blocked by: 01

**What to build:** 用户已保存的参考固定到具体文件及选择时来源。来源资产改名、调整图库、删除或移出项目后，只要原文件仍可合法使用，就能继续保留和使用该参考；实际文件不可用时清楚提示并阻止执行。

**依据：** [实现规格](../spec.md)。主要覆盖用户故事 40–42、49、50。

**前置：** [01 默认资产与单元选材解耦](01-default-assets-and-independent-references.md)。先解除设计默认对保存与执行的阻断，才能完整验收来源生命周期，而不被无关默认校验拦截。

## Acceptance criteria

- [x] 已保存参考保留固定文件及选择时来源快照；资产改名、图库替换或移除原图后，保存回读、查看和模型输入不会自动改用新名称、最新图库、当前默认或其他文件。
- [x] 来源资产删除或移出当前项目后，可核实的既有引用在原文件仍存在且可合法访问时可继续保存、进行指令核对及生成预检，并在实际输入中使用原文件。
- [x] 单元参考界面区分来源资产不可用与实际文件不可用。前者保留来源快照并提示来源状态，不能因此把仍合法的固定文件展示成缺失输入。
- [x] 失效来源不再供新增选择；不得复制、篡改既有来源快照或引用身份，借“继续使用”例外新增原本不存在的资产引用。既有引用的判断使用可核实的保存基线。
- [x] 新增选择仍验证当前可用资产、项目归属、声明资产与具体文件关系、访问权限及媒体契约；既有引用保留也不能绕过实际文件访问与执行要求。
- [x] 文件缺失、访问被撤销或不满足执行要求时，保留可识别引用及问题状态，并在相应新选择或执行入口拒绝操作。单次／批量生成均不能静默替换为默认图或其他文件。
- [x] 来源身份按资产类型与稳定标识判断，名称仅为选择时快照。同资产在不同时间选入、名称快照不同的合法素材，不被误判为多个来源。
- [x] 只有来源目录信息变化且实际输入未变时，不重写参考或凭空恢复／否定已有指令确认；文件真实可用性仍由当前执行校验核实。
- [x] 固定任务、Take 输入及历史执行证据保持原文件、来源与身份，不以当前资产状态重新解释或改写历史。
- [x] 保存、指令及生成消费共享一致的既有引用边界；外部语义变化同步接口说明、OpenAPI 与 generated client，并修订受影响的来源生命周期文档。

## Validation

- 在真实场次版本 HTTP 和数据库事务中，先保存合法引用，再分别模拟资产改名、图库调整、原图移出图库、资产删除及移出项目；回读并比较固定文件和来源快照，验证保存、指令核对及单次／批量生成预检。
- 对每种失效来源分别测试“可核实的既有引用继续使用”和“伪造／追加新引用被拒绝”，失败后原保存内容不变。覆盖文件仍合法、文件缺失、权限撤销、媒体不符，避免来源保留例外扩大为文件校验豁免。
- 用受控模型替身核对实际消费的固定文件；用契约用例补齐同一稳定资产但名称快照不同的情况。比较固定任务和 Take 快照，证明历史未被当前资产状态改写。
- 真实单元画布浏览器验证来源不可用提示、文件不可用提示、已选参考保留、失效来源不可新增，以及保存回读后的状态一致性。
- 完成受影响契约／HTTP／浏览器测试、前端类型检查及相关工作台回归，后端应用改动完成 Pylint；按共享验证影响扩展测试。生成使用受控替身，不调用付费服务，并报告必要检查局限。

## Scope and handoff

本票建立“来源目录失效”和“固定输入失效”的行为边界，不恢复已失效的资产，不建立新资产或替代文件。当前权限和文件约束继续生效。

[03](03-identity-groups-and-existing-data-cleanup.md) 以本票的有效性判定筛选存量幸存参考，避免仅因资产消失误删仍可用的固定文件。主体数量、分组清理及更换来源操作分别归 03、04；本票不执行真实业务数据清理。
