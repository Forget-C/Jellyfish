# 03: 身份主体单组单来源与存量清理

Status: ready-for-agent
Blocked by: 02

**What to build:** 用户为每个人物／物件维护一个明确的身份主体组，每组使用单一资产的多份素材或一组人工素材。正常添加、服务端保存和模型消费遵守同一规则；同时受控整理既有可编辑单元中的不合规身份参考，保留合规多图及固定历史。

**依据：** [实现规格](../spec.md)。主要覆盖用户故事 24–31、43–48，以及故事 37、38、49、50 中的分组、清理与验证边界。

**前置：** [02 来源资产失效后保留固定参考](02-fixed-reference-source-lifecycle.md)，间接依赖 01。清理必须采用已明确的固定参考有效性规则，不能把仅来源资产消失的合法引用判成无效。

## Acceptance criteria

- [x] 规则精确作用于用途为 `identity` 且有效输入角色为 `subject` 的参考；缺省角色按现有契约有效默认处理，显式非法角色仍报契约错误，不能当作缺省吞掉。
- [x] 没有身份参考的对象可没有主体组；存在身份参考时，同一单元内该对象只有一个组，每组恰好归属一个明确存在的人物或物件。不同对象可各有自己的来源。
- [x] 每组使用同一项目资产的素材，或用户明确指定的一组人工素材；人工组可包含上传和已有文件。资产 A 与 B、资产与人工素材不能混组，人工组不新增资产或配置实体。
- [x] 同一资产的合规多图保留在同一组；稳定来源由资产类型及标识决定，来源名称快照不同不产生新来源。同组多图按明确顺序作为一个模型主体消费。
- [x] 正常添加素材时复用目标对象的合法组，并核实来源一致；人工素材由用户明确指定对象。界面不能把每次上传或每张图各建为该对象的新主体，也不通过名称、图片相似度或自动识别猜测合组。
- [x] 首尾帧、场所、构图、连续性等其他用途或输入位置沿用原规则；多人整体图可用于构图，身份参考须明确目标对象，不自动拆解多人组，也不新增“风格”用途。
- [x] 新提交的空对象、多对象、同对象多组或混合来源明确拒绝，事务保持原保存内容。服务端不能把用户新提交的非法输入当作存量自动裁剪；前端须展示可理解的问题。
- [x] 存量整理仅作用于既有当前可编辑单元的身份主体参考；不可编辑版本、固定任务、Take 输入和历史执行证据完全保持，不补造对象或兼容身份。
- [x] 清理先记录原始归属、来源、有效角色及实际模型组。明确主体组标识存在时按该标识分组；缺省组标识时按现有执行行为将每份引用视为独立组。
- [x] 原本单对象、同一明确组、单来源的合规多图全部保留，不能按图片数量裁剪。同来源但没有组标识的多图、同来源但跨组的多图均属于原本多组。
- [x] 同一对象原本多组或多来源时，按原 `ordinal` 顺序只保留第一份有效参考；不能保留第一组的全部图片，也不能在读取时合组以规避该规则。
- [x] 原本空对象或多对象归属的身份组直接移除，不随机指定人物。先分类原始情况再决定保留内容，不能先删部分非法组、再将余下多图重分类为合规而额外保留。
- [x] 筛选幸存参考核实对象、文件及访问条件；来源资产失效但固定文件仍合法的既有引用可保留。没有有效幸存者时保留真实缺项，不自动选入默认图或其他组素材。
- [x] 仅归属、分组或来源不合规触发本次自动清理。单纯文件缺失保留引用及执行阻断；模型能力未知、素材不兼容或数量超限不能单独触发删除，沿用问题提示与生成预检。
- [x] 整理结果确定且幂等，重复执行不继续丢失内容；其他用途、输入角色、其他单元合规参考及原顺序保持。清理造成实际输入变化时沿用指令依据与检查重新核对。
- [x] 分组规则在用户操作、场次版本保存和模型输入中一致。实现同时交付存量处理与新输入拒绝，避免上线新约束后让旧可编辑数据没有合法处理路径。
- [x] 对外契约及语义按项目要求同步 OpenAPI、generated client 和受影响说明；记录存量整理的受控执行方式、作用范围与验证结果，明确区分实施整理和本票发布。

## Validation

- 使用真实场次版本 HTTP 和数据库事务保存并回读合法资产多图、人工组、多人物与物件各自不同来源；通过受控模型输入验证一组合规多图确实只占一个主体，顺序保持。
- 通过 HTTP 覆盖新提交空对象、多对象、多组、资产混用、资产加人工、不存在对象、缺省／非法角色及稳定来源名称差异；非法提交均失败且原记录保持。已有契约与输入组装测试补齐异常组合，不替代 HTTP 验证。
- 在隔离数据库建立存量样本：合规多图、原本多组多来源、同源无组标识、同源跨组、空／多对象组、首个参考不可用但后续有效、无有效幸存者、仅来源失效但文件合法，以及仅文件／能力问题的合规组。
- 组合样本同时包含会被移除的非法组及可保留多图，验证基于原始分类，不能通过删除顺序额外保留；重复整理应产生相同结果。
- 整理前后比较其他用途、首尾帧、连续性引用、其他单元合规内容、不可编辑版本、固定任务和 Take 输入；只有实际发生清理的输入触发相应依据／检查核对。通过真实事务验证失败不留下部分更新。
- 真实画布浏览器验证同资产追加多图、人工组添加、人物／物件目标、来源冲突提示及整理后的真实缺项。使用原有参考入口即可验收，无需等待 05。
- 测试使用隔离样本，不对真实用户数据试运行清理，不调用付费模型。完成相关契约／集成／浏览器测试、前端类型与工作台回归、后端 Pylint，并按共享校验影响扩展测试及报告局限。

## Scope and handoff

本票将新规则和存量处理作为一个可验收交付，复用场次版本业务存储、事务和现有模型输入组装；不在展示层独占约束，不引入读取时自动合组。

现有文件选择去重边界沿用，不新增同文件跨对象／输入位置复用能力，也不因历史文件重复额外清理。显式的跨来源整组替换由 [04](04-replace-identity-reference-source.md) 负责；本票提供其所需的唯一目标组、来源规则及服务器校验。
