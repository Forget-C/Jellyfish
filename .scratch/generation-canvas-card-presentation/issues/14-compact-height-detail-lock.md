# 14: 紧凑设计卡选档与详情锁高

Blocked by: None
Status: ready-for-agent
Resolution: completed

**What to build:** 验收要求、不可改事实、对白、叙事事件和表演规则五类紧凑设计卡根据实际摘要收紧高度。用户打开详情后卡高保持稳定，摘要继续更新，关闭详情后一次恢复到最新内容所需档位；卡面和画布几何同步变化。

**规格依据：** [规格第二版](../spec.md)，尺寸与摘要、详情锁高、统一几何；本轮Q1–Q8、Q16、Q18。原01–13号票的完成记录不代表本票已实现。

- [x] 五类紧凑卡固定宽360px，从128／160／192px中选择能容纳正常可见摘要、必要提示、标题和标准内边距的最小档位。尺寸包含标题，画布缩放不改变逻辑档位。
- [x] 保留各卡既有摘要优先级，核心最多4行、辅助最多1行；名称只在标题，无大幅用途图。对白的说话对象与正文仍按既有预算表达。空态和只有辅助信息分别准确显示，不为未展示字段、空行或隐藏配置撑高。
- [x] 内容增多和减少都可重新选档；一次应用预设、清空等同批变更只处理最终结果。只依据当前有效内容，不等待保存回包。错误全文、保存状态不撑高，摘要业务状态正常参与预算。
- [x] 打开同一卡详情即锁高，包括预设页、参数页和只读详情；切页、展开／收起、失焦和临时隐藏均保持锁定，真正关闭或切换卡片才释放详情锁。普通选中、悬停和聚焦不锁高。
- [x] 锁高期间摘要、名称和问题图标继续反映最新内容；摘要按当前容量及既有优先级省略后续内容，不保留旧摘要、不缩字号、不增加卡内滚动或更多入口。
- [x] 解除详情锁后，在没有其他锁的前提下一次应用最新目标档位。正常预算的目标高度不受锁高期间临时截断影响，不形成“越截断越变小”的循环。详情与手势叠加的完整场景由17号票接入。
- [x] 复用现有卡壳、摘要和几何入口建立统一的实际显示尺寸；卡面、连线端点、选框、小地图、适应全部及已有分组边框同步使用它，不只修改CSS。不建立通用卡片框架或另一套编辑状态。
- [x] 高度直接变化，无伸缩或逐档动画；保留卡片左上角、其他卡片位置、缩放和视角，不因尺寸变化额外平移或自动重排。既有选中、焦点及详情让位行为继续有效。
- [x] 未锁高的非最低档，扣除标准底部内边距后的额外留白小于32px；最低档允许最小外框所需空间。最大档下预算内内容仍被遮挡或裁切判为失败，不能以隐藏溢出通过。
- [x] 复用生成画布页面级浏览器入口，覆盖五类空态、短摘要、满预算、超长及辅助信息，并演示“打开→编辑升／降档需求→同会话切换→关闭或换卡”的完整路径；包含只读、桌面、390px窄屏与缩放。
- [x] 浏览器检查实际内容、尺寸和端点，不用生产选档函数生成期望值；人工查看空态、短文、长文及锁高截断截图。原有点击详情、预设入口、问题定位及子操作不回归。
- [x] 运行前端typecheck及受影响测试，按共享修改影响扩展回归。实施后同步工作台设计标准与画布架构中实际落地的紧凑选档、详情锁高及尺寸职责，记录证据与未完成项，不将后续票范围提前标为完成。
