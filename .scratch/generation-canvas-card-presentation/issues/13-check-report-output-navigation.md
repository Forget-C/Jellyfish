# 13: 检查报告与产物问题定位

Blocked by: 08, 09, 10
Status: ready-for-agent
Resolution: completed

**What to build:** 检查结论带用户进入正确条目或报告，产物问题进入对应结果阅读；明确的设计来源另给定位入口。用户能够阅读证据，而不会把检查结论误当作参数错误。

**规格范围：** 复用10的问题入口，以及08／09和其前置07交付的四模态结果阅读；接通检查、历史报告和产物目标。

- [x] 检查不通过、无法判断、结果失效等首先打开明确检查条目或报告，不统一切到设计参数页，也不把它们自动升级成新的技术阻断规则。
- [x] 报告入口展示结论、适用边界、证据及明确关联条目；来源定位仅在存在可靠来源时独立提供，不把来源存在等同于该字段错误。
- [x] 普通重开检查详情恢复既有页签、展开与滚动；明确条目／报告入口优先定位。返回检查时沿用现有阅读恢复行为。
- [x] 产物问题根据明确目标打开对应文本、图片、音频、视频结果阅读或相关报告，不推测设计责任字段；结果保持只读及正确生成来源。
- [x] 当前输出阅读跟随当前输出；历史报告继续针对固定产物和原生成依据，不能因输出更新偷偷改成新文件或当前设计。
- [x] 历史产物、报告条目、来源或当前结果缺失时如实显示不可用，不展示其他条目或新输出假装定位成功；无可靠目标仅解释。
- [x] 多目标分别提供入口，导航不重新检查、不重新生成、不修改采用或检查选择，不改变生成成功状态。
- [x] 检查卡保持400×424、最多四项摘要与独立快捷执行，生成前计数与生成后产物状态分开；点击条目与执行按钮保持隔离。
- [x] 检查详情继续使用共享长表单Modal、页签和底部动作；只读及窄屏保持可读，导航来源使用既有详情替换／返回机制。
- [x] 复用检查模型、生成后检查、自动检查及结果阅读浏览器场景，覆盖逐项／报告定位、历史证据、四模态产物、输出更新、缺失目标、只读及无意外执行。
- [x] 使用固定媒体和可控运行／报告数据，不要求付费模型调用；运行typecheck及受影响检查，同步检查／结果导航规范及架构事实，不改变检查目录或执行职责。
