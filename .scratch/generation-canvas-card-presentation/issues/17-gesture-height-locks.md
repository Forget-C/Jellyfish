# 17: 拖动与连线期间锁高

Blocked by: 14
Status: ready-for-agent
Resolution: completed

**What to build:** 用户拖动单卡、多卡、分组或建立连线时，相关卡片外框、组框及连接端点保持稳定。详情与手势同时发生时，各自持有的锁独立释放，全部解除后统一应用最新内容所需高度。

**规格依据：** [规格第二版](../spec.md)，操作期间锁高与整理互斥；本轮Q2、Q5、Q6、Q14、Q16–Q18。

- [x] 单卡拖动锁定该卡，多卡拖动锁定全部目标，分组拖动锁定全部可见成员；手势中内容变化不改变其实际高度或组框形状，既有移动坐标行为保持。
- [x] 连线手势锁定来源卡与当前目标卡，目标改变时按当前参与对象维护锁；来源和目标的连接端点始终与实际外框一致。
- [x] 手势完成或取消只释放该手势的锁。详情仍打开时不得随手势结束解锁；连线造成详情临时隐藏仍保留详情会话及其锁。
- [x] 多原因同时锁定时仅在全部释放后一次应用最新目标档位，不逐项、逐档回放中间高度，不遗留锁导致以后内容永久不选档。
- [x] 锁高不暂停内容更新或保存。卡面摘要按当前空间显示最新内容，名称与问题图标继续更新，不将进入手势时的旧内容当作当前设计。
- [x] 普通选中、悬停、焦点不引入锁；既有点击打开、拖动阈值、键盘／触摸操作及独立按钮行为保持，不因新增锁误开详情或触发执行。
- [x] 拖动或连线手势中禁止启动“整理布局”，包括现有可达入口；手势完成或取消后恢复正常可用性。仅打开详情不会禁止整理。
- [x] 实际显示尺寸始终供卡面、连线、选择范围、分组和小地图共同消费。解锁只更新高度，不自动移动邻卡或改变视角；无伸缩动画。
- [x] 在已有页面级交互及组合交互用例中演示单卡、多卡、分组、连线目标切换、取消与详情叠加；操作期间注入有效内容更新，核对锁定时及逐个释放后的可见行为，不只验证结束截图。
- [x] 使用已接入的设计类型即可独立完成验收；结构化与视觉迁移接入后复用同一机制，不要求15或16先完成。覆盖鼠标及现有键盘／触摸取消路径、只读浏览的适用场景、桌面与390px。
- [x] 运行前端typecheck及受影响测试，人工查看端点与组框证据；实施后同步锁叠加、释放与整理互斥的规范和架构事实，不扩展新的手势或业务连接规则。
