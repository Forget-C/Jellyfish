## Problem Statement

第一版已经落实25类设计卡的摘要预算、按类型固定尺寸、统一详情入口、问题定位和结果阅读复用，但同类型的空态、单行内容和满摘要仍使用同一高度，画布上持续出现大块无用途的底部空间。单纯整体缩小固定高度只能改善长摘要，不能解决空态和短摘要的问题。

文本模型也沿用图片、视频模型的424px外框，有限文字预览下方存在明显闲置空间。与此同时，完整媒体预览的比例空边与检查卡的条目、操作预留区具有实际用途，不能按相同标准一律压缩。

普通“整理布局”仍使用固定560px行距，卡片缩小后也会留下过大的行间空间。若只修改卡面CSS而未同步连线、分组、缩略图、新增定位、缓存和撤销机制，会产生可见尺寸与画布几何不一致的问题。

用户需要内容较少时卡片收紧、内容较多时保留正常摘要容量，同时在阅读、编辑、拖动和连线期间保持操作稳定。现有验收仅检查固定尺寸与溢出，不足以判断留白是否合理。

## Solution

为设计卡采用固定宽度、有限高度档位，并根据实际可见摘要、必要提示及标准内边距选择最小可容纳档位。保留25类设计卡已有摘要优先级和行数上限，不按全文长度连续增长。卡面用于识别和浏览，点击卡面统一打开详情；完整内容继续通过现有浮窗、Modal及内容阅读组件查看。

详情会话、拖动及连线期间锁定有关卡片高度，但继续显示最新内容；全部锁解除后一次应用最新档位。尺寸更新不自动重排用户布局。主动整理按实际显示外框及64px间距排列，保留分组内部关系与结果卡的专用排布。

文本模型单独采用固定高度，先以224px验证全部必要状态；媒体、内容、检查及结果卡维持已确认固定尺寸。新增最小选档、底部额外留白、锁高和跨组件几何一致性的验收条件。

设计卡根据当前有效设计内容决定普通打开时进入预设页还是参数页。问题入口按明确的处理目标进入标题、字段、阶段、关系、报告或结果阅读位置；无可靠目标时仅解释问题。

不同模态的结果复用对应内容卡的展示和阅读组件，保留输出标识、来源连线、只读及跟随当前输出更新的行为。尺寸变化同步覆盖画布几何计算，保留用户已有坐标、分组和视口。

## User Stories

1. As a 生成画布用户, I want 不同内容形态使用合适的尺寸档位, so that 短内容不会被大块空白淹没。
2. As a 生成画布用户, I want 设计卡按实际摘要选择有限高度且在操作期间锁高, so that 少内容时空间紧凑且编辑时操作目标稳定。
3. As a 生成画布用户, I want 验收要求等文本设计优先展示核心正文, so that 我能直接读到判断标准。
4. As a 生成画布用户, I want 结构化设计展示少量关键字段, so that 我能迅速比较卡片内容。
5. As a 生成画布用户, I want 视觉设计保留用途示意图和关键参数, so that 我能理解设计用途且不会把示意图当成生成成果。
6. As a 生成画布用户, I want 名称只在标题出现, so that 正文空间留给实际设计。
7. As a 生成画布用户, I want 摘要按卡片职责排序, so that 字段存储顺序不会影响重要内容的可见性。
8. As a 生成画布用户, I want 长内容按有限行数截断且保留原意, so that 我不会读到模型自行改写的设计。
9. As a 生成画布用户, I want 不显示额外配置数量或更多图标, so that 卡面保持简洁且点击即可查看详情。
10. As a 生成画布用户, I want 核心内容缺失与已有辅助信息分别表达, so that 我不会把部分配置误解为完整设计或完全空白。
11. As a 生成画布用户, I want 待确定、不适用、明确没有及失效来源保持准确含义, so that 不同业务状态不会被混为错误。
12. As a 生成画布用户, I want 点击任何卡面都能打开对应详情, so that 我不必记忆设计卡的特殊编辑入口。
13. As a 键盘或触摸用户, I want 能打开卡片、访问菜单和阅读问题说明, so that 操作不依赖鼠标悬停。
14. As a 生成画布用户, I want 播放、快捷检查、菜单和连线操作不会误开详情, so that 卡片内独立操作可靠。
15. As a 生成画布用户, I want 拖动只移动卡片, so that 布局操作不会意外打开编辑器。
16. As a 生成画布用户, I want 浮窗和Modal沿用共享工作台样式及行为, so that 不同卡片的编辑体验一致。
17. As a 窄屏用户, I want 详情保持可读且操作可达, so that 我不需要在裁切的浮窗内编辑。
18. As a 只读画布用户, I want 可以打开完整内容但不能修改, so that 我仍能审阅设计和产物。
19. As a 设计用户, I want 未填写或清空设计后进入预设页, so that 我可以从已有方案开始。
20. As a 设计用户, I want 当前内容完整匹配预设时显示匹配预设, so that 手写或撤销恢复后的相同内容具有一致入口。
21. As a 设计用户, I want 自定义参数或额外设计使详情默认进入参数页, so that 我能直接继续编辑实际配置。
22. As a 设计用户, I want 修改名称、来源、范围或关联不会单独改变预设归类, so that 辅助信息不会干扰设计编辑入口。
23. As a 设计用户, I want 编辑过程中不会因匹配状态变化自动切页, so that 当前工作不会被打断。
24. As a 设计用户, I want 没有预设的对白、事实和空间锚点直接进入参数页, so that 不会看到无意义的空预设列表。
25. As a 设计用户, I want 应用预设保留其未覆盖的配置, so that 切换预设不会意外清空已有设计。
26. As a 生成画布用户, I want 标题问题图标显示已有明确诊断, so that 我能快速发现需要处理的卡片。
27. As a 生成画布用户, I want 问题清单提供明确命名的处理入口, so that 我知道点击后将查看什么。
28. As a 生成画布用户, I want 名称问题定位到标题名称, so that 不会为了改名被送到无关参数页。
29. As a 生成画布用户, I want 明确的字段或阶段问题展开并定位对应位置, so that 我不必在长表单中寻找。
30. As a 生成画布用户, I want 关系及连线问题定位实际关联位置, so that 我不会把连接问题误当成正文错误。
31. As a 检查用户, I want 检查结论优先打开条目或报告且来源定位独立提供, so that 不通过或无法判断不会被直接归因于某个字段。
32. As a 生成画布用户, I want 产物问题打开结果或相关报告, so that 我能先阅读实际证据。
33. As a 生成画布用户, I want 多个相关对象分别提供入口, so that 系统不会擅自选择责任卡片。
34. As a 生成画布用户, I want 无目标或目标失效的问题有真实说明, so that 界面不会假装已经准确定位。
35. As a 生成画布用户, I want 保存和网络等全局问题留在画布状态区域, so that 每张卡不会重复显示同一故障。
36. As a 生成画布用户, I want 定位操作只查看和导航, so that 它不会自动改参数、解除关系或重新执行检查。
37. As a 结果阅读用户, I want 文本结果通过文本内容组件阅读全文并选择复制, so that 卡面截断不会造成信息不可达。
38. As a 结果阅读用户, I want 图片、视频和音频结果复用已有预览及播放器, so that 不需要学习新的阅读方式。
39. As a 结果阅读用户, I want 结果保持只读且明确来自生成, so that 不会误以为可以直接替换模型输出。
40. As a 结果阅读用户, I want 打开详情后看到该输出位置的最新内容, so that 卡面与详情保持一致。
41. As a 结果阅读用户, I want 新音视频不自动播放或继承旧文件播放位置, so that 输出更新不会突然发声或跳到错误时间。
42. As a 生成画布用户, I want 显式复制结果后才创建独立内容卡, so that 阅读结果不会污染画布文档。
43. As a 检查用户, I want 保留最多四项摘要和独立快捷检查, so that 我能在卡面完成常用操作且不会误触执行。
44. As a 历史画布用户, I want 新尺寸保留已有坐标、视口和分组, so that 已组织好的画布不会自动重排。
45. As a 生成画布用户, I want 连线、分组及缩略图与实际卡片尺寸一致, so that 布局和连接位置可信。
46. As a 生成画布用户, I want 自己决定是否整理布局, so that 尺寸升级不会擅自移动其他卡片。
47. As a 生成画布用户, I want 空态、短摘要和满摘要采用各自最小可容纳高度, so that 同类型卡片不会一律为未使用的内容预留空间。
48. As a 设计用户, I want 详情中未出现在摘要的配置不撑高卡面, so that 完整设计的复杂度不会破坏画布浏览密度。
49. As a 设计用户, I want 内容增多和减少都能重新选档, so that 清空或精简后的卡片不会保留过去的大外框。
50. As a 设计用户, I want 打开预设、参数或只读详情期间保持卡高, so that 阅读和操作不被尺寸变化打断。
51. As a 设计用户, I want 同一详情切页、展开、收起或临时隐藏不解除锁高, so that 同一编辑会话保持连续。
52. As a 设计用户, I want 锁高期间摘要仍显示最新内容并按当前容量省略, so that 卡面不会保留已被修改的旧设计。
53. As a 设计用户, I want 关闭详情或切换卡片后恢复正常摘要容量, so that 新内容可按已确认预算展示。

## Implementation Decisions

### 1. 范围与业务边界

- 仅调整独立生成画布的卡面呈现、详情入口、结果阅读复用及已有问题的定位。场次工作台的设计、试拍、剪辑与验收流程不在本规格范围内。
- 遵守现有术语与已接受的独立生成画布、组件与协议边界、检查卡及声音职责决定。
- 画布文档、画布运行、生成结果集、输出标识、布局缓存分别保持既有职责。展示调整不新增生成许可或素材采用语义。
- 预期无需修改后端持久化schema、数据库或对外API契约。现有诊断目标可用于前端路由；无结构化目标的文字提示不通过猜测补目标。
- 不为本功能新增预设采用历史、编辑历史标记或持久化结果卡类型。

### 2. 尺寸档位

所有尺寸为100%缩放下、包含标题的卡片外框。设计卡宽度固定，高度从所属形态的有限档位选择；画布缩放不改变逻辑档位。正文预算是上限，未使用的行不预留空间。其他卡片沿用下表固定尺寸。

| 内容形态 | 适用对象 | 宽×高 | 内容预算 |
| --- | --- | --- | --- |
| 紧凑设计 | 验收要求、不可改事实、对白、叙事事件、表演规则 | 宽360，高128／160／192 | 核心最多4行，辅助最多1行 |
| 结构化设计 | 下节列出的14类 | 宽360，高128／160／192／224 | 2–3项关键内容，合计最多6行，一般每项最多2行 |
| 视觉设计 | 风格、机位、构图、光线、焦点、运镜 | 宽360，高240／272／304 | 保留现有96px用途示意图及合计最多4行参数摘要 |
| 文本内容 | 基础文本、创作依据、人物／场所／道具／服装描述、文本结果 | 400×172 | 最多4行正文及适用的字数、来源或状态 |
| 音频内容 | 基础音频、音频结果 | 300×172 | 播放器、名称、已知时长及状态 |
| 图片和视频内容 | 基础图片／视频及对应结果 | 300×251 | 媒体预览及必要状态 |
| 资产参考 | 人物／场所／道具／服装参考 | 300×251 | 预览、名称、角度、来源／关联状态 |
| 文本模型 | 文本模型卡 | 360×224，固定高度的待验证值 | 四行输出摘要、适用的临时输出说明和底部状态 |
| 媒体模型 | 图片、视频模型卡 | 360×424 | 保留媒体预览、独立操作和执行状态 |
| 检查 | 检查卡 | 400×424 | 目标、计数、最多4项检查及快捷操作 |

- 三类设计的档位集合及摘要预算已确认。根据正常预算下实际可见摘要、必要提示、标题和标准内边距，选择最小可容纳档位；不根据编辑表单是否填满、全文长度或隐藏配置数量选档。实现应避免锁高期间的临时截断反过来影响正常目标高度。
- 文本模型224px是实施验收项：空态、流式、成功、失败、取消及保留旧结果的状态使用同一固定高度。若必要内容放不下，重新定标并记录证据，不减少必要状态信息；不随输出长度逐次选档。
- 设计卡未锁高时，一次完整内容变化后可升档或降档；预设应用、清空、撤销等同批更新只处理最终结果。档位不变则不改变尺寸。
- 依据当前画布正在显示的有效内容，包括尚未保存成功的本地修改。保存失败保留本地内容与对应高度，保存回包本身不触发选档；撤销、恢复或接受服务端内容导致实际内容改变时重新计算。
- 错误全文、保存状态和检查进度不参与设计选档。问题沿用标题图标及详情表达；摘要中的待确定、不适用、失效画面等业务状态保留并参与正常预算。
- 容许最低档必要留白，不通过放大图示、缩小字体、拉伸文字或重复信息填满卡面。媒体等比预览的比例空边、检查操作区预留不套用设计摘要的留白阈值。
- 紧凑与结构化设计使用标题类型图标，不保留大幅通用用途示意图；六类视觉设计保留明确标识用途的示意图，不伪装成生成结果。
- 模型卡流式更新及多输出状态不改变尺寸。

### 2.1 操作期间锁高

锁高仅限制实际显示高度，不阻止内容更新、自动保存或业务状态刷新。普通选中、悬停和键盘聚焦不锁高。

| 锁定原因 | 涉及卡片 | 保持与释放条件 |
| --- | --- | --- |
| 详情会话 | 当前打开详情的卡片，包括只读详情 | 真正关闭或切换到另一张卡时释放；预设／参数切换、展开／收起、失焦及连线导致的临时隐藏均保持 |
| 拖动 | 单卡、多卡拖动的全部目标；分组拖动的全部可见成员 | 手势结束或取消释放对应操作锁 |
| 连线 | 来源卡与当前目标卡 | 按当前参与对象维护对应操作锁；手势结束或取消释放 |

- 多个锁可叠加，只有全部解除才更新高度。某项手势结束不得释放仍存在的详情锁或其他操作锁。
- 锁高期间摘要继续显示最新内容，在当前可容纳空间内沿用优先级省略后续内容；不显示旧摘要，不缩小字号，不增加卡内滚动或更多图标。名称和问题图标继续更新。
- 全部解锁后直接应用最新目标档位，恢复正常摘要容量；不逐档播放变化。
- 未锁高时，全文超过摘要预算属于正常省略；在最大档位下，预算内摘要或必要提示仍被裁切、遮挡属于布局缺陷，不可用隐藏溢出掩盖。锁高期间的临时省略是明确例外。

### 3. 设计摘要目录

表中为显示优先级，不表示必须全部显示。正文受所属档位的行数预算约束，其余完整内容仍在详情中可达。

| 档位 | 设计类型 | 优先摘要 | 其他内容处理 |

通用规则：

- 名称仅在标题展示，不占摘要条目。
- 直接呈现已有内容的有限摘要，不调用模型改写，不依赖后端字段排列顺序。
- 优先显示已配置的核心字段。核心未填写时如实提示，已有辅助内容仍可展示，不把部分配置误报为完成或全空。
- 保留待确定、不适用、明确没有、失效来源等含义；默认值、空字段和名称不构成设计完成标志。
- 来源显示可读名称及真实状态，不用原始内部ID充当正常名称。
- 按行数省略长内容，卡面不滚动正文全文。移除“另有N项配置”、更多文字及更多图标。
- 设计卡不再显示开始设计、编辑设计或查看设计按钮；内容通过整卡入口可达。
- 检查卡保留最多4项及独立快捷执行。生成前计数与生成后产物状态分别表达，不新增整卡通过标志，也不改变检查执行规则。

### 4. 卡壳、浮窗及Modal

- CardShell负责共同标题、选择、拖动、菜单、端口、整卡打开及可选问题状态位置；类型内容继续由明确的展示组件提供。
- 单击卡面及已有键盘激活方式打开详情。按钮、菜单、播放器、问题入口、链接和端口保持独立交互；拖动不触发打开。
- 只读卡仍可打开完整内容，修改能力遵循原有只读规则。
- CanvasCardEditor继续作为统一详情外壳。桌面普通详情沿用锚定浮窗并可展开；现有复杂设计、检查卡及窄屏按既有Modal规则处理，不把全部编辑器强制改为一种容器。
- 复用共享页签、表单、标题及底部动作样式，保持正文滚动与固定操作区边界；不建立平行的编辑器样式体系。
- 打开、展开及关闭详情不更改卡片坐标或重排其他卡片。锚定浮窗沿用已有最小视口让位及焦点、关闭、保存规则。
- 普通检查详情重开恢复既有页签、条目及滚动状态；明确条目／报告入口优先定位，不套用设计卡预设规则。

### 5. 预设与参数默认入口

仅在普通打开设计详情时，根据当前有效设计内容判断，不依赖用户曾点击的按钮或编辑历史：

| 当前内容 | 默认入口 |
| --- | --- |
| 无有效设计，或有效设计已清空 | 预设页 |
| 完整匹配某个预设且没有额外自定义设计 | 预设页，标识匹配预设 |
| 手动输入与预设一致，或撤销后恢复匹配 | 同上 |
| 仅名称、来源、范围或关联发生变化 | 不因此改变设计归类 |
| 设计参数改变，或增加预设外实质设计内容 | 参数页 |
| 对白、不可改事实、空间锚点 | 无预设，始终直接参数页 |

- 只有名称、范围、来源或关联而没有有效设计时，按未配置处理。
- 开启后的会话不会因为编辑、应用预设或匹配变化自动切页；用户可主动切换。
- 预设匹配必须识别额外实质设计，不直接沿用不完整的局部字段匹配结论，也不能仅凭显示文字相同忽略实际引用内容。
- 应用预设继续只覆盖其声明的配置，保留未覆盖内容。A切换到B后若保留了额外实质设计，整卡为自定义；下次普通打开进入参数页。不得仅因刚点选B就声明整卡是纯B。
- 明确问题目标按下一节路由。只有目标确实属于设计参数区时才强制进入参数页。

### 6. 问题展示与导航

- 标题操作菜单前提供一个可选问题图标。已有明确错误使用红色、警告使用黄色；同时存在时显示最高严重程度，清单保留各问题说明。
- 有问题时图标可见，支持悬浮、键盘聚焦及点击读取；有可访问名称，不能只靠颜色或鼠标悬停表达。
- 图标首先展示问题清单，不立即把用户送到参数页。按实际能力提供定位字段、查看关联、查看报告等明确命名的入口。
- 颜色仅表示严重程度，路由由结构化目标及实际处理位置决定。仅展示已有且明确归属于卡片的诊断；待确定或不适用不自动成为错误。

| 问题范围 | 目标与动作 | 限制 |
| --- | --- | --- |
| 名称 | 打开详情并定位标题名称 | 不强制进入参数页 |
| 明确设计字段／运镜阶段 | 参数页内展开对应分组／阶段并定位 | 目标必须有效且明确 |
| 模型配置 | 打开明确对应的配置位置 | 纯能力提示不推测要修改哪项设计 |
| 关系、来源、连线 | 定位相关卡片、连线或关系控件 | 按实际处理位置决定是否打开详情 |
| 检查结论 | 打开条目或报告 | 来源定位是另一个明确入口；不通过、无法判断、失效不等同字段错误 |
| 产物问题 | 打开结果阅读或相关报告 | 不直接归因于某个设计字段 |
| 整卡或跨卡 | 明确相关卡片入口 | 多目标分别提供，整卡普通打开遵循该卡规则 |
| 保存、网络、版本冲突等全局问题 | 画布状态区域及已有恢复操作 | 不分摊到所有卡片，不打开参数页 |

- 保留已有诊断中的卡片、字段路径、阶段、引用、连线及报告目标；导航层不得只传卡片ID而丢失可用定位信息。
- 没有可靠目标时仅展示说明，不按错误文字猜字段或责任卡片。
- 字段失效但卡片仍在时，可以打开卡片并说明无法定位原位置；卡片也不存在时保留说明，不跳到替代对象。
- 堆叠内不可直接访问的目标沿用已有堆叠定位和解释规则，不绕过组织状态强开隐藏成员。
- 导航仅查看和定位，不自动修改参数、切换模型、解除关联、执行检查或重新生成。
- 检查报告中的历史依据继续固定；本节不把历史证据偷偷替换为当前可编辑内容。

### 7. 结果与内容组件复用

- 四模态结果复用对应内容卡的展示与阅读组件。结果仍是当前输出在画布上的展示投影，不新增持久化卡片类型。
- 保留原有输出标识、虚拟身份、来源关系、可用性及依据状态。打开详情不写入画布文档，不推进保存修订。
- 结果详情在可编辑画布中也只读；不把投影交给普通卡片编辑回调。隐藏不适用的导入、选择及替换操作。
- 明确生成来源，不能因缺少普通素材来源字段而误显示为项目文件。
- 文本全文可选择复制，本轮不新增复制全文按钮。图片、音频、视频复用已有预览与播放器，不重复建设阅读器。
- 普通结果详情跟随对应输出位置的最新正式内容更新；未完成或失败成果继续遵守原有运行与结果集边界，不能替换正式输出。
- 音视频换成新文件后不自动播放，不沿用旧文件播放位置；仅状态刷新且文件未变时不应无故重置播放。
- 输出消失时如实表达不可用，不将旧内容假装成当前可用输出。
- 显式复制为内容卡时才创建可独立编辑的副本，副本不继续跟随原模型输出更新。

### 8. 几何、布局与连线

- 尺寸规则集中提供正常目标高度与当前实际显示尺寸；锁高时实际显示尺寸保持锁定值。卡壳、连线端点、选框、分组、小地图、适应全部、新增空位搜索、复制粘贴及可见性判断均使用一致的实际尺寸，不能只改CSS或继续绕过公共规则读取旧类型常量。
- 高度直接切换，不播放伸缩动画，不逐档变化；卡面和有关几何同步更新，保留原有选中、悬停与焦点反馈。
- 高度变化保持卡片左上角、其他已有卡片坐标、画布缩放与视角不变，不为尺寸更新触发额外的视口让位。已有打开详情、展开／收回和视口缩小时的让位规则保持。
- 增高造成重叠时不自动推开其他卡片，不自动二次整理；用户自行移动或主动整理。
- 不改变连接用途、采用、引用保护、结果身份或执行规则。

### 8.1 主动整理

- 普通卡保留三列及现有排布方向。每列宽度由该列最宽外框决定，每行高度由该行最高外框决定；相邻行、列的布局间距均为64px，外框包含标题。较短或较窄卡片在同行／列中产生的差额不属于固定行距缺陷。
- 分组作为整体沿现有方向排布，与相邻排布单元间距64px，保留组内成员相对位置；不引入新的智能布局或组内自动重排算法。
- 结果卡保留跟随模型的专用排布及既有避让规则，不混入普通卡网格。
- 详情打开期间可主动整理，按锁定中的实际显示高度计算，不关闭详情或提前解锁。随后关闭详情导致高度变化时，不再自动整理一次。
- 拖动或连线手势进行期间暂时禁止启动整理，避免并发改变布局。

### 8.2 分组与堆叠

- 展开分组的边框跟随成员实际尺寸更新，不改变成员坐标。拖动分组时按锁高规则稳定全部可见成员及组框。
- 收起分组的300×110外框及堆叠封面的400×300外框维持现状；成员新高度不改变收纳封面尺寸或其连线依据。
- 展开分组或解除堆叠后，恢复原有成员坐标并按当前摘要及适用锁确定显示高度。
- 主动整理不保证消除组内原有或增高产生的重叠，用户手动调整成员。本轮不新增组内整理入口。

### 8.3 缓存、首次展示及撤销

- 保留既有坐标、视口、分组和手动布局信息，不整体清空缓存。旧尺寸只可作为实现中的辅助信息，不能覆盖当前规则与内容得出的实际尺寸。
- 重开画布首次展示采用当前内容对应档位；首次布局就绪前不展示可操作的错误临时外框，不先展示旧大卡再逐张缩小。测量和缓存实现由现有布局机制承担，不新增用户配置。
- 高度派生不新增画布文档字段、保存修订或独立撤销步骤。撤销／重做内容后计算新的目标高度，仍服从当前锁；解除锁定后采用最新内容结果。
- 撤销拖动或主动整理恢复原有位置和对应视图状态，高度继续按当前内容与锁确定，不能强制恢复旧内容对应的缓存尺寸。

### 9. 组件实施顺序

本表只列第二版新增实施工作。第一版已落地的详情入口、摘要目录、预设判定、问题定位和四模态阅读继续作为基线与回归约束，不重新标为待实现。

| 阶段 | 现有职责／组件 | 工作与出口条件 |
| --- | --- | --- |
| 1 | cardGeometry、FlatDesignCard、VisualDesignCard及共享DesignCardBody | 保留摘要语义，建立有限高度选档，区分正常摘要预算与锁高时的临时可见容量 |
| 2 | CardShell、CanvasCardEditor及详情／拖动／连线会话 | 消费实际显示尺寸，处理锁的叠加、会话保持、取消及最终释放；不复制业务编辑状态 |
| 3 | GenerationCanvasGraph、useGraphLayout、分组与结果定位 | 统一所有几何消费者、新增及复制路径，保留坐标与视角，完成首次展示和缓存兼容 |
| 4 | 既有主动整理与撤销机制 | 落实实际列宽／行高、64px间距、分组内部位置保护和锁高中的整理规则 |
| 5 | ModelGenerationCard、GenerationCardFrame | 文本模型独立固定高度定标，保留媒体模型、内容卡、结果和检查卡尺寸与阅读行为 |
| 6 | 现有浏览器验收和规范维护 | 覆盖25类卡面、留白、锁高、几何、恢复和相关回归，记录文本模型最终高度及实施事实 |

使用现有模块及少量集中配置，不为本次需求增加通用卡片框架、通用导航引擎或新的诊断系统。模块名说明职责，不要求机械抽取同名新模块。

## Testing Decisions

### 已确认的主要验证边界

用户在本轮Q18及最终汇总中已确认以现有生成画布页面的浏览器集成测试为主要入口，复用现有隔离环境、测试素材与可控运行数据。该确认同时满足to-spec的测试边界确认步骤，不新增确认门槛。通过用户操作和可观察结果验证行为，不以组件内部状态、函数调用次数或CSS类名本身作为成功标准。几何检查针对可见尺寸、裁切和连接位置；截图作为人工检查留白、层级和可读性的证据，不单独承担行为验收。

沿用一个页面级集成边界组织以下场景，不为每个小组件建立新的测试接缝。第二版重点验证高度、会话和布局；第一版其他行为作为受影响回归，不重复建设测试工具。

| 测试组 | 关键场景 | 成功标准 |
| --- | --- | --- |
| 最小选档与留白 | 全部25类；空态、单行、短摘要、满预算、超长内容、辅助信息、业务状态、只读；增多与减少内容、预设应用、清空 | 选择最小合法档位；不为隐藏配置或空行保留空间；非最低档额外底部留白小于32px；预算内内容完整 |
| 详情锁高 | 预设／参数、只读、展开／收起、失焦、临时隐藏、关闭及切换卡片；锁高时补充或删除内容 | 会话中尺寸稳定且摘要更新；正常切页不解锁；真正退出后一次恢复最新正常容量 |
| 手势与叠加锁 | 单卡、多卡、分组拖动；连接来源与当前目标；详情与手势同时存在；结束与取消 | 参与对象、组框和端点稳定；一项锁释放不影响其他锁；全部释放后更新，无误开详情 |
| 保存与撤销恢复 | 延迟或失败保存、接受服务端内容、内容撤销／重做、拖动与整理撤销、旧尺寸缓存、重开画布 | 尺寸依据当前有效内容；不新增保存或撤销步骤；位置与视角保留；旧高度不覆盖新规则且首次显示不跳变 |
| 几何与主动整理 | 连线端点、选择范围、分组、小地图、适应全部、新增、复制粘贴；普通三列、混合宽高、分组、堆叠、结果卡 | 使用实际显示尺寸；列最大宽度和行最大高度决定起点，布局间距64px；组内位置保留；结果专用排布保留 |
| 整理与锁高交互 | 详情打开时主动整理、关闭后选档；拖动／连线时尝试整理 | 使用当前锁定高度，不关闭详情、不提前解锁、不自动二次整理；手势中不能并发整理 |
| 固定尺寸与运行 | 文本模型空态、流式、成功、失败、取消、旧成果；图片／视频模型；检查卡条目与进度；四模态内容及结果 | 文本模型候选224px容纳必要内容且运行时同高；其他尺寸和必要操作不受影响；媒体空边不误判为设计留白 |
| 打开与编辑 | 卡面鼠标／键盘／触摸、拖动、菜单、播放器、快捷检查；预设匹配、手写匹配、额外参数、连续性分类及额外内容、仅辅助信息、清空、撤销、预设A到B；直接参数卡；浮窗／展开／Modal | 子操作无误触；默认入口正确；会话内不自动跳页；预设不清空未覆盖内容；只读与窄屏可操作 |
| 问题导航 | 标题名称、设计字段、阶段、模型配置、关系、连线、检查条目、历史报告、结果、全局错误；多目标、无目标、失效字段／卡片、堆叠目标 | 问题级别和所属正确；只对可靠目标提供动作；不误跳参数页；降级真实；点击不修改业务数据或触发执行 |
| 结果阅读 | 四模态只读阅读、长文本选择复制、当前输出替换、音视频换文件、同文件状态刷新、缺失输出、历史报告与当前结果区别、显式复制副本 | 复用内容阅读；来源正确；详情跟随当前正式输出；无自动播放／错误时间继承；阅读不建卡，副本独立 |

### 既有测试先例与复用

- generation-canvas-photography-card已经在真实页面覆盖25类设计摘要及旧布局数据，扩展为最小选档、短长内容变化、空态和底部留白的主要样本集。不能只把固定尺寸断言换成调用同一选档函数所得的期望值。
- generation-canvas-model-card-shell已经覆盖模型尺寸、运行状态、媒体预览、连线、旧缓存及四模态结果阅读，用于文本模型高度定标及固定尺寸回归。
- generation-canvas-anchored-editor与既有交互、组合交互、预设及自动保存用例覆盖详情会话、临时隐藏、手势和内容更新，优先在这些页面行为上验证锁高及失败保存。
- generation-canvas-organization、generation-canvas-stacks及既有alignment用例覆盖组、堆叠、主动整理与几何关系，扩展实际外框、64px间距、位置保留及整理撤销。
- generation-canvas-image-fit、generation-canvas-linked-results、generation-canvas-check-model及内容媒体用例分别提供不同图片比例、结果关系和检查快捷操作的回归先例。
- 第一版设计名称、元信息、引用、阶段定位及参数分组用例继续保护摘要语义和完整详情可达性；只扩展受本轮共享修改影响的场景。

### 执行与完成条件

1. 使用桌面及390px窄屏、100%及既有缩放场景；全部25类覆盖空态和代表性短长摘要。验证真实可见几何、预算与最小档位，不以没有滚动条或隐藏溢出作为通过依据。
2. 非最低档、未锁高的设计卡，内容下方空间扣除标准底部内边距后的额外留白应小于32px；最低档允许最小外框所需空间。媒体比例空边、固定操作预留区与锁高临时状态不套用此阈值。处理像素取整时保留合理测量容差，不以容差掩盖整档多余空间。
3. 在最大档位仍无法显示预算内必要内容时判为失败；不得通过缩小字体、删减必要状态或隐藏裁切通过。全文超预算和锁高期间的临时省略必须有对应解锁后验证。
4. 锁高期间检查最新摘要、名称及问题提示仍更新；在多个锁相继释放、手势取消、详情切换后核对最终高度与几何，不只检查最终截图。
5. 用内容编辑、撤销、缓存重开和主动整理的组合场景验证位置、视角、组内相对位置及结果关系。新尺寸若导致重叠，不得把擅自推开邻卡当作修复。
6. 人工查看空态、短摘要、满预算、锁高截断及文本模型各状态的代表性截图，核对留白、层级和可读性；记录文本模型最终固定高度和必要内容的定标证据。
7. 复用固定文本、图片、音视频测试素材和可控运行数据，不要求付费模型调用。
8. 前端代码变更后运行项目typecheck及受影响测试；卡壳、编辑器与几何等共享基础变化按实际影响扩展回归范围。优先保留页面级入口，确有页面无法有效覆盖的独立逻辑时才补必要局部测试。
9. 不为纯展示建立镜像实现的单元测试，不以无关测试代替关键行为验证。未执行或失败的必要检查如实记录。
10. 当前规格发布只做文档结构、内容一致性与链接核验。本轮未实现锁高或动态几何，不把此前浏览器静态高度对照或旧版本测试通过记录当作第二版实现验收。

### 既有证据及其局限

在此前隔离浏览器审查中，空结构化卡304px总高的内容下方空间约213px，三项短摘要卡约177px，满六行镜头卡约118px；空风格卡368px总高的下方空间约154px。浏览器会话内按实际摘要选档后，上述样本分别采用128／160／224／240px，下方空间约37／33／38／26px。以上空间包含正常底部内边距，不能直接与“额外留白小于32px”的阈值比较。

该对照支持有限选档的设计方向，未实现或验证锁高生命周期、动态连线同步、首次布局和新整理规则。相关既有模型、检查、结果及图片预览用例通过只说明原有行为基线，不表示第二版已完成。
