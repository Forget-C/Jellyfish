# 03: 撤销重做与刷新恢复

**What to build:** 用户可撤销已保存或未保存的内容操作，意外刷新后找回当前唯一一份未保存编辑，并先核实可能已经成功的保存。

**Blocked by:** 02

**Status:** ready-for-agent

- [x] 内容编辑、关联调整和时间线编辑使用各版本独立的会话撤销／重做历史；后续内容操作接入同一边界，版本切换不串用历史。
- [x] 手动及自动保存成功均不清空会话历史；撤销已保存内容形成新修改，按当前自动或手动保存模式处理。
- [x] 生成、取消任务、导出和交付不属于内容撤销范围；撤销不删除任务、素材或固定记录，恢复不重放外部执行动作。
- [x] 浏览器只持久保留当前一份未保存编辑数据，包含所属场次／版本、成功保存基准、待核实保存请求身份、剩余操作及编辑内容，媒体只保留引用。
- [x] 切换上下文或发现既有待恢复数据时先处理，不能覆盖尚未处理的数据；不按操作、时间或版本累积多份恢复缓存。
- [x] 保存成功仅清理本次请求覆盖的操作并推进基准，请求期间的新编辑继续保留；全部保存或明确放弃后清除对应缓存。
- [x] 刷新先核实原保存：成功但响应丢失时只恢复之后未保存的操作；无剩余修改显示已保存，不因此另存为；未知或失败继续保留现场。
- [x] 确有未保存数据时提供恢复编辑／丢弃；恢复不改变保存偏好，找回该段操作的撤销能力，但不恢复完整会话历史；丢弃后不再次提示同一数据。
- [x] 核实后服务器与恢复基准仍不一致时，不直接重放、覆盖或静默新建版本；多设备、多用户协作冲突恢复不扩展为本期功能。
- [x] 本地写入失败明确提示未获得崩溃恢复保护，保留页面输入并提供保存；不增加自动过期、多缓存管理或固定容量停编机制。
- [x] 验证响应丢失且已成功、请求后追加编辑、真正失败、结果未知、丢弃及本地写入失败；恢复入口若使用另存为须遵循其任务终态限制。
