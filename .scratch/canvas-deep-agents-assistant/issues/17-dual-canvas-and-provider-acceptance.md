# 17: 双画布完整旅程与真实供应商验收

Status: needs-info
Blocked by: 03, 11, 16

**What to build:** 用同一条创作意图从两个真实画布入口完成修改、生成和审看，并通过真实供应商核对模型能力、专业效果与运行开销。

对应[实现规格中的用户故事](../spec.md#user-stories) 2、6、7、9、11、14、20、21、22、23、24、25。

## Acceptance criteria

- [x] 在自由画布从右侧助手提出“把镜头三的推近放慢，生成一版，再审看”。检查实际保存的提示词、允许的卡片类型、唯一运行及对应结果的点评依据。
- [x] 在分镜画布复演同一任务，设置镜头三、四共用运镜卡。核对审批预览与实际改动一致，镜头四的采用关系和配置不变，审看对应镜头三的新结果。
- [x] 自动化使用可控模型与已知媒体，覆盖可见草稿、发送后改选、实际输入和模态不足时的反馈。通过公开入口核对内容、状态与业务提交次数。
- [ ] 真实供应商单列验证能力测试的完整工具往返与实际收到的模态。用同组素材实测“改一句提示词”和“审看整场后改两张卡”，记录型号、接口、目标命中、专业判断依据、调用次数、响应时间与 token 消耗。
- [ ] 分别报告可控模型结果与真实供应商观察。真实媒体点评按样片可核对的事实、时间段和创作取舍验收，未取得的真实结果明确标记。

## 验收记录

受控验收已合入 `f80ec9d6`。自由画布和分镜画布各在审批前保持零提交，审批后由真实 Worker 各提交一次，审看关联原运行及已知媒体证据。分镜中镜头四保留原运镜。真实供应商实测等待可用的测试模型配置，步骤和记录口径见[测试指南](../../../front/tests/README.md)。
