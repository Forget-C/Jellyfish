# 自由画布与分镜画布的 Deep Agents 助手

Status: ready-for-agent

2026-11-22。产品与技术范围已确认，待实施。验收覆盖两种画布的用户入口、模型管理与供应商接口、MySQL 与 Worker 恢复。

## Problem Statement

创作者可以编辑卡片、连接参考和提交生成，但若想让镜头三的推近更克制，仍要自己查清实际采用的提示词、是否有专属运镜卡、改动会不会影响镜头四，以及新视频到底有没有改善。自由画布和分镜画布使用不同的卡片目录。同一句创作意图，在两种画布中的正确落点可能不同。

用户需要把自己正在编辑的内容和实际样片交给助手讨论，选择接受哪些修改，并能查清修改、生成和审看各自进行到哪一步。模型的生成类别也不足以回答“当前接入能否看这段视频、听音轨、调用画布工具”。

## Solution

在两种画布右侧提供图标样式的悬浮按钮，点击打开独立于卡片的助手侧栏。每张画布保留自己的对话和审批设置。助手由用户发起，可围绕所选元素或整张画布工作，并通过四类产品专业 Skill 提供镜头与场面调度、图片生成指导、视频生成指导和成片审看。

例如，用户说“把镜头三的推近放慢，生成一版，再看看动作是否连贯”。助手先读取发送时可见的草稿和实际采用的输入。自由画布可以改视频提示词；分镜画布可以改镜头三专属的运镜卡。遇到共享运镜卡，预览应展示仅对镜头三生效的方案及其涉及的卡片、连接。编辑达到适用的审批条件后，助手使用同一句话中的生成授权提交一版，随后针对该次结果给出有依据的点评。用户也可以在任何一步保留原稿、调整建议或停止后续工作。

## User Stories

1. 作为创作者，我希望从画布右侧打开助手并继续手动编辑，以便在对话和镜头之间来回核对。
2. 作为创作者，我希望能选择“分析所选卡片”或“审看整张画布”，以便控制一次提问的对象与范围。
3. 作为创作者，我希望发出“改这个镜头”后仍能选中别的卡片，以便继续工作，同时保留原消息的目标。
4. 作为创作者，我希望助手读到我正在输入的提示词，以便无需先退出编辑器或手动保存。
5. 作为自由画布用户，我希望先在空白草稿里讨论想法，决定采用时再保存画布，以便管理列表只出现我决定保留的画布。
6. 作为自由画布用户，我希望把摄影建议写入可用的内容卡、参考或模型配置，以便在首页完成创作并遵守该画布的卡片范围。
7. 作为分镜画布用户，我希望助手能按现有目录创建和修改设计卡，以便直接调整真实采用的镜头设计。
8. 作为创作者，我希望助手能处理卡片、连线、引用采用、分组和布局，以便一句“换首帧参考”能完成从选图到模型采用的整套编辑。
9. 作为导演，我希望建议说明观察依据、建议的拍法和叙事取舍，以便判断它是否符合我的创作意图。
10. 作为创作者，我希望上传样片或从文件管理选择参考素材进行比较，以便先讨论，再决定是否将其加入画布或接到模型。
11. 作为审片人，我希望看到点评对应的图片、片段时段及实际读取的画面或声音，以便核对助手的判断。
12. 作为创作者，我希望能直接说“只从摄影角度看”，并看到助手使用了哪些专业能力，以便控制反馈角度。
13. 作为创作者，我希望询问拍法时先得到建议，以便在决定写入前继续对话，例如“保留景别，只改运镜”。
14. 作为创作者，我希望预览目标、修改前后内容及共享影响，以便只改镜头三时保留镜头四的原设计。
15. 作为创作者，我希望只接受部分建议，把互相依赖的操作一起应用，并一次撤销本次应用，以便自由尝试方案。
16. 作为创作者，我希望等待审批期间的手改得到保留，其他独立建议仍能应用，以便不中断并行编辑。
17. 作为创作者，我希望为当前画布开启或关闭自动审批，重开时能看到设置，以便控制助手可以直接执行哪些编辑。
18. 作为创作者，我希望区分“整理画布”和“删除这张旧参考卡”，以便自动审批仍尊重我对删除或断开已采用引用的意图。
19. 作为创作者，我希望选择这张画布的助手模型，同时保留各模型卡的生成配置，以便独立选择咨询模型和生产模型。
20. 作为创作者，我希望仅能聊天的模型也可讨论文字；需要读素材或调用工具时可切换兼容模型，以便接着处理原请求。
21. 作为模型管理员，我希望按具体模型配置查看输入模态、文字输出与工具调用能力及其来源，以便判断能否承担某项助手工作。
22. 作为模型管理员，我希望主动验证某一项能力并看到测试所用的型号和接口，以便识别过期或未经验证的声明。
23. 作为创作者，我希望“改好后生成一版”一次表达编辑意图和生成授权，以便修改获批后按约定数量提交。
24. 作为创作者，我希望失败后得到原因和修正建议，效果不佳时得到专业反馈，以便自己决定是否再消耗一次生成额度。
25. 作为创作者，我希望收起侧栏、切走或重新进入画布后能找回对话、待审批建议、已提交结果和约定的点评，以便接续工作。
26. 作为创作者，我希望能分别停止助手和取消已提交的生成，以便只中止我选择的工作。
27. 作为创作者，我希望看到布局改动是否已由编辑器执行，以便区分等待重开画布的整理建议与已经移动的卡片。

## Implementation Decisions

### 运行时、技能与模型

- 两种画布复用一个助手实现，执行状态按画布会话隔离。采用 Deep Agents，升级兼容的 LangChain／LangGraph 依赖。使用持久检查点支持等待审批、停止和恢复。首版运行单个 Agent，向其开放产品 Skill 的读取、受当前模型支持的素材观察以及当前画布的业务工具。
- 四类 Skill 由 Jellyfish 随产品发布为只读技能包，可附案例、专业标准和参考资料。通过简介发现、按任务加载，可组合或由用户点名。普通回复简要显示所用专业能力；使用记录保留技能标识及版本。专业建议的落点由当前画布目录、实际采用关系和用户授权共同决定。
- 镜头与场面调度围绕人物走位、景别、机位与叙事意图给出拍法；图片生成指导处理关键帧的构图、光线、参考及提示词；视频生成指导处理动作、运镜和时间节奏；成片审看针对已生成的具体媒体定位可观察的问题。一次审看可接续生成指导，是否写回仍取决于用户意图。
- 每张画布首次使用全局默认文本模型，可覆盖为本画布的助手模型。切换保留消息目标、原请求及其草稿依据。工具能力不足时保留纯文字咨询与粘贴文本改写；读取画布、操作元素或分析特定素材需要对应的有效能力。界面说明缺少哪项能力并提供切换入口。
- 模型管理保留文本、图片、视频生成类别。每个绑定供应商配置的型号另有独立、可校验的能力描述。首版表达文本、图片、连续视频和音频输入、文字输出与完整工具调用往返；已知的上下文上限供长任务使用。能力描述与发给供应商的生成参数分别维护。
- 每项能力保留声明状态（支持、不支持、未知）和来源。管理员可以在模型管理页查看、补充或更正具体模型配置的声明。模型选择器、助手预检与工具暴露使用同一份有效能力判断，结合声明、当前供应商接口和实际接入路径。管理员可按项实测工具往返、读图、读视频或听音频，保留结果、时间和测试时的型号与接口标识。更换型号或接入地址后，旧结果标明对应的原配置。目录导入只读取目录；老记录缺项保留未知并沿用已有生成规则。

### 草稿、素材与专业建议

- 每条请求绑定发送时的整图范围或稳定元素身份。默认从选中项和实际关联项取上下文；用户要求整场分析时才扩展范围。活动编辑器提供用户可见的局部草稿、字段位置和保存依据。仅打开助手、移动卡片、编辑或生成完成都不主动发起点评；用户事先交代生成后审看时，完成事件接续该次请求。
- 用户可从本地或文件管理添加对话参考素材。已保存的画布通过已有文件身份登记对话用途；将素材放到画布或作为某模型的输入，需要相应的编辑及明确采用关系。仅比较样片不会创建卡片。空白自由画布用浏览器草稿身份保留对话及选择；首次应用建卡建议或用户主动保存时，将其幂等归入正式会话。
- 点评区分原文确定的事实、实际观察和建议新增的创作安排，说明依据与取舍。能定位时引用卡片、来源或具体时段。静帧可支持构图等判断，连续画面可支持动作和运镜判断；声画同步需要听到音轨并看到对应时段。媒体无法读取时，说明可用证据，提供当前依据能够支持的建议。

### 编辑、审批与撤销

- 依据当前画布真实归属和可用目录提供卡片、配置、内容、连线、引用采用、分组、布局及删除操作。服务端在业务入口复核。自由画布仅开放既有基础、参考和模型生成范围；分镜画布允许现有规则支持的设计卡。共享编辑器复用现有引用兼容、保存、撤销与恢复路径。
- 询问建议时先回答，由用户决定是否应用。明确的编辑请求形成可预览的修改建议，展示目标、原内容、拟议内容及共享影响。局部指令优先修改镜头实际采用的专属来源；若源卡被多个镜头共用，提出仅影响指定镜头的改法，并展示需要新建或调整的关系。
- 以能独立生效的改动为审批单位。用户可接受部分、继续修改或放弃；“建参考卡、连线并设为首帧”可作为相互依赖的一组。同组操作全部生效才报告成功。一次应用的画布编辑形成一个可撤销操作；撤销编辑与取消生成分别处理。
- 默认为人工审批。按画布开启自动审批后，用户明确要求的编辑可直接写入。明确指令可以指定删除某张卡或解除某条已采用引用；由助手从“整理”等宽泛请求中推断出的此类动作仍需确认。审批记录保留授权来自哪条用户指令及当时适用的审批方式。
- 应用前核对组内相关字段、引用、来源及当前可见草稿。检测到同一目标已修改时，保留手改内容并展示最新差异，可重新拟稿；独立组可继续应用。布局沿用浏览器持久化，编辑器执行并回执后才显示完成。页面已关闭时，布局操作保留待执行，回到画布后根据最新状态处理。

### 生成、恢复与数据归属

- 编辑授权和生成授权分别记录。用户只要求调整提示词时，只执行相应编辑；“改好后生成一版”已明确授权一次生成，编辑达到审批条件且预检通过后即可提交。多版按用户明确的数量分配提交标识。失败后可解释并建议修正；重跑、追加版本或因效果欠佳再次生成需要新的明确指令。
- 关闭侧栏只收起界面。停止助手结束本轮尚未执行的编辑、自动写入和点评，已经应用的编辑可撤销。已经受理的生成继续使用现有运行记录和独立的取消入口。离开或重启后，对话和待审批组仍属于原画布；已交代的审看跟进对应的运行和结果。

| 逻辑记录 | 最小持久依据与用途 |
| --- | --- |
| 模型能力与验证 | 模型配置身份、逐项声明与来源、适用接口、验证结果与时间。接口能传递的模态由相应适配器判断。 |
| 助手会话 | 稳定会话身份、唯一画布归属、可空的助手模型覆盖、审批模式。临时草稿首次保存后迁入同一正式对话。 |
| 消息与轮次 | 客户端请求标识、顺序、角色、内容、轮次状态、目标范围、可见草稿依据、实际模型、附件和已加载的 Skill 版本。 |
| 修改建议与审批组 | 来源轮次、目标元素与字段、原值或摘要、拟议操作及前后差异、审批状态与依据、执行请求标识、回执及撤销关联。 |
| 生成授权与结果 | 授权消息、目标模型卡、允许数量、每次提交的稳定标识、既有运行及其结果身份。恢复时先核对原回执。 |
| 媒体与观察 | 沿用既有文件与用途登记，区分对话参考和模型采用。点评关联实际观察的媒体、静帧、连续画面或音轨及适用时段。 |

持久检查点负责接续 Agent 执行。对用户生效的编辑和生成，以审批组、当前画布文档、编辑器布局回执和既有生成回执为准。应用与回执需支持重放，客户端超时重试或 Worker 重启后，同一授权产生同一业务结果。以上是逻辑数据职责，物理表名与消息内嵌字段由实现按现有约定确定。

## Testing Decisions

按已确认的三处边界验收。自动化使用可控模型和已知媒体，使调用、产出和故障时点可重复；断言用户可见状态、实际保存内容、素材采用关系及运行次数。技能内部提示词措辞、框架节点名和临时消息排列可随实现演进。

| 测试边界 | 代表场景与通过条件 |
| --- | --- |
| 自由画布与分镜画布的真实用户入口 | 从右侧打开助手，在两种画布分别完成“改镜头三、生成一版并审看”。验证自由画布只写允许的内容，分镜可改设计卡，共享来源不会误改镜头四。只问建议时无编辑与生成；发送后改选仍指向原卡，未保存的局部提示词可见。 |
| 同一编辑入口的审批与生命周期 | 验证部分接受、依赖操作成组、手改冲突、无关改动、一次撤销、自动审批及删除或解除引用的授权边界。样片只聊天时不建卡；空白草稿首次保存只归入一次。覆盖收起侧栏、停止助手、取消生成，以及离开后布局待执行、重开后回执。 |
| 模型管理与供应商接口 | 从导入、编辑、验证、选择模型走到助手实际请求。用例覆盖旧模型缺项、已声明但接入不支持、仅文字、可读图、可读连续无声视频、可听音频、可工具往返。检查模型实际收到了什么、回复依据了什么，以及切换后保留原请求。修改接口地址后能区分旧验证结果。 |
| MySQL 与 Worker 恢复 | 在专用 MySQL 测试库运行真实持久化和 Worker，在等待审批、审批提交后回执返回前、生成已受理但助手尚未取得回执时分别中断并重启。恢复后仍显示原建议和最新手改，已执行编辑只出现一次；“生成一版”只产生一次业务提交，三版各自有可追溯回执。停止助手后，未执行步骤不会被恢复流程重新发起。 |

浏览器用例沿用现有两种画布的编辑、保存、引用和单卡生成旅程。服务端沿用分镜定向修改的过期审批、画布保存冲突、生成回执重放和 Worker 终态恢复用例。媒体用例复用已知时段的样本，分别检查“仅静帧”“连续无声画面”“对应音轨可用”的判断边界。共享依赖升级同时回归已有结构化输出、文本流、媒体检查及单卡提交。

真实供应商实测单列记录型号、接入方式、实际收到的模态、工具往返结果。用同组素材执行“改一句提示词”和“审看整场后改两张卡”，记录目标命中、专业判断依据、调用次数、响应时间和 token 消耗。模拟结果用于验证确定性行为；影视判断质量以真实模型输出和样片核对。

## Out of Scope

- 首版专业技能由产品维护，第三方技能市场、用户上传可执行 Skill 和常驻多 Agent 分工留待以后评估。
- 全局画布布局同步、后台修改已关闭浏览器的布局，以及用助手变更历史生成素材，均超出本期范围。
- 项目资产、章节来源和锁定的分镜原文继续沿用既有归属与编辑入口。自由画布增加设计卡类别不在本期范围内。
