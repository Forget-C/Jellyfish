# 08: 项目角色卡片与操作统一

**What to build:** 用户在项目角色列表辨认角色、关联演员和服装，创建角色、进入现有详情或在明确确认后删除角色；列表采用统一卡片，角色详情继续保留原布局。

**Blocked by:** 06 项目演员资源与图片卡片交互统一

**Status:** ready-for-agent

- [ ] 使用紧凑工具栏，以新建角色为实心主动作，移除重复标题、装饰性外层卡片和空状态重复操作，不将角色页改成资产关联优先。
- [ ] 复用06的资源卡片与图片交互：约160px封面完整展示、14px／600名称、最多两行摘要、缺失摘要占位；保留真实关联演员和服装信息，不用内部ID或编造信息补位。
- [ ] 角色名称进入既有角色详情，详情的布局和主题保持原状；卡面不成为含义不明的整块跳转。
- [ ] 图片只预览，缺图及加载失败有明确提示且无空预览；Enter打开、Esc关闭与焦点恢复有效，长名称可获取完整内容。
- [ ] 更多菜单提供编辑和删除角色，使用删除角色的明确语义，不混用取消资产关联；确认展示对象及影响，保留执行锁、防重复提交和失败上下文。
- [ ] 菜单在打开编辑或确认层前关闭，保留顶层Esc、可访问名称和焦点；不改变既有角色配置、关联演员或服装的业务关系。
- [ ] 真实页面测试以隔离响应覆盖空列表、新建和详情去向、不同关联组合、缺图、键盘预览、删除确认／取消／失败／成功及重复提交防护。
- [ ] 按规格双主题、四种视口及网格断点验证关联信息换行、长名称和操作可达性，核对角色详情及内嵌档案未被共享样式重排；完成必要检查并同步角色列表相关规范。

规格覆盖：用户故事1–5、32–40、41–42、51–52；Q2、Q7、Q8、Q12、Q13。06提供卡片和图片交互；01为传递依赖。不改造项目角色详情，不新增角色字段或接口。
