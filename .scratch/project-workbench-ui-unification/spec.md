# 项目内部页与工作台管理的布局、视觉及入口统一

Status: ready-for-agent

确认日期：2026-11-11

评估基线：`codex/0718` 合并提交 `9953fe3d`。

方案来源：本轮评估、grilling Q1–Q15、完整方案最终确认，以及 to-spec 测试边界确认。本文记录已确认、待实施的规格，不代表功能已完成或已部署。

## Problem Statement

分支合并后，首页、项目列表、管理列表和实验室已采用统一的雾蓝主题与紧凑布局，但项目内部页及工作台管理仍混有旧页面结构。用户在项目与制作流程间切换时，会遇到重复标题、重复操作、不同的选中样式和不一致的卡片与表单密度。

章节页依次显示面包屑、页标题和正文同名标题，搜索与创建另占一行；已有场次的章节同时出现“场次管理”和“工作台管理”，却通往相同页面。项目概览仍使用“进入场次”等宽泛文案，下方场次长按钮反复描述相同去向，难以快速扫读。

工作台管理的场次侧栏、步骤按钮和大标题未衔接当前普通页面风格，窄屏操作自然堆叠但缺少清晰分组。项目资源存在外层卡片套图片卡片、多个实心主动作、内部 ID 常驻及键盘不可直接触达图片预览等问题。项目文件默认展示批量选择控件，下载按钮占满卡片一行；项目设置及相关弹窗仍使用旧边框、圆角和间距。

合并已保留独立工作台管理、旧链接兼容和独立画布流程。本次应在这些已存在的业务能力上统一页面体验，不能为了视觉一致恢复已停用的章节组合抽屉、改变资源归属或弱化任务与保存保护。

## Solution

以首页、项目列表、管理页面和实验室已确认的通用视觉规则为基准，统一项目内部页面的内容工具栏、章节入口、资源卡片、文件操作和设置表单，同时整理工作台管理的上下文导航、步骤与主动作。

用户在普通项目页面通过路径定位和一条紧凑工具栏理解当前位置；章节名称编辑原文，右侧按制作状态提供明确动作。项目概览只呈现有限且真实的章节和场次摘要，完整内容通过明确入口继续浏览。进入工作台管理后，左侧只切换本章场次，中央切换本场步骤，右侧执行当前主要动作。

项目资源以封面、名称、摘要、业务信息和更多操作形成稳定扫读顺序。关联型资源突出从资产库关联，角色突出新建角色；预览、编辑、取消关联与删除具有各自明确的入口和保护。文件默认浏览、显式进入批量模式；设置保持明确保存与取消。

本次只调整前端布局、样式和入口表达，复用现有数据、路由和业务接口。保持两种雾蓝外观，独立画布主题继续隔离。各内容页面按任务正常滚动，不推广首页的一屏布局要求。

## User Stories

1. 作为项目用户，我希望项目内部页沿用首页和管理页的颜色、字号及留白，以便切换页面时保持一致的阅读习惯。
2. 作为用户，我希望现有雾蓝微渐变与纯色偏好继续生效，以便无需重复选择外观。
3. 作为用户，我希望路径定位与内容标题各司其职，以便了解当前位置而不反复阅读同名标题。
4. 作为章节管理者，我希望章节标题、数量、搜索和新建集中在一条工具栏，以便尽快看到章节内容。
5. 作为用户，我希望更多菜单只显示当前页面相关操作，以便不用在无关操作中寻找目标。
6. 作为章节编辑者，我希望点击章节名称继续编辑原文，以便保留熟悉的编辑入口。
7. 作为章节编辑者，我希望待补原文的章节清楚显示编辑原文入口，以便完成必要内容。
8. 作为章节管理者，我希望缺原文时仍能打开工作台管理，以便查看已有场次及历史内容。
9. 作为制作人员，我希望有原文但无场次时直接进入场次划分，以便继续下一步。
10. 作为制作人员，我希望已有场次或状态未知时进入工作台管理，以便查看真实制作情况。
11. 作为用户，我希望章节行不出现两个通往相同管理页的同义入口，以便减少选择犹豫。
12. 作为用户，我希望状态标签表达状态、操作表达动作，以便区分信息与可点击入口。
13. 作为章节管理者，我希望搜索、分页和返回定位保持有效，以便进入工作台后还能继续原来的浏览位置。
14. 作为键盘用户，我希望返回章节列表时恢复到对应操作，以便连续操作而不重新寻找焦点。
15. 作为项目负责人，我希望概览保留当前制作、生成画布和章节场次，以便快速理解项目内容。
16. 作为制作人员，我希望当前制作显示章节、真实状态及明确下一步，以便知道继续操作的去向。
17. 作为用户，我希望生成画布保留真实封面和打开入口，以便识别并继续已有自由创作内容。
18. 作为项目负责人，我希望概览最多显示三个有场次的章节，以便保持摘要的可扫读性。
19. 作为制作人员，我希望当前制作章节优先，其余章节按章序排列，以便同时看到重点与稳定顺序。
20. 作为用户，我希望每章只预览前三个场次，并能查看全部，以便避免概览被长列表占满。
21. 作为用户，我希望场次以名称和箭头表示进入入口，以便避免重复的长按钮文案。
22. 作为用户，我希望未知数量不被推算为总数，读取失败不被显示为空，以便信任界面信息。
23. 作为工作台用户，我希望进入管理后左侧只显示本章场次，以便有足够空间处理当前制作。
24. 作为工作台用户，我希望通过面包屑返回项目与章节，以便保留清晰的上级路径。
25. 作为工作台用户，我希望场次名称、步骤和动作形成清楚的横向层级，以便快速找到当前操作。
26. 作为工作台用户，我希望当前步骤通过浅底色和可访问状态标记，以便识别所在阶段。
27. 作为制作人员，我希望提取、核对或生成动作随真实状态变化，以便不会在错误阶段执行任务。
28. 作为用户，我希望次要创建动作按需打开，同时错误和冲突直接可见，以便降低噪声而不遗漏重要信息。
29. 作为窄屏用户，我希望定位、步骤及主要操作按组换行，以便不用横向滚动或寻找被裁掉的按钮。
30. 作为使用长场次名称的用户，我希望名称可以换行而不挤走操作，以便完整辨认当前内容。
31. 作为资源管理者，我希望演员、场所、道具和服装优先提供从资产库关联，以便复用已有资源。
32. 作为角色编辑者，我希望角色页突出新建角色，以便创建项目中的角色配置。
33. 作为用户，我希望页面只有一个突出的主动作，空状态不重复整套按钮，以便清楚理解下一步。
34. 作为资源浏览者，我希望卡片按封面、名称、摘要、业务信息排列，以便快速比较内容。
35. 作为资源浏览者，我希望场所封面填充展示、演员及其他对象保留完整比例，以便兼顾识别和图片完整性。
36. 作为用户，我希望缺图和加载失败有明确提示，以便不会把空白或破图误认为已加载内容。
37. 作为用户，我希望资源名称进入详情、图片只负责预览，以便区分阅读档案与查看图片。
38. 作为角色编辑者，我希望卡片保留关联演员和服装信息，以便理解角色的有效配置。
39. 作为用户，我希望简介缺失有占位、长名称有完整提示、内部 ID 不占据卡面，以便获得可读的摘要。
40. 作为键盘用户，我希望使用 Enter 打开图片并用 Esc 关闭、返回原焦点，以便无需鼠标也能预览。
41. 作为资源管理者，我希望更多菜单明确区分删除角色与取消资产关联，以便理解操作影响。
42. 作为用户，我希望危险操作失败后仍保留对象和上下文，以便核对并恢复操作。
43. 作为文件浏览者，我希望默认浏览文件，只有主动进入批量模式后才显示复选框，以便减少视觉干扰。
44. 作为文件使用者，我希望章节筛选位于工具栏、单文件下载使用紧凑入口，以便快速查找和获取文件。
45. 作为文件使用者，我希望预览不改变批量选择，退出批量模式清空选择，以便避免意外下载其他文件。
46. 作为项目配置者，我希望设置按基本信息和生成默认设置分组，以便理解字段用途。
47. 作为项目配置者，我希望保存和取消集中在表单末尾，保存失败保留输入，以便可靠完成修改。
48. 作为项目配置者，我希望取消恢复已保存值，以便撤销本轮表单编辑。
49. 作为用户，我希望相关弹窗的标题、间距和操作位置一致，以便降低切换操作时的学习成本。
50. 作为用户，我希望弹窗长正文可滚动且主要操作可达，以便在矮屏或窄屏上完成编辑和确认。
51. 作为制作人员，我希望差异核对、历史、未保存保护和任务状态继续有效，以便视觉改版不改变制作结果。
52. 作为画布用户，我希望普通页面改版不影响独立画布和其弹窗主题，以便保留原有创作环境。

## Implementation Decisions

### 范围、职责与实施顺序（Q1）

1. 覆盖评估中的八项：项目内部标题工具栏、章节行操作、项目概览、工作台管理导航、项目资源列表、共享资源图片卡片、项目文件、工作台卡片与项目设置。
2. 第一批处理项目内部工具栏、概览和章节列表；第二批处理工作台管理、对象卡、画布卡和相关弹窗；第三批处理项目演员、角色、场所、道具、服装、文件和设置。批次是实施顺序，不是本次发布实现票据。
3. 工作台管理属于普通应用壳内的制作管理界面；生成画布和场次画布属于继续保留原布局与主题的独立创作空间。场所是地点资产，场次是章节原文中的故事段落，两者不得混用。
4. 保持现有路由身份、查询上下文、返回目标、接口、资源关联及任务生命周期。章节原文编辑留在项目编辑器；划分和场次管理进入已存在的独立工作台管理流程。已停用的章节组合抽屉不得恢复。
5. 不新增后端接口或数据库字段。不为填满页面伪造更新时间、数量、关联或任务状态；所需信息缺失时显示明确未知或缺失状态。本规格没有新增模拟业务数据的需求。

### 共用外观与样式边界

| 项目 | 已确认规则 |
| --- | --- |
| 外观 | 沿用雾蓝微渐变和雾蓝纯色，以及现有浏览器偏好与切换行为 |
| 默认背景 | 雾蓝微渐变，从 `#F0F5FC` 到 `#F7F8FB`；纯色为 `#F7F8FB` |
| 文字和表面 | 主文字 `#263244`，次级文字 `#536174`，内容表面白色 |
| 强调与选中 | 主动作、链接和焦点 `#245FC5`；选中底色 `#E4EDFB` |
| 字号 | 页面标题16px／600；条目标题14px／600；分节标题14px；操作13px；辅助信息12px |
| 工具栏 | 桌面约52–56px；桌面操作控件32px，窄屏36px，独立触屏入口保留足够命中面积 |
| 留白 | 页面左右20px、手机16px；区域间距20px；内部12–16px；控件间距8px |
| 圆角 | 内容表面12px，紧凑控件8px，标签4px |
| 分区 | 使用留白、对齐和轻底色；移除装饰性结构边框和重阴影 |
| 保留边界 | 输入框、错误、键盘焦点继续可辨识；选中及状态不能只依赖颜色 |

复用当前布局、按钮、表单和卡片能力。通过页面作用域或明确的组件样式选项接入，不全局改小所有工具栏、不覆盖所有卡片，也不影响独立画布及其浮层。旧通用工具栏默认值并非必须全站修改的目标。

普通内容页面允许按内容纵向滚动，保持高度链和必要操作可达。不得将首页一屏布局推广到章节、资源列表或工作台管理，不通过缩小辅助字号、隐藏状态或裁切内容来消除滚动。

### 项目内容工具栏（Q2）

1. 保留路径定位，每页只有一条紧凑内容工具栏，取消正文重复的同名标题与装饰性外层卡片标题。
2. 章节页将章节标题、真实数量和搜索放在一条工具栏中，新建章节在右侧。未知数量不显示为零。
3. 项目概览使用紧凑标题和必要操作。其他项目内部页将当前页搜索、筛选、数量和操作纳入相同层级，不叠加通用制作动作与重复子页面工具栏。
4. 更多菜单只显示当前页面相关操作。保留语义标题层级及可访问名称，不能为了视觉去重移除页面必要语义。

### 章节列表与制作去向（Q3）

章节名称继续打开章节原文编辑器；状态标签只表达状态。制作动作集中在右侧，移除名称旁重复的动作链接。

| 状态 | 右侧操作及去向 |
| --- | --- |
| 待补原文 | 编辑原文，并保留轻量工作台管理入口，以便查看已有内容 |
| 已有原文但无场次 | 划分场次，定位独立工作台管理的场次划分步骤 |
| 已有场次 | 工作台管理 |
| 场次状态未知 | 工作台管理，不推定为空章或要求重新划分 |

行内操作使用轻量样式，页面实心蓝主要留给新建章节。读取失败与未知分别表达，原文预览、字数和可靠场次数继续可读。保留搜索、分页、原文编辑、创建、返回章节定位和焦点恢复；返回目标不在当前筛选或分页中时保留已有可达的定位反馈。

### 项目概览的结构与展示上限（Q5、Q11）

1. 保留当前制作、生成画布、章节场次三个区域。保留现有当前制作章节选择依据，不因概览截断改变当前工作身份。
2. 当前制作显示章节、真实状态和下一步。文案明确对应编辑原文、划分场次或工作台管理，不继续使用不能说明目标的泛化进入文案。
3. 生成画布保留真实封面、名称和有效打开入口，不新增假画布或虚假进度。
4. 章节场次按章分组，改为紧凑列表。场次名称加箭头表示进入，并在工作台管理中明确定位该场次；不在每项重复“打开工作台管理”。
5. 最多展示三个有场次的章节；当前制作章节若有场次则优先，其余按章序排列。每章最多前三个场次，保留原场次顺序，不为填满添加占位记录。
6. 超出摘要范围时提供查看本章全部场次及查看全部章节的入口，分别进入该章工作台管理和章节列表。不要把摘要条数当成总数，也不要依据不完整读取结果推算全项目数量。
7. 统一原生链接的强调色、操作字号、悬停与焦点反馈。空数据、加载、失败和重试保持区分。

### 工作台管理导航、步骤和主动作（Q4、Q6）

1. 顶部保留普通应用一级菜单，通过面包屑返回项目和章节；左侧仅承担本章场次切换，不叠加完整项目导航。
2. 桌面场次侧栏保留256px，用于场次名与状态。统一文字、留白、悬停和浅蓝选中态，移除侧栏结构分割线与选中描边。当前项仍有明确的可访问状态。
3. 桌面工具栏按场次身份、步骤、当前动作组织：场次名与编辑入口在左，步骤居中，当前操作在右。
4. 保留对象与参考〔本场〕、分镜与画布〔本场〕两个步骤及其业务范围说明，使用轻底色选中样式。场次划分继续作为既有入口，不改写成新的生产步骤。
5. 提取、核对对象或生成新分镜画布按真实状态成为当前主动作。继续下一步为轻量操作；新建空白画布等次要操作进入更多菜单。菜单调整不改变请求条件或任务身份。
6. 历史场次、来源变化、对象准备过时、错误、冲突及任务状态保持可见；保留相应的核对、重试或恢复入口，不将必要反馈收进更多菜单。
7. 对象卡和画布卡采用白色12px圆角表面、12–16px内部间距。画布卡突出名称、真实任务状态和打开动作；对象卡保留关联、参考图片及冲突信息。不得机械套用项目列表固定四行卡片。

### 工作台管理的窄屏组织（Q10）

1. 窄屏按场次名称与切换、步骤选择、当前主动作与更多分组换行；中等宽度可在空间足够时合并分组，不强制固定为一行或固定行数。
2. 使用已有场次切换抽屉承载侧栏内容，并保留关闭后的焦点恢复。
3. 长场次名称允许换行，不能挤出主要操作。正文自然滚动，主动作始终可达，不通过缩字或裁切维持固定高度。
4. DOM 与键盘顺序应与视觉分组一致，菜单和弹窗按当前顶层处理 Esc。

### 项目资源页面的动作层级（Q7）

1. 项目演员、场所、道具、服装以从资产库关联为实心主动作，新建为次要操作；角色页以新建角色为主动作。
2. 查看资产库使用轻量链接。每页工具栏只有一个突出的主动作，空状态不重复整套创建、关联和跳转按钮。
3. 保留创建、关联、编辑、取消关联和删除的现有范围与接口语义，不将项目关联的移除改成全局资产删除。
4. 移除装饰性外层 Card 包裹及重复标题，列表内容直接在统一工具栏下浏览。

### 项目资源卡片的字段与图片（Q8、Q12）

| 区域 | 最终展示与行为 |
| --- | --- |
| 封面 | 高约160px；场所图片裁切填充，演员、角色、道具和服装完整展示 |
| 名称 | 14px／600，单行截断并可获取完整名称；名称进入已有详情 |
| 摘要 | 最多两行；缺失时显示未填写简介 |
| 业务信息 | 角色保留关联演员、服装；其他类别呈现已有有效标签或关联状态 |
| 操作 | 更多菜单集中编辑及删除或取消关联；图片负责预览 |

网格随实际内容宽度减列，不按桌面视口强排四列。各类业务信息可以按需换行，不强制所有资源相同行数。内部 ID 不常驻卡面；缺失时间、计数、标签和关联状态不得编造。

无图或加载失败使用类型图标与明确提示，不出现破图或可打开的空预览。卡片名称与图片承担不同操作，不能把整个卡面变成另一种含义不明的跳转。

### 预览、菜单与危险操作（Q13）

1. 图片入口使用键盘可操作的控件，点击或 Enter 打开完整比例预览，保留可访问名称和可见焦点。
2. Esc 关闭预览并恢复触发入口焦点。预览只承担查看职责；无图或加载失败不提供无效预览。
3. 更多菜单选择操作后先关闭菜单，再打开编辑或确认层，保留正确的焦点和顶层 Esc 行为。
4. 删除角色与取消资产关联在菜单名称及确认中明确区分，确认框说明对象与影响。执行期间禁止重复提交；失败保留可核对对象与上下文。
5. 共享图片组件的外观和交互调整必须核对受影响调用方；本次未纳入改版的独立详情和内嵌档案不因共享组件变更被隐式重排。

### 项目文件（Q9）

1. 默认浏览和预览，章节筛选进入紧凑工具栏。
2. 显式进入批量选择后才显示复选框、选中数量和批量下载，退出批量模式清空选中项。
3. 单文件下载改为卡片上的紧凑图标按钮，提供提示及可访问名称。保留实际可用的图片、视频、音频预览与下载能力。
4. 预览不改变选择，沿用现有项目关联范围、筛选、分页和真实下载路径；不将项目文件变成全站文件列表，不使用模拟下载成功。

### 项目设置（Q14）

1. 保留左对齐、最大宽度约640px的表单，按基本信息和生成默认设置分组。
2. 白色表面12px圆角、16px内部间距、36px常规输入控件，长文本独占一行。
3. 保存和取消集中在表单末尾，不增加重复的顶部保存按钮。保留修改状态、保存锁、错误反馈和取消恢复已保存值的行为。
4. 保存失败保留本轮输入；不新增字段或更改项目默认配置语义，不改变已有保存及保护流程。

### 相关弹窗（Q15）

1. 统一章节原文编辑、场次名称与顺序、关联资产、画布创建及任务详情的外层标题、间距、按钮层级和滚动方式。
2. 弹窗标题16px／600，分节标题14px，操作13px。正文限制在可用视口内滚动，底部主要操作保持可达。
3. 保留编辑、差异核对、历史、未保存保护、任务状态、取消及重试逻辑；只整理外层表现，不改变数据保存、采用或生成流程。
4. 项目角色详情、场次内嵌资产档案及独立画布内部弹窗仍按已确认范围保持原布局与主题。

## Testing Decisions

测试边界已由用户在 to-spec 阶段明确确认。

### 主要测试入口

以真实页面操作作为统一的最高层测试入口，断言用户可观察的内容、导航去向、请求、焦点、保存结果及布局几何。优先扩展既有浏览器用例，不为样式改版创建平行测试框架，不以内部组件树、状态变量、CSS 类名快照代替行为验证。

复用项目概览、首页活动、工作台管理、旧场次链接和主题偏好的既有浏览器测试。项目资源和项目文件缺少覆盖的场景在相同页面入口补齐。既有章节导航纯逻辑测试可辅助核对目的地，但不替代实际页面跳转。

### 数据与任务边界

布局、空数据、未知字段、失败、长文本及异步状态通过 HTTP 边界隔离响应；工作台流程复用已有隔离后端，使用受控测试数据验证原业务入口仍有效。不调用真实生成供应商，不将测试结果描述为供应商质量或生产部署验收。

共享导航和组件变化时扩展到实际受影响调用方。已通过且代码、环境未变化的检查可复用；只读规格阶段不运行应用构建或测试，也不声称未来用例已通过。

### 必须覆盖的行为

| 范围 | 验收要点 |
| --- | --- |
| 页面工具栏 | 只有一条内容工具栏；标题、真实数量、搜索与创建的层级一致；更多只含当前页操作 |
| 章节 | 名称编辑原文；三类状态操作正确；待补原文仍可管理历史；搜索分页与返回定位、焦点保持 |
| 概览 | 三个内容区域；最多三章、每章三场；当前制作优先及稳定顺序；全部入口可达；不推算未知总数 |
| 工作台导航 | 256px场次侧栏及窄屏抽屉；无重复项目侧栏；步骤切换与当前场次身份保持；深链接和旧链接兼容 |
| 工作台动作与卡片 | 主动作随真实状态变化；次要操作在更多中可达；错误、冲突、历史和任务状态未被隐藏 |
| 项目资源 | 关联与创建层级；名称进入正确详情；有效业务字段保留；卡片按内容宽度减列 |
| 图片预览 | 点击和 Enter；完整比例；Esc 与关闭焦点恢复；无图、加载失败、长名称；无空预览入口 |
| 危险操作 | 删除与取消关联语义不同；确认对象与影响；重复提交防护；失败保留上下文 |
| 项目文件 | 默认无复选框；开启和退出批量模式；退出清空选择；预览不改选择；正确单项与批量下载 |
| 项目设置 | 两组字段；末尾保存取消；修改状态；保存失败保留输入；取消恢复已保存值 |
| 弹窗 | 标题与外层布局；正文滚动、底部操作可达；差异、历史、未保存和任务保护保持 |
| 隔离边界 | 两种主题的普通页面一致；独立画布及其浮层、排除范围内详情未被共享样式污染 |

### 外观与可访问性矩阵

- 两种雾蓝主题覆盖1440×900、1366×768、1024×440及375px宽视口，并补查实际采用的侧栏、顶栏和网格断点两侧。
- 截图与布局几何共同核对标题层级、操作分组、留白、图片比例、横向溢出和底部操作可达性。
- 覆盖长名称、两行摘要、业务信息换行、多章节多场次、零数据、字段未知、读取失败与重试。
- 键盘操作覆盖 Tab 顺序、Enter 激活、可见焦点、菜单与预览顶层 Esc、关闭恢复和工作台返回章节。
- 普通内容页允许合理纵向滚动；禁止通过截断正文、藏操作或缩小字号使截图表面不滚动。
- 浏览器触屏与组合事件只能验证相应前端行为，不声称覆盖实体设备、真实输入法或供应商实际生成质量。

实施完成时按影响范围执行前端类型检查、相关浏览器回归及共享布局受影响检查；必要的单元、lint和构建检查沿用项目完成标准及后续实施工作流。

## Out of Scope

- 后端接口、数据库表结构、权限、生成供应商、任务调度及业务数据迁移。
- 改变场次划分、对象提取、候选核对、采用、历史或任务状态语义。
- 恢复已停用的章节组合抽屉，或重新设计旧场次深链接兼容策略。
- 改造独立生成画布、场次画布及其内部弹窗的布局与主题。
- 项目角色详情、场次内嵌资产档案和 Agent 编辑页的布局重排。
- 重做首页、项目列表、管理列表或实验室已完成的界面；它们是本次视觉基准和必要的共享回归对象。
- 新增主题、跨设备外观同步、虚构业务数据、占位下载或模拟生成成功。
- 将首页的一屏要求、项目列表四行卡片或全站管理侧栏宽度机械推广到所有页面。
- 本次规格发布不包含实现票据拆分、代码实施、提交或远端推送。

## Further Notes

本规格将用户已确认的 Q1–Q15 逐项归入实施决策，完整方案与测试边界均已确认。状态为可交付 Agent 的规格，不是已完成的验收报告。后续若范围或行为发生变化，应更新对应规格并重新确认改变的决定；普通实现细节遵循已确认边界。

项目任务系统采用本地 Markdown；此规格文件的创建即为发布。后续实现票据沿用该功能目录，由相应技能在用户授权后生成，不在本阶段预先创建。

已有通用规范继续作为基准；本规格对项目内部页与工作台管理扩展的规则，在落地后同步到相应长期文档，不能在实施前将设计描述为当前架构事实。
