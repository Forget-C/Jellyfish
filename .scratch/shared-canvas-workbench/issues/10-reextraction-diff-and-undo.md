# 10: 重提取差异确认、人工保护与整批撤销

Status: ready-for-agent
Resolution: completed
Blocked by: 07, 08
User stories: 6, 32, 44, 46, 47, 48, 49, 50, 51, 52

**What to build:** 用户对现有画布重新提取，查看卡片级差异及孤儿预告，决定覆盖人工修改后应用，并可一次撤销。

- [x] 可明确采用变更后的原文；保留仍需引用的原始证据，不增加可切换方案历史。首次任务期间发生编辑的候选也走同一差异应用入口。
- [x] 显示新增／修改／移除的类型、数量和名称；人工修改需要覆盖确认，人工新增保留，使用稳定身份而非同名匹配。
- [x] 删除目标前提示哪些保留卡将失去引用；正文引用还原为显示名称，清理实际绑定、系统配置及画面定位，保留既有文件和可失效来源索引。
- [x] 只安置新增卡片并保持人工位置；普通保存仍执行引用校验，应用时重新核对基线，失败不出现半批结果。
- [x] 真实接口与浏览器验证整批应用、冲突拒绝、一次撤销、保存重开，并覆盖复杂拆卡及默认／镜头参考清理。
- [x] 覆盖设计字段引用、模型正文／指令、名称／图片来源关联及帧定位；正文仅保留原显示名称和其余文字，不复制源卡全文或加入失效标记污染生成文本。
- [x] 原本独立的卡片不标成孤儿；提示应指出实际失去的目标。一次撤销恢复整批卡片、关系、来源状态和必要原文依据。
- [x] 普通画布直接删除仍保持原引用保护；对删除和撤销前后的真实编译输入做对照，不以数组长度或纯前端状态替代验证。

## Testing Decisions

真实差异操作、保存事务与浏览器撤销贯通；覆盖多类引用、人工新增／修改、同名身份、基线冲突、复杂拆卡及默认参考，比较持久文档与编译输入。

遵循[主规格](../spec.md)已确认的测试边界：真实浏览器和服务端公开接口，只替换外部 LLM 与媒体供应商；保留真实保存、引用校验、编译与任务状态，使用隔离数据，不以真实付费生成为自动测试前提。接口、类型检查及受影响回归按项目规范执行。
