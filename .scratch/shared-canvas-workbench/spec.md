# 场次工作台共用生成画布实施规格

Status: ready-for-agent
Resolution: completed

日期：2026-11-09

产品、交互、实施替换路径及本文测试边界均已由用户确认。本规格发布到本地任务系统，供后续实施；不表示功能已实现，也不自动启动业务代码修改。票据的 ready 状态不解除其 Blocked by 依赖。

## Problem Statement

用户希望在场次工作台分析原文、准备对象并自动建立可继续生产的设计，然后像自由生成画布一样编辑卡片、组织引用和逐卡生成。现有工作台以场次版本、导演／单元／指令／剪辑视图承载内容，生成画布使用另一套文档与编辑执行逻辑。仅替换视觉组件无法保证设计、来源、范围、参考和后续生成一致。

用户也需要减少重复配置：对象在分镜前准备，分镜结果自动建卡和布局；重新提取时保护人工新增和修改；能够从轻量引用入口定位来源。现有独立生成画布的行为必须保持稳定，不能因工作台接入而增加无关限制或隐式执行。

## Solution

以现有生成画布为共同基础，新建场次工作台的准备入口和画布编辑页。一个场次关联多张独立画布，每张画布就是一套方案，使用现有自动保存、撤销、恢复和单卡执行；不再建立画布内方案版本，也不另存一份可编辑六部门设计。

工作台先提取对象，用户可以关联或准备参考，再明确启动分镜。一个流程编排入口调用前置对象提取和分镜设计两项必需语义能力，按需复用生产单元组织能力。程序将校验后的设计转换成共同卡片、显式引用和布局，不让模型编造真实文件、端口或坐标。

工作台与自由生成共用编辑和执行工作区。已批准的受限扩展包括：提取编辑上下文、固定原文依据、卡片来源索引与通用引用定位。工作台应用层负责范围组装、重提取差异和引用清理，普通画布的保存、编译、删除保护及单卡执行保持现状。

## User Stories

1. 作为自由生成画布用户，我希望工作台接入后原有编辑、引用和生成行为保持不变，以便继续自由创作。
2. 作为工作台用户，我希望自动生成的卡片与自由生成使用同一套数据和操作，以便无需转换即可继续编辑生产。
3. 作为创作者，我希望一个场次拥有多张画布，以便分别尝试不同方案。
4. 作为创作者，我希望每张画布本身就是一套方案，以便不用理解另一层内部版本。
5. 作为创作者，我希望画布自动保存，以便不必维护另一套工作台保存流程。
6. 作为创作者，我希望复用撤销、重做、冲突保护和未保存恢复，以便避免编辑丢失。
7. 作为创作者，我希望从工作台或生成画布打开时编辑同一份文档，以便结果一致。
8. 作为创作者，我希望新建空白场次画布仍有固定原文依据，以便人工组织也可追溯。
9. 作为创作者，我希望新画布有可修改的默认名称，以便不输入名称也能继续。
10. 作为创作者，我希望首版可以新建独立画布，以便开始另一方案而不依赖复制旧方案。
11. 作为创作者，我希望在画布外的场次准备区看到原文摘要、对象和画布入口，以便集中准备。
12. 作为创作者，我希望直接打开已有画布，以便无需重复对象准备。
13. 作为创作者，我希望进入编辑后拥有完整画布空间，以便不被常驻准备面板挤占。
14. 作为创作者，我希望返回准备区时保留场次和画布上下文，以便连续工作。
15. 作为创作者，我希望按类型浏览带缩略图、名称、关联和参考状态的对象列表，以便快速找到缺项。
16. 作为创作者，我希望对象按稳定身份关联真实资产，以便同名对象不会被错误合并。
17. 作为创作者，我希望复用已有上传、选图和参考图生成功能，以便不在准备区重新学习画布生图。
18. 作为创作者，我希望没有参考图也能进入分镜，以便先完成设计。
19. 作为创作者，我希望点击“生成分镜”后才继续下一阶段，以便有机会先准备对象。
20. 作为创作者，我希望场次候选被采用后由各画布独立管理，以便方案 B 的修改不改变方案 A。
21. 作为创作者，我希望只有包含某对象的镜头采用其默认参考，以便不混入无关人物和道具。
22. 作为创作者，我希望镜头特殊指定优先于默认参考，以便表现局部变化。
23. 作为创作者，我希望更换画布默认参考只更新仍沿用默认的镜头，以便保留局部配置。
24. 作为创作者，我希望后续设计和参考变更不改写已生成素材及运行依据，以便可靠追溯。
25. 作为创作者，我希望提取默认自动产出完整分镜，也能选择忠实提取，以便控制创作补充程度。
26. 作为创作者，我希望忠实提取只识别原文明示内容并保留未知，以便不把补写误当原文。
27. 作为创作者，我希望完整分镜覆盖适用设计并区分事实、建议和待定，以便获得可编辑的创作方案。
28. 作为创作者，我希望复用现有模型能力、统一编排并按需组织复杂分段，以便避免无必要的多 Agent 成本。
29. 作为创作者，我希望真实卡片、文件、连接和布局由程序校验与建立，以便模型不会生成不可用画布。
30. 作为创作者，我希望 Agent 使用我选定的生产模型，未选择时标记待配置，以便保持模型与费用控制。
31. 作为创作者，我希望分镜发现漏提对象时能补建空参考卡，以便继续完善设计。
32. 作为创作者，我希望原文在画布内锁定且不能删除，章节修改后提醒我决定是否重新提取，以便保留明确依据。
33. 作为创作者，我希望人工编辑提取内容时保留原状态、用途及来源，并记录修改，以便不改变设计含义。
34. 作为自由生成用户，我希望已有普通卡片仍遵循原来的人工编辑规则，以便新增上下文不改变既有内容。
35. 作为创作者，我希望卡片底部只有轻量“引用”入口，以便保持卡面简洁。
36. 作为创作者，我希望需要展示引用的卡片共用同一浮窗，无引用则无占位，以便操作一致。

39. 作为创作者，我希望原位置变化或目标删除时明确提示，以便不会被错误高亮误导。
40. 作为创作者，我希望来源索引与真正生成引用分别表达，以便查看来源不会改变模型输入。
41. 作为创作者，我希望自动组织的模型输入只含适用镜头和阶段的设计，以便不混入其他镜头要求。
42. 作为创作者，我希望普通保存不根据范围文字自动重连，以便手工调整不会被系统恢复覆盖。
43. 作为创作者，我希望公共区与镜头分组有清晰初始布局且共享对象不重复，以便阅读和组织场次。
44. 作为创作者，我希望重提取只安置新增卡片并保留人工位置，以便不破坏已有布局。
45. 作为创作者，我希望首次有效结果直接形成可编辑卡片，以便减少确认步骤。
46. 作为创作者，我希望重提取以卡片类型、数量和名称展示新增、修改与移除，以便快速判断影响。
47. 作为创作者，我希望提取卡片上的人工修改只有经我确认才被覆盖，以便保护创作决定。
48. 作为创作者，我希望人工新增卡片始终保留，以便重提取不清空自己的补充。
49. 作为创作者，我希望删除引用目标前知道哪些人工卡将失去引用，以便明确决定是否应用。
50. 作为创作者，我希望解除引用后保留其显示名称与其他正文，并清理对应配置，以便卡片仍可继续修复。

52. 作为创作者，我希望任务期间的人工编辑不会被迟到结果覆盖，以便可以继续工作。
53. 作为创作者，我希望任务可后台继续且完成时不抢走已切换的页面，以便同时处理其他工作。

## Implementation Decisions

1. **数据边界。** 工作台维护场次与多个画布的归属；每张画布独立保存一套方案。共同画布仍以项目和画布为边界，普通自由画布不要求章节或场次。新流程不创建旧式场次版本、不双写设计。
2. **共享工作区。** 从现有生成画布页面中分离两入口确需共享的编辑、卡片、引用、保存、恢复、预检、运行与结果能力；页面宿主各自负责导航和列表范围。不复制整页调用链，不引入通用页面配置平台。
3. **两页结构。** 准备区在画布之外，包含原文摘要、对象候选与本场画布列表。编辑页全幅显示共同画布，顶部可返回准备区。旧四业务视图不充当新多画布页签。
4. **生命周期接口。** 场次画布创建与关联必须校验项目／场次归属、提供真实画布身份，并沿用自动保存的请求回执、并发修订与恢复规则。新增接口按项目契约生成客户端；不新建工作台文档保存队列。
5. **新建与来源。** 新建空白场次画布含固定原文依据，不预建设计及生产卡。默认名称为固定前缀加时间字符串，可编辑，名称不是身份。固定原文允许移动和折叠，普通保存和删除操作不能篡改或移除；采用新原文通过明确操作完成。
6. **原文变化。** 章节修订不自动替换已采用依据；提示变化并由用户决定重新提取。为当前保留内容所需的原始来源定位与证据继续保存，不提供历次方案切换。
7. **提取编辑上下文。** 在新工作台提取内容上明确携带编辑策略，分别记录创建来源、采用的提取依据和人工修改。前后端归一化及输出格式共同遵守策略。无新上下文的普通字段，包括已有模型来源字段，保持原规则。
8. **卡片来源索引。** 来源证据和实际输入绑定分别保存；可表达目标卡、稳定字段／阶段／片段、文本区间及校验依据。来源可以多项，不把模型补写标成原文事实，也不因最后编辑者变化把提取卡误判成人工新增。
9. **引用交互。** 共用底部小字入口与浮窗，只显示索引和必要位置提示。首版同画布定位，章节通过原文卡承接；文本变化降级到卡片／字段提示，删除目标保留失效项。新增展开及高亮仅用于来源导航，不更改普通点击和诊断规则。
10. **对象准备。** 从现有整场设计中拆出前置对象识别能力，复用真实资产身份校验与非画布图片准备。对象准备按类型显示紧凑列表，不因缺图阻止进入分镜；用户明确点击“生成分镜”继续。
11. **参考隔离。** 场次对象参考是初始候选。采用后每张画布独立管理默认参考，只供实际含该对象的镜头使用；镜头独立指定优先。更新默认时只更新仍沿用默认的镜头，运行固定依据与既有素材不改写。
12. **模型能力复用。** 一个工作台编排入口使用现有任务执行器，两个必需语义能力分别处理对象、分镜与设计。六部门是结构化输出的内容分类。按模型能力需要执行分段时，改进复用现有单元组织，不新增布局或常驻审稿 Agent。
13. **任务输入输出。** 冻结原文、模式、对象、目标画布基线和用户已选模型。语义结果在任务中校验，真实身份、文件、端口和坐标由程序分配或解析。旧设计字段及规则可复用，旧版本身份和展示图不作为新持久化数据。
14. **提取模式与纠错。** 默认完整分镜，忠实提取只识别明示内容。完整设计不要求所有类型和字段都有值。复用一次正常生成加最多一次纠错的机制；非法结构或引用不能落入正式画布，待定内容和素材缺项须如实提示。
15. **确定性组装。** 程序将结构化设计映射到已有卡片类型，必要时按目标／阶段／条件拆分可独立设计，保留身份、用途、来源和关系。优先复用显式采用与依赖展开，不让范围说明文字变成新的编译控制语言。
16. **生产配置。** 按用户选定模型及真实能力创建模型卡和输入，未选模型保持待配置。不存在的图片不是有效媒体绑定。依赖闭包及画面目标必须与适用范围一致，不能只验证直接连线。
17. **布局。** 工作台提供初始公共区和镜头分组，使用真实尺寸和现有布局基础。共享对象仅一份，镜头按剧情顺序，组内组织设计、参考及模型卡。重提取仅放置新增卡片，主动整理才整体重排；普通生成画布整理行为不变。
18. **应用事务。** 初次有效结果整批加入目标画布。重新提取显示卡片级差异，人工修改需明确决定覆盖，人工新增保留。提交前核实当前编辑基线；任务期间已编辑则改为待应用，不以旧结果覆盖。
19. **删除与引用。** 工作台应用前列出失去引用的卡片。确认后构造清理实际引用的最终文档并删除目标，继续通过普通保存保护。正文引用转为原显示名称的普通文字；系统引用配置相应解除，不复制源卡全文、不把失效标记混入生成文本。来源索引可保留失效项。
20. **撤销与后台。** 整批撤销恢复卡片、实际关系和相关来源状态；复用现有自动保存与恢复。关闭操作容器不取消任务，用户切走不抢焦点；真实阶段、错误及重试入口保持可见，不展示虚构百分比。
21. **媒体执行。** 预检后由用户明确提交单卡，提取不产生媒体生成授权。缺创作参考为可确认继续的警告；真实失效引用、硬性必填输入和能力错误按现有规则阻断，不提供通用强制绕过。
22. **替换与保留。** 旧实现原位暂留并保留回退基线，新宿主完成验收后切换默认场次入口。旧审片／剪辑／交付入口仍指向原数据，新画布产物本轮不接入。不新增旧数据转换，不清理旧代码或数据。
23. **改动约束。** 已批准的受限基础扩展可以实施；新发现的必要基础行为变更先说明影响并确认。普通命名、接口内部组织和已批准范围内的实现选择不增加审批步骤。

## Testing Decisions

测试边界已由用户于本轮明确确认：以真实浏览器操作和服务端公开接口验证流程，仅替换外部 LLM 与媒体供应商响应，保留真实保存、引用校验、编译、任务生命周期和结果处理。使用隔离数据库及测试文件，不修改用户工作数据，也不把真实付费生成作为自动测试前提。

- 以用户可观察行为为断言：保存重开一致、真实输入正确、保护不被绕过、应用与撤销完整、错误和导航可恢复。避免断言内部函数调用顺序、组件树或镜像实现的测试。
- 优先复用现有画布 HTTP journey、API 保存／运行、场次设计建议和浏览器运行测试宿主，不为每个新增模块发明测试专用入口。模型响应可从外部适配边界受控返回；不能用直接写入最终结果替代完整链路覆盖。
- 核心端到端用例：场次对象提取 → 准备参考 → 新建命名画布并分镜 → 来源定位 → 人工编辑保存重开 → 单卡预检确认 → 测试供应商结果展示。工作台和独立入口读取同一真实文档。
- 状态与来源用例：两种模式、未知／不适用／建议、结构纠错成功与耗尽、真实资产归属、人工修改后的提取语义、章节变化提醒、原文锁定与批量删除保护。普通用户字段及已有模型来源字段保留原行为。
- 范围样本用例：根据已核对数据库内容制作隔离夹具，覆盖两镜头、129 项设计及 122 项适用性声明的代表复杂度；逐项核对语义与来源、同一对象身份、镜头顺序／时长、拆卡后依赖闭包及画面目标。不得以只保留文本证明无损。
- 参考用例：两画布独立采用；镜头覆盖；默认更新；漏提对象；空参考可继续与硬性输入阻断；实际引用与溯源索引分别删除、保留及诊断。
- 重提取用例：人工修改覆盖选择、人工新增保留、孤儿预告、正文引用转普通名称、系统配置清理、帧定位／名称／图片关联清理、整批撤销并重开。应用的 API 使用真实事务，不以纯前端状态代替持久化验证。
- 并发与恢复用例：任务期间编辑、同一文档两入口、保存回执未知及重试、冲突、任务失败、切走后完成、恢复编辑。沿用已有可控任务响应来稳定复现竞态。
- 导航与布局用例：折叠目标、卡片／字段／文本定位、Unicode 文本变化、删除来源、保留人工布局。按项目现有桌面与窄屏基准检查准备页、配置操作和引用浮窗，覆盖键盘焦点及 Escape；不借此重设计普通画布。
- 回归用例：既有普通画布创建、编辑、引用保护、编译、单卡运行与历史依据不变；旧下游深链接仍进入旧宿主，新文档不创建隐藏旧版本。
- 少量公共契约／组装层测试用于密集异常输入与范围组合；其余优先公开 HTTP 和浏览器流程，不以大量微小函数测试替代高层证据。
- 实施时按影响运行前端类型检查、相关浏览器套件、后端相关测试及项目要求的后端检查；共同基础变更须扩展回归覆盖。相同代码与环境已经通过的检查无需重复执行。文档发布本身只做内容、链接、依赖和差异检查。
- 现有先例包括“公开 HTTP 文本→图片→视频 journey”“画布真实数据库 API”“受控模型的浏览器运行”“场次设计建议的任务、基线冲突和原子应用”“工作台共享控件与设计焦点”测试。已确认测试范围不等于这些新用例已经通过。

## Out of Scope

- 整画布复制、画布内部可切换方案版本或另一套工作台自动保存系统。
- 存量场次迁移、新增旧数据兼容、旧记录删除、旧代码最终清理。
- 新画布产物接入旧审片、剪辑、交付及其身份桥接；旧入口仅保留原能力。
- 多卡批量媒体执行、自动执行上下游、提取完成自动生成图片或视频。
- 六部门独立多 Agent、布局 Agent、常驻审稿 Agent、新 Agent 运行平台。
- 自动依据自由文本范围修改编译规则；普通保存自动重排或恢复用户手工关系。
- 跨画布动态引用与来源导航、不同画布间默认参考自动同步。
- 全局改变普通生成画布的字段编辑、删除、诊断导航或执行语义。
- 新视觉系统、无关卡片重设计、通用页面配置平台。
- 真实付费模型输出的艺术质量保证。自动化覆盖可证明流程和契约，不能代替真实模型质量评估。
