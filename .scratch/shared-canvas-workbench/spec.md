## Problem Statement

用户希望在场次工作台分析原文、准备对象并自动建立可继续生产的设计，然后使用与自由生成画布相同的数据和操作编辑卡片、组织引用和逐卡生成。共同画布基线已经实现这一底层统一，但当前入口仍分散在章节列表的场次管理抽屉和独立场次准备页：用户要在多个区域之间切换，才能划分场次、调整范围、提取对象、关联参考和生成分镜。

准备页的大面积横向留白与纵向表单堆叠使生成入口和已有画布落到首屏之外。准备流程提前采用独立画布的暗色外观，也削弱了与主站管理页面的衔接。用户难以分清当前操作作用于整章、某个场次还是某张画布，以及“分镜任务成功”和“结果已应用到画布”的区别。

用户还需要安全地重提取对象、恢复失败任务、更名或删除画布。已有对象结果直接替换、同名对象不一定保留关联、删除缺少分镜任务和确认期间的并发保护、两个画布入口发现候选的方式不同，都会影响人工准备和后续工作。普通自由生成画布仍应保持稳定，只接受本规格明确批准的共同基础改动。

## Solution

以已经建立的共同画布为基础，将场次管理抽屉和场次准备页合并为章节级的“工作台管理”。章节列表只负责章节管理、章节内容编辑及管理页入口。管理页沿用主站风格，以左侧场次列表和右侧步骤内容串联“场次划分〔本章〕→ 对象与参考〔本场〕→ 分镜与画布〔本场〕”；步骤可回访，切换步骤不启动任务。

管理页以紧凑列表准备对象，以信息卡展示本场画布，负责“生成新分镜画布”、新建空白画布、打开、更名、删除及失败任务恢复。对象提取是推荐路径，允许直接生成分镜或带空参考继续；重新提取对象先预览影响再整批确认。分镜任务完成后留在管理页，通过“分镜已就绪”及明确入口进入画布。进入后称为“工作台画布”，保留独立全幅画布风格，承担内容编辑、重新提取、差异应用和媒体生成。

一个场次仍关联多张独立画布，每张画布就是一套方案，复用自动保存、撤销、恢复、引用和单卡执行。两入口打开同一场次画布时，共同发现候选并按相同规则应用：首次未修改的画布在打开时自动应用，已有修改、重试或重新提取进入核对。场次画布更名统一在管理页完成；自由画布保留现有更名入口。共同删除增加活动分镜任务保护和确认期间的版本核对。

复用对象识别、分镜设计、确定性组装和现有任务体系，不增加 Agent 层数或另一套画布保存系统。图片、视频继续由用户明确逐卡执行。章节组合及配套交付操作退出产品界面，旧审片、剪辑和整场导出独立保留，交付历史、后端接口、数据表和文件保护不随界面下线被清理。

## User Stories

1. 作为自由生成画布用户，我希望除明确批准的共同保护外原有编辑、引用和生成行为保持不变，以便继续自由创作。
2. 作为工作台用户，我希望自动生成的卡片与自由生成使用同一套数据和操作，以便无需转换即可继续编辑生产。
3. 作为创作者，我希望一个场次拥有多张画布，以便分别尝试不同方案。
4. 作为创作者，我希望每张画布本身就是一套方案，以便不用理解另一层内部版本。
5. 作为创作者，我希望画布自动保存，以便不必维护另一套工作台保存流程。
6. 作为创作者，我希望复用撤销、重做、冲突保护和未保存恢复，以便避免编辑丢失。
7. 作为创作者，我希望从工作台或生成画布打开时编辑同一份文档，以便结果一致。
8. 作为创作者，我希望新建空白场次画布仍有固定原文依据，以便人工组织也可追溯。
9. 作为创作者，我希望新画布有可修改的默认名称，以便不输入名称也能继续。
10. 作为创作者，我希望首版可以新建独立画布，以便开始另一方案而不依赖复制旧方案。
11. 作为创作者，我希望在画布外的工作台管理页看到场次、原文、对象和画布入口，以便集中准备。
12. 作为创作者，我希望直接打开已有画布，以便无需重复对象准备。
13. 作为创作者，我希望进入编辑后拥有完整画布空间，以便不被常驻准备面板挤占。
14. 作为创作者，我希望返回工作台管理时保留章节、场次、步骤和画布上下文，以便连续工作。
15. 作为创作者，我希望按类型浏览带缩略图、名称、关联和参考状态的对象列表，以便快速找到缺项。
16. 作为创作者，我希望对象按稳定身份关联真实资产，以便同名对象不会被错误合并。
17. 作为创作者，我希望复用已有上传、选图和参考图生成功能，以便不在准备区重新学习画布生图。
18. 作为创作者，我希望没有参考图也能进入分镜，以便先完成设计。
19. 作为创作者，我希望明确提交“生成新分镜画布”配置后才发起任务，以便有机会先准备对象。
20. 作为创作者，我希望场次候选被采用后由各画布独立管理，以便方案 B 的修改不改变方案 A。
21. 作为创作者，我希望只有包含某对象的镜头采用其默认参考，以便不混入无关人物和道具。
22. 作为创作者，我希望镜头特殊指定优先于默认参考，以便表现局部变化。
23. 作为创作者，我希望更换画布默认参考只更新仍沿用默认的镜头，以便保留局部配置。
24. 作为创作者，我希望后续设计和参考变更不改写已生成素材及运行依据，以便可靠追溯。
25. 作为创作者，我希望提取默认自动产出完整分镜，也能选择忠实提取，以便控制创作补充程度。
26. 作为创作者，我希望忠实提取只识别原文明示内容并保留未知，以便不把补写误当原文。
27. 作为创作者，我希望完整分镜覆盖适用设计并区分事实、建议和待定，以便获得可编辑的创作方案。
28. 作为创作者，我希望复用现有模型能力、统一编排并按需组织复杂分段，以便避免无必要的多 Agent 成本。
29. 作为创作者，我希望真实卡片、文件、连接和布局由程序校验与建立，以便模型不会生成不可用画布。

108. 作为创作者，我希望有活动分镜或模型运行时禁止删除画布，以便任务不会失去交付目标。
109. 作为创作者，我希望确认删除期间他人保存修改会使确认失效，以便不会误删刚更新的内容。
110. 作为创作者，我希望删除场次画布后两个列表同步移除入口，以便不会把删除理解成解除关联。
111. 作为创作者，我希望历史场次仍可打开已有画布独立编辑和生成，以便继续使用已有成果。
112. 作为创作者，我希望历史场次停止新的对象准备、画布创建和分镜提取，以便准备动作与当前划分一致。
113. 作为创作者，我希望章节组合退出界面时配套交付按钮一并移除，以便不会提交失去消费入口的交付。
114. 作为旧功能用户，我希望旧交付历史和文件保护保留，以便界面下线不造成数据损失。
115. 作为创作者，我希望旧链接明确落到对应管理或原宿主并说明变化，以便不会误入其他画布。
116. 作为窄屏用户，我希望通过场次抽屉、纵向对象行和单列画布卡完成管理流程，以便不依赖桌面宽度。
117. 作为创作者，我希望实际修改过的未提交生成配置在离开时受到保护，以便不会丢失输入。
118. 作为创作者，我希望默认预填不触发离开确认、已提交任务不阻止导航，以便正常浏览不被打断。
119. 作为维护者，我希望列表摘要和步骤状态来自真实业务数据，以便不再维护一套独立流程进度。

## Implementation Decisions

1. **基线与增量。** 共同画布、场次归属、固定原文、提取上下文、引用定位、设计组装、自动保存与单卡执行作为已完成基线复用。本修订新增管理页面重组、对象候选确认、任务恢复和明确批准的共同保护，不要求重建已存在的能力。工作台管理与工作台画布是页面职责名称，不引入新的方案实体。
2. **页面职责与主题。** 章节列表仅保留章节管理、章节内容编辑和工作台管理入口。原场次管理抽屉与准备页功能合并到独立章节级管理页，使用主站布局、导航、主题和既有 React／Ant Design 控件。工作台画布继续使用独立全幅共同工作区，不常驻对象准备或章节正文面板。
3. **步骤与导航。** 三个步骤依次为场次划分〔本章〕、对象与参考〔本场〕、分镜与画布〔本场〕，属于可回访导航，点击本身不发起任务。无场次时进入第一步；已有场次时恢复有效的最近场次与步骤。显式深链接优先于浏览记忆；切换场次更新本场内容，不继承上一场对象或任务。第一步保留场次选择，返回管理页和章节列表恢复各自上下文与列表位置。
4. **场次列表。** 左侧按剧情顺序展示序号、名称、对象数量和画布数量，支持名称搜索。任务进行或原文变化时增加对应文字状态，历史场次入口放左栏底部。场次原文摘要与选区集中在「场次划分」查看，制作区工具栏展示场次标题、制作页签和当前操作。旧版导演、试拍、审片与剪辑通过已有场次深链接进入，关联的旧版任务可从任务中心打开对应记录。列表的对象数和画布数来自新工作台的数据。
5. **章节划分。** 第一步以章节正文为主阅读区，选择场次时定位并高亮范围；AI 提取与人工调整进入同一整章草稿，复用范围、顺序、身份去向、影响预览和明确保存保护。保存后留页，不自动提取对象。名称和顺序通过当前场次标题旁的简短编辑操作显式保存；范围调整回到第一步。章节正文通过现有编辑器修改，章节划分历史继续使用已有机制，不与画布方案版本混淆。
6. **原文变化的两种状态。** 章节正文变动但尚未重新确认场次范围时，场次仍使用旧的已确认摘录，明确提示并允许继续或前往核对。确认新范围后，已有对象准备若与该摘录不符，则要求重新提取并采用适用对象结果后再创建新的分镜画布。未建立对象准备不因此被迫先提取。已有画布保留各自固定原文，采用新原文须明确操作，不能自动覆盖。
7. **可选对象准备。** 提取对象是第二步的推荐主操作，尚未提取或成功提取为零均可明确直接生成分镜。参考图可留空，漏提对象仍可在分镜阶段发现并建立空参考卡。对象重新提取运行中，默认引导等待；已有准备时提供“使用已保存对象继续”，明确本次采用集合，提交前依据变化须重新核对，已提交画布不会自动补入后来完成的对象结果。
8. **对象列表与参考操作。** 按角色、场所、道具组织紧凑列表，展示名称、简短描述、关联资产、默认参考缩略图和状态，提供类型及未准备参考筛选。关联资产选择和点击缩略图选图留在行内；完整描述和出处按需展开，新建并关联、上传与准备图片进入对象操作菜单，图片准备复用现有资产编辑器。资产关联不等于选定图片；未准备参考说明可以继续，真实失效关联或图片明确提示。图片生成须用户明确发起。
9. **对象身份与人工选择。** 对象按稳定身份和来源核对，不按同名推测继承。身份匹配的对象可更新提取名称与描述，但保留人工资产和图片选择；无法匹配的对象列为新增或待关联，旧对象退出准备列表不删除项目资产或文件。场次准备是供新画布采用的候选，不与既有画布形成长期双向同步。
10. **对象候选与差异。** 首次提取在校验通过、原文及准备基线仍适用时直接展示；重新提取已有准备时，任务成功仅形成候选，不能直接替换已保存列表。预览按对象展示新增、移除、关联或参考受影响项及需重新关联项，用户整批确认应用或暂不应用。首版不提供逐对象勾选、人工配对或按同名自动合并。暂不应用保留原准备，候选可从任务结果恢复查看，不建立用户可切换的准备方案版本。
11. **对象应用与并发。** 候选与原文依据、任务身份及预览准备基线关联，应用使用真实事务、版本核对和幂等回执。仅资产／图片选择变化时，保留人工选择和候选，重新计算差异并再次确认，不重新调用模型，也不只因人工调整就丢弃成功候选。已确认场次摘录变化时旧候选不可直接应用，保留查看并引导重新提取。首次提取期间出现人工准备也不能绕过此保护。应用前再次核对原文和准备修订，过期预览不能覆盖新修改。
12. **画布参考隔离。** 每张画布采用后独立管理默认参考，只供实际包含对象的镜头使用，镜头特殊指定优先。更新默认参考只影响仍沿用默认的镜头，保留独立指定。已生成素材和固定运行依据不被后续参考调整改写。
13. **画布列表。** 第三步默认展示紧凑画布信息卡，含名称、真实分镜任务状态、原文变化提示、打开入口和更多菜单。按创建时间从新到旧稳定排列，支持名称搜索；新卡位于前部，打开、任务完成和刷新不重排已有卡片，最近打开只作标记。无画布时显示生成指引，不预留大幅空封面，不新增画布截图。画布列表可打开任意有效画布。
14. **创建配置。** 统一使用“生成新分镜画布”文案，明确点击后在同页展开简短配置，已有列表保留。画布名预填固定前缀加时间，用户无需输入也可提交；默认自动产出完整分镜，可改为忠实提取。生产模型可稍后选择，未选时保留图片／视频模型卡类型的已有配置能力；说明此模型用于后续画布生产，提交分镜不执行媒体。新建空白画布作为次级入口，只包含固定原文，不预建设计和生产卡。
15. **创建与受理恢复。** 服务端确认创建与任务受理后，立即显示对应真实画布卡，收起配置并突出新卡。失败保留已创建画布和原因；提交结果未知则核实原请求，不凭名称或列表缺项再创建。重复点击同一次提交使用同一请求身份，不产生重复画布或任务。各写入继续校验项目、章节、场次与画布真实归属。
16. **任务与应用状态。** 分开表达排队、生成、校验组装、失败／取消、分镜已就绪、需要核对及当前已采用来源。任务成功仅证明候选已生成，候选可用或历史应用回执不能单独证明当前文档已经采用。摘要依据真实任务和当前文档采用身份给出；读取失败不显示为零项或全部完成。失败保留对象准备与画布内容，提供详情、打开和恢复入口，不显示虚构百分比。
17. **完成导航与后台。** 管理页内完成任务一律留在当前页面，更新所属画布卡并轻量通知，由用户明确打开。切换场次、离开页面或关闭操作容器不取消后台任务，也不抢回焦点。本规则替代较早“首次完成时可自动进入画布”的约定。任务中心和返回导航继续携带准确项目、章节、场次、画布及任务身份。
18. **首次结果应用与双入口恢复。** Worker 保留校验后的候选，不因任务完成在后台直接覆盖文档。任一入口打开同一场次画布时，由共同工作区按可信场次归属发现候选，并复用同一应用判断。首次画布基线未变且无未保存修改、恢复草稿或并发冲突时自动加入结果；已有修改、重试或重新提取进入差异核对。两入口不得一边自动补卡、一边只显示固定原文；无场次归属的自由画布不查询或应用场次候选。复用编辑权、CAS、应用回执与恢复能力，避免重复应用。
19. **失败重试。** 仅对可重试的失败／取消任务提供重试，先打开简短确认，预填原模式和模型选择，展示本次实际采用的原文依据、对象与参考摘要。明确这是使用本次有效输入重试，不承诺完整重放上次冻结输入；输入变化须重新核对，确认时固定所展示的依据。继续使用同一目标画布，不另建方案，结果按重试的待核对规则处理；不会绕过人工修改保护或同画布任务门禁。
20. **并行范围。** 不增加整章批量操作，每次提取、关联或生成都明确作用于当前场次。允许同场为不同画布明确提交多个分镜任务，各自显示状态；同一画布有非终态分镜任务时，服务端与界面都拒绝重复发起。对象任务与分镜任务可独立进行，但前者完成不能隐式改变后者已经固定的输入。
21. **管理与编辑分工。** 管理页负责新建、打开、更名、删除和失败任务恢复；卡片内容编辑、对已有画布重新提取以及卡片级差异应用留在画布。查看或核对结果定位到正确画布及任务，不再建立第二套设计或差异编辑器。画布顶部保留名称、保存状态、返回工作台管理及既有适用操作，旧四业务视图不充当新多画布页签。
22. **更名。** 卡片更多菜单打开预填名称的简短弹窗，明确保存后原位更新，取消不改名。管理页拒绝空白名称，沿用 1—255 字符约束并允许重名；名称不是身份。关联场次的画布在两个编辑入口均移除更名控件，普通自由画布保留原入口。使用最新文档、已有编辑权、幂等保存和修订检查，仅修改名称；不以列表旧副本覆盖内容，冲突或占用时保留输入并提供处理方式。活动任务不因更名自动取消或换输入。更名仍推进现有画布修订，因此可能使旧预检失效或分镜结果转入核对，不新增仅更名跳过检查的例外；无需另建保存系统。
23. **整图删除语义。** 卡片更多菜单提供“删除画布”，确认明确整张文档及其画布运行历史等记录的删除范围和不可恢复性，不解释为隐藏、归档或解除场次关联。删除后两个列表都不再提供有效入口，画布内部撤销不能恢复整图。沿用既有删除范围，解除该画布的文件使用关系，不主动销毁文件实体或其他使用关系。统一任务历史中的失效目标须明确提示，不猜测替代画布。
24. **删除任务保护。** 共同删除接口在最终删除事务内检查活动画布模型运行及活动分镜任务，排队／运行均阻止删除，覆盖两个入口。已有图片／视频及其他模型运行保护继续保留，补足分镜任务缺口；用户看到“任务结束后可删除”等可读原因。删除不隐式取消任务，不能仅靠管理页按钮禁用保证保护。
25. **删除并发保护。** 打开确认时核实画布当前保存修订，执行删除时在服务端再次核对；期间任何已保存修改都使本次确认失效，保留画布并要求重新核对。两个删除入口采用同一规则。复用原有当前页面编辑权、未保存保护及未知响应核实，不宣称修订检查可以发现其他浏览器尚未保存的草稿。
26. **草稿与离开。** 场次和章节编辑复用适用的保存、放弃、继续编辑及提交未知保护。新分镜配置只有用户实际修改名称、模式或模型后，切换场次、步骤或离开才提示“继续填写／放弃配置”；默认预填不算修改。此处不提供会隐含发起任务的“保存并离开”。已受理后台任务不阻止导航；准备、任务和浏览状态不因容器卸载而互相混淆。
27. **历史场次。** 历史／退出当前划分的场次仍可读取准备与画布列表，已有共同画布可打开、编辑、运行模型和按共同保护删除，已有成功候选仍可核对采用。停止对象提取和选择修改、新建场次画布、分镜重提取和失败重试，恢复为当前场次后再开放这些准备动作。后台接口补齐与界面一致的当前成员校验，两个入口不可绕过。旧版历史场次版本仍按原有规则，不把其只读限制套给共同画布；已受理任务及其固定依据继续按既有生命周期处理。
28. **章节组合界面退役。** 移除章节列表的章节组合按钮、对应专属面板，以及旧画布的“用于章节／更新到章节”和“章节当前使用”提示；不迁入新管理页。原章节组合链接返回所属工作台管理并说明功能已停用。旧审片、剪辑、试拍与整场视频导出继续独立使用原宿主和原记录。保留交付后端接口、数据表、历史快照、引用与文件保护；本轮不新增历史交付浏览或提交恢复界面，也不据界面下线删除记录。名称相近但未挂载的更早跨场检查分支不顺带清理。
29. **布局与窄屏。** 管理页采用左侧紧凑场次列表和右侧自适应内容区，正文保持可读行宽，表格利用剩余宽度，避免居中窄列和重复大空态。当前步骤和主动作固定在内容区顶部，任务状态就近显示，后台刷新不抖动布局。窄屏使用场次切换抽屉、纵向对象信息行和单列画布卡，主操作、焦点和关闭入口可达。沿用现有主题、图标、间距与控件约定，状态不只依靠颜色；独立画布保留已有响应式与触摸行为。
30. **摘要与可信关联接口。** 复用现有章节、场次、对象准备、画布和任务服务，按管理列表需要补充整章轻量摘要：对象数、画布数、是否已有成功准备、准备依据是否过时、必要任务身份与状态。画布列表补足稳定创建顺序和候选／采用识别所需元数据，避免逐场读取完整文档或资产目录。共同读取返回经归属校验的章节／场次关联，以供两个入口发现候选、返回管理和识别历史场次；不从名称或固定原文的章节 ID 推测场次。接口变动同步契约与生成客户端，不新增持久化步骤进度。
31. **共同文档与固定原文。** 一场次多画布，每张画布独立承载方案，普通自由画布不要求章节或场次。固定原文允许移动和折叠，但不可通过普通编辑、删除、批量删除或解除锁定篡改；普通文本与用户自建依据卡保持原行为。不创建隐藏旧场次版本或另一份可编辑六部门正文，不在普通保存时按工作台来源自动改写关系。
32. **提取上下文与来源。** 新工作台提取内容携带明确编辑策略，分别记录创建来源、采用依据和人工修改；编辑文字保留状态、用途及来源，状态／用途的修改由用户明确操作。无该上下文的普通字段保持原规则。来源索引与真实输入分别表达，统一卡片底部小字引用和通用浮窗；同画布内定位卡片、字段和文本，展开遮挡结构，源变化或目标删除明确降级提示，不误高亮、不改变实际采用。
33. **模式与模型。** 忠实提取只识别原文明示内容，未知保留待定；完整分镜补充适用设计并区分事实、建议、未知，不要求每种卡片或字段都有值。仅使用用户选定的生产模型组织模型卡与输入，未选时保留待配置。真实图片、端口和模型能力必须核验，不把空参考当作有效媒体绑定，也不擅自选择付费模型。
34. **Agent 与任务边界。** 复用统一任务执行器承载前置对象识别和分镜设计两项语义能力，六部门是输出分类，不是六个独立 Agent。按实际模型能力需要执行分段时复用单元组织；不增加布局 Agent、常驻审稿 Agent 或新运行平台。语义生成冻结适用输入，结构／来源错误沿用一次正常生成加最多一次纠错，仍失败时不得伪装成功。
35. **组装与布局。** 程序将语义输出映射到共同卡片、真实身份、文件及显式引用，按目标／阶段／条件拆分可独立设计并核对依赖闭包与画面目标，不把自由范围说明变成新的编译控制语言。初始布局包含原文及共享对象公共区、按剧情顺序的镜头分组，使用真实卡片尺寸，公共对象只保留一份。重新提取仅安置新增卡片，保留人工位置和组织；主动整理才整体重排。
36. **画布重新提取与撤销。** 对当前画布展示按类型、数量、名称组织的卡片级新增、修改、移除差异，不要求逐字段比较。人工修改需明确确认覆盖，人工新增保留；应用前列出将失去引用的卡片。确认后解除实际采用与系统引用配置，正文引用保留原显示名称为普通文字，不复制源卡全文；孤儿卡保留并可定位修复，原本独立放置的卡片不误报。整批撤销恢复卡片和关系，既有素材不随设计卡删除而销毁。
37. **实际生成。** 模型预检、单卡明确执行、结果管理和固定运行依据继续共用。缺创作参考可经警告确认继续，硬性必填输入缺失、失效引用和能力错误仍阻断，不提供通用强制绕过。管理页的任何提取、创建、应用、更名或导航均不构成图片／视频执行授权。
38. **共同基础授权边界。** 在已完成的受限基础扩展上，本修订明确批准：两个入口一致的活动分镜删除保护、删除保存修订核对、仅场次画布启用的可信关联及候选发现／恢复、场次画布更名入口调整。对象差异与应用、摘要、历史场次提取限制、管理页和入口退役属于工作台业务增量。除此之外普通画布的字段语义、来源导航、编译、布局、编辑权和单卡运行不改变；必要的新基础行为变更仍须单独提出。
39. **替换与存量边界。** 管理页验收后替换现有场次管理抽屉和准备页入口，不长期并列维护两套主流程。已有共同画布按原身份读取并继续使用，不复制文档，不要求旧场次版本转换为新画布。保留可回退基线、支持中的旧宿主和数据；仅清理本次替换直接造成的无效前端接线，不扩大为旧代码、旧 API 或数据库清理。
40. **规格与实施边界。** 本次按用户对本轮测试边界和新增验证重点的明确确认更新并发布规格，不生成新的实现票据，不重开或重写既有 12 张完成票据，不修改业务代码、启动 Worker 或调用真实付费模型。新增需求的实现和后续拆票需等待用户另行指令。后续实施时再同步受影响的长期设计与架构文档，不能在规格发布时将目标行为写成已实现事实。

## Testing Decisions

用户已在本轮 to-spec 流程中单独确认以下测试边界与新增重点；本节依据该次明确回复，不以测试入口相同推定旧确认覆盖新增范围。确认覆盖管理页与步骤、原文与历史场次、对象重新提取、创建与任务恢复、双入口候选应用、更名、删除、界面退役与回归，以及布局与可操作性。

主要从真实浏览器操作贯通服务端公开接口验证，复用已有工作台和画布测试入口；并发、错误归属和绕过界面的请求通过公开接口补充验证。仅在外部 LLM、图片和视频供应商边界替换为受控响应，数据库保存、任务状态、候选组装与应用、归属和引用校验、编译及并发保护均使用真实业务逻辑。使用隔离数据库与测试文件，不操作用户工作数据，不以真实付费生成作为自动测试前提。既有测试入口的复用是实施选择，本轮测试范围的授权来自此次确认。

- **测试质量。** 断言用户可观察行为和持久化结果：页面位置、控件状态、实际提交输入、任务归属、保存重开、候选应用、删除阻断与错误恢复。避免断言内部调用顺序、组件树或复制实现计算逻辑；单元层仅补高层难以穷举的公共契约、范围和异常输入。
- **现有测试先例。** 复用真实浏览器工作台／画布宿主、公开 HTTP 文本→图片→视频 journey、画布真实数据库 API、对象提取与分镜任务、场次划分预览／回执及画布编辑恢复用例。外部适配边界提供固定响应，保留真实 Worker 裁决与结果写入；不直接塞入最终画布绕过新流程。旧测试通过记录只证明基线，不证明本修订。
- **主流程。** 从章节列表进入管理，提取并确认划分，选择场次，提取对象并关联／上传／选图，创建默认命名分镜画布；受理后看见卡片，完成后留页，明确打开后形成卡片，人工编辑、保存、重开，再明确运行单卡并查看受控供应商结果。验证步骤只导航、保存划分不自动提取、所有媒体执行均有明确用户动作。
- **步骤与入口。** 覆盖无章节正文、无场次、已有场次、多个场次和历史场次；恢复有效浏览记忆、显式深链接优先、切换不串场、返回管理和章节列表定位、场次改名／调序及范围定位、整章草稿未保存保护。新管理成为统一入口，旧管理／准备链接进入正确上下文，错误或跨项目身份不能悄悄跳到另一场。
- **原文依据。** 分别覆盖章节正文变化但仍使用旧已确认摘录，以及确认新范围导致已有对象准备过时。前者正确提示并允许继续，后者引导刷新适用准备；原文、固定卡、既有画布和已有运行不被自动改写。不存在准备、准备为零和准备过时三个状态不得混淆。
- **对象准备。** 验证尚未提取／提取为零可直接生成，空参考可继续，资产关联不等于选图，类型及未准备筛选、缩略图选择和行内保存正确。对象任务运行中选择已保存集合继续时，确认所见输入与提交快照一致，新结果不偷偷补进已提交任务。
- **对象重提取。** 首次适用结果直接展示，已有准备的成功重提取只形成候选；预览新增、移除、人工关联受影响和待关联项，整批应用、暂不应用及任务结果重开。身份匹配保留选择，同名但不同来源不盲目继承，退出候选不删除资产和图片，已存在画布不随准备应用被改写。
- **对象应用竞态。** 模型返回前、差异预览后和最终提交前分别修改参考，候选与人工选择保留，差异重新计算并再次确认，外部模型调用不增加。已确认场次摘录变化则拒绝旧候选应用并保留查看。过期预览、重复应用、响应未知重试和错误归属通过真实接口验证，不能仅在前端阻止。
- **列表与任务状态。** 验证画布卡显示受理、排队、执行、失败、已就绪及需要核对等适用状态；当前采用来源以真实文档为准，撤销或替换后不会因历史成功回执误标。名称搜索、创建倒序、最近打开标记和任务刷新均不造成错误重排，读取失败不伪装空列表或已完成；整章摘要不要求逐场打开完整画布。
- **创建与导航。** 默认名称可直接提交，完整／忠实模式及待配置模型正确；重复点击和未知受理核实不会生成重复文档。多个独立画布任务并行而状态不串，活动同画布任务拒绝重复生成。成功、失败、切换场次、离页、刷新均不自动进入画布或丢失任务。
- **双入口候选恢复。** 分别从管理入口和普通项目入口首次打开同一未应用场次画布，均能发现正确候选。首次未修改时自动应用且保存重开一致；人工编辑、恢复草稿、并发保存、更名和失败重试时转入核对。并行打开、重复读取或未知回执不会重复应用，不会错用另一任务候选；普通自由画布不附加场次流程。
- **分镜重试。** 失败／取消后保留目标画布，原配置预填而本次实际原文、对象与参考可核对；确认时使用所展示依据，变化后重新核对，不谎称完整重放旧冻结输入。继续同一画布，受理去重，同画布活动任务被拒绝；成功后核对应用并保留人工编辑。
- **更名。** 管理卡片中预填、取消、明确保存、空白拒绝、长度约束和重名行为正确，卡片位置不变，两入口重新打开显示一致名称；场次画布两个编辑入口均无更名控件，自由画布仍可更名。编辑权占用、CAS 冲突、提交未知均保留输入并核实；改名不覆盖卡片或变更活动运行输入。生成期间改名沿用修订变化后的核对行为。
- **删除。** 用公开接口及两个入口分别覆盖排队／运行中的分镜任务和各类画布模型运行，均阻止删除且不隐式取消。确认之后、实际删除之前保存新内容，删除必须失效，原画布和新内容保留；直接接口调用同样受保护。成功删除释放自身使用关系，其他文件使用与独立记录不被误删，两个列表移除，失效任务链接可理解。未知删除结果先核实，不把网络错误当删除成功；不宣称可检测其他浏览器尚未保存草稿。
- **历史场次。** 已有画布可以从两入口读取、编辑、保存、单卡运行、按保护更名／删除和核对已有成功候选；新对象准备、场次画布创建、分镜重提取／失败重试在界面和服务端一致被禁止。恢复当前身份后准备操作可用，旧版历史页面原规则仍正确。
- **章节组合退役。** 管理和章节页面都无章节组合入口，旧工作台无交付按钮及当前章节使用提示，旧链接返回所属管理并说明停用；旧审片、剪辑、试拍、整场导出仍工作。确认交付 API、历史快照、模型和文件使用保护保留，不删除未挂载跨场检查分支或把新画布产物接入旧交付。
- **画布基线回归。** 保留两种模式、有限纠错、来源和人工编辑语义、原文锁定、引用浮窗与定位、范围／依赖闭包、初始布局和人工组织的既有验证。复杂样本沿用已核对的两镜头、129 项设计、122 项适用性声明等隔离夹具，不能以保存文字替代语义无损验证。
- **参考与卡片差异回归。** 两画布独立采用、镜头特殊指定、默认更新、漏提空参考、创作缺项警告及硬性输入阻断；人工修改覆盖确认、人工新增保留、孤儿预告、正文与系统引用清理、整批撤销和重开。来源索引与真实采用分别验证，实际应用使用真实事务。
- **界面与草稿。** 按既有桌面与窄屏基准核验管理页分栏、长名称、对象列表、固定操作、画布卡片、抽屉和弹窗；包含手机宽度，避免遮挡、页面横向溢出或焦点丢失。键盘可完成选择、更多菜单、更名、确认和返回，状态有文字。修改过的生成配置离开时只允许继续填写或放弃，默认预填不拦截，提交后的后台任务不阻止导航。
- **检查范围。** 后续实施按变更影响执行前端类型检查、相关真实浏览器流程、后端用例及项目要求的静态检查；共同保存、删除和候选恢复须覆盖普通画布消费者。相同代码与环境已通过的检查复用；有相关改动或新疑点才重跑。本次规格发布只验证章节结构、确认覆盖、状态、链接和改动范围，不启动应用／Worker，不运行付费模型，也不把文档检查写成产品验收。

## Out of Scope

- 本轮规格发布后自动拆票、预生成票据、重开既有完成票据、代码实现、提交、部署、启动服务或真实付费生成。
- 整画布复制、画布内部可切换方案版本、对象准备方案版本或另一套工作台自动保存系统。
- 旧场次版本转换为共同画布、存量迁移、新增旧数据兼容、旧场次版本及交付记录批量清理、旧代码全面清理；已有共同画布仍按原身份使用，其明确删除遵守本规格。
- 删除或退役章节交付后端 API、数据表、历史和文件保护；清理未挂载的更早跨场检查能力；另建退役交付的历史浏览或提交恢复页面。
- 新画布产物接入旧审片、剪辑、章节交付或整章视频合成及其身份桥接；旧独立场次功能按已确认范围保留。
- 整章批量对象提取、批量关联、批量分镜，或多卡批量媒体执行、自动执行上下游；同场不同画布的逐次明确提交可以并行。
- 对象差异逐项勾选、人工身份配对或按同名自动合并；不同画布间默认参考自动同步。
- 画布软删除、回收站、解除场次关联或整图删除后的撤销；保证发现其他浏览器未保存草稿。
- 自动生成画布截图、为列表增加大封面预留区、手动拖动卡片排序。
- 六部门独立多 Agent、布局 Agent、常驻审稿 Agent、新 Agent 运行平台。
- 自动依据自由文本范围修改编译规则；普通保存自动重排或恢复人工关系；跨画布动态引用与来源导航。
- 已列明基础扩展之外的普通自由画布行为变更，移除自由画布更名，将历史场次共同画布统一变为只读，或新增更名不推进修订的例外。
- 新视觉系统、无关卡片重设计、通用页面配置平台，以及独立画布触摸交互重做。
- 真实付费模型输出的艺术质量保证。自动测试证明流程与契约，不替代真实模型质量评估。

## Further Notes

本修订的产品确认依据为管理页讨论 Q1—Q32 及用户最终确认，测试确认依据为随后 to-spec 环节单独展示的测试边界与新增验证重点及用户的明确回复；基础依据仍为[目标设计](../../docs/development/design/shared-canvas-workbench.md)、[共享基础 ADR](../../docs/development/adr/0005-shared-canvas-foundation.md)及[领域术语](../../GLOSSARY.md)。共同基础、一场次多画布、固定原文、引用与单卡执行决策继续有效。

相对于上一修订，本轮明确替代：章节场次抽屉与独立准备页分散入口、准备页沿用画布主题、首次任务完成可自动导航、画布内给场次画布更名，以及保留章节组合和界面交付入口。对象重提取新增应用前确认；任务成功与文档已采用分开表达。旧设计／ADR 中对应界面和入口条款描述此前决定，本规格记录用户确认后的新目标；本次不修改它们以假称目标已经实现，后续实施时按实际变更同步。

术语上，“工作台管理”是场次工作台的章节级管理页面，“工作台画布”是关联场次的共同画布编辑页面；两者不增加新的领域实体。“分镜已就绪”表示任务候选可用，既不代表候选已写入文档，也不代表媒体已生成。对象差异应用与画布卡片差异应用是两种不同的业务操作，不共用错误的身份或版本基线。
