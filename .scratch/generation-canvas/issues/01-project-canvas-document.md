# 01: 项目画布与文本内容的创建、保存、重开

Status: ready-for-agent
Blocked by: None

**What to build:** 用户从项目进入画布生成，创建并命名多张画布，编辑文本内容卡、手动保存并重开，获得真实的版本冲突及幂等保护。

**依据：** [实现规格](../spec.md)；[任务依赖与共同验证](../README.md)。验收覆盖：A01、A02、A30。

## Acceptance criteria

- [ ] 项目级入口、列表、创建、读取、命名和无活动内容的删除形成真实 HTTP／数据库／页面链路，不要求章节或场次；沿用项目归属与权限。
- [ ] 建立 CanvasDocument、类型版本和文本内容卡的最小持久契约；卡片有不可变身份，一张文本卡一份内容，空卡可保存。
- [ ] 手动保存提交完整 document、request_id、expected_revision；CAS 冲突返回 REVISION_CONFLICT，不覆盖服务端内容。
- [ ] 保存效果与回执原子持久化；原请求重放返回原回执，同 ID 不同内容返回 IDEMPOTENCY_CONFLICT；后来的 revision 不改变历史回执。
- [ ] 文档编辑与运行记录／当前输出分开，位置、尺寸、视角不纳入内容 revision；不引入草稿、发布或场次版本实体。
- [ ] 类型和结构错误给出 code、target、blocks；坏身份、损坏结构阻止保存，空内容允许保存。
- [ ] 首个消费者实际使用轻量类型定义与 rendererRegistry，不先建未使用的插件／通用表单框架；普通 HTTP 通过 generated client。

## Validation

- HTTP 验证两画布隔离、项目归属、保存回读及回执持久化。
- 隔离 MySQL 多连接验证并发 CAS 与同请求竞争；无环境时列出限制，不用 SQLite 宣称竞争已验收。
- 浏览器完成新建→编辑→保存→切换→刷新，验证内容及 revision，而非只看成功提示。
- 执行 [共同检查要求](../README.md#共同检查要求) 中适用于本票变更的命令，并记录真实结果。

## Scope and handoff

向后续票提供文档读写、稳定卡片身份、类型注册最小边界及保存回执。自动保存与恢复由 02 完成；媒体、连线与运行分别在后续票扩充，未接通入口不能伪装可执行。
