# 06: 单张文本模型的预检、执行与持久事件流

Status: ready-for-agent
Blocked by: 02, 05

**What to build:** 用户保存并预检一张文本模型卡后执行，文本从真实后台 Task 逐段显示，刷新可恢复观察，完整成功后成为正式输出。

**依据：** [实现规格](../spec.md)；[任务依赖与共同验证](../README.md)。验收覆盖：A16、A17、A18、A19、A26、A27、A30、A31。

## Acceptance criteria

- [ ] 建立画布自己的 Task target、operation×target×delivery 校验、项目归属和交付；Task 写入经 TaskService，通用 DTO 在 contracts，不借用实验室消息作为结果归属。
- [ ] 保存当前编辑→预检→preview_token 提交→run_id；本地内容修改立即失效旧预检，迟到预检不能放行，布局不影响；服务端复核 revision／实际输入／有效配置。
- [ ] 同请求与回执原子持久化，丢回包重放同 run／Task，不同请求 ID 才形成独立执行；供应商受理未知不得盲目重发。
- [ ] 单卡只执行自己一次，读取已存在且有效的实际输入；没有有效输入就定位阻止，不补跑上游。
- [ ] 任务受理时冻结有效文本模型参数和供应商路由；执行层使用固定配置，运行期间改输入／模型不改变真正发送的请求，不新增变更监听或 Task 恢复保证。
- [ ] 接入后台文本流，累计正文与有序小片段持久化；一条画布 SSE 推送 snapshot、node.updated、text.delta、node.finished、run.finished；状态、成果和事件同事务落账后推送。
- [ ] 初始快照、恢复游标、重复去重及过期快照具有最小完整实现；离开页面不取消，浏览器恢复不重新请求模型，成功前增量不是正式输出。
- [ ] 完整归档交付后产生独立 ResultSet；相关配置已改则只入历史，当前输出更新不推进文档 revision；失败／取消亦有真实终态和成果清单。
- [ ] 受理执行节点占用并拒绝再次重叠执行；活动模型卡／画布／项目不可删除。前端使用 generated 契约与公共流式 transport，不用状态轮询、不迁移任务中心。

## Validation

- 真实 HTTP＋数据库＋TaskWorker，FakeModel 分段返回；检查真实调用参数、调用次数、增量持久化、回执和当前输出。
- 浏览器保持流打开时观察多次增量，刷新恢复；不能用一次性 JSON 响应伪装流。
- 覆盖本地编辑及迟到预检、受理后修改模型／路由、成功与失败交付；并发幂等用隔离 MySQL。
- 执行 [共同检查要求](../README.md#共同检查要求) 中适用于本票变更的命令，并记录真实结果。

## Scope and handoff

交付可演示的单卡完整链路及公共运行／事件／结果契约。07 扩充取消、历史和故障恢复场景；不得把事件持久化或刷新恢复留成占位。
