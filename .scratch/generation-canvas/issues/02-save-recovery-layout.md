# 02: 自动保存、恢复保护与独立布局

Status: ready-for-agent
Blocked by: 01

**What to build:** 用户持续编辑或关闭重开画布时，自动保存、冲突与恢复保护内容；布局独立记忆，迟到回包不撤销新输入。

**依据：** [实现规格](../spec.md)；[任务依赖与共同验证](../README.md)。验收覆盖：A03、A04。

## Acceptance criteria

- [ ] 默认每五秒检查未保存内容；手动与自动保存进入同一串行队列，保存中仍可继续输入。
- [ ] 请求快照 A 发出后输入 B，A 返回只推进已保存基线，B 保留且仍待保存；运行信息与布局不触发业务保存。
- [ ] 临时失败保留当前编辑；结果未知时核实或原样重放原请求，不混入后来编辑、不换新请求制造重复保存。
- [ ] revision 冲突显式处理，保留本地内容；本地恢复先核实服务器及未明回执，不盲目覆盖。
- [ ] 复用离开保护与编辑所有权行为，按项目／画布隔离存储键、请求及所有权；不复用场次版本 ID 或全场次业务状态。
- [ ] useGraphLayout 按画布保存位置、尺寸和视角，不推进内容修订；内容刷新、浮层开合不重置布局。
- [ ] 浏览器存储不可用、加载失败与恢复失败显示真实状态，不虚报已保存，不新增独立草稿或撤销体系。

## Validation

- 使用既有 periodic-save／canvas-graph 浏览器 harness 验证串行、丢回包、迟到回包、继续输入、冲突、离开和重开。
- 验证两画布及两个标签的隔离与编辑所有权；布局变化不产生内容保存请求。
- 若提取共享保存行为，回归原场次工作台相同保存流程。
- 执行 [共同检查要求](../README.md#共同检查要求) 中适用于本票变更的命令，并记录真实结果。

## Scope and handoff

提供画布编辑控制器的保存与恢复公共行为；后续预检必须等待当前快照保存，不能直接取最近服务端版本运行。
