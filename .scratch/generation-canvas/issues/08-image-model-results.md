# 08: 图片模型的实际输入、多结果与未完成成果

Status: ready-for-agent
Blocked by: 07

**What to build:** 用户用实际选中的图片生成完整有序结果，预览与供应商请求对应；失败时可找回已保存的部分图片并显式另存。

**依据：** [实现规格](../spec.md)；[任务依赖与共同验证](../README.md)。验收覆盖：A12、A15、A18、A22、A23。

## Acceptance criteria

- [ ] 图片模型消费公共 Composer、预检与单卡运行，不新增第二套任务／事件接口；能力、参数及最终输入预览来自真实编译。
- [ ] B 只引用图片3时，只提交对应图片并将 token 映射为真实输入表达；通用图片子集按接收端顺序，重复同输出只一次，不同来源同文件按两项。
- [ ] 数量按实际提交内容校验，模型不支持重复或容量超限则诊断，不静默截断／合并／取第一项；普通文字中的图片编号不自动替换。
- [ ] 一次完整成功的所有图片整体形成有序 ResultSet，整体替换当前输出；预览切换不改变下游，旧结果历史保留。
- [ ] 沿用现有缺 URL、数量不符、下载／归档失败判定；任务失败但已存文件仍以未完成成果显示，不作为正式输出。
- [ ] 未完成或历史图片可预览并显式保存内容卡，建立独立文件引用与来源；运行历史保护其已持久保存的成果。
- [ ] 受理后改模型参数、供应商配置及画布内容不影响本任务实际提交／查询；相关依据变化的结果不覆盖当前配置。

## Validation

- MockTransport 捕获实际 prompt、图片数组、参数和调用次数；图片3子集与不同来源同文件均作明确断言。
- 故障注入第3张下载失败，验证前2张归档、failed 状态、原输出保留及另存后的可用性。
- 浏览器完成生成多图、切预览、查看历史、保存内容卡和引用；检查全程使用统一事件流。
- 执行 [共同检查要求](../README.md#共同检查要求) 中适用于本票变更的命令，并记录真实结果。

## Scope and handoff

提供媒体结果归档、历史文件引用及图片输出位置变化的真实案例。视频票可独立于本票实施；12 使用本票产物验收完整清理生命周期。
