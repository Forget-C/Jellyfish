# 03: 四类内容卡与项目媒体导入

Status: ready-for-agent
Blocked by: 01

**What to build:** 用户可创建图片、视频、音频内容卡，上传、替换或选用项目文件并预览；失败和迟到响应不丢失已有内容或复活删卡。

**依据：** [实现规格](../spec.md)；[任务依赖与共同验证](../README.md)。验收覆盖：A05。

## Acceptance criteria

- [ ] 文本、图片、视频、音频内容卡均只有输出、一卡一份；空媒体卡可保存，不发布有效输出。
- [ ] 复用项目文件上传／查询和已有预览能力，补齐后端文件类型、校验及前端音频导入／播放；不把音频当图片走兜底分支。
- [ ] 上传中无有效输出；失败保留卡片和重试入口；替换失败保留原文件。
- [ ] 上传成功即进入项目文件库，即使画布保存失败仍可重选；上传期间删卡，晚回包不重建卡，文件仍留项目库。
- [ ] 内容卡保存使用真实项目文件引用并保护在用文件；不能绕过项目归属／文件存在性检查。
- [ ] 增加显式清理上传保留关系的入口，释放前检查其他引用；放弃编辑不自动删除文件，不引入临时租约。
- [ ] 来源内容替换保持输出位置身份，文件删除与卡片删除分别处理；基础卡不新增数据输入。

## Validation

- HTTP＋存储替身验证四模态、归属、文件引用、上传与保存分离。
- 浏览器覆盖上传失败、替换失败、上传中删卡、保存失败后从文件库重选和音视频预览。
- 既有图片／视频文件接口完成必要回归，音频支持同步 OpenAPI。
- 执行 [共同检查要求](../README.md#共同检查要求) 中适用于本票变更的命令，并记录真实结果。

## Scope and handoff

为 05 的引用候选及 08／09 的生成输入提供文件与内容输出契约。运行历史和等待节点的文件保护在相应运行票接入，12 验证完整清理生命周期。
