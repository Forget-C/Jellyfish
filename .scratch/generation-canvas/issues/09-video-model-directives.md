# 09: 视频模型的结构化用途指令与单视频生成

Status: ready-for-agent
Blocked by: 07

**What to build:** 用户在共用输入框用固定指令选择首尾帧、关键帧和主体参考，核对真正的媒体用途后生成一段视频。

**依据：** [实现规格](../spec.md)；[任务依赖与共同验证](../README.md)。验收覆盖：A13、A14、A15、A18、A23。

## Acceptance criteria

- [ ] 实现四条已确认系统指令的选择与手写解析、独立配置块、同行正文边界；不调用 LLM 解析用途。
- [ ] 首／尾帧各一次，关键帧保留指令顺序；缺参数、重复、类型不符、能力不支持及不支持组合可保存并定位阻止执行。
- [ ] 指令媒体直接计为实际输入，无须正文重复引用；展开的上游文本不得执行指令或产生新依赖。
- [ ] 直接素材引用使用隐式代指；唯一显式主体可替换对应 token，多组共用素材保留素材代指；保留周围正文，同名不额外做人物冲突校验。
- [ ] 最终预览与标准视频 DTO、实际 Adapter 首尾帧／关键帧／主体字段一致；实际提交的媒体编号映射不依赖接收端显示序号。
- [ ] 参数只开放模型、画幅、时长和高级随机种子，依据真实能力；首版无音频参考、时间码、通用视频编辑／续写及其他未纳入参数。
- [ ] 每次仅一段视频、统一 ResultSet 和事件流，文件带音轨则完整保留；失败／取消保留已存成果，另存内容卡固定来源。
- [ ] 视频提交及轮询所用有效配置／路由固定，运行中修改不重定向既有任务；不改现有 Task 机制。

## Validation

- 用项目上传图片／视频建立引用即可独立验收，不依赖图片模型已实现。
- MockTransport 检查供应商实际请求字段、用途顺序、主体名及运行中配置修改后的查询路由。
- 浏览器验证四类指令、错误定位、同行正文、三种主体情况、视频预览／音轨与历史另存。
- 执行 [共同检查要求](../README.md#共同检查要求) 中适用于本票变更的命令，并记录真实结果。

## Scope and handoff

复用 07 的运行协议并扩充视频能力，不创建专属事件通道。13 负责把本票与图片模型、多节点执行组合回归。
