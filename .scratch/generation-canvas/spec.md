## Problem Statement

用户需要在项目内组织文本、图片、视频、音频及模型处理，按明确引用建立生成流程。现有导演画布与场次业务绑定，不能直接承担独立创作空间；只统一卡片外观也无法解决输出身份、接收端使用方式、保存和后台运行的分工。

用户应能判断每张卡实际使用什么、某次生成依据是什么，以及失败、取消或断网后保留了哪些内容。输入代号不能因重排而换绑内容，编辑不能改变执行中的任务，结果不能因为一次预览选择而改变所有下游。

## Solution

项目内提供独立的“画布生成”入口，管理多张可命名、保存、重新打开的画布。四种内容卡承载固定内容，三种模型卡表达处理；分组仅组织卡片。连接提供候选输入，接收卡通过结构化引用、系统引用指令或类型专属配置决定实际使用。

首次搭建依赖必须先有实际内容，再建立引用；可以预先连线，但不能引用未来输出。之后按单卡、运行到目标或严格框选执行，后台任务使用受理时固定的依据。统一画布事件流展示状态、阶段、文本与成果；当前输出、历史和当前编辑内容分别保存。

## User Stories

1. 作为创作者，我希望在项目内创建、命名并重开多张画布，以便独立组织不同创作流程。
2. 我希望创建四种内容卡和三种模型卡，以便内容模态与处理能力分开表达。
3. 我希望空卡可保存、移动和连线，以便先组织画布，再补充内容。
4. 我希望上传、替换或从项目文件库选择素材，以便复用已有内容。
5. 我希望上传和画布保存各自显示结果，以便保存失败后仍能找到成功上传的文件。
6. 我希望用分组命名、移动和折叠卡片，以便整理画布而不改变模型输入。
7. 我希望拖线时看到兼容连接点和原因，以便正确连接不同类型。
8. 我希望接收端自行排序、选用和解释输入，以便一份上游内容可供多个下游独立使用。
9. 我希望输入 @ 后按模态查找或手动输入代号，以便准确引用内容。
10. 我希望重排输入或重新生成后引用身份保持稳定，以便不会误用另一份内容。
11. 我希望缺失引用保留来源和占位，以便知道应补齐哪项内容。
12. 我希望复制正文时保留引用来源，以便粘贴到其他接收卡不会换绑同名代号。
13. 我希望模型输入框复用参考区、正文区和底部参数栏，以便三类模型保持一致操作方式。
14. 我希望切换模型后保留已有配置并定位不兼容项，以便自行修正实际使用的输入。
15. 我希望预览实际提交的文本、媒体、用途及参数，以便知道模型会收到什么。
16. 我希望使用固定格式指定视频首尾帧、关键帧和主体，以便无需自然语言推断参数。
17. 我希望只运行当前卡、运行到目标或运行框选部分，以便控制执行范围。
18. 我希望看到复用与执行的节点，并在缺少输入时得到定位提示，以便不会自动扩大范围。
19. 我希望运行期间继续编辑，以便新编辑留给下一次执行。
20. 我希望逐段看到文本及后台阶段，以便无需轮询或等待所有结果完成。
21. 我希望离开页面、刷新和断线后恢复观察，以便不重复生成或误取消任务。
22. 我希望每次成功产出完整有序结果集，以便各下游自行使用，不受预览选中项影响。
23. 我希望失败或取消后仍能查看已保存成果，以便决定是否显式保存为内容卡。
24. 我希望删除或断线前知道被哪些引用阻止，以便清理引用后再操作。
25. 我希望自动保存、手动保存、恢复及修订冲突保护当前编辑，以便迟到响应不会覆盖新内容。
26. 我希望从任务中心回到对应画布及运行记录，以便通用任务状态与画布业务上下文各归其位。

## Implementation Decisions

### 1. 功能与类型边界

项目级入口不要求章节、场次、生产单元或旧 Shot。沿用项目权限与模型配置，不引入新的资产实体或独立发布生命周期。

| 卡片 | 输入契约 | 输出契约 | 配置及边界 |
| --- | --- | --- | --- |
| 文本内容卡 | 无 | 一份文本 | 可编辑；空内容无可用输出。 |
| 图片内容卡 | 无 | 一张图片 | 项目文件引用；上传、选择、替换。 |
| 视频内容卡 | 无 | 一段视频 | 保留完整文件及自带音轨，不拆音频。 |
| 音频内容卡 | 无 | 一段音频 | 导入、播放及能力允许时作为输入；无音频生成卡。 |
| 文本模型卡 | 本地正文、实际引用的文本；其他模态仅在真实接入且声明支持时开放 | 完整成功后的文本结果集 | 模型及有效参数；文本须逐段返回。现有纯文本 DTO 不等于已有多模态文本能力。 |
| 图片模型卡 | 正文、展开的文本及实际引用的图片 | 一次成功产生的完整有序图片结果集 | 模型及实际接入支持的图片参数；不自动逐图调用或选第一项。 |
| 视频模型卡 | 正文、展开的文本及能力允许的帧／主体图片、主体视频 | 仅含一段视频的有序结果集 | 模型、画幅、时长；高级设置提供随机种子。 |

后端使用轻量 CardDefinition 基类与具体类型定义，包含稳定类型标识、类型版本、端口、配置、校验及编译规则。模型能力描述独立于类型，声明模态、用途、数量、组合和参数范围。前端使用明确的 rendererRegistry 与专属参数组件，不创建通用表单引擎或供应商专属卡片族。

### 2. 模块与复用边界

| 模块 | 拥有的职责 | 不承担的职责 |
| --- | --- | --- |
| 画布页面及编辑控制器 | 文档编辑、保存队列、模型能力、连线与运行意图；输入与运行视图归并 | 供应商请求编译、服务端状态推断。 |
| CanvasSurface／CardShell | 视口、几何、拖动、框选、端口手势、卡壳、状态和菜单 | 导演业务对象、后台任务生命周期。 |
| GenerationComposer | 参考区、添加入口、ReferenceEditor、类型参数栏、运行入口 | 网络请求、画布存储；内部只保留光标和菜单等临时状态。 |
| 画布业务服务 | 文档、引用与编译、预检、范围、编排、结果归属、事件和文件引用 | 重建 Task 调度、取消或恢复体系。 |
| 现有 Task 服务与 worker | 单次生成任务的受理、状态、执行、取消、归档 | 定义画布编辑状态或整次运行成功等级。 |
| 供应商适配 | 标准生成请求与供应商请求／结果转换 | 依赖 tasks 类型或自行决定画布引用语义。 |

复用 Canvas 的视口和拖动、useGraphLayout 的本地布局、工作台的保存行为、实验室 Composer 的受控布局、项目文件与模型配置。现有 GraphCanvas 主要是业务图浏览，尚不具备本功能完整的可编辑端口连线；现有 textarea 不提供结构化引用。不得将场次存储键、版本实体、编辑锁或实验室断线取消逻辑直接搬入。

API 层收参、鉴权、组织响应；业务逻辑在 service。跨层生成 DTO 放在 app/core/contracts。已有生成目标矩阵、项目归属解析及交付需增加画布分支；只新增目标枚举不足以完成接入。所有 Task 写入继续经过 TaskService。

### 3. 数据与身份

下表定义逻辑协议必需信息；落库表名、索引布局及内部辅助类由实现选择，不增加领域实体。

| 对象 | 必需信息及归属 |
| --- | --- |
| CanvasDocument | 画布／项目身份、名称、schema_version、revision、带稳定 ID 和类型版本的卡片、内容与配置、PromptDocument、候选连接、每目标端口输入顺序、分组。 |
| PromptDocument | 有稳定定位的普通文本、来源输出引用、系统指令与参数；不保存编辑器库内部 JSON，不以编译后的字符串覆盖原文。 |
| 来源输出身份 | 所属画布内的不可变来源卡 ID、输出端口 ID、来源结果位置；显示名称和卡片排列不参与身份。 |
| 当前输出 | 内容卡当前内容，或模型卡当前成功 ResultSet 的指向；运行结果更新不推进编辑 revision。 |
| CanvasRun／节点记录 | 受理范围、固定依据、复用结果、实际执行节点与依赖、任务关联、状态／阶段、错误、实际输入及结束信息。 |
| ResultSet | 一次完整成功交付的有序产物、运行来源、实际模型与参数；历史结果不被下一轮覆盖。 |
| 未完成成果 | 运行中的累计文本或失败／取消后已持久保存的产物；不是正式 ResultSet。 |
| 运行事件与回执 | 事件协议版本、画布／运行／节点、游标和载荷；命令请求身份、摘要与原始回执分别持久化。 |
| 本地布局 | 卡片位置、尺寸、视角；按画布隔离，不进入内容 revision。 |

同一来源输出在一个接收卡中只有一个代号，不同接收卡可各自编号。不同来源卡即使使用同一文件也保持两份输出身份。输入重排只改变已有引用的显示代号，不重新绑定；普通文字不随代号自动改写。

来源结果减少时，仍被实际引用的缺失位置保留接收端占位；无引用的消失项移除。清理最后一个引用后可移除占位并重排。来源再次提供该位置时恢复原引用。固定某次历史产物须保存为独立内容卡，不把稳定输出标识误当永久产物 ID。

### 4. 编辑、连接与实际使用

- 一张内容卡一份内容；分组仅命名、整体移动、折叠，删除分组仅解散成员。
- 连接用途由目标端口定义；改备注不改用途。相同来源端口到相同目标端口不重复建线。自连、循环及损坏的图结构阻止保存。
- 新建不兼容连线拒绝并提示原因；不隐式做图片理解、转写、取帧等转换。
- 候选连接不等于实际使用。依赖、容量和依据变化只根据正文、指令或专用配置真正使用的输入判断。
- 每目标端口有独立顺序，新连接追加；卡片位置和分组不改顺序。多文本输入不解释成多轮对话。
- 模型切换保留现场。未使用的不兼容候选只提示；实际使用的不兼容输入、超限或无效参数阻止相应执行。配置不完整仍可保存。
- 空卡／无结果模型可连线，但不得引用未来输出，即使数量已知。已有引用缺失也不能以本次上游将补齐为理由通过预检；先补齐来源。
- 有实际引用时拒绝断线或删来源卡，并定位引用；用户清理后可立即操作，一次保存最终文档，不要求两次保存或操作日志证明。

### 5. 共用引用编辑器与编译

参考内容区、添加入口、正文编辑区及底部模型／参数／运行栏共用布局。添加文件或新建文本产生可见内容卡并连接；选择已有卡只连接，实际使用仍须显式引用。组件必须保持受控数据、中文输入、键盘和浮层状态的边界。

输入 @ 打开按文本／图片／视频／音频分类的已连接候选。手动输入期间只匹配定位；选择、Enter／Tab、明确分隔符或失焦时才按完整代号绑定，不能将 @图片10提前解析成 @图片1。中文输入法组合期间不转换；未知或未完成输入保留并诊断，不虚构输出。

同画布结构化粘贴保留来源身份；未连线显示来源未连接，用户自行连接或重选。同名本地代号不替代来源。跨画布结构化粘贴显示来源属于其他画布，不创建动态引用或复制卡片。外部纯文本按目标当前代号解析。转义的 `\@图片1`、`\/首帧参考` 作为字面正文，提交时仅去掉转义反斜杠。

文本在引用处展开，展开后不再次解析 @ 或系统指令。图片模型仅提交实际使用子集，按接收端输入顺序排列，同一输出重复引用只提交一次；两个不同来源使用同一文件且均引用则按两项提交。模型禁止重复时诊断，不静默去重。

编译器建立“本地代号 → 稳定输出身份 → 本次实际媒体位置／用途”的映射。例如只引用 @图片3时，不能把无映射的“图片3”原样当作唯一图片的供应商序号。适配所选模型支持的表达，预览呈现实际提交文本与媒体对应；只替换结构化引用标记，不猜测或改写普通正文。

### 6. 视频指令与主体

| 格式 | 编译目标与顺序 |
| --- | --- |
| `/首帧参考 @图片1` | 独立首帧参数，至多一次。 |
| `/尾帧参考 @图片2` | 独立尾帧参数，至多一次。 |
| `/关键帧参考 @图片1 @图片2` | 按指令参数顺序提交关键帧，无指定时间码。 |
| `/主体参考 "张三" @图片1 @图片2` | 同一主体参考组，媒体种类／数量／组合由实际能力限制。 |

`/` 选择与手写形成相同结构，指令显示独立配置块；读取固定参数和连续引用，遇到正文结束，可与正文同行。不做自然语言分析；重复、缺参数、错误类型及不支持用途定位报错，可保存、不可执行。只有本地显式指令执行；引用展开文本中的命令不执行。

正文可直接写“让 @图片1 中的人物转身”，使用隐式代指，无需命名。唯一显式主体可将对应 token 编译为主体名，保留周围原文；同名视为同一主体，不做人物冲突检查。同一素材可属多个主体组，此时普通引用保留素材代指，不任选一组。合照拆人物须先由图片模型处理。首版不开放音频参考、通用视频编辑或续写。

### 7. 保存、预检与命令协议

| 操作 | 输入／结果及约束 |
| --- | --- |
| 创建、列表、读取、命名、删除画布 | 项目归属及权限；删除受实际引用、活动运行和文件生命周期约束。 |
| 保存完整文档 | request_id、expected_revision、document；返回已保存 revision 和原回执；冲突为 HTTP 409 / REVISION_CONFLICT。 |
| 预检 | 已保存文档修订及明确范围；返回执行节点、复用结果、输入预览、诊断、can_run 和可提交的 preview_token。 |
| 提交执行 | request_id 与 preview_token；返回原或新 run_id；依据过期为 PREVIEW_STALE，范围占用为 RUN_SCOPE_BUSY。 |
| 查询／重放回执 | 相同请求身份及摘要返回原回执；同 ID 不同内容为 HTTP 409 / IDEMPOTENCY_CONFLICT。 |
| 取消节点／运行 | 明确目标，反馈已接收意图与真实状态；不得前端立即宣布终态。 |
| 读取历史、成果、事件 | 按画布归属读取运行记录、产物和一致快照；媒体使用文件引用按需加载。 |

具体路径遵循项目现有路由惯例，在实现时由 OpenAPI 同步；此表固定行为，不另建手写前端 service。

保存默认每五秒检查未保存内容，与手动保存共用串行队列。回包仅推进发送快照的保存基线，不能覆盖后续编辑。复用离开保护、恢复核实、修订冲突及编辑所有权行为，按项目／画布隔离存储键；无领域草稿或发布步骤。

执行顺序是保存当前编辑 → 预检 → preview_token 提交。保存失败不运行旧内容。任何需要保存的编辑立即使已有预检失效，迟到回包不得恢复提交资格；本地布局不使预检失效。提交时重新校验 revision、范围、实际输入及有效配置，预检不预占节点。

命令效果与持久回执同事务提交；已成功请求的重放不受后来 revision 变化影响。结果未知时保留原身份和正文核实，不换新 ID。供应商受理不明按现有能力查询或去重，不盲目再次提交。

### 8. 执行范围与固定依据

| 意图 | 实际执行规则 |
| --- | --- |
| 运行当前卡 | 当前模型卡一次；仅复用有效上游，不自动补跑。 |
| 运行到此处 | 目标一次；沿实际引用复用有效上游或执行依据已变的上游。引用内容缺失时先补齐来源，不能提前等待未来位置。 |
| 框选运行 | 仅选中的可执行卡各一次；外部只复用有效输入。遗漏必要中间节点或外部输入无效时提示补选／补齐，不扩大范围。 |

每次独立意图创建新 CanvasRun；没有首次／重跑／重试业务模式。未使用候选不构成依赖，框选中无消费者的模型卡仍执行。执行范围不重叠可并行，重叠拒绝、不排队；仅共同读取不算重叠。

受理时固定节点与边、已有输入、有效模型参数及供应商路由。允许在输入／执行适配层局部修改当前配置读取，实际发送请求和媒体查询均使用固定依据，不仅在 CanvasRun 留一份 JSON；不增加配置变更监听，不改 Task 调度／状态机／恢复行为。

本次也执行的上游，固定其来源输出位置，完成后使用本轮对应结果形成下游快照；不消费旧输出，也不读取别的运行或后续编辑。下游提交前再次校验数量、能力和缺失。运行中编辑只影响后续运行；相关配置或输入使用安排变化时，本次结果只保留历史，不覆盖新配置对应的当前输出。

### 9. 状态、成果与取消

节点状态：waiting、queued、running、succeeded、failed、cancelled、blocked。waiting 尚无 Task；queued 已建 Task；归档等由 running 的阶段表达。自身预校验失败为 failed，上游失败／取消或已确认流程中断导致未执行为 blocked。复用结果单独标记。运行只记录生命周期，不计算整次成功／部分成功等级。

单节点失败只阻止必要后继，独立分支继续。本轮不使用失败节点的旧输出代替新输出。已确认流程中断时，未建 Task 的节点结束等待并记原因，不自动重新提交；已有 Task 沿用真实状态。没有活动任务和仍可执行节点后结束运行、释放占用。浏览器断线不是流程中断。

成功且归档交付完整后产生 ResultSet，按固定依据与当前配置比较决定是否整体更新当前输出；预览单项不改变输出。失败／取消保留旧当前输出，已持久保存的文本、图片或视频在历史中标为未完成。非空成果清单不等于成功。

成果可显式保存为独立内容卡，固定内容和来源；未完成成果须保留未完成来源，显式保存后才可像普通内容卡使用。此关系不持续更新，也不增加“选择当前结果供所有下游使用”的功能。

取消单节点停止该节点并阻塞未执行必要后继，独立分支继续；取消整次运行停止后续调度并请求取消既有任务。请求接收后、真实终态前显示取消中并保留占用；失败或未知响应不视为取消成功。迟到成果沿用现有 Task 处理，不保证补抓或供应商立即停止。

### 10. 统一运行事件流

一个打开的画布共用一条 SSE 连接，复用多个运行；单次运行结束不关闭连接。保存、预检、执行、取消仍为 HTTP 命令。任务中心保留自身现有通道，画布不得同时用状态轮询替代事件流。

| 事件 | 必须可恢复的内容 |
| --- | --- |
| snapshot | 一致切点上的运行／节点、累计文本、已有成果、当前输出及游标。 |
| node.updated | 状态、阶段、适用进度。 |
| text.delta | 节点及输出位置的有序正文片段。 |
| node.finished | 真实终态、已保存成果、最终文本或文件引用、错误、当前输出是否更新。 |
| run.finished | 生命周期结束，不赋整次运行成功等级。 |

状态、成果登记和对应事件同数据库事务落账，提交后才推送；Task 的失败、取消、过期、中断路径也必须同步，不能只挂成功交付回调。累计文本和批量小片段持久化；成功后才发布正式输出。

快照＋游标后只补后续已提交事件；允许重复但须去重，游标过期重取一致快照。游标次序须能正确处理并发提交，不能把自增 ID 分配顺序直接当提交顺序。断线保留最后确认内容并恢复订阅，不取消／重发生成。恢复显示不承诺恢复执行。

现有 API 与 worker 可通过数据库持久事件衔接，无需新增消息中间件。前端在共用传输层扩展流式读取与归并，保留 generated operations/types；现有生成客户端的整体 text() 读取不能承担逐段消费。

### 11. 文件与删除

上传中无有效输出；失败保留卡供重试，替换失败保留旧文件。上传成功即成为项目文件，画布保存失败不回滚文件；上传期间删卡，迟到结果不复活卡，文件仍可从项目库使用。放弃编辑不自动删文件；补齐音频支持和显式清理上传保留关系入口。

内容卡、运行历史和活动运行分别持有文件引用。受理运行时保护所有已知输入，包括尚未创建 Task 的下游要使用的文件。保留的失败／取消成果也纳入历史引用，不能只依赖终态 Task 保护文件。

有实际下游引用时拒绝删来源卡。活动运行占用的模型卡、存在活动运行的画布或项目须取消并等待终态后删除。删卡不删文件，历史仍可通过画布记录访问；删画布清理其历史与引用，其他对象仍引用的文件保留。清理动作检查真实引用，不能以“任务已终态”认定文件可删。

### 12. 诊断

诊断含 code、severity、message、target、blocks；target 使用卡片／连线／端口／引用／提示词片段稳定身份和字段路径。绑定校验 revision 或请求快照，不能把旧定位贴到新正文。前端按结构定位，不解析说明文案。

可编辑的不完整配置允许保存，按实际使用阻止运行；损坏图结构阻止保存。正常预检发现问题返回 can_run=false；请求失败沿用统一 HTTP 外层，在类型化 data 中承载业务码和诊断。

## Testing Decisions

以真实应用边界验证结果，不为可逆展示逐项编写镜像实现的单测。默认替换外部模型和对象存储，不调用付费模型；真实供应商接入验证若后续需要，单独明确范围与费用。

1. **后端主要接缝：真实 HTTP + 隔离数据库 + 真实提交器、TaskService、TaskWorker。**用现有 FakeModel／httpx.MockTransport 控制供应商片段、请求和失败，仅替换外部存储 I/O。验证真正发出的参数、数据库状态、文件引用、回执及事件，而非只测序列化快照。
2. **纯规则补充：**通过引用／编译／范围计算的公开入口验证顺序、转义、指令、缺失、去重及范围边界，不锁定内部类或算法。
3. **数据库竞争：**复用隔离 MySQL 多连接测试，验证 CAS、幂等、占用与提交事件次序。SQLite 只验证功能，不能代替生产事务竞争；环境缺失时明确记未验证项。
4. **前端主要接缝：真实页面 + generated client + 可控后端／SSE。**使用现有浏览器 harness，验证逐段到达、断流、重连、迟到回包、保存冲突与 IME；一次性 JSON 响应不能替代流式测试。
5. **复用回归：**共享组件变更检查原工作台／实验室行为与主题隔离，Task 变更跑相关架构护栏和任务生命周期测试；不迁移任务中心通道。

## Out of Scope

- AI 提取建卡、专用导演／镜头卡、音频生成、隐式模态转换。
- 未来输出提前引用、跨画布动态引用、结果选择卡、运行中通用人工挑选／暂停。
- 草稿实体／发布流程、整次运行成功等级、首次／重跑／重试业务模式。
- Task 调度／状态机／恢复体系改造、任务恢复保证、任务中心通道迁移、独立模型配置监听。
- 通用视频编辑／续写、关键帧时间码、视频音频参考、视频分辨率／帧率／生成声音开关、自动音轨拆分。
- 通用表单／插件引擎、新增卡片／子图复制、自动恢复历史输出为当前输出、独立扩建撤销体系。
