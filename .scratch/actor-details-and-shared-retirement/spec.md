# 角色来源演员详情与历史共享关联退出

本规格整理自本次对话逐轮确认的方案。目标是统一演员详情体验，并让项目资源仅使用独立副本。

## 演员详情

- 覆盖存量与新角色入库产生的演员；不扩展上传演员等其他来源的详情开放能力。
- 复用普通演员详情字段及现有响应式布局。默认锁定名称、结构化字段、补充信息及风格；已有值显示，缺失显示未提供，长内容允许只读展开。
- 标题名称左侧展示“从角色转化 · 详情只读”；开放保存后改为“从角色转化”。
- 图片浏览、管理、主图、视角默认、局部修改及参考生成独立开放。锁定期间历史文字不参与生成，需有效主体参考。
- 空详情使用“添加详情”，已有详情使用“编辑详情”。确认风险后进入本地编辑；首次保存成功才持久化开放，后续不重复确认，不能重新锁定。放弃未保存修改恢复原状态。
- 来源身份保留，不回写来源角色，不产生额外演员副本。开放后的详情参与后续生成，同时默认保留主图作为主体参考，尊重用户本会话明确选择。
- 确认说明：保存后详情将参与后续生成，可能与现有图片不一致，现有图片不会自动更新。
- 演员检测点击直接提交，展示执行/取消状态，完成后点击查看结果，不自动弹窗。失败可见且可重试；结果读取失败仅重读，不重新提交。逐项手动采用，输入变化后旧建议失效。
- 检测仅分析文字，不核对图文一致性。其他类别维持原检测入口。

## 历史共享关联

- 演员、场景、道具、服装统一关闭旧共享关联写入口及隐式关联参考的分支，退出只读、外跳编辑、取消共享关联等兼容。
- 保留正常项目/章节关联表及生成参考能力。选择参考不会导入资源。
- 发现旧共享关联时，按项目、类别、来源资产建立独立副本，同项目全部章节共用副本，不同项目各有副本。库中原件保留。
- 保留旧文字、风格、图片、主图和视角默认；图片文件身份独立。设定型资产保留设定能力，图片型保持图片型规则；演员遵循上述规则。
- 当前有效项目、章节、场次、可编辑方案、画布及资源参考指向副本，媒体使用保护同步更新。
- 同名冲突先列出并确认新名称，不自动合并、覆盖或加后缀。
- 命中旧共享资产的历史执行记录及必要下游依赖直接清理，不迁移历史。保留无关历史及仍在使用的文件。执行前列出具体清理对象和依赖范围；新增对象范围或关键风险后重新确认。
- 先预检活动任务、名称冲突及历史依赖，再转换有效引用并清理已确认历史，验证完成后移除兼容分支。不能先删除只读条件让项目直接改库中原件。

## 验证边界（已确认）

- 后端公开 HTTP API：详情开放持久化、图片/生成权限、旧关联写入口拒绝；不验证模型质量。
- 演员/项目资源浏览器流程：确认与放弃、字段锁定、布局、检测状态；隔离响应不代替后端链路。
- 转换/清理命令的预检和执行入口：资料与图片独立、引用映射、冲突、清理范围及重复执行；本地结果不推断部署库。
- 定期类型检查与单文件测试；最终全量测试。审查基准 1776982f413ef248b0543403b8df359cee81a2c8；提交当前分支。

## 实施状态

演员详情已实现并通过相关 API、三组浏览器回归及类型和 Pylint 检查；首次开放详情须先保存，才可预览、生成或局部修改图片，避免草稿预览与保存后生成内容不一致。旧共享转换及历史清理尚未执行。具体数据候选见同目录 cleanup-review.md；候选不能直接视为批准删除清单。
