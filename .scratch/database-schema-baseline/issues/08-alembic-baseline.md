## What to build

维护者可从空库通过正式迁移和种子入口建立完整目标结构，后续结构变更从新的固定初始 revision 向前追加。

## 验收条件

- [x] 汇总删除项、现行读写方与删除后果；核实计算列、回执、快照、文件引用等合理冗余的用途。沿实际提交路径验证项目默认视频比例，把改变公开产品能力的取舍单列。
- [x] 用一份固定且无父修订的显式初始 DDL 替换旧 revision 链。移除剩余退役 SQL、旧数据回填与转换入口、仅验证旧 revision 的测试，保留其覆盖的现行业务约束。
- [x] 通过 01 的正式入口在专用空库执行迁移及种子，再执行一次。全局模型设置单例和内置模板数量稳定，已配置默认模型和用户模板得到保留；未纳管非空库的保护继续生效。
- [x] 核对唯一 head、完整表集合、列与默认值、外键及删除动作、索引和唯一约束、计算列和关键时间精度。12 张旧四画布表、三个迁移备份表及其他已退役结构均排除。
- [x] 同步建库和测试说明，使维护者能够按迁移、种子、启动 API 与 Worker 的顺序使用新基线。
