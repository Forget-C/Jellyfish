# 单元画布 AI 设计与生产单元组织

Status: ready-for-agent

日期：2026-10-21

本规格记录已确认的产品决策与验收要求。前端、后端测试入口已分别确认；本文不代表功能已实现。

## Problem Statement

场次已有六岗设计、镜头、节拍、事件、动作、连续性要求等数据，但用户在单元画布建立生产单元时，仍需重新选择执行内容、填写动作范围、选择视频模型与时长。现有新建动作主要建立镜头关联，未完成从设计内容到生产单元的组织；现有指令生成又以已经准备好的单元为输入，不能补齐这一步。

首次拍摄可能需要把一个镜头组织成多个生产单元。补拍也需要基于明确的原单元继承内容，再局部调整。仅复制镜头文字或默认建立一个空单元，无法判断合理分段、组织单元衔接，也容易使用户重复填写已有内容。

当前执行输入还会同时加入单元动作范围与完整镜头可见结果。若完整镜头是“拆信、读信、抬头”，补拍只要求“抬头”，完整镜头结果仍可能重新扩大本次执行范围。因此，本功能需要同时解决单元组织与执行范围一致性，不能止于界面填值。

自动组织还必须保护已有工作：用户应在看过差异后决定是否覆盖；AI 不得改写导演设计、其他镜头或真实素材记录；修改或移除单元不能迁移历史任务、Take 和检查记录。

## Solution

在单元画布提供统一的“AI设计”入口。用户选择当前镜头，打开准备弹窗，确认目标视频模型并填写本次要求；修改或补拍时明确选择来源或目标单元。点击“开始设计”后，由一次组织任务结合已有六岗设计和真实模型能力，完成是否分段、如何分段及完整单元方案的生成。

组织方法复用六岗生成方案中的动作完整性、空间关系、镜头组、进入与结束状态、连续性和模型约束。这里形成的是已有设计的生产组织方案，不新增第七个创作岗位，也不重新运行整套六岗设计。

AI 结果单独展示，包含当前镜头的完整单元方案、组织依据、准备缺项以及新增、修改、移除差异。用户确认覆盖后，更新当前场次版本中的相应单元内容，继续使用现有自动保存或手动保存。取消或未确认时，现有内容保持原状；不建立独立草稿功能。

首次拍摄可形成一个或多个单元。补拍从明确的原单元继承可用内容与配置，再针对执行范围进行局部调整；增加补拍可以形成“保留原单元，加一个新补拍单元”的完整方案。后续仍按既有流程准备真实参考、编译与审查指令、检查模型能力、拍摄、审片与人工采用。

## User Stories

1. 作为首次准备拍摄的用户，我希望根据已有六岗设计生成单元方案，以便避免重复填写已经存在的镜头相关内容。
2. 作为用户，我希望同一镜头能够组织为一个或多个单元，以便根据动作完整性和模型能力合理分段。
3. 作为用户，我希望在当前镜头点击统一的“AI设计”入口，以便清楚知道本次操作的作用范围。
4. 作为用户，我希望一次设计任务同时完成分段判断与方案生成，以便不必先触发额外的 AI 判断任务。
5. 作为用户，我希望在设计前选择目标视频模型，以便方案符合实际拍摄能力。
6. 作为首次设计的用户，我希望有效的全局默认视频模型可见地预选，以便减少重复操作并保留修改机会。
7. 作为补拍用户，我希望优先使用明确来源单元的视频模型，以便保持原有拍摄准备的连续性。
8. 作为用户，我希望无有效默认模型时由自己选择，以便系统不会替我随意使用列表中的第一个模型。
9. 作为用户，我希望看到模型能力加载、失败与重试状态，以便能力未核实时不会误启动设计。
10. 作为用户，我希望本次模型选择仅影响本次请求和确认后的方案，以便全局设置与其他单元不会随之改变。
11. 作为用户，我希望组织结果使用已存在且适用于当前镜头的设计内容，以便能追溯每个单元负责拍摄什么。
12. 作为用户，我希望看到分段、进入与结束状态及连续性要求，以便理解多个单元如何共同完成镜头任务。
13. 作为用户，我希望时长和参数建议有实际依据，以便不会把模板默认值当成模型的已知能力。
14. 作为用户，我希望参考需求与已绑定的真实参考分别表达，以便知道仍需要准备哪些素材。
15. 作为用户，我希望缺失条件被明确列出，以便 AI 不会用虚构内容填满表单。
16. 作为修改单元的用户，我希望保留单元身份并仅调整指定执行内容，以便已存在的关联不会被无意替换。
17. 作为补拍用户，我希望显式选择原单元并继承其可用输入，以便无需重新填写全部准备信息。
18. 作为补拍用户，我希望能保留原单元并新增独立补拍单元，以便原拍摄工作与补拍工作分别追踪。
19. 作为用户，我希望只拍“抬头”时指令不再要求重拍完整“拆信、读信、抬头”，以便局部执行范围真正生效。
20. 作为用户，我希望改变人物意图、动作含义、视点或镜头目的时回到导演画布处理，以便生产组织不会偷偷改写创作设计。
21. 作为用户，我希望 AI 任务完成后先看到结果，以便未经我确认不会覆盖现有单元。
22. 作为用户，我希望预览完整显示新增、修改和移除的单元，以便判断从三个单元调整为两个单元等结构变化的影响。
23. 作为用户，我希望一次确认应用整份有效方案，以便不必重复确认同一次覆盖操作。
24. 作为用户，我希望取消预览时已有内容保持原状，以便可以放心评估 AI 建议。
25. 作为用户，我希望确认后的方案沿用现有自动或手动保存，以便无需学习额外的草稿流程。
26. 作为用户，我希望修改其他独立镜头后仍能使用当前镜头的有效结果，以便无关编辑不会造成无效重做。
27. 作为用户，我希望相关输入改变后旧结果不能覆盖新内容，以便保护生成期间的人工修改。
28. 作为用户，我希望过期结果仍可查看并明确提示重新设计，以便理解无法应用的原因。
29. 作为用户，我希望越界输出整体被拒绝并说明原因，以便不会在不知情的情况下收到被裁剪过的方案。
30. 作为用户，我希望移除单元前看到设计引用与实际覆盖标注的阻塞位置，以便先处理真实关联。
31. 作为用户，我希望仅有历史任务或素材的单元可以移除且记录保留，以便调整当前方案时不丢失历史依据。
32. 作为用户，我希望运行中的任务继续使用原固定输入，以便当前方案调整不会改变已经提交的拍摄。
33. 作为用户，我希望移除单元前知道按原依据重试将不可用，以便在确认前理解后果。
34. 作为用户，我希望新建、拆分或合并后的单元拥有新身份，以便旧任务与素材不会被错误归入新工作。
35. 作为用户，我希望 AI 未涉及的指令、真实参考与依赖得到保留，以便建议中未返回某字段不等于清空已有内容。
36. 作为用户，我希望单元方案、拍摄准备、任务成功、素材实际覆盖和剪辑采用分别表达，以便不会把 AI 设计完成误认为已经拍好或采用。

## Implementation Decisions

### 共同领域边界

- 生产单元是一项独立生成工作，镜头是六岗设计中的计划条目。首次拍摄允许一镜多单元；默认一镜一单元不构成领域限制。
- 本功能中的“单元方案”表示当前镜头的生产组织内容，不新增独立版本、草稿或确认状态体系。
- 前端由用户明确触发 AI 设计；不因进入画布、新建普通单元或保存内容而自动调用组织 Agent。
- 一次组织任务完成分段判断和方案生成，不增加每次先运行的“是否需要 AI”分类 Agent。程序负责准备输入、投影适用内容和执行校验，AI 负责组织判断。
- 复用六岗生成方案的方法，不要求重新运行全部六岗、增加岗位或引入多 Agent 编排。
- 同镜头多单元不意味着自动合成、自动连续剪辑或已实现多覆盖项联合生成；方案仍须符合现有执行能力。

### 前端交互

| 编号 | 已确认要求 |
| --- | --- |
| FE-01 | 单元画布统一显示“AI设计”入口。首次组织、已有方案修改和增加补拍复用这一入口，不新增独立的“AI调整”或“创建补拍单元”AI 按钮。 |
| FE-02 | 作用范围为当前选中的一个镜头。准备弹窗只读显示该镜头；没有有效镜头时不能开始。已有多个单元时，通过明确选择的单元身份表达来源或目标，不凭名称或自然语言序号猜测。 |
| FE-03 | 弹窗包含本次要求、目标视频模型及相关能力状态，点击“开始设计”才提交。修改与补拍意图结合所选单元和本次要求表达；统一入口不改变两者的身份规则。 |
| FE-04 | 首次设计可见地预选有效的全局默认视频模型。补拍优先预选明确来源单元的有效视频模型。无有效默认值时要求选择，不自动取模型列表第一项，也不假设存在项目级默认视频模型。 |
| FE-05 | 目标视频模型与执行组织任务的文本模型含义不同。界面明确当前选择的是拍摄视频模型，不能将两类模型混为同一参数。 |
| FE-06 | 能力加载中、加载失败或必要能力未核实时阻止开始，并显示可理解的原因与重试入口。本次模型选择不改写全局设置或提交前的已有单元。 |
| FE-07 | 复用导演画布 AI 设计的准备、任务状态、结果预览与明确应用交互模式，采用现有工作台弹窗、动作区、按钮和选择控件。任务完成只展示结果，不自动填入当前编辑内容。 |
| FE-08 | 预览对象是当前镜头的完整单元方案；显示新增、修改、移除差异、组织说明、参数依据、参考需求和缺失条件。覆盖可以改变单元数量，其他镜头不属于覆盖范围。 |
| FE-09 | 同一预览中展示移除影响与阻塞项，包括仍被引用的位置、可导航的关联内容、历史保留、原依据重试不可用及运行中任务继续执行。存在阻塞项时不能确认覆盖。 |
| FE-10 | 一次用户确认应用整份有效方案，无额外第二次覆盖确认。确认前重新核对结果适用性；确认后更新当前场次版本编辑内容，沿用现有自动保存或手动保存。 |
| FE-11 | 取消、未确认或任务失败不覆盖现有内容。相关输入改变导致结果过期时保留结果供查看，说明原因并要求重新设计，不用旧结果覆盖新编辑。 |
| FE-12 | 用户应用结果后仍可局部手动修改执行内容。涉及创作设计变化时说明应转到导演画布；设计完成不展示为拍摄准备全部通过、实际覆盖或已采用。 |

### 后端输入、输出与生命周期契约

API 层负责收参、鉴权与响应，业务服务负责组织输入、范围校验、任务编排、预览与应用校验。跨层生成 DTO 放在统一 contracts 中；任务模块只负责分派与执行。新增前端调用统一使用 OpenAPI generated client。

接口的具体路径与类名由实现沿用现有命名约定；以下语义是必须满足的契约。

| 编号 | 契约 | 要求 |
| --- | --- | --- |
| BE-01 | 提交上下文 | 明确项目、场次、当前版本、目标镜头、请求身份及本次要求。携带用户点击时的当前编辑内容和保存版本依据，不能仅从旧的持久化内容推断本次输入。修改或补拍明确目标或来源单元身份，并校验其归属。 |
| BE-02 | 目标模型 | 目标视频模型必填，由后端解析真实可用状态和能力；缺失、不可用或必要能力无法核实时拒绝开始并说明原因。冻结本次目标模型与能力依据，AI 不得自行换模型。组织用文本模型沿用既有解析机制，与视频模型分别记录。 |
| BE-03 | 组织输入 | 提供目标镜头适用的六岗设计、节拍、事件、动作、活动、连续性内容、共享约束、现有单元、已知真实参考与依赖，以及模型能力。首次组织不能依赖尚不存在的单元选择；也不能只给 AI 原单元已经选中的少量条目而遗漏其他适用候选。 |
| BE-04 | 固定输入与请求身份 | 沿用现有 AI 建议任务的输入快照、来源和幂等机制。相同请求身份及相同输入返回同一任务；相同身份携带不同输入不得生成另一任务。网络结果未知时核实原请求，避免重复提交产生额外任务。 |
| BE-05 | 结构化结果 | 返回当前镜头的完整建议方案，明确保留、修改、新建与移除关系，覆盖选择、动作范围、分段与衔接要求、组织理由、有依据的参数建议、参考需求和缺失条件。单元及覆盖项身份必须可核对；不存在的设计引用、身份冲突或越界引用不能成为可应用结果。 |
| BE-06 | 任务副作用 | 任务执行只保存结果、固定输入、真实来源与诊断。worker 不直接修改场次版本，也不在任务成功时创建正式单元、绑定参考、改写指令或采用素材。 |
| BE-07 | 读取与预览 | 读取任务状态和结果；预览接受当前编辑内容，重新验证输入依据、作用范围、当前引用和移除影响，返回可展示的完整方案、差异、问题及应用条件。失败诊断或无效输出不得伪装成已验证方案。 |
| BE-08 | 明确应用 | 用户确认时使用当前内容重新校验并构成替换结果，再走既有内容验证与保存机制。仅替换授权镜头的单元组织内容；其他内容以当前编辑状态保留，不能回写提交时的整份旧快照。保存继续执行版本并发控制及项目、文件、引用归属校验。 |
| BE-09 | 错误表达 | 错误明确区分模型/能力缺失、非法身份或引用、范围越界、相关输入已变、移除阻塞和保存冲突；返回可定位的原因供前端展示。任何一次无效覆盖都不能产生部分落库。 |

### 后端组织与范围约束

1. **当前镜头完整方案。** AI 可为目标镜头组织一个或多个单元，明确哪些既有单元保留、哪些局部修改、哪些替换为新单元。补拍结果可以同时保留原单元和新增补拍单元；未涉及其他镜头的单元保持原样。
2. **复用已有设计。** 只选择真实存在且适用于目标镜头的节拍、事件、动作、活动与连续性要求。可按动作完整性、空间关系和目标模型能力组织分段、进入与结束状态及衔接要求，不创造新的故事事实。首次组织应明确已有设计由哪些单元负责；尚未安排或无法满足的内容明确列为缺项，不能靠分段静默遗漏必要内容。补拍仍按明确的局部目标组织，不强制每个补拍单元重拍完整镜头。
3. **执行层可调整的内容。** 包括完成已有设计所需的单元分工、已有动作的局部范围、合法模型参数、参考需求与依赖准备。例如原设计已有“犹豫后抬头”，可以为“只补拍抬头”建立单元。
4. **导演层变化。** 改变人物意图、动作含义、情绪、观察视点、镜头目的或顺序，或增加设计中不存在的手部特写等，属于导演画布。此类请求或结果不得通过动作范围、选择 ID 或指令文字绕过设计边界；应说明需先修改设计。
5. **模型约束。** 本次新增或重新设计的单元使用用户明确选择的视频模型，AI 不得自行换用其他模型；方案中原样保留的单元继续保留原配置，不因本次选择被批量迁移。模型时长、画幅、参考输入等能力以真实能力契约为准；不得直接把六岗模板中的固定秒数、画幅或提示词预算当成当前模型事实。预计时长与模型请求时长分别表达。
6. **建议与事实分离。** AI 可以给出有依据的参数、参考和衔接建议，尚未确认的参数不冒充已确认参数。缺失实际参考或实际落幅时列出准备条件，不能生成虚假的文件、绑定、检查通过、实际覆盖或采用记录。
7. **补拍继承。** 从显式来源单元继承内容、配置与参考输入，按本次明确要求做局部调整。只有在当前目标模型与归属校验下仍有效的输入才能继续作为有效准备；冲突必须指出，不能静默清空或伪装为可用。继承不等于继承检查通过或素材覆盖结论。
8. **整体拒绝越界。** 结果不得改写六岗设计、其他镜头单元、素材判断、剪辑时间线、全局设置或场次输出画幅。出现越界时拒绝整份结果并说明原因，不静默删除越界片段后应用其余部分。若已有单元同时涉及其他镜头，同样受此保护，不能仅因包含目标镜头就整体替换或移除。
9. **相关输入失效。** 冻结并比较目标镜头相关设计、适用共享约束、当前镜头被覆盖的单元、来源/目标单元、参考与依赖输入、目标视频模型及能力依据。相关内容变化后结果不能应用；其他独立镜头的变化不单独导致本结果失效。
10. **并发保护。** 上述业务相关性比较与保存并发控制分别承担职责。即使结果仍适用，也不能用旧版本全量覆盖新编辑；预览后至确认或保存期间发生变化时仍须校验，避免仅在打开预览时检查一次。
11. **执行范围一致性。** 单元动作范围与选择的节拍、事件、动作、活动等共同界定本次执行。完整镜头目的可作为理解背景，不能被无条件加入本次必须拍摄的动作。原设计“拆信、读信、抬头”、本单元“抬头”时，后续指令输入与检查不得重新要求完整动作；仍保留确实适用的共享约束与连续性要求。
12. **准备和执行继续分离。** 保存单元方案不等于指令依据已确认、检查已通过或获准拍摄。仍遵守现有能力预检、指令审查、真实参考和依赖条件；AI 组织不扩大现有视频执行器支持的覆盖组合。

### 历史保护与身份规则

| 编号 | 场景 | 必须保持的行为 |
| --- | --- | --- |
| HP-01 | 既有单元局部修改 | 保留单元稳定身份，以及仍有效的覆盖项身份。当前内容可以修改，历史生成输入、任务与素材依据保留发生时的内容。 |
| HP-02 | 新补拍、拆分、合并 | 新补拍单元及拆分/合并形成的单元使用新身份。结果明确原单元是保留还是移除，不把新工作伪装成旧单元的原有执行。 |
| HP-03 | 未授权字段与缺省字段 | 保留未授权修改的当前指令、来源、真实参考和依赖等内容。AI 未返回字段不等于请求清空。依据变化时按现有机制表达“依据已变”，不自动确认新依据，也不把旧检查当成新方案已通过。 |
| HP-04 | 当前设计引用 | 单元或覆盖项仍被设计适用关系中的 occurrence 引用时，阻止移除并返回引用位置。AI 覆盖不能顺手删除或改写这些设计事实。 |
| HP-05 | 当前实际覆盖标注 | 单元或覆盖项仍被当前版本实际覆盖标注引用时，阻止移除并返回引用位置。不得自动迁移、删除或重解释真实素材观察记录来满足新方案。 |
| HP-06 | 仅有历史任务、Take 或检查记录 | 历史记录本身不阻止从当前方案移除单元；记录继续保留原版本、原单元及原固定依据，不归入新单元。移除不删除媒体、不撤销既有采用、不重写剪辑安排。 |
| HP-07 | 单元仍有运行中任务 | 任务继续按冻结输入执行，不因当前单元修改或移除而取消、重新绑定或改变输入。完成后仍登记为原任务产生的候选素材，不自动采用。 |
| HP-08 | 移除后的重试 | 原单元从当前方案移除后，“按原依据重试”不可用；必须在覆盖预览中预先说明。历史记录仍可读取，不能自动建立替代单元继续原重试。 |
| HP-09 | 历史版本与落幅依赖 | 不原地改写已确认的历史计划或固定执行依据。已有真实落幅与参考依赖继续绑定其历史来源；AI 的进入/结束状态建议不能替代真实落幅证据，也不能自动迁移依赖。 |
| HP-10 | 整份应用 | 同一次有效方案在一次确认下整体应用。引用阻塞、越界或失效时整体不应用；用户处理关联内容后仍需按当时输入重新校验，不能跳过过期检查强行覆盖。 |

### 接口、文档与页面职责

- 新增或变更对外接口时，同步后端实现、OpenAPI 与前端 generated client，确认生成来源为加载当前工作区改动的后端。
- 六岗设计继续归场次设计视图；单元组织、参考准备、指令与能力预检归场次试拍视图；实际覆盖、采用、接缝和返工判断归剪辑与验收视图。
- 任务中心仅承担通用状态、进度、取消和业务回跳。组织依据、范围差异、参考需求及业务诊断留在场次业务页。
- 实现使现有文档不准确时更新对应页面职责、数据边界和操作说明。本文为待实施规格，不将未来行为提前写成已生效架构，也不顺带改写已固化 release note。

## Testing Decisions

### 已确认的测试入口

前端与后端测试入口已分别向用户确认，均复用现有设施，不为本功能新增测试框架。

- **后端：** 以现有真实 HTTP、数据库与任务生命周期为主要入口，覆盖提交、任务完成、结果预览、确认后的内容保存及再次读取。只替换外部模型响应，保留真实输入快照、DTO 校验、业务范围校验与存储约束。复用现有场次设计建议、单元指令建议、单元范围投影和视频历史/重试测试的组织方式。
- **前端：** 使用现有工作台浏览器测试及配套测试后端，实际操作“AI设计”弹窗、模型选择、状态与差异预览、取消和确认覆盖，并通过保存后读取与页面刷新核对真实内容。复用现有单元覆盖编辑、指令建议、模型准备与视频历史流程测试。
- **执行范围回归：** 优先沿上述业务入口断言下游编译输入和可观察检查结果；必要时扩展已有单元范围投影用例，证明局部动作没有被完整镜头结果重新扩大，不另建一个重复的底层 mock 体系。
- **好测试的标准：** 检查用户可见行为、持久化结果、固定输入和被保护的历史事实；不断言内部函数调用次数、组件私有状态、整段随机模型措辞或 prompt 快照。使用可控模型结果验证合法与非法分支，前后端各覆盖自身责任。

### 前端验收

| 编号 | 场景与操作 | 预期结果 |
| --- | --- | --- |
| FA-01 | 当前镜头没有单元，点击“AI设计” | 可直接进入准备弹窗，无需先创建空单元；当前镜头只读显示。未选择有效镜头时不能开始。 |
| FA-02 | 首次设计有有效全局视频默认值；随后测试无效或缺失默认值 | 前者可见地预选，后者要求用户选择；不会选取列表第一项或不存在的项目默认值。 |
| FA-03 | 多个单元中明确选择一个作为补拍来源 | 弹窗使用正确来源身份和其有效视频模型；不会把同镜头其他单元误当来源。 |
| FA-04 | 模型能力正在加载、失败或必要信息缺失 | 开始按钮不可执行，显示原因；重试成功后才允许开始。改变本次选择不会改写全局设置和现有单元。 |
| FA-05 | 提交首次设计并完成组织任务 | 一次用户开始动作生成组织方案；结果可含多个单元，完成时当前编辑内容和已保存内容均未自动改变。 |
| FA-06 | 对三个现有单元生成两个单元的新方案 | 同一预览显示新增、修改、移除及完整结果；其他镜头内容不列入覆盖。 |
| FA-07 | 取消结果，或未确认就离开预览 | 当前单元与持久化内容保持原状，不产生独立草稿或隐藏的自动应用。 |
| FA-08 | 确认有效方案，分别在自动保存和手动保存模式验证 | 一次确认更新当前编辑内容；自动保存正常落库，手动保存沿用现有待保存行为；保存后刷新一致。 |
| FA-09 | 生成后或预览后修改相关输入 | 原结果保留可查看，确认不能覆盖新编辑，提示重新设计。仅修改独立其他镜头时不错误提示结果过期。 |
| FA-10 | 预览中含被设计引用或实际覆盖标注引用的移除项 | 展示具体阻塞位置和跳转，不能确认覆盖；不会提供绕过引用保护的强制覆盖。 |
| FA-11 | 预览移除仅有历史记录或运行中任务的单元 | 明示历史保留、运行任务继续和按原依据重试不可用；没有额外的第二次覆盖确认。 |
| FA-12 | 应用补拍方案后局部手动修改 | 可继续编辑执行内容并正常保存；提示准备缺项和依据变化，不把方案应用显示为已拍摄或已采用。 |
| FA-13 | 请求或结果要求新增设计中不存在的动作、特写或视点 | 显示越界原因及导演画布职责，不把非法结果当成可确认的单元方案。 |
| FA-14 | 提交返回未知结果、任务失败或保存冲突 | 复用既有请求核实、错误和保存状态交互；不重复创建任务、不静默丢失已有内容、不伪报保存成功。 |

### 后端验收

| 编号 | 场景与输入 | 预期结果 |
| --- | --- | --- |
| BA-01 | 项目、场次、版本、镜头或来源单元身份不存在或归属错误 | 拒绝请求，不建立越权任务或写入错误版本；当前内容不变。 |
| BA-02 | 请求缺少目标视频模型、模型不可用或必要能力未核实 | 返回具体原因；不补默认模型、不调用组织任务猜测能力。 |
| BA-03 | 从没有单元的镜头提交设计，镜头存在适用的六岗条目 | 固定输入包含组织所需候选与约束；不要求预先存在单元选择；结果可形成一个或多个合法单元。 |
| BA-04 | 用户尚未保存的当前编辑内容与持久化版本不同 | 本次固定输入对应用户提交的当前内容；不能悄悄使用旧已保存内容生成。 |
| BA-05 | 重复提交同一请求，以及用同一身份提交不同输入 | 同输入复用同一任务，不同输入冲突；未知响应重查不会产生重复任务。 |
| BA-06 | 组织任务成功、失败或返回非法输出 | 只影响任务记录及结果/诊断，不改变场次版本、单元、真实参考、素材判断或剪辑采用。 |
| BA-07 | AI 选择不存在或不适用的节拍、事件、动作、活动、连续性项，或换用其他视频模型 | 整份结果拒绝并给出原因，不裁剪为部分可应用内容。 |
| BA-08 | AI 改写六岗设计、其他镜头单元、素材判断或时间线 | 整份拒绝。含多个镜头的既有单元不能因命中目标镜头就被整体误删。 |
| BA-09 | 正常新增、局部修改、增加补拍、拆分和合并 | 形成明确完整方案；局部修改保留稳定身份，新补拍及拆分/合并产物用新身份，未授权字段不被清空。 |
| BA-10 | 新补拍继承真实参考、参数与依赖；其中部分与目标能力冲突 | 仍有效的输入保留，冲突明确报告；不伪造可用性，不迁移旧检查通过或实际覆盖结论。 |
| BA-11 | 只有参考需求或进入/结束状态建议，没有真实文件或实际落幅 | 保留准备缺项；不虚构参考绑定、实际帧、检查结果或采用状态。 |
| BA-12 | 生成后改变目标镜头设计、适用共享约束、目标单元、来源单元、参考输入或目标模型能力 | 预览及确认应用校验拒绝旧结果；分别覆盖上述相关输入的变化。 |
| BA-13 | 生成后仅改变独立其他镜头，或预览后出现保存并发变更 | 独立变化不使结果失效；应用保留其他镜头的新内容。保存冲突仍由并发机制处理，不用旧全量快照覆盖。 |
| BA-14 | 原镜头要求“拆信、读信、抬头”，新单元只执行已有动作“抬头” | 选项与动作范围一致，下游执行输入和检查不会重新要求拆信、读信；真实适用的约束仍在。 |
| BA-15 | 当前设计 occurrence 引用待移除单元或覆盖项 | 返回引用位置，阻止整份应用；设计内容、引用与单元都不部分改写。 |
| BA-16 | 当前实际覆盖标注引用待移除单元或覆盖项 | 返回标注位置并阻止整份应用；不迁移或删除真实观察记录。 |
| BA-17 | 待移除单元只有历史任务、Take、检查记录或运行中任务 | 可移除当前单元，历史归属和固定依据保留；运行中任务正常完成并登记候选，不要求当前单元仍存在。 |
| BA-18 | 单元被移除后读取历史与请求按原依据重试 | 历史仍可读取；原依据重试不可用，不建立替代单元或改绑历史任务。 |
| BA-19 | 确认方案改变执行依据，但未请求修改指令或检查记录 | 指令与真实来源保留；依据变化按既有机制反映，不自动确认依据或判定检查通过。 |
| BA-20 | 一份方案同时有合法修改与任意越界、阻塞或失效项 | 整体拒绝，单元、设计、素材和时间线均不发生部分写入。 |
| BA-21 | 应用方案后按现有流程编译、审查、拍摄并生成 Take | 真实准备与能力检查继续生效；生成成功只登记候选，不自动记录实际覆盖或采用。 |

### 实施完成时的检查要求

- 前端代码、类型或构建配置改变后执行项目规定的前端 typecheck，并运行受影响的浏览器流程。
- 后端改变后运行上述相关测试；Python 应用代码改变后执行项目规定的全应用 Pylint。
- 对外契约变化时核对 OpenAPI 与 generated client 一致性，使用加载当前工作区改动的后端生成；验证前端实际通过 generated client 调用。
- 验证优先复用已通过且代码与环境未变的检查。遇到共享基础设施影响不明时再扩大测试范围。
- 纯规格整理不要求构建、typecheck 或执行上述业务测试；本次文档完成检查是已确认决策覆盖、前后端职责清晰、验收可执行及无未经确认的范围扩张。

## Out of Scope

- 整场或跨多个镜头的批量 AI 单元规划。
- 重新运行完整六岗创作设计、增加第七岗或新增多 Agent 编排。
- 判断是否需要 AI 的前置模型调用，以及用户未操作就自动运行组织任务。
- 独立草稿系统、生成完成自动覆盖、额外的“AI调整”或“创建补拍单元”AI 入口。
- 通过本功能改变人物意图、动作含义、情绪、镜头目的、视点或镜头顺序。
- 将组织结果直接当作最终拍摄指令，或跳过现有指令编译、审查与模型能力预检。
- 生成真实参考文件或实际落幅证据、自动审片、标注实际覆盖、采用素材、自动拼接与导出。
- 扩大视频执行器对多镜头、多覆盖项、并行画面合成的支持范围。
- 自动删除、迁移、重写历史任务、Take、检查记录、设计引用、实际覆盖标注或既有采用。
- 新增项目级默认视频模型，或由本次请求更新全局默认模型。
- 重规划导演画布的创作性局部修订能力、恢复旧 Shot/ShotDetail 流程或修改无关工作台布局。
