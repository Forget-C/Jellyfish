# 03: 确认首次方案并保护生成期间的编辑

Status: ready-for-agent
Blocked by: 01, 02
Resolution: completed

**What to build:** 用户查看首次单元方案后，一次确认将其填入当前镜头，按现有保存模式持久化并继续准备拍摄；过期结果不能覆盖新编辑。

来源规格：[单元画布 AI 设计与生产单元组织](../spec.md)。

## 前端要求

- 在已有预览中提供一次明确确认，确认前展示完整新建方案，取消不改变当前内容，不增加第二次覆盖确认或独立草稿。
- 确认更新当前编辑内容；自动保存与手动保存各沿用既有行为，准确表达保存中、待保存与冲突。
- 相关输入改变时保留结果供查看，说明失效原因并要求重新设计；独立其他镜头修改不错误使结果失效。
- 确认后新单元可继续手动编辑及使用现有指令准备流程，模型和准备缺项如实显示。

## 后端要求

- 在预览、确认应用和保存边界核对相关固定输入，包括镜头设计、适用共享约束、参考、模型能力及目标镜头当前单元状态；生成期间手动创建单元同样不能被旧结果覆盖。
- 把合法结果映射为当前镜头单元，明确身份与引用，基于当前编辑内容组合修改；不得回写提交时整份旧快照。
- 业务相关性检查与保存版本并发控制分别执行；保留其他镜头的新内容，错误时不部分写入。
- 沿用既有内容验证与保存机制，模型、文件与引用归属继续校验；保存方案不确认指令依据、不判定检查通过。

## 验收标准

- [x] 浏览器分别在自动保存和手动保存模式确认首次方案，保存回读与刷新一致，取消或未确认时内容未变。
- [x] 真实 HTTP 流程覆盖预览前、预览后和确认/保存期间发生的相关输入变更，旧结果均不能覆盖。
- [x] 仅修改独立其他镜头时方案仍适用，并且应用保存保留该镜头最新内容；真实保存冲突不能被绕过。
- [x] 无效身份、范围、版本或能力结果整份拒绝，当前内容不发生部分修改。
- [x] 应用出的局部单元继续编译指令时保持 01 确立的执行边界。

## 验证与完成要求

- 使用已确认的真实 HTTP、数据库与任务生命周期测试，以及现有浏览器流程；仅替换外部模型响应。
- 遵循 TDD：逐条验证行为，先看到相关用例失败，再实现并确认通过。复用既有单元范围投影测试入口。
- 前端改动执行项目 typecheck；Python 应用改动执行相关测试及全应用 Pylint；对外契约变化同步 OpenAPI 与 generated client。
- 验证范围与本票变化匹配；完成时记录实际命令、结果和限制，并勾选已通过的验收项。
