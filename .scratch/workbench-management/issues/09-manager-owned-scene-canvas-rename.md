# 09: 由管理页统一负责场次画布更名

**What to build:** 用户在管理卡片菜单中明确保存画布名称，两个编辑入口一致显示新名称而不再提供场次画布更名；保存不会覆盖内容，普通自由画布继续使用原更名入口。

**Blocked by:** 05 — 以画布卡片展示方案与真实任务状态；07 — 统一两个入口的候选发现与应用恢复

**Status:** ready-for-agent

Resolution: completed

规格依据：[场次工作台共用画布与工作台管理规格，修订 2](../../shared-canvas-workbench/spec.md)，实施决策 21—22、27、38。依赖编号指本目录管理页增量；使用可信场次关联及既有文档保存能力，不另建保存系统。

- [x] 管理卡片更多菜单提供“更名”，弹窗预填当前名称，明确保存后原位更新；取消不改名，搜索和列表仍遵守创建时间顺序。
- [x] 拒绝空白名称，沿用 1—255 字符约束并允许重名；名称改变不改变画布身份或场次归属，公开写入接口遵守相同校验。
- [x] 从工作台或普通项目入口打开关联场次的画布，均只显示名称并移除更名控件；无场次关联的自由画布保留原更名交互。
- [x] 保存基于最新文档并复用现有编辑权、幂等保存和修订检查，仅改变名称，不能用管理列表旧副本覆盖卡片、关系、引用、配置或运行信息；不要求另设专用更名 API。
- [x] 编辑权被占用、CAS 冲突或保存失败时保留用户输入并提供可理解的处理方式；响应未知先核实原提交，不盲目覆盖或把失败当成功。
- [x] 活动分镜和模型任务不阻止更名，改名不取消任务、不改变冻结输入；更名仍推进画布修订，旧预检或分镜自动应用条件按既有规则失效，不新增跳过检查例外。
- [x] 历史场次已有共同画布仍可更名，遵守相同保存保护；管理和两个编辑入口重开后名称一致，原有内容和运行依据保持不变。
- [x] 弹窗、输入校验、保存／取消及冲突反馈在桌面、窄屏和键盘操作下可达，关闭后焦点返回对应卡片菜单。
- [x] 经真实浏览器与公开接口验证预填、取消、空白、长度、重名、双入口控件、保存重开、活动任务及历史场次；模拟真实编辑权占用、并发保存和未知响应，断言文档内容不被覆盖。
- [x] 完成受影响契约、类型、静态及行为检查；回归普通自由画布更名、共同自动保存与候选核对，不扩大其他基础行为。
