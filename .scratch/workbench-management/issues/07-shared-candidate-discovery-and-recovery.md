# 07: 统一两个入口的候选发现与应用恢复

**What to build:** 用户从工作台或普通项目画布入口打开同一场次画布，都能发现正确分镜候选，并按同一套首次应用、差异核对和恢复规则继续工作；自由画布不附加场次流程。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

Resolution: completed

规格依据：[场次工作台共用画布与工作台管理规格，修订 2](../../shared-canvas-workbench/spec.md)，实施决策 16、18、21、27、30—32、36、38。依赖编号指本目录管理页增量；本票可在既有两个画布宿主独立验证，不依赖新管理页完成。

- [x] 共同读取返回经归属校验的真实章节／场次关联，两个入口据此发现属于本画布的候选；不从名称、固定原文的章节 ID 或最近任务推测场次及候选身份。
- [x] Worker 完成任务只保存经校验的候选，不在后台覆盖画布；两个入口进入共同工作区后使用同一发现与应用判断，不出现一边补卡而另一边始终只显示固定原文。
- [x] 首次候选仅在画布基线未变、无未保存修改、无恢复草稿及无并发冲突时自动应用，并通过现有保存机制持久化，重开结果一致。
- [x] 画布已有人工编辑、修订变化、恢复草稿、失败重试或重新提取时进入既有差异核对；更名推进修订也遵守此规则，不新增忽略更名修订的例外。
- [x] 复用编辑权、CAS、应用回执、恢复与整批撤销；并行打开、重复读取、刷新和提交未知不会重复应用、覆盖新修改或误用另一画布／任务候选。
- [x] 候选存在或历史应用回执不能代替当前文档采用判断；撤销、替换与重新应用仍对应正确任务来源，服务端拒绝过期基线和错误归属。
- [x] 差异继续保护人工修改的覆盖确认、人工新增卡片、孤儿预告及既有布局／引用，不能为双入口恢复增加另一套差异编辑器或自动重写人工组织。
- [x] 无场次归属的自由画布不查询或应用场次候选；普通字段、来源导航、编译、保存、布局和单卡运行保持原行为。
- [x] 历史场次的已有成功候选仍可核对采用，共同画布仍可编辑、保存和运行模型；两个入口和服务端一致禁止历史场次发起新的分镜重新提取，恢复当前身份后重新开放。
- [x] 经真实浏览器分别从两个入口首次打开同一待应用画布，覆盖自动应用、编辑后核对、恢复草稿、更名修订、重试、刷新与保存重开；通过公开接口验证并发、重复／未知回执和跨项目或跨场次请求。
- [x] 保留真实数据库、任务候选、组装、引用校验、应用事务和保存，只有外部供应商响应可受控；完成接口／生成客户端同步、适用静态检查及普通画布消费者回归。
