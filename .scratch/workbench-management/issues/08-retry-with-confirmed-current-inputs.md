# 08: 失败重试前核对本次实际输入

**What to build:** 用户从管理卡片恢复失败或取消的分镜任务时，先核对本次实际原文、对象、参考及模式模型，再继续使用原画布；成功结果按重试规则进入核对，避免把新任务误称为旧输入的完整重放。

**Blocked by:** 06 — 创建新分镜画布并可靠承接后台任务；07 — 统一两个入口的候选发现与应用恢复

**Status:** ready-for-agent

Resolution: completed

规格依据：[场次工作台共用画布与工作台管理规格，修订 2](../../shared-canvas-workbench/spec.md)，实施决策 7、15、17、19—21、27、34。依赖编号指本目录管理页增量；复用已交付的配置、输入确认和共同候选应用能力。

- [x] 只有可重试的失败／取消任务提供重试；管理卡片仍保留原因、详情和打开入口，历史任务目标失效时明确说明，不猜测其他画布或创建替代方案。
- [x] 点击重试先打开简短确认，预填原模式和模型选择，展示本次实际采用的已确认原文、对象与参考摘要；明确使用本次有效输入，不承诺完整重放上次冻结输入。
- [x] 原文、准备和参考在展示后变化时要求重新核对，确认提交必须冻结所展示依据；不得在提交时悄悄换为后来最新来源或偷偷补入完成中的对象结果。
- [x] 原文两种变化、准备过时、尚未提取／零对象及对象任务运行时使用已保存准备的判断与新建流程一致，不用失败重试绕过输入保护。
- [x] 重试始终指向原目标画布，失败继续保留文档和人工内容；同一次受理重复提交或响应未知按原请求核实，不重复发起、不另建画布。
- [x] 同一画布存在非终态分镜任务时界面和服务端都拒绝重试；其他画布任务仍可独立运行，不把同场并行误判为冲突。
- [x] 任务完成留在当前页面；从任一入口打开时都按重试待核对规则处理，即使初次画布仍只有原文也不绕过确认，人工修改和新增内容遵守既有保护。
- [x] 历史场次的失败重试在界面和公开接口均被禁止，已有成功候选仍可核对；恢复当前身份后再允许提交，并重新检查当前依据和归属。
- [x] 经真实浏览器贯通失败／取消、确认、输入变化、受理、完成留页和打开核对；经公开接口覆盖未知响应、重复请求、同图活动门禁、历史场次及错误归属。
- [x] 仅替换外部 LLM／媒体供应商，保留真实任务、输入冻结、候选和保存；完成受影响契约、类型、静态及行为检查，确认重试不执行图片或视频。
