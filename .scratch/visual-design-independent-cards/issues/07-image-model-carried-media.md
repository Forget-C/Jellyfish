# 07: 图片模型接收设计携带素材

Status: ready-for-agent
Completion: resolved
Blocked by: 06

**What to build:** 图片模型仅连接并明确采用设计卡，即可获得设计实际引用的图片，查看完整来源，完成真实编译、预检与固定输入执行，无需补连原素材。

依据：[规格](../spec.md)、[共同执行约定](README.md)。前置票据：[06](06-design-field-references.md)。覆盖用户故事：29–33、35、38–41。

## 验收标准

- [x] 仅六类设计的有效字段声明可携带素材；模型采用设计后合入实际图片，不创建额外原素材连线，不伪造直接采用操作，普通连接仍不自动采用设计。
- [x] 模型实际输入区展示携带素材及来源设计卡／字段，可查看和定位；移除素材通过修改设计引用或取消整卡采用实现，不增加按字段过滤采用。
- [x] 未引用候选、停用字段及旧示例不进入实际输入；最后有效引用删除后停止携带，其他字段或其他已采用设计仍引用时继续保留。
- [x] 同一稳定输出经过多张设计或直接输入到达模型时正确去重并保留全部来源路径；不同身份即使文件相同也不静默合并，模型禁止重复文件时返回明确诊断。
- [x] 重建每张设计的本地代号到实际提交图片位置的映射，多个 @图片1 不串图；输入顺序稳定可解释，后台刷新不任意重排。
- [x] 最终输入明确导演设计为主要依据、模型正文为补充；不依连线顺序覆盖结构化硬要求，不新增自然语言冲突检测或绝对遵从承诺。既有结构化冲突诊断不被绕过。
- [x] 合并直接输入和设计携带后统一检查类型、数量、重复文件和来源有效性；不支持的视频／音频等素材或失效来源明确阻断，不转文本、不静默忽略、不以导演优先绕过模型限制。
- [x] 实际素材进入规范化编译输入、公开预检和任务执行 DTO；从真实 worker 接收参数可验证文件、结果集、输入顺序和引用映射，而非仅在界面显示或输出附加数据中存在。
- [x] 执行快照冻结实际文字、素材、结果集及来源依据；运行后修改卡片不改变该次输入，复用文件占用和结果失效机制，不回读后来的实时来源。
- [x] 有效引用、素材／结果集、顺序与上游输出依据变化参与摘要和过期传播；预检后变化使旧预检失效，未使用候选变化不扩大依赖。沿用既有缺失来源规则，不自动补跑上游以放行缺失引用。
- [x] 通过公开保存 → 编译／预检 → 提交 → worker 参数验证图片路径；完成[共同完成条件](README.md#共同完成条件)。

## 验证路径与范围

复用生成画布编译、设计绑定、引用图片和执行依据用例；真实页面验证无额外连线的输入来源、取消采用和诊断定位。公开接口与 worker 验证直接加携带、多设计同源、不同身份同文件、跨卡同代号、上游结果更新及快照不可变。外部供应商使用现有替身，不执行付费生成。

视频用途由 08 完成；阶段定位与图片目标由 09 完成，二者不作为本票新增阻塞。本票可用无阶段歧义的设计验证完整图片路径，不绕过已有画面目标诊断。
