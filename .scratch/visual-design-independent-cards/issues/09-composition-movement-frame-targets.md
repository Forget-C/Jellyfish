# 09: 构图定位运镜阶段与图片画面目标

Status: ready-for-agent
Blocked by: 03, 04

**What to build:** 构图卡可以明确定位同画布运镜的起始、结束或稳定阶段；图片模型在多个有效画面之间选择本张图的目标时刻，同时继续采用完整设计。

依据：[规格](../spec.md)、[共同执行约定](README.md)。前置票据：[03](03-movement-card-phases.md)、[04](04-composition-card.md)。覆盖用户故事：36、37、38、41。

## 验收标准

- [ ] 构图高级设置可显式选择同画布运镜卡及起始、结束或稳定阶段，不自动关联、不按名字或数组位置猜测目标。
- [ ] 卡片和阶段定位按稳定身份保存；刷新重开、重命名、阶段重排后仍指向原目标。删除或失效后保留可定位诊断，不悄悄换绑。
- [ ] 构图定位仅表达目标画面状态，不等于采用运镜整卡正文或继承其媒体，不建立设计正文互引；模型仍分别明确采用所需设计。
- [ ] 图片模型在多个有效画面时提供目标选择；未选择时明确诊断。只有一个有效画面时不额外要求选择，无有效画面时沿用合法的空内容／准备度诊断，不虚构目标。
- [ ] 图片目标配置保存后可恢复；选择只明确时刻，完整运镜设计仍进入输入，不转换为阶段采用或字段过滤，视频不增加该步骤。
- [ ] 公开编译和预检将构图来源、运镜来源与目标状态纳入可结构化判断的冲突诊断；跨卡互斥要求不被连线顺序静默覆盖，不引入自然语言冲突检测。
- [ ] 目标配置及实际相关状态变化参与依据摘要和预检过期判断；任务固定本次目标和设计依据，后续重排／修改不改变历史输入，也不因定位关系携带未采用运镜素材。
- [ ] 只读、无可选运镜、失效目标及长阶段名称均可阅读并明确表达；通过真实页面和公开保存／编译／执行路径验证，完成[共同完成条件](README.md#共同完成条件)。

## 验证路径与范围

复用摄影画面状态、结构化景别冲突、公开编译和执行依据用例，验证构图结束特写要求、阶段重命名／重排／删除、单画面／多画面以及目标选择后完整设计仍输出。真实页面验证定位操作与错误回跳，worker 参数验证固定目标。

本票无需等待 06／07／08，可用无媒体引用的构图与运镜完成验证。素材携带组合在最终集成验收覆盖，不因此增加开发阻塞。
