## 共同完成条件

以下条件属于每张票据验收的一部分，按实际改动范围执行；每张票据同时完成自身功能与验证，不将测试拖到最后一票。

- 使用真实业务页面和公开保存／编译／执行接口这两个已确认边界，优先扩展现有 canvas-design、摄影、引用、设计绑定、编译和执行依据用例；测试外部行为，不以内部组件树、函数数量或状态快照代替验收。
- 页面覆盖真实保存后重新读取的结果；涉及执行时验证真实 worker 接收的固定输入，外部供应商使用既有替身，不发起付费生成。尚不涉及执行的票据不人为增加执行依赖。
- 前端代码、类型或配置改动完成 `pnpm --dir front run typecheck`；业务页面按工作台规范提供受影响桌面／窄屏截图与交互证据，共享组件覆盖原消费者。
- 后端改动运行相关测试及 `uv run pylint app`；共享引用、编译和执行边界影响不明时扩大到完整生成画布回归及必要全量检查。复用同环境、同代码已通过的检查。
- 外部接口 schema 或语义变化同步后端、OpenAPI 与 generated client；确认后端加载当前工作区代码，再运行 `pnpm --dir front run openapi:update`。前端继续走 generated client，不新增手写 service 层。
- API 层只负责收参、鉴权及响应；业务编排属于 service，跨层生成契约属于 contracts。复用既有任务、文件占用、结果失效和快照机制，不重设计任务调度。
- 同步本票实际影响的工作台设计规范、生成画布架构及 ADR 契约说明，只记录真实落地事实；提交中说明验证结果、未完成项和必要例外，不把原型检查当作正式验收。
- 对最终支持的路径不静默丢弃未处理内容。分步实现暂不支持的引用消费等路径明确诊断；功能全部完成后清除本次临时限制及无效代码。
