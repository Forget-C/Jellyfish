# 六类独立画面设计卡：预设优先、参数引用与素材携带

Status: ready-for-agent

日期：2026-11-03

授权范围：用户已通过两轮 grilling 确认产品决策及真实页面与公开保存／编译／执行接口两层测试边界，并在审阅真实组件原型后最终确认调整后的 A 方案。本轮按 to-spec 将确认结果发布到现有规格；本次不拆分实现票据、不开始实现、不执行数据删除。分诊状态不等于实现已经完成或已获实施授权。

## Problem Statement

生成画布的画面设计菜单展示六个入口，实际只有画面风格与摄影设计两类内容卡。后五个入口创建的都是包含全部摄影字段的摄影设计卡，只改变首次进入的编辑分区。用户选择“运镜”后仍需面对构图、机位、光影与焦点，入口、对象身份和编辑范围不一致。

现有编辑器默认呈现参数表单、两层切换和预览区。常见的“选择一个风格或摄影方案”需要先寻找预设入口，专业字段、候选连接与正向示例／反例又形成额外理解成本。Modal 的内容组织、候选管理和模型卡缺少一致的体验。

设计参数目前主要是纯文本，不能可靠表达“站在 @张三 身后”这类带稳定来源的相对参考。用户即使在设计中明确引用了图片，现有设计输出也不会将图片携带给模型；要求模型再次连接并采用同一图片，会造成重复操作及设计文字与实际素材脱节。

本次需要同时明确六类卡的独立职责、预设与高级设置、结构化引用的使用状态，以及设计内容连同实际引用素材进入模型的边界。

## Solution

画面设计提供六类真实独立卡片：画面风格、景别与构图、机位与视角、运镜、光影与色彩、焦点与成像。每张卡独立保存、编辑、复制、删除和连接，用户按需创建，不自动铺满六张，也不维护共享的隐藏摄影对象。

六类卡继续使用工作台风格的 Modal。卡面保持有限摘要，Modal 默认进入本卡的预设图库；右上角“高级设置”切换到本卡全部文本与必要结构参数，使用“返回预设”返回。取消“设计参数／参考与关联”Tab、摄影五分区切换和高级设置内部的“更多参数”。取消独立正向示例／反例展示与配置，不将其搬进高级设置。

界面采用已确认的 A 方案：紧凑、连续的 Modal 表面，左侧预设图库，右侧选中预设的展示和详情。桌面默认仅图库滚动，标题、候选条、右侧详情及底部操作固定；高级设置和窄屏分别使用适合内容的滚动区域。取消独立“管理关联”按钮，通过候选条内“＋”沿用模型卡的添加入口。

Modal 正文顶部统一显示已连线候选条。预设界面点击候选只查看；高级设置支持在文本参数中输入 @，或将顶部候选插入当前明确编辑字段。实际参与输出的引用决定“使用”状态。预设应用与手动修改编辑同一份卡片数据。

模型只支持整卡采用这些设计。被采用设计的有效字段中实际引用的素材随设计输出携带，无须模型到原素材的额外连线；模型端显示实际素材及设计来源，统一校验能力、用途、数量与失效状态。视频用途在视频模型卡配置。导演设计是主要依据，模型正文是补充，不新增自然语言冲突检测或自动改写。

不迁移或长期兼容不兼容旧摄影卡；只清理冲突卡及失效引用，保留其余画布内容，并明确告知受影响模型缺失设计依据。

## User Stories

1. 作为创作者，我希望菜单中的六种画面设计对应六类独立卡片，以便创建的对象与我选择的用途一致。
2. 作为创作者，我希望按需创建某类设计的多张卡片，以便分别表达不同方案或内容组合。
3. 作为创作者，我希望各张卡独立编辑、复制、删除和连接，以便修改一张卡不会改动其他设计。
4. 作为创作者，我希望卡面只展示紧凑且真实的设计摘要，以便在画布中浏览卡片与连线。
5. 作为创作者，我希望打开设计卡后立即看到预设，以便不熟悉专业参数也能开始设计。
6. 作为创作者，我希望查看预设时不会立即覆盖现有内容，以便先理解效果再决定应用。
7. 作为创作者，我希望最多对比两个预设，以便作出选择而不必切换多个窗口。
8. 作为创作者，我希望应用前知道哪些内容将被填写或覆盖，以便保留有意设置的参数。
9. 作为创作者，我希望一次预设应用可以完整撤销，以便恢复此前内容与引用。
10. 作为创作者，我希望预设只更新它声明的字段，以便保留其他参数和自定义说明。
11. 作为创作者，我希望应用后仍留在预设界面并看到应用结果，以便继续比较或进入高级设置。
12. 作为创作者，我希望右上角提供明确的高级设置入口，以便直接手动填写或修改设计参数。
13. 作为创作者，我希望高级设置直接展示本卡全部参数，以便不再逐层寻找 Tab 或更多参数。
14. 作为创作者，我希望预设与高级设置共用同一份数据，以便看到和调整预设实际填写的内容。
15. 作为创作者，我希望自定义配置不被错误标为某个预设，以便知道当前设计的真实状态。
16. 作为创作者，我希望切换预设与高级设置保留输入和浏览上下文，以便继续当前工作。
17. 作为创作者，我希望不再管理独立的正向示例与反例，以便只理解预设、设计参数和候选引用。
18. 作为创作者，我希望 Modal 顶部显示已连线的候选内容及使用状态，以便快速理解设计依据。
19. 作为创作者，我希望候选管理沿用模型卡的视觉和公共规则，以便不必学习另一套素材操作。
20. 作为创作者，我希望在预设界面点击候选只查看内容，以便不会将引用插入未知字段。
21. 作为创作者，我希望在文本参数中通过 @ 选择候选，以便表达带明确来源的相对参考。
22. 作为创作者，我希望点击顶部候选能插入当前明确编辑字段的光标位置，以便快速编写参数。
23. 作为创作者，我希望没有编辑字段时点击候选仅查看，以便系统不会猜测插入位置。
24. 作为创作者，我希望同一候选被多个有效字段引用时始终显示使用，以便局部删除不会误清其他引用。
25. 作为创作者，我希望删除最后一处引用后保留候选连线，以便以后仍可重新引用。
26. 作为创作者，我希望停用字段保留文字和引用但不携带素材，以便恢复配置时无需重新填写。
27. 作为创作者，我希望待确定和明确没有等状态继续保留原意，以便开放要求或否定要求不会被当成空内容。
28. 作为创作者，我希望设计字段沿用模型卡的结构化引用规则，以便改名、排序或重新编号不会引用错误内容。
29. 作为创作者，我希望模型整卡采用设计，以便无需逐字段或逐阶段配置采用范围。
30. 作为创作者，我希望设计实际引用的素材随设计进入模型，以便无需重复连接原素材。
31. 作为创作者，我希望未引用的候选不进入模型输入，以便实际请求只包含明确使用的依据。
32. 作为创作者，我希望模型端能查看携带素材及其设计来源，以便理解最终实际输入。
33. 作为创作者，我希望同一来源通过多条使用路径到达模型时正确去重和映射，以便不会浪费额度或串图。
34. 作为创作者，我希望视频模型允许为携带素材指定用途及主体分组，以便正确表达首尾帧或主体参考。
35. 作为创作者，我希望缺失用途、不支持的媒体及数量超限得到明确诊断，以便调整配置后再生成。
36. 作为创作者，我希望构图要求能够明确关联运镜卡的特定画面阶段，以便表达结束时必须特写等要求。
37. 作为创作者，我希望图片生成能够指定运镜中的目标画面，以便整卡设计不会让单张图片的时刻含糊。
38. 作为创作者，我希望不同设计分别被模型采用，以便不必维护多层设计正文嵌套。
39. 作为创作者，我希望最终输入把导演设计作为主要依据、模型正文作为补充，以便保留清楚的创作层级。
40. 作为创作者，我希望运行固定实际使用的文字、素材和用途，以便后续编辑不会改变已提交任务的依据。
41. 作为创作者，我希望来源变化和失效能够沿设计依赖传到预检和结果状态，以便不会误用过期依据。
42. 作为创作者，我希望旧冲突数据只影响对应卡片和引用，以便其他设计、提示词和素材继续保留。
43. 作为创作者，我希望清理后明确知道哪些模型缺失设计依据，以便不把残缺配置当作完整方案运行。
44. 作为只读用户，我希望可以浏览预设、对比、参数和候选，以便理解设计，同时无法修改或应用。
45. 作为键盘或窄屏用户，我希望关闭、返回、应用、焦点和长内容滚动均可操作，以便完整完成同一设计流程。
46. 作为创作者，我希望 Modal 使用连续表面与紧凑间距，以便将更多空间留给预设和设计内容，减少视觉割裂。
47. 作为创作者，我希望左侧浏览图库、右侧查看选中预设的展示和详情，以便选择时始终保留清楚的对照关系。
48. 作为创作者，我希望滚动图库时标题、候选条、右侧详情和操作区保持固定，以便随时比较、引用和应用。
49. 作为创作者，我希望通过候选条“＋”使用与模型卡一致的添加入口，以便无需学习额外的关联管理界面。
50. 作为创作者，我希望查看候选使用轻量浮层而不撑开主体，以便保持当前预设和浏览位置。
51. 作为创作者，我希望超长变更明细、高级参数和窄屏内容仍可完整阅读，以便紧凑布局不会隐藏必要信息或遮挡操作。

## Implementation Decisions

### 六类对象与字段职责

| 卡片 | 参数范围 |
| --- | --- |
| 画面风格 | 风格方向、色彩倾向、视觉特征、材质倾向、自定义说明 |
| 景别与构图 | 景别、构图重心、画面位置、空间层次、留白、构图要求及已有结构化景别要求 |
| 机位与视角 | 观察视点、机位位置、高度与角度、焦段与透视意图、支撑方式 |
| 运镜 | 运动方式、起始画面、触发条件、运动路径、速度、结束画面及明确运镜阶段 |
| 光影与色彩 | 光源、光线方向、明暗区域、曝光与色温、色彩关系 |
| 焦点与成像 | 景深与焦点、焦点变化、光学效果、运动质感、技术意图、相邻镜头衔接、禁止项 |

- 六类卡在目录、类型契约、保存、输出、渲染和引用中都具有独立身份；不使用五个别名继续编辑一份完整摄影卡。
- 保持已有字段归属，不给所有卡统一新增约束字段。公共字段控件和类型基础可复用，不复制完整摄影字段至每个新类型。
- 不自动创建六卡组合，不因所属镜头相同合并内容，也不引入隐藏内容所有者。
- 现有作用范围、来源、对象关系及必要的专业参数按卡片真实职责保留；独立正向示例／反例配置不属于新界面或新引用机制。

### Modal、预设与高级设置

- 六类设计均继续默认 Modal。统一工作台主题、简洁标题、保存状态、右上工具、关闭及固定操作区；标题、候选、主体和底部使用连续表面，减少横向分界线及嵌套边框。桌面限制视口内尺寸，窄屏使用近全屏布局。
- 采用用户最终确认的 A 布局：顶部为紧凑候选条，主体左侧预设图库，右侧选中预设的展示和详情。桌面预设模式由左侧图库独立滚动，标题、候选、右侧详情和底部操作固定；变更明细可替换右侧预览，超长明细局部滚动。高级设置替换主体并独立滚动；窄屏改为上下排列和内容区滚动，操作区继续固定。压缩重复标题、间距和操作区，不叠加第二个大型窗口。
- 不保留设计参数／参考与关联 Tab、摄影分区导航或高级设置内的更多参数入口。高级设置是本卡文本与必要结构控件，不是另一套示例管理页面。
- 预设图库与高级设置共用同一份受控卡片数据。手动编辑自动保存；未应用的预设选择只属于预览会话，不写入卡片。
- 打开默认进入图库，无自动选中或自动应用首个预设；尚未选择时右侧展示当前配置摘要或选择提示，不将首个预设示意冒充当前设计。预览与对比不改变内容，最多对比两项；示意图／视频解释设计意图，不宣称是当前真实生成结果。
- 应用前提供填写／覆盖摘要及可展开明细，涉及字段文字、状态、用途、来源和引用变化均需准确。只合并预设声明的字段；未涉及字段和引用保留，应用作为一次完整可撤销变更。
- 应用后留在图库并反馈结果。手动修改后的配置不能仅因曾应用过某个预设而继续误标为该预设，未匹配时表达自定义配置。
- 模式切换保留未保存输入、待应用预设、对比选择与各自浏览位置；关闭清除未应用预览，普通编辑继续沿用既有草稿与保存策略。保存失败保留输入并明确显示。
- 本次复用现有预设内容，不大规模扩充图库。预设可只声明部分参数，例如景别与构图预设可组合填写，不将整个卡片当作互斥预设值。
- 只读仍可导航、阅读、查看候选、预览和对比，禁止写入及应用。关闭、内层 Escape、焦点恢复、窄屏操作可达和打开不重排画布沿用工作台规范。

### 候选条与字段引用

- 候选条列出直接连入本卡、符合输入契约的普通文本、对象和媒体来源，包括允许引用的模型正式输出；不按名称检索任意祖先或跨画布内容。
- 缩略图、名称、使用标记及添加规则复用模型卡。取消顶部独立“管理关联”按钮和展开式管理区，通过候选条内“＋”沿用模型卡的上传参考素材／从素材库添加／从当前画布选择入口；连接只增加候选，不自动引用。候选查看使用轻量浮层，避免推挤主体；不把运行提交／模型能力参数／运行结果装入设计编辑器。
- 连接只提供候选。设计卡不设置独立的素材采用开关，是否使用由各字段中实际生效的引用汇总决定。
- 默认预设界面点击候选只查看内容。高级设置输入 @ 选择候选，或点击候选插入当前明确编辑的文本字段及其光标位置；没有明确目标时只查看，不猜字段。
- 复用模型卡的稳定引用片段、候选解析、输入代号、复制粘贴、中文输入、光标与失效显示规则。普通文本引用按既有规则展开，引用不局限于对象名称；对象引用沿用对应出口身份语义。名称和局部代号不能代替稳定输出标识。
- 设计字段由纯文本扩展为可持久化的结构化引用内容；不得仅扫描字符串 @ 或按同名对象推断实际使用。多字段共同维护本卡引用集合，不能对单个字段应用会误清其他字段绑定的逻辑。
- 字段处于未填写或不适用状态时，保留内容及引用，但不输出、不携带媒体，候选状态提示“已引用 · 未生效”。其他字段仍有效引用该来源时，仍标记使用。
- 明确没有、待确定、提议、事实以及背景／设计／约束用途沿用已有输出规则，不因名称看似否定或不确定就自动关闭引用。没有有效输出的引用不成为实际模型输入。
- 删除最后一个字段引用后停止使用，候选连线继续保留。普通删卡／断线仍检查真实引用，停用字段保留的引用也不能被无声破坏；旧冲突数据清理是单独的已授权例外。
- 来源缺失保留可定位的引用状态，不能自动替换为同名候选。实际生效的失效引用阻塞依赖它的运行；保留在停用字段中的引用问题不应凭空进入实际请求。
- 本次不新增设计卡之间的正文互引。多张设计卡由模型分别采用；构图定位运镜阶段是独立结构关系，不代表引用运镜整卡正文或继承其全部媒体。

### 整卡采用与素材携带

- 下游只支持整张设计卡采用；删除分区、字段、阶段采用范围的界面及新契约能力。用户通过创建独立卡片表达不同内容组合，不保留旧局部选择兼容别名。
- 仅本次六类设计卡可以明确发布本卡文字及有效字段实际引用的素材依赖。依赖包含稳定来源身份、实际内容与可用性、来源对应关系，不能扩大为收集所有候选或所有祖先。
- 模型采用设计卡时合入这些声明素材，无需增加模型到原素材的连线，也不伪造用户的直接采用操作。设计到模型的采用仍须明确，普通连接不自动采用整卡。
- 模型端显示实际携带素材及来源设计卡／字段，可查看和定位。素材是否携带由设计引用决定；移除时修改设计引用或取消整张设计卡采用，不恢复模型端按设计字段过滤的能力。
- 统一映射模型直接采用和设计携带的来源。同一稳定输出身份按现有规则去重，多个来源路径保留可追溯信息；不同身份即使对应同一文件也不静默合并。视频同素材的不同合法用途不得因通用去重丢失。
- 最终输入重建本地代号到实际媒体位置／用途的对应，不直接拼接各设计卡的 @图片1。采用稳定、可解释的输入顺序，后台刷新不能任意改变映射。
- 展开的文本作为数据，不二次解释其中的引用或系统指令，不从普通文字猜测媒体用途，也不自动执行上游生成任务。
- 合并后的全部实际素材接受模型输入类型、数量、重复文件、主体分组和用途组合校验。模型不支持携带素材时明确阻断，不静默丢弃、转文本或以导演优先为由绕过能力限制。

### 视频用途、画面目标与设计优先关系

- 视频模型为设计携带素材配置主体参考、首帧、尾帧、关键帧等受模型支持的用途及必要主体分组；无需额外连线。已有明确配置可复用，缺失则提示补齐，不猜首帧或自动用设计卡名作为主体名。
- 视频侧只配置如何使用，素材是否携带仍由有效设计引用决定。用途变化进入保存、预检和固定执行依据，不改变设计卡正文。
- 构图卡保留结构化景别要求，可显式关联同画布某运镜卡的起始、结束或稳定阶段；不自动关联。仅关联画面状态不代表采用整张运镜卡。
- 阶段重命名或重排保留稳定身份；删除或失效须让相关定位产生明确诊断，不能依名称或数组位置换绑。
- 图片模型保留画面目标选择。整卡内容继续作为设计依据，选择目标仅明确生成的时刻，不裁切为阶段采用；只有一个有效画面时不额外要求选择。视频不增加图片画面目标步骤。
- 最终输入明确已采用导演设计为主要依据、模型正文为补充说明。不新增自然语言冲突检测或自动改写，不承诺生成模型绝对遵循优先级。
- 可结构化判断的互斥硬要求继续诊断，不用连线顺序静默覆盖。跨构图与运镜卡的来源身份及目标状态必须进入对应判断。

### 执行依据与不兼容数据

- 实际携带素材必须进入规范化编译输入、预检与执行 DTO，不能仅藏在设计输出的附加数据中。执行快照冻结相关文件、结果集、引用映射、用途和来源依据，执行时不回读后来变化的实时素材。
- 设计引用、媒体内容／结果集、顺序或用途变化参与依据摘要和预检过期判断；上游模型输出依据变化经明确的设计依赖传播到接收模型。未引用候选变化不扩大实际依赖。
- 复用既有文件占用、结果失效和单模型运行机制。历史运行固定依据不被后续编辑原地重写，不自动运行上游补齐缺失结果。
- 用户明确不要求旧摄影卡数据迁移或长期兼容。实施只清理不兼容旧摄影卡及相应失效连线、输入顺序、分组成员、引用绑定、提示词引用和依赖这些绑定的画面目标等关联项。
- 保留其他卡片、普通提示词正文、有效引用与配置；不借清理扩大为整张画布、项目文件、媒体成果或无关历史记录删除。
- 清理后的模型明确显示缺失设计依据，不能因移除引用而被误标为原方案已完整配置；通过重新配置或明确处理缺失问题恢复。
- 处理旧存储时须考虑原文档解析、幂等记录与固定快照的边界，不能先移除类型导致受影响画布整体无法读取，也不能将不兼容旧快照伪装成新契约可执行输入。不可用历史提供明确状态，不引入旧类型长期兼容层或重写历史事实。
- 旧正向示例／反例不自动转成新的有效引用，不因遗留关联而携带素材；不兼容部分按本次有限清理政策处理。

### 组件、契约与文档边界

- 优先复用工作台 Modal 主题、动作区及既有编辑容器能力，统一六类设计的外壳；保留保存、草稿、关闭保护、焦点及 portal 主题行为。连续表面通过留白、文字层级与控件状态表达分组，不以重复横线划分标题、正文和操作区；紧凑布局仍须保持文本可读、焦点可见和操作可达。
- 抽取模型与设计真实共用的候选展示、添加与引用交互部分；用途校验、运行行为和写入由业务调用方负责，不抽出承载全部模型业务的万能编辑器。正式实现复用已有上传、素材库与画布选择能力；原型中上传／素材库的禁用仅是演示范围限制，不作为正式功能的限制。
- 六类设计共用预设／高级设置框架及预设选择器，各卡提供自己的字段和必要结构配置；不建立通用表单引擎，不顺手改造其他导演卡。
- 后端类型目录、设计输出、引用解析、编译、预检和固定执行依据同步调整；API 层负责收参、鉴权与响应，业务规则留在 service 层，跨层契约放统一 contracts。
- 对外 schema／语义变化同步 OpenAPI 与前端 generated client，前端继续使用生成客户端，不新增手写 service 封装。
- 实施落地时同步受影响的工作台设计规范、生成画布架构及相关 ADR 契约说明。规格发布阶段不将未来方案写成已生效架构，不改写历史验收结果。

## Testing Decisions

测试边界已获用户确认：真实生成画布页面与公开保存／编译／执行接口。优先改造现有测试，不按新组件或内部函数数量增加测试层，不以类型名、组件树或内部状态快照代替用户行为验证。

### 真实页面边界

沿用现有 canvas-design 套件、摄影卡、设计编辑器、预设及导演 Modal 浏览器用例，使用真实页面和隔离后端，验证保存后重新读取的画布内容。

1. 六个入口分别创建对应独立类型；编辑、复制、删除、连接及重开不混入其他卡片字段。
2. 默认进入预设，取消两层 Tab；高级设置完整展示本卡参数，必要结构控件可用，独立正反例配置不存在。
3. 预览与对比不写入；应用仅修改声明字段，覆盖可读且一次撤销完整恢复字段、引用与使用状态。预设应用后留在图库，自定义配置不误标。
4. 候选条在顶部，无独立“管理关联”按钮及展开管理区；“＋”沿用模型卡入口。上传、素材库、当前画布选择增加候选但不自动引用；默认点击只查看，高级设置 @ 与点击插入正确字段／光标；无目标不插入，跨字段汇总使用状态。
5. 最后引用删除、字段停用／恢复、失效来源、多字段同源、保存刷新、中文输入、复制粘贴和代号更新不误换来源；候选未使用不进入实际输入。
6. 模型端显示设计携带素材及来源，不要求新增连线；视频用途可配置，缺失或不支持用途显示定位准确的问题。
7. 构图阶段关联、阶段重命名／重排／删除及图片画面目标可操作，不出现局部采用选项或设计正文互引入口。
8. 预设／高级切换、关闭重开、保存失败和后台刷新保留应保留内容；关闭清理未应用预览；只读不能写入但可阅读与对比。
9. 六类 Modal 均采用 A 的连续表面、左图库／右详情结构和紧凑密度。覆盖常规桌面及小高度视口：图库内容溢出后滚动图库，标题、候选、右侧详情和底部操作位置不变；右侧显示实际选中预设，未选择时不自动显示首个方案为当前设计。
10. 展开变更明细时在固定右侧区域内切换内容；超长明细可完整阅读，高级设置独立滚动，切回预设保留浏览位置。候选查看浮层不推挤主体，Escape 优先关闭内层并恢复触发点焦点，不同时关闭 Modal。
11. 窄屏采用上下排列与内容区滚动，底部操作持续可达；关闭、返回、应用、长名称／长文本和候选添加均不被裁切或横向页面溢出影响。视觉验收对照已确认 A 原型，提供六类共享 Modal 与受影响模型候选区域的截图及交互证据，不以暗色背景相近代替验收。

### 公开保存、编译和执行边界

沿用生成画布 HTTP 用例、摄影公开保存／编译测试及真实 worker 接收固定输入的测试。通过公开请求验证诊断、输入预览和实际执行参数，外部供应商使用既有测试替身，不为验收发起付费生成。

1. 六类契约接受各自合法字段并拒绝越界数据；新契约只支持整卡采用，不暗中保留分区／字段／阶段选择。
2. 结构化引用按稳定输出身份保存，文本展开遵循既有规则；引用展开不触发二次指令；无边、跨画布、缺失来源和循环等异常有正确的保存／运行边界。
3. 模型仅连接设计卡时可接收有效引用媒体；普通候选、停用字段及旧示例不携带，最后有效引用移除后停止携带，其他字段引用不受影响。
4. 同源多设计路径、直接加携带路径、不同来源同文件、不同设计局部同代号均产生正确去重、顺序与映射；视频多用途不被去重抹掉。
5. 合并后的媒体接受模型类型、数量、重复文件及视频用途／组合限制；缺配置或不支持时不静默丢弃，不自动创建首尾帧或主体名称。
6. 构图阶段关联仅定位目标，不导入运镜正文／媒体；图片目标不裁切整卡设计；单状态无需多余选择，多状态缺目标明确诊断。
7. 已声明导演设计为主要依据、正文补充，结构化硬冲突仍被识别；不使用实际生成画面是否服从作为确定性的单元断言。
8. 预检和执行真正固定媒体与结果集；预检后来源／用途改变触发过期，运行后修改不改变该运行输入；上游过期通过设计依赖传播，未使用候选变化不污染实际依据。
9. 混合新旧数据定向清理后仍可读取保存；无关卡片、普通正文和有效引用保留，受影响模型显示缺失依据；旧存储／快照不导致整图失效或历史被改写。

### 必要项目检查

- 前端改动后运行项目规定的 typecheck，并按工作台规范执行受影响浏览器验收；共享候选组件需覆盖原模型卡消费者。
- 后端改动后运行相关集成测试及 pylint app；引用解析、编译或执行依据属于共享边界，若影响范围不能限定，扩展至完整生成画布相关回归及必要全量检查。
- 外部契约变化从加载当前工作区代码的后端更新 OpenAPI／generated client，检查生成差异与实际契约一致。
- 文档发布本身只检查规格结构、故事编号、链接及决策一致性；不以未执行的代码测试声明实现通过。

## Out of Scope

- 本次发布不实施、不拆票、不运行数据清理或付费生成。
- 不迁移旧摄影内容，不维护两类旧卡与六类新卡的长期双轨或兼容别名。
- 不保留按分区、字段或运镜阶段采用；不恢复独立正向示例／反例配置。
- 不新增设计卡正文互引、跨画布动态引用、无界祖先媒体收集或自动补跑上游。
- 不把携带素材能力推广到所有导演卡，不重设计任务调度、状态机或生成供应商协议。
- 不新建大规模预设库，不自动从图片提取设计参数，不验证图片内容符合设计，也不承诺预设示意等于生成效果。
- 不新增自然语言冲突检测、自动改写或导演优先级的模型执行保证，不绕过能力和数量限制。
- 不增加所有卡共用的约束字段、通用表单引擎或无关页面视觉重构。
- 不将 B／C 布局、原型切换器、内存示例或演示用诊断作为生产功能；不直接合入可丢弃原型。
- 不清空整张画布、项目文件或无关历史，不修改场次工作台、Take 与剪辑采用等独立业务流程。

## Further Notes

- 本规格使用生成画布、画布文档、模型卡、输出标识、输入代号和画布运行等现有领域术语；设计整卡采用与场次素材的剪辑采用不是同一业务。
- 用户最终确认调整后的 A 方案，以原型分支 `codex-prototype-visual-design` 的 `7e0367fc` 为视觉与交互来源；B／C 只作历史比较。本轮已将选择结果落实到解决方案、用户故事、实现决策及真实页面验收要求。
- 原型已有类型检查和浏览器检查证据，但没有真实后端保存、上传、预检或执行验证；沿用已确认的两层测试边界，不新增内部组件测试层，也不把原型检查替代正式验收。
- 最终决策以本规格为准：初期“默认参数、预设次入口”已被“默认预设、参数在高级设置”取代；“正反例搬入高级设置”已被取消；对象身份限定引用和媒体必须由模型直接补线的建议均未被用户采用。
- Q15 最终确认的是六类设计携带实际引用素材，而不是任意媒体隐式递归传递。Q16 的视频用途、Q17 的主要／补充关系、Q18 的字段生效规则、Q19 的非嵌套范围及 Q20 的两层验收均已确认。
- 本规格替代原卡片规格中“两类设计卡／摄影五入口同内容所有者”“摄影局部采用”“设计媒体必须直接连入模型”及本范围旧 Modal 默认布局的冲突要求；其他业务规则和既有完成证据继续保留。
- 原工作台设计文档及生成画布架构描述的是当前实现，实施后应更新到本规格落地的事实，不能仅靠修改规格声称新功能已存在。
- 规格发布完成不代表浏览器、后端测试或视觉验收已经执行。正式验收需针对新实现单独记录。
