## 1. 目标与边界

让用户直接读懂拍摄指令和检查意见中的人物、镜头、参考素材及业务字段，并能追溯其原始标识和固定依据。

采用“同一份指令、两种视图”：默认显示易读视图，允许切换模型原文。检查结果默认易读，按条展开原始记录。转换只影响展示，不产生新的指令版本，不改变审稿状态或实际模型输入。

技术沿用 React、Ant Design、现有固定快照与编译映射。执行时使用 `superpowers:executing-plans` 按 T1–T4 顺序推进，无需另建架构或并行实施。

本轮不做：

- 不用 AI 另写摘要或润色稿，不维护两份可编辑正文。
- 不清理或重写模型实际提示词，不改变供应商参考绑定规则。
- 不新增页面、双栏对照、全局术语管理或通用富文本编辑器。
- 不回填或重编译历史指令，不使用最新资产信息补写历史事实。
- 不猜测“他”“该对象”等未明确绑定的自然语言代词。
- 不重做固定输入、资产选择、任务中心或剪辑流程。

## 2. 已确认的现状

- `backend/app/services/directing/production.py` 的 `_compile_unit` 输出内部字段名、对象 ID、参考组标识；这是真实执行文本的一部分。
- `backend/app/core/contracts/directing/production.py` 的 `Prompt.text` 保存固定正文；`CompilationDecision` 已包含字段路径、正文摘录和参考关联，但不是所有标题、身份行都有映射。
- 试拍将 `Prompt.text` 传入生成请求；`backend/app/services/generation/media_execution.py` 使用任务快照中的执行文本构造视频输入。参考媒体另随请求传递。
- `front/src/pages/aiStudio/directing/PromptReader.tsx` 已支持按正文摘录查看固定设计依据，且沿对应计划查找历史设计。
- `ShootInstructions.tsx` 已有指令正文、固定输入、版本记录；无须增加外层页面。
- `ShootReview.tsx` 已按问题优先、通过项折叠展示；`ReviewDetails.tsx` 已翻译部分字段路径，但说明、观察、建议等仍直接显示原始文字。

因此“模型原文”指提交给模型的指令文本，不宣称其包含完整请求。图片、模型与参数继续由“固定输入”展示。

## 3. 展示与数据规则

### 拍摄指令

在现有“指令正文”内增加“易读视图 / 模型原文”切换，默认易读。顶部提示“名称和字段已转换；实际提交以模型原文为准”。保留原文的信息顺序和背景／本次动作边界，不重新概括创作内容。

| 原始对象 | 易读名称来源 |
| --- | --- |
| 人物、道具参与者 | 对应固定设计中的参与者名称 |
| 镜头 | 固定设计中的镜头编号；与本单元出现序号分别表达 |
| 节拍、事件、空间锚点、调度状态、验收标准 | 类型与固定顺序编号；可附已有描述的短摘录，不生成新名称 |
| 参考组、参考绑定 | 固定计划中的参与者或资产来源名称，加用途；无名称时用“参考 01”等编号 |
| 已知字段、枚举值 | 复用并补齐中文业务词汇，例如“人物”“调度状态”“主体参考” |
| 未知或有歧义的标识 | 保留原文，提示暂未识别，不匹配到相似对象 |

- 可追溯词语使用细下划线；悬浮或键盘聚焦显示类型、名称、原始标识。
- 点击在现有依据区域展示固定版本、原始 ID、原始字段路径、对象说明；参考素材沿用既有预览。移动端点击即可完成操作。
- 实体详情与编译依据共用同一区域，不叠加抽屉或在按钮内部嵌套按钮。
- 同名对象通过类型、编号或用途区分；详情始终保留完整标识。
- 复制按钮随视图明确标为“复制易读内容”或“复制模型原文”；前者包含当前展示的完整文本，后者逐字复制 `Prompt.text`。
- 切换视图不改变当前工作版本、检查记录或固定输入；检查定位仍指向同一份指令。

示意（非实际项目内容）：

```text
[易读视图 | 模型原文]                       复制易读内容
参考：［林岚 · 外观参考］，主体参考，2 张图片
本次动作：［镜头 05 · 本单元第 2 段］，林岚走到门边。
人物调度：［林岚］位于门内左侧。
```

### 检查结果

保留当前问题优先与通过项折叠结构，不增加全局视图切换。单条依次展示问题、建议、验收条件和影响位置，来源及原始数据按需展开。

- 结论说明、观察、建议、验收条件使用同一套确定性名称转换。
- 影响路径显示“摄影构图 → 镜头 02 → 景别”等业务名称；原路径放入详情。
- “展开原始记录”显示本条未经转换的文字、状态及相关标识，完整保留该条问题内容；不默认铺开整份检查 JSON。
- “查看对应指令与依据”打开对应固定指令的易读视图，按原始映射定位；无法精确定位则明确说明，不高亮相似文字。
- 不合并检查行，不改变通过数量、岗位、出现项、人工取舍及“建议／事实”等状态语义。

### 解析边界

数据链：固定指令或检查记录 → 所属历史计划与设计、单元参考 → 确定性展示片段。

- 只读对应历史快照，不查询当前资产名称代替历史名称；缺失时降级显示原始信息。
- 按对象类型、字段路径及上下文解析；禁止全局字符串替换。自由文本仅转换边界明确、在当前上下文唯一可识别的标识，不转换普通同名词或短串的子串。
- 显示片段保留其原文起止位置；先在原文上计算实体与编译依据范围，再渲染可读标签。可读名称长度变化不得破坏高亮与定位。
- 优先复用现有 `decisions`、字段词典及固定设计信息。现有 v4 编译器的固定格式可在局部识别；未知格式按可识别片段处理，其余保留原文。
- 不新增可读正文存储字段。若实施验证发现个别位置确需后端提供精确映射，只补必要的可选元数据，不修改 `Prompt.text`；历史缺少映射允许降级。

仅在后端实现发生变化时，在 `backend` 运行相关契约、编译及执行快照测试，并运行 `uv run pylint app`；既有问题与本次新增诊断分开记录。对外契约变化时，先确认本工作区后端已加载，再在项目根目录运行 `pnpm --dir front run openapi:update`。

完成必须同时满足：

1. 普通阅读不再需要理解已知对象 ID 和内部字段名，未知内容仍可见。
2. 模型原文、参考绑定和真实提交链不因展示转换发生变化。
3. 名称与依据对应历史版本，同名、缺失对象和歧义不会被猜测补齐。
4. 检查结果与原文可互相核对，定位准确，结论状态不变。
5. 桌面、键盘与移动端均可打开和关闭详情；本轮不新增独立页面或重复编辑入口。

## 7. 实施与验收记录

### 最终实现

- `readableText.ts` 统一固定名称、字段路径、v4 编译字段／枚举和原文区间解析；`ReadableContent.tsx` 提供共用文本交互与只读对象详情。组件名称避免与纯逻辑文件在不区分大小写的文件系统上冲突。
- 指令正文默认易读，支持模型原文、两种明确命名的复制操作、名称提示和详情；名称详情与编译依据共用现有区域。重复片段和重叠映射继续使用原文坐标。
- 检查展示覆盖岗位说明、观察、建议和验收条件；主工作区、人工取舍、任务结果和台账共用解析，并按检查出现项对应的历史指令取上下文。原始检查行保留完整 JSON 供核对。
- 保留实际执行文本、模型参考名称、文件与提交链。没有修改后端、OpenAPI、generated client 或数据库，不需要契约生成与后端检查。
- 补齐本轮操作说明及架构中的真实展示边界，没有新增页面、可读正文存储或 AI 改写流程。
