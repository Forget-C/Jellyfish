# 工作台设计标准迁移

执行标准见[工作台前端设计标准](../../guide/workbench-design/)。先建立可执行标准与真实组件，不一次性重写全部业务区。

| 区域 | 本轮范围 | 后续迁移 |
| --- | --- | --- |
| 共用主题 | 提取局部主题和语义 tokens，覆盖 portal | 按业务区替换余下硬编码色值 |
| 共用工具栏 | 菜单触发、版本操作、保存、四画布切换、撤销／重做 | 各画布业务模块提供的独立主操作入口 |
| AI 设计 | 全部动作、弹窗和固定操作区，复用正文折叠 | 业务阶段继续留在原组件 |
| 任务中心 | 工作台实例的动作及滚动样式；浅色实例隔离 | 历史任务弹窗单独评估 |
| 内容预览 | 原有 CanvasTextPreview 与 AI 原文统一实际行数判断 | 新增长文本均复用；不统一业务数据结构 |
| 其他业务区 | 保留现有行为与入口 | 六岗设计、导出、视频生成、批量拍摄、交付弹窗逐区迁移 |

每批迁移运行类型检查与 `test:workbench-ui`，仅在涉及对应行为时运行业务回归。遗留蓝色主按钮和未迁移弹窗列为存量，不作为新增组件的样例。通过局部替换删除对应旧覆盖规则，不全面重排无关 CSS。

当前不引入新的组件库依赖、业务状态机或表单生成器；不改变全站浅色页面。没有新增领域概念，也没有难以逆转的架构选择，因此不新建领域词条或 ADR。
