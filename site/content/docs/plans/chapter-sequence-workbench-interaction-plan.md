# 章节、场次与工作台交互优化任务计划

> 执行说明：使用 `superpowers:executing-plans` 按任务推进；按下文检查项记录完成状态。本轮交互实现及范围内验收已完成；最终结果和已知检查限制见第 8 节。历史执行记录按发生时状态保留，不代表当前仍待处理。执行时遵循项目 `AGENTS.md`，复用已有授权、实现与有效验证结果。

> 后续入口调整见[章节列表与场次抽屉交互优化计划](/docs/plans/chapter-list-and-sequence-drawer-plan/)（已完成）：章节主区已改为章节表格，场次列表与详情位于同一抽屉，不增加跨章节待核对数量、粗剪数量。本文保留本轮已完成范围及历史验收记录。

**目标：** 从章节中一次操作进入指定场次的工作阶段，使用户始终知道当前场次、版本依据、选中对象和下一步操作。

**架构：** 章节页承担场次浏览、轻量管理与快捷导航，场次工作台继续承担设计、试拍和剪辑。版本弹窗只协调浏览与编辑上下文，不新增“场次总版本”实体，也不改变已有版本依赖、确认和采用机制。试拍关系图是现有领域数据的展示投影，详细编辑与执行继续复用业务组件。

**技术栈：** React 18、TypeScript、Ant Design、React Router、OpenAPI generated client；FastAPI、Pydantic、SQLAlchemy；Node.js 行为测试、现有隔离浏览器脚本、pytest。

## 任务速览

| 用户问题 | 设计决策 | 对应任务 | 核心验收 |
| --- | --- | --- | --- |
| 到工作台层级过多 | 章节内直接展示场次；详情按需打开，主操作直达工作阶段 | T1、T2、T4 | 从章节场次行一次操作进入工作台；返回恢复章节、筛选及滚动位置 |
| 场次列表、任务与历史混杂 | 主列表、原文划场、活动记录、章节组合各自独立入口 | T3 | 日常浏览无需穿过任务历史；编辑名称或原文范围后留在章节 |
| 导演设计切换导致结构变化 | 分镜、清单、关系图使用固定工具栏和详情区域 | T7 | 切换保留范围、筛选、对象及可解释的关联高亮 |
| 设计、计划和剪辑版本关系不清 | 全局“版本与依据”入口，弹窗预览后一次应用工作上下文 | T5、T6 | 计划固定设计明确；剪辑可引用多计划素材；切换不改变采用、不丢编辑 |
| 试拍数据密集、流程难辨 | 当前单元优先的输入—单元—产出关系图，详情就地展开 | T8、T9 | 关键输入、阻塞及下一步清晰；图只表达真实关系，窄屏提供等价排列 |
| 同类问题 | 统一继续工作、深链接、错误恢复和未保存保护 | T4、T5、T9、T10 | 历史链接不偷偷切到最新；重试不重复提交；跨场次不串用上下文 |

**推进顺序：** T0 记录基线 → T1–T4 缩短导航并拆分页面职责 → T5–T6 统一版本上下文 → T7 稳定设计视图 → T8–T9 梳理试拍展示与恢复 → T10 综合验收。各批次完成对应验证后再推进，避免一次替换整套工作台。

**关键取舍：** 抽屉用于轻量详情，完整创作仍保留独立工作台；版本入口统一，但不虚构一个总版本；关系图用于说明输入与产出，不能替代候选审片和剪辑时间线。

## 1. 依据、现状与范围

本计划基于 2026-09-29 工作区代码、运行页面和交互评估。工作区已有未提交的指令生命周期、AI 修订和固定编辑区改动；这些内容属于实施基线，不能被本计划回退、覆盖或当作本轮新成果。

实施前基线事实：

1. 章节页 `ChaptersTab` 跳转到 `ChapterSequencesPage`，再进入 `SequenceWorkspacePage`；后者就是工作台，不存在另一层必须经过的场次详情页。
2. `DashboardTab` 已经有场次直达入口；问题是不同入口行为不一致。
3. `ChapterSequencesPage` 同时展示原文、任务、划场建议、场次列表和章节组合；更新名称、顺序或原文范围后会跳入工作台。
4. 设计、计划、剪辑分别维护选择器，历史抽屉只读。计划固定绑定设计；剪辑按项引用 Take 或设计预演，可以使用不同计划的素材。
5. 设计页采用“镜头／关系”及条件出现的“分镜／清单”两层切换；部分工具和说明随视图增减。
6. 试拍准备重复展示动作、版本依据和说明文字；指令修改与复检已经有固定主区，需继续保留。

### 1.1 本轮包含

- 章节与场次联动、场次详情抽屉、业务阶段直达、同章场次切换和返回恢复。
- 章节原文／划场、活动记录、章节组合与主列表的职责分离。
- 章节场次轻量汇总接口及 generated client 同步。
- 统一版本入口、合法关联选择、未保存保护和历史浏览边界。
- 导演设计固定工具栏与分镜／清单／关系图的选择联动。
- 单元试拍输入—单元—产出关系图、就地详情、状态分层及错误恢复入口。
- 项目“继续工作”、轻量编辑强制跳转等同类问题。

### 1.2 本轮不包含

- 整个工作台移入章节抽屉；全站导航重建；改变项目资产与风格管理职责。
- 通用节点编辑器、任意拖线、用户编排执行流程、新图数据库或全新图形库。
- 合并设计、计划、剪辑为一个业务版本；修改历史引用；自动采用候选或自动拍摄。
- 新增聊天系统、多人协同、跨设备上下文同步、专业多轨剪辑。
- 改写已完成计划的历史验收、修改固化 release note、处理与本轮无关的旧代码。
- 将概念示意当成可直接移植的生产实现。此前示意仅做过脚本语法检查，尚未完成浏览器视觉验收。

## 2. 交互与业务约定

### 2.1 入口与路由

章节主入口统一为：

```text
/projects/:projectId?tab=chapters&chapter=:chapterId
```

- 左侧选择章节；右侧是当前章节的场次列表。首次进入恢复有效的章节记忆，没有记忆时显示按顺序排列的第一章。
- 场次行包含标题、简短摘要、可核实的进展、需要处理的事项与一个主操作；“详情”单独打开抽屉。
- “继续设计／继续试拍／审片”直接进入现有场次路由，并携带对应 `view`。浏览操作不提交生成或确认请求。
- 保留 `/projects/:projectId/chapters/:chapterId/sequences/:sequenceId` 及原有版本、对象、任务定位参数。
- 原章节场次列表路由保留为指向统一章节页的导航入口，保留章节和可映射的面板定位；不复制第二套列表组件。
- 工作台提供可搜索的同章场次切换器及上一场／下一场。跨场切换先处理未保存编辑，不能继承上一场的单元、指令或剪辑身份。
- 章节选择与打开场次写入正常导航历史；筛选、面板、滚动恢复不制造大量后退记录。

### 2.2 信息分区

| 内容 | 所在位置 | 默认行为 |
| --- | --- | --- |
| 场次列表、快捷操作 | 章节主区 | 始终作为主内容 |
| 原文、人工划场、AI 划场建议 | 原文与划场面板 | 按需加载和打开；原文变化时提供明确核对入口 |
| 场次摘要、原文范围、名称与顺序 | 场次详情抽屉 | 保存后留在章节页；另设“保存并打开工作台” |
| 章节分析进度、待查看结果 | 触发操作附近的摘要 | 可直接回到对应建议；不铺开所有任务记录 |
| 任务历史 | 章节活动／本场任务记录 | 按需查看；全局任务中心继续只承担通用状态和业务回跳 |
| 章节组合 | 章节组合面板 | 仅消费已确认粗剪；真实媒体、预演缺口、声音状态分别显示 |
| 技术身份、原始 JSON、完整来源映射 | 对象的技术详情 | 默认收起，不参与日常主操作路径 |

失败记录不能仅因时间久而隐藏。只有存在同一业务对象与输入的明确后续处理证据时，才移入历史；无法确认是否已解决的失败保留“需核对”入口，不新增未经验证的“已解决”业务状态。

### 2.3 版本控制

顶栏统一入口表达：`设计 02 → 计划 04 ｜ 剪辑 03 · 草稿`。它表示当前查看或编辑的对象，不代表实际采用。

| 用户操作 | 必须保持的行为 |
| --- | --- |
| 打开弹窗、预览或比较历史 | 不改变编辑基线、运行任务和采用指针 |
| 选择生产计划 | 在待切换摘要中同步显示其固定设计；点击“切换工作上下文”后一起生效 |
| 选择另一设计 | 只展示属于该设计的计划；清除不匹配的待选计划，允许“尚无计划” |
| 选择草稿设计 | 可查看或编辑；不能以其作为正式生产计划的已确认依据 |
| 切换计划 | 单元按新计划身份恢复；指令与检查仅恢复属于该计划和单元的有效记录 |
| 切换设计或计划 | 剪辑版本、已有片段、Take 固定引用和当前采用不改变 |
| 切换剪辑 | 只切换剪辑查看或编辑基线；不隐式切换设计、计划或当前采用 |
| 切换前有未保存修改或请求尚未结束 | 复用 `WorkspaceDrafts` 的保存／放弃／取消与写入保护 |
| 固定版本不存在、读取失败或 URL 指定了冲突组合 | 明确展示不可用对象并提供修正入口，不降级为“最新版本”继续执行 |

对已有合法浏览记忆允许恢复，不要求用户重复选择。多个历史计划不能按“最新”自动拼成执行依据。无共同绑定关系的历史设计与计划可继续单独查看，但顶部必须表达“计划依据另一设计”，修正为一致上下文前不把两者显示成一条连续依据链。

弹窗内复用现有历史比较能力；版本选择、派生草稿和确认采用是不同操作。指令、检查版本仍在单元内部管理，不加入全局多级选择器。

### 2.4 导演设计与试拍展示

- 导演设计统一为 `范围｜分镜／清单／关系图｜搜索｜问题筛选｜视图设置`。三种视图共用范围、选择与筛选；工具栏、左侧导航、右侧详情保持稳定。
- 分镜和清单改变表现方式；关系图展示同一范围的相关对象。共享人物等对象在另一视图没有直接节点时，保留详情并高亮关联镜头，不伪造一个新选择。
- 原有全场关系总览与节拍内详细关系继续保留，只调整入口与布局。
- 试拍准备使用自动排列的关系图：镜头范围／参考／前段落幅 → 单元 → 指令与检查 → 候选。
- 默认聚焦当前单元；“全场关系”显示本计划单元间的真实依赖，历史计划来源作为外部引用显示。
- 选中输入或单元节点在固定详情区编辑。进入指令与检查时继续使用固定编辑主区和检查侧栏，不把修订流程搬回抽屉。
- 空节点明确显示“未配置”或“可选”；只有真实依赖绘制连接。计划顺序不等于镜头叙事顺序，不按列表相邻自动连接。
- 运行状态贴近相关操作；首屏突出主要问题和一个主操作。正常解释、已通过检查和技术备注按需展开。

GET /api/v1/studio/projects/{project_id}/directing/chapters/{chapter_id}/overview

`ChapterOverview` 返回 `chapter_id`、`title`、`source_version` 和按 `position` 排序的 `sequences`。每个 `SequenceOverview` 包含：

| 字段 | 语义 |
| --- | --- |

| `design_count`、`confirmed_design_count` | 全场设计数量及已确认数量 |
| `plan_count`、`confirmed_plan_count` | 全场生产计划数量及已确认数量 |
| `take_count`、`unreviewed_take_count` | 全场候选与未审片候选数；不代表当前计划产出或实际覆盖 |
| `active_cut_revision_id` | 服务端当前采用指针；无采用时为 null，读取错误不能伪装为 null |
