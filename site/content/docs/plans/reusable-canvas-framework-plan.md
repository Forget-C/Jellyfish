## 1. 目标与范围

从现有设计关系图、生产准备图和指令关联图中提取共同能力，形成可复用的画布框架与交互标准。在此基础上，围绕同一次生成建立由粗到细、能够跨层追溯的完整表达，并支持针对指令的局部优化。以现有业务接入验证复用，不为尚未确定的功能预先建设通用流程引擎。

本轮成功标准：

1. 公共框架提供呈现与浏览能力，不依赖项目、场次、设计、计划、审稿或任务接口。
2. 节点类型、内容、能力与状态分别表达；同一节点可展示内容并提供适用操作，不按展示与操作机械拆分类型。
3. 节点、连线、选择、详情、聚焦、展开、下钻及返回使用一致语义；布局不同不改变语义。
4. 现有业务继续拥有数据、权限、版本及写入规则，公共画布不产生第二份业务事实。
5. 完成现有图的渐进接入，保持草稿、固定输入、只读历史、键盘及窄屏行为，并通过受影响回归。
6. 设计、生产、指令与细节逐层覆盖同一次生成的相关信息；共享和交叉引用保留真实身份，不强制整理成树，也不混同实际媒体覆盖。
7. 完整指令图表达执行要求之间的关系，全部正文和固定输入可查；背景、执行、未表达依据与未知关系分别标识。
8. 用户可对指令或要求组提出调整，核对真实差异及关联影响，明确采用后形成新版本并复检；不自动扩大修改范围、拍摄或采用素材。

快捷生成暂不纳入本方案，不设计其入口、节点类型流转、存储或执行链路。本方案也不包含自由拖线、通用流程引擎、整篇模型原文任意编辑、自动循环优化、新增剪辑 graph 或自动拍摄。完整指令图纳入后续实施步骤，基础框架迁移与业务能力扩展分阶段验证。

## 3. 框架与业务职责

### 概念边界

- **画布**负责节点与关系的呈现、布局及浏览交互。
- **Graph**定义对象身份和关系语义，由业务数据投影得到。
- **执行流程**决定业务输入、授权、任务提交及产出登记，由业务模块负责。

画布上的关系不自动形成执行顺序，节点位置也不表示真实空间、动作时间或输入顺序。

### 公共框架

| 职责 | 范围 |
| --- | --- |
| 视口与布局 | 平移、缩放、适应内容、布局移动；支持现有坐标画布与列式内容的不同布局 |
| 节点外框 | 标题、类型标识、内容、状态、动作区域、选择及关联高亮 |
| 关系呈现 | 端点定位、曲线、方向、标签、命中区域、选中与关系说明入口 |
| 浏览操作 | 选择、聚焦、展开、范围路径与返回；使用调用方提供的对象和范围 |
| 状态与可访问性 | 浏览状态校验、恢复、键盘操作、焦点恢复及窄屏的文字关系表达 |

公共节点通过内容与动作区域接入文字、媒体和业务控件，避免为每个业务复制外框。业务详情继续使用既有 Inspector、modal 或 Drawer；画布不另建一套嵌套侧栏。

公共代码放在前端共享组件范围，建议以 `front/src/components/canvas/` 承接。上述职责不要求逐项创建独立组件；先提取实际重复的节点、连线和视口逻辑，再按维护需要拆分。列式图只复用适用能力，不强制启用平移、缩放或节点拖动。

### 业务接入

调用方负责：

- 从真实对象构造节点、连线及布局，提供名称、状态、来源和合法操作。
- 解释范围、字段归属、可编辑性、版本、固定快照、缺失及并发变化。
- 执行详情打开、修改草稿、保存、确认、编译、检查、生成、审片及采用。
- 在异步操作返回时核对原始上下文，避免迟到结果写入其他对象。

公共层接收不包含领域含义的 `contextKey` 及视图数据，不要求存在 `projectId`、`sequenceId`。会话存储和业务草稿保护继续由调用方接入，公共层不直接调用 generated client，也不解释领域字段路径。

## 4. 节点与类型标准

### 最小呈现信息

公共节点仅要求当前上下文内唯一的身份、类型标识、可读名称及呈现内容；状态、动作和展开内容按现有需要提供。真实对象引用由业务层保留，不创建覆盖所有业务字段的新 DTO。

节点身份与显示名称分开。跨版本、计划、单元或指令的同名对象不得合并；调用方用精确对象身份生成稳定节点 ID。界面添加入口、汇总节点与真实对象区分，不作为虚构对象保存。

### 类型、内容、能力与状态

| 维度 | 作用 | 规则 |
| --- | --- | --- |
| 类型 | 表达节点所属类别 | 设计中的人物、事件、镜头等类型由该场景定义；公共层不固定为文本、图片等有限枚举 |
| 内容 | 展示文字、图片、视频、声音及摘要 | 由内容区域承载；媒体类型不能代替全部业务类型 |
| 能力 | 表达可查看、展开、编辑或执行的操作 | 同一节点可同时展示已有内容并提供适用操作；由场景决定 |
| 状态 | 表达读取、错误、只读或具体业务事实 | 通用呈现状态与草稿、确认、准备度、检查、任务、采用等业务状态分别标记 |

例如，准备图中的参考节点可在同一节点中预览媒体并提供添加、更换或查看来源的入口；类型不随当前展示或操作状态改变。公共框架仅承载这些区域，不拥有输入文件、业务配置或任务结果。

### 下钻与新增对象

- **下钻子项**来自已有对象的归属或明确关系，用于查看更小范围。
- **可新增对象及操作**由具体场景提供，沿用其真实类型、权限及校验。
- 两者不共用一个隐含树结构；共享对象可出现在多个范围，始终保持同一真实身份。
- 类型规则应能说明允许类型和不允许的原因，公共画布不内置具体业务枚举。
- 可新增某类型不等于任意连线都有效。具体关系、输入用途、数量、媒体与能力校验由场景负责，最终提交仍经过业务校验。

本轮复用现有合法对象入口，不实现尚未使用的节点插件注册或端口系统。

## 5. 关系与视觉标准

1. 连线具有稳定身份、源与目标、明确关系类型及可读标签。关系方向按该类型定义，不把全部引用画成时间或因果关系。
2. **实线表示直接且可核实的关系；虚线表示经中间对象投影的间接关系。** 间接关系提供真实路径，不能直接解除汇总边。拟修改、过期、问题严重程度使用状态标识，不占用虚线含义。
3. 检查问题涉及、调整目标及候选变化等关系，按实际字段、范围和冻结来源核对后确定直接或间接，不能只依据旧 `kind` 机械转换线型。
4. 未知、读取失败和引用缺失分别表达；不按名称、节点邻接或自然语言提及猜测关系。自动提取的内容仍服从业务归属、状态及确认规则。
5. 节点类型、业务状态和交互状态分别提供样式标识。类型使用稳定图标、文字和适量底色；选中、关联高亮、缺失、只读、待核对不能只靠颜色判断。
6. 节点外观集中维护：8px 圆角、8px 内边距、14px／20px 标题、12px 类型标识；选中使用 2px 蓝色轮廓，缺失使用虚线边框并保留文字，过期单独降色。业务类型统一映射图形、文字与色调，公共组件只接受通用色调。同类对象在各投影中保持相同外观；允许坐标、分列和自然高度等不同布局与内容密度。线条与箭头共用色值，选中覆盖关系色调，直接／间接线型语义保持独立。
7. 节点摘要省略时保留完整内容入口。缩略图对应真实文件；加载失败仍保留对象身份及重试或处理说明。

## 6. 交互与浏览状态标准

| 操作 | 统一语义 |
| --- | --- |
| 点击节点主体 | 选择对象并展示其详情；不改变修改范围，不保存、生成或采用 |
| 点击节点中的明确动作 | 按动作名称打开编辑、添加、定位或执行入口；权限由业务层校验 |
| 点击连线 | 说明关系、来源及实际拥有引用的对象；修改通过明确的合法入口完成 |
| 聚焦 | 临时查看对象及相关关系；可返回之前的视口与筛选，不切换业务版本 |
| 展开／收起 | 改变信息密度，不新增、删除或确认业务对象 |
| 进入范围／返回 | 改变浏览范围，恢复有效选择与位置；跨业务上下文时沿用草稿保护 |
| 切换观察视角 | 围绕同一对象与版本查看另一投影，不自动选择最新依据 |
| 拖动节点 | 调整布局；不重排覆盖、参考或剪辑条目，不建立或解除引用 |

坐标画布统一平移、缩放、适应内容与布局移动操作。固定列布局保留自然排布；移动端以同一对象和关系的数据提供可读卡片及文字关系，不要求用户必须拖拽或悬停。

浏览状态包含视口、选择、聚焦、展开与布局位置，按调用方的精确上下文隔离。恢复前校验身份、数值和范围；失效选择明确处理，不替换成同名或最新对象。轮询更新事实但不抢焦点、不重置布局，也不覆盖编辑草稿。

只读视图允许浏览、预览和来源定位，不提供业务写入。键盘能够选择对象、查看关系、打开详情及关闭返回；拖动布局保留按钮或键盘替代方式。关闭详情恢复有效触发焦点。

## 7. Graph 的分层覆盖关系与功能边界

### 7.1 同一次生成的上下文

本方案中的“本次生成完整表达”，指用户明确选择的一份固定指令及其绑定的计划版本、单元、设计、参考和参数。它表达生成规格，不证明模型实际遵循，也不等于某个 Take 已被采用。

尚未编译或未选定指令时，只展示设计或准备上下文，并说明尚无固定指令；不拼接各类最新记录伪造完整表达。检查、修订候选和任务是附加上下文，按各自来源核对，不改变固定指令身份。

### 7.2 由粗到细的覆盖层次

| 层次 | 回答的问题 | 内容 | 与下一层的关系 |
| --- | --- | --- | --- |
| 设计层 | 本次生成要实现什么叙事意图？ | 相关节拍、事件、镜头、人物物件、空间及不可变事实 | 按精确设计版本映射到计划覆盖；场次中其余内容只作为可展开背景 |
| 生产层 | 本次生成哪部分，使用什么输入？ | 生产计划、单元、动作范围、参考、模型参数及实际落幅依赖 | 按固定计划与单元映射到编译指令及其输入，不把准备草稿当固定输入 |
| 指令层 | 各项要求如何共同成立？ | 动作、摄影、声音、时序、空间、约束与验收要求之间的关系 | 要求或要求组定位到精确正文、固定字段和参考 |
| 细节层 | 某项要求具体如何表达？ | 原文、条件、数值、单位、状态、依据、检查及候选差异 | 提供核对与合法调整入口，不创建第二份可编辑正文 |

各层综合构成本次生成的完整表达，但不要求每层复制全部信息，也不要求同屏展开所有节点。“覆盖”在本节指信息覆盖，不改变计划覆盖、实际媒体覆盖或剪辑采用的既有含义。

具体定义为：同一固定生成上下文提供一份事实来源，各层提供不同粒度的投影；各投影可访问的信息合起来覆盖完整正文、固定输入及相关依据，投影之间通过明确映射追溯。“完整”包含对未知、缺失和未映射内容的如实保留，不要求把全部自然语言解析成关系边。画布负责承载这些投影，不能以画布布局替代业务关系，也不要求每一层单独创建一个画布实例。

覆盖映射允许多对多：一个设计镜头可对应多个生产单元，一个单元可覆盖多个镜头，一项共享要求可关联多条指令。同一真实对象在不同局部范围内出现时保持身份；按生成范围或指令出现位置区分具体出现项，不能按同名或画布位置合并。

覆盖关系包含两种不同映射，实施时必须分别提供：

| 映射 | 示例 | 判定标准 |
| --- | --- | --- |
| 范围细化 | 设计镜头 → 单元覆盖项 → 动作要求 → 固定正文出现位置 | 下一层说明上层哪部分内容在本次生成中具体落实；不要求对象数量一一对应 |
| 横向关联 | 触发事件 → 动作要求；空间锚点 → 调度要求；验收条件 → 可见结果 | 说明要求之间如何共同成立；沿用明确关系及来源，不作为父子包含处理 |

因此，“从粗到细”描述阅读路径，不意味着所有 graph 都能嵌套成一棵树。设计、生产与指令是不同粒度的投影；依据、检查与修订则是围绕同一要求的辅助视角。后者不能被当作更细一级的执行内容，也不能将检查建议计入当前固定指令。

对象需要区分三种身份：真实对象身份用于跨图引用；覆盖或正文出现项身份用于区分同一对象在不同范围、位置的出现；当前选中项属于浏览状态。返回上层时按真实对象追溯，同时保留出现项位置，不因选中变化建立新的业务对象。

局部范围必须由明确覆盖项确定。一个镜头被拆为两个动作段时，进入其中一段不能因为共享镜头身份而带入另一段的全部动作、事件或表演要求。跨段关系可以展开为关联背景，并保留返回位置；共享人物、空间和不可变事实仍可访问，但不据此扩大执行范围或调整范围。

### 7.3 各类图的职责与修改归属

| 场景／图 | 核心职责 | 读取依据与修改边界 |
| --- | --- | --- |
| 导演设计关系图 | 解释叙事、事件、调度、镜头和验收要求；在本次生成上下文中可定位相关设计范围 | 读取所选设计；人工修改经设计草稿、保存与确认流程，保留全场紧凑概览 |
| 生产计划总览 | 解释单元分配、覆盖摘要与明确依赖 | 读取所选计划，默认只读；进入单元或重组沿用草稿保护，不展开全部指令细节 |
| 单元准备图 | 解释当前单元范围、实际输入、参数和依赖 | 编辑当前计划草稿；不直接改固定设计或已编译指令 |
| 完整指令图 | 解释本次要求之间的关系，提供完整正文和固定输入的展示去向 | 读取固定指令及其快照；调整经第 9 节流程产生新版本，不原地改写 |
| 依据、检查与修订视角 | 围绕选中要求解释来源、问题、修改要求及候选差异 | 作为同一指令工作区的辅助视角或叠加信息，核对精确来源，不成为另一份指令正文 |
| 剪辑验收 | 检查实际素材、可用区间、采用、接缝与返工 | 本轮不新增剪辑 graph；播放器和时间线保持主体，不将指令要求或检查通过当作实际已完成 |

三大主 Tab 继续组织工作阶段，试拍的准备、指令与检查、试拍与候选继续组织工作步骤。Graph 的层次、范围和观察视角属于阶段内部；不把各类图增加成同级主 Tab，也不替代清单、结构化阅读、模型原文、播放器或时间线。

| 主 Tab | 与分层表达的关系 | 阶段交接 |
| --- | --- | --- |
| 导演设计 | 维护设计层的权威内容；展示全场及相关局部关系 | 确认设计后交给生产计划，不把尚未确认的改动注入固定指令 |
| 单元试拍 | 以生产层组织生成范围，向下查看指令层和细节层，向上追溯固定设计 | 明确采用修订后得到新指令；拍摄成功登记 Take，交给素材审查 |
| 剪辑验收 | 对照要求检查真实媒体及采用结果，可回溯上述各层 | 局部返工明确回到设计、准备或指令修改入口；媒体结论不改写原生成规格 |

### 7.4 下钻、展开与跨层追溯

- **进入范围**缩小关注范围，例如单元进入某个覆盖镜头或动作段；返回恢复原范围、选择、筛选和视口。
- **展开关联**查看当前范围的事件、对象、位置和验收要求，不隐式切换工作版本或编辑基线。
- **切换视角**围绕同一固定上下文查看输入、执行内容、依据、检查或修订，不改变所选要求及其真实身份。
- **跨层定位**明确展示源与目标版本；查看固定来源不加载最新设计，进入当前草稿编辑时说明上下文变化并经过草稿保护。
- 从上层可定位到细节，细节可追溯其服务的范围及关联要求。缺失映射明确提示，不能默认载入另一份版本。

### 7.5 跨图操作的归属规则

同一要求可从多个图进入，但只保留一个合法修改归属。关系说明必须能够回答“关系来自哪里、哪一端拥有该引用、允许在哪里修改”。共享画布仅派发明确动作，业务层核对上下文和权限后打开既有入口。

| 浏览或操作 | 负责模块 | 对其他层的处理 |
| --- | --- | --- |
| 选择、展开、切换局部范围、移动节点 | 当前视图与公共画布 | 只传递对象、出现项及固定上下文，不同步改写其他图的业务数据 |
| 修改设计要求或解除设计引用 | 导演设计的草稿与确认流程 | 已编译指令继续显示原固定依据；新设计经计划衔接和重新编译后才进入新指令 |
| 更换参考、模型或计划覆盖 | 单元准备及计划流程 | 提示当前固定指令与准备状态的区别，不用草稿覆盖历史输入 |
| 调整当前指令要求 | 指令局部修订流程 | 修改范围经显式选择建立；相关设计、输入与验收作为核对依据，不自动全部纳入修改 |
| 判断素材是否达到要求 | 剪辑与验收流程 | 记录真实 Take、区间和审查结论，不反向把要求标记为实际已覆盖 |

跨层浏览可以保持原工作阶段；需要切换阶段编辑时，明确目标对象及版本并沿用离开保护。不得通过在 graph 详情内增加另一套保存、确认或采用逻辑绕过原流程。

## 8. 完整指令 Graph 的表达规格

### 8.1 以执行要求为中心

完整指令图以本次执行内容为主线。节点以“可理解、可定位、可提出调整的一项要求或要求组”为基本粒度，是否允许实际调整仍由字段归属和权限决定。连续长说明可保留在要求组中，不逐句机械建节点。

六岗作为来源、职责标签或核对筛选，不默认按六岗拆成六个互不关联的分支。人物、物件、事件和空间锚点作为关联对象；指令要求与业务实体分别表达，不为每段正文复制实体。

| 内容分组 | 展示内容 | 默认与下钻规则 |
| --- | --- | --- |
| 本次执行 | 覆盖镜头、动作段、可见结果及相关摄影、声音要求 | 主体展开；按单元内真实出现顺序组织，不借画布位置表达时序 |
| 相关对象与条件 | 人物、物件、触发事件、空间锚点 | 默认展示直接相关对象，间接路径可展开；保留范围未知与明确无对象的区别 |
| 验收与限制 | 必须观察到的结果、禁止项、连续性要求 | 关键要求可见，连接其明确作用对象；要求存在不代表检查通过或视频已做到 |
| 共享背景与约束 | 人物前提、空间依据、不可变事实、项目风格及场次背景 | 稳定分组；进入局部后仍可发现并访问，不给全部节点机械连线 |
| 固定输入 | 模型、全部固定参数、参考文件、用途、顺序、主体绑定及落幅来源 | 摘要可见，完整信息可展开；过滤和下钻不能遗漏本单元实际输入 |
| 表达与映射核对 | 精确正文、编译来源、未表达依据、未可靠映射内容 | 原文始终可达；无法归类的内容完整保留，不据此伪造精准编辑 |

### 8.2 指令间的关系

| 关系 | 表达含义 | 核对要求 |
| --- | --- | --- |
| 触发 | 某事件或条件触发动作、调度或摄影变化 | 按真实触发字段及固定要求判断，普通事件引用不自动升级为触发 |
| 先后 | 明确动作顺序或前置条件 | 保留条件、数值和单位；不按正文邻接、节点左右或列表次序猜测 |
| 同步／期间 | 要求在另一动作发生期间成立 | 核对作用范围和持续条件，不将“同一镜头”视为同步证据 |
| 约束 | 不可变事实、限制或风格约束具体要求 | 有明确作用对象才连具体边；范围不明时保留全局说明 |
| 表现 | 摄影、声音等要求使关键动作或信息可被观察 | 有明确要求或关联依据；共享参与对象不足以证明表现关系 |
| 验收 | 可观察条件用于核对具体要求或结果 | 计划验收条件、指令检查和实际素材结论分别表达 |
| 连续性 | 前后状态及实际落幅对本次要求形成连续性约束 | 区分设计状态与真实媒体依据，保留历史版本、片段和参考身份 |
| 参与／位置／输入引用 | 实体参与、调度位置或参考绑定解释执行内容 | 沿用真实引用，不把这些关系自动当作时序或执行依赖 |

已有固定结构能够确定关系时，使用其真实引用和字段语义。只有自然语言描述、缺乏可靠关系或映射时，保留原文和待核对说明；不得在展示时额外调用模型猜测连线。确需补充契约的缺口在 C1/C4 核实并按项目规则实现，不另存一份与设计、计划脱节的 graph 事实。

冲突、缺失与不一致作为有来源的检查信息覆盖到相关要求，不能无依据地标成事实边。修改预览可以显示真实新增、移除或受影响关系，但必须基于候选的实际字段与编译结果。

### 8.3 三种表达状态与完整性

“设计中存在”“与本次有关”“已在本次指令表达”分别标识。已表达还应区分执行正文、背景说明及参考表达；未表达依据单独可查，不混入当前指令。`fact`、`proposal`、未知、未填写、不适用和明确没有保持原义。

正文完整性与关系覆盖分别验收：

- **正文完整性**：每段固定正文都有展示去向及原文位置；按原始位置恢复可得到相同正文。标题、重复片段、条件、否定、例外、数值及单位不能丢失。
- **固定输入完整性**：全部参考及参数有明确入口；媒体按真实类型预览，不借最新资产、准备草稿或其他单元补齐。
- **关系覆盖**：已能可靠解释的明确关系均可查，间接关系有真实路径。关系缺口显示待核对，不以正文完整为由宣称全部语义已解析。
- **范围完整性**：下钻后仍能发现共享约束、单元级阻碍、范围外关联与实际修改影响；筛选无结果与本次无内容分别表达。
- **历史与异常**：旧格式、无映射、引用缺失或读取失败保留真实内容和核对路径，不自动修复历史数据或创造精确编辑范围。

完整表达针对编译指令与绑定输入，不证明供应商实际遵循或素材可用；后续审片仍消费真实媒体。

### 8.4 完整性清单与关系证据

“多个图综合后完整”必须通过逐项核对证明，不能以图的数量或节点看起来齐全判定。以本次固定指令为起点生成核对清单；清单是原始记录的只读投影，不增加一份独立保存的指令事实。

| 核对对象 | 必须可追溯的信息 | 未满足时的表现 |
| --- | --- | --- |
| 每段固定正文 | 原始位置、完整内容、展示入口、关联要求或未映射说明 | 保留原文并显示映射缺口；重复片段分别定位，不能去重后丢失位置 |
| 每项相关设计要求 | 固定设计身份、字段、原值与状态、涉及范围、表达去向 | 区分未表达、只作背景、引用表达和无法核实；不能一律标为已表达 |
| 每个固定输入 | 所属单元、参数原值，或文件、用途、顺序、绑定及来源 | 缺失身份仍保留记录并提示；空值、零、false 和未知不可混同 |
| 每条可核实关系 | 两端对象或要求、关系类型、方向、来源字段；间接边另有完整中间路径 | 来源不足时显示文本说明或缺口，不生成无证据连线 |
| 每个显示节点 | 真实对象或要求身份、所属固定上下文、出现范围 | 汇总及占位节点明确标识，不与实体合并或计为新增要求 |

正文可能对应多项要求，一项要求也可能对应多处正文或参考。关系在对象组层面有依据、在具体要求层面缺乏映射时，只展示对象组关系及其依据；不能将该边复制到组内所有要求，制造更精确的假象。

完整性结果分别报告正文、固定输入、可靠关系和映射缺口，不合并成一个容易误解的“完整率”。仅文本描述的关系仍属于可阅读内容；只有落实明确引用并经过对应业务流程后，才能作为可靠关系参与自动影响分析。

### 8.5 一条要求的最小核对单元

以“事件 E 发生后，人物 A 移动到空间锚点 P，摄影保持人物可见，验收条件 C 核对落位”为例，表达应能分别定位动作要求、人物、事件、锚点、摄影要求和验收条件。每条关系仅在固定来源确有对应引用时成立；若“发生后”只有正文说明，就保留这段条件并标明时序尚未结构化，不将普通事件引用升级为触发。

要求详情至少能核对：要求身份和所属固定上下文、覆盖出现项、原值与状态、全部正文出现位置、固定来源、直接或间接关系证据、表达状态，以及合法修改入口。一个要求出现两次时展示两个位置；同一人物被多项要求引用时保留一个真实身份及多个出现项。没有合法编辑映射的要求仍完整可读，不能因不可调整而被排除出完整表达。

## 9. 指令局部优化流程

### 9.1 操作状态与修改归属

查看、选中和调整范围分别保存。点击节点或问题仅浏览或定位；只有“调整此要求／要求组”等明确动作建立调整范围。默认沿用现有局部范围和可编辑字段校验，不新增跨版本任意组装或多方案并行。

| 调整内容 | 处理路径 |
| --- | --- |
| 当前指令允许调整的动作、摄影或要求组 | 通过固定映射建立明确字段范围，进入局部修订及复检 |
| 模型、参考、落幅绑定或不在局部白名单内的单元参数 | 定位拍摄准备，修改合法计划草稿后重新编译；已支持局部修改的参数继续沿用既有能力 |
| 全场不可变事实、共享空间或其他共享设计内容 | 定位设计对象，说明受影响范围，经保存、确认及计划衔接更新；不在局部修订中豁免限制 |
| 无可靠字段映射的正文 | 保留阅读，提供已有整体修订或固定依据核对入口，不伪造精确局部编辑 |
| 指令有效而视频表现有误 | 进入素材审查、重拍或剪辑处理，不因样片偏差自动改设计或宣称计划覆盖 |

### 9.2 从要求到新版本

| 步骤 | 用户与系统行为 | 必须保留的边界 |
| --- | --- | --- |
| 1. 选择调整对象 | 展示要求原文、所属镜头／动作段及精确版本，明确建立局部范围 | 关联高亮不扩大可编辑范围；选择共享对象不自动授权全场修改 |
| 2. 查看关联影响 | 展示触发、动作、摄影、验收及共享约束的直接／间接关联 | “可能相关”“允许修改”“实际变化”分别表达；不能承诺修改一个节点只影响一个节点 |
| 3. 提出修改 | 复用人工字段编辑、自然语言要求及已有检查方向 | 人工“预览修改”不调用 AI；自然语言“生成修改方案”需明确操作；输入改变使旧候选失效 |
| 4. 生成与校验 | 以固定指令、来源、字段范围和修改要求提交，核对白名单、值与引用 | 范围外编辑、检查方向冲突、共享或不可变要求不能静默扩大或跳过；不合适时保留输入并给出合法路径 |
| 5. 核对预览 | 展示真实字段 before/after、完整编译预览、可核实的关系变化及全部实际影响 | 当前版本与拟修改分别显示；多处正文命中全部可查，无法精确定位时提供真实字段差异和完整预览 |
| 6. 明确采用 | 调用现有业务流程保存或派生所需版本，并编译新固定指令 | 不原地改已确认版本；服务端重新核对输入与候选身份，不把看过预览当采用，不部分勾选采用 |
| 7. 复检与继续 | 核对新指令的检查状态和结论；失败时按真实已保存结果提供恢复 | 旧检查不得用于新指令；复检不自动拍摄，生成成功也不自动采用素材 |

关联影响在候选前用于解释修改背景，候选后以实际变化为准。非目标字段若发生真实变化，必须全部显示并按现有业务范围规则拒绝或要求用户明确重新选择；不能静默隐藏或自动扩大授权。

### 9.3 失败、失效与只读

- 切换设计、计划、单元、指令、检查来源或调整范围后，旧请求、候选和迟到结果不能用于新上下文。
- 保存、采用、编译或复检失败保留输入并显示真实进度；已产生的新版本不能被界面假装回滚，恢复沿用既有核实流程，不重复提交无法确认是否成功的操作。
- 未保存编辑继续受到保存／放弃／取消保护；任务轮询不抢焦点、不覆盖编辑、不自动切换版本。
- 历史指令与只读来源允许阅读、比较和追溯，不创建修改草稿或发业务写入。

### 9.4 关联影响与候选差异的核对方式

局部优化中的“局部”指用户授权修改的字段范围，不保证编译后只改变一处文字。影响预览分为三个集合，分别呈现，不用关联高亮代替差异：

1. **关联背景**：与目标有可靠直接关系或明确间接路径的要求、对象、输入及约束。用于理解上下文，保持只读；文本关系缺口单独提示，不参与确定性传播。
2. **允许修改范围**：用户明确选定且业务校验允许的字段。生成请求绑定此范围及固定基线，关联背景不自动扩入。
3. **候选实际变化**：候选与固定基线的全部字段、正文、输入及可核实关系差异。范围内无变化也如实显示；范围外变化全部暴露并按规则拒绝或回到重新选择范围。

关系差异按真实两端身份、类型及来源核对，分为新增、移除、条件变化及未变化关联。布局位置、节点折叠或筛选导致的显示变化不属于业务差异。只改变要求措辞、未改变引用时，可以提示有关联要求需要复核，但不能把所有关联边标记为已修改。

例如，用户调整“人物在触发事件后移动到指定位置”的动作要求：系统先显示真实触发、位置、摄影归属和验收引用，再建立动作字段范围。若候选还改变空间锚点或不可变事实，应阻止按原局部范围采用并提供设计修改路径；若摄影与验收未变化，则展示为核对背景。采用后新指令独立复检，原版本、原正文及原检查仍可追溯。

### 9.5 可复现的优化验收旅程

验收从同一固定指令开始：上层选择单元覆盖范围 → 进入要求关系 → 查看一项要求的全部正文出现位置及来源 → 明确调整 → 人工或 AI 生成候选 → 核对全部差异与关联 → 明确采用 → 查看新版本与复检结果。每一步记录当前上下文、修改范围、请求和业务写入；浏览步骤的业务写入数必须为零。

同一旅程另验证取消、输入变化、范围切换、候选过期、采用失败、采用成功但复检失败和历史只读。成功采用后的恢复以服务端真实版本为准；不得因后续失败再次采用同一候选或假装旧版本被原地覆盖。

优化是否有效分别核对两个结果：候选是否满足用户提出的修改目标，以及是否仍满足固定背景和业务限制。采用与复检通过只能证明相应版本和检查结果；是否改善实际视频仍需拍摄后审片验证，不以图中关系减少、节点变绿或检查通过替代媒体证据。

5. **C7 按矩阵收口**：逐项关联证据，并核对三大 Tab 的职责、异常恢复、历史只读及四尺寸可用性；剩余缺口保留其真实状态。快捷生成的入口、节点流转和执行编排不作为本轮交付或验收前提。

复核发现，原 C2/C3 验收证明了公共组件与交互复用，但 G02 对视觉一致性的证据不足：导演设计使用类型底色和紧凑外框，指令图仍被独立白卡片、圆角、选中态及连线 CSS 覆盖。此前完成判断未覆盖这一差异。本次补齐公共外观，保留各视图适合的布局，不纳入快捷生成。

实施与验收：

1. 将节点外框、字体、类型色调及选中／缺失／过期状态集中到公共样式；移除冲突的业务样式。设计、生产、完整指令及辅助指令共用业务类型标识映射；验收同类对象的实际渲染结果一致。
2. 统一线条与箭头色值及选中优先级，完整要求关系增加明确的连线选中态；验收键盘打开关系时箭头与线条同色、选中为蓝色 2.5px，虚线仍只表示间接关系。
3. 三类真实工作台页面运行样式断言和原业务回归，检查桌面与 375px 等尺寸截图；核对下钻、详情、返回焦点、草稿和固定版本行为仍成立。类型检查及受影响纯行为回归通过后归档证据。
