# 章节入口与整章划分工作流优化计划

> 状态：待实施。本计划承接[章节信息与原文选区划场优化计划](/docs/plans/chapter-source-selection-and-division-plan/)；前序完成状态与验收记录保留。本文件记录未来方案，不代表当前实现。
>
> 核心约定：手动划分默认编辑本章全部场次组成的方案，保存时校验整章、仅更新实际变化的对象。不将“整章编辑”解释为全部场次失效、全部删除重建或自动迁移已有成果。
>
> 延续用户约束：章节列表仍为主页面，场次管理保持左右分栏；不增加跨章节的待核对数量、粗剪数量及相关列、汇总或逐章请求。

## 1. 现状与评估

基线为 2026-09-29 工作区代码；下表区分已确认事实与本轮设计决定。

| 问题 | 当前事实 | 设计决定 |
| --- | --- | --- |
| 列表主操作没有体现阶段 | 每章始终显示“划分场次”；已有场次仍进入划场视图 | 按是否有原文、是否已有场次切换“填写原文／划分场次／场次管理” |
| 章节组合入口重复 | 表格行、场次管理及划场抽屉工具栏均可进入同一组合面板 | 仅保留章节表格操作列的常驻入口 |
| 抽屉内部出现返回按钮 | “返回场次列表”切换面板，标题栏关闭则退出整个抽屉 | 去掉划场内容区的返回按钮；标题栏关闭始终回到章节表格 |
| AI 与手动展示重点不明确 | 默认手动；切换后主要仍为场次、原文和当前选区三栏 | 普通划场入口默认 AI；AI 以分析/候选结果为主，手动以完整原文和整章边界为主 |
| 单场保存不适合共享边界调整 | 当前接口一次写一场，拒绝与其他场次重叠，不能原子调整两场边界 | 引入整章草稿与整章事务保存，按最终方案校验 |
| 重划可能涉及已有成果 | `Sequence` 有独立身份和版本；设计、Take、采用等关联受外键保护，当前没有退出当前划分的状态 | 定义保留、调整、新增及退出当前划分的规则，保留历史身份与成果，禁止级联删除 |

“有场次”不等于“划分完毕”：当前允许未分配原文。本轮不为按钮文案引入完成率或虚构完成状态。

主要实施位置：`ChaptersTab.tsx`、`ChapterSourcePanel.tsx`、`ChapterSourceSelection.tsx`、`SequenceDetails.tsx`、`chapterNavigation.ts`、`WorkspaceDrafts.tsx` 及相关样式；后端涉及 directing 契约、workspace/store 服务、API、场次模型及必要迁移。

## 2. 范围与成功标准

本轮包含：

- 章节行动态主操作、章节组合单一常驻入口、统一抽屉关闭及关闭后的上下文恢复。
- AI 默认视图及开始/重新分析/继续确认的操作状态；与手动视图保持不同的信息重点。
- 手动整章草稿、原文框选与共享边界调整、最终范围校验、差异预览和一次提交。
- AI 候选采用到同一整章草稿，与已有场次的身份映射及替换影响确认。
- 为新增、拆分、合并和移出当前划分补齐场次身份、历史成果及当前列表/组合的处理规则。
- 服务端全章并发校验、事务回滚、必要接口与迁移、测试和文档同步。

成功标准：

1. 用户能从章节主表直接进入当前合适的操作；未知数量不被当作零场。
2. 章节组合只有一个常驻入口，划场抽屉关闭含义一致，不叠加业务抽屉。
3. 默认进入 AI 视图但不自动分析；未确认候选和手动修改都不写入正式场次。
4. 用户可在完整原文上调整本章多场范围并一次保存，共享边界变化不会被中间状态阻塞。
5. 保存前清楚展示新增、修改、退出及保留的场次；未变化对象不递增版本、不重新标记来源。
6. 已有设计、素材、粗剪及历史引用保持可追溯；变化只作用于真实受影响对象。
7. 并发修改、接口异常或事务中途失败不会留下半份划分，也不会静默覆盖草稿。

本轮不包含跨章节统计、章节正文重写、自动生成或采用、自动搬迁设计/素材到新场次、完整制作版本系统重构、多人协作或跨设备草稿同步。一个场次仍只引用一段连续原文，章节组合仍只消费符合既有确认规则的粗剪。

## 3. 章节入口与抽屉

### 3.1 动态主操作

| 章节数据 | 主按钮 | 目标 |
| --- | --- | --- |
| 已确认无原文 | 填写原文 | 复用章节编辑器 |
| 有原文，可靠场次数为 0 | 划分场次 | 本章 AI 划分视图 |
| 可靠场次数大于 0 | 场次管理 | 场次列表及默认详情 |
| 原文状态或数量尚未可靠读取 | 查看场次 | 读取后展示，不按空章节处理 |

- 异常情况“无原文但有历史场次”仍可通过场次数量查看已有对象，主操作引导修复原文；不能隐藏历史成果。
- 场次数量保留快捷入口：有场次时进入管理，0 场时进入划场，无原文时进入填写引导；与主操作规则一致。
- 场次管理顶部保留“调整划分”，普通打开进入 AI 视图。详情的“在原文中调整范围”表达明确手动意图，可直接进入手动整章草稿并定位该场次，不能退回单场立即保存。
- 新建章节后的下一步遵循同一规则；保存首份划分后刷新本章数量和主按钮。
- 按已有列表字段判断，保留分页、搜索和懒加载，不逐章读取工作台或来源概览来计算按钮。

### 3.2 章节组合唯一入口

- 仅保留章节表格操作列的“章节组合”次要按钮，移除管理/划场抽屉内部重复入口。
- 组合视图使用独立同级抽屉，通过标题栏关闭回到章节表格；无可用粗剪时展示缺口，不伪装成加载失败。
- 既有 `panel=assembly` 深链接仍可定位同一功能；保留链接兼容不等于增加常驻按钮。

### 3.3 统一关闭

- 划场视图移除内容区“返回场次列表”；标题栏 `×` 始终关闭整个抽屉并返回章节表格，不根据入口变成返回上一级。
- 保存成功后留在划场视图，明确显示保存结果；不自动关闭或跳到场次管理。
- 关闭后恢复表格页码、搜索、滚动及触发按钮焦点。再次进入场次管理，恢复有效的最近场次，必要时回退第一场。
- 关闭、Escape、遮罩、后退均经过同一整章草稿保护；写入中禁止重复提交和冲突导航，失败保留输入。
- 窄屏场次管理内部“返回场次列表”属于列表/详情切换，可保留；它与本轮移除的划场内容区返回按钮不是同一用途。
- 清理前序为“划场返回管理面板”专设的状态和回调，只移除被新流程替代的代码。

## 4. AI 与手动的展示及操作

### 4.1 默认 AI 视图

普通划场入口默认 AI，进入本身只读取数据。顶部提供“手动调整划分”按钮；详情范围定位等显式手动入口除外。

AI 视图以操作说明、分析进度和候选场次清单为主体。原文通过候选定位和对照区查看，不默认铺开手动编辑的完整三栏界面。

| 状态 | 主要操作 | 补充行为 |
| --- | --- | --- |
| 没有正式场次，也无可用分析结果 | 开始 AI 分析 | 无原文时禁用并引导填写 |
| 已有正式场次，暂无待确认结果 | 重新 AI 分析 | 说明将产生新建议，现有划分保持生效 |
| 有基于当前原文的未确认结果 | 查看／继续确认分析结果 | 重新分析作为次要操作；不能因场次数为 0 而隐藏已有结果 |
| 分析进行中 | 显示进度 | 禁止重复提交，沿用既有任务取消/失败反馈 |
| 分析失败或结果已过期 | 重试／重新 AI 分析 | 保留旧结果供查看，过期范围不能直接采用 |

- 分析明确由用户点击触发；AI 结果仅是建议，不自动修改正式场次或整章草稿。
- 查看结果时显示候选名称、摘录、原文定位及问题。重复摘录需明确选择位置；找不到原文的候选需手动调整后才可采用。
- “采用到本章草稿”是明确操作。已有手动修改时先展示将被替换的草稿差异，不能用迟到任务结果覆盖用户输入。
- 采用后使用同一份整章草稿进行预览、调整和最终保存；本轮最终流程不再通过旧的逐场创建按钮绕过整章提交。
- 分析结果的原文版本与当前场次集合基线分别校验：原文相同不代表分析期间没有人新增或修改场次。

### 4.2 手动整章视图

进入手动视图即加载当前全部场次组成草稿，不提供默认“只改当前一场”的提交模式。明确提示：**“正在编辑本章划分，保存前将核对全部场次范围，仅更新本次变化。”**

- 布局以完整原文为主体：左侧本章场次，正文显示所有已定位范围与边界，右侧显示当前选区/场次；窄屏保持等价的列表、正文和选区切换。
- 复用现有鼠标框选、键盘/触屏选区、Unicode 与 CRLF 偏移映射；范围标签仅用于展示，不修改原文。
- 点击某场只改变编辑焦点。更改范围、名称、顺序、新增或移出均修改本地整章草稿，不立即写接口。
- 相邻且共用边界的两场，调整共享边界时同步改变两侧范围；仍须让用户看到两场各自增加/减少的原文，不能自动吞并第三场。
- 可以保留暂时未完成的草稿，包括重叠或待定位范围；这些问题必须在提交前解决。未分配原文可保留并明确提示，不虚构“全章划分完成”。
- 原文版本变化后旧偏移不得直接套到新正文；先对照和重新定位。未解决的当前成员范围不能作为有效整章方案提交。
- AI 与手动视图切换保留同一草稿；仅切换展示不保存、不丢输入。放弃整章草稿、采用另一份 AI 方案或关闭时再执行相应保护。
- 主操作为“预览划分变更”→“保存本章划分”，无变化时不发送无效写入。

## 5. 场次身份与影响预览

### 5.1 只处理实际变化

| 变更类型 | 保存规则 | 对既有成果的处理 |
| --- | --- | --- |
| 未变化 | 保留 ID、版本、范围和来源 | 不重新标记，不产生新版本 |
| 仅名称/顺序 | 保留 ID，按现有基本信息更新规则处理版本 | 不重新确认来源，不使原文依据失效 |
| 范围变化或显式重新确认来源 | 保留用户指定的 ID，更新范围和来源 | 旧设计/计划/素材保留；按现有来源机制重新核对相关依据，不自动改写或采用 |
| 新增 | 创建新 ID，记录选定原文 | 不自动继承邻场成果 |
| 退出当前划分 | 明确指定旧 ID，不再作为当前成员 | 保留历史场次及成果，不物理删除或级联删除 |

整章保存不修改章节原文。范围调整后的影响仍应区分来源核对、设计/计划确认、素材和剪辑采用，不能合成“全部重新制作”。

### 5.2 拆分、合并与退出

- 拆分时明确哪一段继续使用原场次 ID，其余段落创建新 ID；合并时明确保留哪个场次身份、哪些旧场次退出当前划分。不得按标题相同或范围相似自动决定身份。
- AI 重划先展示与现有场次的对应关系。精确匹配可作为建议，但改变身份或退出已有场次须由用户在差异预览中明确确认；未确认映射不能提交。
- 本轮需要建立“当前划分成员”和“历史场次”的最小状态区分。字段、索引及迁移在契约任务中定稿；不能仅软删除却仍占用当前序号，也不能绕过既有外键保护。
- 当前列表、数量、默认选择、同章切换、概览和章节组合只消费当前成员。历史场次从场次管理内按需查看，不增加第二个章节组合入口。
- 原有历史深链接保持可读，并说明场次已退出当前划分；既有设计、Take、粗剪、来源和接缝引用保持可追溯，不自动搬到新场次。
- 退出当前划分后禁止新发起依赖该场次的生产写入。已有排队/运行任务、其他当前场次的依赖或采用引用需要在预览和服务端校验中明确处理：不得静默取消、删素材或使任务悬空；无法安全退出时返回具体阻塞项，让用户先处理。
- 已发出的任务结果继续按原身份收取和保留，不能因列表隐藏场次而丢弃。任务状态改变或影响范围扩大后，提交前重新核对，不只检查前端展示过的计数。
- 本轮不提供跨场次成果自动迁移、恢复历史场次为当前成员的独立工作流或完整生产版本重构。

### 5.3 提交前预览

预览展示本章保留、新增、名称/顺序变化、范围变化及退出的场次；范围变化显示前后摘录，拆分/合并显示身份去向及受影响成果。这里的本章变更摘要不属于跨章节统计。

最终确认说明保存将影响哪些场次，原文与未修改对象保持什么状态。失败时保留整章草稿和可处理问题，不只显示通用“保存失败”。

## 6. 服务端整章提交

### 6.1 契约内容

新增章节级划分读取/预览/提交所需契约；能复用现有读取接口的部分继续复用，不新增前端手写 service。路径与 DTO 名称在 T3 定稿，至少表达：

| 数据 | 用途 |
| --- | --- |
| 原文版本 | 保证范围来自用户实际编辑的原文 |
| 编辑开始时的完整当前成员集合与各场版本，或等价的服务端集合版本 | 发现新增、退出、改名、调序及范围变化，不能只比较提交项的版本 |
| 最终有序成员清单 | 包含保留的场次 ID、新增项的稳定请求内身份、名称、范围，以及是否明确重新确认来源 |
| 明确退出清单与拆分/合并对应关系 | 不将漏传场次默认为删除；校验不存在重复身份、跨章对象或未经确认的身份替换 |
| 与本次草稿一致的预览依据 | 确认的影响对应最终提交内容；草稿或服务端相关状态变化后重新预览 |

前端不提交任意改写的摘录作为来源，服务端从原文截取。重复点击只允许一个在途请求；响应丢失时先查询/核对提交结果，不重新生成新增项身份盲目重放。接口需明确定义重试行为并验证不会重复创建。

### 6.2 事务和并发

1. 校验项目与章节归属；锁定章节，读取当前原文及场次集合，比较完整基线。
2. 校验全部当前成员和实际依赖状态，计算真实差异；锁顺序与既有单场写入、任务受理流程一致，避免绕过新规则或死锁。
3. 按最终方案校验非空连续区间、Unicode 边界、范围重叠、身份和顺序；允许相邻边界及显式未分配内容。
4. 在同一事务内完成新建、实际变化的更新、排序和退出。处理中间顺序不能触发章节内唯一约束；未变化对象不做无效更新。
5. 一次性返回当前划分、实际变更摘要及新建身份映射。任何校验或写入失败，全部回滚。

- 共享边界调整按最终两场范围校验，不能先用单场接口保存第一场、再保存第二场。
- 不使用前端循环请求模拟原子保存；测试必须包含第二项或后续写入失败后的完整回滚。
- 既有单场接口如继续用于基本信息编辑，必须参与同样的锁与集合并发规则；所有入口都不能绕过归属、版本或当前成员约束。
- 通过 `DirectingStore` 及其服务层完成场次数据读写；API 层负责收参、鉴权和响应，不承载差异编排。
- 对外契约变化同步后端、OpenAPI 与 generated client；先确认 `127.0.0.1:8000` 加载当前工作区，再运行 `pnpm --dir front run openapi:update`。
- 涉及成员状态与索引变化时提供必要 Alembic 迁移，旧场次默认作为当前成员；迁移不删除旧数据，不新增无关生产状态。

## 7. 实施任务与验证

先完成入口及 AI 展示，再定稿整章契约和身份规则、接入事务与编辑界面。前两个阶段可单独验收，但不能据此宣称整章划分已完成。

| 任务 | 内容与交付 | 验证方式 |
| --- | --- | --- |
| T1 入口与关闭 | 动态主按钮、数量快捷入口、组合唯一入口、去掉划场返回按钮、统一关闭与焦点恢复 | 列表状态表全部分支；唯一入口、旧深链接；关闭/Escape/遮罩/后退及草稿保护；零场到有场切换 |
