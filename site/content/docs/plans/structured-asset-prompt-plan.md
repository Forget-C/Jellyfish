# 资产结构化与图片提示词改造方案

> 状态：本轮实现与验证已完成；后续视觉质量对比单独评估。更新日期：2026-09-11。
> 实施范围已按用户要求调整：没有历史兼容负担，不回填旧描述；当前规则见[资产图片管理](/docs/architecture/asset-image-management/)。

## 1. 目标与范围

将演员、场景、道具、服装从以单段 `description` 为主，调整为“分类固定字段 + 补充信息”。后端统一整理资产设定，结合分类模板、图片展示要求和实际参考图生成提示词。

成功标准：

1. 用户通过业务字段表达资产要求，不必手写完整提示词。
2. 用户明确指定的外观、材质、颜色和显著特征在提示词中完整保留，模板或 AI 润色不能静默改写。
3. 同一资产的多个视角共享主体设定；某张图片的展示要求不会回写为全局资产特征。
4. 提示词预览与提交使用相同的最终参考图、模板版本和设定快照。
5. 直接切换到分类字段与补充信息，不保留旧描述写入或历史回填逻辑。
6. 通过固定资产样例比较要求遵循与视角一致性，不能仅以“提示词更长”认定效果改善。

范围约束：

- 复用现有图片供应商、生成编排、文件管理和任务系统，不接入 ComfyUI、InvokeAI 等外部组件。
- 参考公开项目的设计方法，按 Jellyfish 现有架构实现；不整套移植第三方代码或提示词。
- 默认继续使用一张图片一个视角，不增加拼图生成、自动裁切、训练或 LoRA 管线。
- 不增加动态字段平台、可视化流程引擎或复杂提示词 DSL。
- 不改变 `shot.status`、runtime task status 与 `video-readiness` 的职责。

## 2. 现状与改造落点

截至本次代码核对：

| 现有实现 | 本次改造 |
| --- | --- |
| `studio_assets.py` 已区分 Actor、Scene、Prop、Costume，但主体设定均集中于 `description` | 保留四类实体，为各类增加明确字段 |
| Scene、Prop、Costume 共用 `AssetCreate` / `AssetUpdate`；演员另有 schema | 保留公共基础字段，增加分类 Create / Update / Read 定义，并更新实体规格映射 |

## 3. 数据模型

### 3.1 公共信息与分类字段

保留现有名称、标签、题材、画面风格、图片数量、模板绑定等公共信息。新增统一的 `supplementary_info` 文本字段，记录分类字段尚未覆盖的设定及持续性要求。

建议第一版分类字段如下；均为有明确含义的字段，不开放任意键值扩展：

| 资产 | 拟新增字段 | 说明 |
| --- | --- | --- |
| 演员 Actor | `age_appearance`、`gender`、`build`、`facial_features`、`skin_tone`、`hair` | 外观年龄、性别设定、体型、五官、肤色、发型发色 |
| 场景 Scene | `scene_type`、`spatial_layout`、`environment_features`、`materials`、`color_palette` | 场所类型、空间布局、建筑或环境特征、主要材质、色彩 |
| 道具 Prop | `prop_type`、`shape`、`size_description`、`materials`、`colors` | 类型、外形结构、尺寸或相对尺度、材质、颜色 |
| 服装 Costume | `costume_type`、`structure`、`materials`、`colors`、`patterns_accessories` | 类型、款式层次、材质、颜色、纹样与附属配饰 |

设计约定：

- 固定字段存在于 schema，不等于创建时全部必填。暂存和提取草稿允许未知值。
- 分类字段先使用可空字符串；年龄支持“约 30 岁”“青年”等外观描述，不要求伪造精确数值。
- 空值表示未确定；明确“不适用”的内容使用可展示的“不适用”值，整理提示词时按字段语义省略，避免将其拼成外观。
- 短字段限制 200 字符，描述型字段 2000 字符，补充信息 8000 字符；本轮不保留或回填旧描述。
- 存储采用各资产表的明确列，复杂描述使用 Text；公共 schema 只复用真正公共的字段。
- PATCH 中“未传”表示不修改，“传 null”表示清空可空字段；补充信息使用空字符串清空。禁止整表单默认值覆盖未编辑字段。

### 3.2 演员、角色与镜头的边界

- Actor 负责可复用的身份外观，不承担剧情、服装方案或手持道具设定。
- Character 保留演员、服装、道具的组合关系；本轮不在 Character 再复制一套演员年龄、五官字段。
- Character 现有描述继续承担角色语境；生成时只取与形象相关且不与关联资产冲突的内容。
- 动作、表情、天气、时间等默认属于镜头或本次展示要求。只有资产本身就是特殊状态设计时，才明确作为该资产的长期设定。
- 演员图必要的中性展示着装由模板规范控制，不视为角色正式服装；用户明确指定正式服装时，引导使用服装资产与角色组合。

### 3.3 完整描述的来源

目标状态下，四类资产的 `description` 为只读派生描述：由分类字段和补充信息确定性生成，不再作为另一份可独立编辑的完整设定。

名称、标签、风格不自动复制进补充信息。标签不默认全部进入生图提示词，避免内部检索标签变成视觉要求。

统一整理逻辑同时服务资产摘要和生成输入；生成时按用途选择相关内容。原始补充信息仍完整保留，不能因摘要或提示词裁剪而改写源数据。重复信息允许去重，但不能按字符截断丢掉用户要求。

## 4. 提示词体系

### 4.1 两步处理

1. **设定整理**：分类字段和补充信息形成主体描述；默认使用确定规则。输入为长篇口语或剧情时，可选调用 AI 输出整理建议。
2. **任务拼装**：使用确定的类别模板，合入已确认主体描述、视觉风格、展示要求和参考图约束，得到最终执行提示词。

每次生成不强制调用文本模型。AI 负责建议，后端负责契约校验和最终拼装。不要让每次生图都重新设计一次角色。

### 4.2 信息来源与优先级

| 内容 | 来源 | 修改规则 |
| --- | --- | --- |
| 主体设定 | 分类字段、补充信息、关联资产 | 修改资产时变更，图片展示覆盖不得改写 |
| 画面风格 | 当前资产已保存的 `visual_style` / `style` | 创建时可继承项目值；生成时不额外混入另一套项目风格 |
| 视角 | 当前图片槽位 | 只读；改视角应选择对应槽位 |
| 参考关系 | 最终提交的参考图及用途 | 由服务端校验和生成说明，不从自由文本猜测 |
| 构图、背景、灯光、细节强调 | 分类模板默认值与图片展示设置 | 允许在分类职责内调整 |
| 本次附加要求 | 当前生成请求 | 仅进入本次快照，不回写资产或图片默认值 |

优先级按字段作用域处理，不做整段文本的简单覆盖：

- 展示参数：单次显式设置 > 图片级设置 > 模板默认值。
- 主体字段、视角和实际参考关系不参加上述覆盖；显式修改主体应先更新资产或创建独立变体。
- 模板默认值不能推翻用户已经确认的年龄、材质、颜色等设定。
- 用户明确选择的“局部修改”可改变指定项目，但必须列出修改项与保持项；改变身份设定的结果不能自动替换原资产主图。
- 可从结构化输入直接识别的冲突在预览前返回字段级错误。自由文本冲突可由可选 AI 分析提示，不能宣称规则校验能识别所有自然语言矛盾。

### 4.3 模板内容与变量契约

复用现有模板类别。演员、角色、道具、服装维持各自统一类别；场景先保留 `scene_image_front` / `scene_image_other`，本轮不附带迁移类别。

所有类别遵循共同的内容顺序，但不共享不适用的画面约束：

1. 出图用途。
2. 主体设定和用户持续性要求。
3. 风格与材质表现。
4. 当前视角、构图、背景和灯光。
5. 参考图分工、保持项与允许变化项。
6. 需要排除的具体内容。

| 类别 | 默认展示目标 |
| --- | --- |
| 演员 | 单人身份设定，清晰外观、自然站姿、干净背景，不默认加入剧情动作 |
| 角色 | 演员身份与指定服装、道具的组合；保持来源资产各自的特征 |
| 场景 | 清晰空间关系与固定环境，保留建筑、布局和材质；不套用纯棚拍背景 |
| 道具 | 单一物体展示，轮廓完整、尺度和材质清楚，不默认增加持有者 |
| 服装 | 明确款式、层次、面料与配饰；默认无脸人台展示，绑定演员后走角色图 |

变量契约至少声明：允许变量、必需区块、可覆盖展示字段。先以小型后端定义和现有 `variables` / `variable_defaults` 实现，不新增通用规则数据库。

主体描述可继续输出为模板变量 `description`，但必须来自本轮统一整理逻辑。所有默认模板必须实际引用主体描述、风格、视角和参考说明；校验“值存在但模板未使用”造成的信息丢失。

可见细节按视角选择：背面不要求展示正脸；被遮挡的疤痕仍属于身份设定，但不能为展示疤痕而破坏纯侧面或背面要求。约束优先采用明确自然语言，不默认追加长串英文质量词或未经支持的权重语法。

### 4.4 三种生成模式

| 模式 | 输入 | 提示词重点 |
| --- | --- | --- |
| 首次生成 | 资产字段、补充信息、展示要求 | 完整主体设定；没有参考图时不写“保持参考图一致” |
| 参考图派生 | 已有图片、用途、目标视角或组合 | 明确哪些身份、结构、颜色要保持，哪些展示条件可变化 |
| 局部修改 | 一张待修改图、修改要求 | 明确变化动作、变化对象、目标特征与保持项；结果先作为候选 |

首次生成、参考图派生与局部修改均已接通。局部修改须选择一张源图并填写修改要求，结果仅保存为候选，在历史中明确采用。

参考图必须先归一化、校验可访问性、确定数量与顺序，再生成说明和执行快照：

- 每张图至少携带 `file_id` 和用途，如身份、服装、道具、场景布局或画风。
- 多参考图说明中的“图 1”“图 2”须对应最终上传顺序；按供应商支持的表达方式渲染，不假定所有模型都支持 `@Image`。
- 用户上传图需要明确用途；业务关联图可以由服务端推导用途。
- 未指定参考图集合表示使用系统推荐；显式空集合表示不用参考图，不能再次回退到默认图。
- 参考图超出能力限制时返回可理解的错误或要求用户选择，不静默截断。
- 替换、移除参考图后必须重建说明。多图被去重时保留其用途集合，不能丢失角色组合信息。
- 演员、服装、道具只存在其中一类参考图时，只描述实际存在的来源。

### 4.5 AI 整理与用户确认

调整现有资产分析能力，使其返回字段候选、补充信息建议、缺失项与冲突提示。候选需区分原文明确内容和 AI 推断内容；推断不自动保存。

前端展示当前值与建议值，用户逐项或整体采用。已确认值没有显式替换操作时不得被自动覆盖。整理建议生成期间资产发生修改，应提示重新比较，不能用旧建议覆盖新编辑。

只把与当前资产相关的原文或上下文传给文本模型。通用生成输入输出 DTO 放在 `app/core/contracts`；业务 CRUD schema 保持现有业务层归属，tasks 不新增跨层类型。

## 5. 用户界面

资产编辑页已采用共用资产档案布局：顶部资料配图，下方整行展示分类设定与补充描述、生成风格、多视角图片。完整描述保持只读预览，字段使用普通业务名称；当前分区、保存与图片操作规则见[资产图片管理](/docs/architecture/asset-image-management/#资产档案布局)。后续生成面板调整继续复用该骨架。

生成界面显示视角、画风、参考图及其用途；构图、背景、灯光等复用“调整展示方式”。本次附加要求与资产补充信息分开，说明其仅影响当前生成。

高级展开显示最终提示词和来源摘要。用户变更资产、模板、参考图或展示要求后，旧预览需失效或重新渲染；提交必须对应用户当前看到的输入，不能后台换用另一份内容。

分镜编辑页继续负责提取、确认和基础信息修正；工作室继续负责生成准备和执行。通用任务中心只显示任务状态、进度与回跳，提示词诊断和参考图细节留在资产生成界面。

首期缺失字段采用编辑提示，不新增资产状态枚举，也不强制补齐全部字段才能保存。首次文生图至少需要可用主体描述；仅名称且无描述时提示补充。有有效身份参考图时不机械要求把可见外观重复填全。

## 6. 无历史负担的接口与表结构切换

用户已明确不需要迁移历史数据，并批准更新本机开发数据库。本次 revision `f2a3b4c5d6e7`：

- 增加四类资产的分类字段与 `supplementary_info`，删除旧 `description` 列；已有行的新补充信息初始化为空，不复制旧描述。
- `description` 作为只读派生属性返回；创建、更新接口拒绝旧描述和跨类别字段。
- 更新系统图片模板及版本；自定义模板仍保留，但必须满足新的变量契约才能渲染。
- 后端、OpenAPI 和前端同步切换，不增加旧请求兼容层。
- MySQL 的 Text 列通过“先允许空值、初始化空文本、再收紧约束”创建，不使用不支持的 Text 默认值。
- 不承诺旧版本应用或旧任务快照兼容；降级仅恢复表结构，不恢复已删除的数据内容。

## 7. 实施阶段与验收

| 阶段 | 工作 | 验收方式 |
| --- | --- | --- |
| P0：契约与基线 | 固定字段、覆盖规则、模板必需区块；保存当前样例提示词 | 四类字段均有归属；同一用户要求不会同时成为资产设定和图片默认值 |
| P1：演员闭环 | 演员模型、CRUD、编辑表单、描述整理、首次生成与视角派生；修正参考说明生成时机 | 演员创建、编辑、提取确认、主图和侧背面生成链完整；API 和前端类型同步 |
| P2：其他资产与角色组合 | 场景、道具、服装字段和模板；角色按演员、服装、道具关联组织引用 | 各类展示目标正确，服装和道具不污染演员身份；场景不出现纯背景约束 |
| P3：AI 整理与局部修改 | 候选比较、推断确认、修改项与保持项、结果候选采用 | 未确认建议不覆盖源数据；局部修改不自动改写原资产主图 |
| P4：迁移收尾与验证 | 移除旧写入、验证模板契约、最多 3 次真实生图、文档沉淀 | 新字段、模板和候选结果链路可用；小样只作为冒烟证据，不宣称统计上的质量提升 |

当前 P0—P4 已完成。用户授权：先完成自动化与页面验证，再最多调用 3 次图片供应商；本轮不执行 64 次对比。

## 8. 测试与效果评估

### 自动化测试

- CRUD：分类字段类型和长度、空值与 PATCH 语义、未知字段拒绝、分类字段不串写。
- 整理：字段顺序稳定、补充要求完整、未确定／不适用不被编造成事实、超长输入不静默截断。
- 保护：图片级覆盖不能伪造主体、槽位视角或参考关系；结构化冲突返回明确错误。
- 模板：必要区块缺失、自定义模板未使用关键变量、风格实际渲染、按视角调整可见细节。
- 参考图：首次无图、系统默认图、显式空图、替换图、多图用途、去重、顺序、数量上限、不可访问文件。
- 角色组合：仅演员图、仅服装图、演员与服装及道具组合，各自说明与实际输入一致。
- 快照：预览与提交一致，输入改变后旧预览不会静默继续提交，旧任务不随资产修改而变化。
- AI 候选：提取值与推断值区分、采用前不写入、旧候选不覆盖较新的编辑。
- 表结构：旧描述列删除且不回填、新字段可用、系统模板版本更新、旧 API 写入明确拒绝。

### 实际图片对比

准备固定的 8 个资产样例：两个人物、两个场景、两个道具、两套服装。其中覆盖非标准人物、室内外环境、金属与透明材质、明显纹样及用户明确排除项。

按阶段先运行已实现类别。完整对比建议每个样例测试首次生成和参考图派生两种任务，每种任务重复 2 次；新旧策略在同一模型、同样尺寸和相同可控参数下比较。两套策略合计 64 次生成，实际计费以各供应商请求与输出张数为准。该完整对比是后续评估建议，不属于本轮已授权验证范围。

记录：主体特征、颜色材质、视角构图、参考一致性、排除要求、非预期新增内容，以及延迟和重试次数。人工按“满足／部分满足／不满足”评审，保留提示词、输入图、输出图和评审理由。相同 seed 仅在模型支持时使用，不将其视为跨供应商可比条件。

上线门槛：契约测试全通过；样例提示词无已确认硬性要求遗漏；重复观察到的换脸、材质替换、错视角等问题需定位并调整。若视觉结果无改善或发生回退，不因结构化改造完成而宣称一致性提升；可以保留数据改造，继续修订提示词。
