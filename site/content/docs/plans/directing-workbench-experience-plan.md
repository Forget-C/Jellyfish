## 1. 目标与范围

让用户进入场次工作台后，能迅速回答三个问题：**这页做什么、会得到什么、下一步点哪里**。同时能辨认正在查看的候选、本地编辑草稿与已经确认采用的内容。

本轮解决：

1. 历史生成记录、候选与当前采用混在一起，最新记录容易被误认作当前使用版本。
2. 流程阶段与辅助工具并列，用户需要自行判断先后顺序。
3. 文字字段、版本信息和任务记录集中呈现，关键内容与主要操作不突出。

本轮改动范围是场次业务页面的布局、导航、文案、选择规则和状态展示。优先复用现有组件、接口与数据关系；确需补充对外契约时，在对应阶段同步实现、OpenAPI 和 generated client。

不新增专业多轨剪辑、自动审片、自动采用、一键成片、混音或成片导出。最终产出表述为“可预览的本场粗剪”，画面验收与声音完成分别表达。不恢复旧 Shot、镜头槽位或一镜一 Take 的模型。

## 3. 页面结构与布局示意

### 3.1 页面用途与三大阶段

页面主标题：**把这场戏做成可预览的粗剪**。

说明：**先确定怎么拍，再生成视频素材，最后选出片段、组成这场戏。**

| 主导航 | 用户要完成的事 | 本步产出 | 辅助能力归属 |
| --- | --- | --- | --- |
| 1. 设计这场戏 | 确定目标、动作、镜头与六岗要求，修改并确认设计 | 可修改并确认的拍摄方案 | 本场原文、资产关联、固定项目风格与来源 |
| 2. 生成视频素材 | 准备单元和参考，编译、审稿、能力检查，再明确执行 | 待挑选的视频素材 | 视觉验证、批量拍摄、单元拆分/重组、连续性参考准备 |
| 3. 选片与剪辑 | 审片、选择实际区间、组成并确认粗剪、验收及局部返工 | 可预览的本场粗剪 | 实际连续性、边界帧、接缝、整场验收与返工 |

“来源与记录”承载原三本账的追溯能力，在相关对象旁提供入口，并保留完整分类浏览。通用任务中心继续只负责通用状态、进度、取消和业务回跳。

三阶段表示导航顺序，不是必须走完才能回退的向导。设计确认后可先做预演；可边生成边剪辑，也可从局部问题回到设计或生成准备。

### 3.2 通用布局

```text
┌──────────────────────────────────────────────────────────┐
│ 项目 / 章节 / 本场名称                       历史记录     │
│ 把这场戏做成可预览的粗剪                                 │
│ 先确定怎么拍，再生成视频素材，最后选片组成这场戏。         │
├─────────────────┬──────────────────┬─────────────────────┤
│ 1 设计这场戏    │ 2 生成视频素材   │ 3 选片与剪辑        │
│ 得到拍摄方案    │ 得到待挑选视频   │ 得到本场粗剪        │
├─────────────────────────────────┬────────────────────────┤
│ 主工作区                        │ 当前相关上下文         │
│ 当前目标 / 关键问题              │ 本步产出或当前采用     │
│ 计划卡、单元或播放器             │ 简短状态与必要依据     │
│                                 │                        │
│ 按需展开：完整字段与来源         │ 按需展开：版本与详情   │
│ 一个突出的下一步操作             │                        │
└─────────────────────────────────┴────────────────────────┘
```

宽屏主区约占三分之二至四分之三，侧区只展示当前阶段所需信息。窄屏上下排列，关键状态与动作不能依赖悬停。避免同时常驻原文、所有版本、完整任务列表和全部设置。

### 3.3 首次进入与设计页

```text
主区：这场戏，观众需要看到什么？       侧区：这一步会得到
      本场原文摘要                         一份可修改的拍摄方案
      补充创作想法（可不填）               场次目标、人物动作、
      ▸ 人物、场所与风格                    计划镜头、拍摄要求
      [生成拍摄方案草稿]

已有草稿：场次目标 + 关键转折 + 计划镜头卡
          ▸ 六岗设计、完整要求与来源
          [确认方案，去准备视频生成]  修改方案
```

没有参考图时使用明确标注的文字计划卡，不放假缩略图，不要求先生成整套分镜图。摘要来源于同一份设计字段，不新增第二份可编辑正文；“未知、未填写、不适用、明确没有”的区别必须保留。

“生成拍摄方案草稿”描述用户预期得到的内容，不合并任务完成、查看建议、写入草稿与确认设计。模型建议仍须显式写入草稿；确认设计必须使用已保存版本。保存失败、并发变化或未保存编辑时，按钮说明准确的下一步。

### 3.4 视频生成页

```text
主区：本次要拍——递出旧信               侧区：本场拍摄内容
      准备单元与参考 → 指令与检查              门前停步：已有采用
      → 明确执行 / 等待结果                    递出旧信：新视频待看
      参考预览或新视频预览                     抬头认出：待准备参考
      ▸ 本次固定输入、审稿与来源
      ▸ 其他生成结果
      [准备缺少的参考 / 检查指令 / 开始生成 / 查看视频]
```

底部示意的动作按真实状态择一突出，不同时列出为四个主按钮。标题优先用可理解的动作范围，编号在详情保留。候选按 `plan_revision_id + unit_id` 等真实身份组织；同名动作、不同计划版本不能静默合并，跨计划比较须显式选择。

### 3.5 选片与剪辑页

```text
主区：待审与候选 / 当前采用             侧区：当前采用的粗剪
      “递出旧信”第 2 次生成                   第 2 版 · 已确认
      候选播放器                              门前停步：1.0–5.0 秒
      本次选取：0.8–4.6 秒                    其他片段：预演待替换
      ▸ 实际观察、覆盖与来源                   画面待验收 / 声音待后期
      [把这一段加入剪辑草稿]
───────────────────────────────────────────────────────────
当前查看的剪辑 / 编辑草稿（明确标识）
[真实片段] [文字或静态图预演] [真实片段]
保存草稿 → 核对 → 确认并设为当前采用
```

选入草稿立即反馈，但侧区仍显示原当前采用。素材列表按需显示缩略图、动作名称、审片结论和采用区间；同一 Take 多区间采用时逐项可查看。预演用文字标识与不同边框区分，不能仅靠颜色，也不能把预计时长计作已拍到的覆盖。

## 4. 状态、版本与历史的统一规则

| 对象 | 首要展示 | 判定依据 |
| --- | --- | --- |
| 设计与生产计划 | 当前查看/编辑、草稿/已确认、被谁引用 | 版本身份、确认状态与实际引用；不设无依据的全局“当前设计” |
| 提示词与审稿 | 本次计划/单元、固定版本、匹配检查结果 | 所选提示词及对应审稿关系；不独立取各类最后一条拼接 |
| Take | 待审或审片结论；未采用/草稿已选入/当前采用 | 审片注释与剪辑引用分别判定；采用包含具体源区间 |
| 粗剪 | 当前采用、编辑草稿、历史版本 | 服务端当前采用指针；保存草稿不改变指针 |
| 生成任务 | 排队/运行/成功/失败/取消，产出是否仍需处理 | 通用任务状态及真实产出关系；不把成功当作已确认或已采用 |

当前 `WorkspaceRead` 没有独立的当前采用字段；`ContinuityRead` 和 `FeedbackRead` 已提供 `active_cut_revision_id`。实现先复用 generated client 的已有读取能力，在业务页共享准确上下文；不得通过数组末尾、创建时间或“最近确认”的前端猜测替代指针。读取失败显示“采用状态暂不可用”，不能误显示“未采用”。

历史入口遵循：

- “待审与候选”保留新结果和仍可选用的素材；未采用不等于已废弃。
- “当前采用”仅依据已确认剪辑，展示真实区间及预演项。
- “历史记录”按对象归类版本、曾采用关系和任务记录；查看不会产生采用、确认、生成或保存操作。
- 老版本仍被当前素材引用时标记“仍被引用”；不因存在新版本就隐藏其有效关系。
- 既有已确认版本保持不可变。修改产生新草稿，不能原地覆盖。
- 最新记录可作为明确标注的浏览建议；页面恢复优先尊重业务回跳、用户选择和编辑基线，不能以轮询结果覆盖编辑或自动切换采用。
- 若后端没有“已读”记录，不新增虚假的已读状态；“待处理”以尚未写入的建议、未审素材等真实关系判断。

## 5. 引导与表达规范

### 5.1 下一步选择规则

1. 有未保存编辑或并发冲突时，先提供保存、派生或载入的明确入口，不能让后续动作丢失修改。
2. 本次操作受到来源变化、缺失参考、输入不匹配、模型能力或实际依赖阻碍时，显示最直接的修复入口；其他阻碍按需展开。
3. 本次任务运行中时，显示进度和取消；不提供容易重复提交的主动作。
4. 结果完成后，引导查看建议或审看片段，不能自动写入、确认或采用。
5. 无阻碍时，围绕所选岗位、单元或剪辑继续下一步。其他独立单元仍可切换，不把局部阻碍升级为全场锁定。

首屏只突出一个主操作；次要操作仍可访问。新用户从设计开始，老用户恢复所选业务上下文，不反复出现新手向导。提示与状态可以更新，焦点和编辑对象不随轮询跳动。

### 5.2 文案映射

| 现有表达 | 建议展示 | 必须保留的边界 |
| --- | --- | --- |
| 导演设计 | 设计这场戏 | 六岗设计与确认仍完整保留 |
| 单元试拍 | 生成视频素材 | 生成单元身份、范围和模型约束不变 |
| 编译本次试拍 | 准备生成指令 | 仍生成固定版本，变更后重新编译与审稿 |
| 六部门审稿 | 检查生成指令 | 详情保留六岗结论、问题与人工取舍，不能把艺术取舍当作硬校验豁免 |
| 采用当前区间 | 把这一段加入剪辑草稿 | 此步不改变当前采用 |
| 确认此剪辑版本 | 确认并设为当前采用 | 仅对已保存且未发生本地变更的有效版本执行 |
| 三本账 | 来源与记录 | 保留连续性、提示词和 Take 实验三类完整追溯 |

错误文案应说明“缺什么、影响哪个操作、到哪里处理”。正常结论摘要优先展示，详细诊断按需展开。不要用“完成”混指生成完成、审片通过、采用或整场验收。

顺序为 **UX1 → UX2 → UX3 → UX4 → UX5**。前一阶段的状态与引用规则通过验证后，再推进后续布局。阶段编号与已完成的 P1–P6/T01–T18 分开。

| 阶段 | 状态 | 核心交付 | 完成门槛 |

| UX1 状态与采用关系 | 已完成（2026-09-15） | 当前采用读取、引用标识、候选与历史区分、准确采用文案 | A01–A04 已通过 |
| UX2 页面导航与下一步 | 已完成（2026-09-15） | 三阶段外壳、辅助入口归位、动作引导、上下文恢复 | A05–A08 已通过 |
| UX3 设计与生成布局 | 已完成（2026-09-15） | 首次进入、设计摘要/计划卡、单元工作区、关联输入与任务摘要 | A09–A12 已通过 |
| UX4 选片与剪辑布局 | 已完成（2026-09-15） | 候选预览、采用区间、草稿与当前采用、预演与实际片段、验收返工 | A13–A16 已通过 |
| UX5 综合验收与文档收口 | 待实施 | 回归证据、可用性检查、当前架构同步 | A17–A20 通过，前四阶段门槛全部满足 |

### UX1：先把“在看、在改、在用”分清

- **实现范围**：`SequenceWorkspacePage`、`CutEditor` 及必要共享上下文；复用连续性/反馈的当前采用读取能力，补充素材区间与版本引用展示；将加入草稿与确认采用分开命名。
- **验收**：
  - **A01**：新设计/计划草稿与当前采用同时存在时，正确显示查看对象、草稿状态和实际引用；不能自动把新草稿标为当前依据。
  - **A02**：生成成功、保存审片、加入剪辑草稿、保存草稿四种操作均不改变当前采用；确认剪辑成功后才切换，刷新后保持一致。
  - **A03**：同一 Take 被采用多个区间时可查每个区间；审片“整体可用/局部保留”但未采用的候选不会被标为正在使用。
  - **A04**：查看历史不发起业务写入；历史依据仍被使用时显示引用；当前采用接口失败/重载期间不出现错误的“未采用”结论。
- **验证方式**：复用版本与采用相关用例，补齐前端状态派生回归；用已有或合成媒体在页面对照服务端当前采用、剪辑项与区间。

### UX2：让用户能找到下一步

- **依赖**：UX1。
- **实现范围**：工作台外壳、导航与下一步提示；将连续性、视觉验证、批量、三本账和反馈入口归入相关阶段。保留现有 `view` 业务回跳的可达性，可映射到新的阶段及内部区域，不恢复旧业务模型。
- **验收**：
  - **A05**：主导航只有三个阶段，每个均明确本步产出；首次进入有页面用途及一个突出的起始动作，没有满屏空表单。
  - **A06**：未保存编辑、来源变化、缺参考、需审稿、能力不支持、任务运行、结果待查看分别展示正确的下一步；所有阻碍均能定位处理位置。
  - **A07**：从任务、章节、资产返回及原 `view=design/shoot/cut/continuity/batch/visual/ledger/feedback` 入口进入时，仍定位相应内容；刷新不误换场次或已固定输入。
  - **A08**：轮询不覆盖本地编辑、切换所选单元或抢焦点；用户主动离开未保存编辑时有保存/放弃/取消的明确选择；单元局部阻碍不阻止其他无依赖工作。
- **验证方式**：导航与状态用例、浏览器页面检查；逐个验证旧业务链接和刷新恢复，不仅检查静态导航文字。

### UX3：让设计和生成围绕产出展开

- **依赖**：UX2。
- **实现范围**：`DesignEditor`、`PlanEditor`、`SceneAssets`、`StyleEditor`、`DirectingTasks` 及编译审稿区域。摘要与详情读写同一数据；按需复用组件，不新增通用工作流引擎或第二套内容存储。
- **验收**：
  - **A09**：首次进入可从原文和可选创作意见开始，人工起稿仍可访问；生成建议可查看并明确写入草稿，保存后才可确认，失败与迟到结果不覆盖人工修改。
