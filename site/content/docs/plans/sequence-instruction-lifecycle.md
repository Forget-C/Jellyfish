> 2026-09-28。T1–T5 已完成，验收与限制见第 11 节。本计划承接[检查问题处理方向与 AI 修订计划](/docs/plans/sequence-review-ai-revision/)，保留上一轮完成记录，规划后续体验与能力补齐。本次评估依据工作区代码、已有测试和文档，包含尚未提交的改动；没有运行真实拍摄，不作为线上实测或本计划验收通过的证据。

## 1. 目标与范围

让用户在指令生成后随时知道：正在修改什么、修改是否生效、下一步如何继续。检查前、有检查问题和检查通过后，都能主动调整；方向变化后可在同一面板更新方案、明确采用并重新检查。

沿用 React、Ant Design、FastAPI、Pydantic、通用任务系统、DirectingStore 和不可变确认版本。保留三步试拍结构，不新建聊天系统、工作流平台或版本树。实施按 T1–T5 推进；以下保留需求和任务定义，当前实现及验证见第 11 节。

成功标准：用户无需关闭方案面板寻找更新入口；新指令不会复用旧检查批准；中断可继续原操作；已有视频、其他单元和旧版本可追溯。

页面首先回答“当前怎么样、需要我决定什么、下一步做什么”。普通流程不要求用户阅读完整指令、字段路径或版本链；信息简化只改变展示层级，不减少实际校验和用户决策所需的信息。本计划统一本次试拍指令流程的展示规则，不扩展为全站页面改造。

不包含：整篇模型原文任意编辑、多方案并行比较、逐字段勾选部分采用、自动循环修复、自动拍摄、跨设备草稿同步、整场重新设计或新增通用抽象。

## 2. 当前生命周期与问题

当前链路：确认设计 → 确认拍摄准备 → 编译指令 → 六岗检查 → 处理问题 → 生成修改方案 → 采用方案 → 派生设计／计划并重新编译 → 重新检查 → 确认结论 → 明确试拍 → 产出 Take → 审片与采用。

| 环节 | 当前事实 | 待解决问题 |
| --- | --- | --- |
| 生成指令 | `ProductionService._compile_unit` 从固定设计、计划与单元编译正文 | 不改依据而重复生成，通常不会改变创作方向；现有按钮容易让用户误解 |
| 阅读正文 | `PromptReader` 提供易读视图、模型原文、复制和来源 | 缺少清楚的直接修改入口 |
| 信息展示 | 指令、检查、固定依据、版本与技术详情分布在多个入口 | 需要区分默认任务信息、业务核对详情和技术诊断，避免用户为理解下一步先理解内部实现 |
| 主动调整 | 当前修订依附检查来源和非通过问题 | 检查前、全部通过后无法顺畅表达新的创作要求 |
| 补充方向 | 每项问题下折叠输入，统一生成方案 | 整体意图分散，入口不明显 |
| 方向变化 | 旧方案过期，前后端拒绝采用 | 预览侧栏没有就地更新主操作，用户需关闭后回主区生成 |
| 采用中断 | 已有分步保存及恢复能力 | “继续处理”未充分表达已完成产物及待执行步骤 |
| 修订完成 | 可能派生新的单元计划和指令 | 仅按当前计划筛选历史时，原指令和候选不易找回 |

关键依据：

- `backend/app/services/directing/production.py`：编译与固定输入校验。
- `backend/app/services/directing/review_revision.py`：方向、候选白名单、采用与可恢复编排。
- `front/src/pages/aiStudio/directing/ReviewRevisionPanel.tsx`：方向、失效状态与采用按钮。
- `front/src/pages/aiStudio/directing/ShootInstructions.tsx`：指令阅读、版本选择及详情入口。
- `front/tests/workspaceReviewRevision.browser.mjs`：已有案例在方向或声音选择变化后，关闭侧栏、回主区重新生成，再采用。

不能将“旧方案禁止采用”本身当作错误。保护规则必须保留，修复的是更新入口与恢复引导。当前受约束修订也不支持任意更换模型、参考或增删镜头；这些操作需明确导向拍摄准备或场次设计。

## 3. 方案选择与页面组织

| 方案 | 取舍 |
| --- | --- |
| 仅补按钮与提示 | 改动最少，但无法补齐主动修改能力 |
| 统一调整工作区并补齐主动修改 | 推荐；覆盖主要问题，复用当前页面与版本机制 |
| 完整聊天式创作助手 | 状态与授权更难辨认，当前不采用 |

试拍步骤调整为：**拍摄准备 → 指令与检查 → 试拍与候选**。第二步同时承担阅读、调整和检查。

- 主区：默认展示本次拍摄摘要、当前状态、需要处理的问题和一个当前主操作。初次生成显示“指令已生成，可检查或调整”，不自动铺开完整正文；检查完成更新状态摘要，用户正在编辑时不抢焦点。
- 调整区：点击“调整指令”或问题上的“调整这一项”后展开，包含修改要求、关键变化摘要、待确认选择和当前主操作。前后全文按需查看，默认不常驻编辑面板。
- 完整指令与检查明细：通过“查看完整指令”“查看检查明细”进入，可复用详情区的正文／检查页签，不作为默认主区的必读内容。
- 拍摄设置、来源与版本历史：保留辅助入口，按需查看；不在页头并列堆放设计、计划、指令及检查的完整版本链。
- 桌面使用并排面板；窄屏使用同一内容的全屏面板，底部主操作保持可达，关闭后恢复触发位置与草稿。
- 调整面板打开时，当前主操作集中在该面板，不让页面顶部同时突出另一个采用或执行动作。

### 3.1 统一信息层级

| 层级 | 内容 | 展示规则 |
| --- | --- | --- |
| 默认任务信息 | 本次拍什么、当前状态、主要问题、必要选择、修改摘要及下一步 | 直接可见，使用简短业务语言；修改要求仅在调整面板内展开 |
| 按需核对的业务详情 | 完整指令、修改前后、参考素材、检查依据、检查明细、历史版本 | 在相关内容旁提供明确入口，不要求切换全局模式 |
| 更多拍摄设置 | 当前模型实际支持的非主要参数和较少使用的配置 | 在拍摄准备中按需展开；仍遵守计划确认、派生版本与重新检查规则 |
| 技术诊断 | 内部 ID、原始字段路径、完整编译映射、原始 JSON、请求身份 | 放在详情内独立的“技术详情”，只展示原有权限允许的信息，不混入普通业务说明 |

不增加全局“简单／高级模式”，避免两套页面和全局切换负担。高级配置与技术诊断分开；完整指令、参考和差异属于业务核对内容，不需要进入技术诊断才能看到。

模型、时长、画幅和参考数量以一行摘要表达；完整参数及素材在“拍摄设置”中查看。默认展示单元名称和简短内容摘要，摘要从固定内容提取，不额外引入 AI 总结任务。历史场景仍明确标注“历史预览”，不因隐藏版本链而让用户误认当前对象。

问题默认显示通俗标题、影响和建议，已通过项合并为“已通过 N 项”；统计仍沿用真实检查条目口径，不能把问题发现数和岗位／出现项通过数混为一谈。明细展开后仍使用中文名称和具体说明，不把难懂内容原样折叠就视为完成简化。

### 3.2 必须直接显示的信息

以下信息不能因默认简洁而隐藏：

- 阻止下一步的原因、尚未完成的必要选择及直接处理入口。
- 方案未包含最新方向、修改尚未采用、请求结果待核实等影响操作有效性的状态。
- 对创作结果有实质影响的变化，包括声音改为后期、更换模型或参考、时长变化、涉及其他镜头。
- 无法满足的要求、冲突与超出当前单元范围的修改；明确下一步去哪里处理。
- 采用和拍摄动作的实际后果；旧方案不能直接采用、新方案不会自动拍摄。

被折叠设置发生错误时，主区显示可理解的摘要，并提供“查看并处理”直接定位相关项；不强制展开其他无关详情。长错误和底层异常放技术详情，主区保留原因及恢复动作。

### 3.3 展开与关闭规则

使用“查看完整指令”“修改前后”“查看依据”“历史记录”“更多拍摄设置”等具体名称，不用笼统“高级功能”承载所有内容。展开不改变工作版本，不触发写入；关闭不丢失编辑，恢复焦点。正文中的直接编辑是可选入口，普通用户可从主区直接表达修改要求，无需先打开全文。

页面内往返保留有效的展开位置；切换单元或基线后不误用旧详情。异步完成只更新摘要或提供查看结果入口，不自动展开全文、诊断或覆盖当前输入。必要的阻断问题可以直接定位，用户无需自行寻找深层设置。

## 4. 修改方式

### 4.1 直接修改明确内容

正文相关段落提供“修改”，打开准确对应的中文字段，展示当前值。第一版限于可可靠映射且服务端允许修改的内容，例如本镜头运镜、适用表演要求、单元时长和声音安排；并非所有段落都可直接编辑。

修改对应依据后编译新正文，避免后续重新生成冲掉人工修改。直接编辑不需要先调用 AI 改写，生成真实差异和指令预览后，同样显式采用并重新检查。

无法准确映射、涉及共享内容或超出白名单的段落，提供“说明希望怎么改”或定位至设计／拍摄准备。易读名称是展示转换，不能直接反向当作模型原文保存。

第一版不开放整篇模型原文任意编辑，以免正文、参考绑定、设计依据与来源映射不一致。

### 4.2 自然语言修改要求

统一输入：“你希望怎么改？”示例：“保留人物停步，镜头改为固定机位；对白交给后期，其他动作不变。”

- 未检查、有问题、已通过时都可发起，不能强制用户先制造检查问题。
- 检查问题上的“调整这一项”将固定问题上下文带入同一面板；无需分散寻找折叠输入框。
- 有检查问题时，未填写方向也可按已有问题生成方案；无检查问题的主动修改，需实际输入修改要求或编辑字段。
- 整体要求与逐项补充冲突时，指出具体冲突并要求选择，不静默决定优先级。
- 两种方式共用调整草稿；同一字段出现直接编辑与 AI 建议冲突时，保留人工输入并明确列出冲突，未处理前不能采用。
- 生成和采用仍分别触发；暂存、关闭和预览不表示采用。

## 5. 方案预览与状态引导

### 5.1 预览内容

默认展示“本次将修改 N 处”及关键变化的简短清单，例如“镜头由缓慢推进改为固定机位”“对白改为后期添加”，附影响范围和采用后果。摘要从已校验的实际候选差异生成，不能只采用模型自述，也不能省略实质变化。理由简短呈现，长解释按需展开。

提供“修改前后”“查看新指令全文”“查看依据”；逐字段差异、完整指令和来源默认收起。采用前必须能查看拟生成的指令全文，但不强制打开或通读全文才能采用。预览使用与正式编译一致的规则，不得写入已确认版本；采用时重新核对同一份输入与候选，避免批准的内容和最终提交内容不一致。

只作用于本次拍摄的新版本；已有视频不变。涉及多个镜头的共享设计时，提示具体影响并定位设计入口，保留修改要求，不把超范围要求送入反复无法采用的循环。

### 5.2 状态与主操作

| 状态 | 主操作 | 提示与行为 |
| --- | --- | --- |
| 有修改要求、尚无方案 | 生成修改方案 | 先预览，当前指令保持不变 |
| 正在生成 | 正在生成方案… | 显示真实任务；继续编辑会使返回结果成为旧方案 |
| 方案可用 | 采用并重新检查 | 保存新版本并检查，不自动拍摄 |
| 方向或必要选择变化 | 更新修改方案 | 旧方案标为“待更新”，保留对照，不可采用；更新按钮就在当前面板 |
| 缺少必要选择 | 定位待确认项 | 明确缺哪一项；选择后生成包含该选择的新方案 |
| 没有实际差异 | 返回当前指令 | 说明当前内容已符合要求，不创建空版本 |
| 超出支持范围 | 前往对应位置调整 | 解释具体原因，保留要求与返回上下文 |
| 正在采用 | 显示当前进度 | 默认一句话展示实际阶段，例如“修改已保存，正在生成新指令”；完整阶段记录按需展开 |
| 复检仍有问题 | 继续调整 | 展示新检查；旧问题不因采用而自动变为通过 |
| 通过但结论未确认 | 确认检查结论 | 保存本次检查，不授权拍摄 |
| 检查结论已确认且具备开拍条件 | 前往试拍 | 显示实际使用的指令与模型；开拍仍需明确触发 |

方向变动后，不自动采用重新生成的方案。必要声音选项使用结构化选择；“后期添加”只表示制作安排，不代表声音已完成。更换模型导向拍摄准备，不能仅记录一句方向就假定模型已切换。

### 5.3 恢复与提示文案

| 情况 | 提示 | 操作 |
| --- | --- | --- |
| 尚无指令 | 拍摄准备已确认，生成指令后可查看和修改 | 生成指令 |
| 修改草稿未采用 | 修改草稿已暂存，当前拍摄仍使用原指令 | 继续修改 |
| 修改已保存，检查未启动 | 新指令已保存，检查尚未启动 | 重试检查 |
| 检查任务失败 | 本次检查未完成，新指令已保留 | 重新检查 |
| 请求结果不明确 | 正在确认上次操作是否成功 | 查询上次结果 |
| 原文或依据变化 | 显示发生变化的具体依据 | 核对依据，保留输入 |
| 采用完成 | 修改已采用，正在检查新指令 | 查看新指令 |

状态必须依据服务端已持久化产物和任务事实推导，不用前端进度代替成功。重复请求和响应丢失先核实原操作；已完成步骤不重复执行。已受理但失败的检查通过显式重试恢复，不自动循环。

恢复提示默认只说明已完成什么、当前卡在哪里以及下一步操作；请求 ID、重试身份、事务和版本创建细节进入技术详情。主区与调整区避免重复堆叠同一状态提示。

## 6. 版本、来源与执行边界

- 当前工作版本、调整草稿、未采用方案、检查记录和视频任务分别表达；历史预览不改变工作版本。
- 主动修改必须有独立、稳定的来源身份；检查问题修改继续绑定固定检查来源，不能伪造问题或按新检查序号套用旧方向。
- 草稿身份至少包含项目、场次、基线指令和修改来源；采用时校验冻结依据、方向及候选。轮询和迟到响应不覆盖当前编辑。
- 新检查默认不自动继承旧问题处理方向；用户可查看上次修改要求，但不能把旧问题位置映射到新问题。
- 已确认版本不可原地改写，所有写入通过 DirectingStore。设计／计划的派生和适用参考继承沿用现有校验。
- 增加“从上一版修改而来”的精确关联入口。修订派生新计划时仍可返回原计划、指令和候选；不通过同名单元合并历史，也不把所有旧候选混入当前计划列表。
- 新指令执行前仍须完整正式检查，按六岗位乘以全部出现项验证；本期不引入局部检查替代正式检查。
- 人工艺术取舍保持独立入口，不冒充修复，不绕过结构与模型能力校验。
- 正在拍摄的任务使用提交时的固定指令；新编辑不改变运行任务，生成成功只登记 Take，不自动采用。
- 不机械新增数据表或公共层；优先复用现有版本、任务快照与来源关系。需要新增契约时放在 `app/core/contracts/directing`，业务编排放 service，API 负责收参、鉴权和响应。

| --- | --- |

| 业务详情与技术诊断 | 全文、修改前后、参考、依据和历史均可按需访问；技术信息独立，不靠全局模式切换 |
| 重要影响及折叠项错误 | 声音／模型／参考／时长等实质变化、未满足要求和阻断原因不被隐藏；可直接定位设置 |

| 生成后立即修改 | 无检查记录也有合法入口，形成新版本并检查 |
| 检查失败后修改 | 问题与方向对应，同面板更新并采用 |
| 检查通过后修改 | 允许主动调整，新指令不继承旧批准 |
| 生成中改变方向 | 迟到方案标记待更新，不覆盖输入，不抢焦点 |
| 方案中选择声音 | 就地更新，结构化选择纳入实际方案 |
| 直接编辑字段 | 不必先调用 AI，预览与采用一致；非法值拒绝 |
| 无变化／冲突／超范围 | 有具体解释和合法出口，不创建空版本 |
| 采用中断与响应丢失 | 保存产物可核实，恢复无重复任务或版本 |
| 刷新及来源变化 | 草稿恢复且严格隔离，过期依据不可采用 |
| 跨计划历史往返 | 原指令、旧候选可追溯，预览不改变当前版本 |
| 运行中继续编辑 | 原任务固定身份不变，不触发新拍摄或采用 |
| 1440／1024／768／375px | 文案、差异、输入与主操作可达，无横向溢出，键盘焦点可见 |
