## 目标

用户应能从实验室的历史**用户输入**恢复一次生成配置，以便修改提示词或参考素材后再次生成。恢复范围覆盖：

- 文本：模型、最终提示词，以及可恢复时的模板与变量。
- 图片：模型、最终提示词、参考图、目标比例和分辨率档位。
- 视频：模型、最终提示词、画幅、首帧、尾帧、关键帧和命名主体的图片/视频参考。

恢复不会修改原历史消息，也不会复用原异步任务；再次生成会创建新的用户消息和新任务。

## 当前基础与缺口

统一实验室已经以 `ExperimentMessage.payload` 保存用户输入的一部分配置：

- 图片消息保存 `model_id` 和 `reference_file_ids`。
- 视频消息保存 `model_id`、`ratio`、`frame_references` 和 `subject_references`。
- 文本消息保存 `model_id` 和最终文本内容。

基础的图片参考图、视频关键帧和主体参考现已可恢复。图片和视频的新消息会写入版本化输入快照；文本新消息会保存模型和最终提示词快照。仍待补齐的是模板 ID、模板变量，以及图片的全部可选生成参数快照。

## 当前进度

- 已完成：历史用户气泡回填、文本/图片/视频的提示词与模型恢复、图片参考图恢复、视频具名帧与主体素材恢复、旧 payload 降级读取。
- 已完成：图片和视频任务在 user/task 消息中写入 `payload.input_snapshot`。
- 待推进：模板与变量的无损恢复、图片可选生成参数的端到端快照、针对模型或文件失效的更细粒度诊断提示。

## 交互约定

1. 仅用户角色的历史气泡可恢复；模型回复和任务状态气泡不可恢复。
2. 用户点击气泡中的“回填并重试”操作后，将配置回填到当前编辑器并聚焦提示词输入框。
3. 回填**不会自动调用生成接口**。用户必须点击“生成”确认，避免误触产生模型调用成本。
4. 可点击气泡要提供键盘可达的按钮语义；图片预览、视频预览和引用删除等嵌套交互不得意外触发回填。
5. 如果历史模型已删除、文件已不可访问，页面保留其余可用输入，列出未恢复项并阻止或提示用户补齐后再生成。

## 数据契约

在 `app/core/contracts` 新增版本化的 `ExperimentInputSnapshot` 契约，作为跨 API、任务编排和前端恢复共同使用的输入快照。快照应放入用户消息和对应任务消息的 `payload.input_snapshot`：

```json
{
  "version": 1,
  "model_id": "...",
  "prompt": "...",
  "template": { "id": "...", "values": { "subject": "..." } },
  "image": {
    "reference_file_ids": ["..."],
    "target_ratio": "16:9",
    "resolution_profile": "standard"
  },
  "video": {
    "ratio": "16:9",
    "frame_references": {
      "first_frame_file_id": "...",
      "last_frame_file_id": "...",
      "key_frame_file_ids": ["..."]
    },
    "subject_references": [
      { "name": "角色", "image_file_ids": ["..."], "video_file_ids": [] }
    ]
  }
}
```

旧字段在读取时继续兼容：图片读取 `reference_file_ids`，视频读取已有 `frame_references` 与 `subject_references`，文本至少恢复消息正文和 `model_id`。新写入一律使用快照；不需要数据库迁移，因为 `payload` 已是 JSON。

## 实施阶段

### 阶段 1：后端持久化契约

1. 在 `app/core/contracts` 定义并校验版本化快照及图片、视频子结构。
2. 调整文本、图片、视频实验室创建接口：生成用户消息和任务消息时写入同一份快照。
3. 保留既有 payload 字段一段兼容期，读取端优先消费 `input_snapshot`。
4. 覆盖快照写入、旧消息降级读取和文件 ID 顺序保留的服务测试。

### 阶段 2：前端恢复能力

1. 新增共享的历史用户消息操作组件，只负责可访问的“回填并重试”触发与恢复提示展示。
2. 新增模态无关的快照解析/兼容辅助函数；模式组件仅实现自己的草稿状态回填。
3. 文本模式恢复模型和提示词；若模板仍存在则恢复模板与变量，否则将最终提示词作为自由输入。
4. 图片模式恢复模型、提示词、参考图和图片参数；不可用文件从选择中移除并展示数量与名称。
5. 视频模式恢复模型、提示词、比例、具名帧和主体参考；按恢复后的模型 capability 重新校验主体/关键帧互斥与数量上限。
6. 回填后滚动并聚焦 `ExperimentPromptEditor`，但不提交任务。

### 阶段 3：验证与发布

1. 后端测试三种模态的快照持久化与旧 payload 兼容。
2. 前端验证文本、图片和视频各自的恢复映射；覆盖文件缺失、模型删除、模板删除、运行中任务和主体/关键帧冲突。
3. 手工验证恢复后编辑、确认生成、历史不被覆盖，以及新任务与原任务独立。
4. 若 API 响应或请求 DTO 因快照变更而调整，运行 `pnpm run openapi:update` 并完成前端 generated types 校验。

## 验收标准

- 悬浮任意历史用户输入时显示其右下外侧的回填图标；单击图标可进入可编辑的回填态，且不会自动创建任务。
- 图片历史恢复后，参考图按原顺序回填到图片参考区。
- 视频历史恢复后，首帧、尾帧、关键帧和主体图片/视频恢复到各自的语义位置。
- 恢复后再次生成产生新的历史消息和独立任务，不覆盖原记录。
- 历史数据缺失时有明确提示，不静默丢失或错误映射素材。
