## 1. 目标与范围

本计划承接已完成的[场次工作台紧凑布局与试拍检查优化计划](/docs/plans/sequence-workbench-compact-review/)。保留紧凑顶部、问题优先、指令详情面板、公共布局和精确上下文保护，进一步解决步骤顺序不清、检查页内容不足、版本命名误导以及执行与候选展示重复的问题。

推荐结构为：**拍摄准备 → 指令检查 → 试拍与候选**。第三步同时承载明确提交、任务反馈与产出浏览；正式审片、实际覆盖、可用区间、采用及粗剪继续由“剪辑验收”负责。

- 沿用品牌、全局图标栏、面包屑、业务侧栏和三个制作阶段，不重做全站外壳。
- 本轮调整单元试拍内部步骤、检查状态、指令命名和候选浏览；复用上一计划提取的公共展示组件。
- 实施后替代上一计划中的“四个工作区”“非准备页共用检查对象栏”和“候选以跳转按钮展示”规格，其请求恢复、冻结版本、历史只读及编辑保护规则继续有效。
- 旧计划保留原验收记录；当前架构和指南在本计划实施时按真实行为更新，不提前把未来方案写成现状。
- 不新增独立的流程状态机，不扩展为提示词编辑器、全功能素材管理器或第二套剪辑工作台。

## 2. 评估事实与决策

### 本轮五项问题的方案结论

1. **顺序表达**：采用三个可回看的步骤“拍摄准备 → 指令检查 → 试拍与候选”。执行与结果放在同一步，避免生成后再切换一次页面；步骤选中不代表业务完成。
2. **检查页空间**：按实际检查状态展示准备摘要、记录选择、检查进度或问题处理内容；“检查对象”只是紧凑上下文，不能成为整页唯一内容。通过项保留折叠摘要。
3. **指令命名**：设计与指令并非一对一。版本范围限定在同一拍摄计划和单元；单份显示“本次指令”，多份显示稳定的“指令 vN”，不使用全场列表位置冒充版本。
4. **职责边界**：检查页负责检查与确认；第三步负责显式开拍、任务反馈和产出浏览；正式审片、可用区间和采用仍在剪辑验收完成。
5. **候选呈现**：默认真实视频缩略图网格，提供列表切换、真实时长、来源及独立的审片／采用状态；右侧快速预览，进入剪辑验收时保留精确候选上下文。

本节记录评估结论；实际实现、验收证据和验证边界见第11节。

## 4. 三步导航与状态规则

| 步骤 | 核心问题 | 内容与出口 |
| --- | --- | --- |
| 1 拍摄准备 | 本次拍什么、用什么拍 | 动作范围、模型、时长、画幅、参考和必要依赖；保存并确认准备 |
| 2 指令检查 | 执行文本是否符合固定依据 | 生成或选择指令、查看依据、检查问题、确认结论；进入试拍 |
| 3 试拍与候选 | 本次提交怎样了、产出了什么 | 执行摘要、明确开拍、任务反馈、候选网格及快速预览；进入剪辑验收 |

### 4.1 浏览与进度分别表达

- 首次生产遵循先后条件，后续可回看任一步骤。点击步骤只导航，不确认、不生成、不提交视频。
- 当前浏览步骤使用选中态；完成、待处理、运行或待核实依据真实业务记录显示，不用当前页序号推断前面全部完成。
- 第二步状态绑定精确指令及所选检查；人工取舍按真实记录标明，不伪装为自动全部通过。
- 第三步可以同时“生成中”且“已有3个候选”，也可以“本次失败”但保留历史产出；不压成一个完成布尔值。
- 不因新指令未检查、提交失败或任务状态暂不可用而禁止浏览合法历史候选。
- 修改已确认准备或设计继续走版本派生，新依据需要重新编译和检查；旧候选仍保留在原计划与单元范围，不直接迁移到新版本。

### 4.2 主操作与导航

- 主操作与当前浏览步骤一致。准备页处理准备，检查页处理指令或结论，第三步处理开拍、运行或核实；不在候选旁继续显示无关的全局检查主按钮。
- 前置条件不足时，第三步显示原因及“去检查”等定位入口，保留候选浏览；不能用无解释的禁用按钮占据全部反馈。
- 准备确认或结论确认等明确推进动作成功后可进入下一步，但确认结论绝不自动开拍。
- 后台任务结束只更新任务状态与候选数量，不抢占用户正在阅读的步骤、素材或播放位置。
- 桌面保留短步骤名、编号或状态标记及连接线；窄屏显示“第2步／共3步 · 指令检查”并提供切换入口，不挤压为难以点击的三个小标签。
- 步骤状态不只靠颜色区分；可用键盘导航，选中内容具有可访问名称，切换后焦点和滚动遵循现有保护规则。

## 5. 指令检查页的状态内容

主区承担当前检查工作。指令正文、完整固定输入和来源映射继续按需进入详情面板，不通过铺满正文来填补空白。

| 状态 | 主区表达 | 主要动作 |
| --- | --- | --- |
| 准备未确认 | 未满足的准备条件及定位入口 | 返回拍摄准备 |
| 尚无指令 | 已确认准备的简要依据，生成后需检查的说明 | 生成试拍指令 |
| 有指令但未选择 | 在主区展示当前范围内的合法记录及状态；单份无需先进入历史抽屉才能找到 | 明确使用此指令；多份时明确选择 |
| 指令已生成、未检查 | 动作范围、参考概况、六岗检查范围及待检查状态 | 开始检查 |
| 多条检查但未选定 | 紧凑记录列表，显示保存状态、结果概况及可用时间 | 选择检查记录 |
| 检查运行中 | 精确任务的排队或执行状态；取消请求与终态分开 | 等待或请求取消 |
| 检查有问题 | 问题、观察、建议及处理入口；通过项仍折叠为摘要 | 处理首个问题；可单独保存结论 |
| 完整通过但未确认 | 简洁通过摘要、真实保存状态和确认说明 | 确认结论并进入试拍 |
| 结论已确认且可执行 | 当前检查对象、已确认结论及后续入口 | 进入试拍 |
| 失败、记录不完整或读取异常 | 对应原因、仍可查看的已有内容和恢复入口 | 按实际情况重试读取、重新检查或核实请求 |

- 动作和参考摘要必须来自所选指令固定依据；尚无指令时才使用已确认准备，不能以当前较新编辑冒充历史输入。
- 唯一明确编译响应继续定位其真实产出；多个合法记录且无明确选择时不自动挑最新。隐藏多余版本控件不等于隐式改变选择规则。
- 有检查记录但尚未选定必须展示记录选择内容；无记录、未选择、加载中、读取失败分别处理，不再出现仅剩对象栏的无解释状态。
- 保留六岗位乘以出现对象的完整性校验，待检查和缺失行不视为通过。问题分组、原始结论、人工取舍、映射缺失说明沿用上一计划。
- 没有真实任务百分比或预计完成时间时只显示实际状态，不模拟进度。
- 请求结果未知先核实原请求；重新检查与重试读取不同，不能用重复提交掩盖状态读取失败。

## 6. 设计、计划、指令与候选的关系和命名

### 6.1 真实关系

- 一个设计版本可以关联多个拍摄计划；每个计划固定一个设计版本，并包含多个拍摄单元。
- 单元身份为`plan_revision_id + unit_id`，不能跨计划按同名动作合并。
- 每个单元可有零到多份指令快照；每份指令固定一个计划版本和单元，可关联多次检查及多次试拍。
- 一次任务可以没有成功产出，也可以登记多个输出，不假定任务、候选一一对应。
- 每份候选保留其真实指令、计划、单元、任务和输出身份，不能因为切换当前指令而重新归属。

### 6.2 可读命名

| 对象或场景 | 展示规则 |
| --- | --- |
| 计划上下文 | 使用“拍摄计划03 · 已确认”等身份名称；列表序号不自动改称“第3版” |
| 当前范围只有一份指令 | 主区显示“本次指令 · 待检查”等状态，弱化版本号，隐藏多余切换控件；详情仍可追溯 |
| 当前范围有多份指令 | 显示“本次指令 v2 · 共3版”，版本号限定在当前确定的计划与单元范围 |
| 指令历史 | 稳定版本号、真实可用时间、检查状态和有依据的差异；无差异可标注“正文相同”，不编造更新原因 |
| 候选来源 | 当前范围内显示“来自指令 v2”；跨计划查看时补充计划与单元 |
| 检查记录 | 独立显示记录身份及保存状态，不能与指令版本号混用 |

- 版本名须绑定稳定身份，同一范围内不能因排序、筛选、刷新、重进页面或切换阶段而重编号；主区、历史、任务与候选来源统一使用同一命名规则。
- 当前`RevisionSnapshot.version`用于同一草稿的并发修改校验，不能直接作为这里的指令v1/v2，也不能代替确认版本派生关系。
- H1需落实稳定编号的来源及旧记录规则：先核实能否由完整、不可变记录集可靠取得；若不能证明追加与恢复稳定，则提供最小必要的持久编号或读契约，不依赖当前过滤列表位置和客户端临时计数。
- 旧记录无时间或差异依据时明确显示不可用，不伪造创建时间，不显示原始ID代替名称；技术身份仍可在详情中查看。
- 当前编译可能产生正文相同的不同快照。v2代表该范围内的另一份指令记录，不承诺内容更优或创作方向不同；本轮不隐式去重、删除或合并旧记录。

### 6.3 三种动作必须区分

| 动作 | 结果与约束 |
| --- | --- |
| 同指令再拍一次 | 使用明确选择且满足执行条件的指令与检查，创建新的试拍请求；不重新编译、不替换候选 |
| 重新生成指令 | 保留旧快照，生成新的指令记录并重新检查；不称为生成另一个创作方案 |
| 修改准备或设计 | 沿用版本派生规则，重新编译和检查新依据；不修改原指令、检查或候选 |

历史预览仍然只读；只有“切换到此版本”改变当前工作对象。浏览、选择、确认和开拍是不同动作，候选不会自动采用。

## 7. 合并后的试拍与候选工作区

### 7.1 三个纵向区域

1. **执行依据摘要**：当前准备提交的指令、检查状态、模型、时长与画幅，以及“查看执行依据”。不重复指令版本选择器和完整检查记录列表。
2. **当前任务反馈**：准确标明本次请求使用的依据、排队／运行／失败／取消／待核实状态，提供适用恢复动作。历史任务从既有任务入口查看。
3. **候选素材区**：当前计划与单元的真实产出，支持筛选、快速预览和进入剪辑验收。

- 有明确合法输入且无阻塞任务时提供“开始试拍”；已有产出时“同指令再拍一次”沿用同一提交规则，不保留两个重复主按钮。
- 运行中的任务固定其提交时依据。即使用户查看另一份指令，也不能把运行任务的来源名称替换为当前选择，或隐藏仍在运行的本单元任务。
- 生成成功直接将真实登记结果加入候选区；不额外切换Tab，不自动选中或播放新素材。用户可通过“查看新候选”定位。
- 生成失败或取消不产生假候选卡，不移除旧素材。取消请求发出后仍等待服务端终态，提交响应丢失继续核实原请求。
- 无候选时显示具体下一步：尚未具备条件则定位准备或检查；正在生成则显示任务；已失败则显示原因和适用恢复入口。
- 从旧候选打开历史执行依据不能改变下一次提交所用指令。“按这份指令再拍”如提供，必须明确切换和重新核对条件，不能由预览隐式触发。

### 7.2 与剪辑验收的边界

第三步允许浏览、筛选、播放和查看来源。正式审片、实际覆盖标注、可用区间、采用、粗剪与接缝判断继续只在剪辑验收进行，不在快速预览中复制这些编辑功能。

“进入剪辑验收”传递精确候选身份并定位对应素材。返回时恢复计划、单元、步骤、候选选择、筛选与主区位置。预览只是浏览，不写入审片或采用状态。

## 8. 候选素材展示与媒体能力

### 8.1 卡片与列表

默认紧凑缩略图网格，支持切换列表；两种视图使用同一集合、排序、选择和筛选语义。

- 每张卡显示真实视频缩略图、播放入口、可读候选编号、实际时长和指令来源。
- 审片与采用状态分别展示。采用状态依据当前有效粗剪读取，未知或读取失败不默认为未采用。
- 显示“全部候选／当前指令”等筛选及数量，默认不因切换指令隐藏本单元旧产出；“全部”明确限定为当前计划与单元。
- 新候选追加、排序或筛选不能改变已有候选名称，也不能使所选素材突然换成另一条记录。无匹配结果与没有产出分别表达。
- 参考图、设计图和预演卡不能充当真实候选缩略图。缺失缩略图使用明确占位，点击仍尝试播放合法素材。
- 实际时长不可用时显示未知；计划时长只能单独标为计划值，不用来填充实际时长。
- 大量候选按需加载、分页或虚拟化，避免每张卡同时建立播放器、下载完整视频或执行重复取帧；具体方式以现有列表能力和验证结果选择。

### 8.2 快速预览与缩略图

- 桌面右侧面板显示所选视频、来源、真实时长、审片与采用状态及“进入剪辑验收”。窄屏使用可关闭抽屉，沿用公共详情容器。
- 初始加载不自动播放。切换素材停止上一视频，关闭后恢复触发位置；请求迟到不能把前一素材画面或信息放到当前素材下。
- H3先核实既有文件预览、取帧和缓存能否复用。缩略图必须从真实视频派生；必要时补充受同等访问控制的媒体读取或缩略图契约，并同步generated client。
- 派生缩略图是媒体预览缓存，不创建新的业务资产、Take、参考关联或采用记录，不触发付费生成；不能用已有“保存画面为参考”写入流程替代自动缩略图加载。
- 缓存与失效绑定真实文件身份，失败可重试，不能造成每次页面进入都重复取帧。媒体加载失败与业务记录存在分别表达。
- 当前接口没有的尺寸、创建时间、费用、模型进度等字段不先作为必填展示；仅在有可靠来源时展示。
