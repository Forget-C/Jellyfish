# 章节信息与原文选区划场优化计划

> 状态：已完成。P1–P4 已落地，实施结果、验收证据及检查限制见第 8 节。前序[章节列表与场次抽屉交互优化计划](/docs/plans/chapter-list-and-sequence-drawer-plan/)的完成状态和验收记录保留。
>
> 用户约束：章节页继续以章节表格为主体；场次管理采用左右分栏；不增加跨章节的待核对数量、粗剪数量，也不新增对应统计列、顶部汇总或逐章请求。

> 后续调整见[章节入口与整章划分工作流优化计划](/docs/plans/chapter-division-workflow-plan/)（已完成）：入口与 AI 展示已调整，并以整章草稿、影响预览和原子保存替换逐场范围提交。本文保留逐场保存阶段的完成范围与验收记录。

## 1. 评估依据与目标

以下事实来自 2026-09-29 工作区代码核对；交互效果判断属于设计评估，尚无本轮用户测试结论。

| 用户反馈 | 当前事实 | 方案决策 |
| --- | --- | --- |
| 章节表格信息少、留白多 | 当前实际为名称、场次数量、操作三列；字数位于名称副行，名称占据剩余宽度 | 改为五列，增加原文预览并独立展示字数，控制名称列宽度 |
| 场次管理打开后详情为空 | 仅恢复有效的历史选择，没有历史选择时不默认选中 | 显式场次 → 有效历史选择 → 按顺序排列的第一场 |
| 原文编辑入口重复 | 章节名称、抽屉“编辑章节”、原文面板“编辑原文”打开同一个编辑器；详情中的“原文范围”修改的是场次引用 | 收敛正文编辑入口；范围编辑独立命名并改为原文选区 |
| 划场入口较深 | 从章节主表进入场次管理，再进入“原文与划场”，才能选择 AI 分析或手动新建 | 表格行直接提供“划分场次”，场次管理顶部保留同一功能入口 |
| 手动划场缺少全章对照 | 新建表单预填整章原文，再由用户手工修改摘录；范围编辑也是文本框 | 在完整原文上选择连续范围，显示已划分、候选及未分配内容 |

目标：章节表格负责比较和进入任务；场次管理负责逐场查看与轻量编辑；划场视图负责在完整原文上确定场次范围。设计、试拍、剪辑与验收继续由独立场次工作台承担。

实现依据：

- `front/src/pages/aiStudio/project/ProjectWorkbench/tabs/ChaptersTab.tsx`：表格、章节编辑和场次管理入口。
- `front/src/pages/aiStudio/directing/ChapterSceneList.tsx`：选择恢复与逐场摘要。
- `front/src/pages/aiStudio/directing/ChapterSourcePanel.tsx`、`SequenceDetails.tsx`：AI 建议、手动创建、范围保存。
- `front/src/pages/aiStudio/directing/common.ts`：已有连续摘录、重复文本及 Unicode 位置处理。
- `backend/app/core/contracts/directing/workspace.py`：单个连续范围、原文版本及场次版本契约。
- `backend/app/services/directing/workspace.py`：范围写入、归属和版本校验；当前没有场次间范围重叠校验。

## 2. 范围与成功标准

本轮包含五列表格、场次默认选择、入口整理、完整原文范围选择、手动创建与范围调整、AI 候选原文预览及逐场确认。将“新建或调整后的有效范围不与同版本其他场次重叠”作为本轮新增规则，前后端共同校验；允许暂时存在未分配原文。

成功标准：

1. 无需打开章节即可比较名称、原文预览、字数和场次数量，主表直接进入划场。
2. 有场次时，打开管理面板即显示有效场次详情；保留左右分栏和连续切场。
3. 用户能区分修改正文与调整场次范围；普通范围调整不再要求手填摘录或数字偏移。
4. 在完整原文中能定位当前范围、观察其他场次归属、框选新范围并准确保存。
5. AI 与手动共用范围视图和校验，AI 候选经过确认才成为正式场次。
6. 重复文本、Unicode、版本变化、冲突及离开页面均不会造成误定位、静默覆盖或输入丢失。

本轮不包含：

- 跨章节待核对数量、粗剪数量、生产完成率及相关汇总接口。
- 章节原文编辑器重做、自动修改正文、自动更新设计/计划、自动拍摄或采用素材。
- 一个场次引用多个不连续范围、自动拆分或合并已有场次、自动移动相邻场次边界。
- 整章“一键保存所有划分”或批量替换已有场次；其原子性要求见第 5 节。
- 为展示更新时间而扩展后端字段。当前前端映射的加载时间不是真实更新时间，禁止用作表格信息。
- 将本轮待实施方案写入当前架构事实，或改写前序验收和固化 release note。

## 3. 页面与入口设计

### 3.1 章节主表

| 列 | 展示 | 操作与空状态 |
| --- | --- | --- |
| 章节名称 | 序号与名称，约占桌面可用宽度的 20%–25% | 点击“编辑章节”；过长名称截断并可查看全文 |
| 原文预览 | 原文开头最多两行，承担弹性宽度 | 无正文显示“未填写原文”；不冒充 AI 摘要，不自动发起摘要生成 |
| 原文字数 | 从现有原文计算，口径与原文编辑器保持一致 | 无正文显示 0；未知或读取失败不伪装为 0 |
| 场次数量 | 沿用可靠的 `sequence_count` | 点击进入场次管理；`0 场`可点击，未知时显示“查看场次” |
| 操作 | “划分场次”为主要操作，章节组合为次要操作 | 直接打开本章划场视图，无需先进入场次管理 |

- 保留分页、搜索、表格滚动恢复；不将整行变为点击区域。
- 预览和字数复用已有列表数据，不为填充表格逐章请求详情、概览或工作台。
- 窄屏优先收起原文预览、压缩次要操作，保留章节名称、场次数量及划场入口；不以增加整页横向滚动承载新增列。
- “划分场次”进入后显示已有结果；有场次时不默认重划或重新分析。无原文时引导填写原文。

### 3.2 场次管理默认选择

- 完成本章读取后，按“显式链接中的场次 → 本章有效历史选择 → 按 `position` 排序的第一场”确定选择。
- 显式对象不存在或归属不符时展示错误和返回入口，不自动换成另一场；过期历史记忆可回退第一场。
- 默认选择只读取数据，不保存、不核对来源、不触发任务；已有用户选择和未保存草稿不被后台刷新或迟到响应覆盖。
- 自动选择只在打开面板且没有有效选择时执行。窄屏主动“返回列表”后保持列表，不因刷新再次跳进详情。
- 桌面保持左侧列表、右侧详情；窄屏默认打开所选详情并提供“返回场次列表”。
- 恢复的搜索条件若隐藏了当前场次，明确提示并提供清除筛选，不暗中切换当前场次。零场次与无搜索结果分别展示。
- 零场次时显示“开始划分场次”；保存第一场后选中并展示该场，创建成功同时刷新主表数量。

### 3.3 正文编辑与范围调整

章节名称是常驻的“编辑章节”入口。移除场次管理工具栏的重复“编辑章节”和原文卡片中的重复“编辑原文”按钮；无原文、原文需要修正等明确上下文可提供前往同一编辑器的引导，仍执行相同保存保护。

场次详情保留名称、顺序、阶段跳转和保存能力；原文范围改为只读摘录与“在原文中调整范围”按钮。该按钮直接打开划场视图，定位当前场次并进入调整状态，不改变正文。

章节编辑器继续展示“改变章节内容后不会自动更新场次”。已有原文影响确认、保存失败保留输入、返回本章核对等行为不得因入口收敛而丢失。

### 3.4 完整原文划场视图

复用现有 `panel=source` 导航，名称改为“划分场次”。从章节行、场次管理顶部、详情范围按钮进入同一个视图；详情入口携带当前场次。旧链接和工作台返回继续可用。

使用同层全宽面板或现有抽屉的全屏模式，不在场次抽屉上叠加范围编辑弹窗。返回时恢复进入前的场次、筛选、滚动和焦点。

| 区域 | 内容 |
| --- | --- |
| 顶部 | 章节身份、AI 划分／手动划分切换、返回入口；打开页面不自动分析 |
| 左侧 | 本章场次列表，显示名称及可定位状态；点击定位到正文范围 |
| 中间主体 | 完整章节原文，保留真实换行；场次浅色高亮与开始/结束标签 |
| 右侧 | 当前场次或候选名称、只读选中摘录、调整及确认保存操作 |

- “【场次 1 开始】……【场次 1 结束】”是视觉装饰，不写入原文，也不计入选区偏移；零长度范围不能保存。
- 已保存场次、当前编辑草稿、AI 候选明确区分，不能只靠颜色区分状态。未分配文本保留普通底色并提供说明，范围冲突就地标记。
- 点击场次定位原文；点击已有范围可选择场次；拖动选择文本时不触发误跳转或清空选区。
- 中间正文是阅读与选择表面，不提供正文自由编辑。保留整章上下文，不只显示当前摘录。
- 窄屏在同一面板切换列表、原文、当前选区信息，保留选择和滚动，不将桌面三栏硬挤在一行。

## 4. 手动划分与 AI 划分

### 4.1 手动划分和调整

1. 在完整原文上选择一段连续文本；可跨段落，也可在段落内部确定起止位置。
2. 选择“新建场次”或“设为当前场次范围”。调整入口默认绑定原场次，新建入口不得默默覆盖已选场次。
3. 展示名称、选中摘录、范围高亮及冲突提示。允许重新选区和取消，保存前均为本地草稿。
4. 显式确认保存；成功后刷新场次列表、原文标记及相关详情，新建时刷新主表数量。保存后留在当前视图，便于继续划分。

- 新建不再把整章原文预填为场次范围；不要求用户粘贴摘录或输入起止偏移。
- 已有范围调整时先定位并高亮当前有效范围；旧版本范围按第 5 节处理。
- 鼠标框选之外，提供可聚焦的文本位置与“设为开始／设为结束”等等价操作，支持键盘及触屏；不能只有鼠标拖动一种方式。
- 本轮一次保存一个场次，不连带修改相邻场次。不做拖拽共享边界同时修改两场的交互。
- 未保存选区、名称和待确认范围纳入已有草稿保护；切换模式、切场、返回、关闭、后退及进入工作台均不能静默丢弃。

### 4.2 AI 划分

- 显式点击“开始 AI 分析”才提交现有分析任务。进度、失败和结果在划场视图可达；历史记录仍放章节活动，不铺满正文区域。
- AI 返回的标题、摘录和目的作为候选；根据当前分析所依据的原文定位候选范围，在同一完整原文上预览。
- 摘录不存在时显示“无法定位”；多处相同文本时列出候选位置及上下文，用户明确选择，不默认取第一次匹配。
- 用户可选中候选、调整标题和范围，并“确认创建场次”。确认前不增加正式场次数量，不自动覆盖已有场次。
- 候选与已保存范围或其他候选重叠时可预览并调整；与正式场次冲突时不能直接创建。逐场确认后保留其他候选和查看位置，重新校验后续候选。
- 原文版本变化使分析结果过期，禁止直接用旧结果创建；保留旧结果供查看，并提供重新分析入口。
- 切换 AI／手动不隐式执行任务、不清空待保存选区；两种模式复用同一范围定位、预览和保存校验。

## 5. 数据、校验与实现边界

### 5.1 复用现有范围契约

- 继续使用 `SourceSpan(start, end)`、`source_version`；更新场次同时提交 `expected_version`，通过 OpenAPI generated client 调用现有单场次接口。
- 一个场次对应一个连续半开区间 `[start, end)`，要求非空、未越界且确实来自当前原文，不保存用户改写的独立摘录。
- 后端范围采用 Python Unicode 字符索引，浏览器原生选区使用 UTF-16 偏移。建立显示文本节点与真实原文位置的映射并转换；跨节点、换行、emoji 和辅助标签均需验证。
- 不对原文预先 `trim`、折叠空白或替换换行后再计算位置；边界装饰不得进入文本映射。不得把显示字数直接作为范围偏移。
- DOM 选区的位置是用户选择的依据；不能将选中文本再搜索并默默使用第一次匹配。复用 `common.ts` 中已有重复文本与 Unicode 处理，而不沿用手填摘录作为唯一输入。

### 5.2 重叠、未分配与旧版本

- 当前实现没有不重叠保证；本轮在 service 层、与范围写入相同的事务及章节锁内补充校验，防止并发创建绕过前端检查。
- 新建、调整或重新确认后的范围，不得与其他已绑定当前原文版本的场次相交；相邻范围首尾相接合法。修改时排除当前场次自身。
- 已有重叠数据不自动删改；完整原文显示冲突，用户逐场调整。无关场次不因其他位置的历史冲突被禁止保存。保持原有范围不变的名称/顺序修改不承担修复所有历史重叠的职责。
- 允许存在未分配段落，在本章原文中提示；不要求一次覆盖整章，不新增章节生产完成率，也不把“已有场次”表述为“划分完成”。
- 原文版本变化后，旧偏移不得直接绘制到新正文。显示“需要重新定位”及旧摘录；可将唯一精确匹配作为待确认候选，多处匹配由用户选择，不能自动消除 `source_changed`。
- 不使用旧版本偏移参与当前原文重叠判断；有未定位场次时明确显示不确定范围，不能宣称全章已无冲突。旧场次重新确认到当前原文时重新校验重叠。
- 仅编辑名称/顺序不得顺带确认新的原文范围或清除过期状态。实施时核对现有更新接口的写入语义；如需支持过期范围下独立改名/排序，明确调整契约，否则引导先显式核对范围，不以原样回传旧偏移代替核对。
- 保存失败或版本冲突保留输入、已选摘录和重试说明；重新读取后不自动重放旧偏移。草稿未处理前，后台响应不得覆盖用户正在编辑的数据。

### 5.3 组件、接口与后续扩展

- 在 `directing` 下抽取被手动创建、范围调整和 AI 确认共同使用的原文范围选择组件，集中维护文本映射和高亮；不引入通用富文本编辑器或新的范围数据模型。
- 复用 `ChapterSourcePanel` 的任务和建议逻辑、`SequenceDetails` 的场次上下文、既有导航与 `WorkspaceDrafts`。只修改本次受影响的职责，删除本次替换后失效的摘录输入代码。
- 范围选择本身不要求新接口，但重叠校验改变外部接口语义。实施时同步受影响的后端契约说明、OpenAPI、generated client 和文档；先确认 `127.0.0.1:8000` 加载当前工作区，再运行 `pnpm --dir front run openapi:update`。
- 整章批量确认、批量替换或同时移动相邻边界属于后续扩展：需要章节级事务、原文版本及全部受影响场次版本校验，整体成功或整体失败。不能用多次单场次调用承诺原子保存，也不能将部分成功显示为整章成功。该扩展不计入本轮完成条件。

## 6. 实施任务与验证方式

先完成入口和默认行为，再完成手动选区及服务端规则，最后把 AI 候选接入同一视图。每步通过受影响检查再推进；不将已有测试结果当成本轮新实现的验证结果。

| 任务 | 实施内容 | 验证方式 |
| --- | --- | --- |
