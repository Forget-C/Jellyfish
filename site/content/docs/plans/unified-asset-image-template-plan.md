# 统一资产图提示词模板实施计划

## 背景与问题

> 状态（2026-07-19）：演员、角色、道具和服装已完成统一模板迁移；本文保留实施决策和场景图不纳入范围的边界。

历史上，演员图片由 `actor_image_front` 与 `actor_image_other` 两个模板类别分别生成。两套模板重复维护人物质量、风格、构图和负面提示，只有视角、身份继承和参考图说明不同；这会造成规则漂移。

现有默认演员模板还以“电影级”“电影剧照”“故事感”“浅景深背景虚化”为核心描述，导致演员资产图被模型理解成剧情画面而非可复用的人物设定图。

演员、角色、服装和道具均已按同一模式收敛。场景图不纳入本计划：场景本身需要环境信息，不适合使用纯背景展示约束。

## 目标

1. 演员正面、左侧、右侧、背面只使用一个 `actor_image` 模板类别。
2. 视角与参考图关系由后端从业务数据计算；构图、背景、细节强调与负面约束由模板默认值驱动，并可在受控范围内覆盖。
3. 默认演员图定位为“单人资产设定肖像”：统一纯净背景、清晰人物细节、无剧情环境；分镜帧仍可使用电影化提示词。
4. 每次模板内容或默认变量变更时自动递增版本号；每次生成记录所用模板版本和最终提示词，以便追溯，但不提供历史版本管理。
5. 迁移过程彻底移除旧演员模板类别及其数据，不保留读取回退。
6. 角色、服装和道具复用同一变量协议，但维持各自独立的视觉模板，避免主体/构图规则互相污染。

## 非目标

- 不把多角度图合成为单张拼图，也不引入自动裁切。
- 不改变资产图片的多张、多角度数据模型或前端生成入口。
- 不改变场景图、分镜帧和视频提示词的“电影叙事”职责。
- 不在本次强制重生成既有图片。

## 目标契约

### 新模板类别

新增 `PromptCategory.actor_image = "actor_image"`，并将其作为演员图片的唯一分类。完全移除 `actor_image_front` 与 `actor_image_other`：从后端枚举、前端 generated types、提示词分类 API 和数据库模板数据中删除，不保留读取回退。

已生成的演员图片和已完成任务不受此删除影响：它们保存的是文件关联、图片视角、模板版本和最终提交的任务载荷，不会在展示或使用时重新按旧模板类别渲染。开发期直接清理未完成的旧演员图片任务，不保留运行时兼容。

后续同构类别预留为 `character_image`、`costume_image`、`prop_image`；不要在第一阶段直接创建一个笼统的 `asset_image`，以免人物、服装和道具的主体/构图约束互相污染。

### 模板变量

演员模板使用以下稳定变量。变量按来源分为“业务事实”和“可配置规范”：前者保证资产数据语义正确，后者是提示词管理的主要价值，模板可为其提供默认值并允许用户覆盖。

| 变量 | 示例 | 责任 |
| --- | --- | --- |
| `name` | 林晚 | 资产名称 |
| `description` | 26 岁，短发… | 外观事实来源 |
| `tags` | 冷静、调查员 | 辅助识别特征 |
| `visual_style` / `style` | 写实 / 民国 | 项目风格边界 |
| `view_angle` | 正面、左侧、背面 | **业务事实**：图片记录的视角，不可手工伪造 |
| `reference_instruction` | 使用随请求附带的正面参考图… | **业务事实**：由实际附带参考图决定，不可声称不存在的参考图 |
| `pose_instruction` | 正面直视镜头，站立放松 | **系统建议**：按视角给出默认值，可在允许范围内覆盖 |
| `visible_detail_instruction` | 清楚呈现五官、发际线… | **系统建议**：按视角给出默认值，可补充本资产需强调的特征 |
| `framing_instruction` | 三分之二身，人物占画面 70%–80% | **模板默认值**：可改为全身或头像构图 |
| `background_instruction` | 低饱和浅灰摄影棚背景 | **模板默认值**：可改为米白、深灰等受控棚拍背景 |
| `lighting_instruction` | 柔和均匀的棚拍布光 | **模板默认值**：可在资产设定图范围内调整 |
| `negative_prompt` | cinematic still, complex background… | **模板默认值**：可增补或恢复默认 |

服务端应直接传入完整的文本变量。即使模板引擎支持 Jinja 条件，也不要让默认模板依赖 `is_front_view` 等布尔分支；这能避免布尔值字符串化后的渲染歧义，也方便前端预览变量。

### 覆盖层级与恢复默认

变量值必须有明确优先级，避免用户不知道一段提示词来自哪里：

1. **业务事实层（只读）**：`name`、`description`、`view_angle`、实际参考图及 `reference_instruction`。后端从资产和图片记录读取，前端只展示来源。
2. **系统视角建议层**：`pose_instruction`、`visible_detail_instruction`。后端提供按视角的默认值；允许用户填写补充指令，但不能改变 `view_angle` 与参考图事实。
3. **模板默认层**：`framing_instruction`、`background_instruction`、`lighting_instruction`、`negative_prompt`。模板管理页负责编辑和“恢复系统默认”；每次修改自动递增 `version`。
4. **图片规格覆盖层**：某一视角图因全身展示、背部服装细节等需要产生的持续调整；保存到对应 `ActorImage` 的 `prompt_overrides`，可逐项“恢复模板默认”。不放在 `Actor` 上，避免一个背面图的要求影响所有角度。
5. **单次生成层**：本次任务临时补充的指令；不回写资产，任务完成后失效。

最终渲染时以 `单次生成 > 图片规格覆盖 > 模板默认 > 系统建议 > 业务事实` 合并；其中业务事实不可被同名覆盖。预览必须逐项标注值与来源，并提供“恢复图片默认”“恢复模板默认”两个明确动作。

### 产品对象与用户入口

首期不把变量直接暴露成完整的提示词表单，而是提供一个“演员设定图”生成预设：默认是 **身份肖像**，包含三分之二身、纯净棚拍背景和均匀布光。普通用户只选择视角，并可在“调整展示方式”中选择有限的构图/背景选项；高级展开才显示细节强调与负面约束。

提示词管理页面向高级用户或管理员，管理的是预设背后的模板内容和默认变量，不是普通资产编辑的必经步骤。生成页必须展示人类可读的摘要，例如“身份肖像 · 背面 · 使用正面参考图 1 张”，最终提示词和变量来源放在可展开的诊断区域。

演员是跨角色复用的**身份基准**，只负责脸部、体态、发型等稳定特征；角色图是“演员身份 + 服装 + 剧情阶段”的组合结果。角色后续接入统一机制时，必须独立定义其预设与参考图优先级，不能直接继承演员图的图片规格覆盖。

### 模板版本与生成快照

`PromptTemplate` 增加单调递增的 `version` 字段。任意模板内容、变量定义或默认变量发生修改时，服务端在同一次写入中将版本号加一；不保存旧版本模板记录，也不提供版本恢复页面。

每一次资产图片生成在任务载荷和图片生成记录中保存 `template_id`、`template_version`、变量合并结果和最终渲染提示词。模板后续继续修改不会改变已有生成记录，也不影响已生成图片；追溯时直接读取该次生成的快照，而非尝试重新渲染旧模板。

### 默认模板原则

默认模板必须按以下顺序表达：

1. 用途：单人演员资产设定图，不是剧情剧照。
2. 身份和视角：`description`、`view_angle`、姿势与可见细节。
3. 画面控制：统一构图、人物占比、纯净低饱和摄影棚背景、柔和均匀布光。
4. 风格：只承接 `visual_style` 与 `style`，不再默认加入“电影剧照”“故事感”“黄金分割”“强背景虚化”。
5. 负面约束：至少包含 `cinematic still`、`movie scene`、`complex background`、`scenery`、`architecture`、`props`、`crowd`、`multiple people`、`action pose`、`text`、`watermark`。

## 实施阶段（已完成）

### Phase 0：收敛首期产品体验

- 首期只提供“身份肖像”预设：三分之二身、人物居中、纯净棚拍背景、均匀布光。
- 演员生成页的主操作只保留“选择视角”和“生成”；构图、背景、细节强调收纳在“调整展示方式”。
- 确认图片规格覆盖存于 `ActorImage`，不是 `Actor`；一张背面全身图的调整不会影响正面身份图。
- 确认演员/角色边界：演员维护身份基准，角色维护身份在特定服装和剧情阶段下的视觉结果。

验收：页面信息架构、变量可编辑范围与数据归属明确，无需引入评分机制。

### Phase 1：后端模板契约与渲染链

- 在 `PromptCategory`、提示词类别 API 标签、OpenAPI schema 中加入 `actor_image`、`character_image`、`prop_image`、`costume_image`。
- 将 `asset_prompt_category()` 对上述类别的选择改为固定返回各自的统一类别；场景继续维持独立的正面/其他视角类别。
- 在 `build_actor_image_base_draft()` 中先解析当前视角需要的正面参考图，再构建 `reference_instruction`；不要在没有参考图时声称“与参考图完全一致”。
- 新增一个纯函数负责把 `AssetViewAngle` 转为 `pose_instruction`、`visible_detail_instruction`、`reference_instruction` 的系统建议；构图、背景、布光、负面约束从模板默认和覆盖层读取，并为四种视角写表驱动单元测试。
- 为提示词模板补充变量定义与默认值元数据（变量名、展示名、类型、默认值、是否可编辑、是否允许资产覆盖）；现有仅存变量名的 `variables` 字段需保留兼容读取路径。
- 为 `PromptTemplate` 增加 `version`，并在更新模板内容、变量定义或默认值时由服务端原子递增；不实现历史版本表、版本选择或恢复能力。
- 为 `ActorImage` 增加 JSON 形式的持久化 `prompt_overrides`，保存图片规格级可配置变量；单次覆盖只进入 preview / submission payload，不落库。
- 在图片生成任务和结果关联中持久化 `template_id`、`template_version`、合并变量与最终提示词，形成不可变生成快照。
- `build_prompt_with_template()` 的变量渲染保持可观测：预览接口和提交接口必须使用同一份变量与同一份渲染结果。
- 明确自定义模板选择优先级：资产显式绑定的 `prompt_template_id` 优先，其次为 `actor_image` 的默认模板；同时补齐目前未生效或行为不清晰的绑定路径。

验收：四个视角均可得到同一模板 ID、不同视角变量和正确的参考图集合。

### Phase 2：模板数据清理与重新初始化

- 开发期通过新的迁移先删除 `actor_image_front` 与 `actor_image_other` 的全部模板和未完成任务数据，再写入 `actor_image` 系统默认模板、变量定义、默认值及初始版本号；不得只修改 `001-init-prompt-template.sql`，因为已有环境不会自动覆盖已初始化记录。
- 迁移新增 `prompt_overrides` 的存储字段，并为空值保持“继承模板默认”；不得将当前渲染出的变量值批量固化为资产覆盖值。
- 迁移新增模板版本与生成快照字段；已生成图片无需重生成，历史任务如缺少版本信息则标注为 `legacy` 快照。
- 默认模板采用资产设定肖像文案，删除推动“电影截图”的默认措辞。
- 删除关联旧类别模板的显式 `prompt_template_id`，或统一改绑到新的 `actor_image` 系统模板；旧类别下的用户自定义模板同样删除，并按新变量契约重新创建。
- 重新初始化提示词模板数据并校验只存在一个默认 `actor_image` 模板；不要将旧模板复制为新模板，以免继续携带电影剧照导向。

验收：开发库中不存在 `actor_image_front` / `actor_image_other` 模板或未完成任务数据，且有且仅有一个默认 `actor_image` 模板；迁移前已生成的图片仍可正常预览、关联和用于分镜生成。

### Phase 3：前端模板管理与生成体验

- 演员生成页以“身份肖像”预设为默认入口；普通用户选择视角即可发起生成，“调整展示方式”只暴露有限的构图、背景与细节选项。
- 提示词模板管理页将“演员图片”展示为一个高级类别，并显示变量说明、默认值、可编辑范围、当前版本号和恢复系统默认操作；它管理的是生成规范，不只是变量在文案中的排列。
- 前端不再展示旧演员模板类别；重新初始化后仅允许新建和编辑 `actor_image` 模板。
- 演员图片生成预览展示：预设摘要、视角、参考图数量/来源、模板名称及版本号；最终提示词和每个变量的来源在诊断区域展开查看，方便确认侧背面确实继承正面身份图。
- 对应 `ActorImage` 的编辑页提供构图、背景、布光、细节强调和负面约束的覆盖表单；每项可恢复模板默认。单次生成弹窗提供临时覆盖，但默认不回写图片规格。
- 手动编辑提示词时保留系统生成的业务事实区块；用户编辑的是可配置规范和补充描述，不能把“背面”改写成“正面”或伪造参考图。

验收：用户可以在发起任务前看到最终提示词，且正面与侧背面预览使用同一模板类别。

### Phase 4：联调与开发期验证

- 验证正面、左侧、右侧、背面都使用 `actor_image` 的当前版本号，且最终提示词、参考图与变量来源可在任务详情中追溯。
- 修改模板默认背景后确认版本号递增；新任务使用新版本，旧任务与旧图片的快照不变化。
- 验证图片规格覆盖、单次覆盖和“恢复默认”按既定优先级工作。
- 验证旧类别删除后，前后端均无法创建、查询或渲染旧类别。

验收：统一模板主链、版本号和生成快照在开发环境可完整走通；随后进入下一资产类型。

### Phase 5：扩展到其他资产（已完成）

已按以下顺序复制同一机制：

1. `character_image`：已处理演员身份图与服装图的多参考图优先级。
2. `costume_image`：已使用独立模板，强调服装展示、材质与结构细节。
3. `prop_image`：已使用独立模板，强调道具设计、材质与比例。

每一种资产保持独立模板，不与演员模板共享不适用的内容。

## 测试与发布清单

- 后端单元测试：视角变量映射、无正面参考图回退、模板类别选择、默认值与资产/单次覆盖的优先级、模板变量渲染。
- 服务测试：演员图片 preview 与 submit 产出相同的最终提示词和参考图。
- API 测试：提示词类别列表仅包含 `actor_image`，模板更新会递增版本，旧类别无法再创建、查询或渲染。
- 数据测试：任务和图片生成记录会保存 `template_id`、`template_version`、最终提示词及变量快照。
- 前端测试：模板类别显示、变量说明、预览中模板/参考图信息。
- 契约同步：运行 `pnpm run openapi:update`，再运行 `pnpm exec tsc --noEmit`。
- 发布后抽检：生成正面、左侧、右侧、背面各一张，确认请求提示词中没有默认电影剧照/复杂背景导向。

## 风险与决策点

- 图片模型不能严格执行所有否定词，因此“纯背景、人物占比、构图”必须作为正向要求写在模板前部，负面词只做补强。
- 同一参考图无法保证侧背面完全身份一致；需要把参考图数量、模型能力和人工选图纳入质量指标。
- 开发期明确删除旧类别模板和未完成任务数据；已生成图片依赖生成快照，不需要重新渲染或迁移。
- 可配置变量过多会让资产编辑页退化为提示词编辑器；首期以“身份肖像”预设为主，只在“调整展示方式”中开放构图、背景、布光、细节强调和负面约束五项，姿势仅允许附加而非覆盖。
- 如果产品需要同时支持“棚拍资产图”和“电影化演员海报”，应新增用途变量或独立模板类别，不能把两种意图混在默认演员资产模板中。
