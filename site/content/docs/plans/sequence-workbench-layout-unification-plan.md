## 1. 目标与成功标准

按五层职责定义场次工作台展示框架，明确父层提供的区域与子层填入的内容；统一三个阶段的公共导航和操作位置，并让单元试拍在“拍摄准备、指令与检查、试拍与候选”之间切换时保持相同布局骨架。

- 工作台外壳、阶段公共框架、阶段专属框架、工作视图框架和对象详情框架的职责、区域与状态归属明确，子层不重复创建父层导航或侧栏。
- 区分工作阶段、展示视图、工作步骤、对象详情及辅助工具的切换，不将所有内部入口呈现为同级 Tab。
- 三个工作阶段入口始终位于场次选择下方、业务上下文上方；切换阶段保留当前场次。
- 单元试拍的上下文、主操作、步骤栏和左右内容边界一致，切换步骤不改变主按钮位置。
- 桌面打开候选快速预览不挤压主区；空状态、检查运行中、有问题及通过状态均遵守同一结构。
- 阶段与步骤切换保留合法浏览上下文，遵循现有草稿保护，不触发编译、检查、拍摄或采用。
- 窄屏操作可达、无横向溢出；关系图、编辑器和候选展示保留各自功能。
- 导演设计保留主视图与对象详情，剪辑验收保留播放器、时间线与审片／片段／来源详情的专属布局，不为统一框架制造业务步骤。

T1–T6 已于 2026-10-08 完成实施与本轮范围验收。实际截图、布局测量、测试结果和既有失败记录见第 8 节。

## 2. 当前事实与范围

评估入口：`SequenceWorkspacePage.tsx`、`WorkspaceStages.tsx`、`SequenceLayout.tsx`、`DesignEditor.tsx`、`ProductionWorkbench.tsx`、`CutEditor.tsx`、`WorkbenchChrome.tsx`、`workspaceNavigation.ts`、`workspace.css`、`workspaceContext.ts`。

| 当前事实 | 本轮处理 |
| --- | --- |
| `WorkspaceStages` 已提供三个工作阶段，页面通过 URL 的 `view` 表达阶段与辅助视图 | 复用现有导航和 URL 契约，明确层级及稳定位置，不新增独立页面路由体系 |
| 导演设计的分镜／清单／关系图切换主视图，镜头右栏另有叙事／表演／摄影／关联页签 | 区分工作视图与对象详情；详情导航留在右栏，不上提成阶段导航 |
| 剪辑主体同时包含播放器、下方时间线和右侧审片／片段／来源页签 | 保留专属工作区，将右栏页签归为对象详情，不拆成与试拍相同的三个步骤 |
| 批量拍摄、视觉验证、实际连续性、验收与记录沿用阶段工具和辅助 `view` | 保留辅助入口和回跳，不新增一排同级主流程导航 |
| 准备页采用外层参数栏，参数栏随选中内容隐藏 | 将辅助面板放入步骤内容区，未选具体对象时展示单元参数与准备摘要 |
| 第二步在内容内另建 `shoot-studio-layout`，有独立标题、字号、边距和侧栏主按钮 | 统一外壳，将步骤主操作固定到 B 区，检查处理留在辅助面板 |
| 候选页默认纵向排列，预览时增加外层右栏并扩大右栏宽度 | 桌面保持右栏，执行摘要、任务与候选预览共用右栏 |
| 桌面检查栏／抽屉使用 1280px 断点，第二步另有响应式规则 | 复用 `useWorkbenchDesktop` 与对应 CSS 断点，消除同一职责的不同切换规则 |
| 已有浏览位置存储、按计划与单元恢复明确选择、草稿保护和精确回跳 | 保留身份校验与回跳优先级，调整布局不重置业务依据 |

本轮范围由局部试拍布局扩展为工作台展示框架分层：先明确全工作台的父子边界，再完成公共区域必要接入和单元试拍布局统一。导演设计与剪辑验收仅按实际需要接入公共区域，其内部视图、表单、时间线和状态规则沿用现有实现，不重做业务模块。分层不等于每层新增 React 组件，只有本次重复结构具有相同语义且抽离能降低维护成本时才提取组件。

交互示意用于说明两层导航和分区，样例版本号、素材、检查结果及其他阶段的示意视图不构成新增需求。已完成旧计划保留原验收记录；本计划实施后，仅替代其与新布局冲突的显示规格。

## 3. 五层展示框架

| 层级 | 框架职责与提供区域 | 子层或业务负责的内容 | 现有实现入口 |
| --- | --- | --- | --- |
| L0 工作台外壳 | 整体左右布局、A 导航槽、右侧工作槽、底部状态栏、导航收起与响应式 | 各阶段的对象列表和业务状态 | `SequenceLayout`、`SequenceNavigation` |
| L1 阶段公共框架 | 场次栏、阶段导航、B 上下文与操作槽、C 内部导航槽、D 工作槽的顺序和边界 | 版本、标题、动作及阶段内容由阶段提供 | `SequenceWorkspacePage`、`SequenceSwitcher`、`WorkspaceStages`、`WorkbenchChrome` |
| L2 阶段专属框架 | 为当前阶段填充 A/B/C，选择 D 的布局，连接主内容与辅助面板 | 业务对象、版本选择、操作条件及请求回调 | `DesignEditor`、`ProductionWorkbench`、`CutEditor` 及页面内对应阶段组合 |
| L3 工作视图框架 | 一个视图或步骤的局部工具、主内容、辅助内容与浏览位置 | 关系节点、表单、候选、任务与修改方案 | 分镜／清单／关系图，准备／指令检查／试拍候选的现有内容组合 |
| L4 对象详情框架 | 所选对象标题、局部页签、字段区、局部动作、详情与窄屏抽屉 | 字段值、修改规则、来源及业务校验 | `WorkbenchInspector`、设计／剪辑详情、指令详情抽屉 |

```text
工作台外壳 L0
├─ A 导航槽：由当前阶段填入对象列表
├─ 右侧工作槽
│  └─ 阶段公共框架 L1
│     ├─ 场次选择与版本入口
│     ├─ 导演设计 / 单元试拍 / 剪辑验收
│     ├─ B 当前业务上下文与操作
│     ├─ C 当前阶段内部导航（按阶段需要）
│     └─ D 阶段专属框架 L2
│        ├─ 导演设计：分镜 / 清单 / 关系图 L3 + 对象详情 L4
│        ├─ 单元试拍：准备 / 指令检查 / 试拍候选 L3 + 辅助内容与详情 L4
│        └─ 剪辑验收：播放器 + 时间线 + 审片 / 片段 / 来源详情 L4
└─ 底部状态槽
```

### 框架与内容的边界

- 框架决定几何位置、分栏、边距、滚动、折叠、响应式和焦点返回；内容决定展示哪些对象、字段、问题与记录。
- B 主操作的展示位置由框架统一；按钮名称、执行条件、加载状态和回调由阶段业务提供，公共框架不判断计划确认或检查通过。
- 子框架继承父层 A/B/C，不再创建场次选择、阶段导航、版本栏和对象列表。局部工具只管理当前画布、列表、输入或播放器。
- 当前工作视图只填充一个主工作槽和一个辅助槽，不另建嵌套侧栏；modal 与深入阅读抽屉保留其独立交互职责。
- 公共框架提供可选的 C 槽，未使用的区域不保留空白导航行；剪辑详情页签不能为了填满 C 而上提。
- 不为每一层增加可见标题或工具栏；统一层级不能增加顶部密度。
- 默认沿用现有挂载与 portal 机制，避免抽取框架导致编辑器、视频及草稿重挂载，不引入全局布局注册系统。

### 三阶段专属框架

| 阶段 | A 对象内容 | B 上下文与操作 | C 内部导航 | D 工作区 |
| --- | --- | --- | --- | --- |
| 导演设计 | 场次结构、节拍及对象入口 | 当前设计、草稿状态、保存／确认／进入试拍 | 分镜／清单／关系图 | 主视图 + 所选对象详情；关系编辑和字段页签属于详情层 |
| 单元试拍 | 单元列表、搜索、真实状态和候选数 | 当前计划、固定设计依据、单元摘要、步骤主操作 | 拍摄准备／指令与检查／试拍与候选 | 稳定双栏，按步骤替换主内容与辅助内容 |
| 剪辑验收 | 候选素材、审片和来源筛选 | 当前剪辑、草稿状态、保存／确认采用 | 沿用实际阶段工具，不虚构三步骤 | 主播放器 + 下方时间线 + 右侧审片／片段／来源详情 |

设计与试拍复用语义相同的双栏几何规则；剪辑时间线属于阶段固定工作区域，不随详情内容滚走，不因框架接入被隐藏成普通 Tab。

### 浏览与业务状态归属

| 状态 | 归属与约束 |
| --- | --- |
| 导航宽度、收起、桌面／窄屏模式 | L0 外壳；不承担业务对象选择 |
| 场次、阶段、版本与明确回跳身份 | 现有页面 URL 与上下文处理；公共框架只接收展示值和导航回调 |
| 镜头／单元／Take／片段选择与编辑草稿 | 对应阶段业务；沿用版本、项目归属和草稿保护，不迁入布局状态 |
| 视图、步骤、筛选、滚动、画布位置 | 对应 L2/L3；恢复前校验版本及对象身份，不跨单元串用 |
| 详情页签、开合、触发元素与焦点返回 | L4 对象详情；切换详情不重置主区，异步结果不抢占阅读 |

## 4. 分区职责与导航

```text
A 对象导航 │ B 场次选择                              版本与依据
           │   导演设计 | 单元试拍 | 剪辑验收
           │   当前版本 / 当前对象摘要                  主操作
           ├────────────────────────────────────────────
           │ C 当前阶段内部视图或步骤（按需）
           ├──────────────────────────┬─────────────────
           │ D1 主内容                │ D2 辅助面板
```

| 区域 | 职责 | 单元试拍内容 |
| --- | --- | --- |
| A | 在当前阶段选择工作对象 | 单元列表、搜索、真实工作状态与候选数 |
| B | 选择场次和阶段，展示当前业务上下文与主操作 | 计划与固定设计依据、版本入口、单元标题和简要参数、一个步骤主操作 |
| C | 在当前阶段内切换视图或步骤 | 拍摄准备、指令与检查、试拍与候选及各步骤真实状态 |
| D1 | 阅读、编辑或浏览当前业务内容 | 准备关系图、指令修改工作区、候选列表／网格 |
| D2 | 当前对象详情、校验和处理上下文 | 准备参数／检查问题／执行摘要与快速预览 |

### 切换类型与展示位置

| 类型 | 入口例子 | 展示位置与影响 |
| --- | --- | --- |
| 场次上下文 | 场次选择 | 公共场次栏；切换全部业务上下文，沿用草稿保护 |
| 工作阶段 | 导演设计／单元试拍／剪辑验收 | 公共阶段栏；切换 A/B/C/D，保留当前场次 |
| 展示视图 | 分镜／清单／关系图 | 设计 C 区；只改变同一设计的呈现 |
| 工作步骤 | 拍摄准备／指令与检查／试拍与候选 | 试拍 C 区；切换 D 与步骤主操作，保留计划与单元 |
| 对象详情 | 叙事／表演／摄影／关联，审片／片段／来源 | D2 或详情抽屉；只改变所选对象的信息类别 |
| 局部呈现 | 网格／列表、候选范围、画布设置 | 所属内容工具区；不改变阶段或固定执行依据 |
| 辅助工作 | 批量拍摄、视觉验证、实际连续性、验收与记录 | 既有阶段工具及辅助 `view`；保留入口、上下文与业务回跳 |

### 导航继承规则

- 工作阶段视觉上采用固定横向入口，复用 `view`、`changeView` 和既有历史导航行为；刷新、深链、浏览器前进后退均可恢复合法阶段。
- 阶段切换更新 A、C、D 与 B 的业务上下文，不改变场次；三个阶段入口始终可见，不放入“更多”菜单。
- C 的选择态只表示正在浏览的步骤；准备确认、检查结论和候选数量独立显示，不能将浏览位置当作业务完成状态。
- 阶段返回优先保留该阶段已选对象与浏览位置；显式链接和精确回跳优先，失效或跨场身份沿用现有校验，不擅自选择另一份执行依据。
- 版本入口继续复用已有版本管理；移除顶部重复入口，保留阶段工具和任务入口的合法去向。
- 切换详情不重置主区，切步骤不改变单元，切阶段不改变场次。必须改变业务依据的动作仍经既有身份检查和草稿保护，不能以布局切换绕过。
- C 与详情页签采用不同的视觉层级和可访问名称，避免出现多个无法辨识所属对象的同名 Tab 组。

## 5. 单元试拍工作视图框架与布局规格

三个 L3 步骤框架都继承试拍 L2 的 A/B/C，只组织 D 内容与相应辅助槽。准备图节点、字段表单、检查问题和候选卡片是内容，不能各自改变父层分栏。

| 工作视图框架 | 框架组织的区域 | 放入区域的内容 |
| --- | --- | --- |
| 拍摄准备 | 关系画布、画布工具、选中对象辅助区 | 单元、覆盖、对象、参考和依赖节点，参数与准备检查 |
| 指令与检查 | 当前内容、编辑／修改输入、方案预览、检查辅助区 | 指令选择、正文摘要、直接字段编辑、修改要求、问题与结论 |
| 试拍与候选 | 候选工具、结果网格／列表、分页、执行与预览辅助区 | 候选范围、素材卡片、任务与固定依据、所选视频 |

拍摄准备框架示例：

```text
继承父层：单元列表、计划上下文、单元标题、主操作、三个步骤
┌────────────────────────┬─────────────────────┐
│ D1 关系画布             │ D2 所选对象辅助区   │
│ ├─ 局部画布工具         │ ├─ 对象标题         │
│ └─ 准备关系图           │ ├─ 参数与字段       │
│                         │ └─ 准备检查         │
└────────────────────────┴─────────────────────┘
```

| 步骤 | D1 主内容 | D2 辅助面板 | B 主操作示例 |
| --- | --- | --- | --- |
| 拍摄准备 | 当前单元准备关系图 | 单元参数、选中覆盖／依赖详情、准备检查；参考选择沿用现有 modal | 保存并确认准备／进入指令与检查 |
| 指令与检查 | 合法指令选择、当前拍摄内容、直接编辑、统一修改要求与方案预览 | 检查任务、待处理问题、建议及结论 | 生成指令／检查指令／保存或确认结论／进入试拍 |
| 试拍与候选 | 候选范围筛选、网格／列表、分页与新增产出提示 | 固定执行摘要、本单元任务、所选候选快速预览 | 开始试拍／同指令再拍／核实提交／去检查指令 |

- B、C 横跨 D 的完整宽度；D2 从 C 下方开始，不与对象标题或步骤栏并排。
- 桌面 D2 统一以 344px 为基准，主区使用剩余空间；三个步骤采用相同标题层级、外边距和分隔线。内容内部按实际阅读需要保留局部结构。
- 桌面 D2 持续存在，候选未选中时展示执行与选择提示；打开、关闭预览只更新右栏内容，不调整网格宽度。候选预览与摘要分节显示，任务仍可访问。
- B、C 不随 D 内容滚动，D1、D2 各自滚动；沿用按身份和步骤保存的位置，节点定位与修改输入定位不得造成整个工作台跳动。
- B 的步骤主操作保持固定位置，复用现有动作判断、禁用、提交中、失败与请求待核实规则。运行中无合法动作时在同一位置显示真实状态，不保留重复可提交按钮。
- 对象局部动作留在对象旁，包括参考编辑、加入修改建议、更新／采用修改方案、资源重试、进入剪辑验收。不能将所有按钮机械移到 B。
- 完整指令、固定输入、历史和长篇诊断继续按需进入已有详情抽屉；保留选择来源、关闭后焦点返回和异步结果不抢占阅读。
- 低于桌面断点时采用单列 D1 与统一辅助入口／抽屉，阻塞问题或任务摘要在主区可见；低于 768px 沿用步骤选择入口，不挤出不可操作的 Tab。
- 参考主体、资产关联、历史依赖等沿用已生效的 modal／只读边界，不为统一右栏拆除既有交互。

## 6. 不变的业务约束

- 准备、设计、计划的保存与确认保持精确版本规则；已确认版本修改仍派生新版本。
- 指令生成、检查、确认结论、视频提交均需明确动作；确认结论不自动开拍。
- 指令修改方向、预览与采用流程保留既有身份、请求恢复与重新检查约束。
- 切换当前指令不隐藏本单元其他指令的运行拍摄任务或旧候选，任务继续展示提交时的固定依据。
- 新产出只登记 Take，不自动采用，不抢焦点；审片、真实覆盖、可用区间、人工采用与接缝处理仍属于剪辑验收。
- 正式检查保留六岗乘以全部出现对象的完整性要求，待检查或缺失项不能显示为通过。
- 布局变更不改变 API、数据存储或媒体能力；若实施中确需契约变化，另行明确范围并按项目规则同步。
