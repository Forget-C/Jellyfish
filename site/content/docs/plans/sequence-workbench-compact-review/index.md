## 1. 目标与范围

本计划承接已完成的[单元试拍操作推进与检查闭环优化计划](/docs/plans/sequence-workbench-shoot-progression/)。保留已经打通的准备、生成指令、检查、确认结论、明确开拍与查看候选流程，围绕“紧凑布局、问题优先、指令按需查看”重整展示层级。

用户进入页面后应立即看清：当前操作哪个对象、还有什么需要处理、下一步可以做什么。查看指令、固定依据或历史后，应能返回原来的工作位置。

- 本轮范围：单元试拍顶部密度、检查结果层级、指令与检查关系、版本浏览与选择、三个阶段的侧栏搜索及公共展示组件。
- 沿用现有品牌位置、全局图标栏、面包屑、阶段导航、业务侧栏与蓝白风格，不重新设计全站外壳。
- 保留“拍摄准备／指令检查／执行试拍／候选素材”四个工作区；原“指令与检查”更名为“指令检查”，不改变其业务步骤。
- 导演设计与剪辑验收只接入公共布局、导航搜索与详情面板规则；分镜、关系图、播放器、时间线及业务操作继续独立。
- 优先复用现有数据契约、任务身份与恢复机制，不新增重复业务状态或通用工作流引擎。
- 本计划实施后替代上一计划中“指令正文与检查结论常驻同一区域”“通过项逐行常驻”“页签逐项显示第二行状态”的展示规格；上一计划的流程与版本保护继续有效，历史验收记录保持原义。

- 图片中的项目、动作、数量、时间、版本和检查内容均为示意，不写入业务默认值。

## 4. 紧凑顶部与信息层级

### 4.1 三层结构

| 区域 | 保留内容 | 桌面目标高度 |
| --- | --- | --- |
| 版本工具栏 | 计划版本、确认状态、设计依据；历史与更多操作 | 40–44px |
| 单元标题栏 | 单元编号、动作摘要、当前状态；一行镜头范围、时长与画幅；唯一主操作 | 56–64px，包含参数行 |
| 工作区页签 | 拍摄准备／指令检查／执行试拍／候选素材；必要的数量标签 | 36–40px |

以现有1440宽度截图为基准，三层合计目标约132–148px，预计收回约120px纵向空间。该数值是设计目标，不是已完成测量；G3应使用同样内容和视口对比实际结果。

- 标题建议18px，正文13–14px，间距遵循8–16px节奏；不能通过整体缩小文字换取密度。
- 删除常驻的引导标题与解释段落；状态标签与主操作表达当前进展。
- 页签表示正在浏览的工作区，去掉逐项第二行状态；候选数量等必要信息用小标签表达。
- 长动作摘要避免无限撑高标题，提供可访问的完整内容查看方式，不仅依赖鼠标悬停。
- 首次进入、异常、缺项与需要决策时可显示短说明；错误和阻塞条件不能为了紧凑而被隐藏。
- 状态与主操作继续使用精确上下文，不因回看准备或候选而退回起稿；浏览位置与业务进度分别表达。
- 窄屏允许标题与操作换行，优先保证按钮可点击和文本可读，不机械套用桌面高度。

### 4.2 主操作规则

当前单元只有一个突出的主操作，沿用既有状态判断。未检查时为检查入口，有问题时定位首个待处理项，满足条件且结论未确认时为确认结论，执行区才允许明确开始试拍。

“处理首个问题”表示定位问题及可用处理路径，不自动修改设计或指令。有问题的检查仍保留保存结论的次级入口；保存不等于通过，人工艺术取舍继续遵守既有理由和派生规则。

## 5. 检查结果：问题优先

### 5.1 结果汇总

用一行表达，例如“2项需修改 · 1项待检查 · 9项通过”。`revise`、`pending`、`pass`分别统计；读取失败或检查记录不完整不得展示为全部通过。

- 汇总以真实检查条目为单位，正式检查必须遵守六岗位乘以检查对象的完整性要求，不硬编码六条。
- 一条检查可包含多条发现。需要显示发现数量时另标“问题发现N条”，不与检查条目相加或混用。
- 多个检查对象默认按可读镜头／动作分组，岗位作为标签；不能仅按岗位铺六个大区块。
- 同一对象多次出现时保留可区分的出现信息；名称缺失显示不可用说明，技术身份放入详情，不将不同记录错误合并。
- 人工取舍按真实记录标明，不将人工接受的偏离伪装为自动检查通过。

### 5.2 待处理内容

待修改和待检查记录放在通过摘要之前，使用浅分隔线列表，不叠加大卡片。

每条优先呈现：岗位与受影响对象、问题标题或原始结论、观察、修改建议、相关操作。验收条件与完整来源按需展开，重要问题不能全部藏在“查看问题详情”的下一层折叠里。

- 少量问题直接展开观察和建议；大量问题保留全部可见标题与状态，优先展开当前处理项，提供展开其余问题的入口，不静默截断结果。
- 未提供具体发现时，保留原始结论并说明“未提供具体问题详情”，不补写推测问题或建议。
- 可用操作按数据提供：查看相关指令、查看固定依据、定位可修改内容、符合条件时记录人工取舍。
- 固定依据只读；定位可修改设计或准备内容时，明确其版本与影响，沿用草稿保护及新版本派生规则，不修改已确认快照。
- 问题路径转换为可读对象和字段名，原始路径在技术详情中保留；无法解析的路径明确说明，不能跳到相似对象或较新版本。
- 检查任务运行、失败、取消、状态未知继续在当前上下文可见，不混入已通过统计。

### 5.3 通过项与全部通过状态

通过项默认合并为一条约32–36px的摘要：“✓ 已通过N项 · 展开检查明细”。展开后按对象与岗位展示紧凑明细，完整原始依据仍可访问。

全部通过时只保留简洁的结果摘要、真实保存状态和适用的下一步入口，不渲染六张卡片或六条常驻成功记录，也不为填满空白加入无关内容。

是否可以确认或开拍继续依据完整检查、精确指令版本和既有准备度判断；视觉摘要不能代替服务端校验。

## 6. 指令正文、检查对象与版本关系

### 6.1 主区上下文栏

在“指令检查”页签下显示一条紧凑上下文栏：

> 检查对象：试拍指令 v3　查看指令　切换版本　｜　本次检查：09:42 · 结论已保存

- 指令是提交给模型的内容，检查结论针对该指令及其固定依据；必要说明只保留一句。
- “查看指令”始终可发现；正文不再常驻主区，不重复展示摘要与完整正文两个阅读区。
- 同时显示所选检查的时间／可读标识与保存状态。多个检查结果通过“检查记录”入口明确选择，不并排堆叠待确认、已保存和审稿三个选择框。
- 只有一个指令版本时隐藏切换控件；无指令、未选择和读取失败分别显示，不把三者都解释为需要重新生成。
- 版本标签在列表、上下文栏与详情中一致并绑定稳定身份，不能因为列表排序改变而给同一指令换编号。

### 6.2 指令详情面板

| 内容页签 | 职责 |
| --- | --- |
| 指令正文 | 完整正文、复制、实际编译映射；支持从问题定位有关片段 |
| 固定输入 | 所选指令冻结的模型名称、范围、时长、参考、设计与计划依据 |
| 版本记录 | 当前计划与单元范围内的指令版本及关联检查，可查看历史或明确切换 |

- 桌面默认在现有详情区域打开，可按内容使用约400–480px宽度；主区必须仍可阅读。未打开时不保留空白详情列，准备阶段需要编辑的参数面板仍按职责提供。
- 当并排显示会过度挤压主区时切换为抽屉，窄屏可使用全宽面板；不照搬桌面三列。
- 同时只呈现一个详情面板。查看来源、固定字段或版本详情在该面板内切换，并提供返回；不继续嵌套第二层抽屉。
- 关闭后恢复触发控件焦点及原问题位置；切换单元或阶段时关闭或更新面板，并清晰绑定新的合法上下文，不残留旧版本正文。
- 指令正文是版本结果，不伪装为可以直接原地编辑的输入框。“重新生成新版本”保持次级操作，说明新指令需要重新检查。

### 6.3 历史预览与工作版本切换

| 操作 | 对当前上下文的影响 |
| --- | --- |
| 查看历史版本 | 只预览正文和依据，明确标记历史预览；主区检查对象、主操作及提交依据保持原选择 |
| 切换到此版本 | 明确切换当前浏览工作的指令，主区同步展示该指令关联的检查；不等于采用、确认或开拍 |

- 版本列表显示可读版本、实际生成时间与关联检查状态；时间或依据不可用时明确说明，不造默认值。
- 所有版本选择限定在精确计划与单元上下文内。切换后的检查可恢复此前明确选择；没有明确选择且存在多条合法结果时要求选择，不能静默取最新。
- 预览历史时显示“历史预览”与当前工作对象的区别；查看、关闭面板不重置当前选择。
- 切换回工作版本、刷新或浏览器返回，应恢复原来的精确身份与阅读位置；迟到结果不能抢占当前页面。

### 6.4 操作后的主区反馈

| 状态或动作结果 | 主区表达 |
| --- | --- |
| 首次生成指令成功 | 显示“指令已生成 · 待检查”、明确版本、查看正文入口和检查主操作；不要求用户先发现抽屉才能继续 |
| 检查进行中 | 展示精确任务进度，仍可查看对应指令，不允许重复提交同一次检查 |
| 检查完成，有待处理项 | 展示问题和真实保存状态，提供处理入口；允许单独保存结论 |
| 检查完整且通过，结论未确认 | 简洁摘要与“确认结论，进入试拍”入口；确认不提交视频 |
| 结论已确认且具备执行条件 | 执行区核对固定输入，由用户明确开始试拍 |
| 修改模型、范围或参考 | 按原规则派生新计划／指令；说明需要重新检查，原检查继续对应原版本 |
| 请求结果未知或读取失败 | 提供核实／重试读取路径，保留原请求身份与现有内容，不误导重新生成 |

## 7. 三阶段侧栏搜索

统一采用“标题旁搜索图标 → 点击展开输入框”的方式，默认收起。输入即筛选，提供清除按钮，不再额外放搜索提交按钮。

| 阶段 | 左侧搜索范围 | 现有局部功能 |
| --- | --- | --- |
| 导演设计 | 节拍编号、节拍目标 | 中央镜头搜索明确命名为当前范围的镜头筛选；与左侧寻找节拍区分 |
| 单元试拍 | 单元编号、动作摘要 | 保留单元状态与候选数量，不搜索内部ID |
| 剪辑验收 | 候选编号、来源单元、动作摘要 | 与既有审片结论及来源筛选共同生效，显示已生效条件并可清除 |

- 统一搜索入口位置、尺寸、展开、清除、键盘和无结果表现；不同阶段的业务筛选能力不强行做成相同字段。
- 查询按场次和阶段分别保存，读取已有非空条件时必须显式展开并显示；不能恢复隐藏筛选。
- 搜索只筛选列表，不自动改变当前选中对象或清空正文。选中对象不在结果内时保留正文并提示清除筛选。
- “没有匹配项”与“尚无对象”分别表达，前者提供清除入口；关闭搜索框不能留下不可见的有效条件。
- 不丢失导演的全场／未分组入口、资产入口以及各阶段底部工具，不将这些工具当作普通搜索结果删除。
- 移动端搜索、清除等按钮不能被导航容器的通用点击逻辑误判为选择对象而关闭整个导航抽屉。
- 样式仅作用于相应导航项，不再用侧栏内全部`.ant-btn`统一覆盖输入框附属按钮的高度、对齐和溢出规则。

## 8. 公共组件与业务边界

在已有`SequenceLayout`、`SequenceNavigation`、阶段导航和响应式判断基础上逐步提取，不新增平行外壳。组件名称在实现时遵循已有约定，下表定义职责。

| 公共部分 | 负责内容 | 业务层保留内容 |
| --- | --- | --- |
| 阶段工具栏与对象标题栏 | 版本上下文、标题、元信息、状态及主次操作的排列和密度 | 版本选择规则、保存／确认条件、主操作判断 |
| 侧栏导航框架 | 标题、搜索、列表滚动、空态、底部工具位置 | 节拍、单元、候选的渲染与筛选语义 |
| 主区与详情面板 | 面板宽度与显隐、窄屏抽屉、焦点恢复与滚动容器 | 设计编辑、准备参数、指令阅读、审片详情 |
| 基础展示样式 | 间距、分隔线、状态标签、按钮尺寸与选中表现 | 业务状态定义、问题分组与视频操作 |

- 先完成并验证单元试拍的新布局，再将已有相同职责提取并用于导演设计与剪辑验收；G1不另建一套外壳，也不提前设计未使用的通用接口。
- 公共组件接收内容和受控状态，不按`design/shoot/cut`分支承包全部业务，不重写为统一状态机。
- 分镜、关系Graph、检查结果、播放器与时间线保持独立，不强行共享内容组件。
- 不因切换面板或响应式布局重挂载编辑器而丢失草稿，不使视频播放、区间选择或滚动位置意外重置。
- 导演设计原有详情宽度调整与布局恢复等能力继续有效；公共化不能降低现有能力。
- 公共标题只统一操作布局，不强制三个阶段拥有相同按钮或同时只能执行一种业务操作。
- 预期以展示层调整完成。若准确定位确需接口补充，先核实已有编译映射与冻结字段能力，再说明必要契约变化；不为概念图高亮预先扩大后端范围。

## 9. 实施阶段

按G1 → G2 → G3推进。每阶段先核对相关实现与已有回归，再实施和验证；完成上一阶段后再进入依赖阶段。

执行优先级：先解决单元试拍的阅读与操作层级，再复用已经验证的公共展示结构，最后完成三个阶段的综合验收。公共化限于布局与交互规则，不扩大为业务流程重构。阶段完成以对应验收证据为准，不能仅凭组件已抽出或页面已渲染就标记完成。

| 阶段 | 任务与交付 | 验证方式 | 状态 |
| --- | --- | --- | --- |
| G1 试拍信息重排 | 紧凑版本／标题／页签；问题优先、通过摘要；指令详情面板；历史预览与工作版本切换；保留操作反馈和恢复机制 | 用实际页面验证全部通过、多对象待处理、待检查、运行／失败、无指令与多版本；回归确认结论到明确开拍的连续操作及精确身份 | 已完成 |
| G2 公共布局与统一导航 | 将G1已验证的公共职责提取到现有外壳；三阶段统一搜索入口、工具栏与详情规则；修复导航按钮样式作用范围 | 验证三阶段搜索、清除、隐藏选择提示、草稿保护、面板切换与返回；核对分镜／Graph／播放器／时间线原有功能 | 已完成 |
| G3 综合验收与文档 | 四尺寸和键盘验收；同条件前后空间对比；多对象、多版本及异常恢复；真实截图与逐项证据归档；同步受影响架构和指南 | 执行适用类型检查与回归、文档构建和图片链接检查；记录实际结果及未覆盖边界 | 已完成 |

### 验证范围

- G1优先复用`workspaceShootProgress`、`workspaceShootContext`、`workspaceJourney`、`workspaceProduction`等已有回归，按新展示方式调整定位，保留原有业务断言。
- G2补充或复用导航搜索与面板恢复场景，并运行受影响的导演设计、写入保护和剪辑回归；公共布局涉及三阶段，不能只验证试拍。
- 新增回归应验证真实风险：六岗位乘以多对象的统计、历史预览不改变提交对象、筛选不清空正文、迟到响应不抢占选择、关闭面板恢复位置。纯尺寸或低影响样式使用截图与直接检查，不编写镜像实现的测试。
- 前端代码修改后从项目根目录运行`pnpm --dir front run typecheck`；相同代码和环境已通过的检查不重复执行。
