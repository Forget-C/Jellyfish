2026-09-30 核对“胡同路边等待”的设计 2、计划 4、单元 01。该单元仅覆盖 `shot_1`，动作范围为“风雨交加的夜晩胡同，白色面包车停在路边。”；已选参考为张三与胡同马路。

| 对象 | 当前设计数据 | 当前准备图结果与判断 |
| --- | --- | --- |
| 白色面包车 `p_van` | 镜头 01 可见结果明确提及；背景活动和连续性引用了对象 ID；没有镜头调度或表演关联 | 未生成节点。镜头内容与可操作对象不一致，属于需要补齐的关系缺口 |
| 警用甩棍 `p_baton` | 已登记为场内对象，镜头 02 等文字提及；没有指向该对象的镜头调度或表演关联 | 当前单元未展示合理；不能据此断言它在覆盖镜头 02 的单元中也应缺席 |
| 张三 `p_zhangsan` | 当前节拍有表演记录，且单元已选其参考 | 有间接设计关联与实际参考绑定；这些关系不能直接等同于镜头中可见 |

改造前，候选列表直接读取固定设计版本的全部 `participants`。`productionGraph.ts` 只从覆盖镜头的调度、对应节拍表演、当前单元参考绑定中收集对象，未读取背景活动与连续性中的对象关系。

改造前的 `ShotCoverage` 没有直接表达参与对象的字段；背景活动与连续性也没有完整的逐镜范围。对象写在自然语言中，不等于程序已经获得可验证的镜头关系。将全部场次对象或无镜头范围的部门记录加入每个单元，都会扩大范围。

`Participant` 只有 `character_id`、`prop_id`，没有独立类型字段。二者为空时无法区分人物和物件。原标签判断把所有无 `prop_id` 的对象归为角色，已作为 P0 单独修复。

## 2. 目标与边界

成功标准：当前单元的覆盖镜头、明确相关对象、实际参考和落幅依赖可完整查看；相关对象尚未关联资产或尚未选图时仍可见、可操作；其他镜头的对象不因全场名单或文字命中自动进入当前单元。

“完整”指当前单元的生产准备关系。默认画布呈现覆盖、对象、参考和依赖；六岗详细依据通过节点查看并定位固定设计，不默认展开全部字段。

本计划复用现有设计编辑器、准备图和参考 modal，不新增通用关系引擎，不通过自由拖线修改业务关系，不自动选图或开拍。对象关系与实际媒体覆盖、审查和采用保持独立。

## 3. 镜头参与对象契约

已在 `app/core/contracts/directing/design.py` 的 `ShotCoverage` 增加 `participant_ids: list[Identity] | None = None`，引用同一固定设计的 `participants`。

| 值 | 语义 | 处理 |
| --- | --- | --- |
| 字段缺失或 `null` | 对象范围尚未核对，包含历史设计 | 读取兼容，显示范围待核对，不能解释为空镜 |
| `[]` | 已明确此镜头无参与对象 | 不从节拍表演、全场名单反向填充；允许保留场所与用户选入的参考 |
| 非空列表 | 此镜头明确参与的人物／物件 | 即使没有资产或参考也进入准备图；名称、资产关联从固定设计解析 |

该列表描述镜头设计范围，不表示对象必须提供图片，也不保证在本单元的部分动作范围中实际可见。声音来源、前后镜头背景和参考中的非画内对象可作为依据或实际输入存在，不据此宣称出镜。

具体约束：

- 校验重复 ID、悬空 ID、字段类型；引用必须在同一设计内。资产归属继续由 `DirectingStore` 校验。
- 新 AI 设计输出明确的列表，静态车辆、手持物件与人物共同核对；模型结果仍需设计确认。手动新增镜头默认 `null`，由用户明确选择或确认无对象。
- 新设计版本的确认入口要求全部镜头完成范围核对；审稿修订涉及设计修改时也要求完整名单，历史未知设计需先在设计编辑器核对。旧已确认版本继续可读、可作为固定依据；不会因新增字段被后台重新确认或修改。
- 与调度、表演记录有差异时展示依据供核对，不将它们机械合并成出镜名单。一个表演节拍可跨多个镜头，调度记录也可能只是空间依据。
- 本计划不新增 `Participant.kind`。已有资产关联提供角色／物件标签；无类型依据时使用“对象”。名称关键词、ID 前缀和浏览器暂存的资产类型选择不作为分类依据。

## 4. 单元准备图投影

对象节点来自当前计划固定设计及所选单元；节点身份继续包含计划、单元和对象 ID。

1. 对已核对镜头，汇总其明确的 `participant_ids`。共享对象只建一个节点，保留到各覆盖项的设计关联，点击可追溯具体镜头；多镜与重复覆盖项不丢失出处。
2. 对未核对的历史镜头，暂时保留现有调度／表演关联，标明“范围待核对”和具体来源。该结果不宣称完整；不按名称解析正文，不自动扩大到全场背景活动或连续性对象。
3. 合并当前单元所有 `references.participant_ids`。设计范围外的已选对象仍展示“仅本次参考关联”，保留实际输入连线，不伪造镜头设计连线。
4. 场所继续按固定设计显示，未关联时保留准备入口。无对象绑定的空间、构图和帧参考始终保留独立节点。
5. 对象节点分别显示资产状态和本次参考状态。移除最后一份参考后，设计相关对象仍存在；仅因该参考出现的范围外对象可随之消失。

明确镜头列表负责范围，调度、节拍、背景活动和连续性负责解释依据。查看相关部门记录时必须说明是逐镜引用还是全场背景；全场记录出现某对象不会自动新增设计关联边。

原始复现场次的预期：新设计明确 `shot_1 → p_van`，`shot_2 → p_zhangsan/p_baton`，并按设计内容核对镜头 02 的车辆关联。单元 01 的面包车节点可见；甩棍只在该单元显式选入其参考时作为实际输入对象出现。真实数据修订需派生设计、确认并明确更新计划依据，不能通过前端显示修复偷偷改写旧计划。

## 5. graph 中的准备操作

| 状态或操作 | 预期行为 |
| --- | --- |
| 相关对象无资产、无参考 | 节点可点击，预选对象 ID；可选已有素材或上传；提供设计资产关联入口 |
| 对象有资产但未选参考 | 展示可用图片状态，点击选择具体文件；不自动选默认图 |
| 对象已有参考 | 同一 modal 查看、追加、替换、移除和排序，实际文件与主体分组保持可追溯 |
| 通用“添加参考” | 仍可选择全场对象，候选区分当前单元相关、范围待核对和其他场内对象；参考选择不改变设计范围 |
| 修改对象资产关联或镜头对象范围 | 进入对应设计编辑位置，遵循草稿保护与已确认版本派生；准备图不直接改写固定设计 |
| 应用／取消 | modal 内暂存，应用仅更新当前单元草稿；取消不改变单元；保存和确认沿用现有流程 |

模型是否接受素材由原有能力检查决定。节点可见不代表模型已收到图片，也不代表未选图一定是错误。迟到上传、切单元、切计划和只读历史保护继续复用现有实现。

## 6. 编译、版本与兼容

- 设计保存、确认、派生、AI 生成和修订都必须保留新增字段；前端编辑模板、关系编辑、搜索与来源展示同步支持该关系。
- 提示词编译审查新字段的去向：明确的镜头对象作为本次设计依据，完整场次对象及其他部门背景仍遵循现有背景／本次执行分区，不能因 graph 隐藏某对象就声称提示词中没有该对象。
- 不删除声音、环境或连续性约束来迎合图的对象范围；编译范围变化需独立回归，历史固定指令不重新渲染。
- 旧版本缺字段时维持读取兼容。修订通过类型化存储及新版本流程进行，不批量覆写已确认 JSON，不以名称猜测回填。
- P1 已同步 OpenAPI 与 generated client；P0 标签修复本身不改变接口。
- 新字段存于已有设计版本内容，不新增数据库表；服务持久化、API 读取往返均已验证 `null` 与空列表的区别。

## 8. 验收矩阵

| 用例 | 必须满足 |
| --- | --- |
| 镜头 01 仅有面包车、镜头 02 有人物与甩棍 | 单元 01 出现面包车；不会只因全场名单出现甩棍 |

| 只拍镜头内部分动作 | 表达设计相关，不把完整镜头对象列表宣称为实际可见清单 |
| 范围外对象显式选入参考 | 对象与参考可见，仅建立真实输入绑定；不改写设计 |
| 删除最后一份参考 | 设计相关对象保留；仅参考相关对象按实际关系移除 |
| 历史缺字段与显式空列表 | 前者范围待核对并保留旧依据；后者不从节拍表演反向补对象 |
| 无参考、模型纯文本、能力读取失败 | 对象关系仍可查看，参考操作遵循能力规则，不自动写入或执行 |
| 资产类型与未知类型 | 角色／物件只有明确关联时标注；未知与缺失对象不默认标角色 |
| 取消、切单元、迟到上传、保存失败 | 不串改其他单元，不丢失未保存输入，不覆盖历史版本 |
| 设计派生、计划换依据与历史指令 | 新关系经合法版本流程生效；旧指令、旧计划与采用记录保持固定 |
| 桌面与窄屏 | 键盘及触屏可完成节点进入、选图、应用与取消；操作不依赖拖线或悬停 |
