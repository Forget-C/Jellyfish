> 与主流程修复（需求一，用户另行汇总）搭车执行：改到哪个页面，顺手收哪个页面。

## 背景

用户体感：「后台参数显示在前台非常不好用，之前参考巨日禄但并没有改善很多」。

已经做过的（为什么还不够）：

- `72a2762` 给资产工作台做了主区禁词扫描（0 命中）+ 技术详情收起；
- `front/src/pages/aiStudio/components/maskInternalIds.ts` 提供了现成的屏蔽工具
  （UUID / `file_id=` / `storage_key` / 字段名 → 替换为「（内部 ID 见「技术详情」）」）。

**但覆盖率很低（2026-09-26 核实）**：`maskInternalIds` 全仓库仅 4 处引用
（`ChapterStudio.tsx`、`ShotBoundFilesPanel.tsx`、`assetPromptQuality.ts`、`assetProduction.ts`）。
其余主流程页面——项目大厅、工作台五步的其它区域、任务中心、提示词看板、实体管理、
设置/模型页——都没有过这道处理。而 `ChapterStudio.tsx` 本身约 6600 行，只遮几处等于没遮。
这就是"做了但没改善"的直接原因：**口径有了，执行面太窄**。

## 目标与判断标准

三层信息模型（判断每一条文案/字段该放哪层）：

1. **第一眼层（主区）**：只放用户要**决定**的事——名称、业务状态（中文）、缺失项、
   推荐操作、结果（图/视频）、金额或次数（「将调用 1 次模型 / 生成 4 张」）。
2. **折叠依据层**：为什么这么建议——生成依据、剧本片段、质量原因（中文转述）。
3. **技术详情层（默认收起）**：内部 ID、file_id/storage_key、供应商与原始模型名、
   接口路径与参数、任务号、英文枚举原值、后端错误原文。

**主区出现任何第 3 层内容 = 泄漏**，一律收口。参考标准：巨日禄类产品的用户只看
「做什么 / 什么状态 / 结果」，依据与参数默认收起。

## 泄漏模式清单（审计时按这 6 类找）

| # | 模式 | 典型形态 | 收口手法 |
|---|---|---|---|
| 1 | 内部 ID / UUID 直渲 | 资产号、任务号、file_id 出现在卡片/提示/徽章 | `maskInternalIds()` 包裹或移入技术详情 |
| 2 | 后端字段名直渲 | 「该帧槽位没有 file_id」「video_prompt_source 为空」 | `maskInternalIds` 的字段名映射；新词补 `FIELD_NAME_LABELS` |
| 3 | 英文枚举 / 状态码直渲 | `running/failed/dry_run`、asset_type 原值、画质/景别 code | 建**中文映射表**（一处定义全仓复用），主区只渲染中文 |
| 4 | 接口路径 / URL 直渲 | `/api/v1/...`、本机地址、OSS key 出现在错误提示 | 主区换成一句指路，原文进技术详情 |
| 5 | 供应商 / 模型名直渲 | provider 名、模型 ID 出现在按钮/卡片/结果区 | 业务化名（「当前模型方案」），原名进技术详情 |
| 6 | 后端错误原文直渲 | `message.error(err.detail)` 把堆栈式文案弹给用户 | 统一 message 包装层：主区给中文人话 + 「详情」可展开原文 |

## 执行方式（两阶段，先审计后动手）

### 阶段 A：只读审计（不改任何代码）

产出《前台泄漏审计清单》（Markdown，放 `site/content/docs/plans/` 或仓库外由用户定），
按页面逐项列出：文件:行号 → 泄漏模式（1-6）→ 当前文案 → 建议口径。

扫描方法（组合使用，不许只靠其中一种）：

1. **静态扫描**（`front/src/`）：
   - `message\.(success|error|warning|info)\(` 直渲后端 `detail` / `error` 的调用点；
   - JSX 中直渲 `task_id|file_id|asset_id|shot_id|chapter_id|storage_key|job_id|trace`；
   - 直渲后端状态字段但未过中文映射的（找 `.status}}`、`.source}}`、`.channel}}` 等裸露插值）；
   - `/api/v1`、`http://`、`https://` 出现在 JSX 文案或 message 里；
   - 已有 `maskInternalIds` 的 4 处引用点**周边**是否还有漏网（同文件扫一遍）。
2. **运行时走查**：演练模式启动前后端，按下方页面优先级逐页截图核对
   （只读操作，**禁止触发任何付费按钮**）。

页面优先级（按主流程顺序，也是收口顺序）：

1. 项目大厅 / 新建项目向导
2. 项目工作台五步（第 1 步剧本分镜 → 第 2 步资产生产 → 第 3 步整集提示词 → 第 4 步绑定 → 第 5 步生成交付）
3. 章节工作室 `ChapterStudio.tsx`（约 6600 行，重点：生成按钮区、结果区、帧/音频区、全部 `message.*`）
4. 任务中心 `TaskCenter.tsx` 与任务通知（任务号、状态枚举是重灾区）
5. 提示词看板 / 资产详情抽屉 / 「待处理」抽屉
6. 实体管理（角色/场景/道具/服装列表与编辑）
7. 设置 / 模型与供应商页（这页允许技术性最强，但主区仍要中文化）

### 阶段 B：逐页收口（用户确认审计清单后开工）

- **搭车原则**：与需求一（主流程修复）改到同一页时顺手收；不为此单独大规模翻动页面。
- **每页独立 commit**，一个 commit 只收一个页面的泄漏（AGENTS.md 混合 hunk 规则）。
- 收口优先复用 `maskInternalIds`；模式 3（英文枚举）若全仓没有统一映射表，
  新建 `front/src/pages/aiStudio/components/enumLabels.ts`（一处定义、全仓引用、配单测），
  不允许每个页面各写一份映射。
- 模式 6 建统一的 message 包装（主区中文人话 + 可展开原文），不逐点手写 try/catch 文案。
- 技术详情折叠组件已有先例（`ShotProductionWorkspace.tsx:150` 等），新收的页面照抄形态。

   一条「主区 0 命中」测试——禁词表 = 泄漏模式 1/2/4 的正则 + 模式 3 的枚举原值清单。

4. `pnpm exec tsc --noEmit` 与 `pnpm test` 过；不新增 lint 错误（既有 11 条存量另案处理）。

## 边界（不做）

- **不重构页面结构/信息架构**，不动 `ChapterStudio.tsx` 的布局与交互流程——只收文案、
  加折叠、换映射。
- 「技术详情」折叠层**内部**内容不收（那里就是给排查用的）。
- 不改后端错误码与 `meta.error` 结构（前端包装层解决，不动 API 契约）。
- 不处理设置/供应商配置页的深度重构（仅主区中文化）。
- 不触发任何付费调用；走查只点只读路径。
