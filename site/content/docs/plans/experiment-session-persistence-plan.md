# 实验室会话持久化交付计划

## 目标与边界

为文本、图片、视频实验室提供可新建、切换、恢复、重命名与删除的用户会话历史。历史仅用于用户查看，**不得**作为模型上下文自动拼接。

图片与视频会话必须保存生成任务、状态、错误、进度与资料库产物引用；刷新或重新进入后应恢复最终展示。

不在本计划中实现跨实验室会话、多人协作、模型记忆或跨设备用户隔离策略。

## 当前状态

已完成：

- `experiment_sessions`、`experiment_messages` ORM 模型与 Alembic revision；
- 会话创建、列表、重命名、删除、服务端清空、分页消息读取与消息写入 API；
- 三个实验室的会话新建、切换、重命名、删除、URL 定位和历史分页；
- 文本实验室只向模型发送当前用户输入；
- 图片和视频任务与会话消息原子创建，并由 Worker 直接回写终态、错误、进度和结果；
- 会话消息使用原子分配的单调 `sequence` 保持稳定顺序，图片和视频创建接口返回本次提交的服务端消息，由共享前端历史层按 ID 去重接管；
- 会话列表的最近消息摘要、更新时间与运行中任务标识；
- 图片参考图、视频首/尾/关键帧与比例的历史恢复，以及“文件不可用”降级展示。

仍待执行：

- P2 的用户归属、审计、保留策略与归档能力。
- 基于 `sequence` 的游标分页，以及客户端请求幂等键与可靠任务派发；这些属于并发与运维增强，不影响当前消息顺序和单次提交接管契约。

## 目标数据流

```text
用户提交
  → 后端事务：user message + GenerationTask + task message
  → Worker：更新任务状态/产物，并同步 task message
  → 会话消息读取：返回持久化快照与当前任务状态
  → 页面恢复气泡、图片或视频缩略图
```

`payload` 仅保存模型 ID、提示词、参考文件 ID、比例、结果 file_id 等展示快照；禁止写入 API Key、供应商原始鉴权信息或 base64 图片内容。

## 任务拆解

### P0-1：原子创建图片/视频会话任务（已完成）

- 修改 `ImageLabGenerateRequest`、`VideoLabGenerateRequest` 增加 `session_id`。
- 在各自路由中创建用户消息、任务记录、任务消息与 `task_id` 绑定。
- 将数据库提交收敛为单一事务；仅提交成功后再入队。
- 移除前端“创建任务后再创建 task 消息”的串联流程。

验收：任一持久化步骤失败时，不产生孤立任务或孤立消息。

### P0-2：Worker 回写任务消息（已完成）

- 图片 Worker 在 running、succeeded、failed、cancelled 阶段更新 `ExperimentMessage`。
- 视频 Worker 同步更新状态、进度、错误和生成视频 `file_id`。
- 取消接口也必须更新任务消息。
- 读取历史优先使用持久化 `file_id`，URL 仅作为短期回退。

验收：关闭浏览器后任务完成，再进入会话可直接看到正确终态与产物。

### P0-3：修正消息 payload 与异常边界（已完成）

- 增加 payload merge 服务，终态回写不得丢失参考图/模型/比例快照。
- 将三个页面的“持久化用户消息”纳入 `try/finally`，保证失败时恢复提交按钮和草稿。
- 消息 API 返回 Session 不存在时应为 404。

验收：消息写入失败有明确提示；成功任务的历史仍可展示提交配置与结果。

### P1-1：完整会话生命周期 UI（已完成）

- 抽取 `ExperimentSessionList` 或扩展 `ExperimentLabLayout`。
- 提供新建、切换、重命名、删除会话。
- 删除运行中任务会话时提示并拒绝；完成任务会话允许删除。
- “清空历史”改为服务端清空消息或新建会话，不再使用本地 `setMessages([])`。

验收：刷新后清空/删除结果保持一致；三个实验室交互一致。

### P1-2：会话定位与历史性能（已完成）

- 使用 `?session=<id>` 同步当前会话。
- 增加消息分页 API；前端支持加载更早历史，并在合并分页结果时按消息 ID 去重。
- 会话列表显示最近消息摘要和运行中任务标识。

验收：可复制 URL 直接恢复指定会话；长会话首屏不加载全部消息。

### P1-3：历史展示完整恢复（已完成）

- 图片气泡恢复参考图缩略图、生成图 file_id。
- 视频气泡恢复首/尾/关键帧、比例、视频缩略图与预览。
- 文件被删除时展示“文件不可用”降级状态。

验收：历史记录的输入配置与结果可独立阅读，不依赖当前编辑器状态。

### P2：数据归属与运维（预留注释已完成，功能待身份体系落地）

- 当前系统未实现用户与权限能力，本阶段不新增 `owner_id`、鉴权依赖、审计表或保留任务。
- 已在 `ExperimentSession` 模型预留未来 `owner_id`、归档状态和复合索引的迁移边界注释。
- 已在会话 API 预留统一 `current_user` 注入、`owner_id` 过滤及删除/清空审计的注释。
- 身份体系落地后，再实现会话归属、鉴权过滤、审计删除、保留策略、产物 GC 与归档索引。
