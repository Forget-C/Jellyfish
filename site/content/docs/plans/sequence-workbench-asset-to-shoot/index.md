## 1. 目标与范围

用户应能明确回答三个问题：创建的资产在哪里、是否已经关联本场；确认设计后下一步做什么；进入试拍后先拍什么、还缺什么、何时才真正开始生成。

本计划承接[镜头视图与全场关系总览优化计划](/docs/plans/sequence-workbench-scene-overview/)第10节已完成的资产入口和筛选空白修复，保持既有全站布局、品牌、面包屑、侧栏与工作区风格。原计划的完成状态和历史验收记录不改变。

- 本轮范围：本场资产面板、资产创建与详情往返、设计确认后的下一步、试拍起步与单元内步骤引导。
- 继续复用现有资产管理、生成指令、审稿、执行及候选素材能力，不另建资产库或生成流程。
- 不重做剪辑验收，不改变已确认版本不可原地改写、候选不自动采用等业务边界。
- 本文维护目标规格与实施进度；生效行为同步到架构和指南，验收结果独立记录。

## 2. 评估基线中的行为

### 2.1 资产创建与关联

| 当前操作 | 实际结果 | 体验缺口 |
| --- | --- | --- |
| 按需创建人物 | 创建当前项目的角色档案，不是演员资产 | 未明确创建对象的归属与去向 |
| 按需创建场景或道具 | 创建实体，并建立项目／章节关联 | 用户可能误认为只创建了本场关联 |
| 创建成功 | 刷新资产选项，不自动关联本场，不生成实际图片 | 缺少结果反馈、查看资产与准备图片入口 |
| 在本场下拉框选择资产 | 修改当前设计的资产引用，仍需保存设计 | 资产已创建与设计关联已保存容易混淆 |
| 创建场所时初始化图片视角记录 | 存在图片位置记录，不等于已有图片文件 | 不能据此显示“图片已准备” |

角色可在项目工作台“角色”查看；场所可在项目“场景”及资产管理查看；道具沿用既有项目与资产详情入口。创建流程不应把角色称为演员，不把故事场次与场所资产混用。

本地样本的设计02已确认，本场关联为角色“张三”和场所“胡同马路”，共2项。这个观察仅证明当时的关联状态，不证明图片准备完成或已选入试拍参考。

### 2.2 确认设计与进入试拍

- 确认设计只确认该设计版本，不创建生产计划或拍摄单元。
- 直接点击“单元试拍”只切换工作区。
- “为此设计准备试拍”设置固定设计依据，初始化一个无单元、未保存的计划，然后切换工作区。
- 试拍准备区域在没有当前计划或无法取得计划依据时，统一显示“先确认导演设计，再创建拍摄单元。”；已确认设计也会出现这条错误提示。
- 没有计划时仍显示空单元列表、参数栏、禁用操作和四个子页签，下一步隐藏在计划选择控件中。

评估依据：`SceneAssets.tsx`、`SequenceWorkspacePage.tsx`、`ProductionWorkbench.tsx`、`PlanEditor.tsx`，以及后端 `services/directing/workspace.py`、`services/studio/entity_crud.py`。本地只读检查与代码一致。

## 3. 资产面板交互规格

### 3.1 用紧凑清单表达本场需求

保留侧栏顶部“本场资产”和有效关联数量。面板按角色、场所、道具分组，每项展示本场对象、已关联资产、实际图片状态与操作；项目风格放在底部独立区。

| 本场对象 | 关联资产 | 图片状态 | 操作 |
| --- | --- | --- | --- |
| 张三 · 角色 | 张三 | 按实际可用文件核实 | 查看资产、更换 |
| 本场场所 | 胡同马路 | 按实际可用文件核实 | 查看资产、更换 |
| 白色面包车 · 道具 | 未关联 | — | 关联已有、新建并关联 |
| 警用甩棍 · 道具 | 未关联 | — | 关联已有、新建并关联 |

- 上表为结构示意，类型须来自现有明确数据或用户选择，不仅凭名称推断。未知类型先提供类型选择，不为每个对象同时平铺角色与道具两个下拉框。
- 已有多个合法关联不能因界面简化被静默清除；应展示当前关联并提供显式调整入口。
- 有实际图片时显示缩略图；无图片显示“尚无图片”；加载中、不可用及核实失败独立表达，不把缺失数据当作零。
- “更换／解除关联”作为行内次级操作，解除引用不删除资产实体。
- 数量继续按当前项目可核实的资产类型与身份去重，不按人物名称、参与项个数或图片槽位计数。

### 3.2 从具体对象发起创建

主路径为“本场对象 → 新建并关联 → 创建档案 → 返回原对象行”。创建面板预填已有名称和类型，只带入跨场稳定设定，不把本场动作或临时状态写入全局资产描述。

创建前明确展示：

- 保存到：项目「123」→ 角色。
- 创建后关联到：本场人物「张三」。
- 本次创建档案，不生成图片。

主按钮为“创建并关联”。若保留独立创建入口，应明确命名“仅创建项目资产”，并解释尚未关联本场，不能继续使用含义模糊的统一按钮。

创建完成后，原对象行保留结果反馈，例如“角色档案「张三」已创建；本场关联待保存”，并提供“查看资产”“准备图片”。区分以下结果：

1. 资产创建失败：保留输入，可重试，不伪造关联。
2. 资产创建成功、设计关联未保存：保留精确的新资产身份，支持继续关联与保存，不重复创建。
3. 设计关联保存成功：才显示关联已保存。
4. 创建请求结果不明确：先核实结果，不能按同名列表猜测新资产或直接重发创建。

已确认设计的引用变化进入新设计草稿，提前说明“关联将保存到新设计草稿”，不改写原确认版本。取消本场关联不应回滚或删除已经创建的资产。

### 3.3 详情、图片与返回路径

- “查看资产”打开精确资产详情，展示名称、类型与所属项目，支持“返回本场资产”。
- “准备图片”进入既有资产图片能力；生成与上传由用户明确发起，创建档案本身不启动图片生成。
- 往返保留场次、设计版本、原对象、范围、面板位置和未保存编辑；需保存或处理冲突时使用已有草稿保护，不静默丢弃输入。
- 返回时重新核实资产及实际媒体状态；列表加载失败不能删除已有引用。

分别表达四个事实：**资产已建档、本场已关联、已有可用图片、已选入本次试拍参考**。它们不是一个统一完成状态，也不是所有生成任务都必须按顺序通过的硬门槛。角色档案不能假定已绑定演员；图片可用不能推导为当前单元已提交该图片。

## 4. 确认设计到试拍的统一衔接

### 4.1 确认后的主操作

确认成功后保留当前页面，版本栏显示“设计02 · 已确认”，主操作改为“准备试拍 →”，提供一句下一步说明：“选择要试拍的镜头，配置模型与参考素材。”已禁用的确认按钮不再占据主要操作位置。

确认设计与准备试拍保持独立；只浏览或确认设计不自动创建计划、提交生成任务或产生采用行为。

存在计划时以精确设计版本匹配：

- 唯一匹配且没有冲突草稿：提供“继续试拍”，明确显示计划及设计依据。
- 多个匹配：列出名称、状态与依据，用户选择，不自动取最新。
- 只有其他设计版本的计划：标明差异，不将其作为当前设计的试拍结果。
- 已有明确选中的计划：尊重该选择，显示其依据；从另一设计发起准备时解释差异并保护正在编辑的计划。
- 重复进入准备入口复用匹配的未保存准备状态或提示用户选择，不反复初始化、覆盖或创建空计划。

### 4.2 直接进入试拍时按真实状态引导

“准备试拍”按钮和“单元试拍”Tab使用同一套上下文与下一步判断。Tab仍是导航入口，不因点击而写入计划；已确认但无计划时，显示同一准备起点。

| 状态 | 主内容 | 主操作 |
| --- | --- | --- |
| 尚无已确认设计 | 当前设计尚未确认 | 返回导演设计；如有其他确认版本，显式选择 |
| 当前设计已确认，尚无计划 | 从设计02开始准备试拍 | 选择镜头，建立试拍草稿 |
| 有匹配计划，尚未选择 | 已有可继续的试拍计划 | 打开计划 |
| 计划尚无单元 | 选择本次要拍的镜头 | 添加拍摄单元 |
| 已有单元 | 所选单元的工作内容与准备缺项 | 完成当前准备事项 |
| 计划或设计依据不可用 | 无法读取具体依据及原因 | 重试／重新选择 |

无计划时保留全站框架和阶段导航，中央聚焦开始入口；不展示空参数栏、无意义的单元搜索、不可用的拆分重组与保存确认按钮。已有内容不能被加载错误伪装为空白起步页。

### 4.3 从“拍什么”开始建立草稿

准备区展示依据的设计版本及镜头清单，包括镜头编号、动作摘要和预计时长。用户勾选镜头后点击“建立试拍草稿”，才初始化单元；进入页面本身不替用户选拍摄范围。

- 默认建议一镜一个单元；多镜组合为明确选择的进阶操作，并核实模型能力。
- 简短解释：“拍摄单元表示一次计划生成的动作范围；同一镜头可以试拍多次。”
- 预计镜头时长与模型可执行时长分开，不能直接认定预计值满足模型限制。
- 草稿采用显著的“未保存”状态；保留显式保存边界，建立草稿不启动生成。
- 单元基于固定设计版本和真实镜头身份创建覆盖项，保留动作范围及有关引用，不恢复旧Shot身份或状态。

## 5. 单元试拍内的步骤与下一步

保留既有能力，以紧凑的步骤导航表达顺序和真实状态，不增加占满主区的大卡片或长说明：

**① 拍摄准备 → ② 生成指令 → ③ 检查与试拍 → ④ 候选素材**

| 步骤 | 核心工作 | 主要动作 |
| --- | --- | --- |
| 拍摄准备 | 动作范围、模型、时长、参考素材 | 保存并确认拍摄准备 |
| 生成指令 | 准备并查看本次实际内容与冻结输入 | 尚无指令时“准备生成指令”；已有指令时“检查生成指令” |
| 检查与试拍 | 处理阻塞、核对输入与审稿结论 | 满足条件后“开始试拍” |
| 候选素材 | 比较视频、检查实际覆盖 | 审片并选择可用区间 |

- 步骤不是只能前进的向导，已完成内容允许回看；切换单元按计划、单元、提示词和审稿的真实身份恢复上下文。
- “保存并确认”即使合并为一个用户动作，也须区分两次操作的结果；保存成功但确认失败时显示可重试确认，不误报完成。确认已有基线的修改仍派生新版本。
- 缺项提示应具体到“选择视频模型”“补充所需首帧”等，并能定位字段；服务端校验仍是执行依据。
- 每一步只有一个主要下一步动作；保存草稿等次级动作仍可用，任务和历史保持独立入口。
- 生成中显示本单元任务状态；失败展示真实原因；成功显示“候选素材已生成”，不自动采用。
- 从本场资产挑选实际可用文件作为参考，用户显式选择用途与位置；不自动提交该资产的所有图片。
- 缺图是否阻塞由模型及输入要求决定，支持纯文本的模型不能被统一“所有资产必须有图”门槛阻止。

### 6.1 实现边界

- 优先复用现有页面、草稿保护、计划与任务上下文及generated client；不为一次流程新增通用工作流框架。
- 当前创建资产接口返回整个列表。E2须提供可靠的创建结果身份；优先评估在契约中明确返回新实体，禁止用名称或“列表最后一个”推断。如果变更接口，应同步后端、OpenAPI及前端generated client。
- 图片准备状态必须来自真实媒体可用性；当前资产摘要不足时按需补充读取或契约，不从存在图片槽位推断已有可用图片。
- 每阶段只修改相关组件及受影响文档；不重构无关资产管理或生成服务。

## 7. 最终验收标准

- [x] 用户创建角色／场所后能立即看到准确结果、归属和详情入口，并理解未自动生成图片。
- [x] 创建资产与保存设计关联分别反馈；资产已创建但关联失败时可继续，不重复创建。
- [x] 已确认设计的关联变更进入新草稿，原版本与旧计划依据不变。
- [x] 资产详情往返保留未保存编辑及定位，当前项目与资产身份不混淆。
- [x] 确认设计后有明显下一步；直接进入试拍与准备按钮到达一致的正确起点。
- [x] 没有计划、没有单元、未选择、加载失败分别表达；有内容时不错误清空或提示尚未确认。
- [x] 唯一、多计划、其他设计版本及未保存准备状态均有明确处理，不重复创建计划。
- [x] 用户先明确选择拍摄范围，再建立草稿；模型、参考、确认、指令、审稿与执行不被浏览动作隐式触发。

- [x] 候选生成成功不代表审查通过、实际覆盖完成或已经采用。
