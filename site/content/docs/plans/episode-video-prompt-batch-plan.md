## 背景（用户 2026-09-19 提出的流程修正）

现状把大模型生成视频提示词摆在**分镜工作台第 4 步**，等于要求用户进入工作台后**逐镜生成或逐条导入**。
这与真实工作方式相反：一整集（7~20 条）的提示词通常是**一次生成或一次导入**，统一校对确认后，
才进工作台做绑定与生成。工作台应只承担**逐镜检查与补漏**。

## 目标流程

1. 剧本拆分成一整集的若干镜头（第 1 步）。
2. **集级页面**（进入工作台之前）：
   - 批量生成：选当前集全部/部分镜头，一次产出 7~20 条视频提示词，按镜头顺序展示，确认后批量保存；
   - 批量导入：粘贴文本或上传文件 → 解析成多条 → 自动按镜头编号/顺序匹配 → 预览 → 确认。
3. 进入分镜工作台：已能看到整集提示词，逐镜检查修改、绑图片/声音/参考帧、生成视频。

## 硬要求

- 默认**只填充空白镜头**；另提供「覆盖用户选中的镜头」「跳过已确认的提示词」。不得静默覆盖巨日禄导入、人工编辑与已确认内容。
- 导入前**必须预览**：镜头编号 — 镜头内容 — 待导入提示词 — 匹配状态；数量不一致 / 编号重复 / 无法匹配 / 镜头缺失要明确提示，不能错位写入。
- 工作台保留「单镜生成 / 重新生成」，定位补漏与返工。

## 实现要点（待做）

| 组件 | 说明 |
|---|---|
| 集级页面 | 位置与第 4 步导航的关系需要定：建议沿用项目工作台第 4 步（`step=video_prompt`）作为集级入口，工作台内的面板降级为"单镜补漏" |
| 批量生成 | 复用 `previewVideoPrompt`（真 LLM）逐镜串行 + 可停止/重试；按镜头顺序返回；保存走现有 `PATCH /studio/shot-details/{id}`（来源 `llm`，且只在 `meta.llm_called=true` 时允许） |
| 批量导入解析 | 新增解析器：按空行/编号（如 `S001`、`1.`、`#1`）切分多条；输出「候选条目 + 匹配到的镜头 + 匹配依据」 |
| 匹配冲突报告 | 数量不一致、编号重复、无法匹配、镜头缺失四类显式列出，任一存在则**禁止一键保存**，只能逐条调整 |
| 覆盖策略 | 三选一（默认只填充空白），服务端记录来源（`llm` / `jurilu` / `manual`），来源白名单与交付导出一致 |
| 验收 | 7~10 镜小项目：批量生成一次、批量导入一次、数量不一致不错位、工作台每镜读到对应提示词、改一镜不影响他镜 |

## 现状与风险

- 已可复用：工作室内的 `VideoPromptLlmPanel`（批量生成面板）、`previewPromptDelivery`（整集镜头与来源清单）。
- 风险：导入解析若只按顺序匹配，遇到"镜头数 < 提示词数"极易错位 —— 因此**匹配状态必须在预览里逐条可见**，
  且默认策略遇到数量不一致直接拦下。
