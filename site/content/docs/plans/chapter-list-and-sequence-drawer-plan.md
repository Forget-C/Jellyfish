# 章节列表与场次抽屉交互优化计划

> 状态：已完成。P1–P4 已落地，验收结果与证据见第 7 节。用户明确要求：不增加跨章节的待核对数量、粗剪数量；章节主表不设置对应统计列，也不为此新增汇总接口或逐章加载请求。

> 后续优化见[章节信息与原文选区划场优化计划](/docs/plans/chapter-source-selection-and-division-plan/)（已完成）：补充表格信息、默认场次详情、收敛正文编辑入口，并将手动与 AI 划场统一到完整原文选区视图。本文保留本轮完成范围和验收记录。

## 1. 目标与现状

章节页以章节列表为主体，便于比较章节名称和场次数量；点击章节名称编辑章节，点击场次数量管理本章场次。完整导演设计、试拍、剪辑与验收继续使用独立场次工作台。

实施前基线（2026-09-29 工作区代码核对）：

| 现状 | 判断与处理 |
| --- | --- |
| `ChaptersTab` 使用章节下拉框，主区展示当前章场次 | 确实缺少多章节总览；改为章节表格 |
| `ChapterRawTextEditorModal` 已支持原文编辑、精简与对比等操作 | 复用编辑器；补齐章节名称编辑及保存原文时的影响说明 |
| `SequenceDetails` 已支持名称、顺序、原文范围编辑和阶段跳转 | 将详情内容放入场次管理抽屉内部，不重写业务流程 |
| 章节列表接口已返回 `sequence_count` | 直接复用已有字段，不新增统计契约 |
| `source_changed` 比较整章原文版本，已有场次摘录不自动更新 | 即使只改标点，也可能使本章所有已有场次需要核对；相关试拍仍受现有检查约束 |

本计划是[章节、场次与工作台交互优化任务计划](/docs/plans/chapter-sequence-workbench-interaction-plan/)完成后的入口调整：将章节主区从场次列表改为章节表格，保留已落地的版本、阶段直达、来源校验及草稿保护能力。前序计划的完成记录不改写。

取舍：章节比较更直接，但从章节主表进入场次增加一次打开抽屉的操作。通过抽屉内连续切场、阶段直达和返回恢复降低重复操作，不把本方案表述为所有路径都更短。

## 2. 范围与成功标准

### 2.1 本轮范围

- 章节表格、章节编辑弹窗、单层场次管理抽屉及窄屏适配。
- 原文实际变化时的影响提示、保存确认和保存后的本章核对入口。
- 复用原文划场、章节活动、章节组合入口，保留新建章节后的后续操作。
- 章节和场次浏览位置恢复、深链接、未保存保护、加载失败与过期响应处理。

### 2.2 明确不包含

- 跨章节的待核对数量、粗剪数量及相关表格列、顶部统计卡、筛选器和汇总接口。
- 为填充章节表格而逐章请求 `ChapterOverview`、章节组合或完整工作台。
- 将设计、试拍、剪辑状态合成一个章节完成率，或用 `Chapter.status` 代替生产进度。
- 原文自动重划场、自动覆盖摘录、自动更新设计或计划、自动拍摄与自动采用。
- 改变整章原文版本判断、已确认版本不可原地修改等现有业务规则。
- 重做场次工作台、扩展版本系统、增加无关的批量编辑或通用面板框架。

前一轮交互示意中的章节“待处理”列不纳入本计划。示意仅用于说明入口和面板关系，不作为统计字段或已实现能力的依据。

### 2.3 成功标准

1. 默认进入章节页看到章节表格；无需切换章节即可比较名称和场次数量。
2. 名称与场次数量分别打开正确的编辑/管理入口，`0 场`也可操作。
3. 同一抽屉内完成场次选择、详情编辑和保存，无二级场次详情抽屉。
4. 保存原文前说明对已有场次的影响；保存后能进入本章核对，提示不依赖一次性消息。
5. 浏览、保存基本信息和进入工作台互不混淆；已有来源、版本与采用语义保持有效。
6. 关闭、返回、切场和失败重试不丢输入、不串章节、不发起隐式业务写入。

## 3. 页面与交互设计

### 3.1 章节主表

默认列为：

| 列 | 内容 | 交互 |
| --- | --- | --- |
| 章节名称 | 章节序号与名称；可在副行显示已有原文的字数 | 点击打开“编辑章节”，显示明确的编辑提示 |
| 场次数量 | `8 场`、`0 场`，均为可聚焦操作入口 | 点击打开本章场次管理抽屉 |
| 操作 | 章节组合等现有必要入口 | 按需打开相应面板 |

- 不设置“待处理”“粗剪进度”或类似统计列。原文变化、候选待审、已有确认粗剪等信息仍在选定章节的场次列表逐场显示。
- 不将整行设为点击区域，避免与名称、场次数量两种入口冲突。
- 默认按章节顺序排列，复用现有分页与标题搜索能力；不能把固定读取的前 100 章当作完整列表。主表和抽屉内的场次搜索分别保存。
- 读取中、无章节、无搜索结果和读取失败分别展示；失败不能显示成“尚无章节”，场次数量未知不能显示为 `0`。
- 保留“新建章节”。创建成功后更新主表；有原文时进入该章划场，无原文时引导填写原文，不自动分析或创建场次。

### 3.2 编辑章节

- 使用大尺寸弹窗；窄屏改为全屏编辑。展示当前章节身份，编辑章节名称和原文，复用现有精简、对比及辅助能力。
- 原文区域常驻提示：**“改变章节内容后不会自动更新场次。”** 说明中的“章节内容”指作为场次来源的章节原文；名称和精简文本不触发原文版本变化。
- 普通保存、关闭时选择保存、对比视图保存、AI 优化结果保存都进入同一保存判断，不能出现绕过影响提示的路径。

| 保存情况 | 行为 |
| --- | --- |
| 无实际修改 | 不提交无效更新，不弹影响确认 |
| 仅修改名称或精简文本 | 正常保存，不提示场次原文失效 |
| 原文实际变化且无场次 | 正常保存；保留常驻说明及划场入口 |
| 原文实际变化且已有场次 | 提交前显示影响说明，明确确认后才保存 |

影响说明使用本章已有场次数量，来自已有章节读取接口，不属于新增跨章节汇总：

> 修改章节原文不会自动更新已有场次的划分和原文范围。本章已有 N 个场次，保存后需要重新核对。已有设计和素材保留，继续试拍前还需核对相关设计与计划依据。

- 普通保存的影响确认就地展开，提供“确认保存原文”和“继续编辑”，不再叠加一层业务弹窗；离开时复用已有未保存确认，并在“保存后继续”前展示同一影响说明。用户继续改动原文后，需要重新确认当前内容。
- 场次数量读取失败时不按零场处理；保留输入并提供重试，不能用不可靠数据省略影响说明。
- 保存成功后保持编辑器可见，并在原文变更且已有场次时提供“查看本章场次并核对”。该入口打开本章场次抽屉；章节主表不新增待核对数量。
- 保存失败保留全部输入、说明与重试入口；保存请求进行中防止重复提交和关闭造成的输入丢失。

### 3.3 场次管理抽屉

桌面使用宽抽屉，内部为左侧场次列表、右侧详情编辑。宽度根据视口调整，保证原文范围可阅读；窄屏使用同一全屏面板内的“列表 → 详情 → 返回列表”。

- 抽屉标题明确章节名称。首次打开优先恢复有效的本章场次选择；无记忆时显示列表，右侧提示选择场次。无效记忆回到列表，不自动替换显式深链接中的无效对象。
- 列表展示顺序、名称、简短摘录和已有逐场状态。保留“核对原文”“继续设计”“继续试拍”“审片”等现有建议入口；建议不代表执行准备就绪。
- 点击场次名称在右侧展示详情，保留名称、顺序、原文范围编辑。完整原文按需用于对照，不把原文范围输入误解为独立改写章节正文。
- 摘录必须匹配当前章节连续原文；重复出现时保留明确选择位置的能力。保存继续提交既有场次版本和原文版本，冲突保留输入。
- “保存”保存后留在当前场次；阶段入口直接进入独立工作台，不要求先打开详情。“保存并进入工作台”如保留，必须与普通保存明确区分。
- 场次原文待核对提示持续显示在列表和详情，核对成功后刷新服务端状态。不得仅在前端清除标记，也不得宣称旧设计和旧计划已自动更新。
- `0 场`显示空状态及“从原文划分场次”。本章无原文时先引导编辑；有原文时提供人工划场、AI 分析及建议确认。AI 建议不自动成为场次。
- 场次新建、名称/顺序修改及原文范围保存后刷新对应列表；影响场次数量的操作同时刷新章节主表。仅保存名称或原文范围不自行增减数量。

### 3.4 辅助面板与层级

- 原文与划场、章节活动、章节组合保留可达入口，使用同级面板切换或当前容器内视图切换；返回时恢复原场次选择及列表位置。
- 不在场次管理抽屉上再叠加场次详情抽屉。进入章节编辑时先处理未保存内容，关闭编辑后可回到来源面板。
- 复用已有人工划场确认和任务结果逻辑，避免为了统一外壳重写业务组件。任务历史不铺在章节主表或场次主列表中。

## 4. 导航、草稿与数据边界

### 4.1 路由与浏览记忆

优先沿用已有查询参数，不新建另一套章节管理页面：

| 地址参数（项目路径下） | 展示内容 |
| --- | --- |
| `?tab=chapters` | 章节表格；可恢复表格搜索、页码和滚动，不因旧章节记忆自动弹出抽屉 |
| `?tab=chapters&chapter=:chapterId` | 章节表格及该章场次管理抽屉 |
| 上述参数增加 `sequence=:sequenceId` | 抽屉内定位场次详情 |
| 上述参数增加 `panel=source` 或 `panel=assembly` | 对应章节辅助面板；不同时打开场次管理抽屉 |
| `?tab=chapters&edit=:chapterId` | 章节编辑入口；继续兼容已有编辑深链接 |

- 保留现有旧章节场次路由的重定向，以及场次工作台的独立路径、版本、对象和任务定位参数。
- 显式链接优先于浏览记忆；章节/场次不存在或归属不符时提示错误并提供返回入口，不悄悄打开另一对象。
- 打开章节抽屉形成可返回的导航；抽屉内选场、筛选与面板切换避免制造大量后退记录。关闭时明确回到章节表格并清理本次面板参数。
- 从工作台返回恢复该章抽屉、选中场次和列表位置；主表与场次列表的搜索及滚动各自保存，按项目、章节隔离。
- 浏览记忆仅保存定位信息，不保存原文、未提交正文或执行授权；会话存储不可用时仍可正常操作。

### 4.2 未保存保护

复用 `WorkspaceDrafts` 及现有编辑器保护，统一覆盖关闭按钮、取消、遮罩、Escape、浏览器后退、切场、切章和进入工作台：

- 有修改时提供“保存后继续 / 放弃修改 / 继续编辑”；取消或关闭确认本身不能等同放弃。
- 保存成功后才完成待执行导航；失败或版本冲突继续停留并保留输入。
- 写入中禁止重复保存和冲突导航，迟到响应不能覆盖另一章或另一场的编辑内容。
- 编辑器关闭时的保存仍遵循原文影响确认，不能因离开流程而绕过。

### 4.3 请求与契约

- 主表使用 `StudioChaptersService` 的既有分页列表及 `sequence_count`；编辑按需读取章节；只在打开某章抽屉时读取该章概览，详情/划场再按需读取完整原文。
- 原文保存后刷新本章已加载的场次概览和来源数据；原文范围编辑不能拿旧版本继续提交。未保存场次输入先经过保护，不用后台刷新直接覆盖。
- 场次数量从可靠列表/详情读取结果更新，不将更新响应中可能缺省的计数字段当作新的零值。
- 本方案预计仅涉及前端与文档，无新增接口、数据迁移或生成契约。继续使用 generated client，不新增手写 service。
- 如实施发现必须改变外部契约，先记录具体缺口与范围变化，再按项目规则同步后端、OpenAPI 和 generated client；不以此引入本轮排除的汇总统计。
