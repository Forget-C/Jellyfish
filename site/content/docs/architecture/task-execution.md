## 状态与维护入口

本地任务生命周期的唯一真相源是 `tasks.status`，唯一写入口是 `TaskService`。API 接收请求并组织响应，Worker 执行外部操作和报告事实，`TaskQueries` 读取任务及结果。其他服务不得直接创建、修改或删除 Task 行。

本地状态只有 `queued / running / succeeded / failed / cancelled`。`stage` 表达 queued、submitting、polling、saving、finished 等阶段，`progress` 可以为空，两者不构成独立状态机。

Vidu 的 `created`、`queueing`、`processing` 均属于远端处理中，继续查询同一 ID，不作为失败。

供应商是远端生成事实的权威来源，`remote_status` 保存最近一次观察。本地任务完成还需要保存输出及处理业务交付，因此供应商 succeeded 时，本地任务仍可处于 running / saving。

| 生命周期操作 | 维护方法 |
| --- | --- |
| 创建与领取 | submit、claim / claim_next |
| 登记供应商 ID | record_submission |
| 保存轮询观察 | record_poll_result |
| 更新进度 | report_progress |
| 请求取消 | request_cancel |
| 登记输出 | add_output |
| 成功、失败、取消终结 | finish |

`finish` 在任务行锁下统一裁决终态，优先处理已登记的取消意图。成功时，业务数据库交付和任务终态在同一事务提交；终态不可被迟到的完成、失败或取消请求覆盖。媒体输出数量和顺序必须完整，任务才能成功。

## 数据模型

核心存储由四张表组成：

- `tasks`：一次提交的一条执行及历史记录，保存类型、目标、项目、输入快照、状态、时间、文本结果、错误和远端跟踪字段。
- `task_inputs`：以 task_id、role_path、ordinal 标识输入位置，关联不可变文件；媒体分组布局保存在输入快照中。
- `task_outputs`：以 task_id、ordinal 标识输出，关联 files，并记录 published、conflicted 或 skipped 的交付结果。
- `files`：文件身份与唯一对象 key，保存内容类型、大小、哈希、可选媒体元信息和删除标记。

业务图片槽位、镜头视频引用、file_usages、供应商配置、实验室会话及消息继续保留。它们不再复制一套可独立更新的任务生命周期。Run、Attempt、TaskLink、ProviderOperation、Blob 和 outbox 不属于当前执行模型。

输入快照冻结提交参数、模型名称及供应商路由标识，不写入供应商凭据。文件通过 ID 引用，不在任务快照中保存下载后的 data URL。模型或供应商已不可用、必需输入缺失时，任务直接失败。

## 执行进程与容量

FastAPI 在业务事务中创建 queued 任务并返回 ID。独立进程 `python -m app.task_worker` 从数据库领取任务，不依赖 Redis 或 Celery。

当前部署约束是 **一个 Worker 调度进程**。内部通过异步并发和有界线程池执行；不支持同时启动多个独立 Worker 来扩大吞吐，因为启动中断扫描和远端配额按单进程设计。

默认限制：

| 资源 | 数量或时限 |
| --- | --- |
| 文本活动执行 | 4 |
| 媒体提交 | 4 |
| 供应商状态查询 | 8 |
| 输出下载 | 4 |
| 远端在途任务 | 32 |
| 单次 HTTP 超时配置 | 120 秒 |
| 本地执行、单轮查询及结果收取总时限 | 1800 秒 |
| 远端跟踪期限 | 86400 秒 |

远端任务取得 ID 后释放提交名额，等待下次到期查询。供应商及下载复用异步 HTTP 客户端。网络请求、文件下载和对象上传在数据库事务外执行，数据库事务只处理短时读取、状态变更和业务交付。MySQL 运行连接使用 READ COMMITTED，确保取得文件行锁后的引用检查看到最新已提交数据，而不是事务更早建立的快照；写入仍通过行锁和 CAS 串行化。

同步脚本 Agent 在文本线程池执行。异步等待取消或超时后，底层线程实际结束前仍占用文本名额；停止信号和截止时间阻止后续模型请求。已发送的同步请求不能由 Python 安全强制中断，依靠其网络超时结束；停止后的结果不会发布到业务对象。

## 提交、重启与失败

远端图片和视频只提交一次。成功响应必须包含有效供应商任务 ID；缺少 ID 直接失败，不进入 unknown 状态、不重发 create、不进入恢复对账队列。同步返回图片内容的供应商按 direct 执行。

Worker 启动时：

- queued 任务仍可正常领取。
- running 且已有远端 ID 的媒体任务继续查询同一个 ID。
- 旧进程的 direct 执行，以及没有远端 ID 的运行任务，标记中断失败。

这不恢复本地执行步骤。重新执行创建新 Task，可通过 retry_of_task_id 关联原记录，不把旧失败任务重新改为 queued。

临时查询网络错误记录 last_poll_error 并延后查询，不立即把供应商判为失败。达到跟踪期限后做最后一次查询：已完成则收取，仍未完成或无法查询则结束本地跟踪。供应商失败、必需响应数据缺失或结果收取失败直接结束本地任务。本地失败或取消不表示供应商已停止执行。

异步脚本提取每次新任务都调用生成，不提供 refresh_cache 参数；已有同章节活动提取任务仍可被复用。同步提取接口保留自身的进程内缓存选项。

## 文件与业务交付

媒体输出按 task_id 和 ordinal 生成稳定文件身份与对象 key。上传完整后才登记 files 和 task_outputs；重复收取不会登记另一组输出。部分输出已保存而后续输出失败时，已有输出仍可从历史查询。

生成成功与采用结果分别表达：目标版本变化导致 conflicted 时，保留生成文件，不能覆盖用户的新编辑。候选模式或实验室结果可为 skipped。图片槽位、关键帧及视频发布保留业务版本 CAS，手动采用或清空也递增版本。

文件内容身份不可变。删除先登记 delete_requested_at；活动任务输入输出、业务使用关系和当前槽位引用保护文件。后台每三十秒调度一轮独立分页清理，处理删除请求与超过一天宽限期的孤儿对象，不占用生成并发名额。删除字节后保留文件行和任务输出关系。媒体元信息字段允许为空，不能将字段存在误认为所有格式都已自动探测。输入文件缺少 MIME 时先按对象 key 的扩展名解析，再查对象元信息，不默认假设 PNG/MP4；复用已上传输出也校验媒体类型。

## 查询与界面

`/api/v1/film/tasks` 默认查询完整时间范围，按 created_at、id 游标分页；支持状态、类型、目标、项目和日期筛选。活动面板显式传 recent_seconds，查询活动任务及最近终态，并遍历全部返回页。

列表只读取任务轻量列及快照中的目标父 ID 标量，按来源类型批量解析导航信息，不载入完整输入快照或文本结果。状态接口只查询任务轻量列；结果接口读取 Task 及输出文件，输出历史接口用于业务候选列表。

任务中心展示通用任务信息、历史筛选和回跳入口。来源删除后保留任务历史并隐藏回跳。历史窗口位于任务浮层上方，表格内部滚动以保持筛选与翻页入口可见；刷新失败保留上次结果。镜头及角色有明确项目归属；共享资产和全局实验室不猜测项目。前端缓存是显示投影，不能覆盖服务端终态。

实验消息通过 task_id 在读取时派生状态和结果，并校验任务所属会话；不通过消息表维护另一套任务状态。同步 SSE / inline 文本仍由请求及消息协议处理，不进入异步任务历史。

页面职责保持不变：分镜编辑页负责准备与确认，工作室负责生成准备及生成，任务中心只承担通用状态展示。`shot.status` 仍只表达 pending / ready 的信息确认状态，运行时任务状态与 video-readiness 分别读取。

## 验证与部署边界

架构测试检查 TaskService 外的 Task 构造、批量更新和删除，并检查 Worker 不直接赋值任务状态。这是代码护栏，不是数据库权限隔离。

隔离 SQLite 测试覆盖提交、重启轮询、取消、部分输出、文件引用和前端所需接口；隔离 MySQL 9 已验证迁移后的实际结构、多连接领取与终态竞争。真实对象存储已在独立随机前缀验证上传、分页、读取、删除及历史保留，测试对象已清理；供应商生成和目标环境部署不能由这些测试推定完成。

数据库升级要求见 [数据库迁移与系统种子](../database-migrations/)。收缩迁移不转换旧任务历史。2026-09-14 本地开发库已升级至 13b6a9d2e401，并通过 Vidu 图片提交、换 Worker 轮询、文件保存和历史查询完整实测；这不代表生产环境已部署。

事务读取语义参考 [MySQL 隔离级别说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)。
