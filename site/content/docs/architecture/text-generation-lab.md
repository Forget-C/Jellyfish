# 文本生成实验室

文本生成实验室是独立于项目、资产与分镜生产流程的调试页面。它用于测试已登记文本模型的接入状态，并观察不同提示词在不同模型下的输出。

## 当前范围

- 仅支持文本模型。
- 用户必须从模型管理中已登记的 `text` 类别模型中选择一个模型。
- 用户可以载入任意已有提示词模板，随后自由编辑提示词内容。
- 历史消息仅供用户查看；每轮模型调用只发送当前输入，不进行上下文自动拼接。
- 不包含评分、自动比较、结果排序、文件输入或跨模态生成。

## 输入编排

实验会话的输入区使用通用 Composer，而不是独立的“本轮配置”侧栏。Composer 顶部提供紧凑选项入口：

- 模型选项：选择本轮实际调用的已登记模型。
- 提示词选项：在自由输入与已有提示词模板之间切换。

未选择模板时，用户使用普通文本输入框。选择模板后，输入区会根据模板的 `variables` 和 `variable_defaults` 生成变量表单；模板正文保持只读，提交前可展开查看渲染后的最终提示词。选择“转为自由输入”只会将当前渲染结果复制到本轮输入框，不会更新提示词模板实体。

以下前端组件可由后续图片和视频实验室复用：

- `ExperimentComposer`：选项、模态输入区和提交操作的通用容器。
- `ExperimentOptionBar`：模型和模板的紧凑选择入口。
- `PromptTemplateForm`：变量表单、模板渲染和最终提示词预览。

## 调用链路

页面固定通过 `POST /api/v1/studio/labs/text/sessions/{session_id}/stream`
建立 `text/event-stream`。它只提交本轮模型 ID 与用户输入；不会由浏览器
拼接或持久化聊天历史。前端按增量消费 `accepted → delta/progress* →
completed|error|cancelled` 事件，并以事件的 `sequence` 作为单调 SSE id。

在发送 `accepted` 前，后端会在同一事务写入 canonical 用户消息、`hidden`
的 streaming `GenerationTask`、会话关联与冻结快照。`completed` 只会在成功
写入 canonical 助手消息后发送；失败或取消只更新 hidden run，不创建错误助手
气泡。用户停止时，页面立即中止流连接，并调用会话绑定的
`POST /api/v1/studio/labs/text/sessions/{session_id}/runs/{task_id}/cancel`；该
hidden run 不会出现在任务中心。

## 持久化会话历史

三个实验室共用 `experiment_sessions` 与 `experiment_messages`。会话按实验室类型隔离，支持切换、重命名、删除、服务端清空、URL 定位和按页加载更早历史。会话历史不会参与模型上下文，也不会写入项目、资产或分镜生产链路。

## 历史输入回填

实验室消息统一使用 `header`、`content`、`footer` 三段式气泡：header 放身份或任务标签，content 放提示词与媒体，footer 预留给消息操作。鼠标悬浮用户消息气泡时，footer 右侧显示回填图标；只有点击该图标才会将消息恢复为当前编辑草稿，且不会自动创建新的生成任务。用户确认后再次点击生成时，系统会新增一组用户消息与任务/回复，原历史保持不变。

- 文本消息恢复模型与最终提示词。
- 图片消息恢复模型、提示词和参考图；不可用的文件会被跳过并提示。
- 视频消息恢复模型、提示词、画幅、首帧、尾帧、关键帧与命名主体的图片/视频参考；主体参考与关键帧仍按当前模型能力约束互斥。

图片和视频任务会在用户消息与任务消息的 `payload.input_snapshot` 保存版本化输入快照。旧消息仍可从既有 payload 字段降级恢复。

会话记录保留最近消息摘要、更新时间和运行中任务标识，侧栏仅使用标题呈现这些记录。文本消息持久化为用户与模型气泡；图片、视频任务还会保存模型、参考文件、画幅、任务状态、错误和结果快照。资料库文件不可用时，历史界面保留槽位并显示“文件不可用”。

消息展示顺序由会话内单调递增的 `sequence` 决定，不依赖数据库时间戳精度或随机消息 ID。会话记录维护序号计数器；一次图片或视频提交会在同一事务中预留两个连续序号，依次写入用户消息和任务消息。Worker 完成任务时只原位更新任务消息的状态与结果，不创建新的结果消息，也不改变原有 `sequence`。

图片和视频任务创建接口在提交成功后同时返回 `task_id` 及本次写入的两条持久化消息。前端共享历史层直接按 `message.id` 接管这些服务端消息，按 `sequence` 排序，并将以 `task_id` 读取的轮询状态作为瞬时展示覆盖。首次提交导致页面重挂载时，跨组件暂存的仍是服务端已确认消息；历史接口返回相同 ID 后只做去重，因此不会残留重复的本地用户气泡。

主导航将文本、图片和视频入口收敛为唯一 `/lab` 页面。会话的 `lab_type` 决定当前模态；`/lab?session=<id>` 恢复持久化会话，`/lab?mode=<type>` 表示未持久化草稿。旧的 `/text-lab`、`/image-lab`、`/video-lab` 地址仅作为兼容跳转并保留 URL 查询参数。进入实验室时优先恢复 URL 指定会话，否则打开三种模态中更新时间最新的历史；完全没有历史时默认展示文本生成草稿。桌面端将跨模态会话列表固定在聊天历史左侧，“最近对话”只展示会话标题，以保持低信息密度；新建操作会先弹出文本/图片/视频生成选择，并仅切换到对应的未持久化草稿态。首次有效提交时才创建会话、写入 URL 和最近列表，避免产生无消息的空会话。重命名和删除操作在悬浮会话项右侧菜单中完成；删除当前会话后恢复剩余历史中最新的一项，无剩余历史时回到文本草稿。`ExperimentLabPage` 统一承载页面框架、会话和路由状态；文本、图片、视频模态组件只负责历史解析、输入能力、生成提交和任务展示。

模型与提示词模板在用户首次展开各自选择器时按需获取，并在当前页面生命周期内复用已获取结果；模型、模板、会话和资料库加载状态彼此独立，避免配置请求阻塞草稿输入或历史浏览。

当前系统尚未实现用户或权限领域，因此会话暂为全局数据，不包含 `owner_id` 或鉴权过滤。模型和 API 已标注后续接入边界：身份体系落地时必须通过独立迁移增加会话归属和复合索引，并在整个会话路由统一注入当前用户；删除、清空和归档也需要同步记录审计信息。

## 职责边界

- 文本生成实验室：验证模型与提示词，进行连续文本调试。
- 模型管理：登记供应商、模型和默认模型。
- 提示词管理：维护可选提示词模板及其版本。
- 项目和分镜工作流：只使用正式生产链路，不依赖实验会话。
