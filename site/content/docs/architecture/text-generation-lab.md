# 文本生成实验室

文本生成实验室是独立于项目、资产与分镜生产流程的调试页面。它用于测试已登记文本模型的接入状态，并观察不同提示词在不同模型下的输出。

## 当前范围

- 仅支持文本模型。
- 用户必须从模型管理中已登记的 `text` 类别模型中选择一个模型。
- 用户可以载入任意已有提示词模板，随后自由编辑提示词内容。
- 同一浏览器页面中的历史消息会随下一轮请求一并发送，以支持连续对话式调试。
- 不包含评分、自动比较、结果排序、文件输入或跨模态生成。

## 输入编排

实验会话的输入区使用通用 Composer，而不是独立的“本轮配置”侧栏。Composer 顶部提供紧凑选项入口：

- 模型选项：选择本轮实际调用的已登记模型。
- 提示词选项：在自由输入与已有提示词模板之间切换。

未选择模板时，用户使用普通文本输入框。选择模板后，输入区会根据模板的 `variables` 和 `variable_defaults` 生成变量表单；模板正文保持只读，提交前可展开查看渲染后的最终提示词。选择“转为自由输入”只会将当前渲染结果复制到本轮输入框，不会更新提示词模板实体。

以下前端组件可由后续图片和视频实验室复用：

- `ExperimentComposer`：选项、模态输入区和提交操作的通用容器。
- `ExperimentOptionBar`：模型和模板的紧凑选择入口。
- `PromptTemplateForm`：变量表单、模板渲染和最终提示词预览。

## 调用链路

页面通过 `POST /api/v1/studio/text-lab/generate` 发送模型 ID 和消息历史。后端会验证模型类别为 `text`，使用该模型关联供应商的配置构造 Chat 模型，然后执行一轮调用并返回文本结果。

实验会话当前只保存在浏览器内存中；刷新页面后会清空。该取舍确保首期能力不会向项目、资产或分镜数据写入调试结果，也不会误将测试结果当作正式生产内容。

## 职责边界

- 文本生成实验室：验证模型与提示词，进行连续文本调试。
- 模型管理：登记供应商、模型和默认模型。
- 提示词管理：维护可选提示词模板及其版本。
- 项目和分镜工作流：只使用正式生产链路，不依赖实验会话。
