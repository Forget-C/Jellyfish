# 文本生成实验室

文本生成实验室是独立于项目、资产与分镜生产流程的调试页面。它用于测试已登记文本模型的接入状态，并观察不同提示词在不同模型下的输出。

## 当前范围

- 仅支持文本模型。
- 用户必须从模型管理中已登记的 `text` 类别模型中选择一个模型。
- 用户可以载入任意已有提示词模板，随后自由编辑提示词内容。
- 历史消息仅供用户查看；每轮模型调用只发送当前输入，不进行上下文自动拼接。
- 不包含评分、自动比较、结果排序、文件输入或跨模态生成。

## 输入编排

实验会话的输入区使用通用 Composer，而不是独立的“本轮配置”侧栏。Composer 顶部提供紧凑选项入口：

- 模型选项：选择本轮实际调用的已登记模型。
- 提示词选项：在自由输入与已有提示词模板之间切换。

未选择模板时，用户使用普通文本输入框。选择模板后，输入区会根据模板的 `variables` 和 `variable_defaults` 生成变量表单；模板正文保持只读，提交前可展开查看渲染后的最终提示词。选择“转为自由输入”只会将当前渲染结果复制到本轮输入框，不会更新提示词模板实体。

以下前端组件可由后续图片和视频实验室复用：

- `ExperimentComposer`：选项、模态输入区和提交操作的通用容器。
- `ExperimentOptionBar`：模型和模板的紧凑选择入口。
- `PromptTemplateForm`：变量表单、模板渲染和最终提示词预览。

## 调用链路

页面通过 `POST /api/v1/studio/text-lab/generate` 发送模型 ID 和当前消息。后端会验证模型类别为 `text`，使用该模型关联供应商的配置构造 Chat 模型，然后执行一轮调用并返回文本结果。

## 持久化会话历史

三个实验室共用 `experiment_sessions` 与 `experiment_messages`。会话按实验室类型隔离，支持新建、切换、重命名、删除、服务端清空、URL 定位和按页加载更早历史。会话历史不会参与模型上下文，也不会写入项目、资产或分镜生产链路。

会话列表显示最近消息摘要、更新时间和运行中任务标识。文本消息持久化为用户与模型气泡；图片、视频任务还会保存模型、参考文件、画幅、任务状态、错误和结果快照。资料库文件不可用时，历史界面保留槽位并显示“文件不可用”。

当前系统尚未实现用户或权限领域，因此会话暂为全局数据，不包含 `owner_id` 或鉴权过滤。模型和 API 已标注后续接入边界：身份体系落地时必须通过独立迁移增加会话归属和复合索引，并在整个会话路由统一注入当前用户；删除、清空和归档也需要同步记录审计信息。

## 职责边界

- 文本生成实验室：验证模型与提示词，进行连续文本调试。
- 模型管理：登记供应商、模型和默认模型。
- 提示词管理：维护可选提示词模板及其版本。
- 项目和分镜工作流：只使用正式生产链路，不依赖实验会话。
