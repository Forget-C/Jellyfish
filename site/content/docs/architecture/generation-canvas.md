# 生成画布文档存储

项目工作台的“画布生成”入口无需章节或场次。一个项目可创建多张命名画布，通过 URL 的 `tab=generation&canvas=<id>` 重开。当前支持四类内容卡、三类模型卡、候选连接、分组、独立布局以及自动保存和恢复保护。文本模型卡提供保存、预检、后台执行和持久文本流；图片模型卡沿用同一入口执行并发布完整有序图片结果。视频卡的用途编译与提交由对应媒体运行入口消费。完整设计决策见 [独立生成画布](adr/0001-independent-generation-canvas.md) 与 [协议边界](adr/0002-generation-canvas-protocol-boundaries.md)。

`generation_canvases` 保存项目归属、当前完整文档、内容 revision 和已登记卡片身份／类型。文档包含画布身份、项目身份、名称、schema_version、卡片、候选连接、每目标端口独立输入顺序和分组。文本卡使用 `content.text`、type_version 1、不可变 ID 和一份 text，允许空字符串。后端轻量 `CardDefinition` 使用具体卡类型，前端显式 `rendererRegistry` 和 `CardShell` 消费同一文档。布局、运行状态与运行结果不进入此文档。

HTTP 边界为 `/api/v1/studio/generation-canvases/{project_id}` 的列表／创建，以及 `/{canvas_id}` 的读取／PUT 保存／删除。读取、写入和删除均限定项目归属，沿用现有项目 API 的访问边界。前端普通请求由 OpenAPI generated client 发出。

保存提交 `request_id`、`expected_revision` 和完整 `document`。事务先锁文档行，再核实持久回执，最后执行 revision CAS。文档更新和 `generation_canvas_save_receipts` 在同一事务提交。同请求重放原回执，不因后续 revision 改变；同身份不同正文返回 HTTP 409 `IDEMPOTENCY_CONFLICT`，过期修订返回 HTTP 409 `REVISION_CONFLICT`。结构、类型和身份错误返回带 `code`、`severity`、`message`、`target`、`blocks` 的文档诊断。画布领域异常使用标准 `{code,message,data,meta}` 封套，`data` 保留类型化诊断；不从 message 反解析字段。普通 HTTP 异常仍保持原有 `data=null`，命令封套基本校验沿用统一 422 处理。

迁移 `d6a0b4c8e957` 建立文档和保存回执表，`473ab089b58f` 增加独立运行、节点、预检、执行回执、占用、成果、当前输出指向及事件表。MySQL 验证使用显式隔离测试库与独立 HTTP 请求事务，覆盖 CAS、同请求竞争及迁移／模型一致性；SQLite 用于功能持久化与真实页面旅程，不能代替 MySQL 竞争证据。

媒体内容卡使用 `content.image`、`content.video`、`content.audio`，只有各自模态的一个输出位置，没有输入。`file_id` 可为空；`uploading=true` 时即使保留旧文件也不发布有效输出。替换与清空引用保留卡片身份。保存通过真实文件记录核实类型、可用性和项目归属，以 `canvas_content` usage（`canvas_id:card_id`）保护引用，删卡／删画布只释放自己的内容引用。

上传使用项目文件接口，以 `generation_upload` usage 独立保留项目文件，成功后不随画布保存失败或放弃编辑回滚。迟到上传不会重建已删除的卡片，文件仍可在项目库选择。图片、完整视频和音频通过既有文件下载接口预览，音频支持 MP3、WAV、OGG、M4A、AAC、FLAC、OPUS。`DELETE /api/v1/studio/files/{file_id}/upload-retention?project_id=...` 显式释放本项目的画布上传保留，有其他真实使用关系时返回 409；清除其他引用后可重试，再按需调用已有文件删除接口，释放本身不删除字节。


模型卡以 `model.text`、`model.image`、`model.video` 区分能力模态，不按供应商复制卡类型。前端复用受控 `ExperimentComposer` 的正文和底部参数布局；文本请求沿用模型管理参数，当前仅接收文本。图片卡配置画幅、分辨率档位和数量；视频仅配置画幅、时长与高级随机种子。`/{canvas_id}/models/{model_id}/capability` 从已接入 DTO 和真实图片／视频能力解析器派生用途、组合、数量及参数范围，未知模型或加载失败保留现场并提示。

候选边以 `source_card/source_port/target_card/target_port` 定义端点用途，`input_order[接收卡][端口]` 持久保存独立边 ID 顺序。新边追加、重复端点拒绝；自连、循环、损坏端点、损坏顺序和分组成员阻止保存并返回定位诊断。卡片移动或分组不改变输入顺序。新建不兼容连线在 UI 拒绝；同模型下新增边在保存时也核实能力。切换模型保留配置和候选，包括切换前尚未单独保存的边；保存不要求操作日志，模型变化时保留结构有效的候选。能力不匹配与无效参数提供运行级诊断，不阻止保留编辑现场；实际使用判断属于提示词编译边界。

分组仅保存名称、独立成员和折叠状态，解散不会删除成员。几何、尺寸、视角通过 `useGraphLayout` 按项目／画布独立保存在浏览器；分组整体移动也只更新几何，不产生内容 PUT。折叠仍保留成员布局和连接顺序，分组没有集合输出。存储失败显示布局保护警告，继续保留本次会话内布局。

模型正文使用编辑器无关的 `PromptDocument.segments`：`text` 保存原文，`reference` 保存稳定来源，`instruction` 保存命令、参数及引用。片段 ID 与指令内引用 ID 在同一正文内唯一，用于诊断定位；不使用正文偏移。输出身份为 `{canvas_id,card_id,port_id,position}`，不按文件 ID 合并来源。输入重排只改变接收代号，已绑定身份不变。空卡和无结果模型不提供可选择的输出；仍被引用的缺失位置保留占位。

共用编辑器支持按分类选择、完整代号确认、中文组合输入、转义及结构化剪贴载荷 `application/x-jellyfish-prompt+json`。输入 `@` 打开候选列表；输入过程中只匹配，在选择、Enter／Tab、明确分隔符或失焦时才绑定完整代号。组合输入期间不转换。同画布粘贴保留来源，未连接时要求手工连接；跨画布载荷保留外来身份并诊断，不自动复制卡片或按同名代号换绑。外部纯文本按目标当前代号确认。添加入口创建可见内容卡并连接，选择已有卡只新增候选边。

`services/generation_canvas/compiler.py` 的公开 `compile_card` 与 `resolve_outputs` 解析实际引用。内容输出来自真实内容卡；运行层通过独立的 `model_outputs` 参数提供已发布的模型当前结果，不把结果写入编辑文档或虚构未来输出。编译仅在结构化引用处展开文本一次，实际媒体按接收端顺序选出使用子集，并提供本地代号、稳定来源与实际媒体位置映射。通用 `[media:N]` 表达用于无模型能力的基础编译；图片预检在结构化引用处写出 `image N`，对应实际提交图片数组的第 N 项。普通文字中的 `图片3` 或 `[media:1]` 均保持原样，展开内容不再次解释。

`GET /{canvas_id}/cards/{card_id}/compile` 返回已保存正文的基础编译预览、实际使用集合、映射及结构化诊断，不提交任务。保存未完成正文与允许运行分开；未使用的不兼容候选是 warning 且不阻塞，实际使用的不兼容输入与无效参数阻止运行。正文和指令内实际引用共同保护断线及删除来源，定位到稳定片段；保存检查最终文档，因此可清理引用后立即断线／删卡并一次保存。视频指令的具体供应商字段映射和运行预检由后续运行实现消费此边界。


文本和图片单卡运行采用 `POST /{canvas_id}/precheck` → `POST /{canvas_id}/runs`。预检绑定保存 revision、实际引用的结果集、编译后的正文和有效模型参数／供应商路由，十分钟内可提交；不占用节点。受理先锁文档并重放原回执，再核实预检及活动占用；运行、固定依据、真实 Task、占用和回执同事务写入。相同身份不同正文为 `IDEMPOTENCY_CONFLICT`，过期依据为 `PREVIEW_STALE`，重叠执行为 `RUN_SCOPE_BUSY`。单卡仅执行自己一次，不自动补跑上游；实际引用的失效成果为 `INPUT_STALE`。

画布使用 `canvas_node` 生成目标及 `text_chat/image_generation × canvas_node × async_polling` 提交矩阵。此 delivery 表示后台 Task 受理协议，画布观察仍使用 SSE。目标指向独立运行节点，任务来源可回跳项目、画布、运行及节点；不创建实验室消息。受理冻结的模型名、有效参数、供应商身份、路由及凭据只保存在 Task 私有执行输入中；公开预检、运行、事件不携带凭据。Worker 使用该配置调用 `llm.astream`，关闭 SDK 自动重试，每次有效增量在短事务中持久累计正文及事件。离开或刷新页面不改变 Task，也不重发模型请求。

`TaskService` 仍是唯一任务写入口。领取、进度和唯一终态裁决后调用窄范围画布事实同步；成功、失败、取消、排队取消、过期和启动中断均在 Task 的原事务更新节点与事件。完整成功才创建 ResultSet；相关当前依据仍匹配时整体更新当前输出指向，不推进编辑 revision。失败及取消保留未完成正文和旧正式成果。正式指向即使依据已变也保留，`basis_current=false` 表示不能作为单卡有效输入；实际内容仍可显示和绑定引用。结果集身份作为实际输入依据的一部分，未使用候选和无关文档编辑不使已有成果失效。

`GET /{canvas_id}/runtime` 返回一致快照；generated `GET /{canvas_id}/events/connection` 提供公共 SSE 地址，传输层逐段解析并恢复订阅。每张画布的一条连接复用 `snapshot`、`node.updated`、`text.delta`、`node.finished` 和 `run.finished`，单次运行结束不关闭连接。事件头行锁使事实、事件游标和提交顺序一致；快照使用同一把锁复制事实及游标。既有 Task 写入遵守 Task → event head 顺序，受理只创建新 Task；流每次追读使用独立短事务，释放所有锁后才 yield。恢复游标之后只重放已提交事件，过期／超前游标发送权威快照，前端按游标去重；没有运行状态轮询。

活动模型卡不可删除，活动画布和项目也不能删除；取消意图尚未形成真实终态时仍保持占用。文档保存校验最终保留的卡片集合，仍允许修改活动卡的后续输入。本地任意内容编辑立即失效预检，并拒绝迟到的旧预检响应；独立布局改变不失效。运行信息和当前模型输出始终在编辑文档之外归并，不影响未保存提示词或保存 revision。

## 取消与独立历史内容

`POST /{canvas_id}/runs/{run_id}/cancel` 与 `POST /{canvas_id}/runs/{run_id}/nodes/{node_id}/cancel` 明确取消范围，并返回真实运行节点。执行中的任务接收意图后仍为 `running`，以 `stage=cancelling` 展示取消中；排队任务沿用 TaskService 立即终结规则。未知或失败回包不释放范围占用，也不推断终态。整轮取消先按任务 ID 排序锁定全部既有 Task，再逐个调用 TaskService，避免持有事件头后等待另一个 Task。

运行快照和节点事件提供安全的固定 `basis`、实际状态、累计正文、成果和正式结果集身份。源卡删除后运行记录仍在，任务中心来源仍保留项目、画布、运行与节点身份。成果非空不表示成功；未完成正文保留在历史中，不替换旧正式输出。

`GET /{canvas_id}/runs/{run_id}/nodes/{node_id}/outputs/{position}/content` 为已终结文本或图片成果准备独立内容卡。前端将它加入当前编辑文档并走既有 CAS 保存队列。卡片的 `origin` 固定画布、运行、节点、输出位置及 `incomplete` 标记，服务端校验来源归属、实际成果与完成状态；保存后正文可独立编辑，来源不可移除或改写。这项显式操作不改变原模型输出指向，不会跟随后续运行更新。图片内容以独立 `canvas_content` 引用固定文件，后续替换不改变历史成果或原模型输出。

## 图片执行和归档

图片模型的预检、受理、取消、历史与结果继续消费统一运行控制器和每画布一条 SSE。实际引用按接收端顺序形成输入子集；重复引用同一输出只提交一次，不同来源即使指向同一文件也保留各自位置。模型能力明确限制的数量及重复文件在预检诊断，不静默截断或按文件去重。图片公开参数为卡片的数量、画幅与分辨率配置。

Task 私有配置固定媒体提交及后续每次查询的模型、供应商路由和认证；受理后的模型管理或画布修改不改变本次请求。已保存图片逐项登记 TaskOutput，只有全部预期图片归档成功才建立完整 ResultSet，并在当前实际依据仍匹配时整体替换当前指向。预览位置仅为本地显示状态，所有输出位置仍供下游选择。旧成功结果保留在该画布历史中；失败、取消或下载／归档失败只列出已持久保存的未完成成果，不建立正式结果集，不清除旧正式输出。

终态媒体以 `canvas_history` usage（`canvas_id:node_id:ordinal`）保护每个已归档文件。用户可预览历史与未完成图片，并显式另存独立内容卡；来源校验同时核实终态、位置、文件和未完成标记。画布生命周期清理由对应删除边界释放自身历史引用，不能以清理通用 Task 历史替代。
