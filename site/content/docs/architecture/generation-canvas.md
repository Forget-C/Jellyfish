# 生成画布文档存储

项目工作台的“画布生成”入口无需章节或场次。一个项目可创建多张命名画布，通过独立页面 `/projects/{project_id}/generation-canvas?canvas=<id>` 重开；旧 `tab=generation&canvas=<id>` 链接保留画布、运行和节点参数后跳转，不实例化项目页及其章节加载。页面使用完整工作台视口、局部暗色主题、左侧类型目录、摘要卡与单一浮动详情；编辑在详情中进行，展开／关闭不改变画布几何。内容撤销／重做与布局整理撤销分别维护，小地图与定位仅改变浏览位置。当前支持四种基础模态内容、独立原文／创作依据、三类模型卡、候选连接、分组、独立布局以及自动保存和恢复保护。文本模型卡提供保存、预检、后台执行和持久文本流；图片模型卡沿用同一入口执行并发布完整有序图片结果。视频模型卡在同一运行入口按固定用途生成一段完整视频，保留文件自带音轨。完整设计决策见 [独立生成画布](adr/0001-independent-generation-canvas.md) 与 [协议边界](adr/0002-generation-canvas-protocol-boundaries.md)。

`generation_canvases` 保存项目归属、当前完整文档、内容 revision 和已登记卡片身份／类型。文档包含画布身份、项目身份、名称、schema_version、卡片、候选连接、每目标端口独立输入顺序和分组。文本卡使用 `content.text`、type_version 1、不可变 ID 和一份 text，允许空字符串。后端轻量 `CardDefinition` 使用具体卡类型，前端显式 `rendererRegistry` 和 `CardShell` 消费同一文档。布局、运行状态与运行结果不进入此文档。

人物／物件描述使用 `content.object`，类别由 `category` 明确区分 `character`、`prop`、`costume`；场所描述使用 `content.place`，类别固定 `place`。本卡保存 `object_id`、`name`、`text` 与 `source_locator`，不选择资产、不创建旧场次实体。对象身份一旦保存不可替换；名称、描述、来源定位及物件类别可以编辑。同画布独立描述对象的名称去除首尾空白后唯一，跨画布可以重名；复制成独立对象须提供新身份和不同名称。未完成名称或身份可以保存，但没有有效对象引用。

描述卡分别声明 `text` 与 `object` 出口。`text` 的 `DescriptionTextPayload` 保留本卡名称、身份、类别、正文和来源定位，模型仅展开所采用的正文。`object` 的 `ObjectReferencePayload` 仅提供身份、名称、类别，属于文本来源上的关系数据，不增加内容模态，也不能接入模型文本端口。它为命名图片参考的名称关联与类别适配的业务端点提供统一引用。改名后重新读取输出即取得新名称，已采用正文仍沿既有绑定保护断线和删除；未采用候选不额外确认。


四类命名图片参考使用 `reference.character/place/prop/costume`，本卡保存独立标题、默认正面的角度及本地独立对象；实际名称采用保存在 `input_bindings`，具体主图保存在强类型 `image_binding`。名称入口仅消费直接对象出口的身份、名称和类别，不读取描述或来源图片；角色允许人物及可选服装／道具，其他类别只接收本类别。绑定本类别名称后由上游拥有身份与名称，取消／替换后才能独立命名。同画布所有独立对象名称唯一，同一身份可通过直接绑定复用。

每卡只选择一个具体文件，项目文件选择以文件身份固定；从图片来源候选选择时同时固定直接输出身份与结果集身份。来源重生成不替换主图；断开或删除已采用名称／图片来源前必须取消、替换或显式另存改绑。候选三类关系沿同一 DAG 校验。更换主图保留名称，页面提示核对角度和图内位置，不分析图片内容。读取和编译重新核实主图文件的可用性与项目归属，文件失效只使图片出口不可用，合法对象引用继续有效。

`NamedImagePayload` 自含具体文件、已选对象的名称／身份／类别／图内位置及角度；对象出口逐对象提供引用，不携带图片。缺少本类别合法名称或主图时没有有效命名图片输出，合法对象仍可独立输出。图片模型明确采用该图片后自动在编译文本和预检映射中建立 `名称 = image N（角度，位置）`，一图多名称只提交一份媒体，不改写用户正文、不要求再次采用映射、不加入穿着／持有／动作指令。描述须从直接文本出口另行采用。

独立导演设计使用 `direction.situation`（角色情境）、`direction.performance`（人物表演）、`direction.performance_rule`（表演规则）。情境保留当前处境、人物关系；表演保留目标、阻碍、潜台词、注意对象、内在调整、身体动作、目光、呼吸、重心、手部、声音、表达、反应顺序、结束状态及避免的表现；规则保留适用说明。每个具体字段用 `DesignField` 记录正文、未填写／不适用／明确没有／待确定／提议／事实、背景／设计／约束用途及来源；本卡 `scope` 单独保留范围、阶段和条件，不推断全场或镜头适用性。专用摘要与详情按情境、触发反应动作结束、规则分别组织，字段控件可共享，编辑约每秒保存。

三类卡仅提供一个 `text` 出口，强类型 `DesignTextPayload` 声明 `adoption=whole_card`，保留完整结构与状态及本卡来源、范围和必要对象。编译时未填写／不适用不产生要求，明确没有表达否定，提议／待确定保留开放性质；背景不强制转换为可见动作，正文不做语义纠错。人物表演不开放目光等单字段出口，多卡逐卡采用。文本模型可分析不完整设计，实际采用情境／表演的图片或视频生成须有明确主体，不要求节拍、镜头或完整设计计划。

`participant` 只接直接对象出口的人物／服装／道具，情境和表演按稳定对象身份至多一个主体；`effect_object` 接明确作用对象（人物、物件、服装、场所），包括表演的注意对象。对象可来自描述卡或独立命名参考，多人图明确选择具体稳定身份；同一对象多个参考不增加人数。关系只传身份、名称与类别，不传正文或主图，模型需要时另行直接采用。人物表演声明可选的 `beat`、`received_event`、`dialogue_basis`、`acceptance_basis` 接收端点，对应来源尚未交付，当前不能虚构绑定或作为必填前提。

表演与规则的 `image_example`／`video_example` 关联直接已发布图片／视频，`examples` 保存固定文件、正向／反例用途、说明及可选递增毫秒区间（仅视频）。示例不进入设计出口或模型输入；源媒体替换不替换已关联文件。示例文件用 `canvas_content` usage 保护，实际对象及示例关系共用候选 DAG 和断线／删源保护；先取消绑定后可在同一保存中删除来源。人物表演的现有明确结束状态可在图片端指定为画面目标，整卡采用仍保留全部表演字段。
“添加另一角度参考”按用户选定的具体对象新建参考卡，并同时建立直接 `object → name` 候选边及带 `object_id` 的名称采用；只复用对象身份，新卡不复制主图，不自动连接或采用到模型。多人图逐对象选择，标题与角度由新卡独立维护，源对象改名沿直接绑定更新，移除或断开仍受既有绑定保护。

视频模型对实际采用的命名图片逐对象编译名称、身份、主图角度、媒体序号、`input_port`、用户填写的 `subject_name` 及用途内 `purpose_position`；同一主图用于不同用途时分别展示映射，媒体保持去重。主体名称映射使用 `@主体组 图片 N`，N 按该组实际图片提交顺序计算；首尾帧及关键帧直接标明用途和关键帧序号，不把候选序号误作组内序号。映射文本进入本次请求及固定历史，不改写用户正文。首尾帧／关键帧采用不自动生成主体输入；主体只按用户明确分组组织，同一身份多角度不自动归组，不按对象名称改换直接来源。角色主图中的服装／道具名称仅表示同图要素，不自动携带上游图片或穿戴动作。主图角度不规定最终生成视角。

HTTP 边界为 `/api/v1/studio/generation-canvases/{project_id}` 的列表／创建，以及 `/{canvas_id}` 的读取／PUT 保存／删除。读取、写入和删除均限定项目归属，沿用现有项目 API 的访问边界。前端普通请求由 OpenAPI generated client 发出。

保存提交 `request_id`、`expected_revision` 和完整 `document`。事务先锁文档行，再核实持久回执，最后执行 revision CAS。文档更新和 `generation_canvas_save_receipts` 在同一事务提交。同请求重放原回执，不因后续 revision 改变；同身份不同正文返回 HTTP 409 `IDEMPOTENCY_CONFLICT`，过期修订返回 HTTP 409 `REVISION_CONFLICT`。结构、类型和身份错误返回带 `code`、`severity`、`message`、`target`、`blocks` 的文档诊断。画布领域异常使用标准 `{code,message,data,meta}` 封套，`data` 保留类型化诊断；不从 message 反解析字段。普通 HTTP 异常仍保持原有 `data=null`，命令封套基本校验沿用统一 422 处理。

迁移 `d6a0b4c8e957` 建立文档和保存回执表，`473ab089b58f` 增加独立运行、节点、预检、执行回执、占用、成果、当前输出指向及事件表；`8a10d04c631e` 增加等待节点私有执行快照和预检范围意图。MySQL 验证使用显式隔离测试库与独立 HTTP 请求事务，覆盖 CAS、同请求竞争及迁移／模型一致性；SQLite 用于功能持久化与真实页面旅程，不能代替 MySQL 竞争证据。

媒体内容卡使用 `content.image`、`content.video`、`content.audio`，只有各自模态的一个输出位置，没有输入。`file_id` 可为空；`uploading=true` 时即使保留旧文件也不发布有效输出。上传中保留稳定出口身份并标记 `available=false`，不携带有效 payload 或 file_id。读取出口和编译时重新核实文件类型、可用性及项目归属；文件后来失效时同样只保留不可用身份，实际采用处返回可定位的 `OUTPUT_MISSING`。替换与清空引用保留卡片身份。保存通过真实文件记录核实类型、可用性和项目归属，以 `canvas_content` usage（`canvas_id:card_id`）保护引用，删卡／删画布只释放自己的内容引用。

上传使用项目文件接口，以 `generation_upload` usage 独立保留项目文件，文件及使用关系在数据库提交后才返回 201，成功后不随画布保存失败或放弃编辑回滚。迟到上传不会重建已删除的卡片，文件仍可在项目库选择。图片、完整视频和音频通过既有文件下载接口预览，音频支持 MP3、WAV、OGG、M4A、AAC、FLAC、OPUS。`DELETE /api/v1/studio/files/{file_id}/upload-retention?project_id=...` 显式释放本项目的画布上传保留，有其他真实使用关系时返回 409；清除其他引用后可重试，再按需调用已有文件删除接口，释放本身不删除字节。


模型卡以 `model.text`、`model.image`、`model.video` 区分能力模态，不按供应商复制卡类型。前端复用受控 `ExperimentComposer` 的正文和底部参数布局；文本请求沿用模型管理参数，当前仅接收文本。图片卡配置画幅、分辨率档位和数量；视频仅配置画幅、时长与高级随机种子。`/{canvas_id}/models/{model_id}/capability` 从已接入 DTO 和真实图片／视频能力解析器派生用途、组合、数量及参数范围，未知模型或加载失败保留现场并提示。

候选边以 `source_card/source_port/target_card/target_port` 定义端点用途，`input_order[接收卡][端口]` 持久保存独立边 ID 顺序。新边追加、重复端点拒绝；自连、循环、损坏端点、损坏顺序和分组成员阻止保存并返回定位诊断。卡片移动或分组不改变输入顺序。新建不兼容连线在 UI 拒绝；同模型下新增边在保存时也核实能力。切换模型保留配置和候选，包括切换前尚未单独保存的边；保存不要求操作日志，模型变化时保留结构有效的候选。能力不匹配与无效参数提供运行级诊断，不阻止保留编辑现场；实际使用判断依据输入绑定，提示词通过绑定身份参与编译。

分组仅保存名称、独立成员和折叠状态，解散不会删除成员。几何、尺寸、视角通过 `useGraphLayout` 按项目／画布独立保存在浏览器；分组整体移动也只更新几何，不产生内容 PUT。折叠仍保留成员布局和连接顺序，分组没有集合输出。存储失败显示布局保护警告，继续保留本次会话内布局。

模型正文使用编辑器无关的 `PromptDocument.segments`：`text` 保存原文，`reference` 保存输入绑定身份 binding_id，`instruction` 保存命令、参数及引用。新文档使用 schema_version 2，实际来源只在模型卡 input_bindings 中持久化；编辑器为显示与剪贴派生来源，保存时不再写入第二份来源。读取 v1 旧来源片段时在解析阶段规范化为 v2 绑定，不原地修改原始幂等请求正文或既有运行快照，来源及用途含义保持不变。片段 ID 与指令内引用 ID 在同一正文内唯一，用于诊断定位；不使用正文偏移。文本与媒体输出身份为 `{canvas_id,card_id,port_id,position}`，对象引用另带具体 `object_id` 选择器；选择对象时以对象身份定位，列表重排不改绑。空选择器不写入旧身份，因此旧文本／媒体引用和依据哈希不漂移。不按文件 ID 合并来源。输入重排只改变接收代号，已绑定身份不变。空卡和无结果模型不提供可选择的输出；仍被引用的缺失位置保留占位。

共用编辑器支持按分类选择、完整代号确认、中文组合输入、转义及结构化剪贴载荷 `application/x-jellyfish-prompt+json`。输入 `@` 打开候选列表；输入过程中只匹配，在选择、Enter／Tab、明确分隔符或失焦时才绑定完整代号。组合输入期间不转换。同画布粘贴保留来源，未连接时要求手工连接；跨画布载荷保留外来身份并诊断，不自动复制卡片或按同名代号换绑。外部纯文本按目标当前代号确认。添加入口创建可见内容卡并连接，选择已有卡只新增候选边。

`services/generation_canvas/compiler.py` 的公开 `compile_card` 与 `resolve_outputs` 解析实际引用。内容输出来自真实内容卡；运行层通过独立的 `model_outputs` 参数提供已核验的媒体出口和已发布的模型当前结果，不把结果写入编辑文档或虚构未来输出。编译仅在结构化引用处展开文本一次，实际媒体按接收端顺序选出使用子集，并提供本地代号、稳定来源与实际媒体位置映射。通用 `[media:N]` 表达用于无模型能力的基础编译；图片预检在结构化引用处写出 `image N`，对应实际提交图片数组的第 N 项。普通文字中的 `图片3` 或 `[media:1]` 均保持原样，展开内容不再次解释。

`content.basis` 保存创作依据的正文、来源定位和可选选取起止位置，无章节绑定或持续输入。通用文本和创作依据可通过明确选择文本文件导入形成自身内容。来源定位不成为隐式读取授权。

单卡输出由小型 `CardOutputHandler` Protocol 处理，只接收本卡、明确采用的直接输入和本卡已发布结果，处理器不持有完整画布或数据库。外层负责查找直接候选；模型编译内层只接收本卡配置、已解析候选与能力。输出使用稳定来源外壳及带 kind 判别的正文／媒体 payload，旧 text/file_id 读取字段是该 payload 的只读投影，历史旧输出可解析为同一形式。运行依据哈希继续以实际文本／文件和身份计算，不把重复的 payload 传输投影算作输入变化。跨层值契约位于 core/contracts，公开 API 和前端生成类型保持一致。

`GET /{canvas_id}/cards/{card_id}/outputs` 返回对应已保存 revision 的本卡输出与直接候选，不增加绑定或发起任务。前端模型候选、已采用来源正文与正式输出消费此响应，并复用已保存 compile 接口刷新后端诊断；仅接收与保存基线相同 revision 的响应，较旧查询不能覆盖较新修订。采用标识依据已保存卡片，本地编辑与已保存来源分别展示。编辑器有变化时约每 1 秒合并保存，持续输入期间也提交；在途请求串行完成后只提交最新文档。无变化不提交，相同失败正文暂停自动重试，修改或手动保存后继续；未知结果重放原请求，冲突保留本地内容。手动保存和运行预检立即冲刷待保存修改，保存失败不继续预检。约 1 秒是合并周期，下游刷新仍需等待保存及输出计算；保存与刷新不采用候选、不发起模型，也不改变历史。

图片模型详情中的文本依据与参考图片分别明确采用、取消及调整采用顺序，全部写入同一 `input_bindings`；提示词引用仍按绑定身份定位。取消采用同时移除正文中对应引用。图片编译按接收端绑定顺序形成实际使用集合与媒体顺序，候选连接排序不覆盖该选择；重复引用同一输出只提交一次，不按文件 ID 合并不同来源。参考数量与重复文件限制来自所选模型能力，页面提示与后端预检一致。展开来源图片或切换生成结果预览只改变显示，不采用成果。

图片当前输出引用保持卡片、端口和位置身份；来源重生成时该位置更新，位置消失则保留选择并明确报缺失，不退回第一项。需要固定某次成果时，在运行历史中明确另存为图片内容卡，固定具体文件并保留运行、节点、位置及完整／未完成来源；它可经新直接候选连接再明确采用。另存、预览和保存均不运行模型、不回写输入；原始运行历史及独立图片卡的文件使用关系继续保护文件删除。

`GET /{canvas_id}/cards/{card_id}/compile` 返回已保存正文的基础编译预览、实际使用集合、映射及结构化诊断，不提交任务。保存未完成正文与允许运行分开；未使用的不兼容候选是 warning 且不阻塞，实际使用的不兼容输入与无效参数阻止运行。正文和指令内实际引用共同保护断线及删除来源，定位到稳定片段；保存检查最终文档，因此可清理引用后立即断线／删卡并一次保存。视频指令同时编译为预检中的标准 `video_media`，由同一次受理直接用于真实供应商请求。


单卡、运行到目标及严格框选采用 `POST /{canvas_id}/precheck` → `POST /{canvas_id}/runs`。预检绑定保存 revision、实际引用的结果集、编译后的正文和有效模型参数／供应商路由，十分钟内可提交；不占用节点。受理先锁文档并重放原回执，再核实预检及活动占用；运行、固定依据、真实 Task、占用和回执同事务写入。相同身份不同正文为 `IDEMPOTENCY_CONFLICT`，过期依据为 `PREVIEW_STALE`，重叠执行为 `RUN_SCOPE_BUSY`。单卡仅执行自己一次，不自动补跑上游；实际引用的失效成果为 `INPUT_STALE`。

画布使用 `canvas_node` 生成目标及 `text_chat/image_generation/video_generation × canvas_node × async_polling` 提交矩阵。此 delivery 表示后台 Task 受理协议，画布观察仍使用 SSE。目标指向独立运行节点，任务来源可回跳项目、画布、运行及节点；不创建实验室消息。受理冻结的模型名、有效参数、供应商身份、路由及凭据保存在服务端节点私有快照和 Task 私有执行输入中；公开预检、运行、事件不携带凭据。Worker 使用该配置调用 `llm.astream`，关闭 SDK 自动重试，每次有效增量在短事务中持久累计正文及事件。离开或刷新页面不改变 Task，也不重发模型请求。

`TaskService` 仍是唯一任务写入口。领取、进度和唯一终态裁决后调用窄范围画布事实同步；成功、失败、取消、排队取消、过期和启动中断均在 Task 的原事务更新节点与事件。完整成功才创建 ResultSet；相关当前依据仍匹配时整体更新当前输出指向，不推进编辑 revision。失败及取消保留未完成正文和旧正式成果。正式指向即使依据已变也保留，`basis_current=false` 表示不能作为单卡有效输入；实际内容仍可显示和绑定引用。结果集身份作为实际输入依据的一部分，未使用候选和无关文档编辑不使已有成果失效。

`GET /{canvas_id}/runtime` 返回一致快照；generated `GET /{canvas_id}/events/connection` 提供公共 SSE 地址，传输层逐段解析并恢复订阅。每张画布的一条连接复用 `snapshot`、`node.updated`、`text.delta`、`node.finished` 和 `run.finished`，单次运行结束不关闭连接。事件头行锁使事实、事件游标和提交顺序一致；快照使用同一把锁复制事实及游标。既有 Task 写入遵守 Task → event head 顺序，受理只创建新 Task；流每次追读使用独立短事务，释放所有锁后才 yield。恢复游标之后只重放已提交事件，过期／超前游标发送权威快照，前端按游标去重；没有运行状态轮询。

活动模型卡不可删除，活动画布和项目也不能删除；取消意图尚未形成真实终态时仍保持占用。文档保存校验最终保留的卡片集合，仍允许修改活动卡的后续输入。本地任意内容编辑立即失效预检，并拒绝迟到的旧预检响应；独立布局改变不失效。运行信息和当前模型输出始终在编辑文档之外归并，不影响未保存提示词或保存 revision。

空间设计使用 `direction.anchor`、`direction.blocking`、`direction.activity`、`direction.environment` 四种专用卡。锚点维护稳定 `anchor_id`、名称、位置、方位、空间关系和尺度，走位维护稳定 `blocking_id`、位置、朝向、主动权、路径和切换原因；已建立身份不可改绑。镜内活动保留持续任务、注意对象、对主戏的作用、路径、延迟依据／毫秒、入出画、结束状态、景深层次与强度；环境活动与刻意留白及理由分开。它们完整发布强类型设计，不提供单字段采用。锚点与调度另外发布 `anchor`／`blocking` 身份出口，仅含身份名称，供直接关系选择。

空间关系 `space`、`participant`、`position_anchor`、`area_anchor`、`effect_object` 按直接候选、类别和数量校验，参与者可为人物、服装、道具，不能为场所；所属空间／参与者／区域各至多一个实际对象。`change_event` 与 `trigger_event` 用途独立，待事件来源接入，不伪造候选。`SpatialDesignRelations` 保留明确用途；模型采用走位或活动不会读到锚点全文、所属场所描述或任何示意媒体，这些输入须各自直接连接并采用。空间工具不要求节拍或镜头，可独立生成；文本可分析未完成设计，视觉生成采用走位或镜内活动时须明确参与者。范围只保存创作者声明，不自动判定适用性。

空间卡复用图片／视频固定关联、项目文件保护与视频区间规则；锚点可以先用文字建立，图片关联后用归一化 `markers` 标记位置，每张关联图片一个点。更换媒体不改变锚点身份，源媒体替换不更新固定关联，素材不随设计输出，也不自动作为首尾帧。四类工具在表演与调度中提供专用摘要及详情，复用一秒自动保存与保存修订输出刷新。

## 运行到目标与固定依赖

预检请求支持 `kind=single|target|selection`，省略时仍为单卡。目标预检返回按实际引用拓扑排序的 `execution_nodes` 和复用结果；目标总执行一次，有效上游只读复用且不占执行范围，依据已变但仍有实际内容的上游进入范围。候选连线未实际使用时不构成依赖。引用位置缺失时始终阻止受理，即使该来源已在执行范围内。

`planner.py` 统一规划、节点提交和终态唤起。受理一次性固定完整图、所有计划节点的已有具体输入、实际使用依赖、模型能力与有效模型／供应商配置，等待节点也不例外。公开 `basis` 不含凭据，服务端私有 `execution_snapshot` 不进入预检、历史 DTO 或事件。等待节点只用本轮必要上游的成功 ResultSet 整体替换相应来源，再校验实际内容、能力和缺失位置，生成具体 Task 输入；不读当前编辑或其他运行的输出，也不经提交门禁重新解析可变模型配置。

必要上游失败或取消使尚未创建 Task 的后继成为 `blocked`；下游自身输入校验失败为 `failed`。独立分支继续，旧正式结果仍可查看但不能作为本轮失败分支的后备来源。确认的任务启动中断会终结本轮等待节点，不自动补交；已有 Task 保持其真实状态。整轮取消终结全部等待节点并请求取消已有 Task。全部节点终结后释放范围占用并结束生命周期，不计算整轮成功等级。

所有已知媒体输入在受理事务以 `canvas_run` usage（`canvas_id:node_id`）持久保护，包含尚无 Task 的等待节点。后续编辑移除内容卡或引用不会改写该保护及固定输入。受理和终态调度均先取得 event head 再保护具体输入文件；受理只创建新 Task，不取得既有 Task 锁。

## 严格框选与并行观察

`kind=selection` 使用 `card_ids` 固定选中范围；内容卡和分组不生成 Task，选中模型按实际依赖拓扑顺序各执行一次，无消费者的选中模型也执行。选中模型之间使用本轮新结果；范围外只能复用有效正式成果。A→B→C 中只选 A、C 时，即使 B 有旧的有效成果，仍以 `SELECTION_INCOMPLETE` 定位 B；外部失效成果以 `INPUT_STALE` 定位其来源，不扩大范围或自动排队。预检凭据持久保留选中模型集合，受理重新核实同一集合。

文档行锁使同画布受理原子核实执行占用；等待节点也占用。执行范围无重叠即可并行，仅共同读取同一结果不构成冲突；`RUN_SCOPE_BUSY` 的 target 包含冲突 card_id、run_id 和 node_id。取消意图未达到真实终态前不释放占用，终态后由用户明确发起新的运行。

正式发布的 `node.finished` 事件携带权威 `current_outputs`，前端按画布游标归并完整有效性视图，范围外下游只标记依据改变。所有运行共用同一 SSE，一个运行终结不关闭其他运行观察；快照和重放沿用同一游标，不追加重复正文。画布路由的数据库依赖使用 function scope，在发送成功响应前提交事务，保证保存后预检、凭据后受理和回执后观察可由下一 HTTP 连接立即读取。

## 取消与独立历史内容

`POST /{canvas_id}/runs/{run_id}/cancel` 与 `POST /{canvas_id}/runs/{run_id}/nodes/{node_id}/cancel` 明确取消范围，并返回真实运行节点。执行中的任务接收意图后仍为 `running`，以 `stage=cancelling` 展示取消中；排队任务沿用 TaskService 立即终结规则。未知或失败回包不释放范围占用，也不推断终态。取消命令先按已冻结范围的拓扑顺序锁定整轮既有 Task，再逐个调用 TaskService，避免持有事件头后等待另一个 Task。每锁定父节点后重新读取后继 Task 身份，确保等待节点在并发调度中刚获得 Task 时也不会漏取消；单节点取消仅向指定 Task 发取消请求。

运行快照和节点事件提供安全的固定 `basis`、实际状态、累计正文、成果和正式结果集身份。源卡删除后运行记录仍在，任务中心来源仍保留项目、画布、运行与节点身份。成果非空不表示成功；未完成正文保留在历史中，不替换旧正式输出。

`GET /{canvas_id}/runs/{run_id}/nodes/{node_id}/outputs/{position}/content` 为已终结文本、图片或视频成果准备独立内容卡。前端将它加入当前编辑文档并走既有 CAS 保存队列。卡片的 `origin` 固定画布、运行、节点、输出位置及 `incomplete` 标记，服务端校验来源归属、实际成果与完成状态；保存后正文可独立编辑，来源不可移除或改写。这项显式操作不改变原模型输出指向，不会跟随后续运行更新。图片内容以独立 `canvas_content` 引用固定文件，后续替换不改变历史成果或原模型输出。

## 图片执行和归档

图片模型的预检、受理、取消、历史与结果继续消费统一运行控制器和每画布一条 SSE。实际引用按接收端顺序形成输入子集；重复引用同一输出只提交一次，不同来源即使指向同一文件也保留各自位置。模型能力明确限制的数量及重复文件在预检诊断，不静默截断或按文件去重。图片公开参数为卡片的数量、画幅与分辨率配置。

Task 私有配置固定媒体提交及后续每次查询的模型、供应商路由和认证；受理后的模型管理或画布修改不改变本次请求。已保存图片逐项登记 TaskOutput，只有全部预期图片归档成功才建立完整 ResultSet，并在当前实际依据仍匹配时整体替换当前指向。预览位置仅为本地显示状态，所有输出位置仍供下游选择。旧成功结果保留在该画布历史中；失败、取消或下载／归档失败只列出已持久保存的未完成成果，不建立正式结果集，不清除旧正式输出。

终态媒体以 `canvas_history` usage（`canvas_id:node_id:ordinal`）保护每个已归档文件。用户可预览历史与未完成图片，并显式另存独立内容卡；来源校验同时核实终态、位置、文件和未完成标记。画布生命周期清理由对应删除边界释放自身历史引用，不能以清理通用 Task 历史替代。

删除画布在同一数据库事务中清理编辑文档、运行记录和本画布的 `canvas_content`、`canvas_run`、`canvas_history` 使用关系；不请求删除媒体字节。其他画布的独立内容、其他项目的资产使用和项目上传保留不会被此操作释放。项目删除继续由活动运行保护及现有外键级联清理本项目关系。上传保留仍须显式清理；该新增清理入口在数据库提交后返回成功，并在文件服务原有锁与引用校验边界确认无其他使用者后单独登记文件删除。页面对删除或释放保留的失败展示真实拒绝原因；网络结果未知时提供重新读取核实入口，不凭局部响应宣告全部引用已释放。


## 视频用途与单视频执行

共用 Composer 的四条本地系统指令为 `/首帧参考`、`/尾帧参考`、`/关键帧参考` 和 `/主体参考 "名称"`。选择和手写均保存为相同的 `instruction` 片段及独立配置块。手写内容在 Enter／Tab 或失焦时按固定语法形成指令，连续引用保留顺序，遇到正文结束；不调用 LLM。正文可与配置同行。缺引用、缺主体名、重复首尾帧、错误类型、超量及不支持用途／组合均可保存，预检按片段及引用路径定位并阻止执行。

视频详情按选定模型的真实用途提供独立采用、取消、排序及主体分组；普通候选连接不采用或执行。实际用途、顺序及可选 `subject_name` 均以 `input_bindings` 为权威，正文和指令只通过绑定身份参与；旧主体指令读取时规范化名称到绑定；旧v2曾跨主体名称共用同一binding时，按原明确指令拆分用途，保留多组及正文隐式代指，不任选一组。独立主体采用必须明确填写分组，缺失／清空返回绑定定位诊断。首尾帧各至多一项，关键帧按绑定顺序进入 `VideoMediaInput.frames`。主体绑定按规范化名称合并到 `subjects`，同一组内重复来源只一次；不检查素材人物冲突。同一素材仅归属一个显式组时，正文对应引用替换为 `@主体名`，保留周围正文。无显式组或归属多组时，直接引用使用按实际媒体子集编号的隐式 `@mediaN` 组，不任选一个命名组。指令引用本身即为实际输入，无需正文重复。展开文本中的命令、引用及普通 `[media:1]` 字样从不再次解析。

实际 Adapter 决定可用用途：OpenAI 当前只传递单张首帧；Vidu 接入命名图片／视频主体及帧用途；火山接入首尾帧及关键帧；可灵按已接入模型限定帧用途。当前 Adapter 均不支持命名主体与帧参考组合，能力覆盖配置不能扩大真实字段支持。公开参数仅模型、画幅、时长及高级随机种子，不提供音频参考、时间码、通用视频编辑或续写。

每次视频任务仅收取一个输出，直接保存下载的完整字节。提交与每次轮询消费 Task 的固定有效路由和认证；运行中修改模型或供应商配置不改投既有任务。统一结果集、历史、终态事件及 `canvas_history` 文件保护与图片共用。成功后依据不符的成果仅入历史；失败／取消保留已存成果并标记未完成。显式另存视频内容卡固定来源和文件引用，不改写原运行或当前结果。原生视频预览保留完整文件及音轨；历史记录同时展示受理时固定的 `video_media` 用途、分组和顺序。帧用途仅接受图片，视频转帧等隐式转换在预检返回绑定定位诊断。


## 摄影范围与图片画面目标

`direction.photography` 是单一摄影内容所有者，详情的景别与构图、机位与视角、运镜、光影与色彩、焦点与成像五个入口编辑同一份 `PhotographyFields`。字段保留状态、背景／设计／约束用途和来源；范围、条件、制作阶段及对象关系归本卡。新建和“复制为独立摄影方案”明确产生独立卡片，不按所属镜头合并；复制只复制当前内容及直接输入关系，不建立两个方案之间的回连。可选 `shot`、`acceptance_basis` 接收端点等待对应来源交付，独立设计无需镜头。

摄影只有一个 `text` 出口，`PhotographyTextPayload.adoption_scopes` 明确声明 `whole`、`region:<固定区域>`、`field:<固定字段>`、`phase:<稳定阶段ID>`。模型绑定的 `photography_scope` 只接受这些声明，不解释任意路径。未指定范围表示完整设计；显式空选择不能回退完整设计。静态字段清空后身份仍合法；删除阶段使已有选择报 `PHOTOGRAPHY_SCOPE_MISSING`，不回退旧值。整卡随新增内容更新，局部范围不扩展到其他区域。编译在形成 `used` 之前投影文本与完整 payload；运镜只携带对应关注对象及共享作用对象，焦点关系仅跟随焦点区域。未选区域变化不改变实际提交或使既有成果过期。

摄影的作用、关注和焦点对象只采用直接对象出口的身份／名称，正反例只关联直接图片或视频，摄影示例可定位固定字段并保留视频区间。示例与对象正文不进入摄影设计输出；模型使用媒体仍须直接连入并采用。关系、示例、删除保护和候选无环校验沿用统一保存边界。

图片卡独立保存 `frame_targets[{binding_id,state_id}]`，仅定位已采用导演输出声明的 `frame_states`，不增加或拆分采用记录。摄影起始／结束画面和明确创建的运镜阶段提供目标；人物表演与镜内活动只从现有 `exit_state` 提供可选目标，不解析动作自由描述或新增通用阶段。明确多状态运镜用于单张静帧时必须指定目标，视频仍可使用完整过程。目标被清空、删除或超出当前采用范围时须替换或取消；完整设计文字与字段仍保留。

结构化景别可声明明确目标和状态，只有同目标、同状态且必须同时满足的事实设计／约束单值冲突阻止相关生成。图片目标属于另一明确状态时不将其他状态当成本张图的硬要求；提议、待确定、背景和普通文字不升级为冲突，不自动筛选采用范围。模型能力预检仍独立执行；可视化预设与独立风格尚未在摄影编辑中实现。

同卡保存修订刷新期间，前端保留上一已保存候选、输出和正在编辑的控件，标明原修订；不因短暂加载卸载目标选择器。切换卡片不保留另一卡数据，旧响应不能覆盖新范围。
