# 图片生成实验室

图片生成实验室独立于项目、资产和分镜生产流程，用于验证已登记图片模型、图片提示词模板及参考图片对生成结果的影响。

页面仅展示图片相关提示词模板，包括首帧、尾帧、关键帧、角色、演员、道具、场景和服装图片模板；文本及音视频提示词不会进入该选择器。

## 输入与媒体语义

参考图统一使用资料库 `FileItem` 的 `file_id`。用户可以上传图片，也可以从全局资料库选择已有图片；前端按选择顺序提交 `references`，每项包含 `file_id`、`media_kind: image` 和组内 `ordinal`。

API 和任务快照只保存资料库文件标识，不保存供应商侧媒体表示。提交时，统一生成门禁校验每个 `file_id` 存在且是图片；Worker 在执行期通过文件解析器取得供应商需要的媒体表示。因此，会话历史和任务恢复始终以稳定的资料库文件标识为准。

## 统一任务提交

图片实验室通过固定入口提交异步任务：

`POST /api/v1/studio/generation-tasks/labs/image/sessions/{session_id}/tasks`

路径绑定图片模态和 `image_generation` operation，请求体提供已登记的 `model_id`、最终 `execution_prompt`、可选参考图 `media` 及图片 operation 参数。服务端校验会话属于图片实验室，且不允许由请求体切换 operation 或媒体类型。

用户消息、携带 `task_id` 的任务消息和统一 `image_generation` 任务在同一数据库事务内创建；仅提交成功后才投递 Worker。响应返回 `task_id` 以及这两条权威消息，前端直接接管它们，不创建额外的本地乐观消息。

任务快照冻结模型修订、提示词、媒体 `file_id` 和目标会话，不保存凭据值。任务的目标类型是 `experiment_session`，不会读取或修改资产、项目或镜头状态。

## 结果与历史

前端通过通用接口 `GET /api/v1/film/tasks/{task_id}/result` 轮询运行状态和结果。Worker 将成功、失败或取消状态同步写回同一条任务消息；成功图片由统一产物流程归档到资料库，结果快照用于任务气泡和刷新后的历史恢复。

实验室历史保留提示词和参考图的 `file_id`。恢复历史输入时，页面会重新检查这些文件是否仍可用；不可用的文件不会被重新提交。
