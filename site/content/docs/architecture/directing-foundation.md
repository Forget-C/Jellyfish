2026-09-14：场次工作台已有契约、持久化、场次 API、设计/试拍/剪辑页面和单元任务接入。章节与项目概览的主入口进入场次工作区；旧分镜页面与提交路由已移除，项目资产关联使用 `/api/v1/studio/project-assets`。隔离业务测试、MySQL 迁移与真实模型端到端操作验收通过，M1 已达成。样片仍有动作偏差，验收不代表成片质量通过；实际覆盖、保留区间与计划要求分别记录。进度见[实施任务](/docs/plans/directing-workbench-implementation-tasks/)。

场次版本 AI 设计在任务完成前核对新增事实／提议的本次模型任务来源，与应用预览共用校验规则；原样保留的人工内容不要求改写来源。生成边界对仅引用本次冻结章节来源的新增内容保留章节依据，并由服务端补记真实任务来源；不修改原有内容，不补记错误章节版本、人工声明或其他任务身份，也不改写历史结果。其余来源错误与结构错误共用一次有界纠错，纠错仍失败时任务不能标记成功。历史不合格结果在应用时仍被拒绝，保留记录并允许重新发起设计。

单元画布提供当前镜头的“AI设计”准备与只读方案预览。用户明确目标视频模型后，一次单元组织任务冻结未保存内容、适用六岗候选、共享约束、项目风格与真实模型能力；任务结果只包含组织字段，不包含真实参考绑定、指令确认或媒体采用。分段可形成多个独立单元，每个单元遵守现有单覆盖执行限制。执行范围与进入／结束状态以适用设计片段校验，越界整份拒绝；未知时长与未绑定参考保持缺项。任务提交按请求身份幂等，未知响应核实原请求；任务中心回到固定版本、镜头与非模态只读方案记录；准备、比较与确认应用继续使用独立操作弹窗。首次方案或明确所选单元的局部修改，由用户一次明确确认后填入当前编辑，继续沿用自动或手动保存；完成任务或关闭预览不改写当前单元。预览、确认和首次保存均核对目标镜头相关输入、真实模型与供应商身份及能力，保存另执行原有 revision CAS；独立其他镜头以当前编辑内容保留。单元 `organization` 保存可局部人工修改的进入／结束状态与待准备参考要求，并记录人工建立或原 AI 组织任务来源；首次填写人工要求使用明确的 human 来源，AI 来源仍核验真实成功任务，不能以同名来源替代；进入／结束状态进入指令依据约束；待准备参考只进入缺项诊断，不进入视频执行约束。AI 新增或改写参考需求仅允许主体图片／视频与首帧／尾帧／关键帧等有限待准备类别（人物身份参考属于主体参考），自由创作文字使整份结果拒绝；类别不代表模型已支持或真实参考已绑定。组织理由与设计时缺项供追溯，不代表当前准备度、真实参考绑定或指令检查通过。 既有单元以 `source_unit_id` 明确目标，结果以 `operation` 区分保留、修改与新建；局部修改维持单元及仍有效覆盖项身份，保留项维持原模型与配置。未返回的组织状态与参考要求沿用当前值，未授权的指令、真实来源、文件参考、参数与依赖原样保留。执行依据变化由既有指令依据状态表达，原确认及检查记录不被改写；当前设计或实际覆盖引用的覆盖项不能被静默替换。

单元组织的整镜范围由 `action_scope` 明确包含当前镜头的完整非空 `visible_result` 表达；此时已明确适用于该镜头的设计项可使用不同措辞，不要求在范围中逐字重复节拍、事件等全文。局部范围仍要求所选主要动作完整包含在摘录中，不能仅凭同镜关系夹带完整动作；未选项不会自动加入执行。自由文本仍限于适用设计摘录，非法身份、其他镜头引用和出现项限制继续整份拒绝。结构与范围错误共用最多一次模型纠错（总计两次调用），不增加判定任务；局部选择越界的反馈定位到单元、覆盖项及设计字段。结构解析完成后、业务校验前固定所有来源合法的局部动作范围；存在局部范围时，纠错还须保持首次结果的单元及覆盖项身份集合。引用、参数或范围错误均不能通过扩大局部范围、增删或换身份绕过保护。纠错后仍非法则任务失败，不产生可应用方案。

同一单元方案可整体重组：目标镜头中未返回的纯单镜单元明确移除，拆分与合并产物使用新身份，独立其他镜头与跨镜头单元原样保留。预览展示保留、修改、新增、移除及历史影响；设计 occurrence 和当前方案的实际覆盖标注阻塞单元或覆盖项身份移除，返回稳定 subject／Take 身份和当前引用路径。界面可进入原设计对象的适用范围编辑区，或准确选择未采用的原 Take 并定位实际覆盖区；不自动迁移或删除引用。处理后仍重新核对相关输入，过期结果只读保留；暂时读取失败可重新核对原预览，无须重复生成。

`unit_design_task_id` 可选记录最近一次明确应用的单元设计任务，供首次保存重验完整固定输入，纯移除同样适用；它不是草稿、确认或任务状态，保存后的普通人工编辑继续沿既有规则处理。历史检查、任务、Take、媒体、采用时间线和固定计划依赖不随当前单元移除改绑或清除，也不因此阻止移除；运行任务继续使用冻结输入，完成后仍登记原任务候选且不自动采用。原单元移除后拒绝按原依据授权新重试，已经受理的原请求仍按原身份幂等核实，历史读取保持可达。

明确来源的新增补拍使用新单元和覆盖项身份，原单元按保留项继续使用原模型；新单元使用本次目标模型。新单元继承来源仍有效的正文与真实来源、参数、参考输入和固定历史依赖，指令依据确认与检查任务凭证重置。来源已有预计时长可继承；目标上限尚未核实时明确保留能力缺项。参数或参考能力冲突保留原输入并在预览列明，实际落幅与参考尚未绑定的依赖继续待准备；组织状态建议不构成真实落幅。仅适用于来源出现项的动作、事件或活动不能复制选择到新身份，服务端整体拒绝且不改写导演适用范围。后续编译、检查和视频提交使用新增单元的局部执行范围，生成成功仅登记候选 Take。

新建单元不得复用同一场次版本中已保存的历史单元身份。`directing_scene_unit_identities` 与保存事务一起登记身份，删除单元不释放身份；迁移从当前单元、任务固定输入、指令依据及视频执行记录回填，保留旧历史保护。AI 提交时冻结不可复用身份，预览、确认与首次保存时重新核对；当前仍存在的单元可按原身份保留或局部修改。同一次创建在首次保存前形成的指令记录不误判为旧身份，但保存后移除的单元不能重放原方案复活。尚未应用的 AI 建议结果不占用正式单元身份，历史记录继续按原版本和单元读取。升级此功能前，在 backend 目录执行 `uv run alembic upgrade head`。

## 身份与存储

可编辑场次版本的独立角色情境、节拍表演、镜内活动、摄影工作单及不可改事实／待确定问题条目可保存局部 `id`。新建行由工作台分配身份；保存拒绝增加无 ID 行的数量以及重复或无效 ID。编辑、重排和改绑后，画布与工作单优先按 ID 定位；历史无 ID 快照仍可读取，不自动补写身份。保存基线中重复的无 ID 行不会因编辑后剩余匹配变少而获得可靠身份；列表变化后旧卡暂不可编辑，可从当前待同步对象入口明确选择当前行继续编辑。

同一版本的 `design.applicability` 按原工作单对象 ID 与字段记录明确适用性：普通设计可指定镜头或单元出现项，约束可指定全场、镜头或出现项并声明视频、声音或后期阶段及可选条件。原字段中的人物、事件等直接引用仍保留在工作单内；适用性不从共用对象或镜头数量推断。保存时核对来源行、字段、镜头及单元出现项，拒绝重复、矛盾或悬空范围；解除适用性不删除设计内容。

### 可编辑场次版本的已交付切片（2026-10-13）

新工作台字段来源通过项目与场次限定的来源解析器读取；章节摘录和旧历史修订不回退到当前内容。历史修订详情只读，读取失败可原位重试，打开和关闭不切换当前编辑版本。场次视频素材另有明确打开所属版本入口，先核对原版本、单元及执行记录，再执行现有保存／放弃／取消保护；精确回跳保留完整单元，不依赖第一个覆盖项；读取或保存失败留在当前版本。

全场关系总览复用当前场次版本的对象身份及明确导航入口，区分同一素材与多次采用的独立片段。共享设计与参考可就地只读查看；整场设计任务展示固定原文、要求、当时设计与只读建议结果；单元任务与检查按需读取固定输入和真实状态，读取失败原位重试，不发起、应用或确认任务。素材读取失败不阻断已知单元与片段导航；返回当前工作保留未保存输入。

四画布共享右侧场次关系树，提供镜头、单元、指令、同场次源素材与时间线片段导航，以及版本原文、共享设计、参与对象、场所和单元参考的就地只读详情；箭头仅展开，名称按当前版本的明确对象身份定位，同时聚焦相应画布节点，不触发保存或生成。同页切换画布时保留当前版本的素材选择、未应用片段表单、视口及节点滚动；已处理定位请求不重复执行，新明确目标优先。恢复的片段目标已变化或删除时，提示重选并禁止应用。源素材按 Take 身份定位，采用按独立片段身份定位；切素材清除旧片段编辑目标，导航不播放、不采用，片段定位保留整场时间线。关系树的素材、片段与指令摘要消费版本接口的共享 graph，不独立读取素材列表或重算正式业务关系；外部证据失败保留已核实身份并沿共同图刷新原位重试。单元和指令画布按场次版本与镜头记忆明确单元选择；无记忆且仅一个单元时定位唯一对象，多个单元要求明确选择。失效目标保留不可用提示，不按剩余对象替换。修改覆盖所属镜头时携带明确单元与新镜头身份，优先保留正在修改的对象；画布切换不保存、生成或丢弃其未保存正文。单元主操作“进入指令画布”只导航到明确选中的同一单元，保留当前草稿且不提交任务；准备未齐仍可查看。单元与指令画布共用准备校验；指令顶部缺项入口回到原单元定位具体字段，能力未核实时仍可打开 AI 设计查看，工作区中的生成操作禁用；原请求核实仍使用已授权的固定输入。指令建议的读取未知、待核实或运行状态按当前版本和单元进入顶部主操作，非空人工正文也保留原任务入口；状态解除后恢复检查流程。最新成功建议尚未查看时，非空人工正文也先提供查看入口；本页会话查看状态与业务应用状态分开，明确查看不改写正文。无正文时指令顶部入口读取建议区真实任务状态，已有成功建议优先查看并定位，查看不应用或重复提交。指令画布顶部主操作复用检查区核实结果，区分依据核对、检查提交／原请求核实、运行任务、结果查看及视频生成。检查已确认且没有待核实／运行中的检查时，顶部入口复用视频区状态：未保存时明确保存并生成，已保存时生成当前单元视频，运行中查看当前单元任务，视频记录读取失败时原位重试；重试读取不自动生成。当前单元存在待核实或未终态检查时，不以旧确认结果开放视频生成。 视频提交未知时顶部核实入口重放当前单元的原授权；A 保存并提交未知不遮挡 B 的填写、定位及查看。版本保存核实前，依赖修订号的新检查与生成仍受限制，检查原请求核实保持可达。

指令画布顶部“AI 设计”打开独立操作弹窗，保留当前单元、整份或选段范围和可选编写要求；只有“生成指令”提交固定输入。建议先展示生成前正文与建议正文，明确应用后替换当前单元指令并返回画布，应用可撤销，后续仍可人工修改。原准备门槛、局部范围、输入变化拒绝覆盖、取消及原请求恢复沿用既有流程。离开弹窗后的任务完成仅通知原单元并提供返回入口，不自动重开、应用或切换画布。

整份另存接口在章节锁内重新检查关联设计、指令、检查和视频任务的明确终态，复制点击时内容且不额外保存原版本。独立复制来源账本保留创建请求身份及内容，检查依据仅可沿明确复制链引用，实际执行版本不改写。前端另存期间锁定工作台，已有保存先核实，未知创建结果刷新后重放原请求。设计建议原提交请求同样先持久化，提交未知时阻止另存；成功建议不要求先应用。另存账本另固定单素材审查、接缝与整场审片记录身份；读取和章节交付可引用适用的原记录，保留原版本与原时间，并按副本内容重新核对适用性，不吸收原版本后来新增的审查。连续另存保留这批固定身份，副本新判断独立记录。导出任务集成仍未接通，完整关联任务门禁须随导出接入继续验证。

新增 `directing_scene_versions` 保存用户明确创建的场次方案；`id` 是方案身份，`revision` 只作 CAS 保存比较，不是可选择的保存历史。当前内容包含明确选定的原文依据、允许空镜头的强类型六岗设计、可编辑生产单元与输出画幅。人工镜头可以暂未分配节拍，但已填写引用必须存在；固定执行契约仍保留完整设计约束。只接受当前章节真实摘录或该方案已经核实的依据；`source_bases` 保存这些来源证据以支持撤销与旧字段引用，不构成逐次保存历史。原字段来源不随依据选择被重绑。保存与创建经过 `DirectingStore`，校验已填身份、局部关联、项目资产及来源文件，文件引用与正文在同一事务内更新。

单元覆盖出现项以稳定 `id` 记录本次所选节拍、事件、镜内活动、表演行动与可见连续性变化；镜头设计引用只提供候选，不在建单元时自动选入。新选择以当前版本设计行 ID 和镜头或出现项适用范围校验，允许同镜头的不同单元拍摄不同执行内容；无明确范围的镜内活动与连续性变化不能选择。`action_scope` 是本单元另行填写的动作范围，保存时可暂空，发起指令前必须补齐。

单元指令依据读数按本次选择和字段适用范围投影出执行项、适用约束与实际消费的解释背景，逐项保留原字段、来源、阶段、条件和纳入原因。全场规则进入各单元，镜头与出现项规则只进入对应单元；声音与后期阶段保留原阶段而不作为视频模型要求。人物情境按镜头明确参与对象纳入；范围为 `null` 且影响情境或已选行动时，依据标明待核对，指令检查和视频预检拒绝通过；已选节拍或事件缺少可拍内容同样阻断检查。新依据确认与检查比较实际消费的投影，局部内容变化只使受影响单元失效；历史无投影记录继续按原冻结输入比较。来源工作单在历史详情中单独展示，可能包含本单元未消费的设计；指令生成和检查模型只接收投影，不接收整张来源工作单。

新指令检查除六岗逐出现项结论外，按固定投影原顺序记录每项非空视频执行要求与约束的去向。执行项必须引用最终正文中实际存在的片段；身份、空间、构图和连续性约束可引用单元实际绑定且用途匹配的参考。遗漏、虚构引用或未解决去向阻止确认检查及视频提交；解释背景无需逐字复述，声音和后期约束不列入视频去向。自然语言冲突和背景中的误置命令由检查指出，用户修改正文或设计后重新检查；检查结果不能保证生成模型最终遵从。旧检查任务沿原固定结果读取，不追溯要求新增去向。

视频预检和提交均重读已保存修订，复核当前单元的依据、正文、实际参考与已确认检查。失败或取消的视频任务重试原冻结准备输入与参考，不重新运行当前版本的单元投影算法；原参考及模型仍须可用，当前编辑不能替换原执行内容。生成成功仍只登记候选 Take，实际覆盖与采用在后续审片中另行决定。

关联原任务，不新增生产单元、不保存当前编辑。原请求核实幂等，同单元活动任务阻止新重试；历史场次只允许核实已受理的重试，不能新建。界面沿原执行身份持久化授权，响应未知只核实同一请求；后续候选按当前输入比较显示旧依据。候选媒体读取与播放已接通：服务端按项目、场次版本、原单元和执行记录核对候选归属，再返回播放器地址与实测时长；跨单元借用拒绝。界面明确查看才加载原候选，加载／解码失败保留身份并可重试，播放不改变审片、覆盖或采用状态。

当前 AI 设计建议通过场次版本下的 `design-suggestions` 接口冻结明确原文、设计、模型与人工要求，仍由统一 `directing_design` 任务执行。任务快照记录所属场次版本及原请求，相同请求核实不会重复提交；同版本运行任务阻止另一提取请求。读取建议不保存、不建立独立设计草稿；应用前用当前编辑内容重新核对整场设计及来源，内容变化或来源无效时拒绝整次结果。成功应用进入同一内容撤销与保存流程。新增版本建议不能经旧设计采用端点写入独立草稿。整场提取不受当前镜头选中影响。限定范围修订在提交前选择已有完整内容字段，冻结字段路径与输入；对象重排使原选择失效时须重新选择，不按旧下标改写另一对象。任务执行和应用前均校验范围，任何范围外改动整次拒绝，不允许修改身份、引用或结构。来源文件在任务执行期间受活动输入保护，完成后应用仍重新核验文件有效性。应用前重新核对当前单元的镜头引用，包括建议生成后新增的单元；候选删除其引用镜头时整次拒绝并返回关联身份。界面上的引用处理与位置导航仍在完善。

工作台提供批量拍摄入口，明确选择单元后逐项预检，显示通过／受阻数量和定位入口，再提交当前仍匹配的通过项。编辑变化后复用服务端检查比较核对实际相关输入，无关镜头变更不使预检永久失效；核对中或读取失败时暂停该项提交。提交复用单元请求恢复控制器，预检不自动保存或创建任务。批量面板逐项显示未知提交及核实入口，待核实项不参与重复预检或新提交，核实沿用原请求身份。批量面板打开时从服务端读取当前版本各单元执行，并按任务身份合并已知记录，展示实时状态、候选数及逐项取消；读取失败逐项显示重读入口，取消后仍重读服务端终态。

单元视频提交可选携带 expected_preparation，服务端重新预检并比较相关输入及检查身份，变化时拒绝提交；修订号仍按当前保存修订单独校验。

视频执行读取包含 cancel_requested，取消请求不改变 status 的含义。业务页和后台通知在请求取消但未终结时显示取消处理中，继续轮询真实终态。

原依据视频重试失败反馈保留原执行身份。返回入口核实原记录后定位所属单元，展开原固定输入并聚焦记录；读取失败留在当前页面，跨单元返回不保存或覆盖编辑。原参考登记为待删除或已删除时，错误提示包含原绑定及文件身份，禁止改用当前替代输入。重试还通过 S3 HEAD 核实原参考存储对象；对象缺失、为空或连接未能核实时不创建任务，恢复后可重新授权重试。

场次版本提供 take-library 只读接口，汇集同场次旧生产计划 Take 和新版本候选，保留各自原计划／版本与任务身份、固定生产输入及文件登记信息，不复制执行。

场次版本内容包含 take_judgments，按素材种类及 Take 身份保存独立人工判断；保存通过 DirectingStore 核对素材场次归属、文件身份、当前单元动作引用及真实媒体区间，不修改共享 Take 注释。指令输入投影不包含素材判断或时间线。已审查素材判断变更随保存事务新增 directing_scene_take_reviews 只读记录，固定当时原文、设计、单元与该素材判断并独立保护文件；普通依据变化、同请求重放不生成新记录。编辑画布查看固定依据并对比当前未保存内容，变化时提示重新核对，读取失败不显示为通过。结论不变时可对已保存修订明确复核，按版本、保存修订与素材身份幂等返回固定记录，不更新当前方案修订；未知响应可核实原请求，后续未保存编辑不会被回写或视为已复核。实际覆盖由用户明确选择当前单元动作并记录观察和实测区间；编辑画布支持记录、修改、删除及统一撤销，文件来源随区间保持一致，保存拒绝失效动作、错误来源和越界时间码。编辑画布通过同场次素材库浏览旧生产计划与新场次版本素材，明确选择后查看固定生产来源和手动预览；审查结论与可用区间沿当前版本统一保存、撤销。无效可用时间码保留输入并在对应区间显示错误，不静默裁切；服务器拒绝无效区间，用户修正后重新保存。素材列表提供判断问题定位按钮，明确选回原素材并聚焦区间或覆盖编辑区，避免切换画布后丢失错误对象。预览不自动播放或采用，读取失败保留素材身份及判断，允许重试。编辑画布复用实际单元输入投影比较新素材的生成依据，变化时标为旧依据候选；旧生产计划或当前无原单元时要求人工核对，读取失败不显示一致。生成依据与人工审片状态分别显示，均不自动采用。

剪辑 graph 的独立素材视图包含全部同场候选和两类 Take，当前整场视图只展示实际采用关联。固定生产来源与当前版本人工判断分别投影；实际覆盖节点来自已保存观察，保留复合素材身份、真实区间和当前单元／覆盖项，不代表计划全部完成。当前相关素材复核保留最新及仍适用的原记录，批量有界读取固定比较依据；完整历史留在原入口。图证据、原素材库与当前复核可在 revision 不变时刷新，当前输入与播放器会话保持；不可用源继续保留原取材身份。

## 状态、版本和事务

- 草稿新建时 `version=1`。更新必须携带 expected_version，通过 SQL 条件更新递增版本；旧版本写入报 RevisionConflict。
- `confirm_revision` 由上层已鉴权的人工作用域提供 actor_id，服务写入确认人与时间并递增版本。模型输入契约没有确认字段。
- 确认后禁止原地更新。修改以新 ID、parent_id 派生草稿，原版本和旧 Take 保持可追溯。
- 生产计划、提示词、审稿及预演引用同场次的已确认依据。不能把其他项目、其他场次、其他类型或未确认版本拼入当前对象。
- 确认只表示文档冻结，不代表模型能力通过、审稿通过或用户已经授权视频执行。编译和执行使用独立动作记录，执行前检查固定提示词、完整审稿和模型能力。
- 应用审稿结果时锁定原检查任务，将任务身份写入原始审稿版本的`source_task_id`（唯一且可空）。同一任务重试返回同一确认版本；保存和确认在同一事务内完成，失败不留下占用任务身份的草稿。人工取舍另行派生，不占用原任务身份。前端按此身份核实保存结果，不能用报告文字相同推断是同一次检查。
- `DirectingStore` 不 commit 外层事务。每次修改使用 savepoint，使正文、依赖索引和文件使用保护原子更新；失败不留下部分关系。
- 场次创建记录章节原文 SHA-256；章节来源必须匹配该场次保存的来源版本。场次保存原文范围和摘录；修改范围后旧设计来源摘要失效，阻止确认和试拍。名称、排序变化不使来源摘要失效。设计保存同时比较用户编辑时看到的场次版本，旧页面不能将旧内容重新标为最新来源。
- 暂无业务删除接口。外键限制直接删除仍有引用的章节、场次、版本、TaskOutput 和 Take；不会自动清理已有开发数据。

## 生成单元、素材与剪辑

单元试拍页面按“拍摄准备 → 指令与检查 → 试拍与候选”三个可回看的步骤组织。浏览步骤与真实业务进度分别表达，窄屏使用步骤选择入口。顶部保持单元标题与当前步骤的单一主操作，左侧展示工作状态和独立候选数；指令生成、检查提交、确认结论、视频执行分别由用户明确触发。检查与视频进度在各自区域内展示，任务中心保留通用记录。检查结论按出现对象组织，分别统计待修改、待检查和通过项；主要问题直接显示，通过项合并为可展开摘要。正式检查必须满足六岗位乘以全部出现对象的完整性要求。主区在尚未选择指令或检查记录时直接提供合法记录的选择；无检查结果时显示固定依据与检查范围，运行中显示真实任务。指令正文、固定输入与版本记录在同一个详情面板内查看；固定输入按所选指令绑定的计划展示模型名称、媒体参考和可读版本链。历史预览不改变工作版本，只有明确切换才更新匹配检查；浏览位置与业务完成状态分别保存。

“试拍与候选”在主区展示候选素材，右侧持续展示固定执行摘要、本单元任务和所选候选快速预览；未选素材时保留选择提示，打开预览不改变主区宽度。运行任务保持提交时的指令身份，不因切换当前指令隐藏；失败、取消或未检查的新指令不移除旧候选。候选默认网格，支持列表和全部／当前指令筛选，每页12项，使用真实时长及独立的审片、采用状态。新增产出不抢焦点，可显式定位新候选。

候选快速预览复用右侧详情栏，窄屏为抽屉；不自动播放，也不写审片或采用。正式编辑仍在剪辑验收，往返保留精确候选选择。媒体读契约返回`thumbnail_url`，缩略图接口先校验项目与场次，再从真实视频提取最长边480像素的首帧。文件锁串行化缓存生成，缓存身份绑定文件ID与存储键，并记入现有`thumbnail_key`参与清理；丢失时重建，不创建新文件档案、资产、参考、Take或生成任务。缩略图失败与视频播放失败分别可重试。

单元覆盖项保存局部 ID、镜头、节拍、事件和明确动作范围。一镜可出现在多个单元，同一单元可产生多个 Take。计划支持多镜范围，不代表当前任何生成供应商已经验证多镜能力。

ModelCapability 默认 unknown；明确 supported/unsupported 或参考媒体能力需附来源。未知/不支持的方案可作为计划保存；当前编译与执行仅接受单镜试拍，页面提供显式拆分。多镜艺术控制能力尚未经过真实验证。

参考素材固定 file_id、用途、主体及顺序，服务检查媒体类型与可用性。 单元画布分别投影固定首帧、尾帧位置，并按显式 `subject_group_id` 投影普通参考组，历史未分组单图以绑定身份独立呈现；组卡保留稳定编辑目标、全部绑定及文件可用状态。当前编辑预览与保存读取使用同一投影，空添加入口不代表实际输入。组内编辑只改变目标组，其他组、首尾帧和其他单元保持原值；身份主体继续遵守一对象一组及单一来源。新增 `directing_reference`、`directing_take` 两类 FileUsage；现有 API 的 usage_kind 是字符串，场次 API 使用专用类型化契约。冻结设计、参考包、来源证据、Take 和剪辑都复用现有文件可用性检查与删除保护。

Take 只登记已成功、项目匹配、input_snapshot.prompt_revision_id 匹配的 TaskOutput，唯一键为 `(task_id, output_ordinal)`。MySQL 锁定输出行后检查幂等身份。重复登记返回原 Take；明确再次试拍对应另一任务。任务终态交付已接入该服务，TaskService 成功事务中原子登记 Take；取消优先，重复交付不重复登记。

单元试拍前端在发送前将`request_id`及精确指令/审稿身份保存在当前标签页的sessionStorage，未核实响应沿用同一次请求；受理任务身份持久化后才清理待核实记录。浏览器存储不可用时停止新提交。此记录用于刷新恢复，不代表服务端执行状态或授权校验。明确“再拍一次”才分配新的请求身份，服务端仍按已有`DirectingAction`及版本约束执行。

编译接口接受可选`request_id`，在场次锁内复用对应的`DirectingAction`与已确认指令；同一身份不可跨场次、计划、单元或操作复用。响应在工作区字段之外提供`compiled_prompt_revision_id`，前端按该身份选择结果，不根据新增版本数量或排列推测。前端在请求前保存编译身份，响应未核实可跨刷新重试；省略请求身份的旧调用仍表示一次新的编译。

六岗检查提交接受可选`request_id`，其身份在项目与场次内固定到指令及检查参数。场次锁内先核实任务快照中的请求记录，再决定是否创建任务；恢复已取消或已完成任务仍返回原任务，不自动再次检查。恢复元数据保存在任务快照顶层，不进入模型的`run_args`。前端先保存待核实身份，受理任务记录持久化后才清理，刷新可继续核实。MySQL重复读下，恢复分支对操作记录和对应版本使用当前读，编译响应保证携带精确指令正文。

实际覆盖必须指向该 Take 文件并有相同的证据区间；音视频实际时间码需满足 `0 <= in < out <= duration_ms`。未知文件时长不能用于实际剪辑。审查状态与四类结论匹配，结论与采用独立。

planned 项使用预计时长与设计镜头；media 项使用 Take 和实际 source_in/source_out 毫秒区间。Pydantic 判别联合拒绝混填。登记或审查 Take 不自动增加、替换任何剪辑项。

## 阶段二代码增量边界

当前代码新增场次来源范围、场次工作区 API 和六岗文本任务分派。设计与审稿的模型结果通过显式应用动作保存；编译结果冻结为提示词版本，试拍记录编译/执行动作及任务身份。单元视频任务成功后发布为候选 Take，不自动进入粗剪；真实视频时长通过 ffprobe 读取。

文本模型请求失败时，任务保存不含供应商正文或凭据的错误摘要。供应商 `AllocationQuota.FreeTierOnly` 错误显示“免费额度耗尽且仅使用免费额度”的恢复提示；其他模型 HTTP 错误仅显示状态码，模型 SDK 超时显示“请求或执行超时”。失败任务不会生成可采用的导演结果。

场次划分、导演设计和六岗审稿由 Worker 固定关闭思考并开启流式接收，保留模型的其他扩展参数。SDK 在内部聚合分片，页面仍在完整 JSON 校验后展示结果；流式接收不等于页面逐字显示。单次网络读取等待仍为 120 秒，任务总执行时限仍为 1800 秒，持续输出可以超过 120 秒，但首个分片或相邻分片等待过久仍会超时。

导演模型输出先通过完整类型与关联校验。结构不合法时，最多进行一次携带具体校验错误的模型纠错，继续受同一任务的取消和总时限约束；再次不合法则报错，不放宽契约、不保存半份工作单。提示中同时声明 Note 状态、来源版本和局部 ID 关联规则。

场次版本设计另向模型提供 `design_protocol`，补充 JSON Schema 未表达的用途与阶段组合、适用范围、对象字段和行 ID 来源；字段清单复用业务契约常量。该协议仅用于模型输入，不属于工作单或 API 响应字段。纠错时同时提供本轮输出的对象 ID、缺失 ID 位置、镜头／节拍关系及每条适用性记录的合法选项，便于处理被结构错误遮住的引用问题。选项不代表已确定的实际范围，服务端不自动改写模型正文或用途；最终仍执行原有来源、身份、关联与完整性校验，失败正文按只读诊断保留。

前端已接入场次主路由，已通过浏览器验证新建项目、章节、人工划场、设计修改保存及刷新恢复。迁移 `35d9f2b7ca03` 已通过隔离 MySQL 完整升级。阶段二真实试拍、人工审片、局部采用与补拍替换已验收；样片动作偏差不视为计划覆盖完成。后续验收与未完成项见[实施计划](/docs/plans/directing-workbench-implementation-tasks/)。


## 页面与播放边界

场次列表可手动选择原文、接受 AI 建议、调整标题及顺序；重复排序位置显式互换并递增版本。场次工作区通过 URL 的 `view` 切换设计、试拍、剪辑，共享同一场次身份。设计与审稿输出显式采用；场次分析可安全回填本地划分草稿，正式场次仍需用户保存。轮询不覆盖分析期间新增的编辑。

场次工作区通过 generated client 读取反馈接口的 `active_cut_revision_id`，与本次工作区快照配对显示当前采用；不按最新记录推断采用。读取中、失败或指针引用的版本尚未出现在快照中时明确显示状态待核对，只有服务端返回空指针才表示尚未采用。切换场次或刷新后忽略旧请求返回。

设计与计划分别标明当前查看/编辑、草稿/已确认及真实引用；当前采用的 Take 和预演可追溯到仍在使用的旧计划与设计。“版本与历史”只读展示设计、计划、剪辑及曾采用区间，不切换编辑基线或发起写入。素材选择器区分当前采用素材和待审候选，逐项显示 Take 的采用源区间，审片结论与采用独立。

“把这一段加入剪辑草稿”只修改本地草稿；保存草稿不改变当前采用，只有“确认并设为当前采用”成功后才更新采用依据。设计、计划、风格、素材审片、剪辑、反馈和接缝审查的未保存编辑统一提供保存/放弃/取消；保存失败保留输入并阻止继续。页面跳转与浏览器前进/后退通过路由拦截保护编辑；关闭或硬刷新使用浏览器原生离开提醒，取消后可回页面保存。

上述编辑器的写入请求未返回时，工作区暂时禁止输入、拖动、版本切换与其他编辑操作；浏览器导航不能放弃正在提交的内容或重复保存。请求成功或失败后恢复编辑，失败保留原有草稿；等待中的导航可在保存成功后继续。锁定只持续到接口返回，不覆盖后台生成任务的排队和运行时间。

主导航分为“导演设计 → 单元试拍 → 剪辑验收”。版本与写入操作位于阶段控制栏；下一步建议可在“当前进展”抽屉查看，有单元的试拍工作区通过稳定对象标题、状态与单一主操作表达进展。视觉验证、批量、实际连续性、验收返工与来源记录归入阶段内入口，原有八种 `view` 回跳仍可用。点击已选阶段标题可回到该阶段主区。下一步优先处理未保存编辑、已知来源或输入问题，再指向任务、检查结果及素材；主动作使用真实选中对象，服务端拒绝的参考或模型输入定位到对应单元，不把缺少参考图一律判为不能生成。

浏览位置按项目和场次保存在当前浏览器会话，并同步所选版本与单元到 URL。显式链接身份优先；已记住的对象不存在时不猜测最新版本。任务中心回跳包含阶段、任务身份与任务区定位，业务页从实际 Take、已记录的提交范围或固定审稿清单恢复输入。无法恢复时明确提示，不自动选用其他计划；后续取得依据后可显式载入。用户随后改变选择，刷新仍尊重该选择。

创作想法、验证图准备、新资产输入、补拍准备与素材选取区间单独暂存于本浏览器会话；这些准备内容不是已提交的业务版本，也不包含执行授权。暂存失败时保留输入并进入保存/放弃/取消保护。生成、资产创建、计划确认和采用均保留原有显式操作。

轮询只更新服务器事实。素材审片保留开始编辑时的版本，并发更新后提示核对并阻止覆盖保存；连续性依据变化时保留正在编辑的接缝，处理本地修改后才载入更新。任务状态尚未读回时不推荐重复生成；已知提交按计划与单元定位，其他独立单元仍可操作。各阶段验收证据、交付复核与未完成项见[体验优化计划](/docs/plans/directing-workbench-experience-plan/)。

设计页提供“分镜 / 清单 / 关系图”三个直接入口，首次进入默认分镜；密度、画面来源和关系图选项集中在固定的视图设置入口。左侧只选择全场、节拍或未分组范围；切换范围不强制改变展示。分镜和清单严格遵循设计镜头顺序，节拍用标签表达，跨节拍镜头在全场仅出现一次。切换展示共用筛选、选中身份和右侧编辑，本场意图与全场概览属于共享上下文。无图分镜优先展示动作与叙事作用；用户显式启用画面后，才展示统一比例画面区。画面只复用用户明确选择且设计版本、镜头匹配的已保存预演绑定，多来源仍需选择，不自动使用最新图片。排序入口跟随所选镜头，前移/后移只重排筛选镜头占用的位置，其他镜头位置保持。

全场关系使用紧凑节拍行：镜头编号、真实关联对象、问题及进入节拍的明确入口。选择节拍或对象只更新详情与影响高亮，不隐式切换范围；共享对象详情按真实引用说明直接/间接路径，并提供逐镜定位。未分组保留独立行；长集合摘要可展开，搜索覆盖全部原对象。节拍行允许引用同一镜头，全场镜头和时长按身份去重，节拍统计不能直接相加。全场不显示详细关系预设与图形缩放，节拍内保留详细关系图及合法引用编辑。节点聚焦和布局移动不修改业务引用，聚合关系不能直接删除。

右侧对象详情保留 Note 的未填写、未知、建议、事实、不适用与明确没有。六岗、声音与来源通过岗位审阅及对象关联查看或编辑，共享规则列出受影响镜头，没有第二份摘要正文。历史比较按稳定身份显示增删、字段、顺序和来源变化，不改变编辑基线。

建议通过独立准备与结果面板处理，查看不写入，明确写入后再确认已保存版本；失败保留编辑，操作返回多个变化版本时要求用户核对。

侧栏顶部“本场资产”展示当前设计按类型与身份去重的有效资产关联数；未关联、中途加载、核实失败和不可用引用分别表达，名字不算关联。资产列表由场次页共享读取，失败可重试，不自动删除原引用。

“设计问题”打开当前范围的问题面板，按镜头列出问题并定位对应字段，不改变主区筛选。仅工具栏“仅看问题”触发问题筛选；搜索与问题筛选在主区显式显示结果数及清除入口，空结果与本场无镜头分开表达。旧会话筛选仍可恢复，但不会成为无提示空白。共享对象修改前列出受影响镜头。

设计详细图、生产准备／总览与固定列指令图复用 `front/src/components/canvas/` 的节点外框、关系曲线及键盘命中；前两类还共用受控视口和布局移动。公共层不依赖场次 DTO、接口或存储，投影、版本、权限和业务写入继续由调用方负责。节点类型与状态分别传入，生产类型不再伪装为设计镜头类型。节点公共外观集中在 `canvas.css`：8px 圆角与内边距、14px／20px 标题、12px 类型标识、2px 蓝色选中轮廓；缺失以虚线边框和文字提示，过期单独降色。`graphAppearance.tsx` 统一业务类型的图形、文字与色调，同类人物、事件和要求在设计／生产／指令投影中保持一致；公共层只接收通用色调。坐标图保留紧凑尺寸与布局动作，指令图采用自然高度与分列阅读。连线和箭头共用颜色，选中优先于关系色调，不改变直接／间接语义。实线为直接关系，虚线为通过实际字段／对象形成的间接关系；问题、候选和过期状态独立标识。尺寸变化保留用户保存的视角，明确“适应画布”才重新适应；初次范围／内容布局仍按原入口适应。

间接边不能直接解除，而是定位到实际拥有引用的表演或连续性对象。关系类型、范围内聚焦、缩放和平移及节点布局保存在当前浏览器会话，重新进入同一设计可恢复；切换版本不沿用旧图状态。清单和分镜按版本与范围核对滚动记录；全场总览按版本恢复展开与滚动，进入节拍再返回恢复有效筛选和选择。既有storyboard/list/relations浏览记录映射到新入口；过期对象不会被同名对象替代。缺失的间接引用也进入问题检查，并定位实际持有引用的对象。

从镜头详情进入试拍按精确设计版本查找全部计划/单元映射，多个候选逐项选择，无关联时给出准备入口；未保存设计先保存。试拍保存本空间的选择、筛选与内容滚动，剪辑保存精确片段、筛选、时间线缩放和滚动位置。浏览记录不包含执行或采用授权，来源、任务、历史预览不改变编辑基线。

单元与候选素材由左侧统一选择，中央显示当前对象摘要及其工作内容，不再重复放置对象选择器。窄屏通过“场次导航”完成同一选择，选中后关闭导航；切换素材仍保护未保存审片，播放与采用不会由浏览选择自动触发。

生成页聚焦所选单元，旁侧列出本计划的拍摄内容。单元任务摘要只使用真实产出、已记住的提交范围或审稿出现项，不将未知任务分配给同名单元；完整任务记录独立打开。生成指令、审稿与视频以计划版本和单元身份过滤，审稿还必须匹配所选指令的全部出现项；空报告不作为匹配结果。同名单元不跨版本合并。指令与候选使用服务端持久的`display_number`，编号范围为计划版本与单元；排序、过滤和刷新不重新编号。单份指令主区弱化为“本次指令”，多份显示“指令 vN”；跨单元候选名称补充计划及单元。编号缺失明确显示不可用，不以CAS修改版本或过滤位置代替。切换计划或单元只恢复该精确范围内仍合法的明确选择，刷新不自动拼接最新记录。编译响应按明确返回的指令身份定位；无法核实产出身份时保留核实或显式选择路径，不猜测最新版本。固定输入展示范围、模型、全部参数、参考位置/用途/来源，并按图片、视频、声音的真实类型预览；完整正文、正常审稿依据及来源按需展开，问题和人工取舍仍可达。

任务区突出运行、失败和可据业务结果核对的待处理项，已取消及其他完成记录进入完整历史；被明确定位的任务保持可见。设计结果用已写入内容或保留的模型来源核对，审稿结果用已写入内容核对，素材待审以 Take 注释判断，不增加虚假的已读状态。查看、取消、打开结果和完整历史仍保留，批量、验证图及重组继续通过原有接口执行。未知能力仍由编译/执行的服务端校验拒绝，不通过布局隐藏或豁免硬校验。

选片页以候选播放器为主区，旁侧仅显示服务端已确认采用及逐项真实源区间；同一 Take 多次采用逐项保留。候选显示动作、素材及计划身份，观察/覆盖/来源与对比按需展开。选入、替换和重排只修改剪辑草稿，保存成功也不更新侧区采用；确认成功后重新读取采用、接缝及依赖。采用读取失败时保持待核对，不用草稿或最新版本代替。画面验收与声音完成度使用同一采用版本的确认反馈分别展示，缺失记录不推断通过。

剪辑时间线区分真实源区间与预计预演，显示各自时长及条目起点；预演用文字与虚线标识，不作为实际覆盖证据。条目可通过按钮或拖动重排，完整 Take 不裁删。预演按预计时长、真实片段按选定源区间顺序播放；开始粗剪播放时暂停候选播放。单份素材读取失败不阻止其他素材审片；同一 Take 集合的媒体重试需重新加载页面，错误提示明确要求先保存修改再重新加载；页面“刷新状态”不会重新请求媒体。提帧仍使用当前实际播放时刻，来源保存为文件证据。

问题、返工和连续性回跳携带剪辑、片段、Take 或计划/单元身份；同一 Take 的问题证据匹配多个采用片段时只定位素材，不擅自选取其中一个。反馈版本和台账页签随往返保留，未保存修改仍通过统一保存/放弃/取消保护。历史返工可查看与调整旧剪辑，但不能直接准备当前采用的补拍；必须核对当前采用并另建返工记录。已准备的补拍计划逐条提供明确入口，不自动选择最新计划或执行拍摄。三类台账保留完整来源，并可返回对应素材或固定指令。

全站在小于 768 CSS 像素宽度时使用可关闭的主导航抽屉，保留完整内容宽度；桌面使用 64px 全局窄导航与 48px 顶栏，详见[前端基础布局](../frontend-layout/)。三阶段入口在窄屏同时显示并允许文字换行，表单选择、按钮和卡片标题按可用宽度排列，不通过隐藏横向溢出来掩盖被截断的操作。任务中心入口位于全站顶栏，记录在独立抽屉中打开，不再以浮动按钮遮挡工作区底部操作。按钮、折叠标题、输入与业务定位元素提供可见键盘焦点；采用、草稿、预演与声音状态仍使用文字说明。综合回归与真实用户理解测试的完成状态分别记录在体验优化计划中。

生产计划固定文件、用途、主体、输入位置、顺序、模型与参数。参考不可仅属于其他项目。执行面板展示提示词版本实际绑定的输入和编译映射。六部门审稿按出现项完整校验；人工裁决派生新版本并保留原结论。

视频归档使用 ffprobe 获取真实时长，运行镜像包含 ffmpeg；下载接口支持单区间 Range 请求。审片支持独立选择另一候选对比播放，不改变当前采用区间。粗剪可采用实际区间、排序、替换和顺序播放；本地编辑保留起始版本，刷新服务端状态不会更新其并发基线，冲突需要明确载入最新版本。


编译格式当前为 `jellyfish-scene-v4`：将整场背景与本次执行动作分区，明确禁止把背景中的前后镜头动作追加到本单元。本次执行区只放选定镜头、节拍、调度状态、表演与摄影；整场调度、连续性和声音等背景仍保留来源映射。事件、锚点等关联身份及显式延迟数值保留在文本中。设计预计时长明确区别于本次单元时长；模型来源元数据不混入执行提示词。旧提示词版本保持不可变。

场次 API 使用函数作用域的数据库依赖，在响应发出前完成提交，避免确认成功后立即编译却读到未确认状态。页面保持本地编辑基线；服务器版本变化时提示并提供显式载入入口，不以新版本标签掩盖旧编辑内容。保存设计后继续保留正确的场次来源版本，支持连续编辑保存。


## 可读来源解析

`POST /api/v1/studio/projects/{project_id}/directing/sequences/{sequence_id}/sources/resolve` 是只读批量查询，接受1–100项 `Source`，逐项返回可读信息或不可用状态。项目/场次归属先经 DirectingStore 校验，原始来源身份与版本不变。

模型来源按同项目、同场次任务快照中的 `run_args.task_identity` 精确匹配，不能把它当模型ID或任务主键。模型名称取历史快照；生成输入只返回保存的原文上下文，不提供完整任务输入或供应商响应。重复身份、未知来源版本和缺失记录不猜测归属。章节来源只提供对应版本的冻结场次摘录，当前章节名称明确标注；没有字段级定位时不把生成上下文当作逐句引用依据。历史版本同时核对场次、身份和修订。文件先校验项目使用归属、删除状态和真实区间，再提供预览目标。

设计字段、指令、审稿、参考与剪辑观察使用可读来源摘要；原始类型、标识、版本收进技术详情。设计右侧打开来源时保留原字段挂载，返回恢复输入、滚动和键盘焦点。历史在独立只读预览中查看，不切换编辑基线或采用。前端按当前场次去重、合批读取；失败可重试，离开的来源卡片忽略迟到响应。

媒体来源按实际类型预览。记录有入出点时，“播放记录区间”从入点开始并在出点暂停；媒体读取失败显示可重试提示。历史原文存在多个冲突快照时返回不可用，不任取一个，也不以其他场次的生成记录补足来源。C 阶段交互与视觉证据见[优化方案验收记录](/docs/plans/sequence-workbench-interaction-refinement/#9-交付验收)。

## 项目风格版本

风格规则保存所属岗位、可观察要求、例外说明、来源、场次范围和模型名称范围。空范围表示项目内全部场次或全部模型；规则状态区分候选、启用、弃用。风格版本与单条规则状态相互独立：只有已确认版本中的启用规则才可执行。

风格保存和确认都核对项目归属、章节来源版本、已确认工作单来源以及文件可用性和媒体区间。文件证据写入 FileUsage，阻止被引用文件删除。确认版本不可原地修改；修改派生新的候选版本。设计显式绑定 `style_revision_id`，不会自动跟随最新风格。

导演建议提交冻结所选风格和文本模型适用规则；模型不能更换风格身份。视频编译按实际视频模型和当前场次读取规则，并在 Prompt.decisions 保留风格来源。六岗审稿接收相同视频模型的适用规则；验证图按所选图片模型读取规则。规则例外保留在输入中，不能以项目默认风格覆盖明确的场次事实。编译格式 v4 增加固定项目风格规则，已有提示词不被改写。

## 按需资产与视觉验证

场次内可复用本项目资产，也可从具体对象“新建并关联”角色、场所和道具；独立入口“仅创建项目资产”不关联本场。创建只保存稳定设定，不把本场动作、情绪、调度和手部状态写入全局资产。对象内创建成功后将精确资产身份填入设计草稿，关联仍须保存设计；已确认设计派生新草稿，不修改历史依据。

创建接口要求客户端提供UUID格式的`request_id`，返回单个`AssetSummary`。服务端按项目、场次与请求身份确定实体身份，并用项目行锁串行化重复请求；相同输入重试返回原资产，身份相同但内容不同返回冲突。前端保留不明确请求的身份及输入，不能按同名或列表顺序推断创建结果。调用方须随OpenAPI契约更新。

资产摘要区分实际图片文件和空视角记录，返回可用图片身份及不可用图片数量；可用性依据文件记录的类型与删除状态，不代表已验证存储服务可访问。查看嵌入的资产详情不自动创建视角；用户明确准备图片或保存资产时复用既有资产能力。详情返回保留本场设计，资产未保存编辑另行保护。关联、图片准备与选入试拍参考分别表达。

### 设计到试拍的交接

确认设计不创建生产计划或生成任务。确认后的主入口为“准备试拍”或“继续试拍”；无计划时，直接进入试拍同样显示设计依据与镜头选择。只读进入不默认勾选镜头；用户明确建立草稿后按所选镜头创建单元。匹配计划按固定设计身份筛选，多个匹配显式选择，已有草稿不会因阶段往返重新初始化。

有单元后按“拍摄准备、指令检查、试拍与候选”展示内容和当前步骤的下一步；确认检查不会自动开拍。保存并确认准备先保存或派生计划，再确认精确版本；保存成功但确认失败可重试确认。仅试拍计划草稿可在同场阶段间保留并直接往返，版本切换、离开场次及写入中仍受保护；其他编辑继续沿用既有草稿保护。

拍摄准备使用统一“添加参考”抽屉，提供本场资产、已有素材和上传三种来源。本场资产以计划固定设计的关联为依据，逐图选入，不自动提交全部图片。资产关联属于设计，具体文件选择属于单元；上传临时参考不创建资产，移除参考不解除场次关联。

`ReferenceBinding` 的可选 `asset_origin` 保存选择时的资产类型、身份和名称；`subject_group_id` 将同一主体的多张图片聚合为一个模型主体。新增资产来源在保存时校验当前项目、名称及图片归属，与导演默认资产独立。已有选择以同一单元、绑定身份、固定文件、媒体类型及完整来源快照和选择凭据匹配服务端保存基线；显式冻结计划重组由服务端提供新单元到原单元的可信映射，核对原绑定后继承选择，普通请求不能提供此映射。资产改名、图库调整、删除或移出项目不取消已有固定文件选择，也不允许复制绑定、跨单元搬用或篡改来源借用此例外。保存、指令及执行准备复用这一来源边界，并继续检查实际文件权限与媒体约束。资产来源按类型和稳定标识判断是否同源，名称保留选择时快照；当前资产目录不重写冻结任务、Take 或指令证据。参考预览的 `source_status` 独立表示来源目录是否仍可用，文件 `status` 只说明当前项目可见的文件登记，不能据此声称真实字节已核实；正常预检沿用登记校验，Worker 在请求供应商之前下载固定输入，字节缺失时失败且不替换文件。历史无分组字段的参考维持单图主体，不回填或按当前资产自动合组。编译文本的主体引用与模型输入组名一致，原始参考 ID 继续供连续性证据使用。

`GET /api/v1/studio/projects/{project_id}/directing/video-models/{model_id}/reference-capabilities` 返回现有适配器可表达的参考位置、主体媒体与数量限制；空上限表示未知，不代表无限支持或模型效果已验证。前端读取该接口引导选择，更换模型保留已选文件并提示冲突；服务端编译／提交仍复核真实输入。OpenAI 接入只开放一张起始画面，可灵 Turbo 不接收帧参考，Omni 开放首尾帧，Vidu 的主体与帧参考不混用。旧计划中不能被适配器保留的位置或组合会被预检拒绝，需明确修改并重新确认计划，不静默丢图或转换语义。

准备页的“拟发送”读取当前草稿；开拍前的“将发送”和固定详情读取指令所绑定计划，分别显示图片数量、主体分组／帧位置及选择时来源。参考变化须派生计划、重新编译检查，候选成功仍不自动采用。

指令阅读器提供易读视图与模型原文，共用同一份 `Prompt.text`。前端从该指令所属的固定计划、设计和参考来源解析名称，显示片段保留原文坐标，编译依据仍按原文匹配；不维护第二份执行文本，不改变参考绑定或任务快照。检查结果沿出现项所属指令解析名称，原始行按需展开。已知 v4 编译格式可转换字段与枚举；缺失历史对象、未知格式和有歧义的自由文本保留原文，不查询最新资产补写历史。

视觉验证复用图片生成任务，目标为已确认设计版本 `directing_image`。用户选择形象、空间、构图或连续性目的，明确输入画面要求、参考顺序、图片模型和画幅。发送内容包含明确输入与该设计的适用项目风格；不自动把完整设计追加到画面描述。

图片成功后仅建立带项目/章节的候选文件关系，来源为 `image-task:<task_id>`，任务可回到对应场次和设计。结果面板查看候选后，用户需在生产计划参考中明确选择用途、主体和输入位置，再保存/确认计划；不会自动替换资产默认图、既有参考或剪辑。

审片播放器可从当前实际视频位置提取 PNG。服务验证 Take 归属与实际时长，使用 ffmpeg 本地取帧，保存 `frame:<take_id>:<毫秒>` 文件来源及原视频的时间证据；图片可用于后续参考或预演。普通提帧可作通用参考；实际连续性另有采用区间证据，不能用普通参考冒充前段落幅。

## 文字与静态图预演

预演沿用 SequenceCut 的 planned 项，固定已确认设计和镜头，并保存预计时长、可选静态图与相对对白落点。无需图片或生产计划即可添加文字卡。对白必须属于该镜头覆盖的表演节拍，落点必须位于预计时长内；静态图必须是本项目可用图片，并建立文件保护。

粗剪可混合 planned 与 media 项。文字/静态图按预计时间播放，真实素材按采用的实际源区间播放；界面明确显示两类时间。设计镜头的预演缺口仅表示尚未添加预演卡，不能冒充 Take 的实际覆盖证据。

拖动或上下移动均重排同一剪辑列表，重新计算时间线位置；更换素材、移除或载入版本会停止旧播放。确认剪辑后修改会派生新版本，旧预演仍指向原设计。用户可明确把预演项替换为实际 Take 区间；试拍成功本身不会替换它。更改设计仍走设计版本派生，不修改已经确认的预演依据。

## 实际连续性与局部影响

确认剪辑时，在同一事务更新当前采用指针 `directing_active_cuts`；保存草稿不改变实际依据。入幅和落幅只从当前已确认的 media 项提取：读取真实解码帧时间，选择采用区间内第一帧或最后一帧，保存剪辑项、Take、源区间、实际帧时间和图片身份。区间内无帧时拒绝提取；预演卡不提供实际证据。解码使用可寻址的本地临时文件，支持索引位于文件尾部的 MP4。

生产单元的 `dependencies` 固定来源 `plan_revision_id + unit_id`，并明确绑定 `frame_id + reference_id`。来源计划必须已确认，落幅必须来自该来源单元的实际 Take，且对应图片确实作为本单元的 continuity 参考发送。未选择证据的依赖可以保存为待准备计划，但不能编译或提交。引用历史确认版本允许后续计划消费已经拍出的结果，不依赖同一计划中无法原地更新的完成标记。

接缝审查使用时间线上直接相接的两个 media 项，用户查看前段落幅、后段入幅和视频后保存 pass/revise 及理由。预演和时间线空白不算真实接缝。审查记录不可变，当前页面显示仍匹配的最近结论；不运行自动视频理解，也不把计划中的连续性要求当成实际通过结果。

确认替换剪辑后，按采用项身份、Take 和源区间定位失效：有关落幅依赖不能再提交，有关接缝待复核；未改变片段及其相邻关系继续复用原审查。旧计划、提示词、证据和剪辑不改写，已有 Take 不删除，不创建全场重拍任务。修复通过重新提帧、显式派生相关计划及重新编译审稿完成。

单次和批量受理均检查实际依据，Worker 在真正发送视频请求前再次检查排队期间的变化。失效任务以可恢复的连续性提示失败；已经发送给供应商的请求继续使用其固定输入并收取结果，采用仍由人工决定。迁移 `68a2c5e0fd36` 创建证据表，并把旧单元依赖身份转为带原计划版本的未满足依赖，不将其提升为实际证据。


## 章节入口与工作上下文

章节主入口为 `/projects/:projectId?tab=chapters`，主区是章节名称、原文预览、原文字数、场次数量、操作五列的分页表格（窄屏收起预览和字数），使用已有章节列表接口与 `sequence_count`，不增加跨章节待核对或粗剪统计。点击名称打开章节编辑弹窗；有场次时点击场次数量打开 `chapter=:chapterId` 对应的单层管理抽屉，内部左侧为场次列表，右侧为名称、排序和只读原文摘录；“在原文中调整范围”进入完整原文划场视图。打开管理抽屉按显式场次、有效浏览记忆、顺序第一场默认展示详情；无效显式对象报错。窄屏默认显示详情，主动返回列表后不再次自动选中。数量未知显示“查看场次”，不伪装成零场。

`sequence=:sequenceId` 直接定位抽屉内详情；旧章节场次列表路由保留重定向，工作台仍使用独立场次路由。场次行可以直接进入设计、试拍或剪辑阶段，普通保存保留当前场次。表格主操作按已知原文及数量显示“填写原文／划分场次／场次管理”，未知字段显示“查看场次”；0 场数量入口直接划场，无原文时进入编辑器，无原文但有历史场次仍能从数量入口查看。管理顶部提供“调整划分”，沿用 `panel=source` 打开全宽视图。章节组合仅保留表格操作入口，`panel=assembly` 深链接仍可用；组合与划场抽屉标题栏关闭均回到表格，不提供内部返回或重复组合入口。划分页将分析记录与保存版本合并到“历史版本”弹窗，进行中的分析状态保留在划分页。章节名称保留正文编辑入口，场次面板移除重复编辑按钮，无原文时提供填写引导。无场次时从原文划场，无原文的新章节先进入编辑器，不自动分析或创建场次。

普通划场与明确范围编辑入口使用同一划分编辑器；`mode=manual` 旧入口仍定位指定场次，不再显示模式切换。顶部右侧只保留“AI智能划分”“历史版本”，新增场次放在左栏，保存新版本与放弃修改位于底部。三栏分别为本章草稿、完整原文和场次编辑，窄屏切换对应内容。框选支持跨段落、重复文本定位和键盘／触屏选区；装饰边界不写入正文或范围偏移。浏览器 UTF-16 及 CRLF／CR 归一化偏移转换为后端 Unicode 字符半开区间。新建不预填整章范围。

AI 分析只由用户点击发起；有未保存草稿时先确认成功后替换。当前点击发起的任务完成后，仅在章节、原文、成员基线及本地编辑标记均未变化、且未进入历史浏览时回填同一编辑器。否则结果保留到历史，不覆盖草稿。重新进入页面不会自动载入过去的成功结果；轻量历史摘要返回本章进行中的分析身份，避免逐项读取全部旧任务。AI 回填仍是未保存草稿，多处匹配和无法定位项要求核对范围，场次身份在同一编辑区明确映射。

“历史版本”以分页表格展示保存快照与未关联分析，展开才读取正文。正式版本显示 vN；新成功分析显示待保存，旧分析缺少关联证明时显示保存关系未知。查看版本只读展示当时原文并保留当前草稿，返回后继续编辑。基于版本编辑使用当前正式集合为提交基线；旧原文范围先清空并重新定位，恢复退出身份携带其当前并发版本，保存生成新章节版本。草稿替换有独立确认，不把只读查看当作采用。

“继续编辑草稿”和“基于此版本编辑”经统一草稿保护进入对应阶段；计划进入拍摄准备。保存失败或冲突保留输入，保存派生结果提交后再应用用户明确选择的目标，执行前重新校验归属与固定依据。点击编辑本身不创建版本，未确认草稿按起始并发版本原地保存，已确认基线在保存时通过 `parent_id` 派生新 ID；不提供逐次草稿保存快照。计划选择绑定其固定设计，切换设计清空不匹配的计划选择但保留原计划，剪辑独立选择并可明确进入空草稿。切换与草稿保存不改写历史引用或当前采用，不引入场次总版本。指令与检查仍按计划和单元身份选择。

导演设计使用分镜、清单和关系图三个入口，展示设置集中在“视图设置”。单元试拍的拍摄准备图复用设计图的节点样式与画布操作，只展开当前单元的覆盖、明确设计关联、实际参考输入与落幅依赖。点击节点定位具体编辑对象；空集合与已有集合均保留添加节点，界面入口不写入计划。窄屏使用可操作的节点卡片与文字关系。

计划工具区的“生产计划总览”展示当前计划全部单元和显式依赖，默认只读，并提供现有拆分与重组入口。总览浏览保留准备草稿；进入其他单元仍经过草稿保护。画布位置按项目、场次、计划和单元隔离，移动布局不修改业务关系，不依据列表相邻推断依赖。

人物资产的可选素材与本次已选参考分别表达。参考按真实文件、明确主体分组与顺序展示；添加或替换复用参考选择器。角色、物件、场所及参考主体节点共用 640px modal，查看、绑定修改、用途与输入位置、替换、移除及排序在同一弹窗内完成，不再经过右侧参考表单或嵌套选图 Drawer。已有对象默认只显示管理内容，添加或替换时展开选图；通用添加入口默认隐藏已有输入，可在同一弹窗切换为查看本单元全部参考。资产图片、已有素材、上传通过素材来源选择进入，不保留独立“更多参考方式”入口。已选文件从候选中隐藏，保留已选／可新增数量，不自动选择资产图片。

modal 修改独立暂存，取消、关闭或离开不写入计划；只有“应用到本单元”更新计划草稿，仍需原有保存与确认。替换保留参考身份、顺序及仍适用的主体分组；涉及落幅引用的修改提示重新核对。能力读取失败可重试，上传结果在弹窗关闭或选择上下文改变后忽略；打开期间单元输入变化时阻止覆盖。设计资产关联仍使用固定设计：资产来源与参与者必须相符，人工参考可显式修改人物绑定；修改设计关联通过弹窗内的合法版本流程入口，不能覆盖已确认设计。

镜头 `ShotCoverage.participant_ids` 明确参与的人物／物件，引用同一设计的 `participants`。缺失或 `null` 表示范围待核对，`[]` 表示明确无对象；非空名单必须无重复且引用有效。草稿允许待核对，新设计确认及 AI 设计输出要求所有镜头给出明确名单；审稿修订涉及设计修改时同样要求补齐。历史已确认设计仍可读取、编译，修改必须派生新版本，不按名称猜测回填。设计详情的“关联”页可选择名单、明确无对象或标为待核对，问题入口可定位该字段。

准备图以覆盖镜头的明确名单收集设计对象，对象不依赖资产或参考绑定而存在，并分别连接到各覆盖项。明确空名单不被节拍表演重新填充；历史未知名单仅保留调度和表演依据，并标明范围待核对，因此不宣称历史对象完整。实际参考绑定始终合并，范围外对象标为“仅本次参考关联”，不伪造镜头设计边。移除最后一份参考后，设计对象仍保留。背景活动、连续性及正文提及不自动扩大单元范围。节点按已有角色／道具资产关联标为“角色”／“物件”；无关联或对象缺失时使用“对象”，已选状态与引用缺失提示也使用中性称呼。

参考候选按当前单元设计对象、范围待核对的设计关联、其他场内对象分组；所有场内对象仍可明确选入。参考弹窗可以查看逐镜依据及所选对象的全场背景／连续性依据，跳转到计划固定设计的相应对象；镜头节点也可直接定位参与对象字段。修改经统一草稿保护与版本流程，不在准备图直接改写已确认设计。

编译将当前覆盖镜头的明确名单、明确无对象或历史待核对状态写入执行段并记录字段来源；全场对象和其他部门背景仍按原有背景／执行分区保留。固定输入展示从指令绑定的计划与设计读取名单。设计名单不代表部分动作内实际可见，不自动选图，也不改变历史指令、实际媒体覆盖或采用。

场所未关联时保留可操作节点，显式选入的临时空间参考也展示其真实绑定。范围外的已选对象保留，未提取素材可通过通用添加入口补充，不推断全场必需输入。镜头范围、单元参数及落幅依赖继续使用原有 Inspector／窄屏详情抽屉。设计关联连线与实际输入绑定连线分别表示。历史依赖来源只读；当前草稿变化不重写已编译指令的固定输入。指令、检查和候选详情留在对应步骤，准备区仅提供真实记录摘要。详细编辑复用计划编辑器，任务状态读取重试仅重启读取，不提交业务任务。

同章切换不继承上一场对象身份；浏览记忆按项目、场次或章节隔离保存在会话存储中，不能作为执行授权。章节表格搜索、页码、滚动与本章场次搜索、选择、滚动及完整原文阅读位置分别恢复；默认章节主表不因历史记忆自动打开抽屉。划场保存后留在当前视图，关闭回到表格并恢复触发按钮焦点，再次进入管理时恢复有效的最近场次，工作台返回定位本章本场，显式深链接优先于记忆，无效或跨项目对象明确报错。关闭、后退和切换沿用保存／放弃／继续编辑保护，写入失败保留输入；不可用存储不阻止浏览。

## 场次验收、章节组合与反馈

`cut_review`、`repair`、`knowledge` 复用 `DirectingRevision` 的强类型、草稿 CAS、人工确认和派生机制。文件、素材和版本引用经 `DirectingStore` 校验并建立保护索引；没有第二份可编辑台账。确认时间在 MySQL 保留微秒，最新确认决定当前验收，不以草稿创建先后代替确认顺序。

整场审片绑定已确认剪辑版本，记录整体判断、成立部分、缺失覆盖、可用区间、必修/优化/后期问题、待观察证据及声音状态。空剪辑、预演或尚有必修/覆盖缺口不能验收通过。保存剪辑草稿不改变验收依据；确认替换后旧审片保留为历史，旧页面不能再确认其为当前验收。画面通过与声音完成分开，声音默认待后期。

旧 revision 工作台的 `assembly` 接口组合 `Sequence.position` 顺序和各场当前采用，保留原有历史查询与跨场检查契约。当前章节页面已改用下文的固定交付读取与播放器，普通场次编辑不再改变章节已使用内容；当前能力仍是顺序预演，不是成片导出或混音。跨场记录 `directing_chapter_transitions` 固定相邻场次、两侧采用版本和真正整场首尾的实际边界帧，并保存转换意图、人工观察与声音依据。保存时锁定章节顺序和两场采用，顺序/采用变化后记录成为历史；插叙或跳时不要求机械保持同一姿态。

返工记录固定原剪辑项、问题源区间、症状、根因假设、保留的好区间、首选/备选修法、是否需要新素材、主要调整和验收条件。保留区间必须来自原采用且不与同源问题区间重叠；关联结果剪辑时必须完整保留这些好区间。结果可关联新计划单元、实际 Take 区间和确认剪辑，不自动采用。比较按实际输入逐字段计算变化；多个因素不能标成单变量比较，单次比较也不宣称已证明因果。

确认的返工单只有明确需要新素材时，才能按用户选择的原覆盖项、局部动作和时长准备单单元计划草稿；`directing_repair_plans` 连接诊断与新草稿，任务和 Take 继续沿计划身份追溯。此动作不创建模型任务、不修改原采用，之后仍走计划确认、编译、审稿和显式执行。

P/O/C 分别表示原则候选、当前操作条件、项目设定，保存主张、条件、建议、反例/失败信号、例外、证据、可信程度与复核日期。人工确认仅确认此记录；可显式准备为本场适用的项目风格草稿，仍须在项目风格中确认规则及版本后选择使用。候选不会自动应用或改写全局 Skill。

三本账位于场次业务页：连续性账组合设计状态、实际采用、边界证据和接缝；提示词账组合固定全文、字符数、格式、来源、审稿、批准事件和产出；Take 实验账组合真实素材、固定输入、观察、返工诊断、新旧结果及经验。采用片段可展开原计划/单元、六岗设计和参考；通用任务中心职责保持不变。

## 审稿决策信息展示

审稿结果、执行确认、取舍弹窗与提示词版本账使用同一只读详情组件。摘要展示判断，按需展开每项观察、影响对象原字段路径、修改建议、验收条件及各自状态/来源；文件来源包含身份和时间码。空来源、未知、不适用、未填写与明确没有分别表达，不补造依据。待审不显示为需修改，未列具体问题也不代表通过。

影响路径只显示原值，不自动定位或切换到最新设计。取舍弹窗仍可查看原问题，裁决仍使用现有派生版本与理由记录，没有新增审批步骤或下载报告。

### 公共工作区展示

三个阶段复用工具栏、对象标题栏、导航搜索和详情容器，业务判断仍由各阶段提供。导航搜索默认收起，按场次和阶段恢复非空查询时显式展开；关闭搜索清空条件，筛选不修改所选对象，移动端搜索不触发导航关闭。详情容器在桌面与抽屉之间移动同一门户节点，避免响应式切换重挂载内部编辑器。工具栏允许按内容撑高，避免窄屏换行遮挡内容操作。

展示框架分为五层：L0 `SequenceLayout` 提供左右外壳、导航槽与底部状态；L1 页面提供场次栏、工作阶段栏及上下文／内部导航／内容的顺序；L2 设计、试拍、剪辑各自组织专属工作区；L3 主视图或步骤填充主内容和辅助内容；L4 对象详情负责字段、局部页签和抽屉。框架负责几何、滚动与响应式，阶段业务负责身份、草稿和动作条件，不为每层新增可见工具栏或通用状态管理。

“导演设计／单元试拍／剪辑验收”始终位于场次选择下方，通过既有 URL `view` 切换。设计的分镜／清单／关系图导航横跨主区和详情区；试拍的计划栏、单元标题与单一主操作、步骤栏均位于双栏上方。三个阶段复用 `workbench-content` 分栏规则，桌面辅助栏为 344px；剪辑继续保留播放器、下方时间线与右侧审片／片段／来源详情，不增加虚构步骤。试拍三步骤共享同一内容边界，主内容与辅助内容各自滚动，浏览位置按版本、对象与视图身份分别保存并兼容旧单条记录。低于 1280px 时使用单列和辅助抽屉，试拍在步骤栏下显示真实摘要与入口；低于 768px 使用步骤选择框。

## 指令的局部修订与主动调整

`directing_review_revision` 任务冻结原文、设计、计划、单元、指令、整体修改要求、人工字段编辑和逐项方向。检查来源可以是已确认检查版本或成功的检查任务；省略检查来源表示主动修改，未检查和全部通过时均可发起，不伪造检查问题。候选只保存在任务结果中；字段白名单限制为当前单元适用的既有字段，身份、数组结构和关联不能由模型增删。真实候选按契约规范化并核对完整关联，预览与采用使用相同差异。每个待处理问题都须有处理说明，未解决或需要选择时不能部分采用。声音执行方式通过逐项 `sound_execution` 显式选择，不能仅凭模型自述授权。

修订生成和采用分别使用请求身份。场次数据库写锁先于任务查询，兼容 SQLite 的并发请求；采用进度保存在任务快照中，逐步记录新设计／当前单元计划、指令和检查任务。仅修改单元参数时复用原设计；设计改变时创建新设计版本，不覆盖其他草稿或已确认版本。采用服务通过 DirectingStore、现有编译和正式审稿能力执行，不自动生成视频。检查任务受理后的失败由现有检查入口显式重试，不自动建立循环。

问题方向复用浏览器会话草稿，键包含项目、场次、指令及固定检查来源，问题按出现项、岗位和 finding 序号定位。原任务直接保存为检查时延续方向，人工取舍派生检查与新检查隔离。方向改变使原方案过期，服务端采用时再次比较完整输入与方向；响应丢失后沿原请求核实。真实前后差异在固定编辑区中就地展示，移动端保持相同的修改路径。

直接字段编辑通过服务端返回的当前单元白名单选择，校验原值、类型、共享范围、真实差异和来源。`review-revisions/preview` 使用人工编辑生成候选，不调用 AI；同时填写自然语言要求时交给 AI 处理，但不能覆盖人工编辑。局部单元不开放整场共享提示词和声音说明，声音执行安排单独接受明确选择。

预览与正式编译共用正文构建逻辑。候选预览不创建确认版本，文本和候选身份保存到任务结果；历史读取不重新查询当前模型并改变预览。采用校验固定输入和候选身份，新请求必须提交候选身份。整体 `summary` 可表达无变化、未能满足或必要选择，无需伪造问题键；非拟落实结果和无实际变化的候选不能采用。

### 章节明确使用的固定场次交付（2026-10-14）

`SceneDeliveryRecord` 固定来源版本名称、保存修订、完整内容、当时适用的整场审片和真实素材来源；`SceneDeliveryUse` 仅记录章节当前使用指向。只有显式“用于章节／更新到章节”会替换指向，普通保存、版本浏览和内容撤销不写此记录。原请求核实返回原交付，即使后来已交付别的内容也不把章节退回旧记录。新请求锁定章节并核对保存修订、当前场次和真实引用；迁移只创建空表，不自动交付历史内容。

### 整场导出执行与成果登记

场次版本导出使用 `scene_export` 任务，固定保存修订、完整时间线与默认 1080／可选 720 档、30fps／H.264／AAC／MP4 配置。源文件以 `TaskInput` 登记，运行中不得删除；导出任务参与该版本的另存检查。导出不自动采用素材、改变验收或更新章节使用内容。

工作器执行期间的下载、FFmpeg 渲染和对象上传均在数据库事务外进行。输出只在 `TaskService.finish` 的成功裁决事务内登记为文件和已发布成果；取消先登记则没有可下载成果。遗留上传使用 `generated/<task_id>/export.mp4`，由现有孤儿清理在终态后按宽限期处理。任务超时后，尚未结束的渲染线程仍占用有界线程池名额，临时目录由渲染器退出时清理。

渲染中的解码错误使整次导出失败，不跳过片段或以黑场替代。编码进程报错后逐片段核查原媒体区间，定位文件头可读但视频数据损坏的具体片段；正常成功路径不额外重复解码。未定位到单一媒体问题的编码错误及超时保留整场失败说明，不发布半成品。

同一提交身份只核实既有记录；按原记录重试仅适用于失败／取消任务，继续使用原快照。导出当前内容则先保存再创建新请求。业务页展示固定区间、构图、状态、取消和下载；任务中心仅传递已验证的所属版本与任务身份以回跳原记录。同场次内从其他版本查看导出时，独立打开原版本记录，不切换当前编辑版本；固定依据只读，明确重试仍归属原版本并保留当前草稿。跨版本重试结果未知时在弹窗核实原凭据，再返回当前画布。


导出尺寸检查读取真实媒体的显示尺寸和源区间，按逐片段 contain／cover 计算有效画面与放大倍率，不以生成请求或文件名义尺寸替代。两档只改变像素尺寸，时间线位置、源区间、构图方式、播放速度与原声规则保持不变。缩放提示为只读信息；明确导出仍在保存完成后检查固定内容，再创建任务。检查读取失败保留编辑并提供重查与片段定位，不将读取失败解释为没有媒体。


导出成果可用性与任务终态分开：成功记录对对象存储执行 HEAD 核实，文件明确不存在或已登记删除时显示不可用；网络、权限等未能核实时显示未知，可重读而不改变成功事实。新导出在服务端建任务前读取实际源文件并检查媒体区间，不能绕过前端检查提交缺失媒体。新重试还实际解码原快照指定区间，拒绝文件头可读但视频数据已损坏的输入，不能用当前替代素材绕过失效原输入。已受理请求的核实优先返回既有记录，不因后来媒体丢失而创建替代任务。

明确删除导出成果时，仅解除 `scene-export:<task_id>` 自身的项目文件归属，再走现有文件引用保护与延迟字节清理。其他业务仍使用文件时整次删除回滚；成功时保留文件身份、任务成功记录和不可变输出关系，不删除源素材或其他成果。重新导出使用独立文件身份，没有自动过期策略。

指令、指令检查及场次设计任务的轻量来源包含经版本／场次／项目归属校验的原版本，单元任务同时包含原单元。任务中心回跳在业务页按指定任务读取固定记录，同场次当前编辑内容保持不变；读取失败可原位重试，不以其他记录替代。明确打开所属版本继续编辑时重新核实任务和目标对象，并使用统一离开保护；历史场次不开放此编辑入口。详情在离开保护期间暂时收起，取消后恢复，长内容在弹窗内滚动。

任务历史中的指令检查展示原模型、固定正文与输入、六岗判断理由、问题建议和验收要求，复用当前检查的只读结果展示，不提供确认动作。原单元被后续编辑删除不影响已有固定记录阅读；继续编辑必须仍存在原单元及关联镜头。

关闭历史任务详情、更换详情目标或离开当前上下文时，尚未完成的“打开所属版本”读取请求失效；迟到响应不再发起离开保护或导航，也不向新详情写入旧错误。

场次视频任务的来源由真实执行记录关联原版本及单元。任务中心查看视频同样打开原固定记录的只读详情，保留当前版本草稿；明确继续编辑才核验原对象并执行统一离开保护。旧生产计划视频不伪造新场次版本来源。

AI 设计弹窗使用“生成记录”区分场次版本，仅列出所属场次版本的生成任务，以真实任务创建时间、整场／局部范围与状态识别。弹窗明确显示所属版本，“应用设计”旁标注目标名称；应用更新当前编辑内容，不自动新建版本。待应用状态依据当前设计与冻结输入比较，内容已变化时提示待核对，与结果一致时显示与当前设计一致，不伪造持久化应用记录。

场次版本 AI 设计使用冻结的完整版本内容校验新结果：原对象身份、项目资产、镜头和单元出现项引用均须真实有效。新整场任务固定候选接收契约，分别校验数据合法性及设计完整性；范围、可见结果和摄影工作单缺项不等于结构或来源非法。来源、结构与完整性错误共用最多一次纠错；修正可增加承接镜头，但须同时补齐摄影和关联。原设计及已接收候选的有正文字段不能变空或消失，原设计已有的未知／不适用理由也纳入保留检查；此保护不保证自然语言意图不被改变，仍需用户检查差异。

至少得到一份合法候选时任务执行成功，完整性缺项另存，设计可标为待完善。后续纠错产生非法数据、删掉受保护正文、返回非文本或供应商调用失败时，保留最近一次合法候选及其生成轮次，候选缺项与随后未被接收输出的诊断分别记录；不拼接不同轮次设计。始终没有合法候选则任务失败，原始输出仅供诊断。取消与任务总时限继续由 Worker 裁决。历史任务按原冻结契约读取，不将历史失败追溯改成可接收候选。

生成规则复用 JSON Schema 和 `design_protocol` 的字段、用途及身份清单；自然语言说明设计职责、范围继承与未知／不适用的表达。纠错反馈保留结构化缺项及对象路径，补充整行是否有正文、是否原已存在和全部缺范围字段。全空独立记录按行级问题定位，不能误导成补某个字段正文；删除本次新增占位仍须核对原文、理由与引用，不能用删行或编造内容掩盖未决问题。

设计预览展示固定候选、真实差异和待处理问题；失败纠错输出另作只读诊断。用户明确“应用为待完善设计”后在现有工作台继续编辑，不建立第二套候选编辑器。预览再次核对来源、当前人工编辑、项目资产和单元引用；任何冲突拒绝整次应用。应用只更新当前编辑内容，保存后关系图重新计算缺项，不因接收候选清除问题。任务执行状态、设计完整性和当前单元生产准备度分别表达，受影响内容补明前继续受原指令检查与视频准备校验约束。

用户主动发起的局部修订继续只替换选中的已有 Note，禁止修改身份、引用和结构，产品重规划另行推进。范围外原有缺项不阻断一次合法文字修改；局部任务成功、建议应用与整场设计范围完整分别表达。人工编辑中间态可保存，范围缺项仍在关系图展示；受影响单元在补明前不能通过指令检查与视频准备，不以整场缺项数量阻断无关单元。

导演画布的后退、前进、总览及附加信息入口浮于画布左上方，不计入顶部工具栏高度。已有镜头时，顶部 AI 设计左侧显示“下一步：单元画布”；悬浮或键盘聚焦时说明建立或选择单元、明确动作与模型／时长／参考、再生成指令并检查的顺序。入口沿用当前镜头及已有单元选择规则；进入镜头子图后以前述镜头为准备目标。导航不创建单元或确认设计，保存沿用工作台设置；设计缺项继续展示，不阻断用户进入单元画布准备其他明确内容。


### 导演画布的设计对象卡片

导演画布以“场次总览 → 镜头 · 设计”浏览同一场次版本的设计。总览以原文依据为初始锚点，镜头入口按计划顺序独立围绕原文逐圈排列，不设镜头设计分组；全场适用原卡、跨镜共享原卡和未关联设计区分别位于外侧上方、左方和下方，未关联设计区默认收起，可展开或由对象定位自动展开，并有独立的数量气泡与显隐开关。没有镜头时仍可编辑全场与未关联内容，并通过空态入口建立首镜。镜头子图以当前镜头原卡为中心，节拍、调度和锚点在上方，人物／事件／验收依据在左侧，其余岗位工作单在右侧，必要的共享引用在下方；进入镜头入口切换整个子图，不再使用七个岗位子图或整场／当前镜头范围开关。

场次版本读取与保存响应附带同一版本 ID、revision 的服务端关系图；图由已保存的六岗字段引用和明确适用性即时生成，不另存关联真值。范围解析按具体字段职责、明确镜头归属或字段适用性确定，不由当前镜头数量、共同人物或任意图路径推断。摄影继承自身 shot_id；固定约束职责字段即使显式标成普通设计，仍按原阶段和明确范围进入单元约束，不能借用途标签跳过去向核对。按节拍组织的表演行动仍须明确具体字段范围，拆镜不复制表演谱。全场背景的范围用 scene 表达，全场约束用 scene_rule 表达；普通设计恰好服务于所有现有镜头仍保留指定镜头集合。背景与约束用途分别表达，不能把动作或可见结果改标背景来通过验收。

读取与保存响应同时提供 `director_graph` 和 `unit_graph`，与业务内容使用同一版本及 revision。内容及响应元数据在首次读取时一并固定，后续依赖核验刷新同一 ORM 行不会使本次响应混入另一 revision。共同契约定义节点身份、摘要、定位目标、问题、边、视图成员、分组及入口；`GraphAssembler` 统一注册、计数和引用闭合校验，`CanvasReadContext` 固定共享读取快照。导演和单元各自投影业务载荷，原关系图业务编排位于 service 层。每图只有一个 parent_id 为空的根视图；消费者使用返回的根／子图地址，不能约定 ID 字符串。镜头数量和视图卡片数量使用后端元数据，前端不另算展示摘要。前端 `GraphCanvas`、`GraphSubgraphPreview`、布局缓存与浏览历史共同负责绘制、几何及导航，编辑器独立使用当前输入；已迁移区域不从原始业务列表重建图。

单元画布通过全部／指定镜头浏览后端成员，单元聚合入口进入完整独立子图；镜头筛选不裁掉该单元的其他覆盖项。四类配置是动作覆盖、生成配置、组织要求和前段依赖。首帧与尾帧分别投影独立参考卡，空位置提供添加入口，已绑定位置以输入边指向单元；同一文件可分别保留首尾绑定，替换或移除一处不重写另一处。指令图继续保留完整只读参考集合。单元卡片通过 `POST /sequences/{sequence_id}/versions/{version_id}/unit-canvas/preview` 只读投影当前编辑，核对项目、场次、版本与预期保存修订，复用同一后端图构建逻辑。卡面和详情消费同一份当前编辑，AI 方案明确应用后新增的单元在保存前即有卡片；保存失败、恢复、撤销及重做也重新投影。投影更新中或失败时明确显示尚未核实，不将旧摘要当作当前内容；迟到响应不能覆盖新输入。保存状态独立表达，预览不保存版本、不注册引用或创建任务。配置仅从各卡片进入完整详情，种子及额外参数直接在生成配置详情编辑。当前单元准备状态位于顶部，区分待准备、核实中、核实失败和齐备；问题清单提供重试与原字段定位，参考问题打开参考管理，设计缺项回到导演字段。生成指令为独立操作，准备未齐备或尚未核实时禁用。工作台移除手动创建入口，相关创建能力保留；AI 组织仍先明确目标镜头、生成方案并由用户明确应用，没有前端临时业务 graph 或独立保存阶段。 只读执行依据直接复用 `unit_scope`，分开显示执行、适用约束、解释背景和未解决项，保留视频／声音／后期阶段；当前来源按稳定目标定位到单元覆盖项或导演字段。范围类型位于独立 `unit_scope` 公共契约，指令历史和画布共用，不从图关系推定拍摄内容。共享读取上下文批量解析项目可见文件和视频模型及适配器参考能力；生成配置和真实执行共用 `unit_video_inputs` 的模型解析与输入元数据校验，参数／时长／画幅和参考问题定位到各自配置区域。图读取不下载媒体或提交任务，未知配置保持未核实。项目风格沿用既有确认与适用性服务；模型或文件登记变化可在场次 revision 不变时改变重新读取的证据与未知项。参考预览保留绑定角色和 ordinal 顺序，删除或失效文件不被默认素材替代；文件登记可用不代表真实字节或模型输入已经通过执行前复核。

前段依赖卡返回区分固定生产计划单元与场次版本单次采用的强类型证据，保留原 frame／reference 身份、实际帧文件、解码位置和来源；未绑定、当前适用、待复核与不可用分别表达。投影复用现有落幅绑定和连续性校验，采用区间变化不会自动换绑。底层强类型版本内容读取不触发 graph，避免核验证据时递归构建版本图；落幅来源构造也由提帧读取、绑定校验与画布共同使用。此状态只描述依赖证据；`execution_scope_supported` 也仅说明 coverage 形态符合当前执行限制。最终编译和试拍仍逐次复核真实输入及已有指令检查。

节点提供场次背景、全场规则、镜头、单元出现项、待归镜头或未关联归位及原因；字段用途逐项区分背景、设计和约束，混合工作单仍是一张原卡。已有部分明确范围的卡片按这些字段汇总归位，其他字段缺项继续保留，不代表整张卡完整。关系图单独返回设计范围完整性、逐字段缺项与应拍内容尚未分配生产单元的准备缺项。画布展示保存修订及具体定位，更新中的暂存不冒充已确认范围。全场背景无需逐镜关联且不自动执行，卡片摘要沿用同一权威范围读数。单元输入的第三版范围投影复用字段判定，只消费本次动作范围、明确选择的行动、实际适用约束及有明确原因的背景。所属镜头的完整可见结果保留为解释背景，不无条件成为局部单元的执行要求；完整镜头拍摄须由本次动作范围及执行选择明确表达。第一、二版历史投影继续按原规则核对；局部约束不适用于该单元时，不再退回全场背景纳入。无范围字段只有被当前单元消费时才要求补明，不影响其他完整单元。声音和后期约束仍保留原阶段。历史指令建议、依据回执与检查按各自快照的投影版本核对，不因投影升级使未改输入失效；历史比较只使用临时投影，依据状态接口的 current 与新任务始终保留当前投影，避免旧回执使新检查无法确认。当前设计新增旧投影不认识的约束时，要求重新确认依据，保留原快照。

直接边保留拥有者、字段和目标，间接路径列出连续的真实字段引用。画布按图归位和绘线，压缩视图的附加信息仍列出全部直接引用。完全无范围的独立设计行有真实引用时待归镜头，完全无引用时未关联；它们表示设计未完整。每个对象只有一张可编辑原卡；子图对共享对象只显示紧凑、只读的虚拟引用卡。缺失引用保留原标识和不可用状态。

镜头入口沿用叠层边框和模糊子图预览，预览使用实际子图节点、关系与有效个人布局，不显示可读子卡正文，不写入浏览或业务数据。普通原卡使用原有表单、引用校验、只读限制和资产绑定，通过 `WorkbenchModal` 编辑，字段变更按工作台自动保存；弹窗只用右上角图标关闭，显示保存状态。当前没有独立的设计草稿阶段；工作台内部仍保留未保存内容以支持恢复和撤销／重做。未保存编辑期间关系图停留在上次已保存 revision，界面提示关系更新中；保存确认后更新图。导航、布局与预览均不触发业务保存。

总览原文依据到每个镜头入口各有一条结构引导线，到全场内容分区另有一条；它们是无箭头、不可检查来源的浅灰细线，只表示浏览结构，镜头聚焦时突出对应线，窄屏仍显示，不连接跨镜共享或未关联设计。业务连线只取关系图中的直接字段边；压缩或隐藏的边可在附加信息中查看拥有者、字段与目标，服务端另保留间接关系的完整真实路径。未关联区收起时不绘制其端点缺席的线。关系默认弱化，悬停或键盘聚焦突出两端，点击可检查来源字段，不通过连线编辑业务引用。

总览首次布局以原文为中心，镜头入口占内层，其他内容区在外侧避让；窄屏按原文、全场内容、镜头入口、跨镜共享、未关联设计的顺序单列。旧总览中可识别的自动网格坐标迁移到新排布；此前误标为新版的纵列缓存缺少拖动记录，首次读取时重新整理并保留可撤销的旧布局。此后的手动拖动位置单独记录并保留。镜头子图按内容区排列，卡片保持可读尺寸；空分区不占位。手动坐标优先，切镜、编辑、缩放和窗口变化不自动重排；“适应全部”只调整视角，主动整理与布局撤销只影响当前视图。总览和各镜头按本地用户、项目、场次及版本隔离保存位置和缩放；旧七域缓存不直接复用。顶部状态栏显示当前位置及独立的画布浏览前进／后退图标，恢复有效来源现场；右侧附加信息按当前视图展示对象定位和关系来源，其开合状态按总览及各镜头分别记忆。左侧图标从项目资产关联人物／物件，在镜头子图中关联到当前镜头。对象迁移或来源失效时按当前内容解析，无法定位的目标回到当前镜头中心或总览原文，不猜测同名或数组下标。摄影与表演工作单使用唯一业务键，活动与情境使用唯一内容快照；歧义对象不持久定位。小地图只投影当前可见布局。


### 四画布 graph 与业务工作区

剪辑整场图、同场素材图和原工作区切换记录在同一版本的路由浏览历史中，复用共同后退／前进及按视图布局缓存；条目只承载对象与焦点身份，不复制编辑内容。POP 恢复工作区时保留未应用表单，返回图时不以旧浏览选择清空隐藏编辑区。

导演、单元、指令及剪辑图均由版本服务投影同一内容与 revision，读取和保存返回完整四图快照。指令图按明确单元展示完整正文及实际消费依据、参考与当前记录摘要；剪辑图按真实时间线展示采用、待拍占位、源 Take、实际覆盖、真实接缝、整场审片、落幅与受影响后段。摘要读取复用固定依据比较；素材审查、接缝审查与整场验收通过派生 `basis_key` 索引预选最新和最近适用记录，普通版本与列表不扫描全部历史正文。旧数据由明确 Alembic 升级回填，复制仅消费原记录白名单；完整历史按需读取，不调用高层版本读取形成递归。

同 revision 的任务、候选和审片变化通过共同证据刷新进入图，版本、读取序号、revision 和保存内容共同阻止迟到覆盖；刷新保留保存内容的引用以及当前草稿、未应用表单和媒体播放快照。关系树及总览复用这些后端节点与真实边，仅计算显示几何和浏览状态；新增未保存对象通过原编辑入口操作，不拼接临时正式业务图。图响应失败沿原请求核实和恢复机制处理，不新增保存链或 graph 草稿。

剪辑原操作工作区保留播放器、素材库、时间线与审片表单，完整素材审片／接缝／验收／落幅历史由明确阅读或审查动作启用；隐藏工作区及 graph 刷新不自动读取这些完整历史，已打开表单和草稿保持挂载。旧四面板画布只承担工作区几何，不是业务图的回退。新的业务节点布局不套用缺少可靠身份映射的旧容器坐标。选择与跨图定位只浏览原对象，不播放、不采用、不提交任务。
