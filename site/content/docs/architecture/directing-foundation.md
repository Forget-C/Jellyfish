## 身份与存储

所有新增跨层契约在 `backend/app/core/contracts/directing/`，存储模型在 `backend/app/models/directing.py`，业务读写入口为 `backend/app/services/directing/store.py` 的 `DirectingStore`。

| 对象 | 当前存储 | 身份与约束 |
| --- | --- | --- |
| Sequence | `directing_sequences` | 属于 Chapter，通过章节确定 Project；章节内 position 唯一；与场所资产 Scene 不同 |
| SceneDesignRevision | `directing_revisions`，kind=design | 六岗共享一份设计内容；镜头、节拍、事件、调度和空间锚点使用版本内稳定 ID |
| ProjectStyleRevision | `directing_project_styles` | 项目级风格候选与确认版本；设计显式绑定固定版本 |
| ProductionPlanRevision | 同表，kind=plan | 引用同场次已确认设计；GenerationUnit 嵌入计划，身份为 plan_revision_id + unit_id |
| PromptRevision | 同表，kind=prompt | 绑定计划版本与单元；正文、格式版本、编译说明和来源同存 |
| ReviewPacketRevision | 同表，kind=review | 固定提示词、单元、镜头出现项及六岗检查行 |
| SequenceCutRevision | 同表，kind=cut | typed planned/media 项；单主视频轨可留空白但不能重叠 |
| Take | `directing_takes` | 固定 Prompt、计划、单元、TaskOutput、文件；审片注释单独 CAS 更新 |
| 版本依赖索引 | `directing_revision_dependencies` | 从类型化内容派生的直接依赖，不是第二份可编辑真值 |
| 剪辑素材索引 | `directing_cut_take_references` | 从 media 项派生，外键保护被采用的 Take |

设计、计划、提示词、审稿和剪辑共用一张版本表以减少重复版本实现，正文按 kind 用不同 Pydantic 契约校验。GenerationUnit、工作单行、审稿行和剪辑项不单独建表。单元 ID、局部 ID 的同版关联由领域服务校验；数据库保护场次、版本、任务输出、文件和引用索引关系。

`read_revision` 返回带项目/章节/场次的强类型版本快照；`read_take` 返回 TakeSnapshot。内部写入不向 API 暴露 ORM 原始 JSON。调用者必须使用领域服务完成内容和关联校验，不能直接修改 ORM payload 绕过业务约束。

## 状态、版本和事务

- 草稿新建时 `version=1`。更新必须携带 expected_version，通过 SQL 条件更新递增版本；旧版本写入报 RevisionConflict。
- `confirm_revision` 由上层已鉴权的人工作用域提供 actor_id，服务写入确认人与时间并递增版本。模型输入契约没有确认字段。
- 确认后禁止原地更新。修改以新 ID、parent_id 派生草稿，原版本和旧 Take 保持可追溯。
- 生产计划、提示词、审稿及预演引用同场次的已确认依据。不能把其他项目、其他场次、其他类型或未确认版本拼入当前对象。
- 确认只表示文档冻结，不代表模型能力通过、审稿通过或用户已经授权视频执行。编译和执行使用独立动作记录，执行前检查固定提示词、完整审稿和模型能力。
- 应用审稿结果时锁定原检查任务，将任务身份写入原始审稿版本的`source_task_id`（唯一且可空）。同一任务重试返回同一确认版本；保存和确认在同一事务内完成，失败不留下占用任务身份的草稿。人工取舍另行派生，不占用原任务身份。前端按此身份核实保存结果，不能用报告文字相同推断是同一次检查。
- `DirectingStore` 不 commit 外层事务。每次修改使用 savepoint，使正文、依赖索引和文件使用保护原子更新；失败不留下部分关系。
- 场次创建记录章节原文 SHA-256；章节来源必须匹配该场次保存的来源版本。场次保存原文范围和摘录；修改范围后旧设计来源摘要失效，阻止确认和试拍。名称、排序变化不使来源摘要失效。设计保存同时比较用户编辑时看到的场次版本，旧页面不能将旧内容重新标为最新来源。
- 暂无业务删除接口。外键限制直接删除仍有引用的章节、场次、版本、TaskOutput 和 Take；不会自动清理已有开发数据。

## 生成单元、素材与剪辑

单元试拍页面按“拍摄准备 → 指令与检查 → 试拍与候选”三个可回看的步骤组织。浏览步骤与真实业务进度分别表达，窄屏使用步骤选择入口。顶部保持单元标题与当前步骤的单一主操作，左侧展示工作状态和独立候选数；指令生成、检查提交、确认结论、视频执行分别由用户明确触发。检查与视频进度在各自区域内展示，任务中心保留通用记录。检查结论按出现对象组织，分别统计待修改、待检查和通过项；主要问题直接显示，通过项合并为可展开摘要。正式检查必须满足六岗位乘以全部出现对象的完整性要求。主区在尚未选择指令或检查记录时直接提供合法记录的选择；无检查结果时显示固定依据与检查范围，运行中显示真实任务。指令正文、固定输入与版本记录在同一个详情面板内查看；固定输入按所选指令绑定的计划展示模型名称、媒体参考和可读版本链。历史预览不改变工作版本，只有明确切换才更新匹配检查；浏览位置与业务完成状态分别保存。

“试拍与候选”在主区展示候选素材，右侧持续展示固定执行摘要、本单元任务和所选候选快速预览；未选素材时保留选择提示，打开预览不改变主区宽度。运行任务保持提交时的指令身份，不因切换当前指令隐藏；失败、取消或未检查的新指令不移除旧候选。候选默认网格，支持列表和全部／当前指令筛选，每页12项，使用真实时长及独立的审片、采用状态。新增产出不抢焦点，可显式定位新候选。

候选快速预览复用右侧详情栏，窄屏为抽屉；不自动播放，也不写审片或采用。正式编辑仍在剪辑验收，往返保留精确候选选择。媒体读契约返回`thumbnail_url`，缩略图接口先校验项目与场次，再从真实视频提取最长边480像素的首帧。文件锁串行化缓存生成，缓存身份绑定文件ID与存储键，并记入现有`thumbnail_key`参与清理；丢失时重建，不创建新文件档案、资产、参考、Take或生成任务。缩略图失败与视频播放失败分别可重试。

单元覆盖项保存局部 ID、镜头、节拍、事件和明确动作范围。一镜可出现在多个单元，同一单元可产生多个 Take。计划支持多镜范围，不代表当前任何生成供应商已经验证多镜能力。

ModelCapability 默认 unknown；明确 supported/unsupported 或参考媒体能力需附来源。未知/不支持的方案可作为计划保存；当前编译与执行仅接受单镜试拍，页面提供显式拆分。多镜艺术控制能力尚未经过真实验证。

参考素材固定 file_id、用途、主体及顺序，服务检查媒体类型与可用性。新增 `directing_reference`、`directing_take` 两类 FileUsage；现有 API 的 usage_kind 是字符串，场次 API 使用专用类型化契约。冻结设计、参考包、来源证据、Take 和剪辑都复用现有文件可用性检查与删除保护。

Take 只登记已成功、项目匹配、input_snapshot.prompt_revision_id 匹配的 TaskOutput，唯一键为 `(task_id, output_ordinal)`。MySQL 锁定输出行后检查幂等身份。重复登记返回原 Take；明确再次试拍对应另一任务。任务终态交付已接入该服务，TaskService 成功事务中原子登记 Take；取消优先，重复交付不重复登记。

单元试拍前端在发送前将`request_id`及精确指令/审稿身份保存在当前标签页的sessionStorage，未核实响应沿用同一次请求；受理任务身份持久化后才清理待核实记录。浏览器存储不可用时停止新提交。此记录用于刷新恢复，不代表服务端执行状态或授权校验。明确“再拍一次”才分配新的请求身份，服务端仍按已有`DirectingAction`及版本约束执行。

编译接口接受可选`request_id`，在场次锁内复用对应的`DirectingAction`与已确认指令；同一身份不可跨场次、计划、单元或操作复用。响应在工作区字段之外提供`compiled_prompt_revision_id`，前端按该身份选择结果，不根据新增版本数量或排列推测。前端在请求前保存编译身份，响应未核实可跨刷新重试；省略请求身份的旧调用仍表示一次新的编译。

六岗检查提交接受可选`request_id`，其身份在项目与场次内固定到指令及检查参数。场次锁内先核实任务快照中的请求记录，再决定是否创建任务；恢复已取消或已完成任务仍返回原任务，不自动再次检查。恢复元数据保存在任务快照顶层，不进入模型的`run_args`。前端先保存待核实身份，受理任务记录持久化后才清理，刷新可继续核实。MySQL重复读下，恢复分支对操作记录和对应版本使用当前读，编译响应保证携带精确指令正文。

实际覆盖必须指向该 Take 文件并有相同的证据区间；音视频实际时间码需满足 `0 <= in < out <= duration_ms`。未知文件时长不能用于实际剪辑。审查状态与四类结论匹配，结论与采用独立。

planned 项使用预计时长与设计镜头；media 项使用 Take 和实际 source_in/source_out 毫秒区间。Pydantic 判别联合拒绝混填。登记或审查 Take 不自动增加、替换任何剪辑项。

## 阶段二代码增量边界

当前代码新增场次来源范围、场次工作区 API 和六岗文本任务分派。设计与审稿的模型结果通过显式应用动作保存；编译结果冻结为提示词版本，试拍记录编译/执行动作及任务身份。单元视频任务成功后发布为候选 Take，不自动进入粗剪；真实视频时长通过 ffprobe 读取。

文本模型请求失败时，任务保存不含供应商正文或凭据的错误摘要。供应商 `AllocationQuota.FreeTierOnly` 错误显示“免费额度耗尽且仅使用免费额度”的恢复提示；其他模型 HTTP 错误仅显示状态码，模型 SDK 超时显示“请求或执行超时”。失败任务不会生成可采用的导演结果。

场次划分、导演设计和六岗审稿由 Worker 固定关闭思考并开启流式接收，保留模型的其他扩展参数。SDK 在内部聚合分片，页面仍在完整 JSON 校验后展示结果；流式接收不等于页面逐字显示。单次网络读取等待仍为 120 秒，任务总执行时限仍为 1800 秒，持续输出可以超过 120 秒，但首个分片或相邻分片等待过久仍会超时。

导演模型输出先通过完整类型与关联校验。结构不合法时，最多进行一次携带具体校验错误的模型纠错，继续受同一任务的取消和总时限约束；再次不合法则报错，不放宽契约、不保存半份工作单。提示中同时声明 Note 状态、来源版本和局部 ID 关联规则。

## 页面与播放边界

场次列表可手动选择原文、接受 AI 建议、调整标题及顺序；重复排序位置显式互换并递增版本。场次工作区通过 URL 的 `view` 切换设计、试拍、剪辑，共享同一场次身份。设计与审稿输出显式采用；场次分析可安全回填本地划分草稿，正式场次仍需用户保存。轮询不覆盖分析期间新增的编辑。

场次工作区通过 generated client 读取反馈接口的 `active_cut_revision_id`，与本次工作区快照配对显示当前采用；不按最新记录推断采用。读取中、失败或指针引用的版本尚未出现在快照中时明确显示状态待核对，只有服务端返回空指针才表示尚未采用。切换场次或刷新后忽略旧请求返回。

设计与计划分别标明当前查看/编辑、草稿/已确认及真实引用；当前采用的 Take 和预演可追溯到仍在使用的旧计划与设计。“版本与历史”只读展示设计、计划、剪辑及曾采用区间，不切换编辑基线或发起写入。素材选择器区分当前采用素材和待审候选，逐项显示 Take 的采用源区间，审片结论与采用独立。

“把这一段加入剪辑草稿”只修改本地草稿；保存草稿不改变当前采用，只有“确认并设为当前采用”成功后才更新采用依据。设计、计划、风格、素材审片、剪辑、反馈和接缝审查的未保存编辑统一提供保存/放弃/取消；保存失败保留输入并阻止继续。页面跳转与浏览器前进/后退通过路由拦截保护编辑；关闭或硬刷新使用浏览器原生离开提醒，取消后可回页面保存。

上述编辑器的写入请求未返回时，工作区暂时禁止输入、拖动、版本切换与其他编辑操作；浏览器导航不能放弃正在提交的内容或重复保存。请求成功或失败后恢复编辑，失败保留原有草稿；等待中的导航可在保存成功后继续。锁定只持续到接口返回，不覆盖后台生成任务的排队和运行时间。

主导航分为“导演设计 → 单元试拍 → 剪辑验收”。版本与写入操作位于阶段控制栏；下一步建议可在“当前进展”抽屉查看，有单元的试拍工作区通过稳定对象标题、状态与单一主操作表达进展。视觉验证、批量、实际连续性、验收返工与来源记录归入阶段内入口，原有八种 `view` 回跳仍可用。点击已选阶段标题可回到该阶段主区。下一步优先处理未保存编辑、已知来源或输入问题，再指向任务、检查结果及素材；主动作使用真实选中对象，服务端拒绝的参考或模型输入定位到对应单元，不把缺少参考图一律判为不能生成。

浏览位置按项目和场次保存在当前浏览器会话，并同步所选版本与单元到 URL。显式链接身份优先；已记住的对象不存在时不猜测最新版本。任务中心回跳包含阶段、任务身份与任务区定位，业务页从实际 Take、已记录的提交范围或固定审稿清单恢复输入。无法恢复时明确提示，不自动选用其他计划；后续取得依据后可显式载入。用户随后改变选择，刷新仍尊重该选择。

创作想法、验证图准备、新资产输入、补拍准备与素材选取区间单独暂存于本浏览器会话；这些准备内容不是已提交的业务版本，也不包含执行授权。暂存失败时保留输入并进入保存/放弃/取消保护。生成、资产创建、计划确认和采用均保留原有显式操作。

轮询只更新服务器事实。素材审片保留开始编辑时的版本，并发更新后提示核对并阻止覆盖保存；连续性依据变化时保留正在编辑的接缝，处理本地修改后才载入更新。任务状态尚未读回时不推荐重复生成；已知提交按计划与单元定位，其他独立单元仍可操作。各阶段验收证据、交付复核与未完成项见[体验优化计划](/docs/plans/directing-workbench-experience-plan/)。

设计页提供“分镜 / 清单 / 关系图”三个直接入口，首次进入默认分镜；密度、画面来源和关系图选项集中在固定的视图设置入口。左侧只选择全场、节拍或未分组范围；切换范围不强制改变展示。分镜和清单严格遵循设计镜头顺序，节拍用标签表达，跨节拍镜头在全场仅出现一次。切换展示共用筛选、选中身份和右侧编辑，本场意图与全场概览属于共享上下文。无图分镜优先展示动作与叙事作用；用户显式启用画面后，才展示统一比例画面区。画面只复用用户明确选择且设计版本、镜头匹配的已保存预演绑定，多来源仍需选择，不自动使用最新图片。排序入口跟随所选镜头，前移/后移只重排筛选镜头占用的位置，其他镜头位置保持。

全场关系使用紧凑节拍行：镜头编号、真实关联对象、问题及进入节拍的明确入口。选择节拍或对象只更新详情与影响高亮，不隐式切换范围；共享对象详情按真实引用说明直接/间接路径，并提供逐镜定位。未分组保留独立行；长集合摘要可展开，搜索覆盖全部原对象。节拍行允许引用同一镜头，全场镜头和时长按身份去重，节拍统计不能直接相加。全场不显示详细关系预设与图形缩放，节拍内保留详细关系图及合法引用编辑。节点聚焦和布局移动不修改业务引用，聚合关系不能直接删除。

右侧对象详情保留 Note 的未填写、未知、建议、事实、不适用与明确没有。六岗、声音与来源通过岗位审阅及对象关联查看或编辑，共享规则列出受影响镜头，没有第二份摘要正文。历史比较按稳定身份显示增删、字段、顺序和来源变化，不改变编辑基线。

建议通过独立准备与结果面板处理，查看不写入，明确写入后再确认已保存版本；失败保留编辑，操作返回多个变化版本时要求用户核对。

侧栏顶部“本场资产”展示当前设计按类型与身份去重的有效资产关联数；未关联、中途加载、核实失败和不可用引用分别表达，名字不算关联。资产列表由场次页共享读取，失败可重试，不自动删除原引用。

“设计问题”打开当前范围的问题面板，按镜头列出问题并定位对应字段，不改变主区筛选。仅工具栏“仅看问题”触发问题筛选；搜索与问题筛选在主区显式显示结果数及清除入口，空结果与本场无镜头分开表达。旧会话筛选仍可恢复，但不会成为无提示空白。共享对象修改前列出受影响镜头。

设计详细图、生产准备／总览与固定列指令图复用 `front/src/components/canvas/` 的节点外框、关系曲线及键盘命中；前两类还共用受控视口和布局移动。公共层不依赖场次 DTO、接口或存储，投影、版本、权限和业务写入继续由调用方负责。节点类型与状态分别传入，生产类型不再伪装为设计镜头类型。节点公共外观集中在 `canvas.css`：8px 圆角与内边距、14px／20px 标题、12px 类型标识、2px 蓝色选中轮廓；缺失以虚线边框和文字提示，过期单独降色。`graphAppearance.tsx` 统一业务类型的图形、文字与色调，同类人物、事件和要求在设计／生产／指令投影中保持一致；公共层只接收通用色调。坐标图保留紧凑尺寸与布局动作，指令图采用自然高度与分列阅读。连线和箭头共用颜色，选中优先于关系色调，不改变直接／间接语义。实线为直接关系，虚线为通过实际字段／对象形成的间接关系；问题、候选和过期状态独立标识。尺寸变化保留用户保存的视角，明确“适应画布”才重新适应；初次范围／内容布局仍按原入口适应。

间接边不能直接解除，而是定位到实际拥有引用的表演或连续性对象。关系类型、范围内聚焦、缩放和平移及节点布局保存在当前浏览器会话，重新进入同一设计可恢复；切换版本不沿用旧图状态。清单和分镜按版本与范围核对滚动记录；全场总览按版本恢复展开与滚动，进入节拍再返回恢复有效筛选和选择。既有storyboard/list/relations浏览记录映射到新入口；过期对象不会被同名对象替代。缺失的间接引用也进入问题检查，并定位实际持有引用的对象。

从镜头详情进入试拍按精确设计版本查找全部计划/单元映射，多个候选逐项选择，无关联时给出准备入口；未保存设计先保存。试拍保存本空间的选择、筛选与内容滚动，剪辑保存精确片段、筛选、时间线缩放和滚动位置。浏览记录不包含执行或采用授权，来源、任务、历史预览不改变编辑基线。

单元与候选素材由左侧统一选择，中央显示当前对象摘要及其工作内容，不再重复放置对象选择器。窄屏通过“场次导航”完成同一选择，选中后关闭导航；切换素材仍保护未保存审片，播放与采用不会由浏览选择自动触发。

生成页聚焦所选单元，旁侧列出本计划的拍摄内容。单元任务摘要只使用真实产出、已记住的提交范围或审稿出现项，不将未知任务分配给同名单元；完整任务记录独立打开。生成指令、审稿与视频以计划版本和单元身份过滤，审稿还必须匹配所选指令的全部出现项；空报告不作为匹配结果。同名单元不跨版本合并。指令与候选使用服务端持久的`display_number`，编号范围为计划版本与单元；排序、过滤和刷新不重新编号。单份指令主区弱化为“本次指令”，多份显示“指令 vN”；跨单元候选名称补充计划及单元。编号缺失明确显示不可用，不以CAS修改版本或过滤位置代替。切换计划或单元只恢复该精确范围内仍合法的明确选择，刷新不自动拼接最新记录。编译响应按明确返回的指令身份定位；无法核实产出身份时保留核实或显式选择路径，不猜测最新版本。固定输入展示范围、模型、全部参数、参考位置/用途/来源，并按图片、视频、声音的真实类型预览；完整正文、正常审稿依据及来源按需展开，问题和人工取舍仍可达。

任务区突出运行、失败和可据业务结果核对的待处理项，已取消及其他完成记录进入完整历史；被明确定位的任务保持可见。设计结果用已写入内容或保留的模型来源核对，审稿结果用已写入内容核对，素材待审以 Take 注释判断，不增加虚假的已读状态。查看、取消、打开结果和完整历史仍保留，批量、验证图及重组继续通过原有接口执行。未知能力仍由编译/执行的服务端校验拒绝，不通过布局隐藏或豁免硬校验。

选片页以候选播放器为主区，旁侧仅显示服务端已确认采用及逐项真实源区间；同一 Take 多次采用逐项保留。候选显示动作、素材及计划身份，观察/覆盖/来源与对比按需展开。选入、替换和重排只修改剪辑草稿，保存成功也不更新侧区采用；确认成功后重新读取采用、接缝及依赖。采用读取失败时保持待核对，不用草稿或最新版本代替。画面验收与声音完成度使用同一采用版本的确认反馈分别展示，缺失记录不推断通过。

剪辑时间线区分真实源区间与预计预演，显示各自时长及条目起点；预演用文字与虚线标识，不作为实际覆盖证据。条目可通过按钮或拖动重排，完整 Take 不裁删。预演按预计时长、真实片段按选定源区间顺序播放；开始粗剪播放时暂停候选播放。单份素材读取失败不阻止其他素材审片；同一 Take 集合的媒体重试需重新加载页面，错误提示明确要求先保存修改再重新加载；页面“刷新状态”不会重新请求媒体。提帧仍使用当前实际播放时刻，来源保存为文件证据。

问题、返工和连续性回跳携带剪辑、片段、Take 或计划/单元身份；同一 Take 的问题证据匹配多个采用片段时只定位素材，不擅自选取其中一个。反馈版本和台账页签随往返保留，未保存修改仍通过统一保存/放弃/取消保护。历史返工可查看与调整旧剪辑，但不能直接准备当前采用的补拍；必须核对当前采用并另建返工记录。已准备的补拍计划逐条提供明确入口，不自动选择最新计划或执行拍摄。三类台账保留完整来源，并可返回对应素材或固定指令。

全站在小于 768 CSS 像素宽度时使用可关闭的主导航抽屉，保留完整内容宽度；桌面使用 64px 全局窄导航与 48px 顶栏，详见[前端基础布局](../frontend-layout/)。三阶段入口在窄屏同时显示并允许文字换行，表单选择、按钮和卡片标题按可用宽度排列，不通过隐藏横向溢出来掩盖被截断的操作。任务中心入口位于全站顶栏，记录在独立抽屉中打开，不再以浮动按钮遮挡工作区底部操作。按钮、折叠标题、输入与业务定位元素提供可见键盘焦点；采用、草稿、预演与声音状态仍使用文字说明。综合回归与真实用户理解测试的完成状态分别记录在体验优化计划中。

生产计划固定文件、用途、主体、输入位置、顺序、模型与参数。参考不可仅属于其他项目。执行面板展示提示词版本实际绑定的输入和编译映射。六部门审稿按出现项完整校验；人工裁决派生新版本并保留原结论。

视频归档使用 ffprobe 获取真实时长，运行镜像包含 ffmpeg；下载接口支持单区间 Range 请求。审片支持独立选择另一候选对比播放，不改变当前采用区间。粗剪可采用实际区间、排序、替换和顺序播放；本地编辑保留起始版本，刷新服务端状态不会更新其并发基线，冲突需要明确载入最新版本。


编译格式当前为 `jellyfish-scene-v4`：将整场背景与本次执行动作分区，明确禁止把背景中的前后镜头动作追加到本单元。本次执行区只放选定镜头、节拍、调度状态、表演与摄影；整场调度、连续性和声音等背景仍保留来源映射。事件、锚点等关联身份及显式延迟数值保留在文本中。设计预计时长明确区别于本次单元时长；模型来源元数据不混入执行提示词。旧提示词版本保持不可变。

场次 API 使用函数作用域的数据库依赖，在响应发出前完成提交，避免确认成功后立即编译却读到未确认状态。页面保持本地编辑基线；服务器版本变化时提示并提供显式载入入口，不以新版本标签掩盖旧编辑内容。保存设计后继续保留正确的场次来源版本，支持连续编辑保存。


## 可读来源解析

`POST /api/v1/studio/projects/{project_id}/directing/sequences/{sequence_id}/sources/resolve` 是只读批量查询，接受1–100项 `Source`，逐项返回可读信息或不可用状态。项目/场次归属先经 DirectingStore 校验，原始来源身份与版本不变。

模型来源按同项目、同场次任务快照中的 `run_args.task_identity` 精确匹配，不能把它当模型ID或任务主键。模型名称取历史快照；生成输入只返回保存的原文上下文，不提供完整任务输入或供应商响应。重复身份、未知来源版本和缺失记录不猜测归属。章节来源只提供对应版本的冻结场次摘录，当前章节名称明确标注；没有字段级定位时不把生成上下文当作逐句引用依据。历史版本同时核对场次、身份和修订。文件先校验项目使用归属、删除状态和真实区间，再提供预览目标。

设计字段、指令、审稿、参考与剪辑观察使用可读来源摘要；原始类型、标识、版本收进技术详情。设计右侧打开来源时保留原字段挂载，返回恢复输入、滚动和键盘焦点。历史在独立只读预览中查看，不切换编辑基线或采用。前端按当前场次去重、合批读取；失败可重试，离开的来源卡片忽略迟到响应。

媒体来源按实际类型预览。记录有入出点时，“播放记录区间”从入点开始并在出点暂停；媒体读取失败显示可重试提示。历史原文存在多个冲突快照时返回不可用，不任取一个，也不以其他场次的生成记录补足来源。C 阶段交互与视觉证据见[优化方案验收记录](/docs/plans/sequence-workbench-interaction-refinement/#9-交付验收)。

## 项目风格版本

风格规则保存所属岗位、可观察要求、例外说明、来源、场次范围和模型名称范围。空范围表示项目内全部场次或全部模型；规则状态区分候选、启用、弃用。风格版本与单条规则状态相互独立：只有已确认版本中的启用规则才可执行。

风格保存和确认都核对项目归属、章节来源版本、已确认工作单来源以及文件可用性和媒体区间。文件证据写入 FileUsage，阻止被引用文件删除。确认版本不可原地修改；修改派生新的候选版本。设计显式绑定 `style_revision_id`，不会自动跟随最新风格。

导演建议提交冻结所选风格和文本模型适用规则；模型不能更换风格身份。视频编译按实际视频模型和当前场次读取规则，并在 Prompt.decisions 保留风格来源。六岗审稿接收相同视频模型的适用规则；验证图按所选图片模型读取规则。规则例外保留在输入中，不能以项目默认风格覆盖明确的场次事实。编译格式 v4 增加固定项目风格规则，已有提示词不被改写。

## 按需资产与视觉验证

场次内可复用本项目资产，也可从具体对象“新建并关联”角色、场所和道具；独立入口“仅创建项目资产”不关联本场。创建只保存稳定设定，不把本场动作、情绪、调度和手部状态写入全局资产。对象内创建成功后将精确资产身份填入设计草稿，关联仍须保存设计；已确认设计派生新草稿，不修改历史依据。

创建接口要求客户端提供UUID格式的`request_id`，返回单个`AssetSummary`。服务端按项目、场次与请求身份确定实体身份，并用项目行锁串行化重复请求；相同输入重试返回原资产，身份相同但内容不同返回冲突。前端保留不明确请求的身份及输入，不能按同名或列表顺序推断创建结果。调用方须随OpenAPI契约更新。

资产摘要区分实际图片文件和空视角记录，返回可用图片身份及不可用图片数量；可用性依据文件记录的类型与删除状态，不代表已验证存储服务可访问。查看嵌入的资产详情不自动创建视角；用户明确准备图片或保存资产时复用既有资产能力。详情返回保留本场设计，资产未保存编辑另行保护。关联、图片准备与选入试拍参考分别表达。

### 设计到试拍的交接

确认设计不创建生产计划或生成任务。确认后的主入口为“准备试拍”或“继续试拍”；无计划时，直接进入试拍同样显示设计依据与镜头选择。只读进入不默认勾选镜头；用户明确建立草稿后按所选镜头创建单元。匹配计划按固定设计身份筛选，多个匹配显式选择，已有草稿不会因阶段往返重新初始化。

有单元后按“拍摄准备、指令检查、试拍与候选”展示内容和当前步骤的下一步；确认检查不会自动开拍。保存并确认准备先保存或派生计划，再确认精确版本；保存成功但确认失败可重试确认。仅试拍计划草稿可在同场阶段间保留并直接往返，版本切换、离开场次及写入中仍受保护；其他编辑继续沿用既有草稿保护。

拍摄准备使用统一“添加参考”抽屉，提供本场资产、已有素材和上传三种来源。本场资产以计划固定设计的关联为依据，逐图选入，不自动提交全部图片。资产关联属于设计，具体文件选择属于单元；上传临时参考不创建资产，移除参考不解除场次关联。

`ReferenceBinding` 的可选 `asset_origin` 保存选择时的资产类型、身份和名称；`subject_group_id` 将同一主体的多张图片聚合为一个模型主体。新增资产来源在保存时校验项目、固定设计及图片归属；同设计父版本／原草稿继承的未变来源不因资产改名、图片关联调整而失效，执行仍检查固定文件可用性。历史无分组字段的参考维持单图主体，不回填或按当前资产自动合组。编译文本的主体引用与模型输入组名一致，原始参考 ID 继续供连续性证据使用。

`GET /api/v1/studio/projects/{project_id}/directing/video-models/{model_id}/reference-capabilities` 返回现有适配器可表达的参考位置、主体媒体与数量限制；空上限表示未知，不代表无限支持或模型效果已验证。前端读取该接口引导选择，更换模型保留已选文件并提示冲突；服务端编译／提交仍复核真实输入。OpenAI 接入只开放一张起始画面，可灵 Turbo 不接收帧参考，Omni 开放首尾帧，Vidu 的主体与帧参考不混用。旧计划中不能被适配器保留的位置或组合会被预检拒绝，需明确修改并重新确认计划，不静默丢图或转换语义。

准备页的“拟发送”读取当前草稿；开拍前的“将发送”和固定详情读取指令所绑定计划，分别显示图片数量、主体分组／帧位置及选择时来源。参考变化须派生计划、重新编译检查，候选成功仍不自动采用。

指令阅读器提供易读视图与模型原文，共用同一份 `Prompt.text`。前端从该指令所属的固定计划、设计和参考来源解析名称，显示片段保留原文坐标，编译依据仍按原文匹配；不维护第二份执行文本，不改变参考绑定或任务快照。检查结果沿出现项所属指令解析名称，原始行按需展开。已知 v4 编译格式可转换字段与枚举；缺失历史对象、未知格式和有歧义的自由文本保留原文，不查询最新资产补写历史。

视觉验证复用图片生成任务，目标为已确认设计版本 `directing_image`。用户选择形象、空间、构图或连续性目的，明确输入画面要求、参考顺序、图片模型和画幅。发送内容包含明确输入与该设计的适用项目风格；不自动把完整设计追加到画面描述。

图片成功后仅建立带项目/章节的候选文件关系，来源为 `image-task:<task_id>`，任务可回到对应场次和设计。结果面板查看候选后，用户需在生产计划参考中明确选择用途、主体和输入位置，再保存/确认计划；不会自动替换资产默认图、既有参考或剪辑。

审片播放器可从当前实际视频位置提取 PNG。服务验证 Take 归属与实际时长，使用 ffmpeg 本地取帧，保存 `frame:<take_id>:<毫秒>` 文件来源及原视频的时间证据；图片可用于后续参考或预演。普通提帧可作通用参考；实际连续性另有采用区间证据，不能用普通参考冒充前段落幅。

## 文字与静态图预演

预演沿用 SequenceCut 的 planned 项，固定已确认设计和镜头，并保存预计时长、可选静态图与相对对白落点。无需图片或生产计划即可添加文字卡。对白必须属于该镜头覆盖的表演节拍，落点必须位于预计时长内；静态图必须是本项目可用图片，并建立文件保护。

粗剪可混合 planned 与 media 项。文字/静态图按预计时间播放，真实素材按采用的实际源区间播放；界面明确显示两类时间。设计镜头的预演缺口仅表示尚未添加预演卡，不能冒充 Take 的实际覆盖证据。

拖动或上下移动均重排同一剪辑列表，重新计算时间线位置；更换素材、移除或载入版本会停止旧播放。确认剪辑后修改会派生新版本，旧预演仍指向原设计。用户可明确把预演项替换为实际 Take 区间；试拍成功本身不会替换它。更改设计仍走设计版本派生，不修改已经确认的预演依据。


## 批量拍摄与显式重组基础

批量拍摄入口保存所选提示词和六岗审稿版本，逐项预检时不创建任务。用户确认后再次检查每项输入，通过项分别进入通用任务系统；某项受理失败不撤回其他项，重复提交同批返回原任务，不自动重试失败项。页面可恢复批次、查看各项状态并单独取消任务。批次保存依赖迁移 `57f1b4d9ec25`。

已确认生产计划可显式按镜头拆分或组合为新草稿。组合要求模型、画幅、参数、参考与能力依据一致；重组保留未选单元和历史依赖身份；组合同时要求依赖一致，不把已有实际证据重新指向新单元。新计划需重新确认、编译和审稿，不覆盖旧确认版本，不自动创建任务或修改粗剪。

阶段四验收状态及调用计数见[阶段四记录](/docs/plans/directing-phase-four-validation/)。


## 实际连续性与局部影响

确认剪辑时，在同一事务更新当前采用指针 `directing_active_cuts`；保存草稿不改变实际依据。入幅和落幅只从当前已确认的 media 项提取：读取真实解码帧时间，选择采用区间内第一帧或最后一帧，保存剪辑项、Take、源区间、实际帧时间和图片身份。区间内无帧时拒绝提取；预演卡不提供实际证据。解码使用可寻址的本地临时文件，支持索引位于文件尾部的 MP4。

生产单元的 `dependencies` 固定来源 `plan_revision_id + unit_id`，并明确绑定 `frame_id + reference_id`。来源计划必须已确认，落幅必须来自该来源单元的实际 Take，且对应图片确实作为本单元的 continuity 参考发送。未选择证据的依赖可以保存为待准备计划，但不能编译或提交。引用历史确认版本允许后续计划消费已经拍出的结果，不依赖同一计划中无法原地更新的完成标记。

接缝审查使用时间线上直接相接的两个 media 项，用户查看前段落幅、后段入幅和视频后保存 pass/revise 及理由。预演和时间线空白不算真实接缝。审查记录不可变，当前页面显示仍匹配的最近结论；不运行自动视频理解，也不把计划中的连续性要求当成实际通过结果。

确认替换剪辑后，按采用项身份、Take 和源区间定位失效：有关落幅依赖不能再提交，有关接缝待复核；未改变片段及其相邻关系继续复用原审查。旧计划、提示词、证据和剪辑不改写，已有 Take 不删除，不创建全场重拍任务。修复通过重新提帧、显式派生相关计划及重新编译审稿完成。

单次和批量受理均检查实际依据，Worker 在真正发送视频请求前再次检查排队期间的变化。失效任务以可恢复的连续性提示失败；已经发送给供应商的请求继续使用其固定输入并收取结果，采用仍由人工决定。迁移 `68a2c5e0fd36` 创建证据表，并把旧单元依赖身份转为带原计划版本的未满足依赖，不将其提升为实际证据。


## 章节入口与工作上下文

章节主入口为 `/projects/:projectId?tab=chapters`，主区是章节名称、原文预览、原文字数、场次数量、操作五列的分页表格（窄屏收起预览和字数），使用已有章节列表接口与 `sequence_count`，不增加跨章节待核对或粗剪统计。点击名称打开章节编辑弹窗；有场次时点击场次数量打开 `chapter=:chapterId` 对应的单层管理抽屉，内部左侧为场次列表，右侧为名称、排序和只读原文摘录；“在原文中调整范围”进入完整原文划场视图。打开管理抽屉按显式场次、有效浏览记忆、顺序第一场默认展示详情；无效显式对象报错。窄屏默认显示详情，主动返回列表后不再次自动选中。数量未知显示“查看场次”，不伪装成零场。

`sequence=:sequenceId` 直接定位抽屉内详情；旧章节场次列表路由保留重定向，工作台仍使用独立场次路由。场次行可以直接进入设计、试拍或剪辑阶段，普通保存保留当前场次。表格主操作按已知原文及数量显示“填写原文／划分场次／场次管理”，未知字段显示“查看场次”；0 场数量入口直接划场，无原文时进入编辑器，无原文但有历史场次仍能从数量入口查看。管理顶部提供“调整划分”，沿用 `panel=source` 打开全宽视图。章节组合仅保留表格操作入口，`panel=assembly` 深链接仍可用；组合与划场抽屉标题栏关闭均回到表格，不提供内部返回或重复组合入口。划分页将分析记录与保存版本合并到“历史版本”弹窗，进行中的分析状态保留在划分页。章节名称保留正文编辑入口，场次面板移除重复编辑按钮，无原文时提供填写引导。无场次时从原文划场，无原文的新章节先进入编辑器，不自动分析或创建场次。

普通划场与明确范围编辑入口使用同一划分编辑器；`mode=manual` 旧入口仍定位指定场次，不再显示模式切换。顶部右侧只保留“AI智能划分”“历史版本”，新增场次放在左栏，保存新版本与放弃修改位于底部。三栏分别为本章草稿、完整原文和场次编辑，窄屏切换对应内容。框选支持跨段落、重复文本定位和键盘／触屏选区；装饰边界不写入正文或范围偏移。浏览器 UTF-16 及 CRLF／CR 归一化偏移转换为后端 Unicode 字符半开区间。新建不预填整章范围。

AI 分析只由用户点击发起；有未保存草稿时先确认成功后替换。当前点击发起的任务完成后，仅在章节、原文、成员基线及本地编辑标记均未变化、且未进入历史浏览时回填同一编辑器。否则结果保留到历史，不覆盖草稿。重新进入页面不会自动载入过去的成功结果；轻量历史摘要返回本章进行中的分析身份，避免逐项读取全部旧任务。AI 回填仍是未保存草稿，多处匹配和无法定位项要求核对范围，场次身份在同一编辑区明确映射。

“历史版本”以分页表格展示保存快照与未关联分析，展开才读取正文。正式版本显示 vN；新成功分析显示待保存，旧分析缺少关联证明时显示保存关系未知。查看版本只读展示当时原文并保留当前草稿，返回后继续编辑。基于版本编辑使用当前正式集合为提交基线；旧原文范围先清空并重新定位，恢复退出身份携带其当前并发版本，保存生成新章节版本。草稿替换有独立确认，不把只读查看当作采用。

范围写入在章节锁内校验原文版本、场次版本、非空正文、边界和同版本场次重叠，使用锁定读避免 MySQL 旧快照遗漏竞争写入。相邻区间允许，未分配原文允许；历史冲突不自动删改。`SequenceUpdate.span` 省略或为 `null` 时仅改名称/顺序，保留原文摘录、版本及待核对状态。显式修改或重新确认范围才更新来源；范围未变时允许保留既有冲突进行基本信息编辑。旧版本范围不绘制到新原文，也不拿旧偏移判断新正文重叠；重新定位确认后再次校验。整章后端另提供 `POST chapters/{id}/division/preview`、`PUT chapters/{id}/division` 及 `GET chapters/{id}/division/receipts/{request_id}`：完整成员版本基线、明确身份去向与退出、最终范围及预览依据一同校验，在章节事务中只更新实际变化的成员。同请求同内容重放原回执，响应丢失可先查回执。前端手动与 AI 共用整章草稿：选场只改变焦点，范围、名称、顺序、新增及退出均留在本地。调整共享边界同步相邻两场，跨越第三场留下待解决冲突。提交前预览全部差异、身份去向及未分配字符；草稿变更使旧预览失效。保存留页，明确失败保留输入；响应不明时冻结原请求，通过回执或同一请求重试恢复，核实前禁止继续编辑或离开。服务器刷新不会覆盖本地基线，冲突后可对照最新原文与划分，明确放弃后载入。

迁移 `c3e7f9a1b524` 增加 `directing_division_versions` 不可变章节快照与 `directing_division_heads` 当前指向。整章保存及单场改名／调序在章节锁和保存点内同时写入成员、最终快照、指向与回执；无变化不创建版本。快照保存当时原文、有序场次、来源任务／历史版本和身份映射，与 `Sequence.version` 并发版本分开。查询接口为 `GET chapters/{id}/division/history`、`division/versions/{version_id}` 和 `division/analyses/{task_id}`，按项目与章节校验归属；分析详情只投影业务字段，不暴露完整任务配置。旧数据通过显式命令按章接入，完整回执生成导入版本，实际当前成员必要时建立基线；已有当前指向不被历史导入替换。未接入回执也在历史列表保留摘要和缺失说明，不在 GET 请求中回填。操作见[接入指南](/docs/guide/chapter-division-history-import/)，恢复边界验证证据见[实施计划](/docs/plans/chapter-division-version-editor-plan/)。

## 场次验收、章节组合与反馈

`cut_review`、`repair`、`knowledge` 复用 `DirectingRevision` 的强类型、草稿 CAS、人工确认和派生机制。文件、素材和版本引用经 `DirectingStore` 校验并建立保护索引；没有第二份可编辑台账。确认时间在 MySQL 保留微秒，最新确认决定当前验收，不以草稿创建先后代替确认顺序。

整场审片绑定已确认剪辑版本，记录整体判断、成立部分、缺失覆盖、可用区间、必修/优化/后期问题、待观察证据及声音状态。空剪辑、预演或尚有必修/覆盖缺口不能验收通过。保存剪辑草稿不改变验收依据；确认替换后旧审片保留为历史，旧页面不能再确认其为当前验收。画面通过与声音完成分开，声音默认待后期。

章节页面实时组合 `Sequence.position` 顺序和各场当前采用，播放真实源区间，保留场内空白或待拍卡的时间。页面显示未验收、原文变化、缺失覆盖及声音后期事项；当前能力是顺序预览，不是成片导出或混音。跨场记录 `directing_chapter_transitions` 固定相邻场次、两侧采用版本和真正整场首尾的实际边界帧，并保存转换意图、人工观察与声音依据。保存时锁定章节顺序和两场采用，顺序/采用变化后记录成为历史；插叙或跳时不要求机械保持同一姿态。

返工记录固定原剪辑项、问题源区间、症状、根因假设、保留的好区间、首选/备选修法、是否需要新素材、主要调整和验收条件。保留区间必须来自原采用且不与同源问题区间重叠；关联结果剪辑时必须完整保留这些好区间。结果可关联新计划单元、实际 Take 区间和确认剪辑，不自动采用。比较按实际输入逐字段计算变化；多个因素不能标成单变量比较，单次比较也不宣称已证明因果。

确认的返工单只有明确需要新素材时，才能按用户选择的原覆盖项、局部动作和时长准备单单元计划草稿；`directing_repair_plans` 连接诊断与新草稿，任务和 Take 继续沿计划身份追溯。此动作不创建模型任务、不修改原采用，之后仍走计划确认、编译、审稿和显式执行。

P/O/C 分别表示原则候选、当前操作条件、项目设定，保存主张、条件、建议、反例/失败信号、例外、证据、可信程度与复核日期。人工确认仅确认此记录；可显式准备为本场适用的项目风格草稿，仍须在项目风格中确认规则及版本后选择使用。候选不会自动应用或改写全局 Skill。

三本账位于场次业务页：连续性账组合设计状态、实际采用、边界证据和接缝；提示词账组合固定全文、字符数、格式、来源、审稿、批准事件和产出；Take 实验账组合真实素材、固定输入、观察、返工诊断、新旧结果及经验。采用片段可展开原计划/单元、六岗设计和参考；通用任务中心职责保持不变。

迁移不可通过 downgrade 恢复已删旧数据，需使用迁移前数据库备份。当前实现与最终完整性验收分开：已完成的真实流程证据，以及审稿详情和范围内静态问题的收尾结果见[阶段六验证记录](/docs/plans/directing-phase-six-validation/)。


## 审稿决策信息展示

审稿结果、执行确认、取舍弹窗与提示词版本账使用同一只读详情组件。摘要展示判断，按需展开每项观察、影响对象原字段路径、修改建议、验收条件及各自状态/来源；文件来源包含身份和时间码。空来源、未知、不适用、未填写与明确没有分别表达，不补造依据。待审不显示为需修改，未列具体问题也不代表通过。

影响路径只显示原值，不自动定位或切换到最新设计。取舍弹窗仍可查看原问题，裁决仍使用现有派生版本与理由记录，没有新增审批步骤或下载报告。

### 公共工作区展示

三个阶段复用工具栏、对象标题栏、导航搜索和详情容器，业务判断仍由各阶段提供。导航搜索默认收起，按场次和阶段恢复非空查询时显式展开；关闭搜索清空条件，筛选不修改所选对象，移动端搜索不触发导航关闭。详情容器在桌面与抽屉之间移动同一门户节点，避免响应式切换重挂载内部编辑器。工具栏允许按内容撑高，避免窄屏换行遮挡内容操作。

展示框架分为五层：L0 `SequenceLayout` 提供左右外壳、导航槽与底部状态；L1 页面提供场次栏、工作阶段栏及上下文／内部导航／内容的顺序；L2 设计、试拍、剪辑各自组织专属工作区；L3 主视图或步骤填充主内容和辅助内容；L4 对象详情负责字段、局部页签和抽屉。框架负责几何、滚动与响应式，阶段业务负责身份、草稿和动作条件，不为每层新增可见工具栏或通用状态管理。

“导演设计／单元试拍／剪辑验收”始终位于场次选择下方，通过既有 URL `view` 切换。设计的分镜／清单／关系图导航横跨主区和详情区；试拍的计划栏、单元标题与单一主操作、步骤栏均位于双栏上方。三个阶段复用 `workbench-content` 分栏规则，桌面辅助栏为 344px；剪辑继续保留播放器、下方时间线与右侧审片／片段／来源详情，不增加虚构步骤。试拍三步骤共享同一内容边界，主内容与辅助内容各自滚动，浏览位置按版本、对象与视图身份分别保存并兼容旧单条记录。低于 1280px 时使用单列和辅助抽屉，试拍在步骤栏下显示真实摘要与入口；低于 768px 使用步骤选择框。

## 指令的局部修订与主动调整

`directing_review_revision` 任务冻结原文、设计、计划、单元、指令、整体修改要求、人工字段编辑和逐项方向。检查来源可以是已确认检查版本或成功的检查任务；省略检查来源表示主动修改，未检查和全部通过时均可发起，不伪造检查问题。候选只保存在任务结果中；字段白名单限制为当前单元适用的既有字段，身份、数组结构和关联不能由模型增删。真实候选按契约规范化并核对完整关联，预览与采用使用相同差异。每个待处理问题都须有处理说明，未解决或需要选择时不能部分采用。声音执行方式通过逐项 `sound_execution` 显式选择，不能仅凭模型自述授权。

修订生成和采用分别使用请求身份。场次数据库写锁先于任务查询，兼容 SQLite 的并发请求；采用进度保存在任务快照中，逐步记录新设计／当前单元计划、指令和检查任务。仅修改单元参数时复用原设计；设计改变时创建新设计版本，不覆盖其他草稿或已确认版本。采用服务通过 DirectingStore、现有编译和正式审稿能力执行，不自动生成视频。检查任务受理后的失败由现有检查入口显式重试，不自动建立循环。

问题方向复用浏览器会话草稿，键包含项目、场次、指令及固定检查来源，问题按出现项、岗位和 finding 序号定位。原任务直接保存为检查时延续方向，人工取舍派生检查与新检查隔离。方向改变使原方案过期，服务端采用时再次比较完整输入与方向；响应丢失后沿原请求核实。真实前后差异在固定编辑区中就地展示，移动端保持相同的修改路径。

直接字段编辑通过服务端返回的当前单元白名单选择，校验原值、类型、共享范围、真实差异和来源。`review-revisions/preview` 使用人工编辑生成候选，不调用 AI；同时填写自然语言要求时交给 AI 处理，但不能覆盖人工编辑。局部单元不开放整场共享提示词和声音说明，声音执行安排单独接受明确选择。

预览与正式编译共用正文构建逻辑。候选预览不创建确认版本，文本和候选身份保存到任务结果；历史读取不重新查询当前模型并改变预览。采用校验固定输入和候选身份，新请求必须提交候选身份。整体 `summary` 可表达无变化、未能满足或必要选择，无需伪造问题键；非拟落实结果和无实际变化的候选不能采用。

试拍第二步为“指令与检查”，主区以结构化卡片展示固定指令正文，保留背景／执行边界和模型原文；卡片提供局部调整入口，与统一修改要求共享草稿。局部范围由服务端按固定指令的精确可编辑字段核验，生成和采用均回传同一范围；范围外字段编辑或检查方向阻止生成，改变范围保留输入并提示核对。真实字段差异显示在相关卡片，完整预览继续可查；服务端预览携带编译映射。方向变化后旧方案失效，可就地更新。主区可切换局部关联图，按固定编译摘录、问题影响路径和候选变化展示来源、当前正文、要求与预览；新草稿不会关联过期候选；候选到问题的关系同时核对冻结检查来源，原任务直接保存的检查沿用显式 source_task_id，人工派生记录独立。无正文摘录的决定独立可查，不补造正文；单元时长与画幅只有命中固定 v4 编译文本才连接正文。局部图的间接关系详情列出固定字段及编译映射路径，文字关系入口支持窄屏与键盘查看，关闭关系详情返回原触发焦点；切换内容按稳定关系身份核对旧连线。该图作为“依据、检查与修订”辅助视角保留；主区关联图默认提供“完整要求关系”。图的查看对象与修改范围分别保存，节点点击只展开详情，明确调整才改变范围；侧栏提供紧凑关联摘要，图模式下收起重复摘要。检查问题可直接定位正文，多个明确匹配位置全部列出，并按真实坐标高亮；历史详情提供只读关联图，不创建修改草稿或借用当前检查。窄屏采用纵向关系和原有检查抽屉。检查进度与必要问题集中在侧栏，生成、检查和结论确认等步骤主操作统一位于顶部单元标题栏；建议按用户点击加入统一输入，仅消费一次，不跨检查来源或单元重放。移动端先展示检查摘要，通过统一辅助抽屉查看并处理问题，关闭后返回触发入口。完整指令、拍摄设置和历史使用详情抽屉，差异依据与技术诊断按需展开。异步结果不抢占正在查看的详情。历史依据任务中保存的修订来源关联，预览不切换工作版本；明确切换时恢复原计划、指令和检查来源，可返回原计划查看旧视频候选。

完整要求关系通过 `generationInstructionGraph.ts` 按固定 Prompt → Plan → Design 及 unit_id 投影，不读取当前准备草稿或最新同名对象。设计依据、生产与输入、指令关系、要求细节提供同一上下文内的浏览路径，覆盖出现项与真实对象分别标识。要求保留固定值及 Note 状态，表达去向区分执行、背景、输入、参考、未表达和映射待核对；重复正文位置全部可查。触发、参与、位置、验收及归属关系只使用明确字段引用，纯文本时序保留缺口说明。共享背景、全部模型参数、参考及落幅依赖始终有独立完整入口；历史图允许浏览但不提供调整或跨层编辑动作。明确“调整此要求”才按现有可编辑字段建立范围，随后仍由原修订流程处理。局部优化影响核对通过 `instructionOptimization.ts` 区分明确字段范围、带真实引用路径的只读关联背景和候选全部实际变化；范围外、原值不符、不可编辑、重复字段、来源错误和过期候选阻止新采用，但已持久化的采用恢复沿用原请求。候选完整预览与编译映射齐全时，只在克隆快照上计算真实关系增删及未变化关联，不改写当前对象；缺少映射时保留字段差异与完整预览，不推断关系修复。原正文和候选正文的可靠位置分别展示，原正文定位复用已有多处位置入口。阶段验收见对应方案。

同镜头拆段时，局部事件、节拍、表演和调度按固定覆盖项限定；共享镜头及横向引用不将另一动作段追加为本段执行内容。范围外关系可以展开追溯，返回保留原范围及选择；未对应覆盖位置的单元相关依据单独可查。完整要求视图的共享约束、输入及原文等展开状态随精确上下文保存，非法身份不恢复，不可用会话存储不阻止浏览。固定参考按图片、视频、音频呈现；媒体加载失败保留固定文件身份与核对入口，不以其他文件替换。

辅助视角的节点选择、关系选择、列展开和全部关系列表展开按固定来源、正文位置、检查来源及只读状态隔离保存；恢复时只接受当前投影的节点、关系及已知列。候选更新不重置仍有效的选择或焦点，检查来源变化使用另一份浏览记录。会话存储失败仅使浏览记忆不可用，不修改修订输入或扩大调整范围。
