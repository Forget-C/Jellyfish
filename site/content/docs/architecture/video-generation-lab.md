# 视频生成实验室

视频生成实验室独立于项目、资产和分镜生产流程，用于验证已登记的视频模型、`video_prompt` 提示词模板、关键帧与主体参考对生成结果的影响。

## 页面与输入结构

页面复用实验室的共享布局、输入区和历史组件。历史由用户提示词消息和视频任务消息组成；任务消息展示状态、进度、失败原因及成功后的内嵌视频预览。

关键帧按具名槽位保存，而不是无类型图片列表：

- 首帧：`frames.first`
- 尾帧：`frames.last`
- 关键帧：`frames.keys`

三个槽位均引用资料库文件：每个引用包含 `file_id`、`media_kind: image` 和组内 `ordinal`。主体参考独立保存为 `subjects`；每个主体有名称以及一组按顺序排列的图片或视频 `file_id`，提示词可以用 `@主体名称` 指代它。帧槽位只能引用图片，主体名称在一次提交中必须唯一。

API 和任务快照只保存资料库文件标识，不保存供应商侧媒体表示。统一生成门禁负责验证文件类别和模型能力，Worker 仅在执行期通过文件解析器取得供应商所需媒体表示。

## 能力约束

模型能力接口 `GET /api/v1/llm/video-generation-options` 描述主体图片、主体视频以及主体能否与首帧、尾帧、关键帧组合。前端按该能力决定可见输入和允许的组合，不能把主体素材写入关键帧槽位。

Vidu 主体参考映射到 `reference2video` 的 `subjects` 参数。当前适配器以保守规则禁止主体参考与帧参考同时使用；若某个供应商/模型支持该组合，必须先在其 `VideoModelCapability` 中显式声明，再实现对应的供应商请求映射。当前 `viduq2-pro` 支持主体视频，其他已声明的 Vidu 视频模型只支持主体图片。

## 统一任务提交与结果

视频实验室通过固定入口提交异步任务：

`POST /api/v1/studio/generation-tasks/labs/video/sessions/{session_id}/tasks`

路径绑定视频模态和 `video_generation` operation。请求体提供已登记的 `model_id`、最终 `execution_prompt`、`ratio`、可选帧槽位和主体参考；服务端校验会话属于视频实验室，且不允许由请求体切换 operation 或媒体结构。

用户消息、携带 `task_id` 的任务消息和统一 `video_generation` 任务在同一事务中创建，提交成功后才投递 Worker。任务目标类型为 `experiment_session`，不会读取或回写任何 `Shot`。任务快照冻结模型修订、提示词、文件 `file_id` 和目标会话，但不保存凭据值。

前端通过 `GET /api/v1/film/tasks/{task_id}/result` 轮询任务。Worker 将成功、失败或取消状态及结果快照写回同一条任务消息；成功视频由统一产物流程归档到资料库，页面使用结果中的资料库文件信息播放并在刷新后恢复历史输入和预览。

## 与分镜视频生成的边界

- 视频实验室：独立验证模型、提示词、关键帧和主体参考，不绑定镜头，不更新分镜状态。
- 分镜工作室：生成前需要镜头、时长、准备度和项目上下文，成功后会发布并回写镜头的生成视频。
