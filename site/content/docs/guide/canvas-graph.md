# 接入共享画布 graph

四个画布使用版本接口返回的 `director_graph`、`unit_graph`、`instruction_graph`、`edit_graph`。业务内容保存在原 `SceneVersionContent`；graph 是同一次读取的展示投影，不是另一份可保存的业务数据。指令图按明确单元展示已保存正文、实际消费依据与明确参考；完整正文在稳定挂载的独立工作区编辑，建议与检查继续沿用原业务入口。剪辑图默认按真实时间顺序展示已保存采用、待拍占位与源 Take 取材关系；播放器、时间线和原素材库从明确入口进入，浏览切换保持工作区挂载。素材库、审片、接缝与返工仍使用原业务入口。

## 后端接入步骤

1. 在 `app/core/contracts/directing/canvas_graph.py` 复用 `CanvasObject`、`CanvasTarget`、`CanvasNode`、`CanvasEdge`、`CanvasMember`、`CanvasView` 和 `CanvasIssue`。业务节点使用有判别字段的具体类型，新增载荷保持明确字段，不接入任意 JSON 表单。
2. 由 `DirectingStore` 完成项目、场次及版本鉴权，读取强类型内容和 revision；使用 `CanvasReadContext.load` 为同一快照加载共同证据。模型、文件、固定风格及依赖有效性调用既有服务，不在投影器里重新实现鉴权或准备流程。
3. 在 service 层编写领域投影函数，参考 `director_canvas.py`、`unit_canvas.py` 与 `instruction_canvas.py`、`edit_canvas.py`。使用 `GraphAssembler.add_node/add_edge/add_view/add_issue` 注册对象，最后调用 `finish` 并构造具体 graph 类型。构建器不做 I/O，领域投影器负责真实成员、摘要、分组、入口和问题。
4. 每个显示节点使用唯一 ID，并通过 `object` 保留实际业务身份及内容路径；节点 ID、视图 ID 对消费者是不透明地址。配置字段只声明实际可编辑的内容。历史无稳定 ID 对象设为 `stable=false`，其身份限定在当前 revision，不在读取时补写 UUID。
5. 成员复用节点，不复制业务单元；聚合入口提供 `entry_view_id`，节点提供 `home_view_id`，视图提供父级和锚点；每张图只有一个 parent_id 为空的根视图，消费者读取其返回 ID，不约定根地址字符串。所有边必须有真实来源，缺失业务引用明确返回问题或缺失节点。不要静默删边来伪装完整。
6. 保持版本内容、各图和目标的 version/revision 一致。读取内容时同时固定标题、revision、最近保存请求身份和时间等响应元数据；证据加载可能重新读取同一 ORM 行，不能在加载后再从已刷新的实例取响应元数据。读取和保存均返回完整快照；API 只负责收参、鉴权入口和响应，不组装图。

共同校验会拒绝重复节点／边／视图、悬空端点或成员、无效入口与编辑目标、循环层级、快照不一致及不闭合的来源定位。视图数量和分组计数由构建器统一计算，具体业务诊断由投影器提供。

## 证据与执行边界

`CanvasReadContext` 批量读取视频模型与项目可见文件，复用固定项目风格和真实依赖校验。`unit_video_inputs.py` 提供真实执行与图共同使用的模型解析、适配器参考能力和输入元数据校验；它不读取媒体字节，也不提交任务。未知模型或供应商配置返回未核实问题。

参考集合保留每个绑定的 ID、用途、输入角色与顺序；文件预览仅表示当前登记及可访问地址，不宣称媒体字节或生成准备已经通过。依赖证据保留固定计划／场次、单元／采用、实际帧和参考绑定身份，区分未绑定、有效、待复核和不可用。外部模型、文件和采用变化可以在场次 revision 不变时改变重新读取的证据。

只读执行依据复用 `unit_scope`，分别表达执行项、约束、背景与未解决项；来源按钮使用服务端明确返回的 `CanvasBasisTarget`。无法定位的固定来源显示原因，不按同名或数组位置猜测。结构通过、范围支持、生成准备、任务成功、素材审查与剪辑采用始终是不同状态。最终编译、预检和执行仍重新校验真实输入。

指令正文节点额外携带独立的依据状态、绑定回执及当前相关任务摘要。摘要只包含每类最新、活动和正文／检查明确绑定的原记录；数据库先筛选这些身份，再加载所需固定输入，完整历史仍走原记录接口。依据沿历史投影版本比较实际消费，检查适用性还比较固定正文，检查确认另外验证六岗与要求去向。图读取不回读完整版本，不执行准备、应用或确认。

工作台复用现有指令轮询与活动通知刷新证据，也提供“刷新图证据”入口。相同 revision 允许更新 graph；读取序号、场次版本、revision 与已保存内容共同阻止迟到结果覆盖新基线。刷新保持草稿、正文编辑器、焦点和图布局，失败保留旧摘要并提供重试；服务器内容变化进入原保存冲突比较。指令编辑器始终位于稳定的业务工作区，graph 中的检查摘要仅代表已保存输入。

## 前端接入步骤

- 从 OpenAPI generated client 消费具体 graph 类型；业务节点、关系、摘要、计数、问题及视图成员由后端提供，前端不从业务数组重新拼图。先核对 graph 与版本快照，失败显示明确错误。
- 复用 `GraphCanvas`、`GraphSubgraphPreview`、`graphLayout`、`useGraphLayout` 与 `useGraphBrowse`。前端负责几何、视口、缓存和浏览历史；业务布局尺寸与旧缓存迁移保留在对应适配器中。
- 使用返回的视图和定位地址导航，不解析 ID 前缀或用第一 coverage 替代精确单元。锚点和有效布局节点集合使用后端地址；原文标题不能充当节点 ID，旧缓存键仅在业务适配层迁移。镜头筛选只选择后端视图，不裁剪完整单元子图。
- 卡面复用两行字段摘要，为诊断数量、原因及操作保留空间；参考卡仅预览有限绑定，后端总数与详情中的完整集合保持不变。
- 单元聚合预览使用后端 `preview_title`，格式为“镜头 1、镜头 2 — 单元 1”；单元编号是场次内序号，筛选不缩减完整覆盖范围。已绑定素材数量单独保留字段名，诊断数量也显示可见类别，不将摘要值去掉标签后拼接。
- 摘要消费已保存 graph；详情按稳定业务 ID 编辑当前暂存内容。旧 graph 的对象若已在当前编辑中移除，提示不可用，不选替代对象。未保存新对象继续沿用当前编辑入口，保存后获得后端 graph。无 ID 历史行若在保存基线中重复，不把编辑后剩余的唯一同内容行当作身份；旧卡暂不可编辑，使用“编辑待同步对象”明确选择当前行。
- 复用 `WorkbenchDetails`、主题和现有详情。需要定位输入时传入 `focusTarget`，由详情在实际可见后聚焦字段，避免先对隐藏内容设置焦点。
- 保存统一走 `CanvasSequenceWorkbench` 现有串行队列、5 秒周期及手动入口；不要为 graph、配置卡或新画布另建保存接口、草稿实体或自动提交链。

## 验证与接口同步

共同契约测试覆盖四类投影及非法结构；版本 HTTP 用例核对读取／保存快照、实际来源与外部证据变化。真实浏览器验证导航、详情编辑、旧图与当前输入分离、失败恢复和精确回跳。当前回归入口包括 `test_canvas_graph.py`、`test_scene_dependencies.py`、`sceneCanvasGraph.browser.mjs`、`sceneLegacyGraph.browser.mjs`、`directorLayout.browser.mjs`、`sceneGraphSummary.browser.mjs` 和 `scenePeriodicSave.browser.mjs`。

对外 schema 变化后，先核实 8000 端口加载当前工作区后端，再从仓库根目录运行 `pnpm --dir front run openapi:update`。随后执行受影响测试、前端 typecheck 和后端 Pylint；工作台展示与键盘、窄屏检查遵循[工作台前端设计标准](/docs/guide/workbench-design/)。

剪辑投影批量查询全部有权限查看的同场 Take 轻量身份、固定来源及文件登记信息，不展开完整生成输入。默认整场图仍仅关联已采用源，独立“浏览同场素材图”通过服务端 `library_view_id` 进入全部候选视图；显示地址保持不透明。采用用独立 clip ID 定位，多个片段可关联同一源 Take，各自保留源区间、位置和片段适配。待拍占位只带预期内容与预计时长，时间线空白不生成节点。选择图节点只定位原素材或时间线片段；当前编辑已删除的旧图目标明确不可用，未保存新片段继续在原时间线编辑。刷新图证据复用已保存基线保护，不重建播放器或覆盖尚未应用的片段表单。对应浏览器回归为 `sceneEditGraph.browser.mjs` 与 `sceneTimeline.browser.mjs`。

真实接缝由后端按已保存时间线投影，仅连接直接相接的两个真实媒体片段，保留独立采用 ID 与两侧取材引用。接缝摘要区分当前适用、待复核、未审查和依据读取失败；原审查身份、版本、结论与观察保留，完整固定历史沿原入口按需查看。比较复用原接缝依据：源素材、真实区间、片段适配或输出比例变化要求复核，整体平移不改变接续则保持适用。图选择只定位原内联接缝审查，不播放或提交；同 revision 的证据刷新保留当前观察、选区与播放器。对应回归为 `sceneEditSeamsGraph.browser.mjs` 和接缝审查 HTTP 用例。

同场素材图分别展示共享 Take 固定来源、当前版本判断、可用区间、人工实际覆盖登记与剪辑采用。覆盖节点保留复合素材身份、观察、真实源区间和当前单元／覆盖项，数量只表示登记条目，不代表计划完整覆盖；可分别定位原判断和当前目标。当前复核摘要保留最新记录及仍适用的旧记录，完整历史从原素材审片入口按需读取。数据库按每个复合素材分批比较，找到适用记录后不再加载该素材更旧正文，不调用高层版本读取。

同 revision 的新候选、复核和文件可用性随图证据刷新进入原工作区，失败保留身份并可原位重试。素材／时间线一次明确播放固定自己的来源 URL，候选增加和签名 URL 变化不重建播放器或改变运行／暂停位置；下一次明确播放或重试才消费新来源。未保存判断、尚未记录的覆盖表单和未应用片段修改保留。对应回归为 `sceneTakeLibraryGraph.browser.mjs`（4244／8244）及既有 `sceneTakeLibrary.browser.mjs`、`sceneLegacyTakeLibrary.browser.mjs`。


剪辑图的整场验收节点分别显示画面、实际覆盖核对和声音状态，保留最新结论及最近仍适用结论；问题保留多个真实片段目标，原片段消失时不替换目标。落幅节点保留原版本、单次采用、源素材、实际区间与解码位置；后段节点复用已有依赖核验结果，明确定位原单元。选择这些节点只进入原整场验收、实际落幅或单元准备入口，不自动提帧、换绑、审片或生成。整场记录使用分批流式比较，落幅由数据库预选当前采用最新记录和明确绑定帧，完整历史仍在原入口查看。记录完成或手动刷新可在 revision 不变时更新图证据，已有验收输入和播放工作区保持挂载。对应回归为 `sceneEditCutEvidence.browser.mjs`、`sceneCutReviews.browser.mjs`、`sceneEndFrames.browser.mjs` 和 `sceneFrameDependencies.browser.mjs`。
